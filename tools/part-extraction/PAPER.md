# 以 Live2D 模型为监督的动漫立绘通用语义拆分

[设计](DESIGN.md) · [拆分惯例](SPLIT_PRACTICES.md) · [工具说明](README.md)

## 摘要

把一张动漫角色立绘拆成可直接用于 Live2D 制作的分层素材，需要两种能力：知道画面里有哪些部件、各在哪里；以及把每个部件完整画出来，包括被其他部件挡住的部分。本文用已经制作好的 Live2D 模型作为监督来源：模型里每个图层本来就是完整的，渲染时又能精确知道它在画面上露出了多少。在此基础上训练两部分：

- **规划器（planner）**：给出立绘里的每一层：标签、可见区域、完整形状（含被挡住的部分）、前后顺序和分组。v1–v3 是 30 类逐像素分割，v4 加了实例嵌入，v5 改为查询式；
- **拆分 LoRA**：在 FLUX.2 klein 4B 上，以「带周围环境的特写 + 部件可见区域 hint + 文字描述」为输入，输出该部件的完整重绘。

标注由程序规则起步，再由 Haiku 子代理逐节点审核、逐 mesh 描述，没有使用本地大模型。

在留出的模型家族上，LoRA v7c 的部件形状 IoU 为 0.740，被遮挡部分的补全 IoU 为 0.751。规划器 v5 在留出模型的全身图上，按单片计精确率 0.480、召回率 0.622。它也给出被挡住的层，但目前虚报多，正在改进。端到端拆分已能产出可用的头发、服装、四肢与五官图层。主要瓶颈是规划器对小部件的识别，以及训练分辨率。

本文区分三种状态：**实测**指已训练并评估；**已实现**指代码完成但尚未训练或评估；**设计中**指尚未实现。

## 1 问题与思路

手工拆分一张立绘通常要几十到上百个图层。难点不在描边，而在补画：头发后面的脸、衣服下面的身体、手臂挡住的裙子，都要补成完整的一层，并且符合 Live2D 的分层惯例，比如眼白单独一层、身体画到衣服下面多远。

Live2D 模型正好是这种补画的标准答案：作者已经把每个部件画完整了。我们用自研引擎（PSD2Live 的 Umamo）加载模型，对任意一组 mesh 都能渲染出：

- 整个角色；
- 只有这组 mesh、完整无遮挡；
- 这组 mesh 在整体渲染里实际可见的像素。

这三者构成一个训练样本，监督信号完全来自模型数据本身，不需要人工画标准答案。

整个系统遵循一条原则：**图层是生成器的完整输出，代码不处理图层像素**。不贴原画、不按阈值抠图、不用掩码裁切。规划器给出的区域只作为 LoRA 读取的粗略 hint。第 6 节记录了违反这条原则时出现的问题。

## 2 数据

### 2.1 来源与去重

- **来源：** 三个公开收集的 Live2D 模型集合。第四个来源在标注中发现含露骨内容，已从标注、训练数据和后续训练中整体剔除，未从头重训。
- **去重：** 同一角色的换装、表情版本会导致数据泄漏和偏差。按「mesh ID + 包围盒（50 像素网格）」计算 Jaccard 相似度：
  - 相似度 ≥0.6、mesh 数相差在 30% 以内的模型，用并查集归为一个家族；
  - 每个家族取 mesh 最多的模型作代表，共 750 个家族代表；
  - 测试集按家族整体留出，同家族的任何模型都不进入训练。

### 2.2 场景图与初始标签

每个模型解析为场景图：部件树、变形器、参数响应、物理链、裁剪关系、绘制顺序。初始标签由规则给出：

- 从「眼睛画在哪个头部 mesh 上」找出脸；
- 同类 mesh 大部分画在另一个同类 mesh 之上时，判为衣服而不是身体，依据绘制顺序和像素，不依据颜色；
- 遮挡关系要求覆盖物和被覆盖物受不同参数驱动，避免把同一部件的分片误判为遮挡。

### 2.3 Haiku 审核与描述

所有标注都由 Haiku 子代理完成，每批约 160 个图块，最多 50 个并发。

1. **节点审核：** 每个节点（构成一个部件的一组 mesh）给出保留、改类别或丢弃。另外对皮肤、基础身体和身上画了什么（裸露、紧身衣、内衣）做了专项复审。
2. **逐 mesh 描述：** 每个面积足够的 mesh 渲染成一个双栏图块：
   - 左栏：在角色上高亮该 mesh，同变形器组半亮，其余压暗；
   - 右栏：该 mesh 单独放大到棋盘格上。

   Haiku 对每个 mesh 给出：类别（固定词表）、角色（底色 / 阴影 / 高光 / 线稿 / 细节）、部件名（自由英文短语，如 "skirt lace trim"）、外观细节（如 "scalloped white lace edge"）、是否确定。

   结果：529 个批次，共描述 80,228 个 mesh（不含剔除的来源），约每图块 840 token，总成本约 10 美元。完整性检查发现 27 张 sheet 漏答，补派后全部补齐。

逐 mesh 描述的分布有几个特点：

- **角色：** 底色 54,221，细节 7,073，阴影 3,335，线稿 1,652，高光 1,630。
- **部件名长尾很重：** 一万多种名称，前 500 种只覆盖 64%。长尾主要是服装、头饰和道具的自由描述，对提示词的多样性有价值，因此只做确定性的同义词归并（lock / tuft / strand、bangs / front hair、shade / shadow），不强行统一词表。
- **"不确定"占 46%：** 主要是在两个相近类别之间犹豫，部件名本身大多可靠，所以不据此丢弃。

### 2.4 细分节点

细分的单位是图层，不是 mesh（`layer_units.py`）。蒙皮把一张画切成多段，相邻段在粘合处纹理坐标连续（间隙小于 5e-4），这些段合并成一个图层。但如果两段之间夹着一片画出来的底色、且与较小一段重叠 5% 以上，就不合并，这时它们是同一物体的前后两部分，例如穿过手臂的发束。夹在中间的线稿、阴影、高光不算分隔。静止时某一侧完全看不到的，不成对。

在同一模型内，把同一类别、角色、侧别下名称相同的图层归为一组：

- **整组：** 作为一个节点，例如「裙子荷叶边」「外套阴影」。如果这组已占该类别 70% 以上的像素，就和类别节点重复，丢弃。
- **单片：** 由 3 个以上底色图层组成的重复组（发束、手指、裙片），每一片也作为节点，例如「一根前发」。它们由 hint（可见区域）区分，提示词不需要位置词。单片只保留两种（`piece_kinds.py`）：
  - 名称是可以单独成立的物件。Haiku 把部件名分成「物件」和「分段」：物件如一根发束、一根手指、一片裙摆；分段如胸口皮肤、一段睫毛、上眼睑，它们只是作者为了做动画把一个物体切开的结果，「the 睫毛」应当指整条睫毛，不是其中一段。1,498 个名称中 1,099 个是物件。
  - 尺寸足够：较长边至少为 max(32, 脸宽的 1/5)。用相对脸宽的尺度，低清模型保留的单片比例和高清模型一样；用较长边，细长的发束和手指按长度计。按面积或按绝对像素都会偏向丢弃低清模型和细长部件。
- **前后分层：** 被另一物体穿插的图层，另出「整体」「X 在 Y 前面的部分」「X 在 Y 后面的部分」三种节点。同一 mesh 的线稿和色块分到前后两侧是常规的线色分离技法，不是分层，所以每一对都交给 Haiku 看四格图（上下文、整体、前半、后半）确认。145 对中保留 52 对。

结果是 931 个模型、65,792 个细分节点（整组 37,857、单片 27,806、前后分层 129），提示词直接用 Haiku 的原话。

### 2.5 内容约束

- 剔除含露骨内容的来源。
- 训练对中去掉「衣服下画了完整裸露躯干」的身体节点（除非身上画着内衣或紧身衣），以及身体类的全部细分节点。
- 推理时，躯干一律按「画着内衣、完整画在衣服下」生成。这也是常见的 Live2D 制作惯例。

## 3 拆分 LoRA

### 3.1 样本

对每个节点渲染 2 个姿态变体。每个样本包括：

| 图 | 内容 |
|---|---|
| 特写 | 以节点为中心、带周围环境的正方形区域，按贴图原生密度渲染，从不放大原画；随机浅色背景 |
| hint | 节点在特写里实际可见的像素 |
| 目标 | 节点单独、完整渲染在灰底上 |

特写边长取节点的原生尺寸，并有上限。768 渲染时的分布如下：

| 来源 | 中位数 | ≥512 | ≥768 | <192（丢弃） |
|---|---|---|---|---|
| m（1024 渲染） | 352 | 34% | 20% | 24% |
| kis | 325 | 31% | 18% | 27% |
| col | 634 | 57% | 44% | 12% |

大部分部件本身只有几百像素，原生 512 以上的约占三到四成。

### 3.2 提示词

```
Live2D layer split: keep only <部件描述>, the part marked in the second image, drawn complete including any
part hidden behind other layers, exactly in place, on a flat gray background.
```

部件描述在类别短语之后，追加该模型作者的画法：
- 嘴是否带肤色底；
- 皮肤在衣服下画了多少：完整、到边缘、只画可见部分；
- 身上画着什么：紧身衣、内衣。

细分节点直接使用 Haiku 的名称和外观细节。

### 3.3 增强

- **粗糙 hint：** 一半样本的 hint 随机放大或缩小画面的 0.5%–3%，模拟规划器的误差。
- **水平翻转。**
- **眼部样本：** 并入约 900 对。
- **高清化：** 把特写先缩小到 1/2–1/6（缩小后边长不低于 64），一半再做 JPEG 压缩，然后放大回原尺寸，目标保持原生清晰度。目的是让 LoRA 无论输入多清晰，都按原画的清晰度重绘。
- **按模型清晰度分档：** 以脸宽（脸节点面积的平方根，按原生像素计）衡量模型画得多精细。

  | 档 | 脸宽 | 训练对 | 高清化比例 |
  |---|---|---|---|
  | 低清 | < 160 | 随机保留 60% | 0（目标并不比特写清晰，没有可学的细节） |
  | 中 | 160–226 | 全部 | 35% |
  | 高清 | ≥ 227 | 全部 | 50% |

  低清模型仍参与训练，学形状和补全，只是权重略低；细节恢复主要从高清模型学。
- **单片限量：** 单片在训练对中最多占 25%，随机抽取，保证类别节点和整组的权重。

### 3.4 训练与评估

- **训练：** ai-toolkit，FLUX.2 klein base 4B，LoRA rank 64，学习率 4e-5–5e-5。特写和 hint 作为两个参考 latent，目标作为监督。
- **评估：** 用蒸馏版 klein 跑 4 步推理，在留出家族的静止姿态节点上逐类别计算三项指标：形状 IoU、被遮挡部分的补全 IoU、颜色误差。另外几项（`node_metrics.py`）：
  - 特写从小 3 倍或 6 倍的图中读取（`--soft`、`--soften 6`），衡量细节恢复；
  - 前后分层节点按整体、前半、后半分别统计（`--layered`）；
  - 按节点类型（类别、整组、单片）和模型清晰度档分别统计（`--by kind`、`--by tier`）。

## 4 规划器

- **结构：** DINOv2 骨干（Depth Anything V2 Base 的权重）+ DPT 解码器 + 新的分类头，在 518 像素的裁剪上训练。
- **类别权重：** 按像素频率的平方根反比加权，限制在 0.2–5 之间。
- **训练数据：** 模型静止渲染放到随机浅色背景上，配逐像素的类别图。没有标签的像素忽略。

| 版本 | 数据 | 结果 | 状态 |
|---|---|---|---|
| v1 | 规则标签 + 节点审核 | — | 实测 |
| v2 | + 皮肤、基础身体复审 | 第 5/10/15/20 轮 mIoU 0.268 / 0.310 / 0.320 / 0.306 | 实测 |
| v3 | Haiku 逐 mesh 标签覆盖规则标签（猜测且与规则不一致的忽略）；剔除来源；新增背景类；裁剪中心只取部件像素。873 个模型，已标注像素从 16.8% 增至 20.7% | 第 5/10/15/20 轮 mIoU 0.456 / 0.474 / 0.473 / 0.471 | 实测 |
| v3.1 | 同时读两轮逐 mesh 描述（第二轮为 50–300 像素的小 mesh）；碎片与和规则相悖的猜测都忽略 | 第 5/10/15/20 轮 mIoU 0.442 / 0.470 / 0.470 / 0.465 | 实测 |

v2 的单类结果：

- **高：** 虹膜 0.85、耳朵 0.83、脖子 0.78、嘴 0.77、尾巴 0.67。
- **几乎为 0：** 领饰、鼻子、道具、手套。
- **很低：** 睫毛 0.03、头饰 0.05。

v3 的单类结果（第 20 轮）：大部件已经可用（耳朵 0.92、虹膜 0.86、腿 0.86、手臂 0.84、手 0.80、下装 0.78、脸 0.73、上装 0.71），小部件仍弱：眉毛 0.20、口内 0.20、耳饰 0.12、颈饰 0.24、睫毛 0.41，鼻子、面部细节、手套、眼镜为 0。

| 上装 | 784 | 459 / 980 / 1842 | 971 | 47% | 6 / 24 / 68 | 4 / 17 |
| 下装 | 574 | 391 / 797 / 1506 | 838 | 40% | 3 / 11 / 58 | 2 / 8 |
| 头饰 | 552 | 166 / 459 / 976 | 509 | 19% | 4 / 11 / 31 | 2 / 7 |
| 手（单侧） | 909 | 93 / 191 / 410 | 193 | 3% | 5 / 13 / 28 | 1 / 4 |
| 单眼（含眉） | 1645 | 52 / 101 / 238 | 117 | 1% | — | — |
| 嘴 | 750 | 26 / 63 / 147 | 72 | 1% | — | — |

图层只计在 1024 特写里至少 16×16 像素的。结论：

- **静止渲染的分辨率就是原生分辨率。** 各类特写的原生边长与 2048 渲染中边长之比，中位都在 0.92–1.28 之间（全身 0.96）。贴图本身就只有这么多像素，按特写重渲染得不到更多细节，所以 v4 直接从静止渲染（`full.png` 与逐 mesh 的 `meshes/*.png`）裁特写。
- **原生 1024 的大部件特写很少。** 头部原生中位 369 像素，只有 13% 达到 1024；单眼 117，嘴 72。网络输入统一缩放到 728（52 个图块）。头部特写约放大 2 倍，眉毛从全图里的 2 个图块变成十几个，这是第二级规划的主要收益。单眼和嘴原生太小，多数不单设一级：第二级的头部特写里已经要分出眼白、虹膜、睫毛和眉毛。边长不足 160 像素的特写不进训练。
- **聚类参数。** 头部特写约 11 个底色图层（p90 20，最多 42），上装可达 68，全身特写上百。实例嵌入每级 8 维，判别损失 δv = 0.5、δd = 1.5（类中心至少相距 3），聚类阈值 1.5；最小实例为 24 像素或特写面积的 0.04%。

**训练数据（已实现）。** `plan4_data.py frames` 为每个模型取三级特写：全身；每个大部件（一个标签，成对标签按脸的中线分左右）和头部；单眼和嘴。除全身外，每个特写另有一个随机缩放（1.15–2 倍）和平移的变体。`plan4_data.py export` 按绘制顺序把各 mesh 的像素画成逐像素标签：

- 实例：最上层的底色图层（`layer_units.py` 合并的切割段算一层）。阴影、高光、线稿、细节不占实例的像素，作为角色位（多标签）记在下面的实例上；
- 碎片、过小的实例、只画了角色或半透明边缘的像素，不进实例图；
- 每个实例记录标签、侧别、部位（标签 + 侧别；标签是猜测时从命名组名称里取）、命名组（细分节点里同名的底色组，没有则取部位）和绘制顺序。切成多段的图层按多数票取标签：约 5% 的多段图层各段标签不一致。

结果：896 个模型、22,779 个特写（全身 896，头部 1,737，其他大部件 19,086，单眼与嘴 1,060），共 78 万个实例，其中 25% 标签不确定，只监督实例、不监督类别。每个特写的实例数中位：头部 39（p90 62），其他大部件 30（p90 66），全身 46（缩到 1024 后小图层被滤掉）。留出 10 个模型（按家族），247 个特写。

**训练（已实现）。** `train_planner4.py`：骨干、DPT 与类别头从 v3 热启动，新增角色头（4 个 sigmoid）、实例嵌入头（3 × 8 维）和绘制顺序头。网络输入 728，嵌入与顺序在 364 上计算。

- 实例嵌入三段，分别对应单片、命名组、部位，各用判别损失（同一实例的像素拉到均值 δv 以内，不同实例的均值推开 2δd）。推理时按部位 → 组 → 单片依次聚类，停在哪一级就是哪种粒度。
- 绘制顺序：同一特写内每对实例的平均得分按绘制先后做 logistic 排序损失。
- 评估：各级类别 mIoU；三种粒度的实例匹配（IoU > 0.5）精确率与召回率；实例对的顺序正确率。
- 12 GB 显存下用 batch 2 × 累积 2。

**接入（已实现）。** `split_image.py --planner4`：全图（或 `--planner` 给的 v3 结果）定大部件；每个大部件和头部各取 1.3 倍特写再规划一次，取本部件类别的像素，依次聚类到 `--grain` 指定的粒度。每片按标签在 `ORDER` 中的位置、再按特写内的顺序得分排列，写进 Layout 分组 `<大部件>/p<部位>/g<组>`。角色头给出的阴影、高光、线稿、细节记在每层的 `split.roles` 里。`--plan-only` 只输出规划，不调用 ComfyUI。

**训练结果（实测）。** 从 v3 热启动训练 20000 步，前 15000 步在本机，之后在 3080 上续训。留出的 247 个特写，最小簇 64 像素：

- 单片精确率 0.496、召回率 0.519；
- 顺序正确率 0.828；
- 部位 mIoU 0.498。

15000 步与 20000 步在特写评估和测试图上几乎一样，已经收敛。

续训时踩到一个坑：transformers 5 把 DINOv2 注意力层的键名改成了 `q_proj` / `k_proj` / `v_proj` / `o_proj`，宽松加载会静默跳过旧键，骨干注意力等于被重新初始化。`train_planner4.fit_state` 现在在两种命名之间互相映射，那一段续训已重跑。

**推理改进（已实现）。** 在测试图上逐个排查碎片和漏层后，聚类与组装改成：

- **聚类：** 按密度取种子，替代逐像素贪心；小于 64 像素的簇并入均值最近的相邻簇，不再单独成层。
- **层级自底向上：** 每级只在本特写的像素上聚类一次；单片取它多数像素所在的部位和组，不再按上一级的结果切分下一级。
- **像素归属：** 每个像素只归一个特写。特写处理的像素是「本部件区域」加上「本类别中尚未被认领的像素」，靴子、尾巴这类全图分类漏掉的部件不再丢失。
- **第三级：** 头部特写里再取单眼和嘴的特写。
- **跨边界合并：** 大部件的边界会把一层切成两半。两片相邻、标签同属一类（`KIN`，如上装与领饰、腿与袜子），且在全图聚类中多数像素属于同一单片时，合成一层。
- **阈值：** 部位 2.0，组与单片 1.5。

相邻簇按均值距离合并也试过：合并距离 1.75 时单片精确率 0.58、召回率 0.46，2.0 时为 0.62、0.30，用召回率换精确率，默认关闭。

**端到端评估（实测）。** `plan4_eval.py` 在 10 个留出模型的全身特写上运行 `split_image.py` 的完整规划，和画这张图用的图层对比：一个真实图层被某个规划层以 IoU > 0.5 覆盖，就算找到。规划层的多数像素落在真实标签忽略的区域（碎片、半透明边缘）时，不计入精确率。

| 配置（单片粒度） | 规划层 | 精确率 | 召回率 |
|---|---|---|---|
| 逐级嵌套切分（15000 步） | — | 0.27 | 0.50 |
| 自底向上（20000 步） | 590 | 0.30 | 0.51 |
| + 跨边界合并（20000 步） | 536 | 0.33 | 0.50 |

剩下的错误主要有两类：

- **碎片：** 212 个规划层是真实图层的一部分。嵌入在大面积图层内部漂移，一层被分成几片。
- **跨层：** 148 个规划层横跨几个真实图层。

**遮挡统计（实测）。** 在 226 个模型、23,134 个静止时绘制的底色图层上，比较每层可见像素与它的完整形状（不被遮挡时的像素）：

| 可见部分占完整形状 | 图层占比 | 占全部完整面积 |
|---|---|---|
| 完全被盖住 | 9.2% | 5.0% |
| 不足 10% | 10.5% | 16.1% |
| 10–50% | 25.9% | 35.0% |
| 50–90% | 28.5% | 30.4% |
| 90% 以上 | 26.0% | 13.5% |

- 18% 的图层被前面的层切成两段以上，而它的完整形状只有一块。后发 42%、脸 41%、眼白 67%。
- 另有 23,826 个底色图层静止时完全透明（表情、口型差分等），不在规划器范围内。

两点结论：

- 每像素只归一层的分割最多只能找回 81% 的图层（完全被盖住的 9% 一定找不到，可见不足 10% 的大多也找不到）。
- 被切开的层在分割图上是几块，只能靠事后合并。

这两点是 v5 改用查询、并给每层预测完整形状的原因。

### v5：查询式规划器

**结构（已实现）。** `train_planner5.py`：骨干、DPT 与像素头从 v4 热启动，像素头保留作辅助损失。新增部分：

- **解码器：** Mask2Former 式查询解码器，200 个查询、6 层，带遮罩的注意力在 52² 和 104² 两级特征上交替。
- **遮罩特征：** DPT 最高分辨率的融合特征（416²），加一个 RGB 分支。
- **每个查询的输出：**
  - 标签（31 类 + 空）；
  - 可见遮罩，以及完整形状（含被盖住部分）；
  - 绘制顺序得分；
  - 命名组与部位向量（各 16 维），推理时在特写内投票合层，替代 v4 的三级嵌入聚类。

**训练数据（实测）。** `plan4_data.py frames --tiles` 在 v4 的三级特写之外，再给每个模型取若干随机图块：放大 1–4 倍（对数均匀），以一个随机可见像素为中心，和推理时的分块一致。

`export --amodal` 另存每个实例的完整形状（特写一半分辨率，按包围盒裁剪后位压缩）。完全被盖住的实例也导出，标为不可见。结果：896 个模型、29,947 个特写。

**训练（已实现）。** 每张图取 6144 个采样点做匈牙利匹配，每层解码器都有深监督。

- **损失权重：** 类别 2、BCE 5、Dice 5、完整形状 2、空类 0.1、顺序 0.5、组与部位向量 0.5。
- **标签不确定的层：** 只推离空类，不监督具体类别。
- **完全被盖住的层：** 只监督完整形状。

在 3080 上训练 40000 步：batch 2 × 累积 2，约每分钟 90 步，显存 8.9 GB，用时约 7 小时。

**接入（已实现）。** `plan5.py` 分三级图块：

- 第 0 级是全图；
- 第 1 级是半幅图块，相互重叠 50%；
- 第 2 级是头部的四分之一图块。

组装规则：

- 相邻图块在重叠区内 IoU > 0.5 的层合成一层；
- 每个像素归覆盖它的最细一级图块；
- 顺序、组和部位由各图块内的投票决定；
- 被盖住的层按完整形状合并，并保留下来。

`split_image.py --planner5` 给每层写 `regions/<名>_whole.png` 和 `covered` 标记。被盖住的层以完整形状作区域，交给 LoRA 补画。`plan4_eval.py --v5` 另外报告被盖住层的召回率（按完整形状 IoU > 0.5 计）和完整形状 IoU。

**特写评估（实测，300 个留出特写）。** 每 2500 步评估一次，下表选几个存档点：

| 步数 | 可见层精确率 | 可见层召回率 | 被盖住层召回率 | 完整形状 IoU | 标签 | 顺序 |
|---|---|---|---|---|---|---|
| 2500 | 0.140 | 0.389 | 0.177 | 0.609 | 0.833 | 0.789 |
| 10000 | 0.230 | 0.527 | 0.273 | 0.666 | 0.834 | 0.844 |
| 20000 | 0.311 | 0.585 | 0.269 | 0.686 | 0.846 | 0.827 |
| 30000 | 0.355 | 0.607 | 0.296 | 0.690 | 0.843 | 0.828 |
| 40000 | 0.359 | 0.612 | 0.301 | 0.691 | 0.843 | 0.826 |

30000 步之后基本持平。这个评估只在单个特写上做，没有分块与合层，和 v4 的特写评估口径不同，不直接对比。

**端到端评估（实测，同上 10 个留出模型，单片粒度）。**

| | 规划层（计分） | 精确率 | 召回率 | 碎片 / 跨层 | 被盖住层召回率 | 完整形状 IoU |
|---|---|---|---|---|---|---|
| v4 20000 + 跨边界合并 | 536 | 0.328 | 0.500 | 212 / 148 | — | — |
| v5 40000，初版合层 | 462 | 0.385 | 0.506 | 219 / 65 | 0.445（128 层） | 0.625 |
| v5 40000，修正合层 | 592 | 0.358 | 0.602 | 292 / 88 | 0.586（128 层） | 0.654 |

初版合层把相邻的大件并成了一层：围裙并进裙子，裙子与腿、袜子并成一层。原因是逐对的并查集会传递合并，同一图块里的多个查询被连成了一层。桥接主要来自两类层：

- 被盖住的层：它们按完整形状匹配，而完整形状覆盖面大；
- 全图图块里粗分的大层。

修正后的合层规则：

- 同一图块的两个查询永远不合并：按可见像素的匹配先于按完整形状的匹配，各自按 IoU 从高到低处理，会让一簇含有同一图块两个查询的匹配直接跳过。
- 同一级图块之间，像素归可能性高、且离本图块被切开的边缘更远的查询。画面边界不算切口。
- 更细一级只在离自己切口足够远的地方覆盖上一级。图块边缘把物体切开时，查询不可靠：例如下半图块的上边缘切过两条尾巴，一个查询同时盖住了两条。不加这条规则，图块边界会留下直线接缝。

修正后：

- **召回率：** 0.50 → 0.60。
- **被盖住层召回率：** 0.586。v4 按构造找不到这些层。
- **精确率：** 0.358，仍比 v4 高 3 个点。
- **跨层与碎片：** 跨层错误 88 个，仍比 v4 的 148 少；碎片 292 个，比 v4 多。
- **按标签，与 v4 相比：**
  - 变好：脸 0.85 → 1.0，手臂 0.92 → 1.0，前发 0.59 → 0.71，上装 0.40 → 0.58，下装 0.38 → 0.52，腿 0.44 → 0.61；
  - 变差：后发 0.67 → 0.33，鞋 0.2 → 0，身体 0.75 → 0。

**碎片的来源（实测）。** 把 292 个碎片按成因分类：

| 成因 | 数量 |
|---|---|
| 同一图块里，一层被分给了几个查询 | 261 |
| 图块之间没有合上 | 9 |
| 零散残块 | 22 |

这些碎片很小，中位 396 像素，约占所属真实层的 11%。碎片和同层另一部分的完整形状 IoU 中位只有 0.06，所以按完整形状合层救不回来。

问题出在图块内部的像素分配上。每个像素取「遮罩概率 × 得分」最高的查询，于是一个查询即便整体上输给了别的查询，仍能在边角赢到几块。

**修正：重叠过滤。** 采用 Mask2Former 全景推理的做法：一个查询如果只赢到自己可见遮罩中不到一定比例（OVERLAP）的像素，就整个丢弃，像素重新分给其余查询。

| OVERLAP | 精确率 | 召回率 | F1 | 碎片 / 跨层 |
|---|---|---|---|---|
| 不过滤 | 0.358 | 0.602 | 0.449 | 292 / 88 |
| 0.7 | 0.459 | 0.602 | 0.521 | 184 / 66 |
| **0.8（默认）** | **0.492** | **0.594** | 0.538 | 161 / 55 |
| 0.9 | 0.542 | 0.568 | 0.555 | 127 / 42 |
| 0.95 | 0.584 | 0.526 | 0.553 | 102 / 30 |

默认取 0.8：精确率提高 13 个点，召回率基本不变。0.9 的 F1 略高，但召回率低 3 个点；拆分宁可多给，不要漏层。

另试过两种做法，都不如重叠过滤：

| 做法 | 精确率 | 召回率 |
|---|---|---|
| 得分低于 0.9 的层并给最近的层 | 0.434 | 0.560 |
| 小于 800 像素的层并给最近的层 | 0.511 | 0.460 |

**漏掉的层（实测，重叠过滤 0.8）。** 352 个真实层中漏掉 142 个：

| 原因 | 数量 |
|---|---|
| 被并进一个大得多的规划层 | 89 |
| 边界差一些（IoU 0.3–0.5） | 41 |
| 被拆碎 | 7 |
| 没有规划 | 4 |

被合并的 89 个里，70 个由全图图块的单个查询同时盖住两层造成，16 个来自半幅图块，跨图块合层只有 2 个。这 70 个中有 68 个，更细的图块也有一个查询盖住了它的大半，但那个查询同样过大（与真实层的 IoU 中位 0.2），例如鞋与腿成了一层。所以这是模型本身分得不够细，不是合层规则的问题。

两种推理端的尝试：

- **图块边缘只在人物越过时才算切口：** 结果不变。
- **重叠过滤丢掉的像素交给其余查询：** 召回率降到 0.537，已撤回。

**四分之一图块覆盖全身（默认）。** 原来第 2 级只覆盖头部。改为覆盖全身后，小物件在输入里放大一倍：

| | 精确率 | 召回率 | 碎片 / 跨层 |
|---|---|---|---|
| 第 2 级只覆盖头部 | 0.492 | 0.594 | 161 / 55 |
| 第 2 级覆盖全身 | 0.480 | **0.622** | 174 / 63 |

召回率提高约 3 个点，主要在 1000–4000 像素的层（0.75），代价是图块数增加一倍多。

**被盖住的层（实测）。** 新增评估：规划出的被盖住层，各自对应什么。不加过滤时共 689 个：

| 对应 | 数量 |
|---|---|
| 一个真实的被盖住层 | 57 |
| 一个可见层（重复规划） | 156 |
| 什么都不是 | 476 |

重叠过滤后，重复和无对应的数量都减半，但真实被盖住层的匹配也从 57 降到 32。原因在于推理时判断「被盖住」的方式：一个查询赢不到像素，可能是因为它预测这层被盖住，也可能只是另一个查询的副本，两者无法区分。

尝试过「可见面积不到完整形状的 30% 就保留」：真实匹配回到 44，但精确率掉 5 个点，因为小碎片也满足这个条件。

此外，无对应的被盖住层里，一半与某个真实层的 IoU 在 0.3–0.5 之间：位置大致对，但形状破碎。

按得分、几个图块一致、面积、和可见层的重叠等特征，都区分不开真假被盖住层。这需要模型直接给出判断，见下面的 v5.1。

**v5.1（训练中）。** 从 v5 40000 步继续训练 10000 步，两处改动：

- **可见性头：** 每个查询新增一个 sigmoid，预测它对应的层在特写里是否可见，在匹配上的查询上用 BCE 监督。推理时，判为被盖住的查询不参与像素分配，也不会被重叠过滤当作副本丢掉；判为可见、但赢不到足够像素的查询，按副本丢掉。
- **「空」类权重：** 没匹配上任何层的查询，被推向「空」类的权重从 0.1 提到 0.2，压低虚报的被盖住层。

特写评估另报告被盖住查询的精确率：规划为被盖住的查询中，有多少对上真实的被盖住层。

**测试图对比（实测，5 张立绘 + 6 个留出模型）。** 对比 v4 20000 与 v5 40000：

- **v5 更好的地方：** 大件更完整。前一版本被拆散的裙摆、从中间劈开的长袜，现在都是一层；修正合层后，围裙、裙子、腿也各自分开。头发分束更干净。
- **完整形状：** 被盖住的层大多在合理位置，例如外套下的身体、裙子下的腿、头发下的耳朵和脸。但有两个问题：
  - 轮廓偏碎，不够平滑；
  - 数量多：每张图 20–130 个。评估只衡量了召回，没有衡量其中有多少是多余的。

## 5 推理流程

1. 规划器标注全图。输入有透明通道时，背景不参与规划。按类别取连通区域，成对的部件按脸的中线分左右。
2. 按前后顺序处理每个部件。顺序来自对收集模型的统计（`split_practices.py`）。
3. 对每个部件，取以区域为中心、1.3 倍边长的正方形特写和 hint，交给 LoRA 按生成器的最高尺寸（1024）重绘。
4. 用 BiRefNet（matting 权重）去掉灰色背景，得到 RGBA。
5. 输出 PSD2Live 的 Layout 清单：
   - 原图作为参考图层；
   - 每个部件以原生 1024 像素铺在它覆盖的画布区域上，PSD2Live 会保留这个纹理密度；
   - 带部位词和角色自身的侧别；
   - 每层的 `split` 字段保留规划类别、提示词、区域、特写、hint 和去背景前的原始输出，不损失信息。

状态：第 1–3 步在 v7c 上实测过。第 4、5 步已实现：BiRefNet 在三张生成结果上单独验证过，效果良好；整个流程尚未端到端跑通。

## 6 教训

1. **代码处理像素会直接毁掉结果。** 第一版推理流程在可见区域贴原画像素、用灰色差阈值算透明度、按人物轮廓裁剪，结果是拼贴接缝、边缘生硬和低清。LoRA 本身一直是按整层重绘训练的，问题全部出在推理脚本。改为直接使用生成器的整层输出，加 BiRefNet 去背景之后，这些问题就没有了。这条原则同样适用于自动化流程。
2. **没有标签的类别会被乱分。** 规划器训练时背景标为忽略，结果推理时把透明背景分成了各种部件，LoRA 又照着生成色块。应该在模型层面加背景类，而不是用代码裁掉。
3. **分辨率要从数据一路贯通到推理。**
   - 训练桶封顶 512，大部件就学不到细节；
   - 推理时把 1500 像素的裙子压到 512 生成，必然模糊。
   - 但六成样本原生不足 512，所以桶要从 256 起，而不能只有大桶。
4. **规模化标注的成本可控，但结果要复查。**
   - 8 万个 mesh 的 Haiku 描述约 10 美元；
   - 子代理偶尔会每张 sheet 都从 1 开始编号、打开批次外的 sheet、交回占位结果；
   - 必须按文件逐张做完整性检查，并补派漏答的部分。
5. **内容审核要前置。** 一个来源直到逐 mesh 标注时才发现含露骨内容，导致整源剔除，并改动了训练数据。应在入库时就做来源审查。
6. **工程细节：**
   - 系统盘写满导致渲染失败；
   - 用 `pkill -f` 匹配脚本名时，误杀了执行命令的那个 shell 自身；
   - bash 会边执行边读脚本，所以不能修改正在运行的脚本，必须先停再改；
   - 节点渲染应直接写数据盘；
   - 依赖升级可能改掉权重键名（transformers 5 的 DINOv2 注意力），宽松加载会静默跳过，续训前要核对加载的键数。
7. **ai-toolkit 的几个坑：**
   - 分辨率列表里的每一档都会把全部图片编码一遍 latent。但每张图只编码到自己的原生尺寸，所以多数档的结果是重复的，只设最大档即可。
   - 参考图尺寸各异时 batch 必须为 1，否则同一批里的 latent 长度不一致，第 2 步就崩溃。要提高有效 batch，用梯度累积。
   - 崩溃后自动续训的循环要能区分「可恢复」和「必然重复」的错误。否则会把同一个错误重试到底，然后带着空检查点进入评估。
   - 显存充裕时关掉 gradient checkpointing，同样的 GPU 快了约 40%。

## 7 后续计划（按收益排序）

0. **逐层实例规划器（v4、v5 已实测，最高优先级）。** 常见 Live2D 模型有 200–400 层，拆分应当有多少拆多少。现在的规划器在两点上做不到：
   - 它是固定 30 类、每像素单标签的语义分割，同类连通区域只能拆成一块；
   - 阴影、高光、线稿与底色叠在同一批像素上，单标签表示不了。

   数据上的几点认识决定了设计：
   - **实例是图层，不是 mesh。** 蒙皮和切割把一张画切成多段（粘合处纹理坐标连续，`layer_units.py`）。模型 mesh 数中位 251，静止时可见 142，合并成图层后 130（p90 238）。按 mesh 学，等于要模型猜图上看不出的切线。
   - **粒度因作者而异。** 同样的头发，有人画 3 层，有人画 40 层，没有唯一正确答案。规划器应输出层级（部位 → 命名分组 → 单片），推理时选粒度；训练时把同组单片合成一片不算大错。
   - **角色层叠在底色上。** 约 23% 的 mesh 是阴影、高光、线稿或细节，线色分离也是常规技法。它们作为底色实例上的子层（多标签），不和底色争像素。
   - **前后穿插、碎片、遮罩只是提示。** 穿插的物体输出整体，前后两半交给 LoRA 的三种提示；碎片不作实例；遮罩只给 LoRA 当 hint，边界精度不关键，关键是哪一片、叫什么、谁在前。

   结构：骨干同 v3，逐像素多头——类别、角色（多标签）、实例嵌入（层级对比：同片强拉近，同命名组弱拉近，异组推开）、特写内的相对绘制顺序。推理时对底色像素的嵌入聚类得到单片，阈值决定粗细；角色头给出每片的阴影、高光、线稿子层；同组的片被别的片隔开时标为前后候选。数量天然没有上限，当时认为不需要查询解码器（v5 推翻了这一点，见下）。

   递归：第一级 v3 在全图上分大部件；第二级在每个大部件的特写上分组和单片（头部特写里分眼、眉、嘴、鼻，以及眼白、虹膜、睫毛）。数据审计表明，单眼和嘴的原生特写多数不足 160 像素，再细一级收益有限，所以第二级就分到底。

   训练数据：静止渲染中每个图层按绘制顺序被遮挡后剩下的像素即遮罩；类别、角色来自两轮逐 mesh 描述，按图层多数票；分组来自细分节点的同义词合并；按家族整体留出。完全被遮挡的层没有可见像素，由大部件的重绘补出。

   v4 进度（细节见第 4 节）：数据审计、导出、训练（20000 步，已收敛）、接入和端到端评估都已完成。端到端精确率 0.33、召回率 0.50。

   v4 的上限来自表示本身：每像素只归一层，完全被盖住和几乎被盖住的层找不到，被切开的层只能事后合并。遮挡统计表明，这类层约占五分之一。

   **v5** 改为查询式：200 个查询，每个查询直接输出一层的标签、可见遮罩、完整形状、顺序，以及组与部位向量。查询数在分块后不构成上限：每个图块最多 200 层，全图由多级图块拼成。被盖住的层按完整形状监督和输出，交给 LoRA 补画。

   v5 进度：
   - 数据：29,947 个特写，含随机图块和完整形状。
   - 训练：3080 上 40000 步，已收敛。
   - 接入：`plan5.py`、`split_image.py --planner5`。
   - 端到端（重叠过滤 0.8，四分之一图块覆盖全身）：精确率 0.480、召回率 0.622。

   v5 的下一步：
   - 碎片：重叠过滤后剩 161 个，主要是同一图块里一层被分给多个查询；
   - 合并：漏掉的层多半是被一个过大的查询并进别的层，例如鞋与腿成了一层，需要模型分得更细；
   - 被盖住的层：虚报多、形状碎，v5.1 加可见性头并提高「空」类权重；
   - 手臂、后发、鞋、身体的召回率不如 v4；
   - LoRA 端用完整形状作 hint 补画被盖住的层。

   LoRA 需要配合：v4 会请求单片。v7e 已经放开每组 3 片、每模型 20 个节点的上限，改为按物件与尺寸筛选全部单片；之后 hint 再改用规划器风格的粗遮罩。
1. **评估 v7e。** 训练中。它回答三个问题：高清化是否有效（3 倍、6 倍软化测试）；单片和前后分层能否按提示词选中正确的对象；低清模型降权后，低清档的质量是否下降。
2. **规划器 v3。** 背景类加逐 mesh 标签，重点看小部件。如果仍然很弱，就对眼部、口部、手部这类小部件，在头部或手部特写上做第二级规划。
3. **端到端验收。** 用新流程（整层重绘 + BiRefNet + Layout 清单）拆测试立绘，在 PSD2Live 里打开，按眼检查摆放、遮挡和清晰度。
4. **部件类别对齐。** 给 PSD2Live 增加侧发、身体、手等语义类别，或在导入时读取 `split` 字段，不需要重跑拆分。
5. **规划器的细分输出。** 目前单根发束、饰品零件这类细分节点在推理时没有 hint。可以训练规划器输出实例级区域，或交互式点选（SAM 一类模型）。
6. **训练效率。**
   - 生成训练对和节点渲染避免同时运行，或改为只增量渲染；
   - 1024 训练每步约慢 2–3 倍，可以先在 768 上验证数据改动，再上 1024。
