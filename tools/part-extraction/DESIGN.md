# 通用语义拆分：设计与规划

## 1 目标

输入一张立绘（全身或局部），输出一棵**图层树**：每个节点是一张原位、完整（含被遮挡部分）的 RGBA 图层，带语义标签和"设计意图"（它为什么单独成层）。粒度可选：从"头发"到"前发第 3 束"，再到"前发第 3 束的阴影"。输出直接作为 PSD2Live 的 PSD 输入，第一级标签沿用 `SemanticTag`（与 See-through 的类别一致）。

和 See-through 的区别：See-through 是固定约 20 类、单一粒度；这里是**层级可变粒度 + 实例（发束、饰品个体）+ 角色层（底色/线稿/阴影/高光）+ 遮挡补全**。

## 2 核心观点：Live2D 模型本身就是设计意图的标注

模型里每个 ArtMesh 都是画师的一次拆分决定，IR 里能直接读到决定的理由：

| 信号 | 来源 | 揭示的意图 |
|---|---|---|
| Part 树与名称 | 画师的 PSD 文件夹结构 | 层级、语义名称（多语言） |
| 变形器树（warp / rotation） | 绑定结构 | 运动分组：一束头发、一个饰品 |
| 参数响应（关键形） | 每个参数下网格的位移 | 运动语义：眼、嘴、眉、头角度、身体、呼吸 |
| 物理设置 | 输入/输出参数、名称 | 摇摆件；每条摆链是一个实例 |
| 剪贴蒙版 | maskedBy | 着色层附着在底色上，或"窗口"（瞳孔在眼白内） |
| 混合模式 | 正片叠底 / 加算 | 阴影、高光 |
| 绘制顺序 | drawOrder 与渲染树 | 遮挡关系，补全的必要性 |
| 不透明度关键形、开关参数 | 闭眼图、表情符号、服装开关 | 变体 |
| 纹理像素 | 图集 | 颜色、线稿与平涂 |

目前的眼部规则（瞳孔 = 跟随眼球参数）只是其中的特例。P3 的抽样检查说明逐部位写规则不可行：

- 嘴：唇层混进了覆盖嘴部的肤色补丁，有的模型唇与口内对调，还有取景错误（整张是嘴的局部或别处）。
- 头发：只有参数名含 HairFront / HairSide / HairBack 的模型能用；约三分之一的模型没有这些参数，或找不到前发。

所以需要通用的解析器。

## 3 架构

```
立绘 ──► B 规划器 ──► 图层计划（可见区域的层级分割 + 每个节点的属性）
                         │  用户可在此合并/拆分节点（DCC 工作流）
                         ▼
立绘 + 节点规格 + 可见掩码 ──► C 补全器 ──► 每个节点的完整图层
                         ▼
                   D 组装校验 ──► PSD（图层树 + 语义标签）──► PSD2Live

训练数据：Live2D 模型 ──► A 解析器 ──► 场景图 ──► 渲染（输入、ID 缓冲、各节点目标）
```

规划与补全分开，理由：

- 生成模型不擅长决定"有哪些层"，并且每次调用都很贵。
- 分割模型便宜、确定、能给出置信度。
- 计划本身就是可编辑的中间产物，用户改完再生成。

## 4 A 解析器：Live2D 模型 → 场景图

节点字段：

- `id`、`parent`，`level` 取 region / part / instance / role 之一；
- `tag`：`SemanticTag` 加细分，例如 `hair.front.strand`、`accessory.hairclip`；
- `side`；
- `role`：base / line / shadow / highlight / detail / effect；
- `blend`；
- `intent`：受哪些参数组驱动、是否需要补全、剪贴关系、所属变体；
- `meshes`：节点包含的网格。

构建步骤：

1. **骨架树**：Part 树（画师的文件夹），去掉只有一个子节点的空壳。
2. **运动签名**：对每个网格测出它在全部参数两端的位移，得到响应向量。
   - 变形器链相同、响应成比例的网格是一个刚体组，即实例候选。
   - 物理输出参数驱动的链是一个摇摆实例（一束头发、一条丝带）。
3. **角色**：
   - 有混合模式的，按模式判断；
   - 剪贴到兄弟网格、比被剪的底色暗的是阴影，亮的或加算的是高光；
   - 细长、深色、实心的是线稿；
   - 其余为底色。
4. **剪贴关系分两类**（把瞳孔规则推广）：
   - 蒙版与被剪网格运动签名相同，是"附着"（阴影贴在头发上）：目标保留剪贴，因为画师常依赖剪贴而画得超出边界。
   - 某个参数下被剪网格相对蒙版移动，是"窗口"（瞳孔/眼白、口内/嘴）：目标去掉剪贴，输出完整内容。
5. **语义标签**：
   - 先用规则：标准 Cubism 参数 ID，加中/日/英名称词典（前髪、横髪、後ろ髪、アホ毛、影、ハイライト、線、歯、舌……）。
   - 规则无法判断或彼此冲突的节点交给视觉语言模型：给它节点在角色上的高亮渲染、节点名和父节点名，让它选标签。
6. **变体**：开关参数控制的不透明度（闭眼图、表情符号、服装开关）成为变体节点。默认状态渲染一套；每个变体作为单独的样本。
7. **核验**：
   - 每个模型生成一张 HTML 图表：节点树加缩略图，标出低置信度和冲突的节点。
   - 人工修正写成按网格 ID 的覆盖文件，可以重放。

## 5 训练数据

- **姿态**：默认姿态加随机参数（头角度、眼、嘴、身体、物理输出参数）。这样同一个节点有不同的遮挡和形状。
- **每个样本的渲染**：
  - **合成输入**，做增强：风格、色调、线宽、模糊、压缩、背景、缩放。
  - **ID 缓冲**：每个像素最上层可见的网格。映射到任意层级的节点，就得到任意粒度的分割真值，供规划器训练。
  - **节点目标**：只渲染节点的网格，按第 4 节第 4 步处理剪贴，用节点自己的混合模式。
  - **节点的可见掩码**：给补全器的空间提示。
- **取景**：以节点为中心，框为节点包围盒的 1.3–2.5 倍，另加带上下文的大框。按纹理原生密度渲染、不放大，上限 1024。
- **粒度**：节点的目标等于其所有后代的并集，所以同一模型自动给出各层级的样本，规格里写明层级。
- **均衡**：按层级和标签加权采样。发束数量远多于眼睛。
- **透明度**：
  - 现在的目标铺在平灰上，丢失半透明信息（阴影、腮红）。
  - 正片叠底层铺在白底上、加算层铺在黑底上，都是精确的。
  - 普通层需要 alpha。用小实验比较两种做法：单独请求一张蒙版，或者左右两格分别铺黑底和白底，用闭式解求 alpha。

## 6 B 规划器

任务是对可见像素做层级全景分割，同时给每个节点预测：标签、角色、混合模式、是否有被遮挡部分要补全、层间顺序。

- **候选方案**：DINOv3 主干 + Mask2Former 头，在 ID 缓冲真值上训练，在 part / instance / role 三个层级各出一套结果。
- **规模**：模型小，笔记本 4080 也能训。
- **备选**：让扩散模型直接画分割图。实例颜色任意、难以解析，暂缓。

## 7 C 补全器

在现有 LoRA 上扩展：

- **结构化提示**：`Live2D layer split: keep only <标签路径> <角色> <左右>, complete including hidden parts, in place, on <背景>`。
- **实例消歧**：用第二张控制图，即规划器给出的可见掩码，或者用户的点选/涂抹。
  - 待验证：ai-toolkit 的 klein 是否支持多张控制图。这是最早要做的实验。
  - 不支持时的退路：把提示画进输入图的单独通道，或者叠加边框。
- **容量**：一个 LoRA 覆盖全部部位，补全的知识共享。类别增多时提高 rank（64–128）。还不够就换 klein 9B 或全量微调。
- **分辨率**：上限 1024。大面积的层（后发、衣服）先在低密度下补全，再分块细化。

## 8 D 组装与校验

- 按规划器给出的层序合成，与输入比较。
- **可见区域直接取原图像素**，只有遮挡区域用生成结果，保证可见部分零误差。只对上方没有半透明层覆盖的节点成立；有着色层覆盖的底色，用合成误差检查。
- 导出 PSD：组即树结构，层名映射到 `SemanticTag`，交给 PSD2Live 生成绑定。

## 9 评估

- **保留角色**（同现在）：
  - 规划器：各层级的可见 IoU；
  - 补全器：遮挡区 IoU 和颜色误差；
  - 整体：重组误差。
- **AI 立绘集**：20–50 张，覆盖多种画风，人工打分。这才是真正的目标域。
- **端到端**：PSD2Live 自动绑定后预览动作。

## 10 风险

1. **粒度没有唯一答案**：不同画师拆法不同。对策：
   - 规格写明层级，由规划器提议；
   - 训练时接受合理的不同答案；
   - 评估以较粗的层级为准。
2. **域差距**：Live2D 原画多为平涂，AI 立绘多为厚涂。对策：
   - 只对输入做风格增强；
   - 人工核验后的输出回流训练。
3. **标签噪声**：名称不可靠，视觉语言模型会出错。用核验图和覆盖文件兜底。
4. **数据规模**：约 600 个模型，去重后约 450 个角色。发束和饰品的实例数量可观；持续收集。
5. **训练权重的分发**：收集来的模型训练出的权重能否公开，由你决定。
