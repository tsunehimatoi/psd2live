# 下一条拆分路线：从商品级目标倒推

[论文](PAPER.md) · [设计](DESIGN.md) · [拆分惯例](SPLIT_PRACTICES.md) · [实战拆分](live/README.md)

状态：**设计中**（头脑风暴，2026-10-18）。拆分 LoRA 路线记为有可取之处的失败路线（[PAPER 8.3](PAPER.md#83-结论)）。本页先定义目标，再列图层要满足的细节，最后比较候选路线。约束：暂不考虑模型训练；以后要训练，只接受 3080 跑得动的低成本方案。

## 1 目标：商品级是什么

最终产物是 图 → 图层 → Live2D 模型。第 8 节的实战里，PSD2Live 已经能从拆好的图层自动生成可直播的 Rig；离商品级的差距主要在 图 → 图层。按买家验收的方式，商品级可以定义为四条：

| 要求 | 含义 | 怎么验收 |
|---|---|---|
| 静止即原画 | 默认参数下的合成画面就是原图：线、颜色、细节、比例、左右一致性都不变 | 在可见区逐像素比较，误差只来自 8 位取整 |
| 动起来不破 | 头 XYZ ±30、身体 ±10、眨眼、眼球、眉、张嘴与口型、呼吸、物理摆动的极值下，不露底、不出双线、看不到接缝和色差 | 扫参数：统计露出的纹素里缺像素的数量和接缝两侧的颜色跳变，再看图 |
| 动得够细 | 粒度达到商用模型的常见水平：合并网格后每个模型中位约 130 层（p90 约 240）；头发逐束、饰品逐件、投影随投影者动；张嘴有口腔、牙、舌 | 层数与语义覆盖，对照 PSD2Live 的标签表和拆分惯例 |
| 交付可改 | 同样的输入得到同样的输出；每个决定（归属、切线、层序、补画）都能单独修改；人工修正以语义操作为主（点选合并、拆开、画切线），不用逐像素画 | 人工修正的时间（目标待定，见第 6 节） |

成本：在本地显卡（笔记本 4080、3080）上完成，一张图几分钟到几十分钟，不租卡。

## 2 图 → 图层的细节

### 2.1 一层是什么

- 原图坐标上的 RGBA。大部件达到图集纹素密度即可；眼、嘴、小饰品要 1:1，可以带比画布更高的纹理密度。
- 每层分成两部分，并记录边界：
  - **可见区**：静止时露在外面，像素就是原图；
  - **补画区**：静止时被盖住，动起来才可能露出。
- 角色子层：底色、阴影（正片叠底）、高光、线稿。收集的模型里约 23% 的网格是这类子层，73% 的模型给脸单独做了阴影或高光层。
- 元数据：语义标签、侧别（按角色自身）、组、层序，以及单独成层的理由（有自己的参数、物理摆动、遮挡）。

### 2.2 可见像素的划分

- **不重不漏**：每个可见像素只归一层；边缘像素按 alpha 分给前后两层，合起来正好是原图。LoRA 路线的重复和缺口都违反这一条。
- **线归前者**：两个部件交界处的轮廓线属于在前面的部件（刘海压着脸，交界线属于刘海）；部件内部的线（褶皱、发丝线）属于部件自己。
- **抗锯齿反混合**：轮廓线外缘的像素混着后面部件的颜色。前面的部件要还原成"线色 + alpha"，后面的部件在线下面延续自己的底色。否则一动就出色边，之前灰差阈值算 alpha 就是这个问题。
- **半透明**：发梢渐隐、薄纱、腮红、光效都要有正确的 alpha 和颜色。薄纱袖子下的手臂要补全，纱本身是半透明层。
- **没有线的地方怎么切**：发根汇合、脸接脖子、手臂接手、裙摆分片都没有现成的线。切线要落在被盖住的地方或明暗交界处，两侧各自延伸一段，互相重叠。重叠带在两层里都是原图像素，静止合成不变，动起来不开缝。
- **细小部件**：虹膜高光、下睫毛、几个像素的星饰，本来就是一组像素。归属对了就是一层，不需要生成。

### 2.3 补画

- **范围**：至少覆盖 Rig 动起来会露出的地方；能便宜地补出完整形状的就补完整。会露出多少不用猜：PSD2Live 可以按生成的 Rig 扫参数，逐层算出哪些纹素在某个姿态下可见，下文称为露出图。
- **形状**：靠几何与解剖先验：
  - 虹膜是椭圆；
  - 被盖住的头顶是对称的蛋形，比头发外轮廓小；
  - 脸型沿可见的下颌线延续；
  - 躯干在手臂下延续；
  - 后发在头和脖子后连成一片。

  左右成对的部件，可以用露得多的一侧镜像补另一侧。
- **内容**：底色、明暗带、图案都延续下去；线只画在露出时应该有轮廓的地方；补画区和可见区的接缝放在上层边缘之下，静止时被盖住。
- **必补清单**（Live2D 惯例）：
  - 五官、刘海、侧发下的脸部皮肤：眨眼、张嘴、刘海摆动时才不露底；
  - 睫毛下的眼白，眼皮下的完整虹膜；
  - 刘海下的眉毛，下巴下的脖子，侧发下的耳朵；
  - 头和脖子后的后发内侧；
  - 饰品、手臂、头发下的衣服：补衣服，不补裸体；
  - 袖子、裙子下的手臂与腿；
  - 每束头发在相邻发束下的发根。
- 收集的模型里，约五分之一的层在静止时完全或几乎看不见，只能靠补画或生成。

### 2.4 原图里没有的状态

- **张嘴**：口腔、上下牙、舌。闭口的原图无法靠变形得到（见 [PSD 素材与命名](../../docs/zh/spec/PSD_LAYER_SPEC.md#部件分层)）。
- **闭眼**：上睫毛下压，眼白和虹膜被裁掉，下面的脸部皮肤要补好；画风需要时另画闭眼线（`EYE_CLOSE`）。
- 可选：笑眼、腮红强度、泪等表情差分。

### 2.5 结构

- **层序由实际遮挡决定**。穿插的物体要拆成前后两片，例如领口绕过脖子、头发绕到肩前、飘带绕过身体。
- **投影归投影者**：刘海在脸上的影子、下巴在脖子上的影子、手臂在身上的影子要随投影者动；形体自身的明暗留在本层。
- **成组与成对**：
  - 头部组、身体组、发束的物理链；
  - 左右成对的部件取景和尺度一致，避免大小眼。
- **粒度分级**：Rig 必需的约 40–60 层 → 常见的约 130 层 → 精细的 200–400 层（逐束、逐件、角色子层）。粒度是一个参数，不是每层一个手工 hint。

### 2.6 过程

- 确定：除了可选的生成补画，同样输入得到同样输出。
- 可改：所有决定存成数据，改一处不用重跑别处。
- 可测：测静止合成的误差，在露出图上查露底和接缝；只把出问题的层交给人看。

## 3 回看：每条路线败在哪

| 路线 | 做法 | 败在 | 根源 |
|---|---|---|---|
| 手绘 SVG | 照参考图画矢量部件 | 达不到原画细节，补画不可信 | 绘制能力 |
| 整件重绘（ComfyUI 逐组剥离） | 生成器逐组去除、逐件重画 | 每次去除都重画整张，颜色漂移、细节丢失 | 生成器拥有可见像素 |
| 规划器区域内贴原画 | 区域内贴原图，灰差阈值算 alpha，按轮廓裁剪 | 拼贴接缝、边缘生硬、残留 | 归属由粗遮罩决定（规划器精确率约 0.5） |
| 拆分 LoRA | 每层从特写整张重画 | 重复与缺口、粒度靠 hint、细小部件做不到、要人工挑；大小眼、头顶变稀 | 生成器拥有可见像素，且每层独立 |
| See-through | SDXL 一次联合生成约 23 层 | 补方后缩到 1280²，竖长全身图里人物只有几百像素宽；类别固定；细线变糊；后处理仍有贴像素和按连通域切分 | 联合生成的像素预算和固定类别 |

所有失败都指向同一个根源：**可见像素归谁，由一个低精度的来源决定**，要么是粗遮罩，要么是生成器的重新诠释。画面里最精确的边界信息，也就是画师自己画的线和色块，一直没有被用上。

项目里两条看似矛盾的记录其实都对：
- [LAYOUT_AI_ASSIST](../../docs/zh/spec/LAYOUT_AI_ASSIST.md#一次失败的尝试已撤回的结论)：40 多个部件全部整件重画，单件可用，拼起来细节漂移、缺口 11.7%。结论是"保留母版可见像素、只补被遮挡部分"更好；遮罩补画失败，是因为接缝落在了仍然可见的地方。
- [PAPER 第 6 节](PAPER.md#6-教训)第 1 条：在规划器区域里贴原画、按阈值算 alpha，出现拼贴接缝。

失败的是"用粗遮罩切"和"让生成器重画看得见的部分"。还没试过的是：**沿画面自己的线和色块切，接缝放在上层下面，只在看不见的地方新画。**

## 4 候选路线

### A 像拆分师一样拆（推荐）

拆分师的做法是沿线稿选区、复制可见部分，再在下面补画。程序化后分九步：

1. **线与色区**：
   - 提取线稿，包括彩色线（按局部对比度判断，不只取暗色）；
   - 非线像素按线围成的封闭区域分块（陷球填充一类方法，能跨过线上的小缺口）；
   - 每块内再按色调分出底色、阴影、高光。

   赛璐璐和半赛璐璐立绘的线与色块本来就是封闭的。这一步给出全图最细的原子区域，边界跟着画师的线走，精度到亚像素。
2. **归属**：
   - 规划器 v5.2 对每个原子区域按像素投票，给出语义和实例。它的错误多在边界，按区域投票正好能消掉；
   - 轮廓线隔开的是不同实例；内部线（一端悬空的褶皱线、发丝线）不隔开；
   - 按层级合并到目标粒度。

   规划器只决定"是什么"，不决定边界在哪。
3. **线与边缘**：轮廓线归前面的部件；外缘像素反混合成"线色 + alpha"；后面的部件在线下延续自己的底色。
4. **层序**：
   - 线稿的 T 形交点：一条线止于另一条线时，止住的一方在后；
   - 再结合拆分惯例统计的层序先验和规划器的顺序；
   - 遮挡关系成环时（例如领口绕脖子），把其中一层拆成前后两片，PSD2Live 已有[前后分层](../../docs/zh/guide/DEPTH_SPLIT.md)。
5. **角色子层**：
   - 同一部件内按色调分出阴影与高光；
   - 紧贴上层边缘、顺着边缘走的暗色带判为投影，归投影者（额头上的刘海影子随刘海动）；其余留作本层明暗；
   - 底色乘阴影（正片叠底）仍精确等于原图。
6. **补画范围**：
   - 先按几何与先验补出每层的完整形状，这一步只产生遮罩；
   - 用完整形状生成 Rig，扫参数，得到每层的露出图。

   SVG 试验留下的"结构草图"（每块区域被什么盖住、转头会露出什么），在这里由层序和露出图自动得到。
7. **补画内容**：只在露出图内、且静止时被盖住的地方新画：
   - 结构复杂的区域（头发内侧、饰品下的衣服花纹）交给生成器局部重画。你测过 SDXL 动漫底模加 ControlNet 补遮挡区最贴原画风格；LoRA v7e2/v7e3 的整层输出可以作形状和内容参考；
   - 平涂区域（五官下的皮肤、眼白）按边界颜色延续，或同样交给生成器（第 6 节决定）；
   - 左右成对的部件用露得多的一侧镜像。
8. **新状态**：张嘴继续用 Klein 编辑出张嘴图，再用同样的方法拆出口腔、牙、舌；闭眼由 Rig 下压上睫毛，下面靠第 7 步补好的皮肤。
9. **验收**：静止合成与原图逐像素比较；扫参数，查露出图里缺像素的地方和接缝跳变；只把有问题的层交给人看。

它对 LoRA 路线四个问题和 star_lan 测试里提出的问题的处理：

| 问题 | A 的处理 |
|---|---|
| 每层独立补画，重复与缺口 | 可见像素全局划分，不会重复；补画只在被盖住处，静止时不会有缺口；动起来的缺口由露出图找出来补 |
| 粒度靠人工 hint | 原子区域自动给出最细粒度，规划器只投票决定语义；几百层不需要几百个 hint |
| 细小部件 | 高光、下睫毛、小饰品就是一组像素，归属对了就成层；高光下面的虹膜按椭圆补 |
| 没有确定性 | 除生成补画外全部确定；生成只在看不见的地方，一般不用逐层挑 |
| 大小眼、头顶变稀 | 可见像素就是原图 |
| 前发混入皮肤 | 刘海之间露出的皮肤色区归脸 |
| 手臂与身体、身体与蝴蝶结重复 | 同第一行 |
| 裙子顶部分进上衣 | 腰带色区按语义投票归裙子；投错了在区域上点选改正 |
| 前发、侧发、后发、呆毛分错 | 归属结合层序：在脸前面的是前发或侧发，在脸后面的是后发；再按位置分出侧发和呆毛 |
| 嘴 | 闭嘴照搬原图；张嘴的口腔仍靠生成，和之前相同 |

**复用**：
- 规划器 v5.2：语义、完整形状、顺序；
- LoRA v7e2/v7e3：复杂补画区的参考；
- Klein 张嘴编辑；
- Layout 清单与 `LayoutRigCheckTool`；
- PSD2Live 的前后分层与绘画系统；
- 拆分惯例统计。

不需要训练。

**风险**：
- **无线稿或厚涂画风**：原子区域不可靠。先只做有线稿的赛璐璐和半赛璐璐，这是 Live2D 立绘的主流。
- **头发**：发根汇合处没有线，逐束切分要沿发流方向找切线，是最难的一块。
- **投影判定**：规则会误判，需要可视化检查。
- **大面积补画**：后发内侧、长发下的上衣仍依赖生成质量，不过只在动起来时露出一部分。
- **输入分辨率就是上限**：1024 级的立绘（例如 star_lan）要先整图超分一次再拆。

### B 半自动工作台（A 的产品形态）

A 的每一步都是数据，可以放进 PSD2Live 的 Layout 工作区：
- 在原子区域上点选合并、拆开，画切线，改层序；
- 查看露出图，对选中的补画区触发局部生成。

[LAYOUT_AI_ASSIST](../../docs/zh/spec/LAYOUT_AI_ASSIST.md#绘画与拆分) 设计的"绘画与拆分"（魔棒、沿线拆分、按连通块拆分）是它的一部分。如果商品级允许少量人工，这是最现实的交付方式。

### C 接收画师的工作 PSD（输入分级）

委托稿通常附有画师的分层工作文件：线稿、底色、阴影、高光分开，有时已按部位分组。A 的第 1、3、5 步会大幅简化。产品上可以把输入分成三级：扁平图、画师工作 PSD、已拆分 PSD。

### D 保留"整层由生成器画"，换原生高分辨率编辑模型（对照）

用原生 2K–4K 的新编辑模型按 1:1 特写逐层生成，前后依次剥离。分辨率问题会缓解，但重复与缺口、设计漂移、逐层挑选都还在，和整件重绘、拆分 LoRA 是同一个上限。可以低成本做一次对照，不建议作主线。

### E 联合分解模型（See-through、Bunraku 一类）

一次去噪联合生成全部层，层间一致性好。缺点：
- 每层的像素随层数增加而减少，类别固定；
- 要重训，算力和数据远超 3080 的预算；
- 训练数据的许可不明。

排除。

### F 自动矢量化

把线和色块转成矢量，补全变成曲线延长。渐变、纹理、厚涂会失真，和暂停的 SVG 路线一样达不到原画细节。只把其中的几何部分（轮廓延长、切线拟合）用进 A。

### G 用视频生成补遮挡

让视频模型把角色动起来，从帧里取被挡住的内容。帧间一致性和画风漂移不可控，算力也不适合 3080。排除。

### 低成本训练（以后需要时，3080 可跑）

- **原子区域归属分类器**：冻结特征上的小网络，训练几十分钟到几小时。
- **完整形状补全**：输入可见遮罩和局部图，输出完整遮罩；256–512 的小 U-Net。
- **补画区局部重画 LoRA**：SD1.5 或 SDXL 动漫底模，只在被盖住的区域计算损失。

这些都可以先用规则和现成模型代替，确实成为瓶颈时再训。

## 5 与现行原则的关系（需要决定）

PAPER 和现行工作方法里有一条原则："图层是生成器的完整输出，代码不处理图层像素"。它禁住的粗遮罩切图确实不该再做。方案 A 需要把它改成有边界的版本：

1. 可见像素来自原图；归属只由画面自身的结构（线稿、色块、抗锯齿反混合）决定，不用规划器或任何粗遮罩切像素。
2. 代码不画看得见的像素。
3. 新画的像素（补画、新状态）只出现在静止时被盖住的位置，或原图里没有的状态里。
4. 静止合成必须与原图一致，可以逐像素测出来。

如果保持原来的原则，就只剩 D，它和已经失败的两条路线是同一个上限。

## 6 需要决定的事

1. 是否接受第 5 节的原则修改（第 7 节的实验需要它）。
2. 自动化程度：全自动出草稿加少量语义级人工修正（B），还是必须全自动。
3. 画风范围：是否先只做有线稿的赛璐璐和半赛璐璐。
4. 补画区的来源：只用生成器，还是平涂区域允许按边界颜色延续。

## 7 第一个实验（不训练）

在 star_lan 的头部（眼、眉、嘴、鼻、耳、刘海、侧发、发饰）上，不加任何手工 hint 跑 A 的第 1–5 步，再做第 6–7 步的简化版：露出范围先按 Rig 的最大位移外扩代替。

**产出**：
- 原子区域图、归属图、逐层平铺图；
- 静止合成误差；
- 眨眼、视线、转头的姿态图。

**成功标准**：
- 静止合成与原图逐像素一致；
- 虹膜高光、下睫毛、耳坠星饰单独成层；
- 刘海逐束成层，不需要 hint；
- 姿态图不露底；
- 头部层数不少于 LoRA 精细拆分第一批里的头部部分。

如果规划器评估用的留出模型渲染图还在，再用 `plan4_eval` 的同一口径测按单片的精确率、召回率，和规划器 v5.2 的 0.502 / 0.634 直接比。

**成本**：以本地 CPU 为主，规划器在笔记本 4080 上推理；不训练，不租卡。

实验结果决定两件事：是否把 A 推到全身，以及 B 的工作台是否值得做。
