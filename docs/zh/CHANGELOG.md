# 更新日志

[文档目录](../README.md) · [下载](https://github.com/tsunehimatoi/psd2live/releases)

只记录使用者能感知到的变化。v1.4.2 及更早的版本见 [Releases](https://github.com/tsunehimatoi/psd2live/releases)。

## v3.3.1 · 2026-10-10

### 新增

- **崩溃后恢复未保存的编辑**：程序崩溃或内存不足被关闭后，下次启动会询问是否恢复上次未保存的编辑；恢复后作为未保存的工程打开，保存即可保留。
- **旧版本合并结果的修复提示**：工程中有旧版本合并、新版本会合并成不同结构的生成结果（可能表现为弯曲小臂时手臂脱离肩膀、网格不随上身转动）时，编辑画布顶部给出提示，可直接“更新生成结果”或“预览变化”；修复后之后的编辑都会保留。MCP `workspace_inspect` 的再生成检查同样列出这些位置（`REGENERATION_REPAIR_AVAILABLE`）。
- **历史面板“回到最新”**：一键检出最新版本并滚动到它。

### 改进

- **参数名称不再被截断**：参数面板的名称列默认更宽，分隔线常态下也淡淡可见。
- **物理预设按组记忆**：预设选择从当前组设置对应的预设开始，每组各自记住所选预设。
- **窗口记住大小**：窗口在上次关闭时的大小与最大化状态下居中打开。
- **导出进度**：导出尚未报告进度时进度条显示为不确定状态，而不是停在 0。
- **内存占用**：程序按本机内存的一半设置上限，不再固定占用 8 GB；`gradlew run` 时 Gradle 自身也只占 4 GB。
- **工程更小**：保存时不再带上 MCP 工具渲染的视图图片（此前可能有数百张、几十 MB）；旧工程照常打开。
- **GIF 颜色更准**：每个动作按自身画面生成调色板，并默认开启抖动（导出设置 `dither` 可关闭），不再出现偏色与色块。
- **纹理预算提示（MCP）**：换成更高密度的图片后超出纹理页预算或被降低密度时，`atlas_get`、纹理编辑结果和批量编辑都会提示，并给出 `atlas_pack`、`atlas_set_budget` 的处理方法。
- **MCP 失败原因更清楚**：`view_sample_motion` 在运行时无响应时给出原因和替代方法，不再显示为“已取消”；`model_apply_preset` 在烘焙与模拟差距较大或替换了生成的头发摆动时给出警告；`motion_seed_builtin` 在缺少骨架时提示先用 `skeleton_auto` 创建。

### 修复

- **骨架与再生成合并**：先重建网格（如袖子）再创建骨架，或顺序相反时，弯曲小臂不再让手臂脱离肩膀、骨骼不再重复带动袖子；被骨架接管的变形器下的用户网格随之移到新的父级并保持画布位置；绑定在骨骼范围外的网格也会被蒙皮。“工具 → 更新生成结果”会按新规则重做旧版本的合并，重复执行不再产生新的提交。
- **分层 PSD 导出高清图层**：替换为 2 倍分辨率的图层导出时按画布尺寸缩放，不再只显示左上四分之一。
- **嘴型**：闭嘴旁的张嘴图层及唇线在嘴张开前不再多出一条线。
- **文本框快速输入不再丢字**：导出文件夹等输入框快速输入时不再丢字符，退格也不再需要按两次；导出文件夹必须是绝对路径。
- **精灵图**：帧数与网格尺寸不匹配时在渲染前就报错，不再等全部帧渲染完。
- **从源码运行**：rustc 版本低于 1.87 时跳过 Rust 运行时并给出提示，不再导致 `gradlew run` 失败。
- **MCP**：长时间运行时不再保留全部请求结果（含图片），只保留最近 512 个；MCP 对话框中的命令示例隐藏令牌。

## v3.3.0 · 2026-10-10

### 新增

- **导入图片重做**（`tml` 示例实测：导入 1024×512 图片约 0.5–1 秒，之后每次移动、缩放、旋转提交约 40–60 毫秒，此前拖动的每一帧都要重建整个模型）：导入的图片一次提交就带着自己的网格，直接用变换工具移动、缩放、旋转，拖动时与其他对象一样流畅；不再有逐帧重建整个模型的“放置面板”，撤销即取消导入。图片挂到任意变形器下之后仍可随时再移动，像素从不重新采样。
- **图层面板显示像素去向**：鼠标停在图层名上显示原图尺寸、纹理块尺寸（原图的百分比）、在画布上显示的尺寸、顶点数，以及是否为导入图片、是否整体变换过。
- **网格 ID 不再随分类或兄弟图层变化**：改图层分类、增删图层前，所有现有网格的 ID 被固定下来；此前改分类会给网格改名并重新编号同类图层，再生成后在旧网格旁多出一个新网格（“幽灵”网格），删除一个图层也会让同类图层的网格换号。
- **删除图层改为真删除**：删除图层时它的像素和网格一起离开工程（连同引用它们的遮罩、Glue、路径和权重），PSD 图层同时退出生成输入，不再在幕后继续影响变形器框架；撤销即可恢复，不再有“全部恢复”。旧工程中软删除的图层仍可恢复。MCP `layer_soft_delete` 改为 `layer_delete`。
- **网格重建按钮与覆盖提示**：网格面板显示图层的顶点数和边长（画布单位），并提供“按当前像素重建”（MCP `layer_mesh_rebuild`），关键形与绑定迁移到新网格；绘画或换图后有像素落在网格外时，面板提示有多少比例不会显示。移动过的图层重建网格后保持原位。
- **图层整体变换（`layer_transform`）**：任何图层（导入的或 PSD 的，有无父级与绑定）都可整体移动、缩放、旋转；像素、纹理与纹理坐标不变，不触发再生成，再生成后位置保留。选择模式拖动整个图层时即提交这一操作，绘画会对齐到图层的新位置，旋转过的图层也能直接在画布上画：笔触落在图层自己的像素上，矩形、椭圆随图层一起转。在缩放过或像素密度与画布不同的图层上绘画时，画笔、铅笔、橡皮与形状的大小自动换算为该图层的像素数，屏幕上看起来与之前一样大（例如高分辨率导入图片不再一进入就只剩一个小点），光标圈与实际笔触大小一致。纹理面板的位置、尺寸字段改为同一操作，对任何图层都可用。
- **按导出目标导出（MCP）**：`project_export_target` 与“文件 → 导出为”相同，按一个目标（运行时、网页、图像与视频、分层 PSD 等）导出已提交的模型，返回文件与损失。
- **模拟障碍物（MCP）**：`simulation_put` 的 `obstacles` 给模拟体加跟随其他网格的圆形或胶囊障碍物（手臂、腿、躯干），头发与布料被挡在外面；参与烘焙，并导出到 p2lrt 与网页。
- **预览生成结果更新**：“工具 → 预览生成结果更新”先告诉你更新会不会改变模型、有哪些项目需要查看，不改动工程。
- **再生成试运行（MCP）**：`workspace_preview_regeneration` 在提交前试运行改设置、改分类、拆分、更新生成等会重新生成 Rig 的编辑，报告合并时无法干净保留的内容与将增删的对象，不改动工程。
- **导出 Cubism Animator 工程（.can3）**：导出 CMO3 时，模型的动作（预设动作与自己制作的动作片段）另存为同名 `.can3`，每个动作一个场景，在 Cubism Editor 的 Animator 中与 cmo3 一起打开即可继续编辑、再导出 motion3。参数曲线、部件透明度、整体透明度、淡入淡出、循环与事件都会写入；眨眼与口型效果曲线 Animator 没有对应轨道，会在导出报告中列出。can3 按文件名引用 cmo3，两者需放在同一文件夹并来自同一次导出。

### 改进

- **改生成设置不再混入改写**：同一次编辑既改生成设置（或分类）又改写较早的 Rig 编辑时会被拒绝并提示分开提交，而不是把旧编辑悄悄重放到新的生成结果上。
- **拆分后部件继续跟随生成**：拆分图层（连通块、多边形、前后分层）时，部件在原层的位置参与自动生成，你在原层上做的关键形、路径、权重与胶水带到部件上；之后改脸部设置、站姿、骨架或分类，部件也会更新。拆分不再因个别条件退回旧格式。
- **改生成设置与分类更稳**：修改脸部特征、嘴型、头身强度、图层分类等生成设置时，新的生成结果与你已有的编辑直接合并并固定保存，不再在每次打开时重新推演，旧编辑不会因为生成规则变化而失效。
- **长编辑历史不再变慢**：编辑生成的模型时，模型每隔一段（第一次编辑、之后每 32 步）自动固定保存一次，之后的提交、撤销、重做、拖动只在最近的固定点之后重算，与历史长短无关，也不再为此重新生成整个基础模型；模拟烘焙同样不再等待基础模型生成。这样编辑过的工程会以新的修订格式保存，旧版本程序无法打开。
- **旧工程只重算一次**：较早版本保存的、带旧拆分记录或生成迁移记录的工程照常打开；第一次编辑时当前模型被固定保存下来，此后不再按旧记录重放，打开与编辑更快、更稳定。旧拆分的部件作为你自己的网格保留。
- **选择模式移动、缩放导入图片**：在选择模式下拖动或缩放导入的图片（未旋转、未绑定动作、处于默认姿态时），改的是图层在画布上的位置和大小，图片自身的像素保持不变；进入绘画模式时图层不再跳回导入时的大小。已绑定动作、旋转过或网格已单独编辑过的图层仍按原来的方式变形网格。
- **绘画笔刷按部件自身像素计**：笔刷、铅笔、橡皮和形状的 px 数按所画图层自己的像素计算，缩小显示的高分辨率图层上 16 px 的笔刷就是图层上的 16 个像素，最小可以画到单个像素。
- **打开与保存工程显示进度**：打开或保存 `.psd2live` 时，底部状态栏显示当前步骤（解压、读取历史、构建模型；记录编辑、写入历史与素材、打包校验）和百分比，大工程不再像卡住一样没有反馈。
- **模拟求解更快**：头发与布料模拟的弯曲约束每次只算一次角度，参考模拟、实时模拟与烘焙快约三分之一；运动结果与之前有细微差别，编辑器与 PSD2Live 运行时（含网页播放器）仍逐帧一致。
- **模拟起步更稳**：物体静止时的形状校准得更准（同样耗时，与画出的形状相差约为原来的三分之一到二分之一），参考模拟和实时预览重置后的轻微晃动从约 3–6 px 减到 1–1.5 px（裙子、上衣、长发），烘焙的训练数据里混入的这段晃动也随之减小。

以上两项改变了模拟结果，已有的烘焙都会显示为过期，重新烘焙即可。

### 移除

- **`asset_import_png` 的 `spatial_reference_id`**：导入只接受 `asset_prepare_reference` 返回的 `reference_id`。
- **工具 → 升级拆分记录**（以及 MCP `source_upgrade_split_records`）：新的拆分都直接参与生成，旧工程在第一次编辑时固化，不再需要单独升级。拆分任务结果不再带 `record_version` / `record_version_reason`。

### 修复

- **导出与预览一致**：“导出 Live2D 模型”（及 MCP `project_export_model`）直接写出编辑器里已提交的模型，不再从源图重新生成一遍；导出的 moc3 与预览逐字节相同，重新打开的工程导出也不再先生成基础 Rig。
- **烘焙摆动**：编辑过的模型上删除摆动并选择“保留为关键形”（`swing_delete bake=true`）不再报错。
- **导入图片**：保存过纹理集排布后，放置或缩放高分辨率导入图片不再报“does not fit an atlas page”，放不进一页的图块单独缩小；导入的图片可以在层级面板里拖到其他父级下（此前报 Object not found）；头部倾斜的角色上，把图片导入到头部旋转及其下的变形器不再报位置偏移。
- **拆分后修改图层分类**：拆分过图层、又在绘画时重建过网格的工程，修改任意图层的分类（包括导入图片的预设）不再报“Art primitive part was not generated”；在头发模拟等预设之后导入的图片也能修改分类（此前报 Mesh creation artwork is missing）。
- **按网格形状排布的纹理集**：在图层上绘画超出原网格范围后，与之嵌套的相邻图块不再互相覆盖、贴图不再显示异常，也不必重新排布：绘画后的图块占用新画到的单元格，与之冲突的邻居移到空位；因此被挤到空位的图块也只写入自己的网格单元格，不再用整块矩形盖住邻居。
- **层级拖放改父级**：在层级面板把网格拖到另一个变形器下（或在检查器里改它的变形器）时，网格留在画布原位，关键形与混合形随之换算。此前网格保留原局部坐标，从根层级或旋转变形器拖进 Warp 会飞出画布、从 Warp 拖到根层级会缩成一点，导入后在选择模式中移动或缩放过的图片挂到变形器下即直接消失。

## v3.2.0 · 2026-10-09

### 新增

- **运行时 C 接口 1.1**：在自己的程序或引擎里播放导出模型时，同一角色加载多份可共用一份模型数据；可以按层推进动作、表情、行为与物理，并在动作之上叠加自己的参数（例如面捕）；可以读取部件、设置部件透明度，读取隔离部件的绘制分组与合成方式以及透明度合成模式；可以读取参数名称与类型、参数面板分组、动作片段的时长与分组，并跳转动作进度。头文件写明了完整的绘制规则（预乘、乘算/屏幕色、遮罩、剔除方向、各混合模式公式）和多线程约定。只用到旧接口的程序不受影响。
- **运行时 C 接口 1.2**：动作可以分层同时播放并带优先级（与 Cubism 的动作管理器相同）；动作可以带事件（Cubism 动作的用户数据），也可以驱动部件透明度、整体透明度以及眨眼、口型效果，单条曲线可有自己的淡入淡出；多个表情可同时生效；可设置整体透明度，并用自己的颜色替换网格或部件的乘算/屏幕色；物理支持风力、稳定化（从静止状态开始而不是先甩一下）和纵向（Y）输入输出；眨眼间隔、呼吸与视线幅度可调；口型可直接由音频样本驱动。导出 moc3 时，动作的事件、部件与模型曲线和曲线淡入淡出同样写入 motion3。
- **运行时内置软件渲染**：C 接口 1.3 新增 `p2l_render`，不写渲染代码也能把模型画成图像（遮罩、隔离部件组、全部混合模式与剔除，和编辑器导出图像逐像素一致），适合 C/C++ 程序、引擎插件和生成缩略图。
- **运行时的 C#（Unity）绑定与 Android 构建**：新增由头文件生成的 C# 声明、Unity 示例组件、C/C++ 示例程序，以及为 Android（arm64-v8a、armeabi-v7a、x86_64）构建运行时库的脚本。
- **Windows ARM64 与 Linux arm64 安装包**：新增 Windows ARM64 的便携版 ZIP 与 EXE（不含 Cubism 原生预览，Live2D 未提供该平台的 Cubism Core，预览使用 PSD2Live 运行时）和 Linux arm64 的 Deb（Cubism 原生预览使用 Live2D 实验性的 arm64 Core）。两者尚未实机测试，只支持 OpenGL 3.1 的 GPU（如树莓派）上画布可能无法绘制。
- **运行时 C 接口 1.4**：可以只更新每帧真正变化的网格（与 Cubism 的 dynamic flags 相同），接收运行时的错误日志，并让运行时使用宿主自己的内存分配器。

### 改进

- **模拟烘焙改为逐个输入驱动，更贴近模拟、更快**：烘焙先从 Rig 读出每个输入带动物体多远，几乎不带动的输入（如裙子上的头部转动）不再参与，用户动它们时物体也不会莫名晃动；让物体上下移动的输入自动归入上下参数。每个输入随后单独做阶跃和扫频，摆锤里每个输入都得到让物体按它的方式运动的影响度：以前所有输入在同一段动作里随机运动，`tml` 后发上身体左右转动几乎不被摆锤读到，跟随鼠标时导出的摆幅只有模拟的两成，现在与模拟相当。模型预设的后发、前发烘焙在没见过的动作上普遍更准，耗时从约 4–13 秒降到 2–7 秒；布料与上下参数仍偏弱。已有烘焙不会过期，重新烘焙即可使用新方法。
- **烘焙显示视觉检查**：烘焙节先显示在没见过的动作上导出与模拟的摆幅之比、滞后、回落和抖动，看得出差别时以警告色显示，R² 退为次要。输入节显示每个输入带动物体多远，被剔除的输入可勾选「保留」。
- **对比烘焙与参考模拟**：物理体编辑区新增「对比」节：参考模拟可显示为代替导出、只显示导出或叠影（半透明叠在导出上）；「并排」打开两张预览画布分别显示导出和参考；选一个动作「播放」时参考模拟与导出的摆锤一起从静止开始，「检验」在后台用该动作给出视觉检查。
- **参与训练的动作**：「高级」里可让模型自己的动作（用户动作或内置动作）按权重参与烘焙训练，适合主要靠少数固定动作驱动的模型。
- **MCP**：`simulation_put` 新增 `force_inputs` 与 `training_clips`；烘焙摘要返回每个输入的读取结果（`inputs`）与视觉检查（`visual`）；新增只读任务 `simulation_compare`，按动作对比烘焙结果与参考模拟。
- **导出图像与视频按编辑器合成**：导出的 PNG、GIF、视频帧和逐姿势 PSD 现在会把隔离部件作为整体图层合成（含分组的不透明度、乘算/屏幕色、遮罩和混合模式），全部透明度合成模式（atop、out、conjoint、disjoint）也按编辑器的方式绘制，绘制顺序组按部件的绘制顺序排序；开启了剔除的网格只画正面。

### 修复

- **拆分或开启头发模拟之后创建的骨架能让手脚动起来**：在开始界面拆分了图层或开启了头发模拟的工程里，之后创建或修改骨架，骨骼虽然显示，但不会生成手臂和腿的参数，导出的模型与挥手、欢呼等动作里手脚都不动；现在骨架会正常烘焙进模型。设置里直接开关头发模拟等改动同理。在受影响版本中做过并保存的这类修改，打开工程后执行「工具 → 更新生成结果」即可补上。
- **骨骼自动胶水恢复**（v3.1.0 起失效）：把肢体拆成多段（例如腿与鞋分左右拆分、或袖子在肘部切开）再启用骨架时，接缝上的自动胶水（`GlueSkel__…`）消失，后拆分的部件也不再挂到骨骼下、不随骨骼转动。原因是第一次拆分之后，之后的拆分校验没有考虑拆分新生成的成对 Warp，被退回旧版拆分记录，而启用骨架时的合并又不会把骨架给旧版拆分部件的蒙皮与胶水带过去。两处都已修复：新的拆分照常写新版记录，带旧版拆分记录的工程启用骨架时部件也会蒙皮并自动上胶水。已在 v3.1.0–v3.1.2 中启用骨架的工程，撤销到启用骨架之前再重新启用即可恢复。
- **开启五官位移等生成设置之后创建的骨架不再让网格炸开**：在开始界面选「完整」预设（或之后改了五官位移、头部/身体强度等生成设置）的工程里再启用自动骨架，骨架不会蒙皮任何网格（欢呼等动作里手臂不抬起），而尾巴在尾巴摆动时会变成铺满整个画面的大三角形。原因是生成设置变化后网格挂到了生成变形器的改名副本下，启用骨架时的合并把每个网格都当成用户改过父级、保留原位，却又带上了骨架在骨骼空间里做的姿势混合形。现在合并按改名后的变形器对齐，网格正常蒙皮；保留用户父级的网格不再带入在别的父级空间里生成的混合形。已受影响的工程，撤销到启用骨架之前再重新启用即可。
- **导出帧中的「加算（发光）」**：按编辑器的 W3C 加算绘制，不再按 Cubism 旧式加算绘制。
- **快速切换动作不再跳变**：网页播放器和运行时中，上一个动作还在淡出时再切换动作，最早的那个动作会被直接丢掉，画面会突然跳一下；现在每个被替换的动作都会完整淡出。
- **多个角色不再同时眨眼**：同一程序里加载多个角色时，它们的眨眼时机以前完全相同，现在各自错开。
- **运行时出错不再让编辑器闪退**：PSD2Live 运行时（p2lrt）求值某个模型时若内部出错，以前会让整个程序直接退出；现在只是该模型停止响应：软件预览自动改用编辑器自己的求值器，运行时预览后端与导出报告出错原因，程序继续运行。接口不匹配的运行时库（例如经 `PSD2LIVE_RUNTIME` 指定的旧版本）不再被加载，改用编辑器求值器。

### 改进

- **统一的网格显示**：各模式下可编辑的点与线采用同一套外观，颜色含义固定：浅色为结构，强调色为选中，白圈为悬停，红圈为笔刷将推动的点。所有形变笔刷在悬停时就标出会受影响的顶点，与权重笔刷一致；选择笔刷标出会选中的点。Warp 控制点改为方点，与圆形的网格顶点区分。显示栏的网格开关只画网格线，正在编辑的网格和 Warp 不再被重复绘制。
- **统一的 GPU 渲染**：编辑画布、纹理集页面和两种预览都在窗口自己的 OpenGL 上下文里绘制，当帧显示，不再每帧把整幅画面读回内存再上传，平移、缩放和播放不再落后一两帧。界面因此在 Windows 上改用 OpenGL 渲染。Cubism 预览建议重新构建 `native/live2d_renderer`，否则每次修改都会从临时文件重新加载模型。

### 修复

- **在模拟与摆动参数上打键**：可以像 Cubism 中使用物理输出参数一样，让其他网格或 Warp 在模拟、摆动参数上打键，也可以改这些参数的名称和范围；此前会报「参数不在模型中」，部分操作（通道关键形、在默认值处新建轴、删除生成的键、在层级里改名）不报错但提交后结果丢失。用到的参数从此属于工程，删除对应的模拟或摆动后仍保留。
- **删除摆动所作用的 Warp**：摆动随之去掉这个目标，没有其他目标时连同它的参数和物理组一起移除，不再留下不带动任何东西的摆动；其他原因导致摆动失效时（例如重新生成后目标不存在），物理面板中该摆动的物理组下会显示原因。
- **生成关键形上的贝塞尔与 MCP 变形**：在摆动、模拟生成的关键形上用贝塞尔编辑或 MCP `rig_deform` 不再报错，与画笔变形一样作为生成结果覆盖保存；按住 Ctrl 保留子级、复制关键形、增删生成器的键无法保存为覆盖，现在编辑时直接说明原因，不再在提交后丢失。
- **改了生成设置后工程打不开或报错**：开启头发模拟、启用或调整骨架、拆分图层等会改变自动生成结果的操作，此前要把整条编辑历史在新的生成结果上重放，引用已不存在的变形器或顶点的编辑会让整个工程报错（例如“Art primitive parent is missing”“Vertex group has … weights for … vertices”）。现在这类操作把已有的编辑合并到新的生成结果上并作为数据保存，之后不再重放这些旧编辑；无法干净迁移的内容在质量报告中列出。包含这类保存点的工程需要本版本或更新版本才能打开。
- **打开工程更快**：保存时同时保存每个历史版本编辑后的模型，打开、撤销和切换历史时直接读取，不再重新生成与重放。
- **模拟网格上的变形报错**：网格加了模拟预设（或其他生成器添加的参数）后，在它上面用变形笔刷、贝塞尔等编辑会报「参数不在模型中」：编辑记下了生成器参数，而重放编辑时生成器还没运行。现在与 Cubism 一样，编辑只记录目标自身读取的参数：带动父级的摆动、模拟参数无论停在什么值都不影响编辑，目标自身的生成器参数在默认值时也不写进记录。胶水同样按 Cubism 的方式在静止形上胶合，参数不在默认值时先平滑移回默认值，胶合点在静止时不再产生拉扯。
- **按 Alt 后界面卡住**：在 Windows 上单按 Alt（或用 Alt + 右键拖动调整笔刷后松开）会让窗口进入系统菜单模式，之后的按键被吞掉。
- **画布工具与菜单**：工具栏展开较长时下方的工具不再穿透到画布；变换工具、权重渐变、骨骼模式和吸管的右键菜单不再为空；胶水工具在没有选中两张网格时改为禁用并说明原因，不再消失；形状工具的线宽与画笔大小分开；骨骼权重笔刷可用 `[` `]` 调整大小；Warp 网格尺寸标签随界面语言显示。
- **运行时参数逐帧累积**：网页播放器和 C 接口在每帧更新时把呼吸、视线、眨眼和加法表情叠加在上一帧的结果上，播放一段时间后角度等参数会漂到数万。现在每帧都从宿主设置的姿势重新计算。
- **Windows 上保存失败**：被替换的工程文件被短暂占用时，保存会等待占用解除，不再直接失败。
- **命令行 `--mesh-pixels` 报未知选项**：帮助中列出的这个选项此前无法使用，现在按源像素计算网格间距。

- **卸载时可删除用户数据**：在 Windows 的「卸载或更改程序」中选择删除后，可勾选「同时删除我的 PSD2Live 数据」（默认不勾选）。

### 改进

- **图标统一**：工具栏以外的图标按同一套网格重绘，高分屏上线条不再变细，颜色只用于表达含义。
- **骨架编辑更快**：创建、绑定或移动骨骼时只重新烘焙受影响的肢体，并行计算；大尺寸工程上移动手臂关节从约 2–3 秒降到 1 秒以内。
- **保存与打开更快**：保存时不再重新编码所有图像，也不再解包整个归档做校验；打开大工程时图像并行解码。
- **大尺寸工程更流畅**：纹理集的填充、分类和合成，以及指定姿势的 PSD 导出明显加快。
- **安装与升级**：升级或重装默认装回原来的目录，不再询问目录非空；重新构建的同版本安装包会替换已安装的版本，而不是并存。

### 修复

- **Windows 卸载或升级会清空安装目录**，保存在安装目录下的工程会丢失。现在只删除安装的文件；新建工程的默认位置改为「文档\PSD2Live」。**从 3.0.0 升级前，请先把安装目录中的工程移到别处。**
- 另存为不再默认指向当前打开的文件；覆盖确认改在窗口内弹出；编辑尚未完成时请求的另存为不会被随后的 Ctrl+S 变成普通保存；文件选择框不会再跑到主窗口后面。
- 切换编辑 / 预览模式时视角和画布大小保持不变。
- 启用骨架后，原本拆分在手臂悬挂变形器下的部件重放时报「Art primitive parent is missing」。
- 绑定到骨骼、又被手动放到其他变形器下的网格，烘焙后位置错乱或超出范围。
- 修改已绑定网格的拓扑或撤销后，重新打开工程时骨架结果与编辑时不一致。
- 生成后新加入的图层在重绘后网格被悄悄重新生成，之后重建报「Mesh migration baseline changed」。
- Cubism 预览帧偶尔被软件预览覆盖，姿势丢失。

## v3.0.0 · 2026-10-08

距 v2.0.4 改动较大：新增多种导出格式和独立运行时，纹理可以逐层调整，MCP 接口重新设计。旧工程照常打开。

### 新增

- **更多导出格式**：**文件 → 导出为** 新增 VTube Studio、PSD2Live 运行时模型、网页播放器、PNG 序列帧、精灵表、GIF、APNG、WebP 动图、MP4、WebM、ProRes 4444 和指定姿势的 PSD。每次导出附带损失报告，说明目标格式丢失了什么。视频与动图需要自行安装 ffmpeg。
- **PSD2Live 运行时**：开源（MIT）的 Rust 运行时，可在浏览器、Godot 4 或任何能调用 C 接口的程序中播放导出的模型，自带眨眼、呼吸、视线跟随和口型。
- **纹理工作区**：逐层调整纹理密度；在纹理集页面上直接拖动、缩放图块；按网格形状紧凑排布，布局保持不变，直到你要求重新排布。
- **保留原始分辨率**：导入的图片、素材和 CMO3 贴图不再缩到画布分辨率，绘画在图层自身的分辨率上进行。
- **MCP 重新设计**：公开操作从 25 个增至 181 个，可分页发现；最多 128 项编辑可原子提交，也可先试运行检查几何问题；耗时操作作为后台任务执行。旧的工具名已删除，需按新接口接入。
- 实验性：Spine 4.2、DragonBones 5.5、glTF 2.0 导出，仅限命令行。

### 改进

- **拆分更可靠**：按网格拆分、多边形拆分和前后分层得到的部件直接取代原图层，并参与自动生成。之后修改脸部设置、站姿或骨架，部件会跟着更新；原图层不再占用纹理集。
- **关节更自然**：骨骼弯曲时，肘、膝等关节按实测的人体关节姿态塑形，内侧不再出现纹理折叠。
- **手工修改不丢失**：在摇摆、模拟烘焙等生成结果上的修形，重新生成后按三方合并保留；冲突或已失效的修改会在检查器中提示。
- **文件菜单重新整理**：分为「导入」「导出 Live2D 模型」「导出为」三组。
- **统一的变换框**：「变换」工具、Warp / 图层放置框和纹理集图块使用同一套变换框；拖动角点外侧即可旋转（悬停时角点外亮起带箭头的弧线），新增可拖动的锚点作为旋转和 Alt 缩放的中心（默认在中心，带描边便于辨认），缩放光标随框的角度转动；手柄改为圆角方块与胶囊形，拖动时指针旁显示角度、缩放比例或位移。
- **画布与参数**：网格选择与框变换分开；变形工具作用于选中的参数关键点；添加或拖动关键点默认连续移动，选择步长后才吸附。
- **工程格式 v2**：未改动的内容在历史修订之间共享。旧工程照常打开，保存时自动转换。
- **更快**：修改分类或单个图层的网格时只重算受影响的部分；打开工程时复用已保存的骨架结果；编辑提交不再每次重建整个模型；Cubism 原生预览改为就地更新。
- **结果可复现**：同一个 PSD 每次生成的骨架和导出文件完全一致。

### 修复

- 绘画后重建网格时，位于骨骼、站姿变形器、修改过的格子或导入变形器下的网格不再偏移或缩小。
- 动画播放、参数滑块与画布姿势保持同步；平滑跟踪的速度不再受帧率影响。
- 纹理集中新放入的图块不再跳进其他图块空出的位置。
- Windows 上连续快速保存时偶尔替换文件失败。
