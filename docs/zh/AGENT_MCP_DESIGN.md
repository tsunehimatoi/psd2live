# Agent MCP：建模工作流与连续区域变形

更新：2026-09-13。状态：整体重构尚未实现，已落地的姿态拼图单独标注。本文替换此前的工具目录方案；现有可调用接口见 [MCP_AUTHORING.md](MCP_AUTHORING.md)，调研来源见 [同类项目报告](AGENT_PROJECT_RESEARCH_2026-09-13.md)。

工作流依据及本轮纠偏见 [Live2D 建模流程](AGENT_MODELING_WORKFLOW.md)。该文明确关键形生命周期、ArtMesh 编辑、临时变形与永久层级的区别；下文几何机制必须服务这些流程。

## 1. 设计方向

**Agent 选择运动所有者与精确关键形，再描述区域变化；程序将连续变形写入对应对象，并保留其他运动。**

变形器是一张可整体塑形的控制网。内部、边界、透明区域中的控制点都参与定义形变，不只有落在 Mesh 上的点有用。默认操作全网，不默认固定边界；需要固定发根、颈部等区域时才显式 pin。

本次设计以三个目标约束所有决策：

1. 工具少，字段表达精确，不通过隐藏几十种动作把复杂度转移到一个大 JSON。
2. Agent 不下载/计算/回传控制点，默认不见点索引。常规塑形以大区域笔刷和整体形变完成。
3. 需要独立运动层时，创建的变形器实际贴合受控对象。已有对象的局部塑形可使用临时编辑框/路径，不应因此新增永久 Warp；调整幅度相对明确的编辑框可理解。

允许重构现有创建、变形、级联求值与协议实现。已有代码仅在满足新契约时保留，不把复用作为约束。

## 2. 两个根因，分别解决

### 2.1 当前创建逻辑会直接生成父框大小的子 Warp

`core/RigObjectEdits.kt` 中 `RigWarpEdit.applyTo` 将新 Warp 控制点铺满父坐标 0～1，按父 rows/columns 细分，然后只改变 Mesh 父级，不进行局部坐标重参数化。它没有目标边界输入，因此局部发束也可能得到覆盖整个父域的大框。

这样做有实际理由：`org/umamo/render/eval/DeformerCascade.kt` 会先把子 Warp 控制点变换到世界，再在烘焙格网上插值。当前创建逻辑通过网格对齐减少插入子 Warp 后的继承运动重采样误差。

因此“大框”不是只靠教 Agent 调小就能解决。需要真正的局部 Warp 创建和坐标迁移，并验证父级动画及导出一致性。

### 2.2 表达入口仍然容易诱导逐点编辑

`RigGeometryTools.transform` 已有整网 translate/scale/bend、区域权重、sway，证明并非完全缺少算法。但当前入口同时暴露 indices、稠密点分页、点对应，且操作尺度依赖每一步重新计算的网格边界。

大框让默认幅度和半径失去局部意义；点索引又让 Agent 把任务理解成“找到图上的几个点，再挪一点”。结果是局部凹陷、折线和微小修补，没有整体体积变化。

应同时修正几何表达与接口默认行为。只在 prompt 里重复“所有点都能动”不足以改变这一过程。

## 3. 工具收敛

按建模职责暂定下列 9 个领域，核心路径使用前 6 个；数量待真实 Schema 与任务测试验证。不再并列暴露同义 legacy tools；旧客户端通过单独的兼容配置使用旧接口。这里是设计目标，不是现有工具注册状态。

| 工具 | 唯一职责 |
|---|---|
| `inspect` | 当前工程/选区摘要，按 query 找对象或按 id 看少量对象详情 |
| `view` | 看正式模型或候选；同镜头对比、局部图、必要姿态检查 |
| `rig` | 永久 Warp/Rotation、父子关系与运动职责；程序处理坐标迁移 |
| `form` | 参数绑定与关键形集合：插键、复制、镜像、指定组合角及通道/切片编辑 |
| `deform` | 在明确关键形目的地，对 ArtMesh/Warp 施加连续区域/路径形变；临时编辑场不创建层级 |
| `revision` | 提交候选、查询历史/回执、恢复；读写分支有明确类型 |
| `asset` | 准备参考、接收 PNG、放置到候选，三个有类型的分支 |
| `physics` | 输入、输出、摆链设置；默认进入候选 |
| `appearance` | 静态显示、遮罩、连接等绘制关系；动画通道写入由 form 负责 |

不另设 preview、check、get-workflow、get-points、get-geometry-summary 工具。preview 是修改工具的默认返回状态；检查附在 view 或候选诊断中；错误自带必要解释；密集点操作仅属于显式启用的开发诊断配置。

工具数量减少不能靠无类型的 `execute(action,args)`。每个工具只承载一个紧密领域；各分支必填字段、范围和互斥条件由同一类型定义生成 Schema。若 asset 等分支的 Schema 成本高于拆分，需测量后调整，不能只追求数字。

`inspect` 的 query 与 ids 互斥，无参数读取当前上下文。分页游标返回同一版本的数据。`view` 接收候选状态和检查 preset，输出检查实际范围，不自动对所有参数做全排列。

普通改名/显隐可在相应领域声明直接提交，一次完成。几何/层级/素材替换默认候选。工具 annotation 反映最强副作用，不能因某个分支只读就把整个工具标为只读；模型的候选创建也不是完全无副作用的查询。

## 4. 新 Warp 的正确尺寸与密度

仅在需要新增独立运动层时创建；已有对象的一次塑形直接使用 deform。以下是 rig 的局部 Warp 创建负载示意：

```json
{"state":"h17","targets":["mesh:side-hair"],"fit":"motion"}
```

`fit` 可省略，默认 motion。id、共同父级和合适网格由服务器生成；跨父坐标域或选择范围歧义时返回短错误，不凭名称猜。

创建顺序：

1. 取得目标在共同父级局部空间中的中立几何及已有相关姿态包络。使用有效控制几何，不只看屏幕可见 alpha；被遮挡但需要运动的部分仍属于目标。
2. 合并包围范围，加一圈有限余量，为边界插值和预期运动留下空间。余量相对局部宽高，不能相对全身画布。尚无动画时仅根据中立范围和显式运动需求拟合，并注明未覆盖未知运动。
3. 创建真实局部框；默认低密度、依长宽比选网格，例如规则四边形变形先从每方向少量分段开始，复杂弯曲再按误差加密。长发可沿长度更多分段，横向更少。
4. 将目标局部坐标、所有相关关键形和子级坐标正确映射到新 Warp 域，保留 UV、通道、蒙版和组织关系。
5. 验证插入前后中立、已有关键姿态、组合姿态及中间采样的世界位置；通过后才允许提交。

不默认暴露 rows/columns；精度策略可用 coarse/normal/fine，但必须通过误差检验，不能简单把细网格等同高质量。返回默认只有 warp id、候选 state；框太空、需要异常高密度或目标本来就覆盖整头时，才附带具体诊断。

贴合不是无限缩小：需要一圈有意义的空控制区域来平滑过渡；一个控制整头的 Warp 比单束头发大是合理的。检查“空框过多”需比较目标范围与 Warp 范围，不采用全模型统一尺寸阈值。

已有 Warp 的重新贴合不能只改外框：必须迁移已有动画和子级坐标，不可迁移则保留候选失败，不静默清空关键形或重建 Mesh。

### 必须面对的求值与导出问题

局部坐标重参数化本身不能保证当前“先烘焙父级、再插值子网格”的复合结果完全一致。需要验证并选择一种能保持实际输出的实现：

- 优先研究在标准 Warp 语义内，拟合局部网格并按误差自适应细分；误差必须比较实际绑定顶点和参数姿态，而不只比较新框四角。
- 如果现有级联求值限制了局部框，应重构为明确的局部映射复合；同时处理 CPU/GPU、CMO3/MOC3 导出与回读。不能只让应用内预览变好而破坏导出语义。
- 达不到既定误差/复杂度边界则报告无法无损拟合。不能悄悄退回全父框，再把它描述为局部 Warp。

首个工程里程碑是一个“非线性父 Warp 下，小发束插入局部子 Warp”的可复现样例；不是先做更多 prompt。

## 5. 用连续形变場替代点操作

### 5.1 操作目标是整个控制面

每个操作定义连续映射 T，区域笔刷定义权重 w。全部控制点由程序求值：

`p' = p + w(p) · (T(p) - p)`

默认 w=1，即整网形变。只有显式 pin 或区域外的点才保持不动。位于透明区域、Mesh 外缘之外的格点同样参与；不按“控制点下面有没有像素”过滤。

Agent 决定变化方向、范围、幅度和附着位置，不决定每个顶点坐标。稠密数组由后端生成并写入全部受影响控制点。

形变场在整个二维域定义；最终网格仍是采样表示。笔刷小于网格分辨能力时，应适当加密/拟合或返回分辨率不足，而不是退化成只移动一个最近格点。

### 5.2 保留少数有视觉意义的操作

| 操作 | 输入概念 | 适合任务 |
|---|---|---|
| move | 向量 | 半张脸/大片头发向某方向偏移 |
| scale | 横纵倍率，默认区域中心；可显式轴心 | 整体压扁、拉长、扩宽，或局部大片收缩 |
| rotate | 角度、轴心 | 附着部位转动 |
| bend | 沿哪一轴、弯曲角度/有限曲线、可选固定边 | 整片身体/发束弯曲，截面随曲线转动 |
| profile | 沿轴的少量截面宽度倍率 | 上宽下窄、腰部收缩、头顶扩展等渐变体积 |

压缩与扩展都是 scale，不再分别做工具。固定根部摆动用 bend/rotate 加 pin/区域权重表达，不再单列只能用于头发的接口。

常量横移产生平移场；缩放产生向轴心收敛/发散的场。真正的整体 bend 应以连续中心线及随动截面构造映射，例如 `F(s,r)=C(s)+r·n(s)`；不能把现有横向曲线位移当作所有弯曲需求的等价实现。有限曲线控制量保持少，不把每一行横移量交给 Agent 枚举。

profile 用少量纵向站点及横向倍率，插值应保持正倍率，避免过冲引起翻折。首版可先用保形插值；不要求 Agent 理解插值算法。

网格平滑是数值处理或专家修复，不作为普通造型默认步骤。也不能在每次操作后自动拉回边界、抹平轮廓，让真正的大范围变形被消除。

### 5.3 笔刷必须有大片有效区域

`region` 默认省略，表示目标的全部可变形点。常用方向区域为 whole、left/right/top/bottom；自定义笔刷需要圆/椭圆、方形平台与路径带的紧凑表达。按闭眼、发束等任务验证实际必要的形状，不能为缩短 enum 就排除长条线状笔刷。仍不把点索引与多层任意选择组合塞进普通接口。

方向区域的语义在同一个基准编辑框中固定：right 表示右半部大块，过渡带跨过中线；最外侧边界仍可受满权重影响，不在外框边缘又衰减回零。

椭圆笔刷包括中心和双轴半径，软边采用固定默认值：内部是一块近似同幅度移动/缩放的平台，外圈平滑衰减。不要使用从中心立即下降的尖峰权重作为所有大区域编辑的默认，否则仍像在戳局部顶点。

所有笔刷按实际编辑框的空间度量求值，避免细长发束用同一个归一化半径后出现意外挤压。框的 Y 轴向下，角度方向明确。pin 的权重优先于修改，冲突时返回被约束削弱的实际效果。

## 6. 一个固定坐标框，一次输入少量语义参数

一次 deform 用同一基准 state/pose/编辑框。后续操作可以叠加已变形结果，但范围、归一化长度与方向不随每一步包围框变化。需要换轴心时显式指定。

观察 `pose` 和写入 `key` 分开。key 是目标 owner 的精确绑定轴值；pose 可额外包含父级/其他参数。首次写入缺少必要轴时返回需补的轴，不回传所有无关参数，也不吸附到最近键。后续 edit handle 锁定目的地、完整观察值与坐标框；GUI 改动不会改变含义。

整片脸横向压缩，示意：

```json
{"state":"h17","target":"warp:face","key":{"ParamAngleX":30,"ParamAngleY":0},"ops":[{"type":"scale","value":[0.85,1]}]}
```

右半边大区域往左移，再整体弯曲：

```json
{"state":"c1","edit":"e1","ops":[{"type":"move","region":"right","value":[-0.08,0]},{"type":"bend","axis":"y","angle":8}]}
```

这里 c1/e1 来自前一个调用，分别表示候选及已确认的编辑目的地。move 的 -0.08 表示基准编辑框宽度的 8%，angle 单位为度。绑定不明确时不能仅凭 state 推断写哪个关键形。

对下半部使用大片缩放笔刷：

```json
{"state":"c2","edit":"e1","ops":[{"type":"scale","region":{"center":[0.5,0.75],"radius":[0.65,0.45]},"value":[0.9,1]}]}
```

这些调用没有点编号。view 若需要解释影响，可以画稀疏网格、影响热区和几根位移箭头，显示“右半张面正在收缩”，而不是用几百个编号覆盖角色。

默认视图仍是干净角色图。只有诊断形变方向/范围时加 field overlay，不每次额外发两张图。

## 7. 最小返回与 token 预算

在已有 edit handle 且未扩大写入范围时，普通 deform 成功只需：

```json
{"state":"c3","changed":true}
```

有实际问题才增加：

```json
{"state":"c3","issues":[{"code":"FOLD","region":[0.6,0.7,0.9,1]}]}
```

首次目的地解析、批量写入或扩展了关键形集合时，回执还需 edit、实际 owner/key/channel 或其简短差异。不能为了百 token 预算隐藏自动建键/绑定变化。

revision 提交：

```json
{"action":"commit","state":"c3"}
```

revision 提交成功：

```json
{"state":"h18"}
```

缺少关键姿态轴：

```json
{"error":"POSE_INCOMPLETE","missing":{"ParamAngleY":0},"written":false}
```

missing 中的 0 是可选择的默认值，不是系统已经代填的值。复杂错误才补一句原因。代码、单位和字段类型由 Schema 解释，不每次重复说明。

默认不返回全部操作副本、所有 diagnostics、所有参数、所有父级、长 success 文案、固定 next 数组、点数/数据成本和多张图。必要影响范围、未验证项和异常不能为了省 token 隐藏；通过 inspect/view 按需展开。

第一次 inspect 提供最小工作环境：state、当前选区、画布尺寸和相关对象；所有对象只在查询需要时返回。名字便于理解，id 便于调用，避免混用缩写到不可读的字段。

字段尽量简短且常见：state/target/pose/ops/region/value；不把所有名字压成一个字母。真正节省来自减少数据和重复交互，不是让 Agent 记密码。

测量 tools/list 的完整 Schema token、每类请求/响应 token、看图次数和重新读上下文次数。先以普通文本修改回执百 token 以内为设计预算；工具总 Schema 的预算在生成真实 Schema 后根据基线收紧。数字是目标，不是已经测得的性能。

MCP structuredContent 与兼容文本块使用同一紧凑结果；不在协议外假设可以省掉宿主要求的字段。图像使用原生 image content/资源引用，字节不经过模型手工转写。

## 8. 图片组织：一次看到差别，只放大需要判断的部分

`view` 默认返回一张为当前判断组织的拼合图，而不是多个独立 image content。本轮已将现有 `view_render_poses` 改为单张姿态拼图与共享元数据，具体已实现契约见 [MCP_AUTHORING.md](MCP_AUTHORING.md)。以下候选前后对照、sheet 缓存与按 tile 放大仍是设计，不能误认为已经实现。

### 8.1 三类对照，同一个工具

| 当前判断 | 默认图布局 | 不默认附带 |
|---|---|---|
| 一个局部修改是否更好 | 同姿态、同裁切的 before / after 两格 | 全部控制点、差分图 |
| 转动后是否自然 | 行是少量相关姿态，列是 before / after | 无关参数组合、整套逐帧图片 |
| 新素材是否融入原图 | 原组合 / 候选组合；需要时加素材局部 | 所有源层的独立大图 |
| 数值检查找到缺陷 | 最差姿态的局部 before / after；定位需要时加 diff | 每个正常区域的截图 |
| 物理动作是否断裂 | 按真实时间排列的少量关键帧，共用镜头 | 每次都输出完整录像或几十帧 |

“修改前后”与“中立/极限姿态”是两个维度，不能混为一谈：同姿态比较两个 state 才能评价修改；同 state 比较姿态只能说明运动差异。StandRig 的 failure-image 默认比较同一 rig 的中立与目标姿态，借鉴其拼图形式时必须补上真正的 state 对照。

候选默认 compare_to 其直接父候选，首次候选默认比较正式基线。state 已记录来源，Agent 不用反复传 HEAD、对象、画布和姿态。view 保留显式 compare_to，让多次微调后能回看最初版本或最佳候选，防止每次小改看起来都更好、累计却偏离目标。

### 8.2 拼图必须保留尺度与定位

同一对照组使用两个 state 的联合范围加有限背景余量；组内相机、裁切、像素尺度、背景、光栅化设置固定。若各格单独“自动适配”，缩放/漂移会被重新居中掩盖。

每格只有短标签：A/B、姿态值或时间。完整映射在服务端保存，普通返回只含 sheet_id、格子 id 和必要异常。需要放大时：

```json
{"sheet":"s12","tile":"B2"}
```

需要查看其中的局部区域，仍调用 view：

```json
{"sheet":"s12","tile":"B2","crop":[0.3,0.2,0.8,0.7]}
```

crop 是该格子图像内的归一化矩形，不是 Warp 操作坐标。服务端保留 sheet → tile → state/pose/canvas 的映射。图上点选也必须携带 tile，不能把整张拼图坐标直接送入 deform。

局部变形对照需要时在同一张图加入一小格上下文，防止脸部局部看似自然但相对头部位置错误；没有该问题就省略。参考图/生成图与实际渲染图必须标明身份，生成的目标姿态不能冒充已实现的运行结果。

### 8.3 保证可辨识度，不无限往一张图里塞

默认先选择 2～6 个有用格子；具体数量由任务决定。每格维持能辨识目标缺陷的尺度，超过预算就分组或局部放大。主体只有几十像素的全身九宫格不能用于检查睫毛或发根接缝。

差分图只用于找变动位置，不默认占三分之一版面。diff 使用同姿态/同相机的实际图像，并区分透明度变化与颜色变化；“有差异”不等于“更好”，也不能用两个姿态的像素差判断修改退步。

大图合一不保证 token 更低：宿主缩放、图像切片和分辨率策略可能抵消节省。目标是删除重复背景/相同画面并减少观察轮次，同时保留细节；实际测量图像 token 或宿主账单。未知时记录分辨率、格数和调用次数，不能以 PNG 压缩字节冒充视觉 token。

### 8.4 帧选择由程序做，审美判断仍由 Agent 做

根据修改的目标和参数依赖选中立、有效端点、关键组合角；在数值异常或变化较大的区间加密。物理轨迹选启动、最大位移、最差接缝、回正等时刻，同时保留时间顺序和间隔。

多个问题发生在同一姿态/区域时合并格子。几乎相同的帧可去重，但不能漏掉用户要求的端点或瞬时缺陷。无关对象的检查可在后台保留，默认只发短异常；Agent 可主动查看全局，不能被数值评分限制看图范围。

## 9. 预演、检查和提交不重复计算与传输

rig/form/deform 默认生成不可变候选，操作数据、底层点数组和编辑框保存在程序内。多个修改接着候选 state 进行。revision 的提交分支只引用 state，不让 Agent 重传已看过的点或 operations。

deform 执行必要合法性检查，并保留具体失败位置；view 可请求多姿态/组合角/物理轨迹的检查。结果分清“结构可用”和“外观已观察”，数值通过不代表造型自然。

翻面/极端压缩基于采样域与实际求值，而不只看四角。还要比较控制点间的形变，控制点都合法不等于格子内部没有异常。检查相关父级级联后的最终画面。闭眼/闭口的合理近闭合与非预期塌缩必须区分；不要统一用面积比例拒绝所有强压缩，也不要为眼部关闭全部翻面检查。

不为通过检查自动缩小用户要求的角度或幅度。可返回建议或新候选，但必须保留请求值与实际值的差异。静止不动永远不能作为“安全摆动”成功。

候选来源 HEAD、资产及拓扑版本由 state 持有。提交冲突返回最新状态与影响对象，不自动套用到新框。请求回执持久化以应对断线重复提交；查询走 revision 的明确分支，无需增加 receipt 工具。

同一候选相同视图命中缓存；只有用户/Agent 请求才返回图片。对照图固定相机和姿态，候选改变则生成新的证据引用。

## 10. 从外部项目提炼的其他优化，不新增工具入口

| 可借鉴机制 | 参考依据 | PSD2Live 的落地取舍 |
|---|---|---|
| 局部前后拼图、连续运动证据 | PuppetLoom `agent-evidence.ts` | 保留固定范围和版本；避免照搬大尺寸、全部帧一次返回 |
| 数值失败定位后才取局部图 | StandRig `qaCheck.ts`、`qaFailureImage.ts` | 收进 view；允许主动看造型，不要求先失败才可看图 |
| 少量意图控制大量几何 | PuppetLoom `agent-spec.ts` 与部件提案 | 提炼为通用区域形变场；不逐部位复制一套工具 |
| 先排查便宜且可逆的原因 | Iki `measure.ts`、`compose.ts` | 素材贴画布边先移动试拼；定位/尺寸不对先配准，不直接重生图 |
| 增量上下文 | StandRig `rigRoutes.ts` 的 changes 接口 | inspect(state=...) 只返回变化和必要对象；分支不连续时明确要求重同步 |
| 明确执行状态与来源 | cubism-api-bridge 的 execution/sync 状态 | 回执内部完整保存，正常回复极短；不把整份审计日志灌入上下文 |
| 后端/回退原因可追踪 | live2d-automation `pipeline_services.py` | 正常时只保留内部记录，影响结果才输出一条原因；mock 不报作有效模型 |
| 多阶段图层/深度处理 | See-through 推理入口 | 后端可换，仍接统一 asset 输入；不要求 Agent 操作内部各模型步骤 |

这些机制都应通过现有的少量工具表达。不能每找到一个好点子就新增一个 MCP tool。

### 10.1 先验证原因，再支付昂贵成本

同样的“边缘被截断”，可能是素材本身缺像素，也可能是放置超出画布。程序能够做便宜的候选试移和重新测量，区分问题后给出短结果；Agent 不需要先调用生图来试运气。

类似地：看起来挤扁，先查看父级继承与局部 scale；发根露洞，先比较原素材覆盖、放置与绑定；摆幅太小，先检查关键形/输出是否饱和。明确诊断才报告原因；证据不足标为 suspected，不把启发式猜测当定论。

先修确定性问题的原则不等于强制一长串排查工具调用。这些检查可以在一次 rig/deform/asset 执行中完成，仅返回与当前失败有关的一项。

### 10.2 支持小量候选比较，避免无方向反复试

需要调一个量时，可在 deform 的可选 compare 中对同一操作、一个标量给出最多三个显式候选值；程序从同一基线计算并生成同尺度拼图，返回各候选 state。Agent 选一个继续或提交。

比如对同一右半脸压缩比较 0.92 / 0.86 / 0.8，而不是三次独立编辑、三次读状态、三次自行记图。只有 Agent 要求才做候选比较，不能默认扩大搜索或偷偷改变其他参数。多维组合搜索不属于首版，避免将 token 成本转成失控计算成本。

该能力优先作为第二阶段实验；如果 Schema 成本和选择负担超过节省，应移除。普通调用仍只有一个修改结果。

### 10.3 记忆留在工程里，恢复只给有用信息

候选 state 已保存父版本、目标、编辑框、操作和证据；revision 可找回最佳候选与请求结果。恢复上下文只需当前意图、最近候选、未解决问题和必要对象，避免重新输出整条历史及所有失败尝试。

不依赖服务器“记得当前用户正在编辑哪个 Warp”的隐式全局状态：引用始终属于具体工程/候选，多个会话和 GUI 操作不能相互偷换目标。

### 10.4 把连接与工具清单也计入成本

工具说明只保留选择条件与关键语义，错误说明与任务示例在需要时返回。静态 Schema 不重复嵌入同一段长教程，不把所有模型参数枚举到每个工具定义。

缓存资源和内部句柄可以减少回传，但不能宣称减少宿主已经缓存的 tools/list token。实际评测必须区分首次连接、连续任务、上下文恢复三种情形。跨宿主测量兼容性，而不是只针对某一个 Agent harness 调 prompt。

## 11. 开发顺序重新调整

### 第一阶段：已有对象的关键形编辑闭环

先接通明确 owner/key/channel、父链坐标反算、保形插键与多对象写入，配合固定镜头的参数矩阵观察。ArtMesh 与 Warp 均需覆盖；不新建层级也应能修好现有眼口关键形。连续场默认全网，支持大区域平台权重与路径弯曲。

形变场是编辑抽象，不要求新增私有运行时文件格式。若能将结果合理采样到标准 Warp keyforms，应直接输出标准可编辑结果；需要修改运行时语义时，先证明导出一致性。

### 第二阶段：独立运动层与组合形状

重构 RigWarpEdit 的局部坐标迁移与级联求值，证明新建/重新贴合能保留已有运动。与此同时验证复制、镜像、组合角候选及参数切片编辑。通过 inspect/view/rig/form/deform/revision 收敛入口与候选恢复；不把长篇教程塞进 Schema。

### 第三阶段：真实造型任务验证

使用闭眼与微笑/转头组合、已有头部 XY 修形、独立发束摆动三条完整流程。整体压缩、扩展、弯曲仍作为几何单项回归，不能替代建模验收。先验证已经分层的素材，不混入生图失败因素。

### 第四阶段：素材和物理配套收敛

在相同 state 和错误协议上收敛其他工具。没有证据表明需要时，不建立配方市场、任务调度器、复杂自动 planner 或额外分层 API。

## 12. 验收标准

| 层面 | 必须证明 |
|---|---|
| 尺寸 | 小发束得到局部 Warp；不会复制整个父域；必要运动余量保留 |
| 继承 | 插入/重贴合前后已有动画一致，相关关键姿态和中间值均比较 |
| 全网 | 无 region 的移动/缩放作用于整个 Warp，边界和空白控制点也参与 |
| 大笔刷 | 右半区呈大片近似一致位移，过渡连续，不集中成一个小尖峰 |
| 弯曲 | 截面随中心线合理转动；可区分弯曲与简单横向位移 |
| 稳定性 | 改网格密度后，同一笔刷描述产生近似相同的可见形变 |
| 局部性 | 未选对象及其动画不受影响；pin 区保留约束 |
| 关键形 | 新键保持已有插值；指定格/切片修改不覆盖其他格与通道；观察 pose 不偷偷新增绑定 |
| 建模 | 闭眼保留墨线/遮罩；转头职责不重复；镜像/合成角是待检查候选 |
| 导出 | 保存恢复、CMO3/MOC3 回读；有 SDK 环境时再对照实际渲染 |
| 拼图 | 同姿态前后共用尺度，不掩盖缩放/漂移；tile 可准确放大和定位；小缺陷可辨识 |
| Token | 不传点数组，不重复传计划；统计 Schema、请求、回执和观察成本 |
| Agent | 同输入/模型/任务对照：完成率、有效修改次数、理解错误和人工修复时间 |

重点测试应使用“目标 Mesh 只占非线性父 Warp 小部分”的样例。当前覆盖整个 0～1 方形的 fixture 无法暴露大框问题，也不足以验证连续变形的视觉质量。

本轮产品修改仅落地现有 view_render_poses 的紧凑拼图。其余包括新工具面、关键形编辑契约、局部 Warp 与连续路径弯曲仍待实现；以完整建模任务推动后续工作，不再只围绕单张形状优化 prompt。
