## 1. 目标场景与验收标准

**场景**：用户把一张 1600×1200 的蝴蝶结 PNG 拖进画布 → 拖动、缩放、旋转到头顶 → 在层级面板里把它拖进“头部 Warp” → 之后随时再微调位置 → 画几笔修饰。全过程像素保持清晰，网格疏密合适，撤销/重做逐步可回。

| 指标 | 要求 |
| --- | --- |
| 拖动、缩放、旋转时的帧率 | 与普通画布交互相同（60 fps 以上）；拖动中**不运行流水线**、不重建网格、不打包纹理集 |
| 松手 / 确认后的提交 | 典型工程 ≤ 150 ms（A 类：只改 M 中该图层的网格 + 运行修改器 + 编译运行包）；不重新分析、不重新生成其他图层 |
| 历史 | 导入并放置为 **一个** 历史节点；之后每次变换一个节点；取消导入 = 不产生任何节点 |
| 像素 | 任何变换都不重采样原图；渲染用的纹理从原图按图层的纹理密度一次采样得到 |
| 网格 | 只在明确的触发点生成或重建（第 6 节）；变换、换父级、移动都不触发 |
| 父级 | 挂到任意 Warp / 旋转 / 骨骼下后仍可再变换、再换父级，画面位置不跳 |
| 可解释 | 图层面板对每个图层说清：原图尺寸、纹理尺寸（占原图百分比）、在画布上的尺寸、网格顶点数；没有不可见的“影子”图层 |

## 2. 现状诊断（需要推翻的部分）

以下为 2026-10 审查结论，行号见审查记录，此处只给结论。

### 2.1 性能：拖动的每一帧都在跑提交级流水线

放置会话（`WorkspaceImagePlacementSession.preview`）每个鼠标移动事件执行：

1. `layer_set_bounds` 的候选：对**整份源图**重新分析（`WorkspaceLayerInsertionEdits.identities`，分析缓存按源图对象身份命中，而每帧都新建源图对象，必然失效）、对该图层单独跑一次带 Moc3 编译的 `buildPreview`（`materialize`）；
2. 一次完整的 `WorkspacePreviewBuilder.build`：源图变了所以不走快速路径，纹理集全量打包、生成或从检查点重建、重放日志、再编译一次运行包；
3. 每帧新建 `WorkspacePreviewBuilder()`，网格缓存与生成缓存全部丢弃；
4. 界面线程重新加载整个预览运行时。

合计每次鼠标移动约 2–3 次完整构建加 2 次 Moc3 编译。此外旧位置与新位置的并集参与补边，纹理块随拖动距离变大。**卡顿是结构性的，不是可调优的常数。**

### 2.2 “移动一个图层”有四条语义不同的路径

| 路径 | 作用对象 | 行为 |
| --- | --- | --- |
| 变换工具（物件模式） | 网格顶点 | 网格动、图层矩形不动；绘画模式里原图仍画在旧位置 |
| `layer_set_bounds`（文件导入的图层） | 图层矩形 + 创建记录 | 冻结生成输入、写 1×1 空白占位、单独生成一次网格并写 `canvas_mesh_create`；绑定过父级后永久拒绝（"Layer has authored motion"） |
| `layer_set_placement`（素材库图层） | 图层矩形 | 有创建记录才物化，否则从生成输入删掉、交给生成器重新生成 |
| `layer_set_canvas_rect`（纹理面板） | 图层矩形，拉伸栅格 | 让生成器重新放网格；绘画过一次（自动建网格）后永久拒绝 |

变换工具在 `importedBounds` 里猜测“这是不是一次导入图层的平移缩放”，猜中就改发 `layer_set_bounds`，失败时静默退回网格编辑。

### 2.3 一个图层的像素散落在四份源图里

`source`、`generationSource`（冻结的生成输入，含 1×1 空白占位）、`meshSource`（首次绘画重建时整份复制的生成输入，含空白占位）、`placementSource`（导入原图）。它们的成员规则各不相同，没有不变量把它们绑在一起；不同触发点从不同的一份取像素重建网格（绘画保持 `generationSource`，改网格设置读 `meshSource` 再退回 `source`，改分类读 `meshInput(source)`），所以“绘画后网格保持不变”会被无关编辑悄悄推翻，结果依赖编辑顺序。

### 2.4 纹理分辨率没有单一来源

一个图层实际渲染的纹素密度 = 栅格尺寸 × 画布矩形 × 每层密度覆盖 × 全局 `fit` × 超分倍数 × 排布的 fit 步长。“密度”在代码里有两个含义（栅格像素/画布单位，上限 256；纹素/栅格像素，上限 16）。纹理坐标有三套约定（未绑定 Rig 的图层偏移、日志记录的画布单位、绑定后的页面 UV），换绑定经画布坐标中转，图层矩形一变就采样到错位的像素。绘画模式显示原图全分辨率，渲染却是降采样后的纹理且只显示网格覆盖的部分，两者看起来不一样。

### 2.5 网格的触发点是隐形的

- 首次绘画到没有网格的图层时自动建网格（写入的记录此后挡住 `layer_set_canvas_rect`）；
- 导入是否物化网格取决于父级是生成的还是用户建的变形器；
- 一次拆分或改网格设置就冻结整份文档的生成输入与网格设置基线；
- 改网格设置有两条保留规则相反的路径（物化迁移 vs `buildPreviewPreservingPaths` 删除拓扑与关键形编辑）；
- 网格密度：`max(12, …)` 使低于 12 的全局设置无效，密度表在三处重复，单位由**整张文档**的尺寸决定（`unitScale = max(W,H)/2048`），与图层的实际像素无关。

### 2.6 身份与“幽灵”

- 图层 ID 有十余种来源（`lyid:`、`name#index`、`import:<路径哈希>`、`agent:`、`artwork:`、`split:`、`<src>:l`、`<owner>::mouth-lip-n`…），网格 ID 由分类 + 同类序号推导，改分类就改名并重新编号兄弟网格。
- 图层 ↔ 网格的对应在四处按不同优先级临时拼装（`splitDrawableIds` + 生成反查 + 作者反查），每处都假设一对一。
- 软删除一经使用就让文档永久进入“延后过滤”模式：已删除的图层仍参与生成、仍影响变形器框架，只是事后被滤掉；`deletedLayerIds` 同时承载用户删除、取消导入的退路和 CMO3 拆分原图，“全部恢复”会把内部原图复活成重复图层。
- 取消导入留下残留（纹理覆盖、绘制顺序覆盖、画布可见性、检查点里的网格）；重新导入同一文件得到同一 ID，旧的逐 ID 状态附着到新图层上。
- 图层面板列出的是分析结果（嘴唇条带、`:l`/`:r`、拆分部件都是“图层”），删除按钮作用于派生行；面板的眼睛读画布可见性而导出读文档可见性。

## 3. 设计原则

1. **像素不随变换改变。** 图层的像素是不可变的图像资源（按内容寻址）；位置、缩放、旋转是一个仿射**放置**。只有绘画与换图产生新像素。
2. **纹理坐标在图层像素空间。** 网格的 UV 指向图层自己的图像，不指向画布或纹理集页面。于是移动、缩放、旋转图层从不改 UV、从不重新打包纹理集。
3. **纹理集是派生缓存。** 纹理块 = 图层像素 × 该图层的纹理密度；纹理集可以随时丢弃重建，不是任何数据的权威。
4. **网格属于 M，只在明确的触发点生成。** 变换 = 对 M 中该图层网格的顶点做仿射（A 类），不重建。
5. **交互不跑流水线。** 拖动在 GPU 上对已有绘制结果做变换；只有松手/确认才提交一次。预览与提交走同一条候选路径。
6. **一个图层一种身份。** 图层 ID 与网格 ID 在创建时生成一次并保存，不从名称、路径、分类或顺序推导；对应关系保存在 M 中。
7. **删除就是删除。** 删除写一个历史节点，撤销恢复；没有软删除、没有占位、没有“全部恢复”。
8. **用户图层不参与自动生成。** 导入、新建的图层是用户对象（只在 M 中），生成器只读 PSD 图层（生成输入）。

## 4. 数据模型

### 4.1 图层

```
Layer {
  id: LayerId                 // 创建时生成，不透明字符串，永不复用
  name: String
  origin: Psd | User          // Psd = 生成输入；User = 导入、新建、拆分得到的图层
  pixels: PixelRef            // 按内容寻址的 RGBA 图像（原生分辨率），不可变
  placement: Affine2D         // 图像像素 → 画布单位；平移、缩放（可非等比）、旋转
  textureDensity: Float       // 纹素 / 图像像素，默认 1，受纹理预算约束（4.3）
  meshSettings: MeshSettings? // 只覆盖该图层；null 用文档设置
  visible, opacity, blend, order, group
}
```

- `pixels` 与 `placement` 取代 `bounds` / `rect` / `storedCanvasRect` / `LayerCanvasRect`；`LayerSpace`、`CanvasDensity.canvasLayer`、`alignedRaster` 的各种“把栅格对齐到画布”的视图收敛为一个：`placement` 加采样器。PSD 图层导入时 `placement` = 平移到其 PSD 位置、缩放为 1。
- 图层面板一行 = 一个 `Layer`。嘴唇条带、左右拆分的半边、ArtPrimitive 部件都是**网格**（属于某个图层），出现在层级面板，不在图层列表里。
- 拆分（连通块、多边形、前后分层）产生新的 `User` 图层，其 `pixels` 是原图的子图，`placement` 与原图层相同。

### 4.2 网格与图层的对应

M 中每个网格携带 `layerId` 与图层像素空间的 UV：

```
Drawable { id, layerId, mesh { positions (父级空间), uvs (图层图像像素), indices }, ... }
```

- 一个图层可以有多个网格（拆分部件、嘴唇条带）。对应关系就是网格上的 `layerId`，随 M 保存；`splitDrawableIds`、`layerIdByDrawableId`、`importedLayerIds`、`sourceBoundsByDrawableId` 等派生映射全部退役。
- **绑定纹理集**（D 类，打开与每次构建时进行）：`uv_page = tile.origin + uv_image × tile.scale`，只读该图层的纹理块，不经画布坐标。

### 4.3 纹理分辨率：一个旋钮

```
纹理块尺寸 = 图像尺寸 × textureDensity × budgetFit
画布上的纹素密度（只用于显示）= textureDensity × budgetFit × |placement 的缩放|⁻¹
```

- `textureDensity` 是每图层唯一的用户设置（默认 1 = 原图分辨率），面板显示为“纹理 800×600（原图的 50%）”。
- `budgetFit` 是纹理集预算不足时的全局缩小系数（≤ 1），在纹理面板显示为一个数，不再与超分、排布步长相乘出第三个“密度”。超分作为独立的导出选项，不进入编辑时的纹理集。
- “按画布匹配”是一个**按钮**而不是模式：把 `textureDensity` 设为使画布纹素密度 ≈ 目标值，写入设置；放大图层后若纹素不足，面板提示，不自动改。
- 纹理集打包为增量：新图层或像素变化只放入/替换该图层的块；放不下才整页重排，后台进行，不阻塞提交（结果到达前用旧页面加该图层的临时独立纹理绘制）。页面尺寸由块尺寸决定，与画布尺寸无关。

### 4.4 生成输入

- 生成器只读 `origin = Psd` 的图层。再生成事务把它读到的每个输入图层的 `(id, pixels, placement)` 记入 G 的检查点记录（`PixelRef` 按内容寻址，记录本身很小）。
- 这一份就是“冻结的生成输入”：`generationSource`、`meshSource`、`placementSource`、1×1 空白占位、`mesh_generation_baseline`、`rig_generation_baseline` 全部退役。
- 绘画改变 `pixels` 不触发再生成（D 类：只换纹理块）。只有显式的“重建网格”（第 6 节）或 B 类事务读新的像素。

## 5. 操作

| 操作 | 类别 | 作用 |
| --- | --- | --- |
| `layer_import`（文件或素材库） | A | 新建 `User` 图层 + 在 M 中按第 6 节生成网格，挂到指定父级；一次提交 |
| `layer_transform(layer, affine)` | A | 改 `placement`；对该图层在 M 中的所有网格做同一画布仿射（第 5.2 节） |
| `structure bind/move`（换父级） | A | 沿用现有语义：默认姿态下画布位置不变 |
| `layer_mesh_rebuild(layer, settings?)` | A | 从当前像素重建该图层的网格，迁移绑定（第 6 节） |
| `layer_paint` / `layer_replace_image` | D（像素） | 新的 `pixels`；网格不变；超出网格覆盖的像素给出提示 |
| `layer_set_texture_density` | D | 只换纹理块 |
| `layer_delete` | A（User）/ B（Psd） | 用户图层：从 M 删掉其网格；PSD 图层：作为生成输入移除的再生成事务 |
| `layer_classify` | B（Psd）/ 元数据（User） | PSD 图层改变生成；用户图层只记标签（供预设，如“摆动目标”） |
| `layer_adopt_into_generation` | B | 显式把用户图层变为生成输入（少用；替代现在“导入后再改分类让生成器接管”的隐式行为） |

### 5.1 导入与放置会话

1. 拖入或菜单导入：解码、裁掉透明边、算出初始 `placement`（放在视口中心、按需等比缩小到画布内），在**会话**中建出图层与网格（第 6 节，后台线程，带进度）。此时什么都不提交。
2. 会话期间画布显示“候选图层”：用其图像作为独立纹理、其网格按当前 `placement` 绘制（与最终渲染相同的网格与纹理，不是矩形框）。手柄拖动只更新会话里的仿射矩阵，每帧仅上传一个 3×3 矩阵。
3. 父级：拖入时落在层级面板某个变形器上、或会话面板里选择父级；候选网格实时显示在该父级当前姿态下的位置（只需对候选网格做一次父级变换求值）。
4. 确认：一次提交 `layer_import`（像素、最终 `placement`、父级、网格），一个历史节点。取消：丢弃会话，没有历史节点、没有残留。
5. 多张图片一起导入：每张一个候选，会话中逐个调整，确认时一个节点。

素材库（`asset_import_png` + 配准锚点）是同一个 `layer_import`，额外带配准元数据；`layer_set_placement`、`layer_finalize_placement`、`placementSource` 退役。

### 5.2 变换

- 画布变换工具对**任何图层**（PSD 或用户、有无父级、是否绑定）在物件模式下产生 `layer_transform`。编辑模式下的顶点编辑仍是 `canvas_geometry`，两者不再互相猜测。
- `layer_transform` 在 M 上：对图层的每个网格，静止位置先换到画布、施加仿射 A、再换回父级空间；关键形位移按每个顶点处“父级空间 → 画布”映射的局部雅可比换算：先换到画布、乘 A 的线性部分、再换回（父级为旋转时即整体线性；为 Warp 时逐顶点，与再生成合并中“改父级”的换算相同）；路径锚点、Glue 顶点对随顶点走；UV 不变。
- 绑定了骨骼权重、模拟、摆动的网格同样可以变换：顶点组按顶点下标，下标不变；模拟与摆动在修改器中重新求值。不再有 "relocate before binding" 一类拒绝。
- 拖动中：画布对该图层所有网格的**已求值**顶点施加同一屏幕仿射（GPU 统一变量），不改运行时、不求值 Rig；松手提交一次 `layer_transform`，提交完成前保持该仿射显示，完成后无缝切换。
- 父级是 Warp 时，网格在 Warp 网格以外的部分照 Warp 的外推规则变形；会话提示“部分超出 Warp 范围”，不拒绝（现在的 "Parent transform cannot place the imported mesh" 退役）。

### 5.3 删除

- 用户图层：一个 A 类提交，删除图层与其网格（及以它们为目标的 Glue、路径、遮罩引用，清单在确认框列出）。撤销恢复。
- PSD 图层：B 类再生成事务，生成输入不再包含它，按[合并规则](MATERIALIZED_RIG.md#5-再生成合并)删除用户未改过的生成对象、保留改过的并报告。删除后的图层不再影响任何框架。
- `deletedLayerIds`、`layer_soft_delete`、`layer_restore`、`layer_membership` 标记、延后过滤模式、`layer_cancel_import` 全部退役。“隐藏”是 `visible = false`，与删除无关。

## 6. 网格：触发点与密度

### 6.1 触发点（完整清单）

| 触发 | 范围 | 输入像素 |
| --- | --- | --- |
| 导入（会话中） | 新图层 | 导入的像素 |
| 用户点“重建网格”，或确认修改该图层的网格设置 | 该图层 | 当前像素 |
| B 类再生成事务（改生成设置、分类、骨架、更新生成…） | 生成器的 PSD 图层 | 再生成读到的输入（4.4） |
| 拆分 | 被拆的图层 | 切割现有网格，不重新生成（沿用） |

**除此之外没有任何操作会生成或重建网格**：变换、换父级、绘画、换图、调纹理密度、删除别的图层都不会。绘画或换图后像素超出网格覆盖时，图层面板与画布显示“有 N% 的可见像素不在网格内”与“重建网格”按钮；网格覆盖之外的像素不渲染（与现在相同，但现在是静默的）。

重建网格时绑定的迁移沿用 `RasterMeshJournal.prepare` 的顶点来源（精确匹配 → 重心坐标 → 最近顶点），用空间索引把复杂度从 O(V·T) 降到 O(V log T)。

### 6.2 密度

```
目标边长（画布单位）= 网格间距设置 × 语义系数
描边与内部采样在图层图像上进行，步长 = 目标边长 ÷ |placement 缩放|（换算成图像像素），
且不小于 2 个图像像素（低分辨率图像放大时不过度加密）
```

- 网格间距以**画布单位**为准，与文档尺寸无关；`unitScale` 只保留给旧网格的复现（生成器版本的一部分），新网格不使用。
- 去掉 `max(12, …)` 下限：设置值就是实际值，界面的允许范围与生成器一致；语义系数表只在一处定义。
- 图层面板显示“网格间距 8 画布单位 ≈ 原图 20 像素 · 312 顶点”。导入会话中可以直接拖动这个值并实时看到网格。
- 缩放图层后不自动重建：网格随图层缩放，面板显示“当前间距 16 画布单位（设置 8）”，用户决定是否重建。

## 7. 身份

- `LayerId`：新建时生成 `L` + 10 位 base32 随机串，保存在图层上，永不复用，不由路径、名称、序号或内容推导。PSD 图层首次导入时生成一次；重新载入 PSD（替换源图）按 `lyid`、退而按名称 + 位置做一次显式匹配，结果给用户确认。
- `DrawableId`：网格创建时生成并保存在 M 中。生成器仍按现有规则为**生成的**网格提出 ID，但再生成合并先按 `(layerId, 角色)` 把 G′ 的对象对齐到 M 中已有的网格（角色：主网格、嘴唇条带 n、拆分部件 key），对齐上的沿用 M 的 ID；于是改分类不再给网格改名、不再重新编号兄弟网格。
- 所有“按前缀推断归属”（`owner:`、`::mouth-lip`、`:l`/`:r`、`substringBefore(':')`）退役，归属一律读网格上的 `layerId`。

## 8. 交互与性能

| 动作 | 拖动中 | 提交 |
| --- | --- | --- |
| 导入会话 | 候选网格 + 独立纹理，GPU 仿射 | `layer_import`：M 增加网格 → 修改器 → 编译；纹理集增量放入一块 |
| 变换 | 已求值顶点 × GPU 仿射 | `layer_transform`：M 改该图层网格 → 修改器 → 编译；纹理集不动 |
| 换父级 | 无 | A 类 `structure bind` |
| 绘画 | 现有绘画会话（图层图像空间） | 新 `pixels` → 换该块纹理；不分析、不生成 |
| 纹理密度 | 无 | 换该块纹理 |

- 每个工作区只有一个 `PSD2LivePipeline` / `WorkspacePreviewBuilder` 实例，缓存跨提交保留。
- A 类提交不调用 `CharacterAnalyzer`：分析结果（分类、面部中心）只在 B 类事务与打开时计算，按生成输入的 `PixelRef` 集合缓存。
- 预览与提交是同一个候选函数；“预览能看到、提交被拒绝”的分歧不再存在。
- 运行包编译成为 A 类提交的主要开销。若不达 150 ms 目标，下一步是增量编译（只重写变化网格的块），作为独立优化项，不影响本设计。

## 9. 界面

- **图层面板**：每行一个图层，显示缩略图、名称、来源（PSD / 导入 / 拆分）、像素信息（原图 1600×1200 · 纹理 800×600 · 画布 160×120 · 312 顶点），以及“网格未覆盖 N%”“纹素不足”这类提示。删除就是删除（可撤销）；没有派生行，没有“全部恢复”。
- **画布**：物件模式的变换手柄对所有图层一致；绘画模式按 `placement` 显示图层图像，与渲染使用同一网格裁剪显示（网格外的像素以棋盘格淡显，表示“不会渲染”），不再出现“绘画位置与渲染位置不同”。
- **纹理面板**：只读视图加 `textureDensity` 与固定位置；每个纹理块标注所属图层与“原图的 N%”；`budgetFit` 作为一个全局数字显示。
- **导入会话面板**：父级选择、名称、网格间距（实时）、纹理密度、确认 / 取消。

## 11. 迁移

旧工程打开时执行一次性转换（与 [固化 Rig 第 7 节](MATERIALIZED_RIG.md#7-兼容与迁移)相同的方式：转换结果作为新修订保存，旧修订只读）：

1. 每个源图层 → `Layer`：`pixels` = 当前栅格，`placement` 由 `bounds`/`rect` 得出；`import:`、`agent:`、`artwork:`、`split:` 图层为 `User`，其余为 `Psd`。ID 保留原值（已有引用不断），新建的才用新格式。
2. M（最后一个检查点的作者态 Rig）中的网格补上 `layerId`（取自现有的 `layerIdByDrawableId`），UV 由画布单位按该图层的 `placement` 逆变换换成图像像素。
3. 生成输入：取 `generationSource`（若有）中 PSD 图层的像素与位置写入 G 的记录；空白占位、`meshSource`、`placementSource` 丢弃。
4. 软删除的图层：PSD 图层仍保留在 G 的生成输入中（它们确实生成了当前框架），但从图层列表移除；下一次 B 类事务时按正常的删除合并处理。用户图层直接删除。
5. CMO3 导入模型：所有图层为 `User`（没有生成输入），网格本来就全部在 M 中。
6. 日志中的 `canvas_mesh_create`、`canvas_mesh_rebuild` 只作历史保留，不再写入新的。

转换后的工程不能被旧版本打开（工程格式版本 +1）。

## 12. 分阶段计划

每阶段可单独合入，合入时删除被取代的代码；每阶段结束全量测试通过。

| 阶段 | 内容 | 删除 |
| --- | --- | --- |
| P1 模型 | `Layer`（`pixels` + `placement` + `origin`）、网格的 `layerId` 与图像空间 UV、纹理集按图层块绑定（4.2、4.3）、迁移 1–3、5 | `rect`/`storedCanvasRect`、`LayerCanvasRect`、经画布中转的 `reboundTo`、`layerIdByDrawableId` 等派生映射 |
| P2 变换 | `layer_transform`（A 类）、GPU 拖动预览、统一的变换工具 | `layer_set_bounds`、`layer_set_canvas_rect`、`importedBounds`、`WorkspaceLayerPlacementGuard` |
| P3 导入 | 导入会话、`layer_import`（文件与素材库合一）、一节点提交 | `WorkspaceImagePlacementSession`、`WorkspaceImagePlacementCommands`、`WorkspaceLayerInsertionEdits`、`layer_set_placement` 与 finalize、`placementSource` |
| P4 网格 | 触发点清单（6.1）、`layer_mesh_rebuild`、密度规则（6.2）、空间索引迁移 | 绘画自动建网格、`meshSource`、`mesh_generation_baseline`、`buildPreviewPreservingPaths`、`MeshRebuildEdits.reset`、`max(12, …)` |
| P5 生成输入与删除 | 生成输入记入 G（4.4）、硬删除（5.3）、迁移 4 | `generationSource`、空白占位、`deletedLayerIds`、`RigLayerDeletion`、`layer_membership`、延后过滤 |
| P6 身份与界面 | ID 生成规则、按 `(layerId, 角色)` 对齐、图层面板与纹理面板（第 9 节）、MCP 接口（第 10 节） | 前缀推断、`splitDrawableIds`、`assignSplitDrawableIds` 的拼装、双份 `layerVisibility` |

**测试**：第 1 节的蝴蝶结场景作为端到端测试（应用层驱动：导入 → 会话中变换 → 确认 → 换父级到头部 Warp → 再变换 → 绘画 → 逐步撤销），断言历史节点数、每次提交不调用分析与网格生成（计数器）、纹理块尺寸等于原图 × 密度、画面位置在换父级前后不变、冷启动构建与会话模型一致；另加提交耗时的基准（不作为失败条件，记录趋势）。

## 13. 需要决定的事项

| 事项 | 建议 | 代价 |
| --- | --- | --- |
| UV 改为图层图像空间 | 采用。这是去掉“移动图层要重建 / 重新绑定”的根本 | P1 要改所有读写 UV 的地方（生成器输出、日志记录的解码、导出前的绑定） |
| 用户图层不参与自动生成 | 采用。导入的图片不再被分类后由生成器生成变形器；需要时显式 `layer_adopt_into_generation` | 现在“导入后改预设让它自动挂到头发物理”的用法要改成显式一步 |
| 删除改为可撤销的真删除，去掉“全部恢复” | 采用 | 用户习惯的“全部恢复”消失（撤销可替代） |
| 工程格式升级、旧版本不能打开新工程 | 采用 | 与旧版本不能来回切换 |
| 网格间距改为画布单位、与文档尺寸无关 | 采用，只影响新建与重建的网格 | 同一设置值在大画布上得到更密的网格（这正是预期） |
