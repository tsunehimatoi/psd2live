# 素材与 Layout 工作区

[文档目录](../../README.md) · [PSD 素材与命名](PSD_LAYER_SPEC.md) · [文档层](DOCUMENT_LAYER.md) · [工程格式](PROJECT_FORMAT.md) · [使用指南](../guide/LAYOUT.md) · [路线图](../ROADMAP.md)

本页说明基础 Layout 的实现：素材库、摆放、语义标签，以及"先摆放、再生成、可以反复添加和再生成"的 Rig 生成流程。对齐、抠图、补全等依赖外部 AI 的功能不在其中，见 [Layout 的 AI 辅助](LAYOUT_AI_ASSIST.md)（设计中）。操作的使用方法见[使用指南](../guide/LAYOUT.md)，MCP 契约见 [MCP_AUTHORING.md](../agent/MCP_AUTHORING.md)。

## 解决的问题

1. **生成太早。** 以前导入 PSD 的同一步就生成了 Rig，工程里不存在"有图、还没生成"的状态。
2. **之后加的图不会被生成器认领。** 生成后用 `layer_import_images` 加入的图层是用户网格，永远不参与生成。
3. **分辨率被画布绑死。** 小部件只能用画布像素；工程底层早已把画布矩形和栅格分辨率分开（[逐层尺寸](DOCUMENT_LAYER.md#逐层尺寸)），但缺少按部件选分辨率的主流程。
4. **分类是固定枚举。** "类型 / 部件 / 侧别"三列下拉无法表达组合，也挂不了用户自己的标记。
5. **没有素材管理。** 工程里的图只有"已经是图层"一种身份。

## 总体结构

- **Layout 就是源图层本身。** 把素材放到画布上，就是在 `WorkspaceDocument.source` 里增加一个源图层；画布矩形决定位置和大小，像素保持素材原分辨率。不存在与源图并行的 Layout 文档，也没有"发送"一步。
- **生成是显式的一步。** 文档的 Layout 状态（`WorkspaceDocument.layout`，[`WorkspaceLayout`](../../../src/main/kotlin/io/github/psd2live/project/WorkspaceLayout.kt)）记录生成进行到哪里：工程是否已生成、哪些图层在上次生成之后放置、哪些分类改动还在等待。`rig_generate` 把等待的内容交给生成器，用现有的三方合并保留用户编辑。
- **语义标签**取代"类型 / 部件 / 侧别"：生成器认识的词决定部件与侧别，其余是用户自己的标记。差分（开关 / 切换）单独一栏。
- 编辑器的"选择"模式改名为"**物体**"模式（界面文字与教程；内部枚举 `EditHierarchyMode.SELECT` 与快捷键动作 `MODE_SELECT` 不改名，已保存的键位不失效）。

导入 PSD 仍是一步完成：新工程直接生成，结果与以前相同；同时 PSD 的每个图层也登记为素材，并与对应源图层关联，可以在素材面板里替换、再放置或导出。

## 语义标签

### 模型

[`LayerTags`](../../../src/main/kotlin/io/github/psd2live/core/LayerTags.kt) 定义词表与映射：

| 类 | 词 | 生成器 |
| --- | --- | --- |
| 部位词 | `hair` `back` `front` `headwear` `face` `detail` `eye` `iris` `white` `lash` `closed` `brow` `eyewear` `ear` `accessory` `nose` `mouth` `open` `teeth` `upper` `lower` `tongue` `neck` `top` `arm` `bottom` `leg` `foot` `tail` `wings` `object` | 读取 |
| 侧别词 | `left` `right` | 读取 |
| 用户标签 | 其他任意文字（不超过 48 字符，不含逗号与控制字符） | 不读取 |

- 每个 `SemanticTag` 对应一组部位词，例如 `{hair, front}` 是前发，`{eye, iris}` 是瞳孔，`{mouth, open}` 是张嘴，`{neck, accessory}` 是领饰。一组标签对应到"包含其全部词、且词数最多"的那个部位；同样具体的多个部位按表中顺序取第一个，并标为有歧义。对应不到任何部位即"未识别"。
- 同时有 `left` 与 `right` 时视为双侧；编辑时两者互斥。
- 部位与侧别仍写进图层的分类覆盖（`layerOverrides`），所以生成器读到的 `LayerSemantic` 与以前完全相同，网格 ID 也不变；用户标签单独存在 `layout.layerTags`，不进入生成配置，改它不会重建 Rig。
- 差分（`PRESET / TOGGLE / SWITCH` 与参数、切换序号）不是语义，作为图层的差分属性保留，界面上在标签旁单独一栏。

### 标签从哪里来

- **名称识别**：`LayerClassifier` 的别名表照旧给出分类，标签由分类换算；在标签编辑框里输入别名（如 `前发`、`eye-l`）会换算成对应的词。
- **素材标签**：素材条目和文件夹可以带标签。放置时，条目与其所在各级文件夹的标签合并：部位与侧别词写成图层分类，其余成为图层的用户标签。
- **手工**：图层表的标签格点开后可删除、输入新增（带词表补全），也可直接选部位、侧别。

### 生成后的分类修改

已生成的图层改分类或标签后，新的分类先进入 `layout.generation.pendingClassifications`，Rig 仍按生成时的分类；下一次 `rig_generate` 才写进 `layerOverrides` 并经再生成合并生效。多次修改只合并一次。还没被生成器读过的图层（未生成工程的图层、生成后才放置的图层）改分类立即写入，因为它们还没有 Rig。生成设置（网格密度、Rig 数值等）的修改仍立即再生成。

## 生成状态

| 状态 | 画布 | 可做的事 |
| --- | --- | --- |
| 未生成（`project_create` 新建的工程） | 每个图层显示为一个普通网格（图层轮廓，位于根下，没有变形器与参数） | 素材、放置、移动缩放镜像、替换、删除、标签、生成设置；Rig 编辑与导出返回 `not_generated` |
| 已生成、有待生成内容 | 已生成部分照常显示 Rig；之后放置的图层在 Rig 前方显示为普通网格 | 一切照常；对待生成图层的 Rig 编辑返回 `not_generated`；导出只包含已生成部分 |
| 已生成、无待生成内容 | 与以前相同 | 与以前相同 |

旧工程没有 Layout 状态，读作"已生成、无待生成内容"，打开、保存、文档身份都与以前相同。

### 生成视图

生成器只读文档的**生成视图**（[`WorkspaceLayoutPreview.base`](../../../src/main/kotlin/io/github/psd2live/application/WorkspaceLayoutPreview.kt)）：源图里去掉待生成的图层（未生成工程则是全部图层）。所有 Rig 编辑也在生成视图与生成模型上进行，待生成图层原样放回；新的日志条目若指向待生成图层的网格会被拒绝。

预览模型 = 生成模型 + 待生成图层的普通网格：待生成图层由一次只生成网格的构建（`meshOnly`、无变形器与物理）得到轮廓网格，纹理放在生成模型纹理集页面之后，网格放在面板顶层、绘制在最前。`RigPreviewModel.layoutBase` 保存不含它们的生成模型，后续构建、再生成合并与导出都读它；未生成工程的预览模型标记 `layoutPreview`。

待生成图层没有 Rig，按画布矩形和像素编辑：

- `layer_set_canvas_rect` 与物体模式的整层拖动（`layer_transform`）改写画布矩形，像素不重采样；镜像翻转像素；旋转要等生成后再做。
- `layer_replace_image` 只换像素，画布矩形不变，也不冻结任何生成输入。
- `layer_delete` 直接从源图移除，连同它的标签、素材关联与等待项。

### 生成与重新生成

`rig_generate` 是一次文档编辑、一个历史节点：

1. 未生成工程：标记为已生成，清空生成输入，按当前全部图层从头构建，结果与直接导入同一组图层相同。
2. 已生成工程：待生成图层加入生成；等待的分类写入 `layerOverrides`；选择刷新几何的图层（默认是替换过图片的图层，`refresh_geometry` 可指定，`[]` 表示全部保留）从冻结的生成输入（`generationSource`）中移除，从当前像素生成。
3. 之后照常准备候选：分类变化走 `normalizeMeshEdits` 的再生成合并，新增图层走构建时的再生成合并（`RigRegenerationCheckpoint`）。用户没改过的跟随新的生成结果，用户改过的保留，新图层采用生成的网格；已有网格的 ID 由 `splitDrawableIds` 固定，新图层按分类取名。合并不能干净迁移的内容进入 `quality.regeneration`。

已生成图层上的 `layer_transform` 是用户对网格的编辑，再生成合并会保留它，不折算回画布矩形。

## 素材库

### 类型与来源

| 类型 | 来源 | 在素材库里 |
| --- | --- | --- |
| 位图 | PNG、BMP、TIFF、WebP、JPEG | 一个条目；内置解码器读不了的（有损 WebP、渐进 JPEG 等）用 Skia 解码 |
| 分层图 | PSD；CMO3 的分层图 | 一个文件夹：图层组成为子文件夹，每层一个条目，记下 PSD 中的位置（默认摆放）、不透明度与可见性；CMO3 没有分层图时取其纹理集页面 |
| 矢量图 | SVG | 一个条目，保存 SVG 原文，按其宽高（或 viewBox）用 Skia 栅格化；`material_set_resolution` 改纹理分辨率，单边不超过 4096 |
| 文件夹 | 软件内新建，或导入的文件夹 | 文件夹，保留嵌套结构（最多 32 层）；按名称自然顺序读取，跳过隐藏项与不支持的文件，经链接重复出现的文件夹只读一次 |

CMO3 的完整模型仍用 `project_import_cmo3` 导入，不进入 Layout 流程。单张图片受 16 MP 上限；一次导入最多 64 个路径、4096 个文件、256 MiB。

### 存储

- 素材库是文档数据（`layout.materials`），**进入历史**：导入、新建文件夹、移动、重命名、删除、标签、改分辨率都是可撤销的编辑。
- 像素沿用按内容寻址的去重栅格（工作目录 `blobs/`，归档 `assets/`），与源图层共用同一份；SVG 原文直接存在素材节点里。PSD 原文件不另存。
- 在 [v2 归档](PROJECT_FORMAT.md) 中，Layout 状态拆成两个新节点：`layout`（用户标签、素材关联、生成状态）与 `materials`（素材库）。没有 Layout 状态的文档不写这两个节点，修订身份不变；不认识这两类节点的旧版本会拒绝打开新文档，而不是丢掉素材。
- 被未删除的图层显示着的素材不能删除，错误信息列出这些图层；删除图层后即可删除素材，撤销会一起回来。
- 旧工程打开时素材库为空；之后导入的 PSD 会把各图层登记为素材并建立关联。
- 现有 `asset_*` 工作流的 PNG 素材与 `assetCatalog` 照常工作，与素材库分开。

导入在任务里读取文件（不进入纯候选），读出的内容暂存在进程内，以内容摘要为名（`material_add` 的 `staging`），然后作为一次文档编辑提交。

### 放置

`layer_place` 把条目或整个文件夹放到画布上：

- 条目成为一个源图层；文件夹的每个条目各成一个图层，子文件夹成为源图组，条目之间保持相对位置。
- 默认位置是条目的默认摆放（PSD 中的位置），连同它所在的 PSD 画布（条目的 `placementWidth × placementHeight`）一起映射到工程画布：两者尺寸相同时原样放回，不同时把 PSD 画布居中、超出时等比缩小，图层在其中保持原来的位置。不知道 PSD 画布尺寸的旧条目把这些位置的整体包围盒当作画布居中。没有默认摆放时按"1 素材像素 = 1 画布单位"居中，超出画布时等比缩小。`rect` 指定单个条目的画布矩形（像素不重采样，矩形越小纹理越密），`at` 把整体中心放到该点。
- 新图层画在已有图层之上；在已生成工程里进入待生成。
- 条目与各级文件夹的标签成为图层标签（见上）。
- `layer_replace_image` 新增来源 `material_id`：图层显示该素材，素材关联随之更新。

### 参考图与特写

`WorkspaceLayout.reference`（`LayoutReference`）把一个素材条目叠在画布上，供摆放和对照：素材 ID、画布矩形、不透明度、显示与否。它是文档数据（随工程保存、可撤销），但不是图层，生成视图、Rig 与导出都不含它；被参考图使用的素材不能删除。`layout_set_reference` 设置、修改或清除，新设时默认等比缩放到画布内并居中。

`material_crop` 从条目无损裁出新条目：`rect` 为条目像素，`canvas_rect` 为画布单位（经参考图矩形，或条目按本画布的默认摆放换算）。新条目的默认摆放就是这些像素在画布上的位置，放置时落回原处。`material_export_png` 把条目原样写成 PNG。典型用法是从参考图截取头部、眼睛等特写，交给外部放大或重绘成更清晰的分层部件，再导入并按特写的位置放置——部件的像素多于参考图，图层摆在同样大小的矩形里，纹理就更密。导入的图片没有位置，`material_set_placement` 的 `from` 让它取特写的位置。

### 剥离

`material_peel`（`WorkspaceMaterialPeel`）用一张去掉了某个部件的生成图把部件从当前图上剥下来，得到两个新条目，都放在当前图的位置：

- **部件**：当前图自身的像素，透明度来自两图的差异（各通道色差的最大值，轻微模糊后在阈值区间内线性过渡），可用同尺寸蒙版限制范围、扩张（`grow`）、把收缩后的蒙版强制不透明（`core`），最后闭运算填小缝（`close`）。`keep` 给出部件上的点（条目像素），只保留与这些点相连的块，生成模型顺手改动的远处碎点不进部件。
- **其下的图**：当前图，只在部件区域换成生成图。生成模型会轻微重画整张图，所以部件之外一律保留原像素，部件叠回其下的图即还原当前图。
- **比较尺寸**：生成模型常在较小的尺寸上工作，输出放大回当前图的尺寸后，每条线都比原图略软，按原尺寸比较会把线条当成差异。`compare_scale` 给出放大倍数，两图先按块平均缩小同样倍数再比较，差异再双线性放大回来，只剩生成模型真正改动的地方。
- **色调**：比较前先去掉整图的色调偏移（各通道差值的中位数，在比较尺寸上统计），否则偏移本身会被当成一层淡淡的部件；揭开区域合成前按周围未改动的一圈像素在 Lab 空间匹配均值与方差。

从最前面的部件开始，每一步在上一步剩下的图上继续，被挡的部分由生成模型补出。外部生成工具见 `tools/comfy`。

`view_render_model` 可同时画参考图：`reference.mode` 为 `over`（盖在模型上）、`under`（垫在模型下）或 `difference`（逐通道差值，重合处为黑，结果附 `referenceDifference` 平均差值 0–1），`opacity` 覆盖参考图自身的不透明度；`density` 按图层纹理密度着色（每画布单位 ¼ 纹理像素以下为蓝、1 为绿、4 以上为橙，与纹理工作区热力图同一色阶），结果附 `texelDensity`。编辑画布右下的显示开关里有「参考图」（文档有参考图时出现，按其不透明度盖在作品上）与「纹理密度」；素材右键菜单可设为参考图、调整不透明度（按 25% 递进）与清除。

### 矢量绘制

部件可以照着参考图用矢量画出来（`WorkspaceDrawingEdits`、`WorkspaceVectorDrawing`）：

- **绘制即素材**：`material_draw` 写入一个矢量条目，SVG 的 `viewBox` 是它在画布上的位置（画布单位），也就是条目的默认摆放；条目按密度（每画布单位的纹理像素，0.05–16）渲染，小部件可以给到需要的像素。写入时去掉根元素的 `width`、`height` 并设 `preserveAspectRatio="none"`，`viewBox` 恰好铺满栅格。重画时，显示它的图层替换像素，原先位于旧位置的图层移到新位置；图层与素材的关联保持。
- **局部修改**：`material_draw` 的 `edits` 按元素 `id` 改属性（`WorkspaceVectorDrawing.patch`），不必整份重发；`material_get` 的 `include_svg` 读回存储的原文。
- **绘制套件**：`WorkspaceLayout.drawingKit`（`DrawingKit`）保存颜色、类规则和 SVG 定义，所有绘制共用，各部件因此用同一套颜色与线条。修改套件时所有矢量条目按原分辨率重新渲染，变化的同步到图层；会让绘制缺少颜色时拒绝。
- **渲染前的解析**：Skia 的 SVG 模块不支持样式表与 CSS 变量，渲染前先把套件与绘制自身 `<style>` 的规则（元素、`#id`、`.class` 选择器，可组合、不可嵌套）按特异性写入各元素的 `style`，元素自己的 `style` 最后；`var(--name)` 换成套件颜色；套件定义并入 `<defs>`（绘制自身同 id 的优先）；带 `data-taper` 的路径按宽度系数（从头到尾均匀分布）把描边换成填充轮廓，线条两头可以收细。`<ellipse>` 换成等价的 `<path>`（渲染器给椭圆的包围盒渐变画成黑色）。导入的 SVG 同样按文档套件渲染。混合模式不渲染。
- **读参考图**：`reference_sample` 取点的颜色和区域主色（Lab 空间对 5 位直方图做 k-means），`reference_trace` 按颜色容差从种子扩展、沿像素边界取外轮廓并简化成多边形与平滑路径，`reference_snap` 把点吸到附近线条的中心。三者都按参考图在画布上的位置换算，返回画布坐标。
- **对照**：`view_render_model` 的 `grid` 画带坐标标注的网格，`outline_material_ids` 把条目的不透明边缘描在视图上，不必放置即可与参考图对照。

### 导出为 PSD

`material_export_psd` 把文件夹写成 PSD：条目按默认摆放放置（没有的从左上角排成一行），子文件夹成为图层组，画布取工程画布并扩到能容纳全部条目；矢量条目按纹理分辨率栅格化，密度不同的图层按画布矩形重采样写出。

## 素材与图层的关联

`layerMaterials` 中关联的图层显示素材自身的像素（栅格与素材相同，矩形为放置矩形），素材是唯一来源（`WorkspaceMaterialLinks`）：

- 绘画关联图层即绘画素材：`source_paint_*` 与 `paint_session_begin`（`layer_id`）按普通图层在整张画布上绘画，会话快照另报 `material_id`；提交时按图层网格裁切（`WorkspacePaintOverflow`），网格上且在素材矩形内的像素写成素材修改并同步所有关联图层，其余新画的像素拆成紧邻其上的新图层，关联保留。拆出的图层同时成为素材（与原图层的素材同一文件夹、紧随其后，原图层未关联时放在顶层）并与之关联。
- 网格重建对关联图层保留整幅素材栅格，不裁边。
- `WorkspaceDocumentEdits.apply` 与栅格提交在候选完成后执行 `reconcile`：图层像素不再等于素材时移除关联（拆分、换成别的图片等）。`material_unlink` 显式解除，像素保持不变。

## 界面

- **素材面板**（停靠模块 `materials`）：左侧可收起的精简文件夹树，与内容区之间的分隔线可拖动调宽（72–360dp）；内容区在路径栏（↑ 与各级）下列出当前文件夹的子文件夹与条目，可切网格 / 列表；来自 PSD / CMO3 的文件夹（`MaterialFolder.origin`）显示为带格式色带的文件图标与项目数；搜索匹配名称与标签（含文件夹标签），范围为全部文件夹。条目角标显示被几个图层使用。从系统拖文件到面板即导入到指针下的文件夹（文件夹磁贴或路径栏一级，否则当前文件夹）；把条目或文件夹拖到编辑画布即在落点放置，拖到文件夹磁贴、树行或路径栏一级即 `material_move`；右键菜单为共用的 `PressMenu`（与画布菜单同一外壳与动画）；双击文件夹进入，双击条目打开素材窗口；右键菜单有打开、放置、替换选中图层的图片、纹理分辨率（SVG）、选中使用它的图层、重命名、新建文件夹、文件夹导出为 PSD、移到上一级、删除。缩略图按需在后台生成，按 128 / 512 / 2048 三档缓存在内存中；透明边超过约两成面积时裁到可见像素再缩放。
- **素材窗口**：独立的系统窗口（`MaterialEditorWindow`，`PSD2LiveViewModel.materialEditor` 指定条目），可自由缩放、移动；打开时面板单击条目即切换。视图滚轮缩放、中键 / 空格拖动平移，视图之外裁掉。绘画直接复用画布的绘画模式：窗口持有一个专用的 `CanvasEditor`（绘画模式），其绘画会话是素材会话（`WorkspacePaintSession.materialId`，`layerId` 为 `material:<id>`）；工具栏 `CanvasToolBar`、选项栏 `ToolOptionsBar`、会话栏 `PaintSessionBar`、右键菜单 `CanvasContextMenu`、叠加层 `drawPaintOverlays` 与按下 / 拖动 / 松开处理都是画布的同一份代码，按键按按键表分派。颜色与笔尖设置打开时取自当前画布、关闭时写回。素材会话只在素材自身像素变化或换工程时失效，其他编辑照常提交；应用经 `paint_session_commit` 写成一次 `material_set_pixels`，离开素材或关闭窗口时自动应用。"调整"菜单为翻转与色相 / 饱和度 / 明度 / 对比度（后台预览），有未应用笔画时不可用。
- **Layout 工作区预设**：素材面板在左，编辑画布居中，层级树与图层表在右。开始页「排版工程」（或"文件 > 导入 > 新建 Layout 工程"）输入画布尺寸后新建未生成工程并进入此工作区。
- **生成栏**：编辑画布右上角在有待生成内容时出现，显示"未生成"、"待生成 N"或替换过的图片数，主按钮"生成 / 重新生成"，下拉可选择是否刷新替换图片的几何。
- **图层表**：类型 / 部件 / 侧别三列改为标签格（待生成的分类以强调色描边）、差分与差分参数两栏。
- **教程**："选择模式"一课改为"物体模式"，新增"素材与摆放"一课。

## 操作（GUI 与 MCP 共用）

所有文档操作都是纯候选，GUI 通过 `WorkspaceDocumentPort.applyDocumentEdits` 调用，MCP 以单成员文档批量的进程任务执行，二者都可作为 `workspace_apply_edits` 的成员。

| 操作 | 种类 | 说明 |
| --- | --- | --- |
| `layer_tag` | 文档 | 1–128 个图层的标签 `set` / `add` / `remove` |
| `layer_set_variant` | 文档 | 差分：`none` / `toggle` / `switch` |
| `layer_classify` | 文档（现有） | 已生成图层的结果带 `pending: true` |
| `rig_generate` | 文档 | 生成或重新生成；`refresh_geometry` |
| `material_import` | 文档，任务 | 读取文件并提交 `material_add` |
| `material_add` | 文档 | 加入 `material_import` 暂存的内容 |
| `material_folder_create` / `material_move` / `material_rename` / `material_delete` / `material_tag` | 文档 | 整理 |
| `material_set_resolution` | 文档 | SVG 纹理分辨率，显示它的图层随之替换像素 |
| `material_unlink` | 文档 | 解除图层与素材的关联，像素归图层自己 |
| `material_set_pixels` | 文档 | 写入素材绘画会话暂存的像素（`staging`），由 `paint_session_commit` 发起；尺寸不变，显示它的图层随之替换像素 |
| `material_paint` / `material_adjust` | 文档 | 在条目像素上画一笔或按顺序画一组笔画（`gestures`） / 翻转与调色；尺寸不变，显示它的图层随之替换像素，SVG 变为位图 |
| `layer_place` | 文档 | 放置条目或文件夹 |
| `material_list` / `material_get` / `material_preview` | 查询 | 列表（分页、筛选）、详情（含引用图层）、PNG 预览 |
| `material_export_psd` | 输出，任务 | 文件夹导出为 PSD |
| `material_export_png` | 输出，任务 | 条目原样写成 PNG |
| `layout_set_reference` | 文档 | 设置、修改或清除参考图 |
| `material_crop` | 文档 | 无损裁出新条目，记住画布位置 |
| `material_set_placement` | 文档 | 设置条目的默认位置（矩形或取另一条目的位置） |
| `material_peel` | 文档 | 用去掉部件的生成图剥离部件，新建部件与其下的图两个条目 |
| `material_draw` | 文档 | 以画布坐标的 SVG 绘制或重画矢量条目，按密度渲染，图层随之更新 |
| `layout_set_drawing_kit` | 文档 | 绘制共用的颜色、类规则与定义，修改后重新渲染所有矢量条目 |
| `reference_sample` / `reference_trace` / `reference_snap` | 查询 | 参考图的颜色与主色、魔棒轮廓、吸附到线条 |
| `project_create` | 工程，任务 | 新建未生成的空工程 |
| `workspace_inspect scope=generation` | 查询 | 是否已生成、待生成图层、等待的分类、可刷新几何的图层 |

`workspace_inspect scope=layers` 的每个图层增加 `tags`，待生成的加 `pending: true`，来自素材的加 `material_id`。新的错误类别 `not_generated`（`WorkspaceNotGenerated`）表示操作需要已生成的 Rig。

## 验证

场景测试覆盖：

- 标签与旧分类得到相同的 Rig 与网格 ID，用户标签不改变 Rig，保存重开保留（`LayerTagScenario`）。
- 未生成工程只显示网格、拒绝 Rig 编辑，生成后与直接构建的 Rig 相同、文档相同；生成后放置的图层显示为普通网格、可移动、拒绝 Rig 编辑，重新生成后获得生成网格并随头部转动，用户的变形器与关键形保留，网格 ID 不变；分类等待下一次生成，与"分类 + 生成"同批得到同一 Rig（`LayoutGenerationScenario`）。
- 参考图不成为图层、被使用时素材不能删除，按画布矩形裁出的特写像素与参考图一致、放置后落回原处；差值、叠加与密度视图，修改、保存重开与清除（`ReferenceLayoutScenario`）。
- 参考图取色、主色、魔棒轮廓（面积）与吸附到线条；以套件颜色和类规则绘制，位置与像素尺寸来自 `viewBox` 与密度，`data-taper` 线条中间粗两头细，未知颜色被拒绝；放置后重画得更大，图层移到新位置并保持关联；修改套件后绘制与图层同步，删除仍在使用的颜色被拒绝；网格与轮廓视图；保存重开（`VectorDrawingScenario`）。
- PSD、PNG、SVG 导入为素材；文件夹、移动、标签；放置后标签成为分类；被引用的素材拒绝删除；SVG 改分辨率后图层像素变化而画布矩形不变；用素材替换图片；在素材上绘画与调整后显示它的图层同步、画布矩形不变，一组笔画按顺序作为一次修改落下；素材绘画会话的笔画、撤销在会话内，期间其他编辑照常提交，提交后素材与图层一致，素材像素被别处修改后会话拒绝继续绘画；画关联图层（单笔与会话）即画素材、另一个关联图层同步，画出图层网格的部分拆成新图层而关联保留，网格重建保留关联，解除关联后绘画只改该图层，关联随保存重开保留（`aLinkedLayerShowsItsMaterial`）；空调整与同时给出单笔和笔画列表被拒绝，绘画后的 SVG 变为位图；生成、保存重开；文件夹导出 PSD 再读回，图层与位置一致；空工程放置整个 PSD 文件夹后生成（`MaterialLibraryScenario`）。
