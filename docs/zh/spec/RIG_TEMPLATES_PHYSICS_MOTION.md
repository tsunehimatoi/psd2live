# 算法模板目录：物理与动作

> 本目录写于部位与模块架构之前，沿用“插槽 / 模板”的说法：同一插槽下互斥的做法将登记为该部位的**基础算法**，可叠加的能力登记为**模块**，`*/current` 对应各部位的 `legacy` 基础算法。实现状态以注册表（MCP `module_catalog`）为准，本页的 P0/P1/P2 只是规划优先级，“已实现”指引入注册表之前已有的算法。见 [Rig 预设架构](RIG_PRESETS.md)。

[文档目录](../../README.md) · [预设架构](RIG_PRESETS.md) · 模板目录：[面部](RIG_TEMPLATES_FACE.md) · [头发与身体](RIG_TEMPLATES_HAIR_BODY.md) · [物理与动作](RIG_TEMPLATES_PHYSICS_MOTION.md) · [结构与表现](RIG_TEMPLATES_STRUCTURE.md)

本页是 [Rig 预设架构](RIG_PRESETS.md) 的模板目录之一：每个区域插槽可注册多个算法模板，模型预设为每个插槽选择一个模板并给出参数值。同一问题的不同做法作为同一插槽下的不同模板并存。设计依据为通用 Live2D 制作惯例；数值均为建议默认值与可调范围，实现后按出图调校。每个插槽的 `*/current` 是现有算法，作为默认模板登记，选它时输出不变。

## 范围与约定

- 负责插槽：`physics.*`（输入滤波与驱动参数、输入混合、摆链、级联、激励、reflect 与取反）、`motion.*`（待机、眨眼、口型、次级运动、相位与周期），以及 `breath` 的物理 / 动作侧面。头发与衣物的**物理参数**归本组，几何（切段、Glue、网格、关键形形状）归 hair-body 组；本组只写"物理输出接到哪一层、用什么增益"的接线规范。
- 补充插槽：`physics.input`、`physics.axis`、`physics.carrier`（接线规范）、`physics.gravity`、`physics.role`、`motion.phase`、`motion.layer`、`motion.effect-clock`、`host.mapping`。
- 符号：质点（particle）序号 v=1..n，v=1 为最靠根的运动质点；`r` 段长（Cubism 物理单位），`m` mobility，`d` delay，`a` acceleration；输入类型 `X`（平移，只产生瞬态）/ `Angle`（角度，产生稳态偏转）；`reflect` 为取反。H = 人物高，h_head = 头高，L = 部件沿主轴长度，W_f = 脸宽。
- 方向约定（全目录共用）：所有左右成对部件的关键形使用**画布方向**约定（+1 = 尖端朝画布 +X）。reflect 规则都以此为前提；若改用"外侧为正"的镜像约定，横向 / 纵向两类规则都要反转（见 `physics.reflect/vertical-flare` 失败模式）。
- 现有实现登记为各插槽的 `*/current`，依据当前源码。

## physics.filter：输入滤波与驱动参数

把"追踪 / 动作写入的输入参数"和"几何绑定的驱动参数"分开，中间放一个物理组当二阶滤波器。这是所有身体级惯性、级联与耦合的基础。

### `physics.filter/current` — 几何直接绑定标准参数
- 现状：`DeformBodyXY`、`DeformBodyLean`、`DeformBodyZBreath`、头部旋转都直接以 `ParamAngle*`、`ParamBodyAngle*` 为轴；物理只输出头发、眼球果冻、骨骼跟随、摆动、模拟参数。`PhysicsGenerator.headAndBodyInputs` 固定为 AngleX 60 X / AngleZ 60 Angle / BodyAngleX 40 X / BodyAngleZ 40 Angle。
- 问题：身体与头完全同步、像贴纸；追踪抖动被头发、裙摆放大；没有惯性与过冲。

### `physics.filter/drive-param` — 输入参数 → 单摆 → 驱动参数（影子参数）
- 目的：给大块（身体、可选头部滚转）加 80–250 ms 滞后与 5–15% 过冲，并过滤追踪噪声。
- 适用：任何生成模型；身体三轴默认启用；AngleZ 可选（侧倾杠杆最长）；AngleX/Y（视线朝向）默认**不**过滤，或只用极硬弹簧（d ≥ 0.92）。
- 产出：
  - 参数：每个被过滤轴 P 新增驱动参数 `P★`（ID 规则 `<P>Drive`，范围与默认同 P）。P 保留标准 ID，作为追踪 / 动作 / 表情的写入口，不绑定几何；所有生成关键形改绑 `P★`。
  - 物理组 `PhysicsDrive_<P>`：输入 P（Angle 100，或 80 + 耦合 20），1 个运动质点（2 质点链），输出 `P★`（Angle，v=1）。
  - 可选同一输入生成两条驱动（躯干用平滑档、腿 / 下身用更弹档，阻尼低 20–30%）。
- 算法：
  1. 选档：刚性弹簧档（身体）r 9–12、m 0.7、d 0.85、a 1.5；头部滚转档 r 8–15、m 0.8、d 0.92、a 1.2；腿弹档 d 0.6。
  2. 增益标定：离线对 P 施加满幅阶跃，仿真到稳态，取 scale 使稳态 P★/P = 1.0（0.9–1.1）；同时记录 90% 上升时间（目标 0.12–0.3 s）与过冲（目标 ≤ 10–15%），超标调 d/a 重算。scale 不写死，任何参数范围、归一化角度都能自洽。
  3. 输出夹紧：过冲会被参数范围削平；关键形端点必须能承受 ≤ 1.15 倍满值，或把 scale 降 5%。
  4. 下游物理（头发、裙、胸、尾…）的输入改读 P★（见 `physics.cascade/staged-inputs`）。
  5. 导出兜底：目标不支持物理或宿主关闭物理时，P★ 恒为 0、身体冻结。导出选项"直通"：把 P★ 绑定改写回 P（或删除该物理组、参数重命名），写入损失报告。
  6. 动作约束：MotionGenerator、表情只写 P；P★ 不对外开放写入（写了会被物理每帧覆盖）。
- 可调：`lag`（时间常数 0.06–0.25 s，默认 0.12）、`overshoot`（0–15%，默认 8%）、`gain`（0.9–1.1，默认 1.0）、`axes`（{BodyX,BodyY,BodyZ} 默认；可加 AngleZ / AngleX / AngleY / BodyPositionY）、`split_lower`（是否为下身另建更弹的驱动）。
- 失败 / 质检：阶跃响应测试（上升时间、过冲、稳态增益、静止无漂移）；两层滞后叠加使头发迟钝 → 第二层 d 相应降低；过冲过大像果冻；宿主映射到 P★ 时物理每帧覆盖 → 导出说明 + `host.mapping/vts-profile` 预置映射。
- 引擎能力：物理输出到普通参数、参数 used-by 为零的"纯输入参数"、导出时按目标降级。
- 难度：中（参数体系、生成器绑定、导出、MCP 文档同时改）。优先级：P1（价值最高的结构变化，但牵动全部身体生成器与导出路径，需单独一轮）。
- 现状差距：没有"输入 → 驱动"分层；`headAndBodyInputs` 读原值；导出没有无物理回退。

### `physics.filter/head-leads-body` — 只有面部追踪时，由头部角度经物理生成身体
- 目的：没有身体追踪时，得到"头先动、身体慢半拍跟上、手臂衣物再晚一拍"的层级惯性。
- 适用：面向面捕直播的模型；与 `drive-param` 共用驱动参数；用户有身体追踪时切换为混合。
- 产出：BodyX★ ← AngleX、BodyY★ ← AngleY、BodyZ★ ← AngleZ 三个物理组（Angle 型，2 质点）；可选肩 X、胯 X 瞬态组（输入 AngleX，X 型）。
- 算法：
  1. 稳态跟随比 k = 身体满值 / 头满值时的比例：默认 0.35（"跟随型"），可到 0.9（"同转型"）；用阶跃仿真反算 scale。
  2. 身体 Y 用最长摆（最慢），X/Z 次之；r 7–12、m 0.65–0.7、d 0.85、a 1.5。
  3. 瞬态组（肩 X、胯 X）：输入头 X 为 X 型，峰值为参数范围 20–50%，m 0.9（比身体更晚），静止后回中。
  4. 追踪混合开关：有身体追踪时输入改为 0.5·头 + 0.5·身体追踪，或关闭本规则。
  5. 符号约定与头相反时用 reflect。
- 可调：`follow_ratio` 0.25–1.0（默认 0.35）、`lag` 0.2–0.5 s、`overshoot` 0–10%、`transient_peak` 0.2–0.5。
- 失败 / 质检：idle 动作若写身体参数会被覆盖（改写头角或写输入参数）；拖拽时物理需限幅；不要同一参数同时由宿主映射与物理写。
- 引擎能力：同 drive-param。难度：易（在 drive-param 之上只是输入配方）。优先级：P1（随 drive-param 一起交付，作为其输入配方选项）。
- 现状差距：身体只由追踪 / 动作直接驱动。

### `physics.filter/root-inertia` — 不替换直接绑定，只在根部叠一层惯性旋转
- 目的：保留追踪直连的"跟手"，同时给倾斜加过冲与回落，体重感从躯干传到末梢。比 drive-param 改动小，可先落地。
- 适用：身体 Z（侧倾）与身体 Y（上下）；全身或半身。
- 产出：参数 `ParamBodyZInertia`、`ParamBodyYInertia`；在 `DeformBodyZBreath` 内部拆成"直接部分（30–50% 倾角）+ 惯性旋转（其余）"，枢轴在腰 / 胯；物理组 2 个（单摆）。
- 算法：
  1. 根链顺序：呼吸 → [BodyY 惯性 warp] → BodyZ 直接 warp → [BodyZ 惯性旋转] → 身体 XY → 头。
  2. 物理：输入 BodyZ（Angle 100），r 10、m 0.55、d 1.2、a 0.8；输出惯性参数。BodyY 同理（输入 BodyY，X 型）。
  3. BodyY 惯性只做上身下沉与回弹，幅度 ≤ 0.1 h_head；全身站姿时腿用屈膝消化，不整体平移（与 `DeformLegs`"脚不动"一致）。
  4. 尾、裙根、长后摆挂在惯性参数之下，自然获得滞后。
- 可调：`direct_share` 0.3–0.6（默认 0.4）、`overshoot`（由输出 scale 控制，默认 10%）、`pivot_height`（腰 ↔ 胯）。
- 失败 / 质检：惯性过大像喝醉；动作文件里已有缓入缓出时会二次延迟（可按信号来源——追踪或动作——降权）。
- 引擎能力：物理、旋转变形器。难度：易。优先级：P1（与 body.lean / body.turn 的生成器协调后实施）。
- 现状差距：身体参数直接作用于几何，物理只用于悬挂物。

### `physics.filter/derived-rule` — 通用"派生参数规则表"（物理当二阶滤波器）
- 目的：把"B 应跟着 A 走、慢半拍、带过冲"的任何关系写成一条数据规则，由生成器统一变成物理组；drive-param、head-leads-body、表情耦合都是它的实例。
- 产出：规则 `target ← Σ wᵢ·sourceᵢ`，字段 {k 满量程比, T 响应时间, o 过冲, 是否附加 X 型余震分量}；每条规则一个物理组 `PhysicsDerive_<target>`。
- 算法：
  1. 输入设为 Angle 型、权重 wᵢ（和为 100）；单段摆；`scale = k_target / (Σw/100 · θn_rad)`，再用阶跃仿真微调。
  2. 由 (T, o) 查摆参数表：T≈0.3 s、o≈5–10% → r 7–12、m 0.65–0.7、d 0.85、a 1.5；T≈0.5 s、o≈20% → r 10、m 0.8、d 0.9、a 1.5，可再加一段增加余震。
  3. 需要"持续 + 余震"时，同一输入再加一条小权重 X 型规则。
  4. 派生参数被动作写入时，生成动作阶段排除该参数。
- 可调：k 0.3–1.0、T 0.15–0.6 s、o 0–25%、权重。
- 失败 / 质检：输出被参数范围截断；规则形成环路（检测并拒绝）。
- 引擎能力：物理。难度：易（机制）/ 规则表需经验。优先级：P1（作为 drive-param 的实现底座）。
- 现状差距：物理输入集合写死，没有派生参数类规则。

## physics.input：输入混合

### `physics.input/current` — 固定头身输入
- 现状：头发、摆动横向、新建组、模拟默认都用 `headAndBodyInputs`（AngleX 60 X / AngleZ 60 Angle / BodyX 40 X / BodyZ 40 Angle）；纵向摆动用 AngleY 60 X / BodyAngleY 40 X / AngleZ 20 Angle；不含呼吸，不按挂点区分。

### `physics.input/mount-recipe` — 按挂点所在层级与局部运动选择输入、类型与权重
- 目的：让每组物理"感受到"它挂点真实受到的运动：转角 → Angle 型（保持下垂），平移 → X 型（被推一下），并按挂点离头 / 离身的远近分配头身比。
- 适用：所有生成物理组（头发、摆动、饰品、衣物、肢体）。
- 产出：组的输入列表（参数、类型、权重、reflect）。
- 算法：
  1. 求挂点所在的层级根：头（在头部旋转之下）、上身（在身体 Z 旋转之下）、下身 / 腿（根级）、手臂。
  2. 对每个候选输入参数，在其端点求挂点处局部雅可比：旋转分量占比 > 0.5 → Angle 型，否则 X 型。缺省表：
     - 头挂件：AngleX X、AngleY X、AngleZ Angle、BodyX X、BodyZ Angle，头 : 身 ≈ 2 : 1。
     - 后颈 / 长后发：头 : 身 ≈ 2 : 3（后发被身体带得更多）。
     - 上身挂件：只取身体，BodyZ Angle 100、BodyX/Y X 30。
     - 腿 / 根级挂件：BodyX/Y/Z 全部 X 型（10–30）；被裙扫过的再加驱动裙子的参数（X 型 0.2–0.5）。
     - 手臂：身体 X/Y X 型 50、BodyZ Angle 100（下垂臂保持下垂）。
  3. 若 `physics.filter/drive-param` 已启用，身体类输入一律读 P★。
  4. 缺少的参数过滤掉（沿用 `available`）。
- 可调：`head_body_ratio`（每类挂点一档）、`angle_threshold`（0.5）、`sweep_coupling`（0–0.5）。
- 失败 / 质检：全部 Angle 型时静止后不回中、姿态被"拉偏"；全部 X 型时歪头后下垂物跟着歪（应配合 `physics.gravity`）。质检：对每个输入做阶跃，检查挂点处响应方向与"惯性落后"一致。
- 引擎能力：物理；求值器（雅可比）。难度：易。优先级：P0（只改生成器输入表）。
- 现状差距：输入按部件大类写死，没有按挂点局部运动选类型的步骤。

### `physics.input/hair-class-recipe` — 发束类别的输入配方
- 目的：越长、越靠后的发束对转头权重越低、对歪头（重力）和身体权重越高；刘海以头部为主。
- 产出：前发 / 侧发 / 后发 / 长束四档输入表，按发束长度在档间插值。
- 算法：
  1. 发束分类见 `physics.chain/scale-ramp`（按根部位置、长度、宽度）。
  2. 缺省（权重，类型）：
     - 刘海：AngleX 60 X、AngleZ 60 Angle、AngleY 15 X、BodyZ 30 Angle、呼吸 10。
     - 侧发：AngleX 45 X、AngleZ 70 Angle、AngleY 30 X、BodyZ 40 Angle、呼吸 15。
     - 后发 / 长束：AngleX 35 X、AngleZ 50 Angle、AngleY 30 X、BodyX 40 X、BodyZ 50 Angle、呼吸 20。
  3. 长度 L/h_head 在 0.5–2.0 间线性插值刘海 → 长束。
  4. 左右成对的 AngleY / BodyY 输入按 `physics.reflect/vertical-flare` 决定 reflect。
- 可调：各档权重（±30%）、长度插值端点。
- 失败 / 质检：转头时前后发同相（应有时间差）→ 后发头权重过高。
- 难度：易。优先级：P0。
- 现状差距：前后发同一输入集。

## physics.chain：摆链设计与按部位的链参数

### `physics.chain/current` — 单段摆与等参数分段
- 现状：`PhysicsHairFront`（1 段 r 7.9 m .77 d 1.45 a .8，±10°）、`PhysicsHairBack`（1 段 r 15 m .95 d .8 a 1.5，±30°），只输出 v=1；`swingRules` 每段参数完全相同（`List(segments){segment}`），所有输出共用一个 outputScale，段长 = length/segments，输出 v=k+1；骨骼跟随每骨单独一组，只以父骨参数为输入。`SwingPresets` HAIR / ACCESSORY / CLOTH 三档标量。

### `physics.chain/material-profile` — 按材质给出沿链分布曲线 m(t)、d(t)、a(t)、r(t)
- 目的：材质手感由参数**沿链的分布**决定，不由单值决定：鞭梢越往梢越敏感、越少阻尼；垂坠越往梢越迟钝；硬饰快而短。
- 适用：所有摆链（发、丝带、布、尾、链条、肢体）。材质由语义标签 + 细长度 + 面积推断，用户可改。
- 产出：材质剖面表（数据，不是代码分支），每项 = 节点数规则 + 四条沿链曲线端点（t∈[0,1] 线性或指数插值）。
- 算法（设计默认，t = 0 根、1 梢）：

  | 剖面 | 节点数 | r（相对） | m | d | a | 典型部件 |
  | --- | --- | --- | --- | --- | --- | --- |
  | whip（鞭梢） | 4–5 | 1 → 0.6 | 0.95 → 0.8 | 0.75 → 0.45 | 1 → 3 | 鬓角长束、强调发丝、马尾、细丝带 |
  | hair（普通发） | 3–5 | 1 → 0.7 | 0.95 → 0.9 | 0.9 → 0.8 | 0.9 → 1.2 | 刘海、侧发、后发 |
  | drape（垂坠布） | 4–5 | 1 → 0.8 | 0.9 | 0.8 → 0.95 | 1 → 0.7 | 裙、袖、披风、厚尾 |
  | silk（长丝带） | 6–10 | 0.6 均匀 | 0.65 | 2.0 | 0.6 | 长飘带、绳 |
  | spring（刚性弹簧） | 1 | — | 0.7 | 0.85 | 1.5 | 驱动参数（filter） |
  | bounce（弹跳） | 3 | 1 | 0.85 | 0.85 → 0.7 | 1.5 → 2.5 | 胸、兽耳 |
  | trinket（轻小） | 2–3 | 0.6 | 0.9 | 0.9 | 0.9 | 蝴蝶结、小坠 |
  | rigid（硬饰快摆） | 1–2 | 0.8 | 0.9 | 0.6 | 1.5 | 鞋花、扣饰 |
  | sweep（均匀慢链） | 6 | 1 均匀 | 0.6 | 1.1 | 0.8 | 扫光、星群（激励用） |

  - r 的绝对值：总长 Σr 按部件长度缩放到 20–50（与现有 `lengthPx/30` 夹 3..16 的规则统一成一个函数，不再两处各写）。
  - 段长方向有两种可选分布：`taper`（向梢递减，梢部分辨率高，适合发、丝带）与 `grow`（向梢递增，梢部更慢更沉，适合长发的"重梢"手感）；默认 taper。
- 可调：`profile`（枚举，可扩展）、`stiffness`（整体乘 d，0.7–1.3）、`liveliness`（整体乘 a，0.7–1.5）、`radius_profile`（taper / grow）、`length_scale`。
- 失败 / 质检：a > 4 且 d < 0.4 易发散，在 30 fps 下仿真 60 s 检查最大值；段数多且 m 低时响应过慢；质检用阶跃输入检查梢部相位滞后单调增加、静止输出为 0。
- 引擎能力：物理（每节点独立参数，已支持）。难度：易。优先级：P0（把 `SwingPresets`、`hairRule`、骨骼跟随的常数改成剖面表查询）。
- 现状差距：所有生成链各段参数相同；材质预设只存在于布料模拟。

### `physics.chain/particle-map` — 少质点驱动多关节：关节 → 质点映射
- 目的：物理质点少 → 稳、不抖；视觉关节多 → 曲线平滑；同一质点分摊到连续几节，把折角变成圆弧；梢部读更远的质点 → 波沿链向下传。
- 适用：任何 N ≥ 3 的关节链、嵌套 warp 链或多形状发束。
- 产出：每个输出 (参数, v)。
- 算法：
  1. 运动质点数 M = clamp(round(0.6·N), 3, 6)；N ≤ 3 时 M = N。
  2. 映射 v_i = clamp(ceil(M·(i/N)^γ), 1, M)，γ 默认 1.3（根部多节共享 v=1）。
  3. 偏移 o：自由条带 o=0；从一点吊下的链（耳坠、眼镜链、挂在饰物上的子链）o=1，读晚一拍的质点。
  4. 碎发 / 中段先甩型：中段关节改读 M−1。
  5. 链长：M+1 个质点，按 material-profile 的 r 曲线分配。
- 可调：`M` 3–6、`gamma` 1.0–1.5、`offset` 0–2。
- 失败 / 质检：M ≤ 2 整链像刚体；M > 6 高频抖；共用同一质点的节过多会丢相位（同一质点最多 3 节）。质检：阶跃下各关节峰值时刻单调后移。
- 引擎能力：物理多输出。难度：易。优先级：P0。
- 现状差距：`SwingPhysics` 一段一个质点，段多时链变长、更易抖。

### `physics.chain/scale-ramp` — 输出增益沿链的曲线（按部位分类）
- 目的：同一链结构，换 scale 曲线就换"性格"：饱和 = 贴额的刘海只整体晃；线性 = 长发越往梢越自由；陡增 = 鬓角鞭梢吸睛；中段峰 = 有重量的布带；递减 = 补偿嵌套累积或表现"整片翻转、梢被拖住"的硬布。
- 适用：所有多输出链。
- 产出：每个输出的 scale_k。
- 算法：
  1. 归一化曲线 f(s)，s = 关节在链上的相对位置：
     - `saturate`（刘海）：f = min(1, s/0.35)。
     - `linear`（后发、侧发）：f = 0.1 + 0.9·s，s > 0.75 后饱和。
     - `whip`（鬓角长束、马尾）：f = 0.2 + 0.3·s + 0.5·max(0,(s−0.7)/0.3)²。
     - `pinned-root`（碎发、贴头皮发束）：s < 0.25 时 0，之后线性到 0.8。
     - `mid-peak`（丝带、布带、厚尾）：f = sin(π(0.2 + 0.7s))，梢约 0.7。
     - `falling`（硬布翻片、嵌套 warp 累积补偿、手臂）：f = ρ^(k−1)，ρ 0.7–0.9。
     - `flat`（短链、轻缎带）：f = 1，靠链本身累积放大。
  2. scale_k = s_max · f(s_k)；s_max 由"满值时该关节转角 = 关节可用范围的 45–60%"反推。
  3. 嵌套载体（旋转链、嵌套 warp）一律检查累积：阶跃下 Σ scale_k·θ_k ≤ 150°（旋转）或梢位移 ≤ 0.6 L（warp），超出时整体降 s_max 或改 `falling`。
  4. 梢部最后 1–2 节可选回落到 0.75–0.85，防止尖端折回。
  5. 根部锁定见 `root-anchor`。
- 可调：`curve`（枚举）、`s_max`（20–100）、`tip_falloff` 0.75–1、`rho` 0.6–0.9。
- 失败 / 质检：scale 递增过快梢部抽搐（scale_n/scale_1 ≤ 2.5，除 whip）；递减过度梢部死板。
- 引擎能力：物理。难度：易。优先级：P0。
- 现状差距：所有输出共用一个 outputScale。

### `physics.chain/root-anchor` — 根部锁定、贴附段与硬关节
- 目的：发根、穿带的丝带根不该晃；有厚度的布带只在少数折点弯。
- 适用：所有链。挂法由几何关系判断：根部与载体重叠长度、是否穿过 / 被压（腰带、打结、双层）。
- 产出：被锁关节的输出 scale = 0（参数保留，方便日后打开），或该段直接挂载体不建参数。
- 算法：
  1. 贴附长度 ℓ_attach = 主轴上与载体图层仍重叠的前缀；ℓ_attach / L 四舍五入到节数 → 锁定节数（默认 15–25%）。
  2. 挂法：从皮肤长出（发）→ 锁首节或首 15–25%；从系结点垂下（饰带、坠、尾）→ 不锁；被其他件压住 / 穿过 → 锁到压住处。
  3. 硬关节：对每个关节算"可弯度"：原画中轴曲率 > 阈值（必须可弯）、处于打结 / 双层区（不可弯）、材质刚度（缎带、蕾丝较硬）。硬材质跳过 20–40% 关节，连续跳过 ≤ 2，梢部最后一节始终可弯。
  4. 可弯关节按顺序依次读 v（与 particle-map 合并计算）。
- 可调：`anchor_ratio` 0.1–0.25、`stiff_skip` 0–0.4、`root_softness`（锁定节 scale 0–0.1·s_max，默认 0）。
- 失败 / 质检：锁太死急转头时发根僵；锁定段与活动段之间需要 Glue（几何组）。
- 难度：易。优先级：P0。
- 现状差距：SwingDeformer 用 softness 控制根硬，但所有段都参与弯曲，无锁定 / 跳关节规则。

### `physics.chain/tiered-taps` — 一条链按"离根距离 / 松紧"分档驱动多个部件
- 目的：多个部件共享一条链，相位天然一致（近处先动、动得少，远处后动、动得多），物理组数量也少；不同部件取不同深度避免整齐划一。
- 适用：同一区域（头、身体）上响应应该一致的一批可动件。
- 产出：区域链（头链、身体链，各 X、Y 两组），按档分配输出参数。
- 算法：
  1. 每件求"松紧 × 到区域枢轴的距离 / 区域高"：< 0.5 第 1 档（帽子、发饰、整块刘海、肩、外套上部）；0.5–1.0 第 2 档（单束、前臂、袖、裙）；> 1.0 第 3 档（手、袖口、手持物、下摆）。
  2. 链节点数 = 档数 + 1–2；第 k 档读 v=k；倍率 q^(k−1)，q 1.1–1.3。
  3. 同件的"整体"与"局部"取相邻两档（块 + 束、外层 + 内层）。
  4. 各档幅度：帽子 ≈ 帽高 5–10%，刘海块 ≈ 刘海长 5%，单束 ≈ 10%；肩 ±10–15°，前臂屈伸比 1.4–2。
- 可调：档阈值、q、每档幅度比例。
- 失败 / 质检：帽子与头发滞后差太大露缝（帽下需要头发底色）；手臂被追踪 / 动作直接驱动时该档降权。
- 难度：中。优先级：P1（依赖分区语义与 carrier）。
- 现状差距：每个对象各建物理组；没有帽 / 发饰滞后档，也没有"块 + 束"两级。

### `physics.chain/accessory-bus` — 同类小饰物共享一条物理总线，实例间做确定性差异
- 目的：小饰件逐个调物理太贵且无必要；共享一条快摆，节奏统一、成本低，再用实例形状与幅度差打破复制感。
- 适用：面积 < 1% 人物面积的饰件、重复饰物（≥3 个相似连通块）、互斥差分里的同一饰品。
- 产出：每个区域（颈、胸、上臂、腰、鞋）一对总线物理组（X 组、Y 组，各 2 输出）；每件饰物一层 warp 或"静态对齐旋转 + 驱动旋转"。
- 算法：
  1. 按挂接区域聚类；区域跨度 > 2–3 h_head 时拆成两条总线。
  2. 总线：X 组（区域对应输入，X/Angle 按 mount-recipe）、Y 组（竖直输入 + 呼吸 20）；剖面 `rigid` 或 `trinket`。
  3. 实例幅度 φ_i = φ₀·(1 + j_i)，j_i 由实例 ID 哈希确定，范围 −0.4..+0.3；方向 ±15° 抖动；相邻同类件在 2–3 个总线输出之间轮换。
  4. 极小件（< 0.05% 人物面积）用 4 顶点网格 + 两个旋转，不建 warp。
  5. 同一饰品出现在多个互斥差分里：共用总线参数，各份关键形按各自局部坐标换算，使画面位移一致。
  6. 近距离同时可见的成对饰物（左右耳坠）不共用，或至少链长不同。
- 可调：总线粒度、`instance_jitter` 0–0.4、共享距离阈值 0.2–0.4H。
- 失败 / 质检：共用参数 + 同形状 → 机械同步；相邻饰物摆动后互相穿插。
- 难度：中。优先级：P1。
- 现状差距：每个摆动一组物理，没有总线、没有实例差异。

### `physics.chain/limb-pendulum` — 下垂肢体的被动摆链（手臂、背手、举起臂）
- 目的：面捕不追手时手臂是死的；做成挂在肩上的复摆，身体一动手臂自然晃、手最晚最多。物理参数与姿势参数分开叠加，不再与动作互相覆盖。
- 适用：已有手臂骨骼 / 旋转链（arm 几何属 hair-body）。姿态分类：下垂臂（主轴与竖直 < 35°，手在肘下）、接触臂（手与躯干重叠或有接触对）、背手、需要摆姿势的臂（关闭）。
- 产出：每臂一组物理（左右各一组，输入取反），输出 `ParamArmSway<L|R>_<k>`；以**混合形状**或独立旋转层加到各关节，不改写姿势参数。
- 算法：
  1. 输入：身体 X/Y X 型 30–50、BodyZ Angle 100（下垂保持）、呼吸 15–20；已启用 drive-param 时读 P★。
  2. 链：节点数 = 关节数 + 1，r 按上臂 : 前臂 : 手 ≈ 14 : 12 : 6 缩放，剖面 `hair` 偏阻尼（d 0.9–1）。
  3. 下垂臂：各关节同号，读 v1..vk，scale 比 1 : 1.2 : 1.5 : 2（旋转载体用递减曲线 `falling` 时改 1 : 0.75 : 0.4，取决于载体是否累积）；满值角：肩 ±10–15°、肘 ±15–20°、腕 ±10–12°；实际物理幅度控制在关节手动范围的 20–30%。
  4. 不对称限位：朝身体方向的范围 = 外展方向的 0.35–0.65；以"手臂与躯干轮廓的最小间隙"求内收上限。
  5. 手指：同一参数，各指幅度 base·(1 + 0.3k)，起始角错开 3–15°；或指根 / 指尖读更深质点并 reflect（表现被拖拽）。
  6. 接触臂：上臂同号 v2；前臂 reflect v3，scale ≈ s·L_upper/L_fore；手 reflect v4。校验：BodyZ 满幅时手中心位移 < 0.3 倍上臂端点位移，否则最小二乘调整。
  7. 背手（原画有被遮挡的完整手）：外层 warp 让手绕肩肘向外摆、露出 0.3–0.5 手长；输入身体 X/Y/Z，一侧 Y reflect。
  8. 有用户手部追踪或动作直接驱动手臂姿势时，物理权重降到 20–30% 或关闭。
- 可调：`sway_amp`（手位移 3–10% H）、`inner_outer_ratio` 0.35–0.65、`finger_fan`、`mode`（hang / contact / behind-back / off）。
- 失败 / 质检：身体前倾时手臂向后漂（输入加身体 Y）；反相过大手向反方向甩；关节处必须有 Glue 或覆盖层（几何组）。
- 引擎能力：混合形状（或附加旋转层）、物理。难度：中。优先级：P1（解除"手臂不进物理"的限制，前提是物理输出走独立叠加通道）。
- 现状差距：`skeletonRules` 明确让手臂与腿不进物理；只有 `DeformArmHang` 约 4° 静态反摆。

### `physics.chain/dual-band` — 主摆 × 细颤双频叠加
- 目的：单一摆只有一个主频；"整体大摆 + 梢部细碎抖动 + 整体上下弹"三个频段叠加更像真发。
- 适用：马尾、长辫、强调发丝等视觉焦点的长链；默认关闭。
- 产出：同链第二组物理 `<id>_Fine`；每关节加细颤混合形状（或 2D 键的第二轴）；可选整段 Y 弹 / X 摆混合形状（垂坠剖面驱动）。
- 算法：
  1. 细颤物理：输入同主摆，权重 ×0.4；节点 m 递减到 0.7、a 递增到 3–4（whip 剖面）；scale 为主摆 3–5 倍。
  2. 细颤角度只占主摆角 5–10%（≤ 12%）。
  3. Y 弹：输入以 AngleY 为主，幅度为段长 3–5%。
- 可调：`fine_ratio` 0.05–0.12、细颤末节点 d 0.4–0.55、Y 弹幅度 0.02–0.06 段长。
- 失败 / 质检：细颤与主摆同量级像抽搐。
- 引擎能力：混合形状（避免二维键 × 骨数膨胀）。难度：中。优先级：P2。
- 现状差距：一个物体只有一组摆锤。

### `physics.chain/follower-share` — 跟随件直接复用本体参数（影子链、副本、变体）
- 目的：影子、高光副本、差分件、漫符与本体零相位差，且不重复物理组。
- 产出：跟随件的关节 / warp 直接以本体输出参数为轴；不新建物理组。漫符等"浮在头上"的件按跟随比例缩小关键形。
- 算法：
  1. 配对规则由 lighting / effect 插槽给出（影子配对、漫符锚点）；本模板只负责接线：跟随件的每个物理轴绑定本体同名参数，关键形按跟随件自己的几何重算。
  2. 漫符：取最近发物理组前两个输出做 2D warp，跟随比例 0.3–0.5（≤ 0.5）。
  3. 跟随件在不同父 warp（视差不同）时，只共享参数，不共享变形器。
- 可调：`follow_ratio` 0.3–1.0。
- 失败 / 质检：本体覆盖（用户改了本体物理）后跟随件必须同步——因为共享参数，天然同步；复制设置的做法会失步，禁止。
- 难度：易。优先级：P1（随影子 / 漫符生成器一起）。
- 现状差距：没有跟随件；SeeThrough 复制件机制可扩展。

- 现状：所有物理组读标准输入；骨骼尾巴是唯一的"读父骨参数"的例外；`DocumentGenerators` 中 PHYSICS 只有一个节点，没有组间依赖图。

### `physics.cascade/staged-inputs` — 下游物理读上游物理的输出（依赖图）
- 目的：二阶系统串联 = 更高阶响应：身体先晃、衣服再晃、毛尖最后晃，时间层次自然出现；追踪噪声不被放大。
- 产出：物理组依赖图（主运动组 → 附着物组 → 末梢组），physics3 中按拓扑序排列。
- 算法：
  1. 生成时为每组声明 `reads`（输入参数）与 `writes`（输出参数），构建 DAG；检测环路并报 `FEEDBACK`（现有 issue 类型）。
  2. 拓扑排序决定 physics3 中的顺序（Cubism 按设置顺序求值，上游排前保证同帧读到新值）。
  3. 下游输入替换表：BodyX → BodyX★（X 40）、BodyY → BodyY★（X 40）、BodyZ → BodyZ★（Angle 60）、下身 Z★（Angle 40 reflect）。
  4. 每级 d 递减 0.05–0.1，让末梢更灵；三级以上缩短 r。
- 可调：`stages` 2–3、`per_stage_d_drop` 0.05–0.1。
- 失败 / 质检：延迟累积显得迟钝（第二层 d 降低）；顺序错导致一帧延迟抖动。
- 引擎能力：物理组顺序（已有 `physicsOrder`）。难度：易。优先级：P1（与 drive-param 同轮）。
- 现状差距：没有依赖图，用户顺序与生成顺序混在一起。

### `physics.cascade/body-lag-chain` — 身体逐级滞后：上身 → 腰 → 胯 / 腿 → 裙
- 目的：真实转身是"波"：躯干先动，骨盆、腿、衣摆依次跟上，形成上下身角度差的"扭"。
- 适用：全身模型（半身只做到腰）；需要 drive-param。
- 产出：驱动参数 `BodyX★`（L0 上身）、`BodyXLower★`（L1 腰胯）、`BodyXHem★`（L3 下垂物，供裙 / 后摆物理读）；腰带区 2D warp、每腿一个髋旋转（几何由 body 插槽建，本模板给参数与物理）。
- 算法：
  1. L0 来自 drive-param。
  2. Lk = Pendulum(Lk−1 输出（X 型 0.8）+ 次轴 0.2 + 原始输入（Angle 0.3–1.0）)；r 为上一层的 0.85–0.95；m 0.65–0.85；d 0.65–0.9；末层 d ≥ 0.85。
  3. 原始输入以 Angle 型、reflect 混入时产生"持续反向"（下身静止时略反向扭）；不想要持续反向时只用 X 型。
  4. 旋转幅值逐层比 0.4–0.6（越往下越稳）。
  5. 验收：阶跃过冲 ≤ 10–15%，稳定 0.4–0.8 s；Input 正向阶跃时各层同号（刻意反相的除外）。
- 可调：`layers` 3–5、`r_ratio` 0.85–0.95、`amp_ratio` 0.4–0.6、`raw_mix` 0.3–1.0（越大越跟手）。
- 失败 / 质检：层多且都低通 → 软；层间相位差大 → 腰线撕裂（必须 Glue 或锁定上边缘）；reflect 符号错 → 下身反向扭。
- 难度：中（还牵涉层级重排与跨层 Glue）。优先级：P1。
- 现状差距：`DeformBodyXY` 是一次性的空间衰减，没有时间滞后；腿与身体同步。

### `physics.cascade/hip-counter-twist` — 臀部反向扭（对立式站姿）
- 目的：转身时骨盆反向扭一点保持平衡，站立摇摆有重心转移感。
- 适用：全身站姿；风格选项（与"脚永远不动"互斥或限制脚位移）。
- 产出：`ParamHipTwist★`、`ParamHipLift★`、`ParamShoulderReact★`，各一组物理（读级联输出，reflect）。
- 算法：
  1. 扭臀 = Pendulum(Delay(BodyX★ + HeadY)×0.1 + Delay(HeadZ)×0.3)，输出 reflect（与上身反向）；Delay 指读 body-lag-chain 的上一层输出。
  2. 抬臀 = 同一延迟量的竖直分量，一侧腿根抬 1–2% H。
  3. 关键形（body 插槽）：骨盆区绕髋中心在画面内反向平移 2–4% H。
  4. 肩反应 = Pendulum(−HeadZ×0.2 − BodyX×0.3 − BodyZ×0.3)，表达"歪头时对侧肩上提"。
- 可调：`counter_ratio` 0.1–0.3、`hip_shift` 2–4% H、`foot_slide_limit`（默认 0）。
- 失败 / 质检：腿区横移过大像滑步；r 不超过上身 2 倍。
- 难度：中。优先级：P2。
- 现状差距：没有臀部反向扭。

### `physics.cascade/attached-subchain` — 子链挂在母链某段上，读更深的质点
- 目的：复合物体（帽尖挂金环、分叉发束）继承母链运动，子摆叠在母链弯曲上并晚一拍。
- 适用：几何组给出挂接图（子链根轴心命中母链某段网格）。
- 产出：子链的物理输出；与母链合并为同一组（输入相同）或单独成组（delay 更大）。
- 算法：
  1. 合并组：子链关节 j 读 v = v_mother(挂接段) + ceil(j·(M − v_mother)/N_child)；子链根关节 scale 0（分叉处刚性）。
  2. 单独组：输入同母链（或读母段输出，见 output-feed），d 比母链大 0.1–0.2。
  3. 子链 scale 为母链 1.0–1.2 倍；挂接深度 > 3 级时逐级 ×0.8 防角度累积失控。
  4. 子链是下垂物时，在挂接处插重力层（physics.gravity）。
- 可调：`particle_offset` 1–2、`child_gain` 1.0–1.2。
- 失败 / 质检：母链根锁死时子链需保留独立 X 输入才能动；子链比母链先动（读浅了）。
- 难度：中。优先级：P1（与分支 / 挂接几何同轮）。
- 现状差距：swing 之间不能挂接。

### `physics.cascade/output-feed` — 二级物理以上级输出为输入（毛尖、附属抖动）
- 目的：主摆到位后末梢再抖一下，不需要额外输入设计。
- 产出：二级组 `<id>_Tip`：输入 = 链倒数第 2 节输出（Angle 100，按需 reflect），3–4 质点，输出毛尖 / 毛簇外扩混合形状（0.05 段长）。
- 可调：读取的节、增益。
- 失败 / 质检：环路检测（staged-inputs）；二级过强像抽搐。
- 难度：易。优先级：P2。

### `physics.cascade/surface-follow` — 贴附件读取所附表面的物理参数
- 目的：贴在会晃动的表面（胸、腹、裙面）上的饰物、衣物不像浮在空中；直接复用表面参数，比再建物理组省且同步。
- 产出：贴附件的变形栈中插一层以表面物理参数为轴的旋转 / 位移层（或共享混合形状），幅度 = 表面在贴附点的位移 × 跟随权重。
- 算法：
  1. 贴附关系：贴附件网格与表面网格重叠 ≥ 50% 且绘制在其上。
  2. 权重：贴身 1.0；衣物外层 0.3–0.6；饰物根部 1.0，自身另有摆动物理（叠加）。
- 可调：`follow_weight` 0.3–1.0。
- 难度：易。优先级：P1（随 chest-bounce）。
- 现状差距：没有饰物 / 衣物读取表面物理的连接。

## physics.excitation：激励

### `physics.excitation/current` — 只有头身角度
- 现状：激励只来自追踪 / 动作写入的头身参数；呼吸只驱动躯干几何（`DeformBodyZBreath`），不进任何物理；动作生成器不知道物理存在。

### `physics.excitation/breath-feed` — 呼吸作为永续低幅激励
- 目的：用户静止时，长链部件、生物、浮空物仍以呼吸节奏、带相位差地动；不依赖 idle 动作，任何宿主（自动呼吸）都成立，永不与追踪冲突。
- 适用：所有生成物理组（低权重）；"活物"类（尾、翅、兽耳、触角、浮空道具、小生物）可只接呼吸。
- 产出：在各组输入中追加 `ParamBreath`；活物组只含呼吸。
- 算法：
  1. 默认权重（Angle 型）：头发 10–20、裙与衣物 5–15（长重下摆取下限）、挂饰 15、手臂 15–20、胸 10、眼高光 30–50、尾巴 / 浮空坠 / 生物 80–100、闪烁星群 80。
  2. 活物组：只接呼吸 100（可再弱接头身 10–20），3–4 质点，scale 沿链增（梢 / 根 2–3）；兄弟对象依次读 v=1/2/3 并交替 reflect，或交替 Angle / X 型输入。
  3. 呆毛类"弹起"部件对呼吸 reflect，呼气上翘。
  4. 防共振：摆的固有周期取呼吸周期的 0.5–0.8 倍；m ≤ 0.9 或权重 ≤ 65；仿真 60 s，呼吸单独产生的输出 ≤ 参数范围 20–30%，每节偏转 ≤ 25°。
  5. 下限：呼吸周期内各组输出振幅 ≥ 满值 3–5%，否则加权。
  6. 宿主不自动驱动呼吸时，生成的 idle 必须写 ParamBreath（现有 idle 已写）。
- 可调：`breath_weight`（按部位一档）、`alive_mode`（only-breath / mixed）、`phase_spread`（v 偏移 / reflect / 类型交替）。
- 失败 / 质检：权重过大像有风；周期接近固有频率越摆越大；呼吸 < 2 s 会抖。
- 引擎能力：物理。难度：易。优先级：P0（只改输入表 + 共振检查）。
- 现状差距：`headAndBodyInputs` 与纵向输入不含呼吸。

### `physics.excitation/kick-channel` — 不绑几何的激励参数，由动作写入冲量
- 目的：游戏立绘的大动作主要来自动作，身体参数变化可能很小，物理不被激发；专用激励让动作师 / 生成器直接"告诉"物理这里该甩，且不造成静态形变；头慢转不甩飞头发、快顿挫有余振。
- 适用：生成动作的模型；左右对称组各读一个 kick 或其一 reflect。
- 产出：参数 `ParamPhysKick_<cluster>`（±30，无绑定，used-by 0），每个物理组簇（前发左 / 右、后发左 / 右、裙、缎带）一个；各组输入追加 kick（X 型，权重为头部输入的 2–4 倍）。
- 算法：
  1. 动作生成器在身体、头、手臂参数二阶导极值处写脉冲：0 → ±峰 → 0，上升 0.15–0.25 s、回落 0.2–0.3 s，方向与运动方向相反（惯性）。
  2. 持续旋转类动作：写与运动同周期的方波，左右反相。
  3. 校验：激励参数在动作结束前回到 0；峰值不超过代理范围 100%。
  4. 可移植性：保留姿态输入的小权重后备（AngleX 10）。
  5. 运行时无动作时，宿主可把拖拽 / 跟踪的速度注入（`host.mapping`）。
- 可调：`kick_weight` 20–40、`pulse_width` 0.3–0.5 s、`amp` 10–30。
- 失败 / 质检：脉冲过尖引起爆振；激励与姿态不同步显得"自己动"；完全没有后备输入时面捕转头不触发物理。
- 引擎能力：物理、动作写曲线、纯输入参数。难度：中。优先级：P1（与 MotionGenerator 联动）。
- 现状差距：动作生成器不写激励。

### `physics.excitation/wind-gust` — 全局风与分组阵风
- 目的：静止时也在微动，且头发、丝带、衣摆节奏不同。
- 产出：`ParamPhysWind`（全局，idle 中写正弦）、`ParamPhysGust_<g>`（每组，idle 中写半正弦序列，峰值确定性哈希抖动）；各组输入追加（头发 wind 20–50 / gust 40；布料 wind 15–30）。
- 可调：风周期 = 主周期；阵风周期比 0.3–0.7 主周期；幅度。
- 失败 / 质检：与 breath-feed 叠加过量（两者二选一或减半）。
- 难度：中。优先级：P2（breath-feed 已覆盖大部分需求）。

### `physics.excitation/blink-feed` — 眨眼作为非眼部件的随机计时器
- 目的：眨眼是自然、随机间隔的阶跃；接进刘海、兽耳、触角物理，每次眨眼轻颤一下，不用额外动作也不机械。
- 产出：在选定组的输入中加 `ParamEyeLOpen`/`ParamEyeROpen`（X 型）；兽耳组以眨眼为主输入。
- 算法：
  1. 权重：刘海 10–20、兽耳 50–100（另混头部 15–30）、触角 30。
  2. 单侧耳只读同侧眼；按"向后抖"的方向决定 reflect。
  3. 追踪眨眼抖动：输入加 0.05 死区，或改由眨眼速度驱动（derived-rule 的 X 型分量）。
- 可调：权重、死区。
- 失败 / 质检：长时间闭眼耳朵静止（可接受）；追踪半睁抖动导致持续颤。
- 难度：易。优先级：P1。
- 现状差距：眨眼只驱动 `PhysicsEyeJelly`。

### `physics.excitation/toggle-impulse` — 开关切换当作物理冲量
- 目的：开关在宿主里通常 0.3–0.5 s 推到 1，作为小权重 X 输入就是阶跃激励：换姿势时身体有重心转移、道具出场有弹性。
- 产出：
  - 姿势开关：在身体 Y★ 组与最近挂件组各加输入 T（X 型 5–10），方向按开关前后手部重心的竖直变化符号。
  - 出场开关：新组 `PhysicsPop_<T>`：输入 T（X 100），3 质点，m 0.95 d 1 a 1；输出作为道具根层混合形状（+1 = 纵向拉长 10–15%、横向收缩 5–10%、上移 1–2% 道具高）。
- 算法：校验 T 以 0.5 s 线性 0→1 时，身体 Y 峰值偏移 ≈ 范围 5–10%，0.6 s 内回静；出场首峰 0.6–0.8 满值。
- 可调：权重 4–10、弹性 5–15%。
- 失败 / 质检：表情淡入很慢时阶跃变斜坡，弹性弱（调小 d）；关闭时会反向弹一次（可接受）。
- 难度：易。优先级：P2（依赖 toggle 插槽的开关体系）。

### `physics.excitation/sway-root` — 根部全身摇摆参数并入物理输入
- 目的：idle 的重心转移经物理传到裙、发、领结，而不是只有平移。
- 产出：根部参数（几何归 body 插槽）作为物理输入（X 型 30–60）。
- 难度：易。优先级：P2（随 body 插槽的摇摆参数）。

## physics.reflect：reflect 与取反

### `physics.reflect/current` — 不使用
- 现状：`PhysicsEngine` 支持 reflect，生成器从不使用；VERTICAL swing 所有链同号；左右物理对称。

### `physics.reflect/vertical-flare` — 纵向输入单侧取反，点头 / 颠簸时两侧对称张开与收拢
- 目的：下垂的摆只能左右摆，纵向运动本激发不了它；把纵向作为横向 X 输入喂给左右两组并单侧取反，点头时两侧同时外张或内收，产生蓬起 / 收拢的体积感；转头时仍同向。
- 适用：关于身体中线成对的悬垂件（侧发、后发左右块、左右裙片、左右长纱、手臂）。中线上的件（正中辫子）不接纵向或只接一点；中线宽后发可由几何组切成左右两半各成一组。
- 产出：左右两组的纵向输入 reflect 标志；可选"开合"关键形（几何组按 θ = θ_max·|x − x_mid|/半宽 绕挂点外转）。
- 算法：
  1. 按挂点在中线哪一侧分组。
  2. 横向输入（AngleX X、AngleZ Angle）两侧相同；纵向输入（AngleY、BodyAngleY 作 X 型）权重为横向的 0.3–1.0，单侧 reflect。
  3. 定符号：渲染一次 AngleY 正弦扫描，选择使"抬头时外张"（或按风格"低头时外张"）的一侧取反；检查两侧末端水平位移符号相反。
  4. 不对称发型按两侧总面积归一化纵向权重。
- 可调：`vertical_ratio` 0.3–1.0（默认 0.5）、`flare_on`（抬头 / 低头）、`center_policy`（skip / weak / split）。
- 失败 / 质检：关键形改用"外侧为正"约定时规则反转（横向需 reflect、纵向不需）——生成器必须固定画布方向约定；向内收时与身体 / 手臂穿插（收拢幅度 ≤ 张开一半）。
- 引擎能力：物理 reflect。难度：易。优先级：P0。
- 现状差距：VERTICAL 组不分左右、不用 reflect。

### `physics.reflect/mirror-pair` — 成对件的镜像模式：对称开合 / 同向 / 混合
- 目的：左右两片同向摆像一块硬板；一侧取反形成对称开合，像衣摆随转身"呼吸"。但全镜像在急转身时不符合惯性，所以要可混合。
- 适用：成对的飘带、纱、长缎带、胸前蝴蝶结环、裙侧片。
- 产出：成对件共用一组物理（输出侧 reflect），或两组物理按 λ 混合输入。
- 算法：
  1. 分类：贴身成对（胸前结、裙侧片、开襟）→ 开合；离体悬挂（耳坠、颈前飘带）→ 同向；离体距离 > 0.3 饰物长度视为离体。
  2. 开合模式：一组物理，另一侧所有输出 reflect（零相位差）。
  3. 混合模式：两组物理，第二组横向输入 = (1−λ)·原 + λ·取反（实现为同参数的两条输入：权重 (1−λ)w 不 reflect、λw reflect）。
  4. 判断依据用"实际屏幕方向"：基角已在网格层镜像时再 reflect 会变成同向。
- 可调：`mode`（open-close / same / blend）、`lambda` 0–1（默认 0.6）。
- 失败 / 质检：基角接近 ±180° 时方向容易弄反 → 渲染验证。
- 难度：易。优先级：P1。
- 现状差距：没有成对镜像逻辑。

### `physics.reflect/upward-invert` — 朝上附属物的输出取反
- 目的：物理链本质是下垂摆；朝上的物体（羽毛、呆毛、触角、立耳）用同一转向会把尖端推向错误一侧，取反后才像发梢一样落后于运动。
- 适用：静息方向 d（根 → 尖）满足 d·g < −0.3 的链。
- 产出：该链全部输出 reflect；scale ×1.5–2.5（轻物件）；外加随头倾斜层（几何组）。
- 算法：
  1. 计算 d·g；< −0.3 → 朝上；|d·g| < 0.3（水平伸出）改用侧向分量判断。
  2. 校验：AngleX 阶跃后，朝上件尖端位移方向与头发梢一致（都落后于头）。
- 可调：`threshold` −0.3、`gain` 1.5–2.5、随头倾斜增益。
- 失败 / 质检：硬质朝上物（帽檐装饰）不应做链。
- 难度：易。优先级：P1。
- 现状差距：swing 不区分朝上 / 朝下。

### `physics.reflect/desync` — 相似挂件去同步：半数取反 + 确定性抖动 + 刻意不对称
- 目的：同参数的一排件会像机器一样齐步走；取反一个输入轴、加小幅确定性差异就打散。
- 适用：同类挂件组（叶、结、带、发束、裙片）、左右成对部件（小幅不对称）。
- 产出：每组的 reflect 位、权重与 m/d/scale 的确定性扰动；或"两套错调摆"分配。
- 算法：
  1. 同类分组，按空间顺序（左右交替或从上到下）给竖直输入加 reflect，比例约 50%。
  2. 扰动：权重 ×(1 ± 0.2·h)、d ×(1 ± 0.1·h)、scale ×(1 ± 0.1·h)，h = hash(组 ID) ∈ [−1,1]（确定性，禁止随机数）。
  3. 多发束共享物理时：两套摆（A：标准；B：r ×1.2、d −0.2），发束按序交替。
  4. 左右对称部件：先镜像生成，再对一侧做 δ = 5–15% 的确定性扰动；影子 / 跟随件完全复用本体（不扰动）。
- 可调：`reflect_ratio` 0–0.5、`jitter` 0–0.2、`lr_asymmetry` 0–0.2、`detuned_pair`（开 / 关）。
- 失败 / 质检：扰动不能破坏镜像对的开合关系；抖动必须可重放（ID 哈希）。
- 难度：易。优先级：P0。
- 现状差距：物理左右对称、固定权重。

## physics.axis：按运动方向拆分通道（补充插槽）

### `physics.axis/current` — 横向 + 可选纵向
- 现状：swing 有 LATERAL / VERTICAL 两种方向，纵向按拉伸形状；头发预设只有横向；衣物 `SwingPreset.CLOTH` 单一摆动。

### `physics.axis/xy-split` — 横摆与纵弹两条独立通道
- 目的：点头"颠"与摇头"甩"可同时发生而不串扰；每个方向独立幅度与衰减。
- 适用：发组、衣物、手臂（大面积部件）。
- 产出：X 组（横向输入）与 Y 组（AngleY / BodyY 主 + 呼吸），各自输出；Y 层 warp 在外、X 层在内（几何组按此嵌套）。
- 算法：
  1. X 组输入：AngleX 50 / AngleZ 30 / AngleY 20（或 mount-recipe）；Y 组：AngleX 0 / AngleY 70 / AngleZ 30 + 呼吸 20。
  2. Y 链更短（r ×0.8）、衰减更快；Y 输出幅度为 X 的 0.4–0.6。
  3. Y 归一化更灵敏（角度 ±15）。
- 可调：`y_ratio` 0.4–0.6、`y_chain_ratio` 0.7–0.9。
- 失败 / 质检：两通道链参数相同显得同步。
- 难度：易。优先级：P0（现有 swing 已有两方向，只改输入表与链比例）。

### `physics.axis/three-axis` — 发束 X 横摆、Z 卷曲、Y 伸缩三通道
- 目的：发束对头部运动有三种响应（甩、扭、弹），各由最相关的头部输入主导。
- 适用：刘海、侧发、后发组（高质量预设）。
- 产出：每发组三组物理；三层混合形状（几何组：Y → X → Z 顺序嵌套）。
- 算法：
  1. 输入配方（权重，类型）：X 组 头 X 0.5 X、头 Z 0.4 Angle、头 Y 0.3 X、呼吸 0.1；Z 组 头 Z 0.45 Angle、头 X 0.45 X、头 Y 0.3 X（reflect）、呼吸 0.15；Y 组 头 Y 0.45 X、头 X 0.2 X、头 Z 0.2 Angle、呼吸 0.1。
  2. 链段数 = 发束长度 / (0.1–0.15 h_head)，取 2–5；m 0.9（Z 组 0.93，更灵活）、d 0.85、a 0.9。
  3. 幅度比 X : Z : Y ≈ 1 : 1.5 : 2.5（以 % H 计）；各轴输出读不同质点（particle-map）。
  4. 可选：前发组最深输出反相驱动后发（前后反相，读作有体积），后发幅度 ≥ 前发 0.8 倍。
- 可调：三轴幅度比、主导输入权重 40–55%。
- 失败 / 质检：Z 卷曲在宽发束上撕开相邻发束（共享 Z 形状或 Glue）；短刘海 Y 伸缩露额头。
- 引擎能力：混合形状。难度：中。优先级：P2。

### `physics.axis/skirt-modes` — 裙子按模态拆物理：横摆、上掀 / 外张、扭、弹跳
- 目的：裙子对转身、起伏、倾斜、急停的反应不同；内外层幅度不同产生层次。
- 适用：bottomwear 中判为裙子的部件（`garmentProfile`）及其层次（外裙、罩纱、衬裙、长后摆）。
- 产出：模态物理组 `PhysicsSkirt_<mode>`；每层裙的模态订阅表与层增益；几何（warp 叠加顺序、关键形）归 hair-body 的 skirt 插槽。
- 算法：
  1. 模态与输入：
     - sway：BodyX★ 40 X + BodyZ★ 100 Angle（+ 上身侧倾 X 20）→ 3 输出 v1–v3，增益 1 : 0.6 : 0.4，符号 (+,−,−) 形成波。
     - lift：BodyY★ 40 X（+ 呼吸 10，或 Angle reflect 表现持续外张）→ 2 输出。
     - twist：BodyX 20 X + BodyZ 40 Angle reflect → 1–2 输出。
     - bounce（可选）：BodyY 派生量 X 型 → 2 输出。
  2. 层增益：按内 → 外排序，最内 0.2、最外 1.0，线性；标为轻薄（纱、蕾丝）× 1.5–2；保证内层位移 < 外层（不穿出）。
  3. 订阅：外裙全部模态；衬裙 sway + twist；褶片 / 蛋糕层再读 v2/v3 做相位差。
  4. 长后摆（长度 > 0.25H）：不在身体 Z 旋转下（几何），物理以 BodyZ Angle 1.0 为主、BodyX/Y X 0.3，左右片 mirror-pair 开合。
  5. 头部影响：sway 组可混 AngleX / AngleZ 0–30%。
  6. X/Y 模态幅度比默认 2 : 1。
- 可调：`modes`（集合）、`layer_gain_inner` 0.15–0.3、`sheer_boost` 1.5–2、`xy_ratio` 1.5–3、`head_influence` 0–0.4。
- 失败 / 质检：裙下露腿时上弹不能露出腿根；6 层 × 13 键开销 → 用混合形状；内层位移大于外层 → 穿帮。
- 引擎能力：物理、混合形状（推荐）。难度：中。优先级：P1。
- 现状差距：`SwingPreset.CLOTH` 单一摆动；裙子由模拟或 swing 整体处理。

### `physics.axis/chest-bounce` — 胸部 X / Y 两组多相弹跳
- 目的：正反相交替叠加得到"回旋 8 字"的弹动；呼吸让静止时也有微起伏。
- 适用：胸部区域（语义 / 体型）存在；默认幅度保守，风格可关闭。
- 产出：`PhysicsChest_X`、`PhysicsChest_Y`（`bounce` 剖面，4 节点）；输出 v1、v2（reflect）、v3。几何（高斯位移场、与身体转角组合）归 chest 插槽。
- 算法：
  1. X 组：BodyX★ 25 X + BodyZ★ 50 Angle；Y 组：BodyY★ 100 X + BodyZ★ 20 Angle + 呼吸 10 Angle（身体读 P★）。
  2. 各 4 节点 `bounce` 剖面；输出 v1、v2（reflect）、v3：v1 × v2 做 2D（或两个混合形状），v3 走混合形状。
  3. 幅度相对胸高：X v1 ±0.12、v2 ±0.06，Y v1 ±0.10、v2 ±0.05；整体相对胸宽 5–15%（默认 6%）。
  4. 可选第三轴：把身体转角作为最内层物理 warp 的轴，使晃动方向在每个转身姿态下贴合体块。
  5. 贴身衣物经 `surface-follow` 共享。
- 可调：`amp` 0–0.15 胸宽、`breath_weight` 5–15、`phase_combo`。
- 失败 / 质检：领口被拉扯（锁骨以上衰减为 0）；外层衣物全额跟随穿帮（0.3–0.6）。
- 难度：中。优先级：P1。
- 现状差距：无胸部物理，呼吸只扩胸。

## physics.carrier：物理输出接线规范（补充插槽；几何归 hair-body）

本插槽只规定"哪个物理输出接到哪一层、用几个键、走关键形轴还是混合形状"。关键形形状由 hair-body / body 插槽的几何模板计算。

### `physics.carrier/current` — 单 warp 全组合三键
- 现状：`RigSwingEdits` 每个参数只放 min / default / max 三键，所有段的轴乘在同一个 warp 上（3^(2n) 个关键形，超过 1,000,000 单元跳过）；`SwingDeformer` 能在单个键内保长。

### `physics.carrier/dense-arc-keys` — 物理输出参数按角度密集采样（弧线键）
- 目的：warp 关键形之间线性插值，两端各转 θ 时中间姿态的末端走弦线、发束变短；每 5° 一个键把弦误差降到 0.1% 以下，键里还可以有随角度变化的弯曲分布。
- 适用：所有以 warp 承载的物理输出（摆动、发、裙、袖）。旋转变形器载体不需要（旋转本身是圆弧）。
- 产出：参数键数 K（含两端与 0）。
- 算法：
  1. 每个采样角在几何侧用保长弯曲精确求值（`SwingDeformer` 已有），不插值。
  2. 键数自适应：R = 关节到梢距离（px），ε = 0.5 px（或 0.2–0.3% 长度），Δθ = 2·acos(1 − ε/R)，K = 2·ceil(θmax/Δθ)+1，夹到 5..13。
  3. 二维 warp（两个物理轴）键数平方增长：只在必要时两轴都密，否则次轴用 3–5 键；或改走 `node-layers` / `blendshape-secondary` 避免乘积。
  4. 中间键可编码非线性响应（如小幅只动根、大幅梢卷，或 |u|^1.3 缓入）。
- 可调：`epsilon_px` 0.2–1、`max_keys` 5–13、`nonlinear_exp` 1–1.6。
- 失败 / 质检：键数 × 嵌套层 × 格点使体积与运行开销上升，导出前预估关键形总数并给出警告阈值。
- 引擎能力：多键。难度：易。优先级：P0（改 `SwingGenerator` 的键集合，导出逐字节变化需更新 golden）。
- 现状差距：只有三键，中间姿态走弦线。

### `physics.carrier/node-layers` — 每个质点一层嵌套载体，集合逐级缩小
- 目的：把"根 → 梢"的相位差映射到空间上：外层整体摆、内层只弯远端；嵌套避免把所有轴乘在一个 warp 上。
- 适用：宽而薄的刘海、裙、袖、披风；成组相连的衣物（共享前缀层，不撕开）。
- 产出：层表 [(层 k, 覆盖集合, 轴 = 质点 k 的输出)]；scale 按 `scale-ramp` 的 `falling`（补偿累积）或 `linear`（内层区域小、需放大）。
- 算法：
  1. 建悬挂树：每个悬垂部件的挂点深度（腰 → 裙身 → 裙摆下飘带 / 流苏）。
  2. 第 k 层包住深度 ≥ k 的部件（集合逐级缩小）；同组相连衣物共用同一层，局部性靠关键形衰减实现。
  3. 输出子集：靠近脸的短发片只接内层（梢部）参数，长发片接全部；同组相邻发片轮换子集，避免整块同摆。
  4. scale：嵌套累积型默认 `falling`（每层 −15%）；若内层只覆盖小区域、几何幅度本就小，则 `linear` 递增。
  5. 层数 > 3 时把最内层合并进上一层的关键形。
- 可调：层数 2–4、层幅度比 1 : 0.5–0.8 : 0.3–0.5、子集策略。
- 失败 / 质检：内层 warp 没盖住梢部 → 折痕（包围盒扩 10%，检查所有顶点在内层中）；挂线以上必须严格 0 位移。
- 难度：中。优先级：P1。

### `physics.carrier/node-pair-2d` — 相邻质点作为一个 warp 的两轴（S 形行波）
- 目的：两个有相位差的输出在 3×3 角上分别是"根弯尖直 / 根直尖弯 / 同向弯 / 反向 S"，摆动中曲率沿物体传播。
- 适用：不支持混合形状的导出目标上的次级运动；每物 2 个输出。
- 产出：一个 2D warp，轴 (v_j, v_{j+1})，第二轴按需 reflect。
- 算法：f(s) = s²，g(s) = 4·max(0, s − 0.5)²；角键 = 两基形状之和，按 0.7–1 缩放或 clamp 防越界；p 取较近根的质点，q 取更远一个。
- 可调：f、g 指数 1.5–2.5，g 起点 0.4–0.6，第二轴 reflect，角键缩放。
- 失败 / 质检：长轴方向判错扭成波浪边；两轴同号叠加梢位移翻倍。
- 难度：中。优先级：P2（`blendshape-secondary` 可替代）。

### `physics.carrier/blendshape-secondary` — 主轴走关键形网格，物理等次级运动走混合形状
- 目的：关键形乘法组合会爆炸；混合形状是"在当前形状上加一份位移"，成本随通道数线性，摆动只做一次就能在任意角度、任意其他摆动下叠加；同一参数还能加到分属不同父级的多张网格上（贴身衣物、手臂各分支）。
- 适用：所有物理输出、表情微调、门控效果；主轴（头 XY、身体 XY、眼开合 × 笑、嘴开合 × 形）仍用关键形网格。
- 产出：参数类型 `BLEND_SHAPE`；每个物理输出在其载体（专用的"物理层" warp，或网格本身）上生成 ±1 两个位移场。
- 算法：
  1. 判定：对象已有 ≥ 2 个乘法轴，且新参数 (a) 最大位移 < 对象尺寸 15–20%，(b) 在其他轴四角处差量方向夹角 < 20° → 混合形状；否则作为乘法轴或独立 warp 层。
  2. 每个物理部位按轴拆层：角度 warp（最外）→ 变体层 → Y 层 → X 层 → Z 层 → 网格；每层与上层同分辨率，不设关键形轴，只挂混合形状。位移定义在该层局部坐标，所以会跟随父层的转向。
  3. 同一层可挂多个按质点顺序的形状（第 k 个只弯 s ≥ (k−1)/N 的部分），叠成行波。
  4. 组合极值检测：所有混合形状同时满值时，按 √(Σp²) 限幅或降低单形幅度；任意角度键 × 满值，网格不翻转、不与邻件分离。
  5. 导出降级：Cubism 5.0 以下 → 每个次级参数一层嵌套 warp（推荐），或烘焙进最少的乘法组合，写损失报告并预估关键形数。
- 可调：`max_grid_dims`（默认 2）、`blend_threshold` 0.15–0.2、降级策略。
- 失败 / 质检：主形变大时常量位移方向错（例如转头 45° 时卷发朝向翻转）→ 必须放在角度层之内；降级后关键形激增。
- 引擎能力：混合形状（Umamo 已支持编辑与 moc3 读写；`SimBaker` 已能在关键形数超过 64 时改用混合形）。难度：中。优先级：P1（生成器层面的统一策略，影响所有物理生成器）。
- 现状差距：生成器（swing、头发、裙）不产出混合形状。

## physics.gravity：静态重力补偿（补充插槽；结构与 hair-body 协调）

### `physics.gravity/current` — 无
- 现状：只有身体 X 时手臂绕肩反摆约 4°（`DeformArmHang`）；传统发丝 follow warp 在头发长过下巴时有 `HairRoll` 让下段回卷；前后发、饰品没有重力层；头一歪下垂物整体跟着歪。

### `physics.gravity/anchor-counter` — 在下垂物链根插入反向旋转，物理只负责动态
- 目的：头一歪，头发和耳坠跟着整体旋转会像贴纸"翘起来"，是 2D 模型最廉价的瞬间。先在变形器层面抵消父级转角，静态截图本身就对，不依赖物理收敛；物理只描述偏离静平衡的摆动。
- 适用：语义为发束、辫子、耳坠、挂坠、流苏、链、缎带尾，且静息主轴与重力夹角 < 45°、悬挂点在上方。朝上的物体、贴身发片不加。
- 产出：每条下垂链根部插入重力层 `Rotation_Grav_<id>`（轴心在悬挂点，轴 = 头 Z 源参数，可选身体 Z 源）；可选定位层（角度 0，以 AngleX×Y 为轴只移动支点）；宽后发用逐行反转的 AngleZ warp。该链物理的 AngleZ 输入保留为 Angle 型，但输出 scale 降到"只负责动态"。
- 算法：
  1. 收集悬挂点 p 的祖先旋转源：头 Z（含 drive-param 的 AngleZ★）、身体 Z（含惯性参数）。
  2. 每个源一层旋转，键角 = −k × 该键下祖先在 p 处的累计转角（求值器测 p 附近短向量的方向变化）。
  3. 贴附段：主轴上仍与载体重叠的前缀 ℓ_attach > 0.1L 时，把重力层插在第一个越过 ℓ_attach 的关节之后，贴附段随载体转。
  4. 不对称裁剪：±端点各做一次碰撞检测（与身体、脸、手臂轮廓），相交一侧减小 k（内侧 / 外侧比 0.6–1.0，碰到支撑物时 k = 0）。
  5. 支点跟随：头部透视大时加定位层（角度恒 0，以 AngleX×Y 为轴，支点 = 附着点在头部椭球代理上随头转后的投影）。
  6. 物理：AngleZ 仍为 Angle 输入，scale 使平衡时补偿约 (1−k)·头倾角的一部分；总补偿 ≈ 0.85–0.95。
  7. 校验：AngleZ、BodyZ 端点各渲染一次，下垂物主轴与竖直方向夹角 ≤ (1−k)·父转角 + 3°。
- 可调：`k_head` 0.65–0.9（发束默认 0.8、耳坠 0.75、链 0.9）、`k_body` 0.8–1.0、`attach_ratio` 0.15–0.25、`inner_outer` 0.6–1.0、`one_sided`。
- 失败 / 质检：k = 1 冻住；k 过大辫子末端扫向身体；悬挂点在强 warp 区（脸侧）时 warp 本身带来转角，用雅可比估计；宽发束单个重力层使发根离开头皮 → 必须用贴附段规则。
- 引擎能力：旋转变形器多键、求值器。难度：中。优先级：P1（结构与 hair-body 的链生成一起落地；价值高）。
- 现状差距：SwingDeformer 不区分静平衡与动态。

## physics.role：运动角色标签（补充插槽）

### `physics.role/motion-role-tag` — 为物理组 / 生成器记录"运动角色"，换装时按角色改挂
- 目的：同一角色多套服装时，"角色手感"（眼部、头部、手臂节奏、头戴软壳的滞后）应一致；按运动角色而不是外观改挂，物理参数几乎不用重调。

## motion.idle：待机与次级运动

### `motion.idle/current` — `MotionSynth.idle`
- 现状：周期 12 s；三口深浅不同的呼吸；重心 `sin(2周) + 0.4·sin(3周)`；BODY_Y、ANGLE_Y、BODY_X、BODY_Z、ANGLE_Z、ANGLE_X 各带幅度与相位滞后；有骨骼时尾巴 0.55·5 周、翅膀随呼吸、上半身随重心晃 2.5°、手臂 `relaxedArms` 逐关节滞后；被物理驱动的参数 `exclude`。旋钮 sway / breath / head / speed / blink。眨眼时刻固定 2.7、6.9、7.25、10.6 s。

### `motion.idle/traveling-wave` — 主动肢体的逐节相位行波（不走物理）
- 目的：尾、翅、触角、手指是肌肉主动控制的，物理只在身体动时才动、静止时就死了；行波让它们始终在动，根领先形成"驱动 → 传递"，梢略大形成甩尾。
- 适用：标为主动肢体的链（尾、翅、可选兽耳、手指）；链参数不被物理输出占用（否则物理每帧覆盖动作）。
- 产出：idle 动作中每节一条曲线（4 个贝塞尔点：起、极小、极大、终，首尾等值）。
- 算法：
  1. θ_i(t) = b_i + A_i·sin(2πt/T − φ_i)。
  2. T = idle 主周期的约数（motion.phase）；φ_1 = 0，φ_2 = π/2，i > 2 时 φ_i = φ_{i−1} + Δφ，Δφ = 0.3–0.5 rad（约 0.05–0.08 周期）。
  3. A_1 = 0.6θmax；i ≥ 2 时 A_i = 0.4θmax·(1 + g·(i−2)/(N−2))，g 默认 0.1（略增）；"柔软材质"风格 g 0.5–1.5。
  4. b_i = 原画曲率偏置（该节相对直线的弯角），或 0（偏置应并入静息网格，见 wave-plus-physics）。
  5. 物理只接根骨，或根骨只吃身体惯性（root-inertia）；若需要物理残余，用 `wave-plus-physics`。
- 可调：`T`、`delta_phi`、`amp_growth` 0.1–1.5、`theta_max`、`root_lead`（默认 π/2）。
- 失败 / 质检：周期不整除 idle 长度时循环点跳；宿主不播 idle 时冻住（可接受，或改用 breath-feed）。
- 难度：易。优先级：P1（骨骼尾巴已有；需要把 `skeletonRules` 的尾巴跟随与行波二选一）。
- 现状差距：有尾巴摆动预设，没有逐骨相位行波生成规则，也不区分主动肢体与被动悬挂物。

### `motion.idle/wave-plus-physics` — 动作行波与物理残余放在两根轴上相加
- 目的：反重力的漂浮发 / 缎带由手写行波表达，物理只负责头部转动带来的额外晃动，两者互不覆盖。
- 适用：标"漂浮"属性的长发、缎带；任何需要动作与物理同时驱动的关节。
- 产出：每侧 N 个行波参数 W_k（±30，仅动作写）+ N 个物理参数 P_k；关节角 = a_k·W_k/30 + b_k·P_k/30（2D 键或混合形状）。
- 算法：W_k(t) = A_k·sin(2πt/T − kφ)，T 4–6 s，φ 使相邻节滞后 0.1–0.15 T，A_k 根 → 梢递增，两侧错开 0.5T；a_k 根 → 梢递增（如 5°/10°/15°/20°），同侧不同发束 × 0.5–1.2（ID 哈希）；物理 scale 根 → 梢递减，只做小幅残余。静息造型偏置并入静息网格，不写进动作（否则停播时跳回原画）。
- 可调：T、滞后、梢部振幅 15–25°、物理 scale 比例。
- 难度：中。优先级：P2。

### `motion.idle/dual-oscillator` — 双振荡 idle → 物理低通 → 长链（程序化甩尾）
- 目的：两个不同周期的振荡叠加后长时间才重复，物理把方波式输入变成平滑并带鞭梢传播的摆动；情绪改变抬尾高度与摆动偏置，全部在运行时内完成。
- 产出：振荡参数 O1、O2（idle 写缓入缓出往返）；偏置参数 B1、B2；中间物理组 M1 = 0.75·B1 + 0.25·O1、M2 = 0.75·B2 + 0.25·O2（单段摆）；偏置组 Off = f(B1, B2)；尾巴物理组输入 M2 20 / M1 30 / Off 40 / 抬尾 5（X 型），N + 2 个等长质点，`whip` 剖面；抬尾参数 R（几何：根部旋转 0…150–180°）。
- 算法：T1 1.5–2.5 s，T2 = T1/1.5（或 5:4）；动作长度 = 最小公倍数；中间物理单段 r 10、d 1、a 1；表情"开心"直接设 R = 0.6、B1 = 0.5；宿主映射（笑意 → R、B）写进 `host.mapping`。
- 可调：T1、周期比、抬尾角、输入权重。
- 失败 / 质检：其他动作覆盖振荡轨道时甩尾停止 → 振荡轨道放进所有预设动作或单独动作层；物理 FPS 低时鞭梢抖动。
- 难度：难。优先级：P2。

### `motion.idle/head-body-phase` — 头部椭圆轨迹、身体滞后、单侧摆动与脊柱分段相位
- 目的：相位差避免机械同步；身体滞后于头表现重量；单侧摆动有回正瞬间；脊柱分段形成自下而上传递的 S 形。
- 适用：所有 idle；脊柱分段需 body 插槽提供分段参数。
- 产出：idle 中头 / 身体 / 脊柱轨道的相位与幅度规则（替换 `MotionSynth.idle` 中写死的滞后常数为可调表）。
- 算法：
  1. 偏航 = A_x·sin(2πt/T)，俯仰 = A_y·sin(2πt/T + 0.25·2π)，翻滚 = A_z·sin(…) + 偏置。
  2. 身体 = 头幅度 × 0.05–0.1（度数比），滞后 0.2–0.25T。
  3. 风格选项 `one_sided`：头、身体改单侧余弦，方向取原画朝向侧。
  4. 脊柱分段（若有）：hip → waist → chest 相位递增 0.1–0.15T，每层 1–3°。
  5. 被物理驱动的参数（drive-param 的输入）照写；P★ 不写。
- 可调：`T` 2–4 s、`yaw_pitch_phase` 0.2–0.3T、`body_lag` 0.2–0.25T、`one_sided`。
- 难度：易。优先级：P0（只是把现有常数改成规则表，并补椭圆相位）。

### `motion.idle/display-pose` — 原画对称站姿，idle 常量部分摆成展示姿势
- 目的：画师只画最好拆分的正面站姿，好看的展示姿态全部由参数决定，随时可改。
- 适用：游戏立绘 / 展示用模型；直播模型应把展示姿势做成追踪的偏置（`motion.layer/perf-overlay`）而不是 idle 常量。
- 产出：idle 常量轨道（姿势偏置），变化轨道在其上叠加。
- 算法：自动提出展示姿势（头 X −8…−15、头 Y 向镜头稍上、身体 X 与头同向约一半、单腿承重、手臂前臂内收 90–120°）；限制在 rig 修形覆盖范围内。
- 可调：头偏置、身体比例、手势选择。
- 失败 / 质检：宿主在 idle 上叠加追踪时常量与追踪冲突。
- 难度：易（依赖身体 / 手臂姿势参数）。优先级：P2。

### `motion.idle/micro-steps` — 高频小幅交替（碎步、颤动类特技片段）
- 目的：用极小幅高频反相抖动让观众读出"碎步移动"。
- 产出：一次性动作片段：频率 5–7 Hz，振幅为参数范围 0.3–3%（踝 : 膝 : 髋 ≈ 4 : 2 : 1），左右反相，首尾 0.3 s 包络。
- 失败 / 质检：幅度 > 2–3% 变抽搐。
- 难度：易（依赖腿 FK 参数）。优先级：P2。

## motion.phase：相位与周期设计（补充插槽）

### `motion.phase/current` — 12 s 周期内的固定滞后常数
- 现状：`MotionSynth.idle` 的周期与各轨道滞后写死；尾巴 5 周；没有对附件参数的周期规划。

### `motion.phase/divisor-clock` — 子周期全部整除循环长度，相位按黄金比错开
- 目的：所有可见周期都是循环长度的约数，循环点处每条曲线回到起点，无缝；3、4、6 s 组合使最短重复图案仍是整个循环，观者不觉"同步呼吸"。
- 适用：所有 idle 轨道（呼吸、头身、行波、特效时钟、风、激励）。
- 产出：idle 时钟规划器：输入各轨道的"自然周期"建议值，输出量化后的周期与初相。
- 算法：
  1. 循环长度 L：10–14 s，默认 12（约数多）；现有 12 s 保留。
  2. 自然周期建议值：呼吸 3–4 s、头部 3–6 s、悬浮 5–7 s、扇翅 3–5 s、闪烁 2–4 s、自转 6–12 s、行波 = 呼吸。量化到 L 的最近约数。
  3. 初相 φ_k = (k·L/(K·1.618)) mod L；峰值时刻相互错开 ≥ 0.3 s。
  4. 曲线形状：上升占周期 45–50%，缓入缓出贝塞尔；闪烁类加底值 0.3–0.5 满值。
  5. 例外：粒子锯齿（effect-clock/life-sawtooth）周期可不整除（左右用互质比约 1.08），但回落帧必须落在不透明度 0 区间。
  6. 子周期 < 2 s 显得急躁，除拍翅、闪烁外下限 2 s。
- 可调：`L` 8–16 s、`min_period` 2 s、`phase_spread`。
- 失败 / 质检：所有峰值对齐产生"整体一跳"——检查任意 0.3 s 窗口内的峰值数。
- 难度：易。优先级：P0（idle 生成器的基础设施）。

## motion.layer：表演层与待机层（补充插槽）

### `motion.layer/current` — 只有标准参数一套
- 现状：动作写标准参数；追踪接管时表演消失，或动作覆盖追踪。

### `motion.layer/perf-overlay` — 追踪参数与表演参数分离
- 目的：动作提供大姿态与节奏、追踪在上面叠细节，两者相加不互相覆盖。

- 可调：`g_idle` 0.2–0.4。
- 失败 / 质检：复制的轨道与动作长度不整除时在动作结束处跳（截到整周期或淡出）。

## motion.effect-clock：特效的时间驱动（补充插槽；动作侧，特效几何归 effect 插槽）

### `motion.effect-clock/repeat-ramp` — repeat 参数 + 常驻循环线性斜坡，开关只管显隐
- 目的：exp3 表情不能做动画；把"时间"放进始终运行的 idle（repeat 参数无限循环），把"是否可见"交给开关，热键一按看到的是已经在跑的动画。
- 产出：参数 `ParamFxClock_<fx>`（repeat，[0, R]）；idle 中写线性 0 → n·R（n 整数，或在循环长度内恰好整数圈）；多实例初始偏移 0.15–0.3 周期。
- 算法：键在 0（透明）/ 0.1R（淡入完成）/ 0.8–0.85R（开始淡出）/ R（透明）；下落类加中间键 s(0.5R) ≈ 0.25–0.35 s(R) 模拟加速；门控在容器不透明度上（effect 插槽）。
- 可调：周期 1–3 s、淡入 / 淡出比例、实例相位。
- 失败 / 质检：宿主不播 idle 时冻住（但显隐仍正确）；repeat 跨越回绕点时插值方向（用超范围值或分段）；导出必须标 repeat（Cubism 4.2+），低版本回退为锯齿往返并写损失报告。
- 引擎能力：repeat 参数（运行时模型已有 `repeat` 字段）。难度：易。优先级：P1。
- 现状差距：`MotionLoops` 只做动作循环，没有循环特效时钟。

### `motion.effect-clock/stepped-phase` — 台阶式相位：一个一个冒出、停一下
- 目的：台阶式比匀速更有节奏感。
- 产出：idle 中相位轨道：每周期 N 个台阶（占空比 0.3–0.6），首尾值同余周期。
- 可调：周期 1–2.5 s、占空比、上升距离 0.1–0.3 h_head（几何侧）。
- 失败 / 质检：首尾不同余时每循环跳一下。
- 难度：中。优先级：P2。

### `motion.effect-clock/life-sawtooth` — 粒子生命周期参数 0–1 + 锯齿循环
- 目的：粒子的一生压缩进一个 0–1 参数，动作只写最简单的锯齿；不需要 repeat 支持。
- 产出：idle 中每个 life 参数一条锯齿：上升 T_life、回落 0.02 s、间隔 T_gap；左右 / 多实例用近似互质周期（比约 1.08）与初始延迟。
- 可调：周期 1.5–3 s、淡入 0.08–0.2、淡出起点 0.8–0.9。
- 失败 / 质检：宿主平滑会把回落抹成可见的"倒退"→ life 参数不得映射到追踪、不经表情淡入；回落帧必须在不透明度 0 区间。
- 难度：易。优先级：P1（不依赖 repeat，兼容性最好，可作 repeat-ramp 的降级）。

## motion.blink：眨眼

### `motion.blink/current` — 固定时刻、对称曲线
- 现状：`MotionGenerator.blinkTracks`：0.35 s 起闭、0.45 s 到 `1−closure`、0.58 s 睁开；double 时再加一次 0.85 倍浅眨；idle 眨眼时刻固定 2.7、6.9、7.25、10.6 s。预览 `PreviewAnimationClock` 另有一套硬编码眨眼（每 4.6 s，窗口 4.18–4.46），不读 Blink 旋钮与用户覆盖。

### `motion.blink/natural-timing` — 闭快开慢、短保持、确定性的间隔与双眨
- 目的：真实眨眼闭合快、睁开稍慢；间隔不规则但可重放。
- 产出：眨眼曲线生成规则（闭 / 保持 / 开时长、缓动、双眨概率与间隔），idle 内眨眼时刻由确定性序列生成；预览与导出读同一套轨道。
- 算法：
  1. 时长：闭 0.15 s（ease-in）、保持 0.04 s、开 0.22 s（ease-out），整体可按 `speed` 缩放；风格选项 `snappy`（开也快）。
  2. 间隔：2–5 s，由 hash(模型 ID, 序号) 生成，确保 idle 循环内次数与位置固定、首尾无眨眼跨越循环点。
  3. 双眨：约 20% 的眨眼后 0.3–0.4 s 追加一次 0.85 倍浅眨。
  4. 预览：`PreviewAnimationClock` 改为播放同一 idle 轨道（消除两套行为）。
- 可调：`close_s` 0.1–0.2、`hold_s` 0–0.06、`open_s` 0.13–0.35、`interval` 2–5 s、`double_prob` 0–0.3、`closure`。
- 失败 / 质检：眨眼跨越循环点（禁止）；眨眼激励物理（blink-feed）时，间隔过密余震叠加。
- 难度：易。优先级：P0。

### `motion.blink/brow-follow` — 眨眼时眉跟随下压（写在动作里，不写进 rig）
- 目的：眼轮匝肌带动眉的真实联动，写在动作里便于按情绪调整。
- 产出：眨眼曲线附带眉 Y 轨道：闭眼段下压 d_brow，与眼同步缓动。
- 可调：`brow_dip` 0–0.6（默认 0.4；"委屈 / 柔和"风格 0）。
- 失败 / 质检：与 rig 层的眉眼联动（eye.* / brow 插槽）叠加过量 → 二者择一或总量限幅。
- 难度：易。优先级：P1。

## motion.lipsync：口型（动作 / 映射侧；口型几何归 mouth.* 插槽）

### `motion.lipsync/current` — 无增益与映射配置
- 现状：`ParamMouthOpenY` 0…1；预览有硬编码口型待机；不输出宿主映射；生成动作不含说话曲线。

### `motion.lipsync/host-overdrive` — 口型与追踪的过驱、饱和、死区与分通道平滑
- 目的：追踪 / 音量信号很少到达极值；过驱 + 截断让满幅口型可达；嘴不加平滑（否则口型拖沓）。
- 产出：宿主映射配置（见 `host.mapping/vts-profile`）中的口型行：输入区间按 5–95 分位、输出 = 参数范围 × 过驱系数 1.3–2.0、平滑 0；超量张口用独立参数（如 `ParamMouthOpenYExtra`）或表情，不改标准参数范围。
- 可调：过驱系数、死区中心、平滑。
- 失败 / 质检：过驱过大口型一直全开；标准参数范围被改后其他软件不兼容（禁止）。
- 难度：易。优先级：P1（随 host.mapping）。

### `motion.lipsync/talk-curve` — 生成"说话"动作曲线，开口分布偏小开口
- 目的：预设动作（问候、反应）带说话口型；开口值分布与真实语音一致（多小开口、少全开），配合 mouth 几何的非均匀中间键。
- 产出：说话片段生成器：音节节奏 4–6 Hz，开口值从 Beta 型分布取样（众数 0.25–0.35，偶发 0.8–1.0），MouthForm 小幅随机游走；确定性种子。
- 可调：语速、最大开口、分布形状。
- 难度：中。优先级：P2。

## breath：呼吸的物理 / 动作侧

### `breath/current` — 呼吸直接驱动躯干几何
- 现状：`DeformBodyZBreath` 按原画肩线与腰线抬肩、扩胸，腰以下不动；`ParamBreath` 由 MotionGenerator idle 写（三口深浅不同的呼吸）；不进物理，不驱动其他部件。

### `breath/torso-physics-only` — 全身站姿：呼吸只经物理体现在胸与上衣
- 目的：全身站立模型整体抬肩显得飘；只经物理体现在胸与上衣的轻微起伏，有滞后、柔和，站姿稳定。
- 适用：全身站姿（风格选项）；半身模型仍可直接抬肩。
- 产出：`DeformBodyZBreath` 的呼吸幅度降到很小的胸廓扩张（≤ 0.5% 胸宽）；胸 / 上衣 Y 物理输入加呼吸 40–100（Angle）。
- 可调：`direct_amp` 0–1（相对现有幅度，全身默认 0.2，半身 1.0）、`physics_weight` 40–100。
- 失败 / 质检：宿主无呼吸时完全静止（idle 写呼吸）。
- 难度：易。优先级：P1（与 chest-bounce、breath-feed 一起）。

### `breath/lfo-drive` — 把呼吸当全局 LFO：辉光、漫符、浮空道具
- 目的：运行时自动呼吸是永远在跑的周期信号，借来驱动贴花、辉光、浮空物，开关一开就自带节奏，不需要动作。
- 适用：effect / prop / lighting 插槽产生的辉光、漫符、浮空物（几何在那些插槽）；本模板只给"以呼吸为轴"的键设计。
- 产出：以 `ParamBreath` 为轴的键（直接绑定）或以呼吸驱动的物理输出为轴（需要不规则节奏时）。
- 算法：
  1. 辉光：按空间位置交错分两组，A 组 0 → a、B 组 a → 0，a 0.2–0.45。
  2. 浮空道具：根 warp 上浮 0.01–0.02 H、±2° 摆。
  3. 漫符：怒符缩放 0.9 ↔ 1.1，问号 / 汗滴摆 10–20° 或下滑 0.1 h_head。
  4. 星群：呼吸 0.8 + 头 0.1–0.2 进 `sweep` 剖面物理，输出 F 与漂移；每颗星亮区间中心 c_i 均匀错开在 −0.6…0.6、窗宽 0.4–0.5（先仿真一个呼吸周期确认 F 实际范围再分配）。
- 可调：各映射幅度、反相分组、节奏源（呼吸 / 专用循环参数）。
- 失败 / 质检：节奏被绑定到呼吸（"生气"可能偏慢 → 改用 2 倍频循环参数）；宿主不驱动呼吸时静止（可接受）。
- 难度：易。优先级：P1。

### `breath/limb-breathe` — 呼吸带动手臂微张、手指微开合
- 目的：静止站立时手不是刚体。
- 两种做法：
  - 直接键（简单）：上臂旋转以呼吸为轴外展 1–3°，左右相反；前臂网格 0.3–0.5% 跟随。
  - 经物理（有滞后）：呼吸并入 `limb-pendulum` 输入（15–30），或单独软链 r 5、m 0.6、d 0.6、a 1.2，肘读 v3、腕读 v4。
- 产出：叠加层（不覆盖姿势参数）。
- 可调：臂展 1–3°、手位移 1.5–2.5% H、指张 10–30%。
- 失败 / 质检：一个呼吸周期内手位移 ≤ 2% H。
- 难度：易。优先级：P1。

### `breath/pose-modulated` — 呼吸 × 姿势的二维键
- 目的：姿势不同，肩的受力方向不同，呼吸作用于肩的量应随姿势变。
- 产出：肩 / 上臂根旋转以 (呼吸, 姿势开关) 为 2D 轴。
- 难度：中（依赖姿势分支）。优先级：P2。

## host.mapping：宿主映射（补充插槽）

### `host.mapping/vts-profile` — 随导出生成追踪映射配置
- 目的：drive-param 等结构要求宿主写"输入参数"；没有配置时用户很容易把追踪映射到驱动参数，表现为"身体不动"。
- 产出：可选导出文件（VTube Studio 参数映射）：每个追踪输入 → 输入参数、区间、过驱、平滑；呼吸设为自动呼吸；说明文档列出不应映射的驱动参数。
- 可调：过驱系数、平滑（角度 15、眼 10、嘴 0）、是否导出。
- 难度：易。优先级：P1（与 drive-param 同轮，否则 drive-param 在直播宿主上不可用）。
- 现状差距：不输出任何宿主映射。

### `host.mapping/drag-hit` — 拖拽交互参数：命中区拖动、松手回弹、接反应动作
- 目的：用户直接"摸"到弹性部件，参数跟手、松手回弹。
- 产出：为可交互弹性部件建"拉动"参数（X/Y，[−1,1]，几何归对应插槽）；导出控制器配置：增益 = 1/部件像素尺寸、回弹 150–250 ms、结束动作；不支持的宿主退化为点击触发动作。
- 可调：回弹时间、拉伸上限 20–40% 部件宽。
- 失败 / 质检：拖动参数与物理输出同参数会被覆盖（必须分开）。
- 难度：中。优先级：P2。

## 跨插槽约束与实现提示

1. **物理输出覆盖动作**：Cubism 物理每帧覆盖其输出参数。任何"既要动作写、又要物理动"的关节都必须用两个参数（`wave-plus-physics`、`limb-pendulum`、`drive-param` 的 P / P★ 分离），MotionGenerator 生成时排除物理输出参数（现有 `exclude` 机制扩展为"排除全部物理输出 + 驱动参数"）。
2. **方向约定**：全局固定"画布方向"关键形约定，reflect 规则才可复用；镜像生成（`KeyformMirror`）与 reflect 规则需在同一处定义。
3. **剖面与规则都是数据**：材质剖面、scale 曲线、输入配方、相位表应进入预设注册表（模板参数 + 版本号）。实时生成类模板必须带算法版本，改常数时旧工程按旧版本重放（现状痛点 2）。
4. **确定性**：所有"抖动 / 随机相位 / 实例差异"一律用 ID 哈希；不得使用随机数。
5. **生成器图**：每个物理模板实例应是独立生成器节点并声明读写集（依赖图同时服务 `staged-inputs` 的物理排序与 `GeneratedOverrides` 的归属）。
6. **用户覆盖语义**：生成物理组的用户覆盖应从"同 ID 整组替换"改为"生成值 + 用户差量"三方合并（与模拟摆锤一致），否则改剖面 / 改长度后旧覆盖遮住新值。
7. **导出降级**：drive-param（无物理直通）、blendshape-secondary（嵌套 warp 或烘焙）、repeat-ramp（锯齿往返）都要在损失报告中写明；`ExportGoldenTool` 对比时这些模板默认关闭以保持旧工程字节一致。
