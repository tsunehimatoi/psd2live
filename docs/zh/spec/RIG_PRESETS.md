# Rig 预设架构：部位、基础算法与模块

[文档目录](../../README.md) · 模块与算法目录：[面部](RIG_TEMPLATES_FACE.md) · [头发与身体](RIG_TEMPLATES_HAIR_BODY.md) · [物理与动作](RIG_TEMPLATES_PHYSICS_MOTION.md) · [结构与表现](RIG_TEMPLATES_STRUCTURE.md) · [变形器与参数](DEFORMER_AND_PARAMETER_SPEC.md) · [文档层](DOCUMENT_LAYER.md)

本页描述自动生成怎样组织成可选择、可关闭、可调整的部分：

- 每个部位有一种或几种互斥的**基础算法**，外加若干可叠加的**模块**；
- 工程的**配方**记录每个部位用哪种基础算法、哪些模块关闭了、哪些数值改过。

各算法与模块的设计（读什么、产出什么、关键形怎么算、好看的标准）在四份目录中；本页只规定它们怎样注册、选择、保存、重放和暴露。

## 目标

自动生成的模型默认就要具备手工精调模型在视觉表现上的长处：

- 眼、眉、嘴有完整的表情空间，不只是开合；
- 眨眼、说话带出周边的联动和余震；
- 转头有深度；
- 头发和衣物有重量与错相。

这些能力逐个做成模块。

- **默认全开**：新工程默认开启全部适用的模块。
- **按需关闭**：用户可以按参数量关掉任意一个，也可以用预设或参数预算一次关掉一批。
- **少量旋钮**：每个模块只暴露少量有意义的旋钮，每个旋钮内部驱动一组底层数值。以后可以在画布上拖动特征点和手柄来调整。

判断一个模块是否做成，只看效果：

1. 用审阅工具（`RigReviewTool`）出姿态板和动作片段；
2. 对照该部位的“好看的样子”和“常见毛病”逐条检查；
3. 数值检查只作提示。

## 术语

| 术语 | 含义 | 代码 |
| --- | --- | --- |
| 部位（area） | 一张卡片管的范围：头与脸、眼、眉、嘴与下半脸、头发、身体、服饰与挂件、表情、动作。一张卡片管左右两侧 | `RigArea` |
| 基础算法（base） | 部位内互斥的做法，例如眼睑闭合用原有算法还是模板拟合。ID 为 `部位/名称`，带版本号与可调数值 | `RigBase` |
| 模块（module） | 部位内可叠加的一项能力，例如笑眼、视线带眼睑、眨眼余震，各自开关。ID 为 `部位.名称` | `RigModule` |
| 旋钮（knob） | 基础算法或模块的一个可调数值：单位、范围、默认值、是否折叠为高级 | `RecipeKnob` |
| 配方（recipe） | 工程为每个部位选的基础算法、关闭的模块与改过的数值，存于设置 `rig` | `RigRecipe` |
| 部件角色（part role） | 图层在其部位内是什么：高光、瞳孔、下睫毛、双眼皮线、阴影、腮红、侧发、呆毛、马尾、辫子、兽耳、缎带、吊坠、硬质饰物、袖、裙 | `PartRole` |
| 模型预设 | 开始页的快捷组合（最小 / 默认 / 完整）与模型预设面板中的各组 | `StartQuickPreset` |
| Rig 数值 | 原有算法在参数满值时的幅度，是各部位原有基础算法的参数；面板中放在各部位卡片的「数值」里 | `RigTuning` |

## 注册表

`core/recipe/RigModules.kt` 是唯一的注册表。部位按面板显示卡片的顺序登记。

**基础算法**

- 每个部位的第一个基础算法是 `部位/legacy`，即引入注册表之前的生成方式。
- 较新的基础算法登记在其后，最后一个是新工程的默认。

**模块**

每个模块声明以下内容：

| 字段 | 含义 |
| --- | --- |
| `tier` | 重要程度：`CORE`（部位看起来完整所必需）、`MAJOR`（明显的视觉品质）、`MINOR`（锦上添花）。预设与预算按它裁剪 |
| `requires` | 依赖的模块；关闭被依赖的模块时，依赖它的模块一起关闭 |
| `applies` | 素材是否具备它要处理的部件（按部位、侧别和部件角色判断）。不适用的模块不显示、不计成本，也不生成 |
| `parameters` | 它为这份素材新增的参数 |
| `estimate` | 关闭时的成本估计 |
| `physicsGroups` | 它生成的物理组 |
| `setting` | 设置中原有的对应开关（见下） |

**ID 与版本**

- ID 一旦可能被工程保存就不再改名。
- 算法改变了已有工程的生成结果时，升版本号；配方中记录设置数值时的版本。

**沿用旧开关的模块**

注册表之前已有的几个开关也登记为模块：

| 模块 | 对应设置 |
| --- | --- |
| `eye.see-through` | `seeThroughEyes` |
| `eye.jelly` | `physicsEyeJelly` |
| `brow.see-through` | `seeThroughBrows` |
| `mouth.outline` | `mouthOutlineEnabled` |

- 它们的开关就是原设置，旧工程中同样有效；
- 它们没有旋钮。

## 成本

成本的四项是：

- 新增参数（逐个列出 ID）；
- 新增关键形：在键有该模块参数的网格上，多出的格子数；
- 混合形状的形数；
- 物理组数。

成本的来源：

- 模块开启时，从生成好的 Rig 上实测（`ModuleCost.measure`）；
- 模块关闭时，用模块自己的估计，面板以 “≈” 标出。

## 配方：选择、保存与升级

**新旧工程**

- 新工程的设置写入 `rig` 键，内容为空对象时表示全部默认：各部位用默认基础算法，适用模块全开。
- 引入配方之前保存的工程，设置中没有 `rig` 键，读作旧配方（`RigRecipe.Legacy`）：
  - 各部位用 `legacy` 基础算法；
  - 除沿用旧开关的模块外，不开任何模块。

  因此旧工程照旧生成，设置文本与修订身份也不变。
- 升级：写入 `rig: {}`，可撤销。
- 退回旧配方：写入 `rig: null`，设置中随之不再有这个键。

**修改（设置补丁 `changes.rig`）**

面板、MCP 走同一条路径。

| 内容 | 写法 |
| --- | --- |
| 部位的基础算法 | `bases: {部位: {base, values}}`；为 `null` 回到默认 |
| 模块 | `modules: {模块: {on, values}}`；为 `null` 回到“开启、数值默认” |

- 保留同一基础算法或模块时，数值与原有的合并。
- 沿用旧开关的模块，`on` 写到对应设置上，不能带 `values`。
- 以下都被拒绝：
  - 未知的部位、基础算法、模块、数值；
  - 超出范围的值；
  - `bases`、`modules` 之外的键。

**保存格式**

- 只写与默认不同的项：模块只记 `on: false` 与改过的数值。
- 读取时，不认识的部位、基础算法、模块与数值被跳过，所以较新版本保存的工程仍能打开；数值夹到范围内。

## 重建与重放

配方是生成设置，按以下方式参与重建：

- 它进入阶段缓存可读的设置（`RigBuilder.stageConfig`）；
- `RigGenerationChange` 把它算作生成规则变化：修改配方会生成新基础 G′，与旧基础 G、作者态 M 三方合并，并在日志末尾写 `rig_checkpoint`；用户在旧基础上的编辑按合并规则保留；
- 模块新增的参数只在模块生成时加入模型；关闭模块后，未被引用的参数随合并移除。

因此开关模块、调旋钮都是一次可撤销的历史提交，保存、重开后照常重建。

“改参数即重算、保留用户微调”的模块应作为日志之后的生成器实现，并在 `DocumentGenerators` 登记它拥有的关键形（见[文档层](DOCUMENT_LAYER.md)）。

## 部件角色

部件角色细化语义标签：

- 例如同为虹膜层，高光、瞳孔与虹膜本体各自运动；
- 同为睫毛层，下睫毛、双眼皮线、眼睑阴影随闭眼的行为各不相同。

**作为标签词**

- 每个角色是一个标签词：`highlight`、`pupil`、`lower`、`lid`、`shadow`、`blush`、`side`、`ahoge`、`ponytail`、`braid`、`animal`、`ribbon`、`pendant`、`rigid`、`sleeve`、`skirt`、`upperlip`、`lowerlip`、`upperline`、`lowerline`。
- 角色词与部位、侧别词一起写在图层的标签里（`LayerTags`）。
- 每个角色只能细化特定的部位，放在不适用的部位上不起作用。

**自动判断**（`PartRoles`）按顺序进行：

1. 图层名与所在文件夹的中、日、英、韩关键词；
2. 图层在同部位各层中的位置和混合方式。例如：
   - 虹膜内较小的滤色层或亮层是高光，较小的暗层是瞳孔；
   - 眼睛中线以下的睫毛层是下睫毛，上睫毛上方的细线是双眼皮线；
   - 正片叠底的脸部、头发、衣物层是阴影；
   - 脸侧垂到脸中部以下的前发是侧发；
   - 整片（不分左右）的下装，下摆不窄于腰部、下摆中间不断开（裤子在两腿之间断开），是裙子。

**用户修正**

- 用户写在标签里的角色优先。
- 从标签中去掉一个推断出的角色，记为 `PartRole.PLAIN`（无角色），分析不再重新推断。
- MCP 的 `layer_classify` 用 `part` 字段设置：角色词、`none` 或 `auto`。
- 角色存在图层分类覆盖中；没有角色的覆盖与以前的文本完全相同。

**谁读角色**

- 只有模块读角色，旧配方不读，所以角色不改变旧工程的生成结果。

## 面板与 MCP

**面板**

模型预设面板的「部位与模块」组：

- 顶部：
  - 预设（完整 / 标准 / 精简 / 自定义）；
  - 参数预算：按“重要程度从低到高、参数从多到少”关闭模块，直到新增参数不超过预算；
  - 重置按钮。
- 下面是各部位的卡片。卡片头显示开启的模块数与新增参数数，展开后：
  - 有多种基础算法时，显示基础算法下拉框与其旋钮；
  - 每个模块一行：开关、成本，开启后显示旋钮；
  - 只显示适用于当前素材的模块；
  - 最后是该部位的「数值」折叠项：这一部位的 Rig 数值（`RigTuning`，头与脸含头部转向与鼻耳，身体含转身、上下、前后倾、大小变、身体 Z 与呼吸、立体与透视），常用的按小组列出，其余折进「高级」，带只重置这些数值的按钮。
- 只显示当前配方下真正起作用的 Rig 数值：某个模块或基础算法在生成时自己画的部分，对应的旧数值不再显示（`RigTuning.replacedBy`、`RigModules.tuningInEffect`）。`face.depth-turn` 生成时，脸、五官与前后发在 AngleX / AngleY 上的九宫格转头数值不显示（风格转头取代它们，原来的变形器在转头键上保持静止）；拟合眼取代原有的闭眼数值（眨眼深度、眼角、睫毛压扁），拟合眉取代眉毛抬起，拟合嘴取代原有嘴形数值，头发链取代前后发各自的整体摆动与卷曲。旧工程（配方未升级）和关掉这些模块时，这些数值照常显示并起作用；项目文件与 MCP 仍接受全部字段。
- 旧工程在组顶部提示可以升级；不自动升级。

**MCP**

- `module_catalog`（只读）：列出全部部位、基础算法、模块与旋钮。打开工程时还返回：
  - 是否为新配方、各部位当前的基础算法；
  - 每个模块是否适用、是否开启，以及成本。
- `settings_update`：通过 `changes.rig` 修改配方。
- `workspace_inspect scope=settings`：返回存储形式，可原样写回。

## 特征点拟合（`core/fit`）

五官的新基础算法不靠写死的公式，而是读出原画的特征点，再把标准模板拟合上去：

| 组件 | 作用 |
| --- | --- |
| `EyeFitting` | 先由两只眼白中心的连线求出头部的水平方向（只有一只眼时取 Rig 的水平），眼睛的坐标系随之倾斜：歪头、侧身的角色沿自己的脸开合。沿这个方向，眼白不透明像素的两端是内外眼角，再在两眼角之间逐处沿“脸的向下方向”读出上下睑缘（各 17 个采样，画师通常把眼白画完整地压在睫毛下）；闭眼线读出它的中线，虹膜读出外框。坐标以内眼角为原点、单位为两眼角沿头部水平方向的距离，外眼角可以高于或低于内眼角。检查宽度、开合比例、上下睑缘次序与眼角倾斜，不合格的眼睛退回原有算法，并给出原因 |
| `EyelidModel` | 伪 3D 眼睑：眼睑是绕眼角连线转动的平面，与眼球相交处就是睑缘，所以眼睑下行时睑缘始终是盖过眼球的弧，只在越过眼角线时变直，之后成为闭眼的下弯弧 |
| `ThinPlateSpline` | 薄板样条：把模板的特征点精确对到检测出的特征点，同一映射用于模板的每个姿态 |
| `BiharmonicField` | 规则网格上的双调和位移场：只在约束处（睑缘、唇缘）给出位移，其余处取最平滑的解，外圈为零；用于让眼睑皮肤、阴影等跟着睑缘多行平滑地动 |
| `EyeRig` | `eye/fitted` 基础算法。上睑按伪 3D 模型（以两眼角连线为基线）下行：越过眼角线之前保持向上的弧并匀速下降（困倦的下垂眼睑），之后转为闭眼弧；越过的开度按眼角在上下睑之间的位置决定，限制在 0.15–0.25。闭眼线落在下睑稍上方（原画有闭眼线时落在线上，并在 0.06 处换线），下睑默认只上推 5%，与手工模型一致：眨眼时下睑与下睫毛几乎不动，眼白在上睑下提前收起，最后下睫毛与睫毛层的下眶部分并入闭眼线，只剩一条线。上睫毛贴上睑缘并变薄，超出眼角的眼尾随睑缘末端移动，并随闭合向外下垂；双眼皮线与眼睑阴影（部件角色 `lid`、`shadow`）随双调和场移动。笑眼、睁大、情绪与视线都表达为“两条睑缘的姿态”，各层按同样的方式跟随 |
| `BrowRig` | `brow/fitted` 基础算法与眉毛模块。眉毛同样在头部坐标系里读出：沿头部水平方向的两端为内外端（离脸中线近的是内端），中线按 17 个采样读出。上下移动的幅度约为下方眼睛开口高度的一半（旋钮“移动幅度”），没有拟合眼时取眉长的四分之一。角度绕眉毛中点沿弧转动而不是错切，用五个关键点；左右移动、弯拱与眨眼下沉是叠加的混合形状 |
| `HeadTurn` | `face.depth-turn` 模块。脸、五官与头发按"转头风格"（`TurnStyle`，存于二进制的 `rig/head-turn-style.bin`）变化，风格是三层结构：**元变形**是一组有名字的位移量，都以脸宽为单位、按转头方向镜像（转向 +x 为正）：脸中部的滑移；沿脸轮廓从下巴起按弧长等分的 24 个点各自相对中部的位移；每只眼（白眼加睫毛）的中心相对中部的领先与上下、整体 2×2 线性变化（收窄与倾斜一起，远眼外端收得多是线性变化本身的结果，不是转动）、睫毛尾越过眼白外端的部分的额外位移、虹膜在开口中的相对位置与自身宽度、眼到同高轮廓的余量；每条眉的领先、上下、宽度、倾斜与拱起；嘴的领先、上下、2×2 线性变化与嘴线弯曲；近耳、远耳与头饰的整体位移；头发每个角色（刘海、侧发、头顶、垂下的发、后发、后发下段）的一组场参数。每个元变形是转头份额 a 与俯仰份额 p 上的一个**切比雪夫曲面**：f(a,p) = Σ c<sub>i0</sub> U<sub>i</sub>(a) + Σ c<sub>0j</sub> V<sub>j</sub>(p) + Σ c<sub>ij</sub> 0；第一项只管左右转，第二项只管抬头低头，第三项只是斜向姿态自己的变化。系数可以直接读：转头的一阶是匀速部分，二阶是提前或滞后（同一个转头里各部分不是同步缩放，例如两眼间距与远眼的收窄后半程才明显，近眼起步慢），俯仰的奇数阶是抬头与低头的差，偶数阶是两者共有的部分。曲面按各参考的全部关键形拟合，高阶项按阶数加罚，所以关键形少的参考保持低阶、平滑，并向全体的平均形状靠拢；主轴建在系数上。存储时每个值只保留用得上的项（去掉后任何一组曲面的变化不超过容差），系数为每值一个缩放的 8 位或 16 位整数，再压缩，整个风格约 48 KB。**用户控制**在默认风格上叠加美术滑条，每个滑条沿一个方向改变一组元变形（100% 45% 为风格本身），再乘全局"转头强度"。风格也可以从几种完整的转头风格开始（`style` 旋钮，面板中为"转头风格"下拉框：标准、强立体、夸张、大幅、点头、柔和），每种是风格主轴上的一整组曲面（含头发）；选中后模块其余数值恢复默认，滑条在其上调整。角度数值只是参数的位置：AngleX 端点 ±45 即风格的转头端点，AngleY 端点 ±30 即抬头、低头端点；关键形 AngleX 取 0、±11.25、±22.5、±33.75、±45，AngleY 取 0、±15、±30，小幅与大幅各有自己的形状。**绘制**：脸（`FaceTurn`）在每个键上把 24 个轮廓点放到风格给的位置，眼间到鼻下的一块中部整体滑移，其余各点由薄板样条插值，所以脸保持自己的形状；脸的 Warp 与其下更细的脸皮 Warp 0，到结束处为发梢 1）为一次项，发梢领先发根。头发跟随、发梢领先、后发视差三个滑条分别按比例缩放前片的偏离、前片的发梢项和后片的偏离。头发片的各个系数同样是转头（分左右）与俯仰上的切比雪夫曲面。头发与头饰按 AngleX、AngleY 各自叠加的形状生成，前发与后发的跟随变形器不再另加转头。风格不处理的图层（眼镜、丝带、挂件等）仍按各自所在的头部"壳"绕头转动：皮肤与五官在脸面上，鼻子略凸，前发更靠外，后发在背面，耳朵略在轴后，眼镜、头饰整体刚性，幅度随转头幅度与立体感。已知不足：大幅转头时近侧头顶外缘可能露出一点头皮（防露缝规则尚未完成）；头发的对角姿态只有两向之和 |

## 实现约定

- `legacy` 基础算法的代码路径保持不变：
  - 新基础算法与模块在分派点按 `config.recipe.base(部位)` 与 `RigModules.builds(模块, config, 素材)` 选择实现；
  - 实现只依赖纯几何输入，不读界面状态。
- 一个模块改变某参数的键位时，共享该参数的所有网格必须用同一组键。例如眼白是虹膜的蒙版，必须与睫毛同键。
- 次级变化优先用混合形状叠加在主关键形之上，避免关键形数量按维度相乘。不支持混合形状的导出目标由降级器烘焙或丢弃，并写损失报告。
- 生成结果只含 Cubism 能表达的混合形状（`CubismBlendShapes`，基础 Rig 组装后执行）：Cubism 只在“混合形状”类型的参数上叠加混合形状，这类参数不能作关键形轴；挂在普通参数上的混合形状无法写进 moc3 / cmo3，Cubism 运行时会画错。因此：
  - 只被混合形状使用、默认值为 0 且各形的静止键在 0 的参数（元音、面捕、眉形、头发与布料的链段、手臂摆动、胸部等）改为混合形状参数；
  - 同时是某个关键形轴的参数（转头角度、眼与嘴的开合、视线、眉高与角度、嘴形）上的形状改成关键形：网格自身关键形网格（几何与各通道轴的并集，即 moc3 里该网格的关键形数）不超过 256 个、顶点值不超过 12 万时按这些参数的键折进网格，结果精确（形状的权重在键之间、限制在点之间都是线性的，在全部键上取值的网格完全复现）；超出时交给网格自己的 Warp（`<网格 ID>_Turn` 放转头，`<网格 ID>_Shape<n>` 放其余联动，每个不超过 64 个关键形），插在网格与原父级之间，8×8 格点按形状对网格顶点在自身各关键形下的位移最小二乘拟合，与 Live2D 手工模型把转头放在部件 Warp 里的做法相同。Warp 在父级带弯时只能按格点逼近，误差在 1 画布像素左右；
  - 形状改变的不透明度与颜色折进网格的通道；生成的形状一律不改绘制顺序（各形的绘制顺序取网格最终的静止值）。
- 生成对象与参数的 ID 是确定的：
  - 模块新增的参数优先用 Cubism 标准名，面捕扩展用常见的社区命名；
  - 新对象 ID 由模块与目标派生，不用随机数。

## 扩展一个模块

1. 在目录中写设计：
   - 适用条件、产出、分步算法、旋钮；
   - 好看的样子与常见毛病；
   - 失败时回落到什么。
2. 在 `RigModules` 中登记：所属部位、重要程度、依赖、适用条件、参数、成本估计、旋钮。
3. 在生成分派点实现，`legacy` 路径不变。
4. 补四种语言的名称与说明（`settings.rig.module.*`、`settings.rig.knob.*`）。
5. 验证：
   - 用 `RigReviewTool` 出姿态板与动作片段，对照好看的标准检查；
   - 用 `ExportGoldenTool` 确认旧配方的工程逐字节不变；
   - 加回归测试（`RigRecipeTest`、`RigModulesScenario`）。
