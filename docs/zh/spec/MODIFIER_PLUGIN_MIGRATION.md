# 修改器插件迁移执行规范

本文规定重构顺序、框架放行条件与逐项验收账本。已经落地的能力单独列出，不把设计或内核抽离计为修改器迁移完成。现有公开能力见 [插件指南](../guide/ALGORITHM_PLUGINS.md)。

## 完成边界

迁移单位是完整修改器，不是计算类。必须同时具备可安装包、完整资源、无产品层依赖、直接计算所属结果、稳定身份与版本锁定、完整贡献，以及相关效果等价和事务回归。

已有工作进程包不等于生成链路独立。宿主预生成绑定模板再交给插件，仍不通过验收。新实现不得调用 `RigBuilder`、`RigModifierSource.template`、`generated` 或改名后的整套生成回调。默认预设、预设切换和新增修改器全部走独立算法。完成迁移后清理宿主的旧模板生成和提取路径。已保存的版本由锁定的兼容包重放，未转换的工程由显式转换入口处理。旧版风格仍由独立的旧风格算法提供。

## 框架分层

- `algorithm-api` 为 MIT 中立契约，不引用产品、Umamo、工程、历史、UI；协议可跨语言表达。
- 共享算法库提供轮廓、特征测量、坐标变换、插值、参数定义和几何计算。使用 GPL 引擎的实现留在 GPL 模块。不能在共享服务中隐藏整套绑定生成。
- 插件读取捕获输入、配置和显式依赖，返回所属变更、资源、贡献和诊断；包内携带实际需要的模型数据。
- 宿主管理包、工作进程、调度、校验、缓存、覆盖、应用前缀、取消、CAS 和单历史节点提交，不替插件计算运动结果。

## 已落地的框架部分

- **变更与资源**：`ModifierModelChanges` 支持直接变更、对象前置状态及写入范围检查。JVM 工作进程支持稀疏 `model_changes_v1` 和生成图像的 `model_changes_v2`；宿主验证并附加生成网格、图像和路径。六语言的新载荷覆盖尚未完成。
- **输入与缓存**：已提供 `source_layers/1` 栅格观察、源到模型变换与目标引用；`ReadingModifierAlgorithmPlugin` 支持逐对象读取和父级链查询。JVM 工作进程的 `input_reads_v1` 已用物理包验证命中与失效。显式上游能力包含目标、版本、配置、输出别名及包身份，应用前缀保留其身份。源裁剪与通道遮罩语义仍需扩大验证。
- **坐标与结构**：`BindingCoordinates` 提供真实父空间的正逆变换和重新挂接。当前 `rig.scaffold` 的 `scaffold/5` 入口只接收源层分类、坐标测量、未绑定拓扑、图集 UV 和普通材质；插件内部生成部件、全部静态变形器、局部网格及默认关键形。它不再接收 `template` 资源，也不调用整套生成器。眼眉的带符号零、虹膜与嘴部的浮点残差、头发摇摆关闭后的重挂均保留旧计算语义。
- **结构试点证据**：完整静态模型逐项对照、36 项绑定回归、前缀应用与预设转换通过；新源输入在两个历史算法版本的真实安装包工作进程中完成安装、求值、卸载与重装检查，结果与进程内一致。结构插件已直接记录并返回部件、变形器、目标网格和组织树的类型化变更，带对象前置状态；只转换目标网格与实际写入对象，不遍历无关网格的几何输出。参数顺序和其他作者字段保留原引用。已接入实际读取缓存：有序网格成员与目标网格分别观察；未选网格的几何和显示通道不作为绑定输入。框架总验收仍未完成，不能只凭独立计算判定全部迁移完成。

旧锁定包保留对应输入格式：1.0.37 之前使用 `scaffold/1`，1.0.37 使用仅独立部件树的 `/2`，1.0.38–1.0.39 使用独立身体／头部的 `/3`，1.0.40 使用独立全部变形器的 `/4`；1.0.41 起使用无模板的 `/5`。宿主用同一套独立脚手架计算生成历史输入，已核对四种旧输入格式在全选和部分目标下的资源字节。 第一项旧绑定也从独立脚手架和源图显示属性取得中性起点，原来专门构建中性整模的入口已删除。禁止静默替换包版本。普通素材直接构造网格和图集绑定，跳过旧的语义层级、参数与通道装配。已应用的修改器、作者关键形、物理与动作可在此基础上重放。延迟生成、分层图元以及使用冻结生成素材的记录仍走各自的兼容入口。其余尚未迁移的修改器仍会运行旧模板路径，整条生成链路的验收要检查默认预设和后续修改器的实际调用。

当前仍未达到下文框架总放行门槛。使用已稳定输入契约的类型可以先并行实现，是否切换生产入口仍按各项证据决定。

## 当前试点发现与下一交付顺序

1. **结构生成输入**：`rig.scaffold` 的新入口已从源测量与未绑定网格独立计算完整静态结果，旧入口只服务于旧锁定包及未迁移修改器。下游对象来源查询现复用插件生成的规范结构，应用前缀后的前置实例保留已持久化插件引用；实际读取缓存已经接线，仍需核实其对首次加载的影响。
2. **生成资源事务**：`mouth.outline` 同时修改原嘴网格并新增图像与描边网格。契约需要把 owner 的预期状态、网格与路径变更、生成资源身份与 RGBA、画布位置、素材局部像素 UV 一起提交。宿主负责图集追加、纹理与源图记录、组织关系和恢复；不能在资源附加成功而几何失败时发布部分结果。
3. **实际运动依赖**。拟合嘴、描边、元音、捕捉、吐舌、下颌、颊睑、深度和回弹均已有直接读取源测量与实际前置修改器的实现。整口开口、双眼闭嘴和单眼闭嘴的适用默认组已接入。单眼开口已验证独立拟合和轮廓，分层唇线已验证独立拟合、轮廓、元音、捕捉和下颌。超出已验证前置组合的素材仍可能调用历史模板。
4. **多语言契约验证**：同一组有效／无效输入资源及变更样例覆盖六种语言，验证协议与内容校验；实际算法效果仍单独验证。包版本、冲突、缺失与取消不由算法各自实现。
5. **清理兼容边界**：核对默认预设、单项添加与显式转换的实际调用链，清理宿主中已迁移算法的模板生成和提取代码。验证历史包版本、生成对象 ID、作者覆盖和工程重放。性能优化安排在重构交付后。CLI 的 TML 候选从源测量规划导出 ID，在求值后恢复动态载体的原有 ID 和布局。完整 IR 对照无差异，MOC3、CMO3 和物理侧车已通过导出读回。旧工程转换保留生成唇线、素材、变形路径和透视副本的历史 ID。TML 已通过严格转换与冷重放，核对包含贴图、形变、物理和动作的完整模型。完整预设的正式 CLI 入口仍须核对其他素材、无变形器模式和关闭动作或物理的组合。

   显式栈的导出直接使用求值后的物理、动作和运行时角色。独立 CLI 的仅网格模式已切到素材网格和空栈，保留原有网格密度、语义遮罩、部件和参数定义。TML 的新链路与 DS 的实际入口均通过完整 IR 对照和导出读回。无变形器模式已直接从画布素材生成原有关键形，并保留降级后所需的局部载体。TML 已通过 MOC3 和 JSON 字节对照，以及归一化编辑器标识后的 CMO3 读回。

物理试点静态复审未发现产品生成器依赖；现有读取整个物理分区会因 FPS 变化保守失效，属于后续缓存粒度优化。静态复审不代替安装、取消、持久化与导出验证。主代理按实际证据更新放行结论及逐项账本。

## 输入契约

作者快照具有修订号和稳定对象引用，不读取实时选择或工程。源素材声明语义、像素与遮罩资源、尺寸和坐标变换；网格声明位置、UV、拓扑及父坐标系。明确画布像素、父局部、归一化晶格空间。

二进制资源按内容哈希引用，声明格式、元素类型、尺寸与布局，验证长度、哈希、边界和解压限制。首次同步后只传缺少资源。进程内实现读取同一逻辑输入，不强制序列化往返。

共享分析按源资源、分析版本和分析选项寻址；运动强度变化不能无故使原始像素测量失效。上游通过实例和能力引用提供，不允许插件自行寻找当前活动实例。宿主适配器可声明可选上游，只传递前序已生效且目标相交的能力，缺失时继续求值。外部包清单目前仅声明必需能力。

## 输出契约

输出是有类型的新增、修改、删除、复用声明，覆盖参数及组织、层级、网格、变形器、关键形、关系、图像、物理、模拟绑定和动作。不能每项返回完整模型再全量比较。

已有对象的修改带预期输入标识；新增对象使用实例身份和局部名称导出 ID，宿主保留旧 ID 映射。组合编辑声明组合方式和坐标空间；整对象替换按独占写入处理，不默认可交换。

宿主检查实际写入范围、参数兼容、引用完整、层级无环、有限数值、网格与资源有效性；失败不发布部分结果。贡献明确新增、修改、复用对象，诊断使用稳定代码与对象引用，GUI/MCP 共用。覆盖在所属输出验证后合并，应用前缀保持后续引用与原有覆盖语义。

## 依赖、版本与缓存

包依赖、算法能力依赖、实例前置项分开表达。包使用完整版本范围及冲突列表，工程锁定实际包与依赖内容，禁止静默升级。前置能力由前序有效实例或固化内容提供，缺失时保留配置并暂停求值。

能力别名由实例所锁定的算法版本与包声明。应用前缀时保存实际声明，后续依赖可以使用已经固化的内容。旧记录缺少该字段时按原实例身份解析。

遵从栈顺序，非法移动说明冲突而不重排；只有读写关系证明无冲突的任务才并行，按确定顺序合并。未知关系串行且保守失效。

缓存包含包内容、算法版本、实例、配置、目标、实际读取资源、上游输出和覆盖。复用时验证读取集合；读取需求变化必须重新计算。取消过期候选，只提交最新有效结果。模拟只随真实输入变化重新烘焙。

## 框架放行门槛

三个单修改器试点分别由独立的 GPT-6.1 Sol 任务负责，主代理集成公共接口。

| 试点 | 需要证明的能力 | 不接受的替代结果 |
| --- | --- | --- |
| `rig.scaffold` | 从捕获素材和作者几何直接生成层级、局部坐标及稳定对象身份 | 把宿主生成的结构模板包装成插件返回值 |
| `mouth.outline` | 从源像素生成图像、网格、关键形及资源关系，保存后仍可重建 | 仅迁移绘图函数，绑定继续从整套模板提取 |
| `physics` | 独立计算、声明真实读取、输出验证、包生命周期与缓存失效 | 只有协议模拟测试，没有安装包的实际求值 |

试点发现的公共缺口由主代理集中补齐；不要求每个插件发明自己的坐标、资源或提交系统。保留旧结果作等价对照，但新路径不得调用它来生成输入。无法等价时继续标记未完成，不用兼容回退掩盖新路径缺失。

正式放行前，用真实修改器验证几何／层级、生成图像、物理三类路径；独立运行不得依赖预生成模板。验证冲突、取消、资源缺失、版本缺失和缓存失效；提供无应用类路径示例、协议说明、脚手架和契约检查器。

六语言使用相同边界并实际安装求值：Python、Kotlin、Rust、C、C++、C#。Kotlin 外部包使用应用 JVM。安装不自动编译或执行脚本，进程隔离不是安全沙箱。

## 并行与集成

每种修改器分配独立的 GPT-6.1 Sol 任务。使用独立 Git 工作树和聊天按依赖分批并行，主聊天的子代理也各自只负责一种修改器。任务单明确类型与版本、输入依赖、输出 ID、文件范围、旧路径替换位置及等价用例。

子代理仅修改所属插件和测试；主代理负责公共契约、宿主、注册、构建和最终提交。契约缺口集中解决，禁止复制局部框架或覆盖其他代理修改。主代理检查整套模板可达性、资源完整性和结果等价，再做相关回归并提交。

每个任务单必须包含：唯一修改器类型、支持的算法版本、允许修改的文件、依赖输入、现有行为入口、稳定 ID 约束、必须删除的模板调用、相关验证及交接清单。独立工作树用单独提交交付，公共契约和包版本由主代理协调，构建与定向验证集中执行。主代理逐项审查并分批合并，不能把同一算法的多个计算类拆成多个完成数。

队列按依赖推进，每项由独立任务负责：

1. 基础绑定：身体、脸、眼、眉、嘴、头发各算法，以及绑定结构的版本兼容。
2. 依赖基础绑定的形变：眼部、眉部、嘴部和头部附加项，身体、衣物及配件项。
3. 依赖资源与运动的附加项：描边与表情图像、透出与裁剪、摆动、模拟、物理和动作；已经有包的项也按同一完成边界复审。

具备稳定输入契约的项目可并行开发。依赖尚未落实的项目可以先实现本项可独立验证的部分，集成前必须核对实际前置能力和版本，避免用临时模板替代前置项。

开发期间只跑相关验证，最终集中一次全量回归，核对正式入口和历史工程。按完整修改器或框架能力提交，不按零散计算类提交。

## 迁移账本

按类型共 49 种，版本变体不重复计数。“已有包”不代表已通过上述更严格的生成独立性验收。内核抽离不增加完整迁移数量。

形如 `mouth.outline@11` 的数字是该修改器锁定的算法版本。工程同时记录算法包的完整版本与内容标识，重开时按该身份加载。同一种修改器可有多个版本供不同前置组合使用，算法版本与应用版本、预设组无关。

公开 DS 的默认组已接入共享头部框架、眼眉插件、整套开口口型、表情及身体附件。普通工程的描边 v8 使用真实发束载体，已核对图像、网格和动态关键形。DS 通过工作台新建及冷重放的完整模型对照，此默认组求值没有调用旧整模模板。补入可见牙舌图层的 DS 工作台也已核对默认选版和完整模型。含舌时依次选择舌头 v6、下颌 v9、颊睑联动 v9、深度 v7 和弹性 v10。仅牙齿时使用深度 v6 和弹性 v9。丝带 v5、兽耳 v4 和尾巴／翅膀 v2 已在相应的共享前置组合中核对实际挂接、形变和物理。单眼整口开口带牙舌的合成组合已核对拟合嘴 v3 与描边 v7，其他单眼开口素材仍须覆盖。

当前应用随附 49 种修改器的可执行包。新建带预设的源工程优先使用独立的旧版身体 v2，选择旧版预设且满足条件时也使用旧版脸、旧版眼部和旧版眉 v2。默认现代预设在完整共享脚手架和未编辑的有脸源素材上成对选择拟合脸 v3 与拟合眼 v5，适用的笑眼、睁大、视线联动、眼部情绪和高光使用 v3，余震和虹膜挤压使用 v4。公开 TML 的默认组已验证可导入，调整后的完整 IR 和冷重放均与旧选版一致。双侧眼部素材上，适用的眉部链使用拟合眉、眉形和眨眼带眉 v3，眉睑联动 v5，眉弹动 v4。同侧眼白、睫毛和眉齐备且具备可用独立闭嘴图时，现代组使用独立单眼眉口链。该组合已验证逐阶段和完整 IR 等价，且没有请求旧模板。符合条件的现代组已独立求值腮红、阴郁表情、手臂摆动和裙摆。胸部回弹在已核对的开口与闭嘴组合使用 v3。丝带和兽形附件在共享闭嘴与裙摆前置下使用 v3。现代推荐组在双侧眼部和可拟合的整口闭嘴素材上选择整组独立口型算法。没有分层唇线，且描边有可用轮廓时才切换。在具备双侧眼部、整口素材和可用头部拟合的标准预设上，开口也选用独立口型链，按素材有无独立牙齿或舌头选择相应的深度和弹性。已核对无口腔组件、仅牙齿、带舌头三类素材的完整 IR。单眼开口和分层唇线仍有部分后续修改器使用兼容入口。其他缺少配对五官图层的组合也有兼容限制。
