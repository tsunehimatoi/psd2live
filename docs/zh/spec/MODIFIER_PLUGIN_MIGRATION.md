# 修改器插件迁移执行规范

本文规定下一阶段工作，不代表新契约已经实现。现有公开能力见 [插件指南](../guide/ALGORITHM_PLUGINS.md)。

## 完成边界

迁移单位是完整修改器，不是计算类。必须同时具备可安装包、完整资源、无产品层依赖、直接计算所属结果、稳定身份与版本锁定、完整贡献，以及相关效果等价和事务回归。

已有工作进程包不等于生成链路独立。宿主预生成绑定模板再交给插件，仍不通过验收。新实现不得调用 `RigBuilder`、`RigModifierSource.template`、`generated` 或改名后的整套生成回调。旧入口只作既有工程兼容，不作为新实现方式。

## 框架分层

- `algorithm-api` 为 MIT 中立契约，不引用产品、Umamo、工程、历史、UI；协议可跨语言表达。
- 共享算法库提供轮廓、特征测量、坐标变换、插值、参数定义和几何计算。使用 GPL 引擎的实现留在 GPL 模块。不能在共享服务中隐藏整套绑定生成。
- 插件读取捕获输入、配置和显式依赖，返回所属变更、资源、贡献和诊断；包内携带实际需要的模型数据。
- 宿主管理包、工作进程、调度、校验、缓存、覆盖、应用前缀、取消、CAS 和单历史节点提交，不替插件计算运动结果。

## 已落地的框架部分

JVM API 1.3 已提供 `ModifierModelChanges` 及直接变更入口，物理组算法已接入；宿主检查写入部分和对象前置状态。外部 JVM 工作进程已通过 `model_changes_v1` 返回稀疏变更载荷，物理包安装及重装求值通过。当前仍使用模型投影输入，贡献与依赖缓存保留旧流程，新载荷的六语言覆盖尚未完成。已增加 `source_layers/1` 栅格观察快照、源到模型画布的仿射变换及目标引用，眼部轮廓拟合已通过实际宿主路径读取该契约。进程内 `ReadingModifierAlgorithmPlugin` 已提供按对象读取、父级链查询及实际读取缓存，物理插件已接入。显式上游能力已包含目标、版本、配置、输出别名和已知包内容身份，支持上下文 v2 传输；应用前缀保留能力身份。`BindingCoordinates` 已提供按读取视图构建的父空间正逆变换和结构化重新挂接，复用现有求解算法。独立遮罩和跨进程读取跟踪仍待补齐，几何／资源实际修改器的完整集成仍需验证。此状态未达到下文的框架放行门槛，不开始批量迁移。

## 输入契约

作者快照具有修订号和稳定对象引用，不读取实时选择或工程。源素材声明语义、像素与遮罩资源、尺寸和坐标变换；网格声明位置、UV、拓扑及父坐标系。明确画布像素、父局部、归一化晶格空间。

二进制资源按内容哈希引用，声明格式、元素类型、尺寸与布局，验证长度、哈希、边界和解压限制。首次同步后只传缺少资源。进程内实现读取同一逻辑输入，不强制序列化往返。

共享分析按源资源、分析版本和分析选项寻址；运动强度变化不能无故使原始像素测量失效。上游通过实例和能力引用提供，不允许插件自行寻找当前活动实例。

## 输出契约

输出是有类型的新增、修改、删除、复用声明，覆盖参数及组织、层级、网格、变形器、关键形、关系、图像、物理、模拟绑定和动作。不能每项返回完整模型再全量比较。

已有对象的修改带预期输入标识；新增对象使用实例身份和局部名称导出 ID，宿主保留旧 ID 映射。组合编辑声明组合方式和坐标空间；整对象替换按独占写入处理，不默认可交换。

宿主检查实际写入范围、参数兼容、引用完整、层级无环、有限数值、网格与资源有效性；失败不发布部分结果。贡献明确新增、修改、复用对象，诊断使用稳定代码与对象引用，GUI/MCP 共用。覆盖在所属输出验证后合并，应用前缀保持后续引用与原有覆盖语义。

## 依赖、版本与缓存

包依赖、算法能力依赖、实例前置项分开表达。包使用完整版本范围及冲突列表，工程锁定实际包与依赖内容，禁止静默升级。前置能力由前序有效实例或固化内容提供，缺失时保留配置并暂停求值。

遵从栈顺序，非法移动说明冲突而不重排；只有读写关系证明无冲突的任务才并行，按确定顺序合并。未知关系串行且保守失效。

缓存包含包内容、算法版本、实例、配置、目标、实际读取资源、上游输出和覆盖。复用时验证读取集合；读取需求变化必须重新计算。取消过期候选，只提交最新有效结果。模拟只随真实输入变化重新烘焙。

## 框架放行门槛

大规模派发前，用真实修改器验证几何／层级、生成图像、物理三类路径；独立运行不得依赖预生成模板。验证冲突、取消、资源缺失、版本缺失和缓存失效；提供无应用类路径示例、协议说明、脚手架和契约检查器。

六语言使用相同边界并实际安装求值：Python、Kotlin、Rust、C、C++、C#。Kotlin 外部包使用应用 JVM。安装不自动编译或执行脚本，进程隔离不是安全沙箱。

## 并行与集成

框架放行后，每种修改器分配独立的 6.1 sol 子代理任务。当前容量包含主代理共四个，最多三项并行，按依赖分批。任务单明确类型与版本、输入依赖、输出 ID、文件范围、旧路径替换位置及等价用例。

子代理仅修改所属插件和测试；主代理负责公共契约、宿主、注册、构建和最终提交。契约缺口集中解决，禁止复制局部框架或覆盖其他代理修改。主代理检查整套模板可达性、资源完整性和结果等价，再做相关回归并提交。

开发期间只跑相关验证，最终集中一次全量回归和专用性能验收。按完整修改器或框架能力提交，不按零散计算类提交。

## 最终交付

固定汇报完整迁移数、仍依赖整套生成的数量、首次／重复生成与修改响应耗时、剩余问题。完整生成扣除同步模拟烘焙后目标不超过 4 秒，烘焙仍完整执行，不省略效果、不延后工作、不改变计时范围。

最终覆盖安装／卸载／重装、版本缺失与恢复、异常与取消、依赖和写入冲突、缓存和排序、现有预设效果、衣物模拟、覆盖和应用前缀、历史重放、保存重开、导出读回。同步四语言界面文案、中英文用户及 MCP 文档。缺少证据的项目保持未完成。
