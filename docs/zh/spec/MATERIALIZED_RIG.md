# 固化 Rig：以作者态 Rig 为权威数据的工程模型

[文档目录](../../README.md) · [文档层](DOCUMENT_LAYER.md) · [工程格式](PROJECT_FORMAT.md)

> 状态：阶段 0–5 均已实现，包括拆分与生成设置、分类的合并、“更新生成”与再生成试运行（见[实现进度](#10-实现进度)，其中列出与设计的差异）。本页给出目标模型、存储、操作分类、再生成合并规则与分阶段计划；已实现部分的事实以 [文档层](DOCUMENT_LAYER.md) 与 [工程格式](PROJECT_FORMAT.md) 为准。

## 1. 背景

### 1.1 现状

`PuppetModel` 不保存。每次打开、撤销、切换历史或提交编辑时：

1. `RigBuilder` 按**当前代码**和**当前设置**从源图生成基础 Rig（含骨架烘焙、v2 拆分部件的停放）；
2. `RigEditOverlay.applyTo` 在其上依次重放旧格式静态编辑与 `authoringJournal`；
3. 摆动、模拟写回、`skeleton.skin` 与生成结果覆盖按 `DocumentGenerators` 的图运行，再生成物理与动作。

日志条目按 ID 引用生成的变形器、参数与网格，部分条目（`vertex_group_put`、`canvas_geometry`、`set` 的顶点位移、路径、Glue 顶点对、拆分记录）还按**顶点下标**引用。条目只在写下它的那一刻、那一份基础 Rig 上才确定成立；之后基础 Rig 的结构一变，它就可能找不到目标，或静默作用到错误的对象上。

### 1.2 结构漂移的来源

| 来源 | 例子 |
| --- | --- |
| 生成设置 | 开启头发模拟删除 `DeformHair*Physics` 与 `ParamHair*`；启用骨架不再生成手臂下垂 Warp 与左右成对 Warp；`runtimeTarget` 让骨骼与模拟参数在关键形轴与混合形之间切换 |
| 骨架 | 绑定网格改挂到骨骼旋转、插入关节行（顶点数变化）、折叠无网格的链接骨骼 |
| 拆分与源图 | 部件取代原网格；新部件参与框架生成，改变其他对象的框架 |
| 生成代码本身 | 任何生成规则、默认网格、ID 派生的修改都会改变旧工程的基础 Rig |

### 1.3 为保住重放已付出的代价

现有保护机制，每一项都只覆盖一部分情形：

- 冻结生成输入：`generationSource`、`meshSource`、`mesh_generation_baseline`（网格设置）；
- 生成迁移：`RigGenerationMigration` 在设置/分类变化时把迁移写成日志记录 `rig_generation_transition`（内含整份生成 Rig 的 JSON），保留退役对象；
- 父级不再生成：`VanishedParent`、`ArtPrimitiveJournal.rehome`、结构编辑 `bind`/`move` 的跳过；
- 拆分：v1/v2 两套 `art_primitive` 记录，v2 的乘客、停放（`PrimitiveSkins`）、两遍捕获、乘客容错（`StubTolerance` / `SupersededEntryNote`）、骨架烘焙前解码部件（`skinnable`）；
- 骨架：`SkeletonCanvasSkin.lockedTopology`、`handEditedTopology` 拓扑锁、日志安放网格的事后蒙皮；
- 性能：`ReplayCheckpoints`、`GeneratorReuse`、阶段缓存与头部缓存，都是为了让每次重放足够快。

近期同类修复（2026-10-07 至 10-08）：`7f30f7aa`（头发模拟删 Warp 后 v2 部件父级缺失）、`2d6d0b7d`（启用骨架后手臂下垂 Warp 消失）、`36d6fbb5`（日志改变骨架烘焙读取的内容时不能在缓存基础上续放）、`5019b69b`（骨骼绑定网格被日志改挂）、`29099a3a`（部件在骨架烘焙之后才出现）、`220c7d5a`（预设重建基础时部件被当普通图层生成）、`ea226c07`（v1 部件不在上一次生成中）、`a08df353`（v2 部件的父级链编辑被应用两次）、`3c36db5a`（生成输入冻结前加入的图层被静默重新生成）。

### 1.4 尚未覆盖的缺口

按“生成设置改变结构、而日志已有引用”排查的结果：

| 触发 | 失效的条目 | 现有保护 |
| --- | --- | --- |
| 头发模拟开关 | 以 `ParamHair*` 为键或以 `DeformHair*Physics` 为目标的 `set`、`canvas_geometry`、重命名、面板编辑、其下新建的 Warp 报错；该 Warp 上的 `set` 静默跳过 | 仅 `bind`/`move` 与拆分部件改挂；`RigGenerationMigration.settingsChanged` 不含这两个开关 |
| 恢复经典摆动、删除模拟 | 以模拟输出参数为键的条目报错 | 无 |
| 启用骨架、增删骨骼 | 消失的成对 Warp 与骨骼上的条目报错；关节行使 `vertex_group_put`、`set` 位移、`canvas_geometry`、`path_put` 顶点数不符；Warp 下记录的归一化位移换到骨骼空间后静默错位 | 拓扑锁只看 `canvas_topology` 与日志安放的网格；带顶点组的普通绑定网格不锁 |
| `runtimeTarget` | `set` 静默改走混合形路径；混合形参数上的 Glue 关键形报错 | 无 |

除上述容错路径外，任何一条重放失败都使整次重建失败，错误只有一条消息：提交被拒绝，打开工程或切换历史时得不到模型。

### 1.5 与原设计的差距

工程格式的原设计要求“文档层只保存声明式的状态，打开工程时不再靠重放命令重建模型；命令历史保留，只用于撤销和分支”，v1 迁移时“用当前版本重放一次，把结果固化保存”。已落地的部分：内容哈希、生成器依赖图、生成缓存、三方合并、按内容寻址的 v2 归档；覆盖与三方合并只接入了摆动、模拟与 `skeleton.skin`。本文立项时未落地的是核心一步：v2 节点保存的仍是“源图 + 设置 + 日志”，基础 Rig 每次按当前代码重新生成。这一步现已按本文实现（[实现进度](#10-实现进度)）。

## 2. 目标与非目标

**目标**

- 打开、撤销与切换历史直接从修订保存的固化 Rig 得到模型；生成代码或生成设置的变化不影响已保存修订的打开。
- 编辑命令在提交时对当前模型执行一次，结果随修订保存；命令只需在执行时的模型上成立。
- 改变生成输入是一次显式的再生成事务：重新生成后把用户的修改合并上去，合并不了的情况作为结构化问题报告，在提交前可预览，而不是在打开时崩溃。
- 生成器的改进不再自动改写旧工程；由用户发起“更新生成”。

**非目标**

- 不取消命令：GUI 与 MCP 仍共用同一套 JSON 命令与原子批量，提交边界（候选 → CAS → 一个历史节点）不变。
- 不把所有编辑改写成“生成结果 + 覆盖”：只有每次求值都会重跑的修改器（摆动、模拟写回、`skeleton.skin`）才使用覆盖。
- 不保存预览运行包、纹理集页面或物理、动作的生成结果。

## 3. 模型

```
文档输入 ──(再生成事务)──▶ G 生成快照 ──┐
                                          ├─ 三方合并 ─▶ M 固化 Rig ──▶ 修改器 ──▶ 预览 / 导出
编辑命令 ─────────────(直接作用)────────────────────────┘
```

| 对象 | 内容 | 现在的对应物 |
| --- | --- | --- |
| **M 固化 Rig** | 作者态 Rig：基础生成（含骨架烘焙）加上全部编辑，摆动、模拟写回与覆盖合并之前。纹理坐标为画布单位（未绑定纹理集） | `RigEditOverlay.authored(BuiltRig)` 的结果 |
| **G 生成快照** | 上一次再生成时生成器的输出，未经编辑；只作再生成合并的公共祖先 | `BuiltRig.resolvedPuppet()`（去乘客、放入部件）的未绑定形式 |
| **生成元数据** | 网格 → 源图层映射、部件槽与中性边界、面部中心与半径、生成器版本、生成输入摘要 | `BuiltRig` 中 `puppet` 以外的字段 |
| **修改器** | `skeleton.skin`、摆动、模拟写回、生成结果覆盖合并、物理组、生成动作 | `DocumentGenerators` 中日志之后的节点 |

- **打开**：读取 M 与元数据 → 分析源图（分类，供界面与预设使用）→ 打包并绑定纹理集 → 运行修改器 → 编译预览。
- **G 只在再生成时读取**，打开时不解码。

## 4. 操作分类

| 类别 | 操作 | 处理 |
| --- | --- | --- |
| A 直接编辑 | `canvas_geometry`、`canvas_topology`、`canvas_create_warp/rotation`、Glue 的创建与编辑、`path_put/delete`、`vertex_group_put/delete`、关键形 `set/copy/delete`、`parameter_keys`、`structure`（含参数增删改、绑定、移动、重命名）、`warp`、`canvas_mesh_create`、网格显隐与材质 | 命令按现有 `apply` 语义（严格，不跳过缺失目标）作用于 M；G 不变 |
| B 再生成事务 | 网格设置、嘴型等生成设置、头身强度与 `rigTuning`、分类与父级覆盖、图层增删与恢复、拆分、需要重建网格的绘画与换图、画布矩形移动、骨架定义、头发模拟开关、`runtimeTarget`、更新生成器版本 | 重新生成 G′，按第 5 节合并出 M′，得到 (G′, M′) |
| C 修改器设置 | 摆动、模拟（含烘焙结果）、物理组与顺序、帧率、生成动作与片段 | 只改文档中的修改器设置；M、G 不变 |
| D 绑定与导出 | 纹理密度、预算、固定位置、图集排布，不重建网格的绘画与换图，导出设置 | 只影响纹理集绑定或导出；M、G 不变 |

- A 类的候选为“在 M 上执行命令 + 运行修改器”；画布拖拽预览同样在 M 上套用待提交命令。
- B 类在锁外计算，报告进度并检查原协程取消，提交规则与现有重建型提交相同。
- 历史节点保存所执行的命令，用于显示、审计与 MCP，不再用于重建。

### 4.1 记录层与作用层

A 类命令在用户看到的完成态 Rig（M 加修改器）上记录，作用于 M（修改器之前）。修改器添加的参数与轴（模拟模式参数、摆动参数、它们在目标上的关键形轴）在 M 中不存在，因此写入日志前命令按 M 规范化：

- 关键形坐标中修改器添加的轴（目标在完成态有而在 M 中没有该轴）取默认值时去掉，命令落在修改器据以生成的静止格上；不在默认值的修改器格由生成结果覆盖记录（`generated_override`）在修改器之后作用。
- 观察姿态只保留目标几何实际读取的参数（目标自身的关键形轴、混合形参数及其限制参数，以及关键形坐标中的参数），且只保留不在默认值的。几何编辑作用于目标在父级局部空间中的关键形，与 Cubism 相同：只要求目标自身的参数在键上（编辑前吸附到最近的键），父级参数可以停在任何值。只经父级带动目标的修改器参数（例如挂在上层 Warp 上的摆动）因此不进入记录，无论它当时取什么值（`RigGeometryTools.referencePose`，编译时对 `canvas_geometry` 与 Bezier 记录统一施加）。
- **修改器参数的收养**：命令引用修改器的参数（在其他对象上打键、通道关键形、改名、改范围）时，在它之前写一条按修改器当前定义创建该参数的 `structure` 记录（`GeneratedParameterAdoption`）。此后参数属于文档：日志可以引用它，修改器沿用已存在的参数（与对待任何已有参数相同），删除修改器后参数和用户在上面的关键形保留。这与 Cubism 中物理输出参数就是普通参数一致。修改器自己的参数只能随修改器删除；收养后的参数可以删除，修改器会按自己的定义重新创建。
- **修改器拥有的关键形**：Bezier 编辑与关键形 `set`（含 MCP `rig_deform`）写入修改器格时改写为生成结果覆盖；保留子级位置的编辑、复制到或复制自修改器格、在修改器轴上增删键无法作为覆盖表达，在记录时拒绝并指明应修改的修改器（`GeneratedOverrides.ownedWrites`）。
- Glue 与 Cubism 相同在静止形（默认姿态）上配对：编译时去掉记录中的姿态，焊接只依赖两网格的静止几何，与修改器无关；画布在胶合前把参数移回默认值。较早写下的带姿态的记录按原姿态重放。
- 判断依据是两个 Rig 本身：修改器参数是完成态有而 M 没有的参数，修改器轴是目标在完成态有而在 M 中没有的轴；关键形的拥有者取自修改器图。上述规范化集中在 `JournalRecording.record`，所有写入日志的编辑都经过它。
- 会话中的候选在 M 上执行新增命令再运行修改器，与打开时的构建是同一路径；无法作用于 M 的命令在编辑时即失败，不会写入工程后到再次打开才报错。

## 5. 再生成合并

输入：公共祖先 G、新生成 G′、当前 M。输出：M′ 与问题列表。对象按稳定 ID 对齐（参数、部件、变形器、网格、带 ID 的 Glue、路径；顶点组按“网格 + 名称”；无 ID 的 Glue 按网格对）。判断“用户改过”一律按 M 与 G 的位相等，M 与 G 都是保存值，没有重新计算带来的浮点误差。

| 情形 | 规则 | 报告 |
| --- | --- | --- |
| 只在 M 中（用户创建） | 保留。父级的内容由生成器交给了另一个变形器（[接替](#113-接替)）时随之改挂；否则父级在 M′ 中不存在时，沿它在 G 中的祖先链找到 G′ 仍有的最近祖先改挂。默认姿态下的画布位置不变，关键形位移按父级空间的线性部分换算 | `followed` / `rehomed` |
| G 有、G′ 无 | M 中该对象与 G 相同：删除；不同：保留为退役对象 | `retired_kept` |
| G 有、M 无（用户删除） | 保持删除，即使 G′ 仍生成它 | — |
| G′ 新增 | 加入 | — |
| 三者都有：字段 | 逐字段三方合并：用户未改的跟随 G′，生成未变的保留用户值，两边都改时保留用户值 | `conflict` |
| 三者都有：父级 | 用户未改父级而 G′ 改了：跟随 G′，按画布位置不变换算局部坐标与关键形。用户改挂到的父级被接替时随之改挂 | `reparented` / `followed` |
| 三者都有：关键形 | 轴取并集；逐格、逐顶点（或控制点）三方合并 | `conflict` |
| 拓扑不同（G 与 G′） | 用户差值 M − G 经画布纹理坐标迁移（`RasterMeshJournal.prepare` 的顶点来源）到 G′ 的拓扑上再加回；顶点组、路径、Glue 顶点对随同一迁移计划移动（沿用 `MaterializedMeshRebuild`） | `topology_migrated` |
| 用户改过拓扑（M 与 G 拓扑不同） | 保留用户拓扑；G′ 相对 G 的生成变化经画布纹理坐标映射到用户顶点：取 G′ 的父级，静止位置为 M 显示的位置加上 G′ 相对 G 在画布上的移动，关键形与混合形为 G′ 的（采样到用户顶点）加上用户相对 G 的差值（换到新父级）。网格无法匹配或新父级容纳不了时整份保留 M | `topology_followed` / `topology_kept` |
| 参数被 G′ 删除而 M 中有引用 | 保留参数为退役参数及其上的用户关键形 | `retired_kept` |

- 问题以结构化记录报告（`RigRegeneration.Issue`：类型、对象、说明），等级只由 `core/quality/RegenerationRule` 决定：冲突、保留用户拓扑与丢弃对象为 warning，改挂、随接替改挂、保留退役对象、改父级、拓扑迁移与用户拓扑跟随生成为 info。合并在写固化点时已经完成，报告是观察性的（`RegenerationQuality`，`can_proceed` 恒为 true），不阻断提交；最后一个固化点的问题进入 `workspace_inspect` 的 `quality.regeneration`。
- B 类操作的试运行：`workspace_preview_regeneration`（MCP）与“工具 → 预览生成结果更新”（GUI）返回将写入的固化点及其合并问题，不提交。
- 设计拟复用 `format-compile` 的 `ThreeWayMerge`（MIT）；实现的合并引擎 `RigRegeneration` 在产品层按中立 IR 内容比较，`ThreeWayMerge` 只用于生成结果覆盖（`GeneratedOverrides`）。

### 5.1 用此模型重述现有特例

- **拆分**：源图改变（原图层由部件取代）的 B 类事务。部件继承原网格的用户差值（M − G，经分区的顶点来源）；G′ 中部件是普通图层的生成结果。v2 两遍捕获的目的（部件参与生成、记录只存生成之外的作者数据）在一次合并中达成，乘客、停放与拆分记录的重放机制随之退出日常路径。
- **骨架**：骨架烘焙属于生成器，输出进入 G。改骨骼是 B 类事务（沿用按肢体重烘焙）；关节行是拓扑迁移，用户在绑定网格上的修改按合并规则带过去，不再需要拓扑锁与烘焙前解码部件。用户把绑定网格改挂到非骨骼变形器时，仍由修改器 `skeleton.skin` 蒙皮。
- **头发模拟、手臂下垂 Warp 消失**：G′ 中变形器消失，其下的用户对象按“只在 M 中”改挂，对应 `VanishedParent` 的通用形式。
- **生成迁移**：`rig_generation_transition` 把迁移写进日志并在每次重放时执行；改为一次性合并后，迁移结果直接是 M′。

## 6. 存储

设计稿称之为“工程格式 v3”；实际落地仍是 v2 归档，含固化点的修订升为修订 schema 3，Rig 对象按内容寻址保存在 `rig/objects/<sha256>.bin`（不分类型目录），修订的作者态 Rig 索引在可选的 `rig/revisions/`（见第 10 节与[工程格式 · 固化点](PROJECT_FORMAT.md#固化点)）。下表为原设计：

| 路径 | 内容 |
| --- | --- |
| `rig/objects/<类型>/<sha256>.bin` | 单个对象的持久编码：参数列表与参数树、部件树、每个变形器、每个网格（网格、关键形、通道、混合形）、Glue、路径、顶点组、画布与元数据 |
| `history/revisions/<key>.json` | 新增 `rig: {materialized: {...}, generated: {...}, meta}`，列出 M 与 G 的对象哈希；不同修订、M 与 G 之间按内容共享对象 |

- **编码**：基于中立 IR（`format-model`，MIT）定义带 schema 版本的持久编码，配向前迁移与语料回归测试。`RigIrBinary` 是缓存格式，只接受自身版本，不作持久格式；浮点同样按原始位保存。
- **纹理**：M、G 保存画布单位纹理坐标，打开时按纹理集绑定（沿用 `UvBinding` 的换算），纹理集仍由文档决定。
- **体积**（tml，单个整 Rig，`RigIrBinary`）：

| | 原始 | deflate | 解码为 `PuppetModel` |
| --- | ---: | ---: | ---: |
| 无骨架 | 约 336 KB | 约 174 KB | 约 3.5 ms |
| 自动骨架 | 约 7.1 MB | 约 5.6 MB | 约 26 ms |

  骨架 Rig 的体积主要是骨骼参数上的网格关键形，浮点压缩率低。按对象寻址后，A 类编辑只写被改的对象；重烘焙骨骼会重写所在肢体的绑定网格。
- 日志节点照常保存，作为命令记录。

## 7. 兼容与迁移

- **打开 v2 工程**：头部修订用现有重放管线（冻结为旧版重放路径）重放一次，得到 M 与 G 并在下次保存时写出；重放失败时以修复状态打开，列出失败条目，允许切换到更早的修订。
- **其他修订**：在首次切换到它时按同一路径固化；未固化的修订保留 v2 文档节点。
- **旧版重放路径**：v1/v2 拆分记录、旧格式静态字段、生成迁移记录、`VanishedParent` 与乘客容错移入单独的包，只做修复，不再随新功能扩展；用已保存的工程（`legacy-split.psd2live`、`v1-sample.psd2live`）按 IR 哈希锁定。它仍调用当前的生成代码，所以旧修订的固化结果可能随生成代码变化，但每个修订只固化一次。
- **缺少 G 的修订**（固化前的旧修订、导入后首次再生成）：以当前代码对保存的生成输入重新生成作为 G。生成代码的差异因此被视为用户修改而保留，不会丢失数据。
- **导入的 CMO3 模型**：G 为导入基线，不参与再生成。

## 8. 分阶段计划

每阶段按功能验收链路验收：领域数据 → 历史 → 保存恢复 → 目标版本 → 导出读回 → 视觉检查（见[运行时与导出边界](RUNTIME_EXPORT_ARCHITECTURE_AND_GAPS.md)）。

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 0 止血（独立） | 头发模拟删除旧摆动 Warp 时拆分部件随基础网格改挂；骨架拓扑锁计入按细分前顶点数写下逐顶点记录的绑定网格 | 已有工程在两种开关下可重建；对应回归测试 |
| 1 影子固化 | 保存时在可删除的缓存目录写出 M、G 对象；打开仍重放。开发工具对比重放结果与保存的 M，收集不一致语料；测量体积与耗时 | 旧程序照常打开；`ExportGoldenTool` 逐字节一致 |
| 2 以固化结果打开 | M 成为打开与切换历史的权威数据，修订索引升级 schema；编辑仍经现有重建管线得到候选，再写出 M | 打开路径不经过 `RigBuilder`；生成代码改动不影响已固化修订；v2 工程迁移测试 |
| 3 直接编辑 | A 类命令直接作用于 M；提交只在 M 上执行命令，与基础重建和重放检查点无关 | A 类提交耗时与日志长度无关；GUI 与 MCP 行为一致 |
| 4 再生成合并 | 实现第 5 节合并与问题报告；B 类操作逐项迁入（设置与分类 → 头发模拟 → 骨架 → 拆分 → 网格重建）；增加“更新生成”与试运行 | 第 1.4 节每一行都有合并测试；新编辑不再写 `rig_generation_transition` 与 `art_primitive` |
| 5 清理 | 重放检查点、乘客与停放、骨架前解码部件、生成迁移记录仅留在旧版重放路径；文档改写 | 热路径不再引用旧版重放包 |

### 8.1 测试

- 固化一致性：对测试语料，以固化结果打开与经重放重建得到相同的 IR 哈希。
- 合并：在手写小 Rig 上覆盖第 5 节每条规则（变形器消失、参数删除但有用户关键形、关节行插入、用户拓扑与生成拓扑同时变化、用户删除的生成对象、用户创建的 Warp 父级消失）。
- 格式：修订 schema 3 拆分与拼回无损、对象共享、schema 迁移、旧程序拒绝打开更高 schema 而不丢字段。
- 在示例 PSD 上跑整条流水线的对比做成开发工具，不进全量测试。

## 9. 风险与待定

- **体积**：骨架频繁调整的长历史会积累多份绑定网格，需要实测；可选措施是只为分支末端与头部保留 G，其余修订缺 G 时按第 7 节回退。
- **生成改进不再自动生效**：需要在界面上提示工程使用的生成器版本，并提供“更新生成”入口与试运行报告。这是产品层面的取舍。
- **分类仍随代码变化**：打开时分析源图的结果只影响界面与预设，不影响 M；预设在执行时读取当前分析，属于 B 或 C 类操作。
- **内存**：每个历史节点的 M 用软引用缓存，未命中时从存储解码（骨架 Rig 约 26 ms）。
- **MCP**：公开命令不变；新增再生成试运行与 `workspace_inspect` 中的合并问题，需声明严格的 `resultSchema` / `jobResultSchema`。
- **已定**：`generationSource` 冻结在固化后保留。不发生再生成的编辑（绘画、换图）不改变生成结果；再生成（拆分、预设切换、骨架、“更新生成结果”）以冻结像素生成 G′，冻结之后新增的图层取当前像素，因此绘画不会在下一次无关的再生成里被当作生成器的变化；唯一的例外是改变生成规则本身（生成设置与分类），它按当前像素生成 G′、网格输入照用保存的（`RigGenerationChange`）。绘制顺序覆盖与父级覆盖都是生成输入，归 B 类：基础生成读取它们，生成的模型改动它们时按再生成合并并写固化点（`WorkspacePreviewBuilder.normalizeMeshEdits`；测试 `paintingNeverReachesTheGenerationAndAnUpdateFindsNothingToDo`、`parentAndDrawOrderOverridesRegenerate`）。

## 10. 实现进度

**阶段 0（已实现）**

- 骨骼绑定的网格，若日志中按顶点下标的记录全部按细分前的顶点数写下，骨架不再为它插入关节行（`SkeletonCanvasSkin.lockedTopology`），见[文档层 · 日志安放的网格](DOCUMENT_LAYER.md#日志安放的网格)。
- 头发模拟删除旧摆动 Warp 时，v2 拆分部件与基础网格一起改挂到跟随 Warp（`RigBuilder`）。没有采用“保留静止 Warp”：那会改变已烘焙头发模拟所在的父级空间。

**阶段 1–2（核心已实现）**

- 重放拆成两段（`RigEditOverlay.replayAuthored` / `finish`）：`BuiltRig.authoredRig` 给出作者态 Rig（`AuthoredRig`：作者态 puppet、日志创建网格的映射、需应用图层显隐的网格），`AuthoredRig.finished` 运行修改器、覆盖合并、延后面板编辑、显隐与绘制顺序。`withRigEdits` 即两段相接，导出与此前逐字节一致（`ExportGoldenTool`）。
- `RigPreviewModel` 的基础 Rig 与作者态 Rig 由 `PreviewRigSources` 提供：生成构建已知基础 Rig，作者态在首次使用时由重放检查点给出；由作者态构建的模型只在有人读取 `baseRig` 时才生成基础 Rig。
- `PSD2LivePipeline.materializedPreview`：由作者态 Rig 构建预览，只做源图分析与纹理集打包，不运行 `RigBuilder`、骨架烘焙与日志重放；纹理集绑定键不同时返回空，由调用方照常构建。延迟删除（软删除图层）的文档同样支持；导入 CMO3 的模型不支持。
- 按修订的存储（`project/MaterializedRigStore`）：本进程构建过的修订（软引用）与打开归档读到的修订。`WorkspacePreviewBuilder.build` 先查存储（打开、切换历史、撤销），除非当前模型能更便宜地更新（见阶段 3，或基础 Rig 已在手、只是编辑覆盖层）；保存把可得的修订写入归档 `rig/`（格式见[工程格式 · 作者态 Rig](PROJECT_FORMAT.md#作者态-rig)）。
- 持久编码：`RigIrObjects`（MIT）把中立 IR 拆为框架、变形器与网格对象，按版本可读；`MaterializedRigCodec` 写头部。

**阶段 3（追加编辑已实现）**

- 新文档的作者态阶段输入与当前模型相同、只在日志末尾追加了条目（`RigEditOverlay.extends`，追加的不是 `art_primitive` 记录）时，`PSD2LivePipeline.updateRigEdits` 把追加的条目按重放语义作用于当前作者态 Rig（`appendedTo`），再运行收尾阶段；不读取基础 Rig，也不重放此前的条目。结果的基础 Rig 沿用当前模型的（仍按需生成）。
- 提交路径上不再无谓地生成基础 Rig：生成结果覆盖的捕获只在日志有 `art_primitive` 记录时才读取基础 Rig 的拆分部件（`RigPreviewModel.primitiveSkins`）。
- 由作者态 Rig 打开的工程，画布与 MCP 的几何、关键形、结构、顶点组、路径等编辑因此不触发生成；改变生成输入与拆分仍经基础 Rig（合并需要 G 与 G′）。

**阶段 3（已实现）**

- 生成的模型的第一次编辑在原日志末尾、新条目之前写入当前作者态 Rig 的固化点，之后最后一个固化点后满 32 条（`RigEditOverlay.CHECKPOINT_INTERVAL`）的编辑再写一个；生成快照沿用上一个固化点的，没有时取基础 Rig。任何构建因此最多重放 32 条与本次编辑的条目。
- 改写较早条目的编辑（拖动合并、生成结果覆盖的捕获、撤销与重做）由已保存的修订或固化点之后的条目得到作者态（`RigPreviewModel.authoredWithoutBase`、`PSD2LivePipeline.updateRigEdits`），不生成基础 Rig，也不经重放检查点。
- 模拟烘焙、重新烘焙与对比读取作者态 Rig 经收尾阶段的结果（`SimAuthoring.AuthoredRigs`），不生成基础 Rig。
- 实测（tml 样例，经运行时连续 40 次结构编辑）：第一次编辑约 190 ms（含写固化点），之后每次约 20–40 ms，第 33 条处的固化约 50 ms；冷构建约 170 ms，不生成基础 Rig。

**阶段 4（已实现）**

- 合并引擎 `RigRegeneration.merge(G, G′, M)` 按第 5 节合并：对象按 ID 对齐，“改过”按中立 IR 的内容判定；几何残差经 `PrimitiveResidual`（v2 拆分的残差工具）换到新父级空间并按画布纹理坐标迁移到新顶点；顶点组、路径、Glue 顶点对随之迁移；消失的生成变形器在默认姿态收拢后展开（umamo `withDeformerDeleted`），其下的用户对象上移；问题按类型报告。G 与 G′ 取 `BuiltRig.resolvedPuppet`（v2 部件就位），因此基础生成为部件做的改挂与蒙皮也作为生成结果参与合并。v1 部件只由记录创建，任一侧骨架蒙皮了它时，该记录在 G 与 G′ 上各按日志方式重放（G′ 用新基础的 `PrimitiveSkins`），骨架给它的蒙皮与焊接 Glue 同样作为生成结果合并；任一侧重放失败则两侧都不放，部件仍按用户对象保留。生成迁移（`rig_generation_frames`）把网格挂到生成变形器的改名副本（`GenerationFrame<n>_…`）下之后，G 与 G′ 按最后一条迁移记录的 `frames` 改名再合并（`RigGenerationFrames.named`），否则每个网格都会被当作用户改过父级；固化点保存的生成结果仍是生成器原样输出。混合形按参数三方合并，且必须与合并后几何处于同一父级空间与拓扑：几何取 G′ 时用户的形状经残差的父级空间换算带过去，几何保留 M 时在另一父级空间生成的形状不采用（报告 `dropped`，用户的同名形状保留）。
- 固化点：日志记录 `rig_checkpoint` 保存合并后的作者态 Rig（对象按内容寻址，随文档持久化）与合并问题；重放从最后一个固化点开始，其前的条目只作历史；纹理集变化时固化的 Rig 按画布纹理坐标重新绑定。见[文档层 · 固化点](DOCUMENT_LAYER.md#固化点)与[工程格式 · 固化点](PROJECT_FORMAT.md#固化点)。
- 触发：编辑延续当前日志、且新文档的基础生成结果（按旧条目所见）与当前不同，就合并并在边界写固化点——不论旧条目能否在新结果上重放。头发模拟预设在内部同样如此。
- 运行时把重建插入的固化点并入提交；批量成员由前一个候选构建。最后一个固化点的问题进入 `workspace_inspect` 的 `quality.regeneration`。
- 格式：含固化点的修订为修订 schema 3，索引列出其 Rig 对象，归档保存在 `rig/objects/`；旧程序拒绝打开这类工程。
- 生成的模型启用骨架后不再在日志中重采样顶点组，由合并迁移。
- 生成设置与分类：生成的模型在准备编辑时合并并写固化点，G′ 由当前源图生成；不再写 `rig_generation_transition`、`rig_generation_frames` 与随迁移创建的网格记录。`rig_generation_baseline` 只在其后没有固化点时约束基础生成。
- 拆分（第 5.1 节）：G 与 M 中的原网格由拆分自身切成同样的部件，与部件代替原图层后的 G′ 合并；`art_primitive` 记录（生成的原网格为只作声明的版本 2，日志创建的原网格为版本 1）之后紧随固化点，记录不重放。两遍捕获、守卫、版本 1 回退、`psd2live.artPrimitiveV2` 开关与显式升级命令已删除。
- 试运行：`workspace_preview_regeneration`（只读后台任务）对 1–128 项文档操作做与提交相同的候选准备与重建，报告将写入的固化点（`regeneration` 带合并问题，`materialized` 为新条目前固化的作者态）与增删的对象，不发布状态、历史或资源；同一 state 上提交相同操作得到相同的候选修订。
- 固化点同时保存它所基于的生成快照 G′（与作者态共享未变对象）。“更新生成”（`rig_update_generation`，GUI“工具 → 更新生成结果”）以最后一个固化点的生成快照为 G、本程序现在为同样输入生成的结果为 G′、当前作者态为 M 合并，在日志末尾写新的固化点；生成结果相同时不提交。
- 实测（一个带 v2 拆分与预设顶点组的用户工程）：合并与完整生成并重放的结果在默认、头部转动、身体转动姿态下逐点一致（开启后发模拟、启用自动骨架两种情形，差值 0），合并 10–15 ms。经运行时依次应用后发预设与自动骨架：各写一个固化点，拆分部件改挂到跟随 Warp，无合并问题；保存约 7.2 MB（原 6.3 MB），冷打开并构建头部约 0.6 s，结果逐位一致，不生成基础 Rig。

**与设计的差异**

- 生成输入变化触发的再生成以当前程序为当前文档重新生成 G（而不是取固化点保存的 G）：程序变化带来的差异因此被视为用户修改而保留，新版本生成器的改进只经“更新生成”进入工程。
- 修订的作者态 Rig 索引（`rig/revisions/`）是可选数据（缺失时照常构建），但有则作为该修订的数据使用：纹理集绑定键不同时重新绑定而不退回重放，因此本版本保存的工程打开时不依赖重放。权威数据是日志中的固化点。没有固化点的文档（旧工程，或尚未发生生成变化的新工程）仍由生成与整条日志重放构建，旧版重放机制（`VanishedParent`、乘客容错、v1/v2 拆分记录等）因此保留。
- 拆分改变了部件参与的框架，每次拆分都会写一个固化点。

**阶段 5（已实现）**

- 新编辑不再写需要基础 Rig 才能重放的记录（拆分记录之后总有固化点，生成迁移改为合并）。日志在最后一个固化点之后仍有较早版本写下的这类记录时，延续它的第一次编辑先把当前作者态 Rig 固化在原日志末尾，这些记录只重放这一次（`RigEditOverlay.replaysLegacy`）。
- 只在旧版重放与导入 CMO3 模型上使用的代码移入 `core.legacy`（拆分记录重放、乘客容错、父级不再生成、生成迁移的写入与重放、重放检查点），见[文档层 · 旧版重放](DOCUMENT_LAYER.md#旧版重放)。导入模型没有生成结果可合并，仍写迁移记录与旧分区，但写下它们的提交立即在其后写入固化点：这些记录只在自己那次构建中重放一次。

- 导入 CMO3 的模型同样在第一次编辑与每 32 条时写固化点（不带生成快照：G 是导入基线，不再生成），构建在导入基线上从固化点开始重放，重放量同样有界；它们不由作者态 Rig 单独构建（纹理坐标按导入的纹理页寻址，没有绑定键），生成设置变化仍写迁移记录（第 7 节）；拆分、深度拆分与迁移等要在导入基线上重放的记录，由写下它们的提交在其后紧接着写入固化点（`WorkspacePreviewBuilder.importedRecordsCheckpointed`），之后的构建、打开与撤销都不再重放它们（`ImportedSplitCheckpointTest`）。
- GUI：“工具 → 预览生成结果更新”以同一试运行报告更新是否会改变 Rig 以及需要查看的项目，不提交；结果与“更新生成结果”的结果一样写入日志面板（编辑时状态栏被画布提示占用）。桌面程序实测（Xvfb、软件渲染，tml 导入后经 MCP 编辑）：第一次编辑写入带生成快照的固化点约 0.3 s，两项菜单随之可用，预览报告“生成结果没有变化”，`workspace_preview_regeneration` 对头身强度修改报告一个 `regeneration` 固化点且工程状态不变。

**实测**（含 6 个修订的一个用户工程，无骨架）：头部修订由生成与重放构建约 2.2 s，由保存的作者态 Rig 冷打开并构建约 0.4 s，IR 哈希一致；归档增加约 0.3 MB。

## 11. 结构接替与合并忠实性

### 11.1 问题

再生成改变结构（父级、拓扑、插入或删除变形器）而用户数据以旧结构表达，是一类反复出现的问题（`2d6d0b7d`、`5019b69b`、`18f24b89`、`9eff1d60`、`e72fc541`、`da426e1f`、`7f30f7aa` 等）。在固化点模型下，它有三个共同成因：

1. **合并按差异推断意图，错误会自我固化**：“用户改过”由 M 与 G 的位比较判定。一次合并若没能把生成器的结构变化带到对象上（M′ ≠ G′ 但用户没改过），下一次合并就把这个差异当成用户修改保留，再也不会跟随生成器。实例：用户重建过拓扑的袖子在启用骨架时按“保留用户拓扑”留在已不生成的 `DeformArmHang_L/R` 下，被收拢到呼吸 Warp，丢掉了骨骼蒙皮；此后每次合并都报告“用户改挂了它”。
2. **生成器知道对象去了哪里，合并只能猜**：骨架的躯干 Warp 接管呼吸 Warp 上的全部内容，启用骨架时骨骼接替手臂下垂 Warp，但这些关系不随生成结果输出，合并只能用沿祖先链就近改挂（`VanishedParent`、`rehomed`）之类的启发式。实例：导入后绑到呼吸 Warp 的图片不进入躯干 Warp，不随上身转动。
3. **设计与实现的缺口是静默的**：第 5 节规定用户改过拓扑时“G′ 相对 G 的生成变化经迁移计划映射到用户拓扑”，实现只整份保留 M，问题以 warning 记入不显示的报告。

### 11.2 方案

按四层处理，前一层的失效由后一层兜底或发现：

| 层 | 内容 | 解决 |
| --- | --- | --- |
| 骨骼作用按状态判定 | `skeleton.skin` 蒙皮的网格除日志记录安放的（`placedByRecords`）外，还包括最后一个固化点的作者态 Rig 中不受其肢体任何骨骼带动的绑定网格（`SkeletonCanvasSkin.unskinned`：父级链上没有该肢体的骨骼变形器，网格也没有该肢体参数上的关键形轴或混合形）。烘焙仍只按记录决定不改挂哪些网格 | 不论网格怎样到达那里（记录、合并、旧版本），绑定的网格总随骨骼运动：挂在骨骼下由烘焙带动，否则在画布上蒙皮 |
| 骨架作用检查 | 观察报告 `quality.skeleton`（`SkeletonBindingQuality`）：骨骼绑定却不受骨骼带动的网格（`SKELETON_BINDING_INEFFECTIVE`，warning）、挂在呼吸 Warp 下却绕过躯干 Warp 且不以身体半段为轴的网格（`SKELETON_TORSO_BYPASSED`，warning）、绑定了 Rig 中没有的网格（`SKELETON_BINDING_MISSING`，info） | 静默失效变为可见 |
| 接替 | 合并从 G 与 G′ 读出生成器把哪个变形器的内容交给了哪个（例：呼吸 Warp 的内容 → 躯干 Warp；手臂下垂 Warp → 对应手臂骨骼，见 [11.3](#113-接替)）；用户创建或改挂的对象随之改挂；用户改过拓扑而生成侧改了父级或几何时，取新父级并把生成变化经画布纹理坐标映射到用户拓扑（补齐第 5 节） | 合并不再猜测结构去向 |
| 合并忠实性 | 不变式：M′ 的某值 ≠ G′ ⇒ M 的同一值 ≠ G（用户没改过的值等于新生成的值）；测试中断言，运行时违反则取 G′ 并报告。另以“先 A 后 B / 先 B 后 A”的顺序矩阵测试 B 类操作与 A 类操作的组合；提供从最后一个忠实的固化点重新合并的修复操作 | 合并错误不再自我固化，已损坏工程可修复 |

**进度**：前三层已实现（`SkeletonCanvasSkinTest.aMeshACheckpointHoldsOutsideItsBonesTurnsWithThemWithoutARecord`、`SkeletonBindingQualityTest`、`RigRegenerationTest` 的接替与用户拓扑两条）；合并忠实性为下一步。

### 11.3 接替

接替关系不另存，由合并从 G 与 G′ 本身读出（`RigRegeneration.successors`）：G 中挂在变形器 D 下、G′ 仍有的对象，在 G′ 中全部挂在同一个 X ≠ D 下，并且 D 已不在 G′ 中（启用骨架后不再生成的手臂下垂 Warp），或 X 是 G′ 新增、位于 D 之下的变形器（骨架插在呼吸 Warp 下的躯干 Warp）。对象分散到多个父级时不认定接替；消失的 D 若把内容交给了自己的父级，照常按 `rehomed` 收拢。因此已保存的固化点（都存有 G）无需改格式即可使用，规则也不依赖某个生成阶段的约定。

合并时，用户创建的对象与用户改挂过的对象，若父级被接替（可逐级），随之改挂：网格按结构编辑 `bind` 的 `space=canvas` 方式保持默认姿态下的画布位置（`RigStructureEdits.carriedToParent`），变形器在改挂不改变其下任何网格的静止位置时才改挂；做不到时保持原样并报告 `conflict`（父级随后消失的，照旧收拢）。

在带骨架的实际工程上重做启用骨架时的合并：重建过拓扑的袖子挂到手臂骨骼下，保留用户的顶点，骨骼在其上的关键形与混合形（姿态、小臂、手）随之迁移，静止位置偏差小于 0.01 px；导入后绑到呼吸 Warp 的图片与前后分层的上衣部件随接替进入躯干 Warp，随上身转动。
