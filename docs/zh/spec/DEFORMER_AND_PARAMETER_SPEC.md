# 变形器与参数参考

[文档目录](../../README.md) · [English](../../en/spec/DEFORMER_AND_PARAMETER_SPEC.md) · [日本語](../../ja/spec/DEFORMER_AND_PARAMETER_SPEC.md) · [PSD 素材与命名](PSD_LAYER_SPEC.md)

本页描述自动生成的默认结构与编辑约定。实际对象取决于素材、模型预设和后续编辑，应以层级树、参数面板或 MCP `workspace_inspect` 返回值为准。

## 结构

身体的根是 `DeformBodyXY`，只覆盖身体自己的部件（躯干、衣服、手臂、裙子、尾巴）和头部转动的脖子，不覆盖头发和腿。身体 X 让腰以上的上半身作为一个整体绕中线转向，腰和胸转得一样多，转向在胯部逐渐消失：胸前向转向一侧移动，转向前方的肩膀略大略低，脖子靠近转轴、几乎不动，头始终在身体中间；身体 Y 向下时肩膀略张开、向上时背部伸直。身体同时随髋部移动：身体 X 时略微横移，身体 Y 向下时下沉、膝盖内扣，向上时腿伸直、略微升高。其下依次是 `DeformBodyLean`（两个参数。“身体前后倾”：身体按带厚度的实体在三维中前倾并按透视绘制，骨盆绕髋关节前倾一部分并带动裙子，脊柱在腰部沿弧线逐渐弯到全角度，腰部不会被单独压扁；前倾时胸部透视缩短、整体下移并略微变大，头保持原有形状随脖子下移，脸同时向下转；后仰时变小、脸略微上抬。“大小变（头身比）”：正值头从脖子处整体放大、胸部变宽、躯干和手臂变短、腿和裙子变短，上身随之下移，更接近 Q 版；负值相反，更接近正常比例；脚不动。未启用骨架时每只手臂另有一个以身体 X 和这两个参数为轴的 `DeformArmHang_L/R`，手臂像从肩膀垂下的整体一样随肩膀移动和缩放，不随身体弯折；身体 X 时手臂不随转向一侧放大下移，而是绕肩膀反向摆约 4°，手略微落后于身体。启用骨架时上臂旋转变形器同样以身体 X 为轴抵消继承的转角并做同样的摆动）和 `DeformBodyZBreath`（身体 Z / 呼吸），头部旋转与头壳跟随位于其下。站立的全身角色另有并列的根 `DeformLegs`（腿部，以身体 X、身体 Y 和大小变为轴），只承载腿和鞋，脚在任何身体参数下都不动。面部经纬网、脸部轮廓和五官位移承接眼眉鼻嘴耳；前后发各有头壳跟随与物理分支。实际层级还包含区域组、瞳孔保持 / 视线及可选嘴唇等对象；具体结构以层级树或 MCP `workspace_inspect` 的返回为准。 生成 Rig 各处在参数满值时的幅度都可在模型预设各部位卡片的「数值」或 MCP `settings.rigTuning` 中调整：头部转向与脸面、五官（眼、瞳孔、视线、闭眼、眉、鼻、嘴、耳）、头发的跟随与摇摆、前后倾时的低头与抬头，以及身体各参数（转身角度、手臂摆动、髋部横移、下沉与上升、膝盖、背部与肩膀、前后倾角度与骨盆分担、头身比各项、身体 Z 与呼吸、躯干厚度与视距）；不常用的项折叠在其中的「高级」里；某个模块或基础算法自己画的部分（风格转头，拟合的眼、眉、嘴，头发链）生成时，对应的数值不显示。默认值即上文所述，「头部幅度」「身体幅度」再分别整体缩放头部和身体的幅度。

## 坐标与关键形

画布原点在左上，X 向右、Y 向下。对象几何在父级局部空间中求值；Warp 的归一化局部坐标与 Rotation 局部坐标不可混用。静息网格和关键形在转换时还存在不同的坐标约定，导出通过 restMeshesToCanvasSpace 等转换处理。

直接绑定决定对象自己的形状轴，父级参数通过层级继承。关键形是参数坐标处的对象形状，不是动画时间帧；动画文件随时间驱动参数，物理也输出参数值。新增参数后仍需绑定形状才会有动作。

## 自动形变

头部 X/Y 以端点与中点组合生成九姿态；原画头部倾斜作为局部基准估计。面部采用经纬网和分区修形，眼眉、瞳孔、嘴和耳朵有独立补偿或遮罩逻辑。腿按髋、膝、踝两骨 IK 弯曲，膝盖朝观众方向弯，正面看大腿变短而不是向外甩；腿画在一张图层上也能分别屈膝。头部旋转和直接挂在身体上的骨骼旋转变形器另以身体前后倾和大小变为轴随之缩放。腿已拆分并绑定到腿骨时，每根挂着腿部网格的腿骨下另有一个以身体 X/Y 为轴的站姿 warp，把网格放到腿部 warp 给出的位置：旋转变形器只传递支点和角度，腿部 warp 的弯曲传不到它下面。平面倾斜与呼吸分层处理：身体 Z 让腰线以上绕腰倾斜，各行只平移、宽度不变；呼吸按原画的肩线和腰线定位，抬起肩部和它带着的头、手臂，胸口略微扩张，腰以下不动。前后发分离于强面部形变，并分别输出摆动参数；眼球形变可由眨眼物理驱动。

**眉眼透过刘海**（`SeeThroughLayers`）：被前发盖住的眉毛各生成一个复制件，画在盖住它的刘海之上，以半透明显示，并以这些刘海网格为剪切蒙版，只在刘海范围内出现。这是动漫风格 Live2D 模型的通用做法：复制眉毛图层，提到刘海之上，降低不透明度并用刘海剪切。分两步：基础 Rig 只记录候选（`BuiltRig.seeThrough`：每条眉毛或每个眼部图层——眼白、虹膜（含高光）、睫毛、闭眼线——及在静止姿态下按像素覆盖它的刘海网格，不论设置如何，随物化 Rig 一并保存；保存时带 `see_through_rules`，3.6.5 按旧规则（只记睫毛与闭眼线）保存的候选读作未知，预览重新生成）；成品 Rig 在日志、生成器、生成结果覆盖、图层显隐与绘制顺序覆盖之后按设置制作复制件（`BuiltRig.seeThroughCopies` 记录复制件到原件，只认这份记录，不按 ID 识别）。复制件 ID 为 `<原件 ID>_SeeThrough`，已有同名网格时不制作也不覆盖；与原件共用父变形器、网格、几何关键形、混合形状、颜色与显隐；不透明度为原件的不透明度（静态值与关键形）乘以 `seeThroughOpacity`（默认 50%）；蒙版取候选中仍存在、可见、且在每个关键形都画在原件之上的刘海，没有则不制作；绘制顺序在这些刘海的最高顺序（含关键形）之上半个生成间隔，并低于其余网格的最低顺序；复制件紧排在原件之前、与原件同一部件，部件隐藏或淡出时一起隐藏。因此复制件跟随原件的全部变形、画布编辑、生成结果覆盖与刘海顺序的改动，改设置只需重放、不触发再生成；画布拖拽预览也同步复制件。复制件不在作者态 Rig 中，点名它的编辑返回 `generated_copy`，画布上不可选取。**眼睛透过刘海**用另一种通用做法——在刘海上开窗：剪切蒙版只能相加，复制件无法同时被眼白和刘海剪切，复制虹膜会把眼白外的虹膜画到头发上、闭眼时也不消失。所以盖住未被剪切的眼部图层（眼白、睫毛、没有眼白剪切的虹膜）的每条刘海，在成品 Rig 中以这些眼部图层为蒙版**反向剪切**，再在它之上画一份以同样蒙版正向剪切的刘海复制件（ID `<刘海 ID>_SeeThrough`），不透明度为刘海的不透明度乘以 `1 − seeThroughOpacity`：眼睛范围内头发按设定比例变淡，下面整只眼睛照原样显示，被眼白剪切的虹膜与高光自然透出（`BuiltRig.seeThroughWindows` 记录刘海到开窗的眼部图层）。复制件绘制顺序在刘海之上、低于盖在它上面的眉毛复制件，紧排在刘海之前、同一部件。会随眼睛开合淡入淡出的图层（闭眼线）不能做蒙版（蒙版不看不透明度），仍按眉毛的做法复制到刘海之上；被自身蒙版剪切的图层（虹膜、高光）经其蒙版的窗口显示，不单独处理。刘海已有自己的蒙版或反向蒙版时保留不开窗，报告 `bangs_clipped`；运行时目标低于 Cubism 4.0（无反向蒙版）时不开窗，报告 `target_unsupported`。窗口只在成品 Rig 中：作者态刘海没有这些蒙版，检查器的剪切 ID 与反向蒙版显示、编辑的都是文档自己的值（`authoredMasksOf`），MCP `objects` 中刘海的 `topologyInfo.seeThroughWindow` 列出开窗的眼部图层。眉毛与眼睛默认都开启：动漫立绘中两者都常被刘海遮住，透出眉眼是通用做法。设置 `seeThroughBrows`、`seeThroughEyes`、`seeThroughOpacity`（CLI `--no-see-through` 两者都关、`--no-see-through-eyes` 只关眼睛、`--see-through-opacity`）；此前保存的工程没有这些键，读取为关闭，重开时 Rig 不变；3.6.5 保存的工程带着当时默认关闭的 `seeThroughEyes: false`，保持关闭，外观不变；3.6.5 中打开了眼线的工程重开后改为整只眼睛透过（眼线部分外观相同，眼白与虹膜新显示出来）；导入的 cmo3 / moc3 不制作复制件，其中的同名网格照原样保留。限制：胶水、变形路径、顶点组不复制给复制件（胶水会把伙伴网格拉两次），实时模拟帧只作用于原件，烘焙后的关键形则照常复制；原件被拆分或替换、刘海网格全部消失时不再制作，并在 `quality.overrides` 以 `SEE_THROUGH_DROPPED`（info）报告；复制件不对应源图层，MCP 中报告原件的图层。

这些是预设算法，不是通用 3D 重建。原画分层、锚点误差、宽发片、极端角度与重叠区域都可能需要人工修形。精确曲线常数和网格分割随实现演进，维护时直接核对源码，不复制脱离版本的公式。

| 多键编辑 | 一次修改多个关键形的绘制顺序、不透明度与颜色 | 「多键编辑…」：按参数键值选范围，覆盖 / 相加 / 相乘 / 滤色地修改不透明度、绘制顺序、正片叠底色、滤色；MCP `keyform_apply op=multi_key`。几何的多键同时编辑尚无 | 本次 |
| 四角自动合成 | 自动生成四个角的形状 | 需逐个制作斜角 | 后续 |
| 参数插值方式 | 扩展插值等 | 键之间为线性插值 | 后续 |
| 恢复变形器形状 | 恢复到记录的原始形状 | 「全部键恢复为默认键形状」：对象每个键回到默认键形状（不单独记录原始形状）；MCP `op=reset all_keys=true` | 本次 |
| 锁定 / 隐藏点 | 物体的锁定与隐藏 | 图层可隐藏、画布可只显示所选；单个点的锁定与隐藏尚无 | 后续 |
| 骨骼 | 骨骼（Cubism 无直接对应时烘焙） | 骨骼姿态（Shift+W，自动 / FK / IK）、编辑骨骼（Alt+W，编辑 / 新建 / 挤出 / 绑定 / 权重），导出烘焙为参数与变形器 | 已有 |
| 模拟权重 | 无直接对应 | 权重笔刷（Shift+V）、权重渐变（Alt+V） | 已有 |
| 参数键 | 键的追加、删除、移动 | 参数面板加键、拖动、改值、删除、均分；解除选中对象与参数的绑定 | 已有 |

关键形复制 / 粘贴、重置、补间与多键编辑与镜像一样在提交时展开为普通 `set`：重放不再读取其他键，GUI 与 MCP 走同一条 `keyform_apply` 命令，几何 `set` 作用在生成器拥有的关键形上时按生成结果覆盖记录，通道 `set` 是普通通道关键形。软选择与临时变形网格只决定一次拖动中各点的位置，提交的仍是该次画布几何编辑。

## 验证

检查中立姿态、端点、组合角和中间值；检查父级与局部形状是否重复施加运动。导出流水线包含几何诊断与读回检查，但警告不是“所有姿态已验证”的证明；运行时目标不支持的功能还可能被降级。
