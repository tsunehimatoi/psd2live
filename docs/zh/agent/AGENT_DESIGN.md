# Agent 设计与验收

[文档目录](../../README.md) · [MCP 接口](MCP_AUTHORING.md) · [能力实测](../STATUS.md) · [路线图](../ROADMAP.md)

本页说明 Agent/MCP 接入的设计边界与验收方式；具体接口契约以 [MCP 接口](MCP_AUTHORING.md) 与服务运行时 Schema 为准。

---

## 1. 角色分工

| 角色 | 职责 |
| --- | --- |
| **外部 Agent** | 理解用户意图、选择目标对象、规划工具调用与观察结果（图像生成由宿主提供） |
| **PSD2Live** | 执行确定性的素材、网格、参数、物理、模拟与分支历史操作 |
| **建模者** | 决定美术风格、效果取舍与最终验收 |

---

## 2. 核心设计边界

- **统一命令通道**：GUI 与 MCP 共用同一套应用层命令（`WorkspaceHost`），均在捕获的起始 `state` 上准备候选并以 CAS 提交单个历史节点；仅修改渲染快照会在重建或重开时丢失。
- **稳定身份引用**：所有对象通过确定性 ID 引用，不使用显示名代替标识。
- **并发与历史**：`state` 用于乐观并发控制；历史只追加不改写，检出旧节点继续编辑形成分支。
- **作者姿态分离**：预览姿态（`preview_set/reset`、滑块拖动与自动关键帧）走 `WorkspacePoseCommands` 辅助 CAS，不污染 Rig 编辑历史。
- **素材与拆分同源**：
  - 图片导入与配准通过独立会话准备并提交素材清单。
  - 连通块/多边形拆分（`source_split_components` / `source_split_polygon`）与深度遮挡拆分（`source_split_depth`）与 GUI 共用同一应用层命令，支持指定预设 ID 以便在同一原子批量中继续编辑新图层。
- **严格输出契约与错误**：公开操作均声明 `request` / `outputSchema`（后台任务另含终态 `jobResultSchema`），失败统一返回结构化错误码与冲突上下文；任务查询成功不代表业务成功，需检查终态 `status`。
- **摘要优先的观察**：查询先返回摘要，再按目标与分页展开；预览截图使用固定画布镜头，明确区分原始素材、合成预览与运行时模型。

---

## 3. 任务验收检查项

1. **前置检查**：确认工程 `state`、目标对象 ID 与依赖图层。
2. **批量与试运行**：多项关联修改优先用 `workspace_preview_edits` 试运行，再以 `workspace_apply_edits` 原子提交。
3. **重放与持久化**：修改后确认可撤销/重做，且保存并重开 `.psd2live` 工程后结果一致。
4. **视觉与导出复核**：通过预览截图核对多参数姿态，导出目标格式并检查 `.psd2live.json` 损失报告。
