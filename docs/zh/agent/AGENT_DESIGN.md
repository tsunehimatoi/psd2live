# Agent 设计与验收

[文档目录](../../README.md) · [可调用接口](MCP_AUTHORING.md) · [实测](../STATUS.md) · [路线图](../ROADMAP.md)

本页只说明设计取舍与验收方式。公开 API 由接口文档和服务 Schema 定义，任务完成率由实测记录定义；研究提案不作为已上线功能。

GUI 与 MCP 走同一套应用层命令：每项编辑先在捕获的起始状态上准备候选，再以 CAS 提交一个历史节点；GUI 入口以可信用户身份调用，MCP 以 Agent 身份调用，单项修改多为进程任务，可批量的成员直接执行同一候选。

作者姿态是辅助状态，本身不进入 Rig 历史：`preview_set/reset` 与快照应用合并已提交的姿态与锁；GUI 姿态、FK/IK 目标与选中动作的自动关键帧经 `WorkspacePoseCommands` 与 `preview_pose` 共用一次 CAS；查询、修改和保存读取同一持久基线；显式无变化可校正界面并停止播放，不推进状态或历史。GUI 的参数修改先在本地生效，按 FIFO 队列提交，队列只沿自己已落地的提交前进，失败时回到已提交姿态；拖动滑块时每个采样立即写入作者姿态，松手只提交一次。播放与跟踪是进程内会话（见[画布渲染器](../spec/CANVAS_RENDERER.md#11-播放与跟踪会话)），其帧之上叠加尚未落地的修改，使面板、画布、预览与物理读取同一姿态。

图片与素材进入模型时固定图层身份：`layer_import_images` 与 GUI 图片追加整批一次历史提交；素材图层添加、配准定位与确认共用单项 / 原子批量候选；导入模型及自建父变形器下的新网格保存明确的网格创建记录，重新配准原位替换记录并保留身份与父级。连续拖动放置是独立应用会话，预览不进入保存，外部编辑及重开使其失效。

## 分工

Agent 理解意图、选择对象、规划工具调用和观察结果；程序负责确定性的素材、网格、参数、物理和历史操作。建模者决定风格与最终效果。

外部 Agent 经本地 MCP 操作桌面工作区。当前不存在由本文承诺的内置 Chat、通用自动拆发器或自动九轴视觉拟合器。图像生成由宿主提供，工具负责接收、定位与绑定结果。

## 编辑边界

- 对象使用稳定 ID 引用，显示名不能代替标识。
- 源素材、派生素材、网格、父级、参数与关键形之间的关系必须可追踪。
- 写入通过统一工程命令和历史；只修改渲染快照会在重建或重开时丢失。
- `state` 处理并发，不是逐操作审批。无效引用、父子环、非有限数值和非法拓扑须拒绝；美术效果用观察与诊断判断。
- 历史追加，不改写旧节点；恢复后继续编辑形成分支。暂存素材、临时会话、已提交历史和磁盘工程是不同状态。
- 素材准备、PNG 导入、配准和重处理由独立应用会话准备私有候选，以辅助 CAS 发布素材清单及不可变文件；实际修改推进持久 state，保留 Rig 历史与 revision。四项公开写入为进程任务，取消/冲突前缀不发布，提交后保留准确结果及图片。查询和保存使用捕获清单；旧 v1 工程在打开时固定已有成员。

## 工具设计

公开入口围绕编辑领域组织：观察、形状、关键形、结构、素材、路径、参数、物理与历史。每项操作使用 `domain_operation` 名称与严格 `request` schema。应用层注册表同时驱动 MCP 发布、校验和能力发现；不提供任意内部工具名分发。

`project` 保存中立文档、DTO 和归档；应用层定义必须实现的能力接口、运行时及命令边界，GUI 与 MCP 负责适配。`WorkspaceBackend` 仅供宿主组合接口，命令消费者按所需能力绑定，不继承抛异常或返回空值的默认实现。PSD/图片新建和切换、CMO3 新建与替换已共用可脱离 GUI 的应用层导入器；GUI 负责确认和投影，MCP 返回进程任务。桌面适配器（`DesktopWorkspace`）组合这些接口；目前没有脱离桌面应用的独立运行时。

优先用连续形变或路径表达局部动作，避免要求模型猜测大批顶点。连续操作仍需明确坐标、目标参数键与父级关系；它不保证姿态自然或拓扑无翻折。

源图拆分先用 `source_get_components` 查询当前网格连通块，再按返回顺序命名并保留查询状态。`source_split_components/source_split_polygon` 与 GUI 连通块对话框共用独立应用命令，支持原子批量和后台取消；指定 `piece_ids` 后可让后续成员引用新层。生成的模型上部件以 `art_primitive` 记录取代原图层，携带原图层已有的关键形、通道、混合形、路径、顶点权重与 Glue，模拟目标、烘焙偏移与连接角色迁移到部件，无关对象的编辑不受影响；导入 CMO3 模型沿用旧记录，原图层软删除。普通、拆分、新建及导入 CMO3 网格在单层/全局网格更新及重置时保存有序网格替换，迁移绑定和烘焙偏移，保留早期日志基线；每次替换插值前一拓扑，重置设置不恢复拓扑变粗时丢失的细节。拆分只分配现有像素，不能当作遮挡补画。

深度遮挡制作使用 `source_split_depth`：以原始网格 ID 指定源和中间对象，用后层、前层两个新图层取代源网格（导入 CMO3 模型在原网格之上复制出前层），方向 Glue 让前层跟随后层，固定两层绘制顺序。可预先指定前后层、网格与 Glue ID，在同一原子批量继续绘画或打关键形；任务终态提供新图层 ID。它与 GUI 共用应用候选，支持已有绑定，嘴部只复制所选网格；导入 CMO3 模型同样支持，GUI 前后层入口与之一致。前层绘画保留拓扑，显式网格设置可以重生；隐藏内容需另行绘画补充。

即时调用与后台任务使用同一应用层结构化错误：Agent 根据错误码和冲突上下文选择恢复动作，修正后的新尝试使用新请求 ID；任务查询成功并不代表任务业务成功，必须读取任务状态。

全部公开操作必须声明输出契约：结果在注册表去重内部校验，并发布同一完整 MCP outputSchema；后台操作还必须公开终态业务 schema。状态分支明确哪些字段存在，成功结果和失败错误不能混用。能力发现自身通过本地递归定义校验嵌套 schema，终态契约只存在于后台能力。复合 inspect 有 scope 判别字段，素材和模拟输出保留加工、配准、方向与质量诊断。`output_contract` 指服务实现问题，不能作为回滚证据。

查询先返回摘要，再按目标与分页展开。 复合工作区、骨架与动作查询使用运行时同一次不可变捕获，返回的持久状态不混入并发版本；预览查询读取已提交姿态/锁，求值帧和未提交界面值不替代它。图片固定画布镜头、限制相关区域和姿态数；清楚区分原始素材、合成预览和实际运行时模型。

## 一次任务的验收

1. **基线**：记录 HEAD、目标对象、参数和预期变化，取得相关部位与整体图。
2. **素材**：检查透明边、朝向、画布位置、遮挡余量；切分现有像素不等于补全隐藏内容。
3. **结构**：检查父级、遮罩、绘制顺序、直接绑定与继承参数。需要独立运动时才增加变形器。
4. **形状**：检查中立姿态、端点、必要的组合角和中间值；对照修改前后，确认未损坏相关部件。
5. **物理**：输出参数先有运动形状，再配置驱动。时间采样观察延迟、回弹和稳定状态。
6. **持久化与交付**：保存、恢复并重新导出；检查报告和目标软件中的实际效果。

几何合法只说明工程可计算，不能替代第 4–6 项。生成参考图也不能替代实际模型运动。

## 成本与停止条件

复用已有 ID、空间映射与成功返回的 `state`，不要每次完整扫描。静态比较合并为小型拼图，只在定位疑点时扩大局部图。先区分层序、位置、绑定与像素问题，再决定是否重新生图。

记录时间、token / 图像消耗与返工次数。达到用户预算、无法获取必要外部输入或持续修正无有效进展时，应报告具体阻碍和已有成果；不要把反复调用当成成功证据。

## 后续设计方向

本轮采用独立应用层、单次原子批量、进程内后台任务和全部 GUI 业务覆盖，不提供跨调用事务、内置聊天或独立无界面服务器。批量重建、导入、保存与导出任务已支持断线继续及重试去重；GUI 业务入口均已接入共享命令（188 项公开操作、70 项后台、87 项批量成员）。桌面窗口验收、含 Cubism SDK 的运行等未结事项与更广泛的产品方向在[路线图](../ROADMAP.md)维护；重构期间的阶段记录已[归档](archive/REFACTOR_PROGRESS.md)。
