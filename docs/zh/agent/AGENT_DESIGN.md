## 2. 产品边界与硬约束

一句话定义：**LLM 负责理解、规划、选择工具与验收；确定性算法与可配置模板负责改图、Mesh、变形器、参数和物理；建模师保留审美判断与最终精修。**

产物必须保留可编辑的 ArtMesh、Deformer、Parameter、Physics、源图与来源关系。出现下列任一情况即判定任务失败并回滚：

- 原始素材无法恢复或重新导入；
- 图层、网格、变形器与参数之间失去稳定对应关系；
- 静态画面看似正确，但关键参数、组合角、物理或极限姿势不可修；
- 修正自动结果的工作量预计高于从原始素材重做；
- 依赖无法解释、无法重放的像素或几何修改；
- 违反 Cubism 的结构、性能或导出约束。

| 硬约束 | 具体口径 |
|---|---|
| 素材分离决定上限 | 不得只按可见轮廓切刀，必须生成有合理重叠与遮挡补全的独立 RGBA 素材。原 PSD 是不可变来源，「删除原图层」只能是工作区软删除；每个派生层记录 `sourceAssetId`、mask/路径、生成设置、模型版本与 prompt hash |
| PSD 导入/重导入是一级能力 | 名称不能充当主键，一律使用永久 UUID；Import Manifest 记录源 PSD 指纹、源层路径、像素边界、ArtMesh ID 与历史映射；Mesh 在添加 keyform 前冻结，之后禁止静默重建；重导入先出匹配报告（精确 ID、路径/名称、视觉指纹、歧义、未匹配） |
| Mesh 不是统一密度铺网 | Mesh 工具必须输出 alpha 清理与孤立小区报告、轮廓环/内部点/三角形/UV/边缘距离、自交与退化检查，并按眼睑、嘴、长发、刚性饰品分别选策略，而非全局 preset |
| 变形器层级影响可修改性与性能 | 每次层级变更都要验证无环、父类型合法、各 keyform 下子顶点在父 Warp 安全范围内；Warp 范围与密度匹配运动需要，不制造巨大空 Warp；删除空 Deformer，阻止无意义层级膨胀 |
| 先有运动再有求解器 | 物理的输出对象是已做好摆动 keyform 的参数；每片发束有独立输出参数与局部摆动形状，可共享输入但延迟、阻尼、长度、输出比例独立可调；同一输出被多组驱动时总影响不得超过 100% |

规范依据：[变形器与参数规范](../spec/DEFORMER_AND_PARAMETER_SPEC.md)、[PSD 图层规范](../spec/PSD_LAYER_SPEC.md)。规范中的算法意图不能作为造型质量已经通过的证据。

## 3. 总体架构与工作区领域模型

```text
内置 Chat（可替换模型） ─┐
                          ├─ Agent Runtime：Workflow Registry / Planner / Task Orchestrator / Tool Registry
外部 Agent ──────── MCP ─┘        │
                          Domain Command Kernel
                 Read/View · Asset · Rig（Mesh/Deformer/Parameter/Physics）
                          │
                 Append-only History Tree
                          │
        PSD/KRA/CLIP 导入 · CMO3/MOC3/JSON 导出 · 可选 Cubism Bridge
```

核心原则是「一套能力，两个入口」：内置 Chat 与外部 MCP 调用同一个 Tool Registry 和同一个 Domain Command Kernel，都不直接操作 UI ViewModel。MCP 是控制平面而不是大文件通道，大图与 PSD 存在工作区 Asset Store，工具只返回短元数据与有时效的本机资源引用。所有能力先在内部领域模型完成，导入 Cubism 后另做一次 ID 映射与 round-trip 验证；Alpha 期外部 API 不能作为唯一数据真相。

### 3.1 领域模型

```text
Project
├─ SourceDocument[]   原始 PSD/KRA/CLIP，不可变
├─ AssetRevision[]    RGBA、mask、补全图与生成来源
├─ LayerNode[]        语义、左右、深度、遮挡、父子、显示名
├─ ArtMesh[] · Deformer[] · Parameter[] · PhysicsGroup[]
├─ WorkspaceHead      当前可编辑状态指向的历史节点
└─ HistoryTree        追加式快照、分支、撤回与任务恢复
```

显示名由命名策略生成（如 `hair_front_left_01`），改名不破坏引用。

### 3.2 Agent 权限与不可变边界

通过 Bearer Token 认证的 Agent 被视为**当前工作区所有者**，不是只能执行白名单动作的访客：图层增删改、RGBA/Mask/Mesh/Deformer 编辑、参数与 Keyform 增删改、长任务调度都不需要逐操作审批。程序不以审查决策为目标，只拒绝无法形成合法工程状态的命令（引用不存在的对象、父子环、NaN、损坏拓扑、违反目标格式硬约束）；视觉质量以诊断返回，Agent 据此继续修正。

唯一不可写边界是 History Store 与 History Tree 本身：写命令永远只追加节点，`history_checkout` 只移动 `WorkspaceHead`，从旧节点继续编辑自然产生新分支且原未来分支保留；Agent 没有直接改写历史的工具。大型二进制资产按内容寻址存放，历史节点只引用 hash。这与线性 Undo 不同：线性栈撤回后继续编辑会丢弃 redo 分支，不满足本产品的恢复要求。

### 3.3 事务、并发与长任务

所有会追加历史节点的写工具都携带并发边界字段（合并工具面对外名为 `state`，旧细粒度名称为 `expected_history_head_node_id`）：这不是审批，而是防止长任务把基于旧视图算出的结果覆盖用户或另一任务刚完成的修改。HEAD 不一致返回 stale-head 错误，调用方刷新工程后重新协调计划。单个编辑 Tool 当前即一次原子提交（先在不可变副本上应用并重建 Rig，成功后追加节点）；下列多命令事务仍是后续协议，尚未作为 MCP Tool 暴露：

`transaction_begin(expectedHistoryHeadNodeId) → 多个 domain command → 可选 validate/view（Agent 自主决定何时检查）→ transaction_commit(message) 或 transaction_cancel`。它会用于把「拆三层 + 生成 Mesh + 建 Warp + K 帧」合并为一个可撤回节点。耗时任务不得占住一次 MCP 调用：`task_start`/`task_update`/`task_get`/`task_list` 保存 Agent 自己制定且可替换的计划、进度与产物 ID，是恢复检查点而非审批门或固定流程；细粒度的继续、取消、恢复执行器仍待实现。`WAITING_FOR_USER` 只用于确实缺少创作意图或外部输入。

## 4. 工具收敛与表达入口

目标是工具少、字段精确，不把复杂度藏进一个无类型的大 JSON，也不并列暴露同义 legacy 工具。下列 10 个领域**已经是当前注册的合并工具面**（注册前会移除全部旧细粒度工具，见 [MCP_AUTHORING.md](MCP_AUTHORING.md) 第 5 节），核心路径使用前 6 个；下面各小节描述的字段语义与连续形变规则仍属设计口径。

| 工具 | 唯一职责 |
|---|---|
| `inspect` | 工程/选区摘要；按 query 找对象，按 id 看少量详情；两者互斥 |
| `view` | 看正式模型或候选：同镜头对照、局部图、必要姿态检查 |
| `rig` | 永久 Warp/Rotation、父子关系与运动职责；坐标迁移由程序完成 |
| `form` | 参数绑定与关键形集合：插键、复制、镜像、组合角、通道/切片编辑 |
| `parameter` | 参数定义增删改；参数本身不产生运动，需由 `form`/`deform` 绑定形状 |
| `deform` | 在明确关键形目的地对 ArtMesh/Warp 施加连续区域或路径形变；临时编辑场不留层级 |
| `revision` | 提交候选、查询历史与回执、恢复；读写分支类型明确 |
| `asset` | 准备参考、接收 PNG、放置到候选 |
| `physics` | 输入、输出、摆链设置，默认进入候选 |
| `appearance` | 静态显示、遮罩、连接等绘制关系；动画通道仍由 `form` 写入 |

不另设 `preview`/`check`/`get-points`/`get-geometry-summary` 工具：preview 是修改工具的默认返回状态，检查附在 `view` 或候选诊断中，错误自带必要解释，密集点操作只属于显式启用的开发诊断配置。工具 annotation 反映最强副作用，不能因某个分支只读就把整个工具标为只读。

### 4.1 用连续形变场替代点操作

操作目标是整个控制面。每次操作定义连续映射 `T`，区域笔刷定义权重 `w`，程序对全部控制点求值：

`p' = p + w(p) · (T(p) - p)`

默认 `w=1`，即整网形变；只有显式 `pin` 或区域外的点保持不动。透明区域、Mesh 外缘之外的格点同样参与，不按「控制点下面有没有像素」过滤。Agent 决定方向、范围、幅度与附着位置，不决定顶点坐标。笔刷小于网格分辨能力时应加密拟合或返回分辨率不足，而不是退化成只移动一个最近格点。

| 保留的操作 | 输入概念 | 适合任务 |
|---|---|---|
| `move` | 向量 | 半张脸/大片头发整体偏移 |
| `scale` | 横纵倍率，默认区域中心，可显式轴心 | 整体压扁、拉长、扩宽，局部大片收缩 |
| `rotate` | 角度、轴心 | 附着部位转动 |
| `bend` | 轴向、弯曲角度或有限曲线、可选固定边 | 整片身体/发束弯曲，截面随曲线转动 |
| `profile` | 沿轴的少量截面宽度倍率 | 上宽下窄、腰部收缩、头顶扩展 |

压缩与扩展都是 `scale`；固定根部摆动用 `bend`/`rotate` 加 `pin` 表达，不再单列只能用于头发的接口。真正的整体弯曲应以连续中心线加随动截面构造映射（例如 `F(s,r)=C(s)+r·n(s)`），不能把横向曲线位移当作所有弯曲需求的等价实现。`profile` 用少量纵向站点插值并保持正倍率，避免过冲翻折。网格平滑属于数值处理或专家修复，不作为普通造型的默认步骤，也不在每次操作后自动抹平轮廓。

笔刷要求：`region` 省略表示全部可变形点，常用方向区域为 `whole`/`left`/`right`/`top`/`bottom`，自定义笔刷需支持圆/椭圆、方形平台与路径带。方向区域的语义在同一基准编辑框内固定（`right` 是右半大块，过渡带跨中线，最外侧边界仍可受满权重）；椭圆笔刷含中心与双轴半径，内部是近似等幅平台、外圈平滑衰减，不能用从中心立即下降的尖峰权重。所有笔刷按实际编辑框的空间度量求值，`pin` 权重优先于修改，冲突时返回被约束削弱的实际效果。

### 4.2 一个固定坐标框，一次输入少量语义参数

一次 `deform` 使用同一基准 state/pose/编辑框；后续操作可以叠加已变形结果，但范围、归一化长度与方向不随每一步包围框变化，需要换轴心时显式指定。观察 `pose` 与写入 `key` 分开：`key` 是目标 owner 的精确绑定轴值，`pose` 可额外包含父级参数；缺少必要轴时返回需补的轴，不回传无关参数，也不吸附到最近键。

```json
{"state":"h17","target":"warp:face","key":{"ParamAngleX":30,"ParamAngleY":0},"ops":[{"type":"scale","value":[0.85,1]}]}
```

```json
{"state":"c1","edit":"e1","ops":[{"type":"move","region":"right","value":[-0.08,0]},{"type":"bend","axis":"y","angle":8}]}
```

`-0.08` 表示基准编辑框宽度的 8%，角度单位为度；`c1`/`e1` 来自前一个调用的候选与已确认目的地。这些调用没有点编号。`view` 需要解释影响时，画稀疏网格、影响热区与少量位移箭头即可；默认仍是干净角色图，只在诊断方向与范围时加 field overlay。

### 4.3 工作流与按需知识

工作流是领域作业指导，不是固定脚本。它应声明开始前必须读取的结构与视图、可选策略及判断条件、禁止动作与失败条件、必须调用的验证器、可接受的质量阈值，以及对用户的完成报告格式。当前实现只保留服务端 `instructions`：此前的知识工具、prompt 与打包知识文件均已移除（见 [MCP_AUTHORING.md](MCP_AUTHORING.md) 第 6 节）；简单改名不必加载绘画流程，也不要求在宿主侧安装 Skill 文件。建议主题包括 `psd-audit`、`semantic-labeling`、`hair-separation`、`face-rig`、`eye-rig`、`mouth-rig`、`secondary-motion`、`project-qc`。

程序只强制不可变源、事务、alpha/拓扑/越界/物理约束与结构不变量（参数 ID 唯一、`min ≤ default ≤ max`、坐标有限、顶点数匹配目标拓扑、引用有效）；「这个摆幅是否好看」由 Agent 与建模师判断，不成为权限门。安全不变量写在程序里，不能只寄托于 Prompt 是否听话，也不要把「修头部」做成一个不透明的自动建模按钮。

## 5. 从建模流程反推的能力缺口

建模的目标不是「改好一张形状」，而是让一组图层在参数变化时持续保持结构、体积、遮挡与角色特征，并仍可继续编辑。因此每次修改都要回答三件事：哪一级对象负责运动、形状写入参数空间的什么位置、这次变化如何与已有运动组合。

| 此前不足 | 修正后的要求 |
|---|---|
| 局部修改优先创建小 Warp | 先选已有运动所有者；临时笔刷/路径不创建层级，需要独立运动才建永久 Warp/Rotation |
| 普通塑形以 Warp 为唯一目标 | ArtMesh 与 Warp 均是一等编辑目标；细眼睑/唇线可能应直接编辑网格关键形 |
| 把 pose 当作写入目标 | 区分观察姿态、精确关键形地址、基础形状与叠加修正，不从 GUI 当前值猜目的地 |
| 眼睛/嘴巴归结为压缩 | 同一闭合轨迹下不同素材承担孔径、线条、遮挡等不同作用，需要协同而非同倍率压扁 |
| 关键形创建/复制是配套功能 | 它们是主工作流：插入、复制、镜像、合成组合角、按参数切片修改并保留其他形状 |
| 合法网格即可继续 | 合法性、预期闭合、造型与中间插值分别评估，不统一惩罚强压缩 |
| 拼图只是把图片放一起 | 布局必须表达参数关系与修改版本，每格可定位到对象、关键形与观察姿态 |

### 5.1 可核对的编辑目的地

`inspect` 的对象摘要应回答「能改什么、现在由谁控制」，按选区只返回相关信息：

```json
{"state":"h17","target":"mesh:lashL","direct":["EyeOpenL"],"inherited":["AngleX","AngleY"],"related":["mesh:whiteL","mesh:irisL"]}
```

这是实际绑定摘要，不是按名称猜出的标准模板；候选不明确时返回候选名让 Agent 选择，语义识别结果须带来源并允许修正。一次编辑目的地包含工程版本、对象集合、通道、精确关键形地址、观察姿态与固定坐标框，服务端可生成短 edit handle 供后续沿候选继承。三种写入不能混用：

- **基础形状**：改变不随指定参数变化的基准，必须说明对既有动画的迁移策略，不能把转头姿态下看到的位置直接写成 rest mesh；
- **关键形**：写入指定 owner 的精确参数单元，显示姿态可含父级转头，但写眨眼不得顺便新增头部 XY 绑定；
- **组合修正**：写入已有组合单元或明确的增量层；仅在格式、运行时与导出都支持时使用独立增量层，否则烘焙到指定组合关键形，不假称支持 Cubism Blend Shape。

画布笔刷位移必须通过当前父链反算到目的地的局部坐标，不可逆或多解处返回定位错误。关键形管理由程序做数组与插值运算：新增键采样当前插值且不清空其他格子；复制只带指定形状与通道，跨对象需兼容拓扑或明确映射；镜像需明确轴与对象配对，默认只补未编辑目标；双轴先做轴向形再合成指定角落；支持参数切片（例如 `Smile=1` 的全部 `EyeOpen` 键统一调绘制顺序，不触碰 `Smile=0`）。

### 5.2 临时变形与永久层级

永久 Warp 只在需要新增独立运动层时创建，已有对象的一次塑形直接用 `deform`。`rig` 的局部 Warp 创建负载示意：

```json
{"state":"h17","targets":["mesh:side-hair"],"fit":"motion"}
```

`fit` 默认 `motion`，id、共同父级与网格由服务器生成；跨父坐标域或选择范围歧义时返回短错误，不凭名称猜。创建顺序：

1. 取得目标在共同父级局部空间中的中立几何与已有姿态包络，使用有效控制几何而非屏幕可见 alpha；
2. 合并包围范围并加一圈相对局部宽高的有限余量，尚无动画时注明未覆盖未知运动；
3. 创建真实局部框，默认低密度、依长宽比选网格，复杂弯曲再按误差加密；
4. 把目标局部坐标、相关关键形与子级坐标正确映射到新 Warp 域，保留 UV、通道、蒙版与组织关系；
5. 验证插入前后中立、已有关键姿态、组合姿态及中间采样的世界位置后才允许提交。

不默认暴露 `rows`/`columns`，精度策略用 `coarse`/`normal`/`fine` 但必须通过误差检验，不能把细网格等同于高质量。返回默认只有 warp id 与候选 state；框太空、密度异常或目标本来就覆盖整头时才附带诊断。「贴合」不是无限缩小：需要一圈有意义的空控制区域来平滑过渡，检查空框需比较目标范围与 Warp 范围，不用全模型统一尺寸阈值。已有 Warp 的重新贴合必须迁移动画与子级坐标，不可迁移时候选失败，不静默清空关键形或重建 Mesh。

**已修正的旧假设**：旧创建逻辑把新 Warp 控制点铺满父坐标 0～1（`RigWarpEdit` 不接收目标边界），会生成覆盖整个父域的大框，理由是网格对齐可减少插入子 Warp 后的继承运动重采样误差。这不能靠教 Agent 调小解决，必须实现真正的局部坐标重参数化，并验证父级动画与导出一致性：无法在标准 Warp 语义内拟合到误差边界时，应重构为明确的局部映射复合，并同时处理 CPU/GPU 与 CMO3/MOC3 导出回读，不能只让应用内预览变好；也达不到要求就报告无法无损拟合，不悄悄退回全父框再称之为局部 Warp。

### 5.3 三条完整建模路径

| 路径 | 关键判断 | 不能冒充完成 |
|---|---|---|
| 修好闭眼并保持微笑与转头 | 确认闭眼是几何、替换素材还是混合；定义共同闭合弧与眼角锚点；眼白孔径、睫毛墨线厚度、下眼睑、虹膜高光服从同一目标但各自倍率不同 | 睫毛与眼白等比缩到一条线；闭眼只隐藏瞳孔；用统一面积阈值阻止合理近闭合 |
| 修头部 XY，而非压扁整张脸 | 区分整体轮廓、五官透视、头发跟随与遮挡错误；按默认形 → 轴向形 → 缺失角落合成 → 四角局部校正 → 中间轨迹检查推进，每次只修责任明确的一层 | 简单 `scale` 冒充「实现了转头」；父级移动与子级补偿重复计入 |
| 让一束头发独立摆动 | 已有 owner 直接编辑，需要独立输出才插入局部 Warp 并保留头部跟随层；用发根到发梢的路径或大范围 `bend` 创作两端形状，发根是有限固定区域而非一个点 | 用静态拼图冒充物理结果；调阻尼补救端点形状错误 |

口部沿用同一编辑机制但有自己的约束（上下唇闭合线、嘴角固定范围、口腔/牙齿/舌头遮挡、开口面积与笑形组合），不能复制闭眼阈值。物理驱动的是已经建好的输出参数范围，验收需覆盖静止回正、快速左右转头、低/高 FPS、输入极值与多组叠加。

## 6. 成本与信息压缩

### 6.1 最小返回与 token 预算

在已有 edit handle 且未扩大写入范围时，普通 `deform` 成功只需 `{"state":"c3","changed":true}`；有实际问题才加 `issues`（带 `code` 与区域）。首次目的地解析、批量写入或扩展关键形集合时，回执还需 `edit`、实际 owner/key/channel 或简短差异，不能为百 token 预算隐藏自动建键或绑定变化。缺少关键姿态轴时返回 `POSE_INCOMPLETE` 与 `missing`，其中数值是可选默认值，不代表系统已代填。

默认不返回全部操作副本、所有 diagnostics、所有参数与父级、长 success 文案、固定 next 数组、点数与多张图。必要影响范围、未验证项与异常不能为省 token 隐藏，改用 `inspect`/`view` 按需展开。字段名保持简短常见（`state`/`target`/`pose`/`ops`/`region`/`value`），不压成单字母。首次 `inspect` 只给最小工作环境：state、当前选区、画布尺寸与相关对象。设计预算为普通文本修改回执百 token 以内，工具总 Schema 预算在生成真实 Schema 后按基线收紧——数字是目标，不是已测性能。

### 6.2 图片组织

`view` 默认返回一张为当前判断组织的拼合图，而不是多个独立 image content。已落地的只有单张姿态拼图（同版本静态对照）；候选前后对照、sheet 缓存与 tile 放大仍是设计。

| 当前判断 | 默认图布局 | 不默认附带 |
|---|---|---|
| 局部修改是否更好 | 同姿态、同裁切的 before/after 两格 | 全部控制点、差分图 |
| 转动后是否自然 | 行是少量相关姿态，列是 before/after | 无关参数组合、逐帧图片 |
| 新素材是否融入 | 原组合/候选组合，必要时加素材局部 | 所有源层独立大图 |
| 数值检查发现缺陷 | 最差姿态的局部 before/after | 每个正常区域截图 |
| 物理动作是否断裂 | 按真实时间排列的少量关键帧，共用镜头 | 完整录像或几十帧 |

「修改前后」与「中立/极限姿态」是两个维度，不能混为一谈：同姿态比较两个 state 才能评价修改。候选默认对比其直接父候选，首次候选对比正式基线，`view` 保留显式 `compare_to` 以便回看最初版本或最佳候选。同一对照组固定相机、裁切、像素尺度、背景与光栅化设置，否则缩放或漂移会被自动居中掩盖。每格只有短标签，完整映射在服务端保存，普通返回只含 `sheet_id` 与格子 id；放大用 `{"sheet":"s12","tile":"B2"}`，看局部再加 `crop`（该格内的归一化矩形，不是 Warp 操作坐标）。图上点选也必须携带 tile。

默认先选 2～6 个有用格子，每格保持能辨识目标缺陷的尺度，超预算就分组或局部放大；主体只有几十像素的全身九宫格不能用于检查睫毛或发根接缝。差分图只用于定位变动，需区分透明度与颜色变化，「有差异」不等于「更好」，也不能用两个姿态的像素差判断退步。大图合一不保证 token 更低，宿主的缩放与切片策略可能抵消节省；目标是删除重复背景并减少观察轮次，实际应测量图像 token 或宿主账单。帧选择由程序做（中立、有效端点、关键组合角，异常区间加密），审美判断仍由 Agent 做，不能被数值评分限制看图范围。

### 6.3 不重复计算与传输

`rig`/`form`/`deform` 默认生成不可变候选，操作数据、底层点数组与编辑框保存在程序内；`revision` 的提交分支只引用 state，不让 Agent 重传已看过的点或 operations。`deform` 执行必要合法性检查并保留具体失败位置，`view` 可请求多姿态、组合角或物理轨迹检查；结果要分清「结构可用」与「外观已观察」，数值通过不代表造型自然。翻面与极端压缩检查基于采样域与实际求值，同时比较控制点之间的形变与父级级联后的最终画面；不统一用面积比例拒绝所有强压缩，也不为通过检查自动缩小请求幅度（静止不动不能作为「安全摆动」成功）。

候选来源 HEAD、资产与拓扑版本由 state 持有；提交冲突返回最新状态与影响对象，不自动套用到新框。同候选相同视图命中缓存，只有被请求才返回图片，对照图固定相机与姿态。先验证便宜且可逆的原因再支付昂贵成本：边缘被截断先区分素材缺像素与放置越界，看起来挤扁先查父级继承与局部 `scale`，发根露洞先比较原素材覆盖与绑定；证据不足标注为 suspected。这些检查可在一次 `rig`/`deform`/`asset` 执行中完成，只返回与当前失败有关的一项。需要调一个量时，可在 `deform` 的可选 `compare` 中对同一操作的一个标量给出最多三个显式候选值，由程序从同一基线生成同尺度拼图；只有 Agent 要求才做，多维组合搜索不属于首版。

记忆留在工程里：候选 state 保存父版本、目标、编辑框、操作与证据，恢复上下文只需当前意图、最近候选、未解决问题与必要对象。不依赖「服务器记得当前正在编辑哪个 Warp」的隐式全局状态，引用始终属于具体工程与候选。

外部项目可借鉴机制与参考源码见 [调研存档](archive/AGENT_RESEARCH_2026-09-13.md)，能力对照见 [实现对比](../spec/IMPLEMENTATION_COMPARISON.md)；借鉴项一律通过上述少量工具表达，不因一个好点子新增 MCP tool。

## 7. 分阶段实施顺序与验收标准

以下顺序是收敛后的**唯一口径**：它取代早期按「素材闭环优先、结构自动化在后」排列的阶段表，也取代以单张形状优化为中心的排期。理由是：没有精确关键形与多对象写入，素材再多也修不好现有模型；局部 Warp 只是「需要新增独立运动层」的分支，不能占据整条路线。

| 阶段 | 目标 | 内容 |
|---|---|---|
| 一、已有对象的关键形编辑闭环 | 打通写入路径 | 明确 owner/key/channel、父链坐标反算、保形插键与多对象写入；ArtMesh 与 Warp 都覆盖；配合固定镜头的参数矩阵观察；连续场默认全网，支持大区域平台权重与路径弯曲 |
| 二、独立运动层与组合形状 | 新增运动结构 | 重构局部坐标迁移与级联求值，证明新建与重贴合能保留已有运动；验证复制、镜像、组合角候选与参数切片；用 `inspect`/`view`/`rig`/`form`/`deform`/`revision` 收敛入口 |
| 三、真实造型任务验证 | 端到端验收 | 闭眼与微笑/转头组合、已有头部 XY 修形、独立发束摆动三条完整流程；整体压缩、扩展、弯曲只作几何回归，不能替代建模验收；先用已分层素材，不混入生图失败因素 |
| 四、素材与物理配套收敛 | 补齐外围 | 在相同 state 与错误协议上收敛 `asset`/`appearance`/`physics`；没有证据时不建配方市场、任务调度器、复杂自动 planner 或额外分层 API |

形变场是编辑抽象，不要求新增私有运行时文件格式：能把结果合理采样到标准 Warp keyform 就直接输出标准可编辑结果，需要修改运行时语义时先证明导出一致性。

| 层面 | 必须证明 |
|---|---|
| 尺寸 | 小发束得到局部 Warp，不复制整个父域，必要运动余量保留 |
| 继承 | 插入/重贴合前后已有动画一致，比较相关关键姿态与中间值 |
| 全网 | 无 `region` 的移动/缩放作用于整个 Warp，边界与空白控制点参与 |
| 大笔刷 | 右半区呈大片近似一致位移，过渡连续，不集中成一个小尖峰 |
| 弯曲 | 截面随中心线合理转动，可区分弯曲与简单横向位移 |
| 稳定性 | 改网格密度后同一笔刷描述产生近似相同的可见形变 |
| 局部性 | 未选对象及其动画不受影响，`pin` 区保留约束 |
| 关键形 | 新键保持已有插值；指定格或切片修改不覆盖其他格与通道；观察 pose 不偷偷新增绑定 |
| 建模 | 闭眼保留墨线/遮罩；转头职责不重复；镜像/合成角是待检查候选 |
| 导出 | 保存恢复、CMO3/MOC3 回读；有 SDK 环境时再对照实际渲染 |
| 拼图 | 同姿态前后共用尺度，不掩盖缩放或漂移；tile 可准确放大定位；小缺陷可辨识 |
| Token | 不传点数组、不重复传计划；统计 Schema、请求、回执与观察成本 |
| Agent | 同输入/模型/任务对照完成率、有效修改次数、理解错误与人工修复时间 |

重点测试必须使用「目标 Mesh 只占非线性父 Warp 小部分」的样例；覆盖整个 0～1 方形的 fixture 既无法暴露大框问题，也不足以验证连续形变的视觉质量。发布门槛另需固定样本集与高级建模师盲评，覆盖结构正确、动态质量、性能（顶点数与 Deformer 数、越界顶点、目标平台 FPS）、可维护性（二次修改耗时）、可恢复性与重放性。核心指标不是自动完成百分比，而是**建模师在自动工程上完成真实返修的总时间是否稳定低于手工重建**。操作级说明与使用方式见 [用户指南](../guide/USER_GUIDE.md)。
