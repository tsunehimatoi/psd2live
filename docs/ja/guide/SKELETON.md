# ボーンとポーズ

[ドキュメント目次](../README.md) · [操作早見表](USER_GUIDE.md) · [物理演算](PHYSICS.md)

ボーンは、体、四肢、尻尾、翼を、Cubism がそのまま実行できる構造へベイクします。上半身と下半身は、体のデフォーマチェーンの末端にある**曲げデフォーマ**で、**回転デフォーマ**が四肢など塊のパーツの回転を担い、関節をまたぐメッシュは**補正キーフォーム**で滑らかに曲がります。書き出した moc3/cmo3 は本プログラムに依存せず、Cubism Editor で編集を続けられます。

## ワークフロー

ボーンの操作は「ボーン」タブにまとまっています。これは「階層ツリー」と同じパネルの中にある、並んだ 2 つのタブです（古いレイアウトにはこのタブが自動で追加されます。ウィンドウメニューから個別に開閉することもできます）。ツリーは階層順に各ボーンを列挙し、それにバインドされた描画オブジェクトがその下に並び、同じ色で示され、表示されるのはレイヤー名（分割時に付けた名前）です。描画オブジェクト名をクリックすると階層ツリーで対応するレイヤーが選択され、スケルトンの編集中は、それが属するボーンが選択されます。

**スケルトンは独立した選択対象**で、描画オブジェクト、デフォーマと並びます。ポーズ付けとスケルトンの編集は、どちらもキャンバスの「ボーン」モードで行います（モードメニュー、既定は `Alt+5`）。変形、編集などのほかのモードはスケルトンに作用しません。

| モード | スケルトン |
| --- | --- |
| オブジェクト | キャンバス上にボーンを薄く表示し、ボーンをクリックする（または「ボーン」タブでボーンの行をクリックする）とスケルトンが選択されます。描画オブジェクトまたはデフォーマを選択すると、スケルトンの選択は自動で解除されます。ビューオプションの「ボーン」スイッチで、このボーンの層を隠せます。隠すとキャンバス上ではボーンをクリックできなくなりますが、タブからは引き続き選択できます |
| ボーン | ツールバーに「ボーンのポーズ」（既定は `Shift+W`）と「ボーンを編集」（既定は `Alt+W`）の 2 つのツールがあります。どのモードでもこの 2 つのキーを押すとボーンモードに入ります。入ったときスケルトンが有効ならボーンのポーズを使い、そうでなければボーンの編集を使います。ボーンモードで描画オブジェクトまたはデフォーマを選択すると、オブジェクトモードに戻ります |

1. **スケルトンの作成 / 編集**：ボーンモードで「ボーンを編集」ツールを選ぶか、オブジェクトモードで描画オブジェクトを右クリックして「スケルトンを作成」/「スケルトンを編集」を選びます。プロジェクトにまだスケルトンがないとき、ボーンモードに入ってもすぐには生成されず、キャンバス中央に「スケルトンを作成」ボタンが表示されます。それをクリックする（または「ボーン」タブの同名ボタン）と作成されます。タブ右上の赤いゴミ箱「スケルトンを削除」は、スケルトン全体を取り除きます（履歴 1 件、取り消し可）。そのあと再作成できます。編集中、バインドされた各描画オブジェクトは、所属ボーンの色でキャンバス上に半透明で塗られ、選択中のボーンの描画オブジェクトはより目立ちます。作成時には、一式のスケルトンが自動で推定されます。
   - **意味でバインド**：レイヤーのタグと左右でバインドします。腕は同じ側の handwear、脚は legwear、足は footwear、尻尾と翼はそれぞれのレイヤーへバインドします。スイッチ類、切り替え類のバリアントレイヤーは一緒にバインドされますが、ボーン位置の推定には参加しません。
   - **人体の構成で位置を決める**：
     - 肩関節は胴の肩線の下、胴の縁の内側に置き、股関節は腰の線の下に置きます（スカートに隠れていても同様に置きます）。
     - 曲がった肘／膝は、折れの外側の角の内側に置き、真っすぐな四肢は比率で置きます。上腕 : 前腕 : 手 ≈ 1 : 0.85 : 0.55、太もも ≈ すねです。
     - 手首は前腕と手の比率で置きます。靴があるときは足首を靴の口に置き、つま先は靴の最も遠い端を取ります。
     - 尻尾はメッシュ内部の中心軸に沿って 3–4 節に分け、1 本の柔軟なボーンチェーンになります（以下の「柔軟なボーンチェーン」を参照）。中心軸が比較的真っすぐなときは等分し、はっきり曲がっているときは関節を曲がりに置き、各節の弦が中心軸に最も近くなるようにします。
   - 関節の端点をドラッグして位置を調整します。ArtMesh をクリックすると、現在のボーンへバインドされます。
   - 「編集」サブツールでは、Shift クリックで選択の増減、空白のドラッグで矩形選択、ボーンの胴体のドラッグで選択全体を平行移動します。「ツール詳細」パネルでは、全選択、ボーンチェーンの選択、回転、拡大縮小ができます。回転／拡大縮小の軸は選択端点の中心で、子孫を含めることをオンにできます。外側でつながった端点は追従し、切れた端点は動きません。
   - 「ツール詳細」パネルには、複製、ミラー、再分割、融合もあります。複製は既定ではメッシュをバインドせず、バインドを複製へ移すことを選べます。子孫を含めるオプションは、ボーンチェーン全体を複製するかどうかを制御します。ミラーは X 軸を設定でき、左右と方向を自動で反転し、明確に一致する反対側のメッシュ数を表示します。曖昧なレイヤーは未バインドのままです。対称編集をオンにすると、ミラーで対になった関節の移動と選択の変形が連動します。
   - 再分割は、現在の四肢ボーンを 2–16 節に分け、先頭の ID とバインドを残し、子ボーンは最後の節にぶら下がります。融合は、現在つながっている子ボーンを、分岐のない四肢の親へ統合し、バインドを移します。組み込みの体／頭は再分割も融合もせず、その複製はカスタムボーンになります。再分割／融合は静止スケルトンを基準にベイクし直し、影響を受けたミラーの対を解除します。
   - **サブツール**：左側ツールバーの「ボーンを編集」の下に、「編集／新規ボーン／押し出し／バインド／ウェイト」が並びます（`1`–`5`。キャンバスの右クリックメニューでも切り替えられます）。編集は関節の移動とメッシュのバインドに使います。新規ボーンは始点から終点へドラッグし、親ボーンのない独立したカスタムボーンを作ります。押し出しは、選択ボーンの末端からドラッグするか空白をクリックして子ボーンを作り、新しいボーンを自動で選択するので連続して伸ばせます。ドラッグ中はプレビューが表示され、離すと作成されます。長さが画面上 4 ピクセル未満のときは作成されません。新しいボーンは既定ではメッシュをバインドせず、「編集」に戻ってからバインドします。ツリー上部の「ボーン追加」は、既定で下へ 60 ピクセル伸ばすショートカット操作を残し、新しいボーンを選択します。
   - バインドされたメッシュは、**四肢全体**の上でウェイトを自動計算します。同じ四肢のメッシュは、その中の 1 本のボーンへバインドすれば足ります。
   - **柔軟**：ボーンパネルで「柔軟（滑らかな曲線）」にチェックすると、選択したボーンが柔軟なボーンチェーンの 1 節になります。尻尾、ひれ、指のように柔らかく長い部位は、これで関節で折れ角にならずに 1 本の滑らかな曲線へ曲がります。1 本の柔軟なボーンの下に複数の柔軟な子ボーンがぶら下がると分岐点になります。たとえば魚の尾の上下 2 枚です。分岐点は関節上にしか置けず、ボーンの途中で分岐させるときは先に再分割します。
   - **ボーンチェーンを真っすぐに**：柔軟なボーンチェーン上のボーンを選択し、「ボーンチェーンを真っすぐに」をクリックします。ボーンチェーンは根元から節ごとに 1 本の直線へ回り、原画はボーンチェーンに沿って展開されます（動くのはメッシュ頂点だけで、テクスチャと UV は変わりません）。静止ポーズは真っすぐになり、原画の曲がりはポーズ「<ボーン名> drawn」として別に保存され、各関節の制限はそれを含むように自動で広がります。そのあと、真っすぐな状態からキーフォームと物理演算を付けられます。分岐では開いたまま、各枝が別々に真っすぐになります。「原画の曲がりを復元」は、ボーンとメッシュを原画へ戻します。
   - ツリーでボーンをクリックしてから、キャンバス上の ArtMesh をクリックするとバインドできます。描画オブジェクトの行末の「×」でバインドを解除します。尻尾と翼は、タブ上部のチェックで追加または削除できます。
   - 一括操作は「バインド」サブツールへ切り替え、ツリーで対象ボーンを選び、クリック、矩形選択、または「ツール詳細」の一覧のチェックでメッシュを選びます。Shift の矩形選択はメッシュを追加します。キャンバスは操作待ちのメッシュをハイライトし、「ツール詳細」は数と対象ボーンを表示します。「選択をバインド」または「選択のバインドを解除」で一括適用します。
   - 「ウェイト」サブツールは、バインド済みの四肢メッシュを選び、ツリーで同じ四肢内のボーンを選びます。クリック／ドラッグで増減、置換、平滑ができます。青からオレンジが、選択ボーンの影響を表します。描き方（加算／減算／置換／平滑）、半径、強度、置換値は、キャンバス左下のツールオプションバー（および右クリックメニュー）で設定します。現在の角度スキニングは、頂点ごとに 1 本、または隣接する 2 本のボーンを保ち、描画は自動で正規化されます。
   - ウェイトのクリーンアップでは、影響を 1–2 本と低いウェイトのしきい値を選び、空の値、無効な参照、正規化されていない行を検出して修復できます。自動ウェイトへ戻すこともできます。ウェイトの複製／ミラーは、先にソース、対象、補間／最近頂点／同一トポロジの方式、およびボーンの対応を選び、一致数と未一致数を見てから適用します。未一致の頂点は自動ウェイトを残します。最近頂点には距離の制限があり、ミラーは軸を設定できます。同一トポロジは、頂点数と三角形インデックスが一致している必要があります。
   - 手作業のウェイトはプロジェクトとともに保存され、プレビューと書き出しのベイクに使われます。ウェイトは静止位置と三角形サンプルで保存され、メッシュが頂点を増やしたときは補間で継承します。ボーンを再分割するとき、そのボーンの影響を受ける手作業メッシュは自動ウェイトへ戻り、新しい骨節へ割り当て直します。
   - ボーンを選択したあと、タブ下部で「関節の帯域」（関節の両側で、どれだけの幅の範囲を滑らかに遷移させるか。「自動」をクリックすると既定値に戻ります）と「最小 / 最大」角度を調整できます。角度範囲は、そのボーンパラメータの範囲です。
   - ボーン設定の名前は、Enter または入力欄を離れると保存され、ボーン ID とパラメータは変わりません。親のドロップダウンで親ボーンを変更または解除でき、既定では座標を保ちます。「親ボーンの末端へ接続」をオンにすると、部分ツリー全体が親ボーンの末端へ平行移動します。オフにすると親と位置は残り、重なった端点も一緒には動かなくなります。自身と子孫は親に設定できません。
   - スケルトンの編集が終わったら、「ボーンパラメータのサンプリング」で許容差（ピクセル）、最小角度間隔、単一メッシュのキーフォーム上限を調整できます。スライダーを動かすとモデルが再構築され、実際に生成されたパラメータ点の総数が表示されます。ツリーでは各ボーンの横に、対応パラメータの点数が表示されます。計算中は「パラメータ点を計算しています」と表示され、設定はプロジェクトとともに保存されます。「リセット」で既定値に戻ります。
   - **編集を離れると保存**： 「ボーンのポーズ」ツールへ切り替える、ほかのモードへ切り替える、別のレイヤーを選択する、「完了」をクリックする、のいずれでも、変更は履歴 1 件として書き込まれ、モデルが再構築されます。「完了」のあと、スケルトンが有効なら「ボーンのポーズ」ツールへ切り替えてポーズを付け、無効ならボーンモードに入る前のモードへ戻ります。今回の変更を捨てるのは「キャンセル」だけです。「完了」「キャンセル」は、モードバー、「ボーン」タブの下部、キャンバスの右クリックメニューにあります。
   - 編集中、タブ下部の「無効化」はスケルトンをオフにするだけで、ボーンとバインドは残ります。タブの「有効化」で復元できます。
2. **ポーズを付ける**：ボーンモードで「ボーンのポーズ」ツールを選びます。スケルトンが有効なとき、ボーンモードに入ると既定でこのツールになります。
   - ボーンの胴体をドラッグ：FK。このボーンだけが回転します。
   - 左側ツールバー（ポーズツールの下）またはキャンバスの右クリックメニューで「自動／FK／IK」を選べます（`1`–`3`）。自動は、胴体のドラッグを FK、末端または Shift ドラッグを IK に保ちます。明示的な FK は常に現在のボーンだけを回し、明示的な IK は常にボーンチェーンを解きます。
   - ボーンを選択したあと、「ツール詳細」の IK 設定がその末端のチェーン長（1–32 本）、反復回数、ピクセル許容差、曲げ方向を決め、各関節は自身の角度制限に従い続けます。「選択ボーンの末端を固定」をクリックしたあと親パラメータを変更すると、解き続けます。キャンバスの十字をドラッグするか、目標座標を入力すると位置を変えられ、開始、停止、解放に対応します。到達できない、または互いに衝突する目標は、残差を表示します。
   - IK の目標と設定はプロジェクトに保存されます。書き出しモデルはパラメータ範囲を残し、アニメーションは解いたあとの角度を残します。書き出しには、ランタイムの固定目標や IK 制約は含まれません。保存／名前付きポーズの挿入で、解いた結果をアニメーションへ書き込めます。
   - ボーンのポーズツールの「ツール詳細」では、現在のモデルパラメータを名前で保存でき（同名は上書き）、保存済みのポーズを選んで適用または削除できます。適用は、取り除かれたパラメータを飛ばし、現在のパラメータ範囲に制限します。アニメーションエディタを開き、「保存済みポーズを挿入」のドロップダウンでスナップショットを選ぶと、再生ヘッドの位置に、まだ存在するすべてのパラメータを挿入し、欠けているカーブを作成します。既存キーフレームの補間と制御ハンドルは残ります。
   - ボーンの末端をドラッグする、または `Shift` を押しながらドラッグする：IK。このボーンと、最大 2 階層上の親ボーンが一緒にポインタのほうを向き、各関節は角度制限に従います。
   - 既定の角度範囲は広いです（たとえば上腕 −90°〜150°、前腕 ±150°）。ドラッグの途中で引っかかることはありません。ある関節を制限したいときは、スケルトンの編集時にその最小／最大角度を小さくします。
   - ポーズ付けが変更するのはパラメータ値だけで、メッシュは変更せず、履歴も作りません。モードバーとキャンバスの右クリックメニューの「ポーズをリセット」は、すべてのボーンパラメータとポーズパラメータをゼロに戻します。右下の表示バーの「スキンウェイトを表示」は、ボーンの色で各頂点を塗り、関節の帯の色は 2 本のボーンの色の混合です。
3. **モーション**：モーションパネルには、現在のスケルトンが再生できるモーションが現れます。「モデルプリセット」→「モーション」グループにあるスイッチは「基礎モーション」（待機、まばたき、うなずき、首振り）と「ボーンモーション」の 2 つだけで、オフにするとグループ全体がモーションパネル、アニメーションエディタ、プレビュー、書き出しから取り除かれます。各モーションのスイッチと詳細パラメータは残り、開き直すと復元されます。個別のモーションは、モーションパネルで行ごとに有効にします。書き出し時にモーションにチェックがあると、対応する `motion3.json` が同時に書き出され、model3 の同名モーショングループへ登録されます。各プリセットは、下表の**ポーズ**と、頭と体の標準パラメータで構成されます。ポーズは 2 種類です。モデル内の**ポーズパラメータ**（しゃがみ、重心、膝の内また、弾み、尾振り、羽ばたき）は、作用がすでにモデルへベイクされていて、モーションはいつどの程度まで行うかだけを決めます。**ジェスチャ**（腕の振り、両腕の開閉、手を上げる、手を振る動き、片足を後ろへ跳ねる）はモデル内にパラメータがなく、モーションを書き出すときにボーン角度パラメータのカーブへ換算され、モーション自体が同じボーンパラメータに書く値と加算されます。脚のポーズ帯の上腕回転もジェスチャに属します。脚のポーズ（しゃがみ、重心、膝の内また）は加算だけで、同じモーションが使うのはそのうち 1 つで、残りは 0 のままです。弾みは着地を必要とせず、それらの上に重ねられます。スケルトンが再生できないポーズは省かれます。

   プリセットモーションは、角度が固定されたテンプレートではありません。生成時は、まず原画の静止スケルトンから各腕の向きと長さ、頭身比、顔の位置を読み、人体が楽な範囲（肩はおよそ 115° を超えず、肘は逆に折れず、手首は 35° を超えない）の中でポーズを求めます。たとえば手を振るときは手が顔の横、目の高さあたりで止まり、顔を隠さず、照れているときは両手を体の前で合わせます。時間の上では予備動作、イーズインとイーズアウト、ボーンチェーンに沿った段階的な遅れ、オーバーシュートからの落ち着きがあり、体の残りの部分（重心、体の傾き、頭）がそれに合わせます。Q 版の体型のモーションは、より弾みがあります。キーフレームは拍の上だけに置き、ベジェ曲線で遷移します。

| Idle（12 秒ループ） | 常時 | 立っている人のようにリラックスします。深さと長さの違う呼吸が 3 回、吸気は速く呼気は遅く、肩を上げて胸を広げ、体が少し遅れてうなずき、頭はさらに遅れます。重心は周期 6 秒と 4 秒の 2 成分の重ね合わせで、ループ内では繰り返しません。腰が先に重心を換え、上半身、体の向きが順に遅れて追従し、頭は逆にわずかに傾いて視線を水平に保ち、最後に頭を回し、自分でもゆっくり漂います。腕は自然に下がり、上腕、前腕、手が段階的に遅れて 2〜4° 揺れ、左右は完全には同期しません。尻尾はゆっくり揺れ、翼は呼吸に合わせます。スケルトンがないときは、体と頭の部分だけが残ります。カーブは折れ目にだけキーフレームを置きます |
| TailSwing（3 秒） | メッシュがバインドされた尻尾がある | 尾振り。既定は往復 3 回、1 回 1 秒 |
| Crouch（2.2 秒） | 脚のボーンがある | 先にわずかに持ち上げてからしゃがみ、体を前傾させ、頭を上げて前方を見、腕は少し遅れて体の前へ収めます。底部は軽く戻り、立ち上がるときはわずかにのけぞってから落ち着きます。重心は 0 のままです |
| WeightShift（3 秒） | 脚のボーンがある | 先に逆方向へ軽く押し、重心を片側へ移して安定させてから戻ります。体、頭が順に遅れて追従し、腕は慣性で 1 拍遅れて揺れます。しゃがみは 0 のままです |
| Shy（3 秒） | 脚のボーン、またはメッシュがバインドされた腕がある | 照れてもじもじします。先に目を上げて一瞥し、それからうつむいて首をかしげ、視線を外します。膝は内また、両手は体の前で合わせて小さくこすり、体は左右に小さくねじれます |

| HeadTilt（2.2 秒） | 脚のボーン、またはメッシュがバインドされた腕がある | 首をかしげます。先に逆方向へわずかに動き、それから大きくかしげ、少しオーバーシュートしてから 1 拍止まります。体と重心は少し遅れて同じ方向へ傾き、両手はわずかに内側へ収まります |
| Cheer（2.2 秒） | 脚のボーン、またはメッシュがバインドされた腕がある | 喜んで歓声を上げます。先にしゃがんでから跳び、踏み切りと着地に速度があり、着地は膝を曲げて緩衝し、2 回目の跳びは小さめです。両腕は 1 回目の跳びに合わせて頭の横の上まで振り出され、着地とともに上下し、下ろすときは肘が先に曲がります。頭を上げ、尻尾と翼が速く揺れます |
| LegKick（2.6 秒） | メッシュがバインドされた脚がある | 片足を跳ねます。重心を左足へ移し、右足を後ろへ跳ねて軽く揺らし、両腕を開いてバランスを取り、首をかしげます |
| Sway（3 秒） | 脚のボーン、またはメッシュがバインドされた腕がある | 楽しそうに揺れます。軽く押したあと左右に 2 回揺れ、徐々に弱まり、各部位が順に遅れて追従し、腕は慣性で揺れます |
| IdleCute（12 秒ループ） | 脚のボーンがある | 少女の待機です。Idle を基礎に、膝の内また 0.3、両手を体の前へ合わせるポーズを 30% 取り、腕はこのポーズの上で同様にリラックスして揺れ、重心のループはしません。Idle モーショングループへ書き出され、通常の Idle とは別の 2 つ目の待機モーションになります。プレビューでは 1 周再生します |

モーションパネルで各プリセットを展開すると、その詳細パラメータがあります。変更するとプレビュー、アニメーションエディタ、書き出しが同時に反映され、プロジェクトとともに保存され、取り消せます。

| モーション | 詳細パラメータ |
| --- | --- |
| Idle | 揺れ（重心、体、腕、尻尾）、呼吸（呼吸、体の上下、羽ばたき）、頭部（頭の 3 つの角度）、速度、まばたきのスイッチ |
| IdleCute | Idle と同じ。ほかに内寄せの程度（膝の内またと両手を合わせる割合、既定 0.3） |
| Blink | 閉じる程度、速度、2 連続のまばたき |
| Nod / Shake | 振幅、速度、回数（回ごとに前回より少し弱い） |
| TailSwing | 振幅、速度、回数 |
| Crouch / Cheer | しゃがみの深さまたは強さ、速度 |
| その他のボーンプリセット | 振幅、速度 |

振幅は、単発のモーションでは開始時の静止値を中心に拡大縮小し、ループモーションではカーブの平均を中心に拡大縮小します。目の開閉は振幅では変わりません。速度は、キーフレームの時間と長さを同時に拡大縮小します。アニメーションエディタでプリセットのキーフレームを変更すると、そのプリセットは手動上書きになり、詳細パラメータは一時的に効かなくなります。「既定に戻す」は、上書きとパラメータを同時に消します。右クリックメニューの「削除」は、プリセットを一覧と書き出しから取り除き、「新規モーション」メニューの「削除したプリセットを復元」で戻せます。パネル上の再生ボタンとアニメーションエディタは、同じ再生状態を共有します。クリックするとエディタでそのモーションを開いて再生し、もう一度クリックするかエディタで一時停止すると同期します。

物理演算を書き出すとき、尻尾の第 2 節以降の関節と翼は物理演算の駆動に渡されます。あるポーズに関わるボーンがすべて物理演算で駆動されるとき（たとえば羽ばたき）、Idle はそのポーズを書かなくなり、両者が衝突するのを避けます。物理演算が書くのはボーンパラメータで、尾振りと羽ばたきはその上に重ねるブレンドシェイプの変形なので、両方同時に効かせられます。

## ツール一覧

ボーンモードには、「ボーンのポーズ」と「ボーンを編集」の 2 つの主ツールがあります。ボーンの編集には 5 つのサブツールがあります。編集、新規ボーン、押し出し、バインド、ウェイトです。ボーンのポーズには自動 / FK / IK があります。サブツールはツールバーで主ツールの下に並び、切り替えても同じ下書きを保ちます。完了するか編集を離れると履歴 1 件として保存され、キャンセルすると下書きを捨てます。

| 領域 | すでにある操作 | 境界 |
| --- | --- | --- |
| 編集 | 単一選択、Shift による増減選択、矩形選択、ボーンチェーンの選択、平行移動 / 回転 / 拡大縮小、関節のドラッグ | 外側でつながった端点は同期します。変形は子孫を含めることを選べます |
| 新規ボーン | ドラッグで独立したカスタムボーンを作成し、プレビューを表示して自動選択 | 親は設定せず、メッシュのバインドを自動では継承しません |
| 押し出し | 選択ボーンの末端から子ボーンを伸ばし、連続して押し出せる | 作成されるカスタムボーンは毎回 1 本です |
| ツリー操作 | 既定の長さで追加、削除（子ボーンは元の親へ付く）、尻尾と翼のスイッチ、改名、親の設定 / 解除、関節の接続 / 切断、複製、ミラー、再分割、融合 | 親の候補は自身と子孫を除きます。接続は部分ツリーを平行移動し、切断は位置を残します。体のボーンは削除できません。再分割と融合は四肢のボーンだけに使います |
| バインド | 単一メッシュのバインド、クリック / 矩形選択 / 一覧のチェックによる一括バインドと解除、ハイライトプレビュー | 各メッシュが指定するバインドボーンは 1 本です。四肢の内部はウェイトを自動計算します |
| 関節の設定 | 関節の帯域、最小角度と最大角度 | 帯域は自動ウェイトの遷移を制御します。手作業のウェイトはウェイトサブツールで編集します |
| ポーズ | 自動 / FK / IK、IK の固定目標とソルバ設定、ポーズのリセット、名前付きポーズの保存 / 適用、アニメーションエディタへのスナップショット挿入 | 適用と挿入は、すでに存在しないパラメータを飛ばし、現在の範囲に制限します。IK の目標は制作にだけ使い、書き出すのは解いたあとの角度です |
| ウェイト | ボーンの色でスキンウェイトを表示、増減 / 置換 / 平滑、正規化 / クリーンアップ、複製 / ミラー | 角度スキニングと一致します。頂点ごとに 1 本、または隣接する 2 本のボーンです。一致しなかった頂点は自動ウェイトを使います |
| スケルトンの管理 | 自動推定、有効化と無効化、下書きの完了とキャンセル | 1 プロジェクトにスケルトンは 1 組です |
| サンプリングとモーション | サンプリング許容差、角度間隔、キーフォーム上限、ボーンのプリセットモーション | 「ボーン」タブとモーションパネルで設定します |

## 生成される構造

| オブジェクト | ID | 説明 |
| --- | --- | --- |
| 胴の曲げ | `DeformSkelTorso`（曲げデフォーマ） | 呼吸デフォーマの下にぶら下がり、呼吸デフォーマがもともと持っていたすべての子オブジェクト（胴、服、腕、翼、尻尾、頭の回転）を引き継ぎます。軸は上半身と下半身のパラメータです。腰の線より上は上半身、下は下半身に合わせて腰を軸に回転し、腰の遷移帯の中では滑らかに曲がります。脚はここに入りません。下半身が回転するときスカートと尻尾は一緒に回り、足は地面に残ります |
| ボーンの回転デフォーマ | `DeformSkel_<ボーン ID>` | 四肢、尻尾、翼にだけ生成されます。pivot はボーンの頭部（親ボーン末端の関節）にあり、ハンドルはボーンの方向に沿います（Cubism のハンドルは 0° で上を向き、時計回りが正なので、垂直下向きのボーンの `baseAngle` は 180° です。入れ子のデフォーマは、親ボーンに対する回転角だけを記録します）。ボーンの階層に従って入れ子になり、腕、翼、尻尾は胴の曲げの下、脚は脚の warp（`DeformLegs`）の下にぶら下がります。体のデフォーマに直接ぶら下がる腕と翼は、別に体の Y を軸にし、上体の前傾・後傾に合わせて透視で拡大縮小します（warp の拡大縮小は回転デフォーマへ伝わりません）。下にメッシュも子デフォーマもぶら下がっていないボーンはデフォーマを生成せず、同じメッシュ内部の関節（自分のメッシュを持たず、次の区間とだけつながっている）も単独では生成されず、次の区間のデフォーマへ入ります |
| Glue | `GlueSkel__<メッシュA>__<メッシュB>` | 同じ四肢が複数のメッシュに分かれているとき、継ぎ目上で位置が重なる頂点を自動で溶接します |
| ボーンパラメータ | `ParamArmLA`、`ParamArmLB`、`ParamHandL`、`ParamLegLA`、`ParamLegLB`、`ParamFootL`、`ParamTail1..n`、`ParamWingL` など | 単位は度です。正の値は、体から離れる方向への揺れを表し、左右は一致します。加算できる四肢のボーンパラメータはブレンドシェイプパラメータで、残りは通常パラメータです（「ブレンドシェイプのボーン」を参照） |
| しゃがみ | `ParamSkelCrouch`（0..1、ブレンドシェイプ） | 体が脚の長さの 10% 沈み、膝は観客の方向、やや外側へ曲がり、足は元の位置を保ちます |
| 重心移動 | `ParamSkelWeight`（-1..1、ブレンドシェイプ） | 腰が横へ移り、わずかに傾き、必要なら同時に沈んで、両足が地面に届くようにします。上体は逆に戻して正します。モーションの中では上腕があとから追従します（ジェスチャ） |
| 尾振り | `ParamSkelTailSwing`（-1..1、ブレンドシェイプ） | 尻尾が節ごとに片側へ巻き、尾の先に近いほど多く回ります |
| 羽ばたき | `ParamSkelWingFlap`（-1..1、ブレンドシェイプ） | 左右の翼が対称に羽ばたきます |
| 膝の内また | `ParamSkelKneesIn`（0..1、ブレンドシェイプ） | 体がわずかに沈み、膝が内側へ回り、足は元の位置を保ちます。モーションの中では上腕がわずかに内側へ収まります（ジェスチャ） |
| 弾み | `ParamSkelHop`（0..1、ブレンドシェイプ） | 体と脚の warp が全体として上へ移り、脚はそれに合わせて地面を離れます。しゃがみに重ねると、膝を曲げた跳びになります |

脚のポーズは、体の warp（腰の動き）と脚の warp（脚が 2 ボーン IK で曲がり、足裏は動かない）に作用するので、脚が同じレイヤーに描かれ、脚のボーンにメッシュがバインドされていなくても同様に使えます。脚が分割され脚のボーンへバインドされているときは、脚のボーンの回転デフォーマが別に IK で回転します。

次のジェスチャはモデル内にパラメータがなく、ボーン角度パラメータで再生されます。プリセットモーションの腕のポーズは体型から解かれ、そのうちここでいうジェスチャを使うのは LegKick の片足の後ろ跳ねだけです。

| ジェスチャ | 説明 |
| --- | --- |
| 腕の振り | 左右の腕が逆方向に振り、遠い関節ほど振幅が減ります |
| 両腕の開閉 | −1 は両手を体の前で合わせます（上腕、前腕、手がすべて体の内側へ回ります）。+1 は両腕を開いて上へ上げます |
| 手を上げる（右） | キャラクターの右腕だけを回します。肘を肩の高さまで上げ、前腕を立て、顔の横に置きます |
| 手を振る動き | 右の前腕と右手が左右に振り、手を上げる動きの上に重ねて使います |
| 片足を後ろへ跳ねる | +1 はキャラクターの左脚、−1 は右脚です。太ももをやや内側へ収め、すねを外側へ翻し、つま先もそれに合わせて跳ねます。重心の上に重ねられます |

## アルゴリズム

- **デフォーマの階層**：回転デフォーマが曲げデフォーマの下にぶら下がるとき、継承するのは支点の位置と角度だけで、上層の曲げの非剛体変形は伝わりません。曲げデフォーマが曲げデフォーマの下にぶら下がるときは、子デフォーマの制御点だけを変換します。そのため体のボーンは回転デフォーマを使わず、体のチェーンの末端にある細かいメッシュの曲げデフォーマにします。体の X/Y、体の Z、呼吸の曲げが胴のメッシュまで届き、肩と頭の支点も一緒に動きます。細かい腰の曲げはメッシュと四肢に直接作用し、粗いメッシュの上層デフォーマに再サンプルされません。曲げデフォーマは静止時には恒等写像なので、挿入してもどのオブジェクトも動かず、子オブジェクトの座標も変わりません。スケルトンを有効にしたあと、呼吸と体の Z の肩線・腰線は上半身ボーンから取るので、呼吸は腰より上だけを持ち上げ、体の Z は上半身ボーンの腰を軸に傾きます。脚の warp の股・膝・足首は脚のボーンから取ります。体のデフォーマの構造は[デフォーマとパラメータの仕様](../spec/DEFORMER_AND_PARAMETER_SPEC.md)を参照してください。
  ```
  DeformBodyXY（身体 X/Y：躯干转向，身体随髋部平移、下沉、站高；腿部姿势的髋部运动）
   └ DeformBodyLean（身体前后倾）
       └ DeformBodyZBreath（身体 Z、呼吸）
           └ DeformSkelTorso（上半身 + 下半身）
               ├ 躯干、衣服、裙子等网格
               ├ 手臂、翅膀、尾巴的旋转变形器
               └ DeformHeadRotation → 头部
  DeformLegs（身体 X/Y 和腿部姿势下的腿，脚掌不动）
   ├ 未绑定的腿部网格
   └ 腿骨的旋转变形器
       └ DeformSkel_<骨骼 ID>Stance（身体 X/Y 下的站姿）→ 绑定到这根骨骼的腿部网格
  ```
- **腰の曲げ**：上半身と下半身は、どちらも腰（ボーンの頭部）を軸にします。ボーン方向に沿った腰までの距離は、「関節の帯域」の中で smoothstep により遷移し、帯の外では完全に剛体回転します。既定の半幅はボーン長の 25%、上限は 45% で、スケルトンの編集時に上／下半身を選択して調整できます。
- **剛体部分**：回転デフォーマが補間するのは角度であり、頂点位置ではありません。そのためパラメータがどの値でも四肢は正確な剛体回転になり、キーフレームの間で短くなりません。いくつかの関節が同時に回るときも、キーフォームを掛け合わせる必要はありません。
- **ウェイト**：各頂点が追従できるのは、関節の両側のボーン最大 2 本です。頂点に最も近いボーンが主ボーンです。主ボーン両端の関節帯の中では、関節の角の二等分線までの符号付き距離を smoothstep で遷移します。関節帯の既定の半幅は、2 本のボーンのうち短いほうの 35%、上限は 45% なので、同じボーンの両端の関節帯は重なりません。
- **角度の混合**：関節帯の中の頂点は、関節の周りを「ウェイト × 相対角度」だけ回転し、2 つの剛体位置の間を線形混合（LBS）するのではありません。これで頂点から関節までの距離は変わらず、曲がっても四肢の幅は変わらず、肘の内側は潰れません。
- **メッシュをどこに掛けるか**：
  - 各メッシュは、優先して、**そのメッシュが覆う関節のうち体に最も近いもの**に対応する回転デフォーマの下に掛かります。これでメッシュと前の区間との接続はデフォーマが直接担い、遠いボーンが回っても接続がキーフォーム補間で打ち消すことに依存しません。メッシュがどの関節も覆わないときだけ、ウェイトとパラメータの結合の程度で、掛けるボーンを選びます。メッシュがほかのボーンまで伸びている部分は、それらのボーンの角度を、メッシュ自身のキーフォームへ書きます。
  - **未分割**（1 枚のメッシュが四肢全体を覆う）：メッシュが肩、肘、手首を含むなら上腕の下に掛かり、肩の接続は上腕に正確に追従します。肘と手首はメッシュのキーフォームの中で曲がります。ストッキングが太ももの途中から足首まで描かれ、股関節は覆わないが膝関節は覆うなら、すねの下に掛かります。上の太もものデフォーマは、引き続き股の支点として脚全体を回します。下にメッシュがないボーン（たとえば足）はデフォーマを生成しません。
  - **分割済み**（区間ごとに 1 枚のメッシュ）：各区間は自分のボーンの回転デフォーマの下に掛かります。関節帯の頂点は引き続き位置でスキニングされ、2 つの区間は重なる場所の変形が完全に同じなので、継ぎ目は裂けません。継ぎ目上で重なる頂点には、別に自動で Glue が付きます。
  - **中間の関節**（たとえば太ももとすねが 1 枚のメッシュで太ももの下に掛かり、足は別の 1 枚）：各メッシュの回転デフォーマは最大 1 つで、すねは単独では生成されません。足の回転デフォーマは太ももの下に直接掛かり、すねのパラメータを自分のキーフォーム軸にします。角度は直接加算され、pivot は膝の円弧に沿ってキーを取り、キー間隔は膝までの距離から取るので、pivot が円弧から外れる量は 1px を超えず、メッシュの精度と一致します。すねがブレンドシェイプパラメータのとき、この部分も同様にブレンドシェイプとして書かれます。
- **補正キーフォーム**：キーフォームの軸は、関係する関節のパラメータだけです。各軸は 0 の両側をそれぞれ等分し、2 つのキーの間の線形補間が本物の円弧から設定許容差を超えて外れない、最少のキー数を取ります。既定の許容差は 1px、最小角度間隔は 7.5° です。関節に近い部位（たとえば関節帯だけが影響を受ける）はキーが疎で、掛けたボーン以外の長い剛体部位だけが密なキーを必要とします。単一メッシュのキーフォーム総数の既定上限は 600 で、超えるときはキーが最も多い軸から減らします。各キーフォームは、ランタイムが実際に構築するデフォーマ変換で計算されるので、剛体部分の着地点はデフォーマと完全に一致します。完全に正確にする必要があるときは、四肢を区間へ分割します。
- **ブレンドシェイプのボーン**：キーフォームメッシュは、軸の組み合わせごとに形状を 1 つ保存するので、肘と手首の 2 関節をまたぐメッシュは「前腕のキー数 × 手のキー数」個のキーフォームを保存します。どの頂点も 2 本のボーンから同時に影響を受けないなら、2 つの関節の曲がりは単純な加算なので、ブレンドシェイプに切り替えると必要な形状は「前腕のキー数 + 手のキー数」個になります。書き出し対象が Cubism 5.0 以上のとき、この条件を満たすボーンパラメータはブレンドシェイプパラメータです。回転デフォーマは静止形状を 1 つだけ残し、回転角はブレンドシェイプが最小、0、最大の 3 キーの間を線形補間し、結果は引き続き正確な剛体回転です。メッシュのこのボーン上の補正も、ブレンドシェイプへ変わります。パラメータの型はモデル全体で 1 種類だけなので、どこか 1 か所でも掛け算が必要なら（頂点が 2 本のボーンから同時に影響を受ける、または連続する 2 つの中間関節が同じ回転デフォーマへ折りたたまれる）、そのパラメータは通常パラメータのままです。尻尾と翼は物理演算が読み書きするため、常に通常パラメータです。掛けるボーンは、先に関節の被覆範囲で決め、接続を安定させます。メッシュが関節を覆っていないときだけ、各関節を互いに独立させられるボーンを優先して選びます。

- **関節形状テンプレート**：膝と肘の外側の形状は、MHR v1.0.1 人体モデルのポーズ参照から取ります（`src/main/resources/skinning/mhr-joints.tsv`。`tools/research/extract_mhr_joint_templates.py` が抽出し、許諾は `licenses/MHR.txt`）。関節の種類ごとに軸方向断面 25、角度 11 で、伸ばした関節の半幅で正規化します。`SkeletonJointTemplates` は、メッシュ境界と関節の横断面の交点で幅をフィットし、線形スキニングに対する局所残差を得て、関節の両側およそ 3 半幅以内にだけ作用し、滑らかに減衰します。手作業のウェイトは再計算されません。横断面をフィットできるすべての接続関節（手首、足首、カスタムのボーンチェーンを含む）の内側は、同じ規則で曲げの角の二等分線へ折りたたまれ、内側の混合帯は重なりと裏返りを許し、外側と折りたたみに参加しない面は引き続き三角形の向きを検査します。参照は単一の中立体型を曲げ平面へ投影した二次元で、静止の挟角が 25° を超える、横断面が閉じない、または広すぎるボーンチェーンの外側は、基礎の ARAP を残します。新しいボーンの関節帯は既定で軸方向間隔 16 で、ボーンのサンプリングパネルの「関節メッシュ密度」で調整できます（ボーン JSON バージョン 10 は `sampling.jointMeshSegments` を保存し、古いファイルの欠測値は 4 です）。
- **関節の密度**：バインドされたメッシュは、各関節帯の中で角の二等分線方向に「関節メッシュ密度」+1 行の頂点を挿入します（既定は間隔 16、17 行。この設定がない古いスケルトンは間隔 4、5 行）。行と外側輪郭の交点には必ず頂点が挿入され、輪郭が弧を描けるようにします。新しい頂点は元の頂点のアフィン結合なので画面は動かず、既存のキーフォームと Glue は自動で再マップされます。ベイクを繰り返しても頂点は増えません。
- **柔軟なボーンチェーン**：ボーンは中心線の制御ポリゴンで、パスデフォーマのハンドルのようなものです。中心線は根元のボーンの頭部からボーンに沿って進み、各関節で角を丸め、最後は末端ボーンの尾端に着地します。角の丸めは、関節の前後から同じ距離（両側のうち短い節の半分）を取り、有理二次ベジェ（中間制御点は関節そのもの、ウェイトは cos(転角/2)）でつなぎます。両側が等長のときはちょうど円弧になり、曲がりは関節に集中せず丸めの中へ均等に分布します。そのためボーンをどう切っても曲がりは滑らかです。短いボーンの間は詰まった小さな丸め、長いボーンの中間は直線で、曲線全体の接線は連続し、逆方向へ折れません。尾の先は常にボーンの尾の先にあり、メッシュがボーンより短くなることはありません。分岐では、茎が分岐点まで真っすぐに進み、各葉は分岐点から曲がり始め、1 枚の葉を回しても茎ともう 1 枚の葉は影響を受けません。分岐点の近くでは、葉のメッシュが「茎の末端に合わせて剛体回転する」から「葉の曲線に従う」へ滑らかに遷移し、遷移距離は葉の半節の長さで、凹角で引き裂かれません。
  - **連結だけでバインド**：各ボーンに沿ってサンプルし（画面のメッシュ内に落ちるサンプルだけを取り、ボーンが原画の外へ出た部分は参加しません）、サンプルに最も近い頂点を種にします。そのあとメッシュの辺に沿って多ソース最短路を行い、各頂点はメッシュ距離が最も近い種のボーンへ帰属します。巻いたあとでくっついていても、メッシュ上でつながっていない 2 区間の尻尾は、互いに引っ張りません。弧長は、頂点が原画曲線上で最も近い点を取り、所属ボーンとその前後各半節の範囲だけで探します。頂点は弧長と、曲線までの横オフセットを覚え、そのあと曲線の局所座標系とともに全体が回転し、中心線からの距離にはよりません。柔軟なボーンチェーンの頂点は曲線だけで決まり、関節テンプレートと ARAP は通りません。剛体の親ボーン（たとえば手のひら）と柔軟な根本ボーンの間は、引き続き通常の関節帯で遷移します。
  - **弧長**：弧長はボーンの静止長で計算され、各区間の曲線はそれが表すボーン長に対応して比例写像されるので、ボーンがどう曲がっても、頂点はその節のボーン上の相対位置を保ちます。
  - **ベイク**：ボーンチェーンの根元は、引き続き正確な回転デフォーマです。メッシュが 1 つか 2 つの関節からしか影響を受けないとき、曲がりはメッシュの補正キーフォームへ書かれ、キー数は剛体のボーンチェーンと同じ許容差でフィットします。メッシュ全体が柔軟なボーンチェーン上にあり、3 つ以上の関節から影響を受けるとき（長い尻尾、分岐のある魚の尾）は、関節ごとに入れ子の曲げデフォーマ（`DeformSkel_<ボーン ID>Flex`）へ切り替えます。キーフォームメッシュはすべての関節のキー数の積を保存する必要があり、6 関節では上限 600 の下で各関節に残るのは −90°、0、90° の 3 キーだけで、中間まで回すとメッシュは 2 つのキーの形状の間を線形補間して明らかに短くなります。入れ子の曲げデフォーマはそれぞれ自分のパラメータだけを軸にし、キー数は加算され、1px の許容差で十分に取ります。各デフォーマは、丸めよりあとにある部分を関節の周りに回します。丸めの中の各点は、丸めの弧長上の割合に従い、曲線上の同じ割合の点と接線方向へ剛体移動するので、丸めは曲がる方向へすぼみ、関節の前の部分が逆方向へ振り出されることはありません（ウェイトだけで関節の周りに回すと、関節の前の部分は逆方向へ振れ、数節が一緒に曲がると波になります）。これは、曲線が曲がり終えたボーンの上にあるときの姿そのものなので、デフォーマがどこまで回ってもメッシュはそのときのボーンの曲線上に落ち、尾の先はボーンと一致します。分岐では、葉が分岐点から葉の中点まで、ウェイトに従って分岐点の周りを回転します。メッシュ点の弧長は、最も近いメッシュ頂点の弧長を取ります（連結だけによるバインドから）。メッシュ間隔は、つながっていない隣接部分の間の最も狭い隙間に合わせて密にし（最大 64×64）、内側のデフォーマはメッシュを外側のメッシュの空白へ回し、空白は回された部分が受け取るべきウェイトを取ります。パラメータ、物理演算、尾振りなどのポーズは変わらず、尾振りはブレンドシェイプとして各デフォーマに加算されます。柔軟なボーンのパラメータはブレンドシェイプにしません。
  - **真っすぐに**：真っすぐにする前に、ボーンチェーンの茎（根本ボーンから分岐点または尾の先まで）を原画の中心線へ貼り付けます。ボーンチェーンに沿って 6px ごとに原画輪郭の中間位置を取り（断面の前後幅が 6 割しかない端部の切り口は数えない）、最小二乗で各関節を動かし、中心線の曲線がこれらの点を通るようにします。根本ボーンの頭部は動かず、各関節には元の位置へ戻る弱い制約が少し付き、分岐後の葉は分岐点とともに平行移動します。中心線が原画に沿っていないと、展開後に各所のずれの距離が直線の両側へそのまま残り、波になります。関節が原画の中心線上に描かれているとき、曲線は曲がりで曲げの内側へ切り込みます。貼り付けたあと真っすぐにします。各ボーンは `drawnBend`、つまり原画がそのボーン頭部で、ボーンの静止ジオメトリより余分に曲がっている角度を記録します。バインドは原画ジオメトリ（静止スケルトンを `drawnBend` で曲げ戻したもの）の上で行い、静止メッシュは静止曲線の上に置きます。各関節は `drawnBend` を追加のキーにするので、原画のポーズはキーフォーム上で正確に復元されます。ボーン JSON バージョン 11 は `flex` と `drawnBend` を保存します。バージョン 11 より前のスケルトンを読むとき、尻尾のボーンチェーンは自動で柔軟なボーンチェーンになります。入れ子の曲げデフォーマを通るメッシュも同様に静止曲線の上に置かれ、デフォーマが原画の曲がりまで回るとメッシュは原画の曲線へ戻るので、原画のポーズはメッシュ精度の範囲で復元されます。
  - **別の場所へ掛けたメッシュ**：履歴によって非ボーンのデフォーマへ掛けられた（または自分の warp に包まれた）メッシュはベイクを通らず、履歴の再生後にスキニングされます。これも柔軟なボーンチェーンの曲線に沿って曲がります。真っすぐにするとき、このステップはメッシュの静止頂点を動かせないので、「原画から展開して真っすぐに至った」変位を、その各キーフォーム（静止キーを含む）へ書き、ブレンドシェイプは静止キーから量ります。
- **ポーズパラメータとジェスチャ**：関節をまたぐメッシュは、関節の反対側の部位を自分の形状の中に書くので、その部分がどこに落ちるかは関節の**合計角度**によります。ブレンドシェイプが足せるのは、各パラメータが単独で生んだ変位だけで、同じ関節を 2 回に分けて回した変位の和は、一度に合計角度を回した変位と等しくありません。ポーズがボーン角度の上に重なる、または 2 つのポーズが同じ関節を回すとき、四肢はボーンから外れ、角度が大きいと偏差は数百ピクセルに達します。そのため四肢の関節は、自分のボーンパラメータだけで回転します。四肢の関節だけを回すポーズはジェスチャで、モーションがボーン角度へ換算して再生します。モーションの各軌跡はキーの間が時間上の三次曲線（ベジェハンドルは時間の 1/3 に固定）で、ポーズは隣り合うキーの間が線形なので、ボーン曲線もこれらの時刻の間は三次曲線です。換算時は、各キーと、ポーズが自身のキー値を通過する時刻で点を取り、両側の傾きを付けるので、ボーン曲線はポーズと完全に一致します。モデルに残るのは、ボーンパラメータでは代替できないポーズだけです。脚のポーズの腰の動き（IK と合わせて両足を地面に付ける）と上半身を戻して正すこと、および物理演算が駆動する尻尾と翼です。これらはブレンドシェイプの形で関係するオブジェクトへ重ねられます。体と脚の warp（腰の動きと脚の曲がり）、胴の曲げ（上半身を逆に戻して正す）、ボーンの回転デフォーマ（脚の IK 回転角、尻尾と翼の回転角）、スキンメッシュ（関節帯の曲がり）です。脚のポーズと、手で回した足首などの脚の角度を重ねるときは、上述の誤差が残ります（たとえば完全にしゃがんでから足首を 40° 回すと、つま先がおよそ 10px ずれます）。プリセットモーションの中でこのように重ねるのは LegKick だけで、偏差はおよそ 2.5px です。
- **脚の姿勢**：しゃがみと重心移動は、各キー値で腰の位置から解きます。脚の warp の中の各脚は、股、膝、足首の 2 ボーン IK で曲がります。脚は原画の横方向の曲がりを保ち、余分な曲がりは観客の方向を向き、正面から見ると太ももは短くなって外へ振られず、そのあとポーズに合わせて内側または外側へ回ります。足裏の行は固定です。腰の横移動で脚が原画の真っすぐさまで届かなくなると、腰は自動で沈み、両足が届くようにします。メッシュがバインドされた脚のボーンは、ランタイムの実際の腰の位置で 2 ボーン IK により回転を解き、膝は外側へ曲がり（膝の内またのときは内側）、足裏は水平を保ちます。体の X/Y は、脚のボーンの下の立ちポーズ warp が担います。回転デフォーマは脚の warp の曲がりを伝えられないので、メッシュが掛かっている各脚のボーンの下には、体の X/Y を軸とする warp（各 3 キー）が 1 つあり、各キー値の制御点はランタイムの実際のボーン位置から逆算され、メッシュが脚の warp の与える位置に落ちます。腰は体とともに動き、膝は曲がり、足裏は動かず、未バインドの脚と一致します。各ポーズは残りを 0 として解き、同時に効くときは単純な加算なので、足が動かないままなのは、そのうち 1 つの振幅がとても小さいときだけです。プリセットモーションは、そのためしゃがみと重心移動を同時には駆動しません。
- **書き出しの要件**：回転デフォーマ上のブレンドシェイプには Cubism 5.0 以上が必要です。書き出し対象が 5.0 未満のとき、すべてのボーンパラメータは通常パラメータのキーフォームへベイクされます。回転デフォーマ上のポーズは取り除かれます（書き出し時に案内が出ます）。

## 制限

- **左右が 1 つにまとまったメッシュはバインドされません。** 四肢のレイヤーは、インポート後に「モデル → モデル全体の独立メッシュを確認…」で、メッシュごとに左右 1 つずつへ分割してください。両脚または両足がまだ同じレイヤーに描かれていると、自動推定は 2 本の脚のボーンを作りますが、このメッシュはバインドせず、しゃがみと重心移動も生成されません。先に分割し、そのあと「スケルトンを編集」で別々にバインドします。
- **手でトポロジを変えたメッシュは密度を上げません。** 履歴に手作業のトポロジ編集（再分割、頂点配置など）があるメッシュは、その編集が頂点番号で再生されるので、ボーンはそこに頂点を挿入しません。曲がる場所が十分に滑らかでないときは、関節に手で点を足してください。
- 柔軟なボーンチェーンの両側がとても広いとき（たとえば広い魚のひれ）、曲げ半径が半幅より小さい場所の内側は折りたたまれます。関節の制限を小さくするか、広い部分を分岐へ分割できます。原画自体が自分へ折れ返る急な曲がり（帯域が曲がり半径より大きい U 字）も同様です。内角の頂点は曲率中心の反対側にあり、開くかさらに曲げると面が裏返ります。
- 真っすぐにしたあと、柔軟なボーンチェーンの下に掛かる柔軟でない子ボーンは、引き続き静止ジオメトリでスキニングされ、展開には追従しません。
- 入れ子の曲げデフォーマを使うメッシュの精度は、メッシュ間隔に制限されます。隣り合い、つながっておらず、数ピクセルしか離れていない部分が急な曲がりにあるとき、原画のポーズは数ピクセルずれることがあります。帯の半幅より小さいヘアピン曲がり（たとえば幅 16px で、中間が 4px しか離れていない U 字）では、偏差が十数ピクセルに達することがあります。
- 真っすぐにする貼り付けが使う自由度はボーンの本数だけです。数節のボーンで大きな曲がりを回るとき（たとえば 3 節で 200°）、展開後の中心線にまだ数ピクセルの起伏が残ることがあり、先にボーンを再分割してから真っすぐにできます。貼り付けは関節を動かすので、メッシュの関節の再分割も切り直され、頂点数が変わることがあります。
- より古いバージョンで保存したプロジェクトで、再生成のマージがかつて尻尾のメッシュの掛け先を変えていなかった場合、そのあとのマージはそれをずっと「ユーザーが掛け替えた」ものとして扱い、ボーンの変化（真っすぐにすることを含む）はもう作用しません。品質レポートに `REGENERATION_CONFLICT` と「修復可能」の案内が出るので、「生成結果を更新」を一度実行すると復元できます。
- 真っすぐにしたあとの長さは、ボーン長に沿って展開されます。曲線は曲がりでボーンの折れ線より少し短いので、原画の曲がりが強いほど、展開後は少し長くなります（4 節のボーンで 90° 回るとおよそ 3% 長くなります）。
- 真っすぐにしたあと、手描きのウェイトは引き続き原画の位置でサンプルされますが、エディタでウェイトを掴む／描くときに読むのは真っすぐにしたあとの静止位置なので、両者はずれます。真っすぐにしたボーンチェーンには、自動ウェイトを使うことを勧めます。
- およそ 90° を超える曲げでは、関節の内側に重なりが出ます。Spine の線形スキニングと同じで、関節の帯域を調整するか、原画を分割して改善します。
- ボーンをベイクしたあと、Cubism Editor にはボーンとしての意味は残りません。ボーンを変え続ける必要があるときは、本プログラムのプロジェクトファイルを残してください。
