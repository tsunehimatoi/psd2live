# プリセット

明示的なスタックを持つプロジェクトでは「プリセット」パネルが表示されます。古いプロジェクトを開いたときは、これまでどおりのプリセットパネルを使い続けます。「編集可能なプリセットへ変換」で明示的に変換できます。現在確認済みなのは、通常の素材、基礎となる旧版バインド、複数の部位と追加モジュールを含む現代のプリセットの用例です。ほかのプロジェクトは、結果に差があるために拒否されることがあります。停止済みの旧シミュレーションは停止インスタンスとして残り、有効な旧シミュレーションは、既存のベイクが候補入力と一致している必要があります。ソース画像のバインドは、新しいパネルで追加、調整、並べ替え、確定できます。スイング、物理グループ、シミュレーション、生成モーションも、同じ入り口から追加し、スタック内で調整できます。スタートページのクイック構成も、隔離した変換を通して明示的なモディファイアを追加します。

## PSD プロジェクトの新規作成

「旧版」「新版」は、同じプロジェクトモデルの下にある 2 組のモディファイアグループのプリセットであり、2 種類のプロジェクトバージョンではありません。スタートページの「推奨プリセット」は、新版グループのフィットバインド、追加モジュール、物理演算、モーション、衣装シミュレーションを直接追加し、スタックが一括して評価します。古いモデルを先に生成してから変換するのではありません。「標準」のモジュール等級で機能を削ることも、もうありません。失敗またはキャンセルでは、部分的なプロジェクトはインストールされません。

## 追加と切り替え

1. メッシュを選択するか、未選択のまますべてのメッシュを扱います。追加後の対象は固定され、選択が変わっても変わりません。
2. 「プリセットを追加」は部位で分類されます。同じ部位の旧／新アルゴリズムは一緒に並びます。衣装、前髪、後ろ髪のシミュレーションは対応する分類にあり、パーツを自動認識して材質、ウェイト、ベイクのバインドを作ります。汎用ジェネレーターは詳細分類にあります。
3. 項目をクリックしただけでは、依存関係と追加一覧を計画するだけで、確定したときにコストの高い評価を実行します。重ねられず、選択した対象がすべてすでに持っている項目は表示されなくなり、無効な項目も既存として数えます。一部の対象がすでに持っているときは既存数を表示し、まだ覆っていない対象だけを補います。重ねられるスイングやモーションなどは、引き続き追加できます。
4. 「プリセットを切り替え」は、テンプレートメニューで新版、旧版、またはカスタムテンプレートを選び、シミュレーションの方式とモジュール数（空、基礎、簡略、標準、完全）を選びます。適用すると元のスタック全体が置き換わります。通常のオーサード内容は残り、切り替え 1 回が履歴ノード 1 つになり、取り消しで元のスタックに戻ります。

旧版は元の基礎アルゴリズムと既定の動的設定を使い、新版は再構成前の完全な現代のレシピを使います。体に沿った衣装にシミュレーションが不要なときはスキップし、グループ全体の生成は止めません。自動ウェイトは、個別に追加したシミュレーションインスタンスとともに保存され、同名のオーサードウェイトがすでにあるときはそれが優先されます。グループ全体の切り替えは、現在のところ、生成内容の上書きや確定済みのプリセット能力に出会うと明示的に拒否し、編集を捨てません。先にそれらの内容を処理する必要があります。テンプレートメニューの数量段階は、テンプレートを明示的に選んだときだけモジュールを絞り込みます。通常のインポートとコマンドラインは、引き続き設定済みのレシピで初期化します。

パネルには 2 つのモードがあります。「設定」はフォルダにまとめ、既定では用途でグループ化します。フォルダの追加、改名、削除ができ、モディファイアとフォルダをドラッグして位置を整理できます。整理は評価順序を変えず、モデルも再計算しません。「並べ替え」はフラットな一覧を表示し、パラメータ一覧と同じドラッグ操作で実際の評価順序を調整します。不正な依存順序は引き続き拒否されます。新しい項目は前置項目を自動で伴い、既存インスタンスは並べ替えません。フォルダの配置はプロジェクトとともに保存され、取り消しとやり直しができます。

「プリセットを切り替え」には、新版ライト、新版リッチダイナミクス、旧版ライトの組み合わせもあります。テンプレートメニューの下部では、現在の構成の保存、JSON のインポートまたは書き出し、選択したライブラリプリセットの削除ができます。保存に含まれるのはモディファイアの構成とフォルダで、生成内容上のオーサード上書きとベイクキャッシュは含みません。シミュレーションは適用時にベイクし直します。ユーザープリセットと組み込みプリセットは、どちらも JSON としてアプリの設定にあり、組み込み項目が欠けているときは、まずプログラムに同梱された JSON から復元し、そのあと同じパスで読みます。プロジェクトをまたいで適用するときは、安定したオブジェクト参照、または同名同型で一意なオブジェクトで対象を特定します。一意に一致できないときはエラーになり、作用範囲は広がりません。

共通構造モディファイアの「顔の特徴の変位」は、もとからある変形階層を使います。頭と顔のバインドがその後ろにある場合、共通構造を確定したあともその階層は残ります。

新しく追加する共通構造はバージョン 2 を使い、同じ対象グループの親を共有して、メッシュごとに完全な親チェーンを複製しないようにします。共有構造のあとに続くバインドは、そのグループの対象をすべて覆う必要があります。異なるオーサードの親の下にある対象は、同じ構造へまとめられません。保存済みのバージョン 1 のスタックは、引き続き元のオブジェクト ID で再生され、今回は古い分岐を自動ではアップグレードも統合もしません。

## 調整と位置指定

一覧のプリセットをクリックすると、右側で完全な数値を直接調整できます。頭の回し方、強度、各詳細を含みます。一覧は行の高さを詰め、左右は独立してスクロールし、中央の区切りはドラッグして幅を調整できます。数値はインスペクタのレイアウトを踏襲します。物理演算は現在の入力、出力、またはセグメントを編集し、モーションは現在のトラックとキーフレームを編集します。

「対象」と「生成内容」は、それぞれ作用オブジェクトの位置指定と実際の寄与を示します。「ここまで適用」は、現在の項目の操作に残ります。

顔には互いに排他な基礎アルゴリズムが 2 つあります。`face/legacy`（旧アルゴリズム）と `face/fitted`（フィットした頭の回転）です。同じ対象で同時には有効にできません。フィット項目の内部は既存のフィットアルゴリズムを再利用し、下流が必要とする頭と顔のパラメータを提供します。旧顔項目は別に足しません。古いプロジェクトの `face.depth-turn` 記録は引き続き再生され、新しく追加する入り口は `face/fitted` を使います。単項目の追加が頭と顔の依存を必要とするときは、対象上にすでにある旧顔の提供者を再利用します。提供者がないときは、既定でフィットした顔を追加します。旧顔または旧アルゴリズムグループを明示的に選んだ場合は、引き続き旧アルゴリズムを使い、既存のスタックは自動では書き換わりません。

「並べ替え」モードでモディファイア名をドラッグすると、実際の評価順序が変わります。ドラッグの残像と隣の行の譲りは、パラメータパネルと実装を共有します。依存に反する移動は拒否され、元のスタックは変わりません。スライダーの連続ドラッグや数値入力は、終わったときに履歴ノードを 1 つだけ確定します。

無効にすると、もう評価されません。それに依存する下流項目はスタックに残り、「依存関係が不足」と表示されます。元のインスタンスを再度有効にすると、その上書きを復元できます。削除も同様に休眠中の上書きを残し、取り消しで復元できます。別に追加した新しいインスタンスは、削除済みインスタンスの編集を継承しません。

生成されたメッシュ、パーツ、デフォーマは、通常のエディタで改名し、適用できる静的な見た目を調整し、デフォーマの付け替えや階層の移動ができます。参照するオブジェクトは、その項目の評価時にすでに存在している必要があります。生成パラメータの改名、範囲、既定値の調整は、そのパラメータを提供するインスタンスとともに保存されます。下流のパラメータ定義と衝突する調整は拒否されます。編集は、オブジェクトを作成したモディファイアに追従し、無効のときは休眠し、再度有効にすると復元されます。

モディファイアが生成したオブジェクトのトラックには、キーフォームの挿入、移動、削除ができます。コマンドが異なるインスタンスに属するトラックを同時に変えるときは、具体的なトラックを選んでください。生成パラメータのパネルキーも、そのパラメータを提供するインスタンスとともに保存されます。

変形ツールは「ジオメトリ補正の方式」を共有します。既定の「相対補正」は局所的な変化を保存し、そのあとモディファイアを調整すると補正が引き続き加算されます。「固定した修正値」を選ぶと、今回の修正の値が残り、生成結果もそれを変えたときは衝突を報告します。この選択は、ブラシ、頂点と変形の編集、Bezier、キーフォームのジオメトリコマンドに一貫して効きます。履歴は自動では書き換わりません。API の明示的なキーフォーム代入は、既定では固定上書きのままで、`correction_mode` で明示的に選べます。トポロジ、UV、または親のバインドが変わったあと、確実に対応できない補正は残して不一致を報告し、ほかの頂点には被せません。変形モードは既定で現在のパラメータ値を保ち、必要に応じてキーフォームを追加します。「最も近い共通キーフォームへ吸着」を選ぶと、複数選択したオブジェクトはパラメータごとに一括して吸着します。共通のキー値がないときは、単一トラックを選ぶか、キーフォームを補うよう案内します。この方針は各変形ツールに適用されます。

書き出しがランタイムのリアルタイムシミュレーションに対応する形式のとき、有効でベイクが有効なシミュレーション項目はモデルとともに書き出され、同じ評価で生成されたパラメータと物理グループを参照します。

### パーツのサブ設定と物理演算

「設定」一覧で、目、眉、口と下半顔、頭と顔、体、または髪を選び、右側の「調整」ページを開きます。「基礎設定」には、そのパーツの現在の基礎アルゴリズムのパラメータが収まります。「モード」の選択があるときは、ここで現在の基礎アルゴリズムを確認できます。各パーツが提供するサブ機能は異なり、パネルに並ぶ項目が基準です。

1. サブ機能名の横の矢印をクリックして設定を展開します。名前の前のチェックボックスをオンにするとその機能が有効になり、オフにすると停止します。折りたたみはコントロールをしまうだけで、停止後も局所設定は残り、再度有効にすると引き続き使えます。
2. 「独立した作用オブジェクト」を展開すると、そのサブ機能自身のオブジェクト一覧が見えます。「パーツの作用オブジェクトを継承」と表示されているときは、所属パーツのオブジェクトを使います。タイトルの右側に数が表示され、オブジェクト名をクリックするとキャンバスまたは対応パネルで位置を特定できます。キャンバスでほかのオブジェクトを選んでも、この一覧は変わりません。
3. 展開領域で、その機能の数値を調整します。たとえば「口と下半顔 → 唇の線」では「線幅」を調整し、6 桁の RGB 16 進色を入力するか、「縁の色をサンプル」をクリックして自動の色取りに戻せます。色の入力は Enter、またはフォーカスを外したあとに確定します。スライダーの連続ドラッグや数値入力は、終わったときに履歴を 1 歩記録し、取り消しとやり直しができます。

物理演算を持つサブ機能には「物理演算」チェックボックスも表示され、その機能の物理生成を有効または停止します。その下の矢印付き「物理演算」行は、具体的な物理グループを展開します。展開したあと、入力、出力、または振り子のセグメントを選び、ウェイト、スケール、各セグメントのパラメータを調整します。物理演算のスイッチをオフにしても、既存の局所設定は残ります。先にサブ機能を有効にして依存を補うよう案内されたときは、それらの条件を先に処理してから、生成された物理グループを編集します。

これらの局所設定は、所属パーツとともにプロジェクトへ保存されます。調整が終わったら `Ctrl+S` を押し、[保存状態](USER_GUIDE.md#2-保存状態と復元)を確認してください。「復元コピーを保存しました」のあとも、`.psd2live` のプロジェクトファイルは保存が必要です。

変形モードの「編集段階」では、自動の帰属、モディファイアより前の基礎、有効ないずれかのモディファイアのあと、または現在のスタックの末尾を選べます。キャンバスはその段階の形状を表示し、ピックとキーフォームへの吸着もそれを基準にします。基礎の編集で使えるのは、その時点ですでにあるパラメータだけです。指定した段階の補正は対応するノードのあとに保存され、そのあと下流の実行が続きます。スタックの末尾を選ぶと、今回の編集時の末尾ノードへのバインドが記録され、そのあと追加したモディファイアが古い記録を自動で移動することはありません。段階が使えないときは、その選択を抜けて案内し、無効なノードへの書き込みは続きません。

## モディファイアの適用

適用ボタンの上には、先に、確定する項目、接頭辞とともに取り除く停止項目、残して再評価する下流、適用境界をまたぐ明示的な依存が並びます。手作業の修正は、統合する数と休眠する数を別々に示します。「選択したモディファイアを適用」または「ここまで適用」を選べます。選択した項目は確定後も元の評価位置を保ち、上流と下流は元の順序で実行を続けます。基礎へ先に入れてから上流を繰り返すことはありません。互換性のない上流入力の変化は拒否され、適用を取り消すか、依存を一緒に適用する必要があります。有効な項目のいずれかに失敗、依存の不足、孤立した補正があると適用は止まり、残す下流も含まれます。バックグラウンドの確定は完全な結果を再検査し、画面上の計画は確定の検証に代われません。旧式の固定上書きの衝突は手作業の値を残し、画面が案内したうえで現在の結果の適用を許します。

「ここまで適用」は、現在の項目とその前までの有効な結果を通常の編集可能な内容として確定し、接頭辞全体を取り除きます。無効な項目も接頭辞とともに取り除かれ、現在の評価には参加しません。保存済みの停止中のモーションと物理グループは、再度有効にできる通常の内容として残ります。後続の項目はインスタンスとオブジェクト参照を残します。適用の前後で、完全な結果は一致している必要があります。

物理グループは通常の物理設定になり、生成モーションは通常のクリップになります（ファイル名、書き出しグループ、ランタイムの既定フェードイン／フェードアウトは残ります）。シミュレーションは、生成済みのバインド内容を確定します。現在の再生フレームは記録しません。依存の不足、一致できない上書き、無効なベイクは適用を止めます。失敗しても部分的な結果は残りません。取り消しで元のスタックに戻ります。

目のモディファイアには、見開き、まぶたの線のフェード、ハイライトの視差も追加できます。見開きは開眼範囲を明示的に 2 まで広げ、寄与一覧にパラメータの変更が表示されます。ハイライトの追加計画には、頭と顔のバインド依存が含まれます。新しく追加した停止点のキーフォームは座標を表示し、出どころを区別しやすくします。

目と眉の前髪透過は、それぞれ追加し、透明度を調整できます。寄与一覧には、生成された複製メッシュ、階層、マスクの関係が表示されます。

「スイッチの編成」は、対象の中のスイッチと差分レイヤーにパラメータと透明度のキーフォームを追加します。差分を切り替えるとき、新しいレイヤーが先にフェードインし、古いレイヤーが続いてフェードアウトします。スイッチと差分は、追加済みのスイングチェーンも駆動でき、寄与一覧には影響を受ける物理グループが並びます。

「口の輪郭」は、適用できる口の素材に上下の唇メッシュとそれぞれのテクスチャを生成します。モディファイアの中で線幅を調整し、RGB 色を入力するか、自動の色取りに戻せます。適用後、メッシュとテクスチャはプロジェクトとともに保存されます。

## ネイティブジェネレーター

スイングは支点、オフセット、軸方向、セグメント、形状、付属する物理演算を調整できます。物理グループはパラメータの入力／出力、各セグメント、正規化を調整できます。生成モーションは既存のアルゴリズムを使い、現在のパラメータが支えられるトラックだけを追加し、ポップアップメニューでプリセットを選びます。スタックに入ったあと、長さ、ループ、フェードイン／フェードアウト、トラック、キーフレームを調整できます。数値は、追加後のプリセット調整領域で編集します。

物理グループには、すでに存在し使える出力パラメータと、それとは別の入力パラメータが必要です。適切なパラメータがないときは、先にバインドまたは通常のパラメータを追加します。出力の書き込みが衝突すると追加は止まります。既存の物理グループは置き換えません。シミュレーションは、バックグラウンドで実際のスタック接頭辞をベイクし、現在の再生フレームは使いません。材質、入力、モード数、キー数、誇張を調整し、ブレンドシェイプの出力モードを選び、静的入力軸を追加または削除できます。固定、剛性、形状、質量、減衰、風力は、対象上の名前付き頂点グループを選べ、既定では各対象の同種グループの先頭を読みます。衝突体は、シミュレーション対象ではないメッシュを選べ、頂点 A／B、両端の半径、摩擦を設定するか、取り除けます。2 つの端点が同じときは円、違うときはカプセルで、頂点番号は 0 から始まります。トレーニングクリップには、既存の通常モーションとスタック内の前置モーションを選べ、ウェイトを調整するか取り除けます。参照するクリップが欠けているとき、シミュレーションは残ったまま評価を一時停止します。シミュレーションを、クリップを提供するモーションより前へ移す操作は拒否されます。自動ベイクをオンにすると、上流の編集は同じトランザクション内で結果を更新します。オフのあと、期限切れの結果は確定を止めます。動きが足りない入力は拒否されます。小さな入力を残す必要があると確認したときは、「残す」にチェックできます。

まばたきの余震と眉の戻りは、バインドとともに物理グループを追加します。モディファイア内の「物理演算」を展開すると、入力／出力、セグメント、正規化を調整でき、値はそのインスタンスに保存されます。異なる対象は、互換性のある標準物理グループを共有できます。再利用一覧にはその出どころが表示され、名前は先行項目を残します。物理の値を変えた結果が共有相手と互換でなくなると確定は拒否され、先にほかの共有相手を停止してから、項目ごとに一致するまで調整する必要があります。確定後は、これらの値を残した通常の物理設定になります。

口には、口形キャプチャ、舌出し、下顎の追従、口腔の奥行き、口の戻りも追加できます。追加計画には必要な前置項目が並びます。赤面と陰りは色チャンネルを追加し、口形と組み合わせられます。色のキーフォームの編集もインスタンスに属し、停止後は休眠し、元のインスタンスを復元すると再び有効になります。

頬紅 v4（`expression.cheek@4`）は、明示的に選ぶためだけのソース入力候補です。同側の単眼、眉、まつげが揃った口全体の開口素材と、未編集・未分割のプリセットスキンに対応します。前置バージョンは[アルゴリズムプラグイン](ALGORITHM_PLUGINS.md)に列挙されたソースチェーンに合っている必要があり、2 つの感情パラメータはどちらも未使用である必要があります。単独でコンパイルして凍結した `skinReplayV1` の補助実装は、ソースの計測から動きを再構築し、既存のスキンとキャリアを正確に照合してから暖色を加えます。密な詳細メッシュが前の状態を正確に再現できないときは拒否され、前置バージョンを下げて照合を一致させることはしません。既存の既定とプロジェクトのバージョンロックは変わらず、陰鬱 v4 は引き続き頬紅 v1 を要求します。この候補は、プリセットチェーン全体が独立して移行済みであることを意味しません。

物理パネルが表示するのは、スタックが実際に評価するグループで、出どころは「モディファイア」とマークされます。生成グループは、所属するモディファイアの中で調整してください。「プリセットを開く」でそのパネルに戻れます。生成グループの順序はモディファイアのスタックが決め、確定後は通常に編集、停止、並べ替えができるカスタム設定になります。

スキンの切り抜きは、頬紅、スキンの明暗、前髪の影に顔のマスクを追加します。首の連動は、首を頭の傾きに追従させ、首の影を切り抜きます。追加計画には、固定された頭と顔のバインドの前置項目が含まれます。どちらも既存の素材を踏襲します。寄与領域には、マスクの追加前後の出どころと反転状態が表示され、オブジェクトまたは出どころをクリックすると位置を特定できます。

首の連動 v4 は、明示的に選ぶためだけのソース入力候補版です。ワーカープロセスは、現在の前置構成から通常の首の傾きと影の頭回転の動きを再構築します。現在のところ、同梱されている前置パッケージを使う必要があり、共有の体／呼吸の分岐に直接ぶら下がり、左右に分かれておらず、ソース UV とトポロジが変わっていない首メッシュだけに対応します。古い前置パッケージの要約、対になった首、カスタムの親による包み、独立した頭回転キャリアを新たに必要とする場合は拒否されます。既存の首のバージョン、プリセットの選択、保存済みの v1–v3 パッケージのロックはそのままです。

髪は、セグメントチェーンの基礎アルゴリズムを選べ、同じ対象の旧来の髪スイングとは排他です。スカートの裾、リボンと垂れ飾り、獣耳／尾／翼のチェーン、胸と腕の追従も個別に追加できます。追加計画には、必要な体と頭顔のバインドが並びます。チェーンの振れ幅、髪の硬さ、実際の物理グループは、所属項目の中で調整します。ほかの項目の順序を調整しても、これらのチェーンのオブジェクト参照は変わりません。

フィットした顔そのものが、頭と顔の基礎バインドです。その項目の中で、回転の振幅、奥行き、造型を調整します。新しい造型を選ぶと、その項目のほかの数値は既定に戻ります。条件を満たす横髪は、大きな角度で頭を回したとき顔の後ろへ回ります。

物理演算を追加するときは、前髪、後ろ髪、眼球ゼリーのプリセットを選べます。必要なパラメータが欠けているとき、追加計画には同時に追加する基礎バインドが並びます。モーションを追加するときは、原版または自然版の待機、まばたき、うなずき、首振り、または自然な発話を選べます。自然なモーションを選ぶと、追加計画は欠けている基礎バインドを補います。確定前に数値を編集しても、計画中の前置項目は残ります。追加を確定したあと、物理ルールとモーショントラックは、対応するインスタンスの中で編集できます。

## MCP との共用

`modifier_apply_plan` は `id` と `scope`（`selected` が選択項目、`prefix` がここまでの接頭辞、既定は `prefix`）を受け取り、キャプチャした `state`、適用範囲、停止項目、保持項目、境界をまたぐ依存、阻止理由を返します。プロジェクトは変更しません。範囲を確認したあと、同じ `scope` とその `state` で `modifier_apply` を呼び出します。計画の `can_apply` が示すのは、キャプチャ済みの報告に既知の阻止項目がないことだけで、最終的な確定には完全な評価と整合性の検証が引き続き必要です。

`modifier_catalog` はアルゴリズムカタログを提供し、`modifier_stack` はキャプチャ版の状態と実際の寄与を提供します。`modifier_plan` はソース画像のバインドと前置項目を計画し、スイング、物理グループ、シミュレーション、生成モーションのネイティブ構成にも対応します。先にその `group` と `entries` を `workspace_preview_regeneration` へ渡し、同じ `state` で `modifier_add_group` を確定すると、GUI の追加手順を再現できます。詳しくは [MCP API](../agent/MCP_AUTHORING.md) を参照してください。

まばたきモーションのモディファイアは、EyeBlink のランタイムパラメータ役割も同時に寄与し、関係一覧に表示されます。モディファイアを適用したあと、その役割は通常のモデルメタデータとして確定し、プロジェクトとともに保存されます。

モーションモディファイアを適用すると、元のクリップのファイル名とカーブ制御点が残ります。そのあとパラメータ範囲を調整すると、通常のモーションは新しい範囲に合わせて整理されます。保存、開き直し、再構築だけではカーブは変わりません。

モーショントラックはスタック内で展開でき、キーの時間、数値、補間、ベジェの入り／出ハンドルを編集できます。イベントグループは、追加、時間と内容の編集、削除に対応します。適用後も通常のモーションクリップとして残ります。

## PSD 以外の新規作成

空の Layout と Layout マニフェストのインポートは、空のプリセットスタックを使います。素材は引き続き通常どおり編集できます。空のスタックで最初に生成するときは、完全な新版ベースラインを使います。プリセットがすでにある状態で新しい素材を生成するときは、選んだ互換グループに従ってバインドを補い、既存のプリセットは保たれます。MCP の `rig_generate.preset_group` は 6 種類のグループ、または `none`（通常メッシュを残す）を選べます。ソース画像データからの新規作成は推奨グループを使います。古いプロジェクトは、旧来の生成経路を残します。

CMO3 からの新規作成は空のプリセットスタックを使い、インポートしたモデルと物理設定は通常のオーサード内容として残ります。

アルゴリズムのインストール、アンインストール、多言語への接続は[アルゴリズムプラグイン](ALGORITHM_PLUGINS.md)を参照してください。
