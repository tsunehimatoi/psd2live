# 物理演算

[ドキュメント目次](../README.md) · [スイング生成](SWING.md) · [シミュレーションとベイク](SIMULATION.md) · [MCP の使い方と API](../agent/MCP_AUTHORING.md)

物理演算は、パラメータを頭や体などの入力に追従させ、慣性で揺らします。PSD2Live は Cubism の振り子モデルを使います。根元から垂れ下がる一連の振り子（Cubism Editor の「振り子設定」で番号 1、2、3… の各行）で、入力が根元を押すか重力を傾け、振り子が慣性で揺れ、指定した振り子の角度が出力パラメータへ書き込まれます。書き出し時には `physics3.json` と `.cmo3` へ書き込まれます。

## 物理グループの出どころ

モデルのすべての物理グループは物理パネルに並び、出どころは 5 種類です。

| 出どころ | 説明 | ID |
|------|------|----|
| プリセット | レイヤーから自動生成される前髪、後ろ髪、ゼリー目（レイヤーに対応するパーツがあるときだけ現れます） | `PhysicsHairFront`、`PhysicsHairBack`、`PhysicsEyeJelly` |
| ボーン | スケルトンの第 2 節以降の尻尾、翼の追従 | `PhysicsSkel_<ボーン id>` |
| スイング | 各スイングの各方向に振り子が 1 本。詳しくは[スイング生成](SWING.md) | `PhysicsSwing_<id>[_X\|_Y]` |
| シミュレーション | ベイク済みのシミュレーションごとに、当てはめた振り子が 1 本。各節がモードパラメータを 1 つ駆動します。上下の動きには、平行移動を入力とする振り子が別に 1 本あります。詳しくは[シミュレーションとベイク](SIMULATION.md) | `PhysicsSim_<id>`、`PhysicsSim_<id>_y` |
| カスタム | パネルまたは MCP で新規作成 | 既定は `PhysicsCustom<N>` |

生成されたグループも直接編集できます。編集すると「編集済み」になり、保存されるのはその版です。出どころ（スイング、ボーン）がそのあと変化しても、上書きされません。シミュレーションの振り子は、再ベイクまたは出力の改名のあと三方マージされ、変更したフィールドだけが残り、残りは新しい当てはめ結果に追従します（[シミュレーションとベイク](SIMULATION.md)を参照）。「生成値に戻す」で、生成された版に戻ります。各グループは個別にオフにでき、オフのグループは書き出されません。カスタムグループが、ある生成グループの出力パラメータを駆動しているとき、その生成グループは「置換済み」と表示され、同様に書き出されません。

インポートした CMO3 の物理設定は、ファイル内の ID をそのまま使います。Cubism Editor は ID が同じ設定をいくつか保存することがあり、そのときは 2 番目以降を順に `<id>_2`、`<id>_3`… へ変えます（ファイル内にすでにある ID は飛ばします）。すべての設定は残り、インポートのたびに同じ ID になり、書き出しもこれらの ID を使います。

同じパラメータを駆動できる有効なグループは 1 つだけです。グループが無効なとき（パラメータが存在しない、入力または出力がない、あるパラメータが入力と出力の両方である）は、一覧で「無効」とマークされ、書き出されず、編集領域に理由が表示されます。

## 物理パネル

物理演算のマスタースイッチと物理フレームレートは、プレビューキャンバスの左側ツールバーにあり、待機アニメーション、マウス追従と一緒に置かれています。物理フレームレートは 30 / 60 / 90 / 120 / 無制限から選べ（既定は 60）、プロジェクトの設定です。物理演算はこれに従って計算し、書き出す `physics3.json`（`Fps`）と CMO3 にも書き込まれます。「無制限」を選ぶと、物理演算は各レンダリングフレームごとに計算され、書き出しは `Fps` を宣言せず、ランタイムはそれぞれのフレームで物理演算を計算します（CMO3 には物理 FPS を書きません）。プレビューの出画はこれでは制限されません。プレビューのフレームレート上限は、キャンバス左下のステータスカプセルのメニューにあり、既定は「ディスプレイに追従」で、物理フレームレートとは無関係です。物理演算は 2 ステップの間を補間します。

パネル上部には、物理演算が動いているか、現在のフレームレート、「有効 n / m」のカウント、プレビューの待機アニメーションとマウス追従のスイッチが表示されます。

待機アニメーションと物理演算は互いに独立しています。待機アニメーションが停止し、物理演算がオンのとき、パラメータスライダーをドラッグするかマウス追従で頭を回すと、プレビュー内の物理演算は同様に揺れ、静止するとプレビューは出画を止めます。物理演算をオフにすると、編集ポーズだけが表示されます。一時停止中の物理演算は、書き出しと一致するエンジンで計算され（以下の「プレビューと書き出しの一致」を参照）、一時停止したモーションの再生は続きません。

パラメータパネルとプレビューは常に一致します。待機アニメーションの再生中、スライダーはプレビューに合わせてフレームごとに変わります。停止中は、マウス追従が動かす角度と眼球パラメータもパラメータパネルにリアルタイムで表示され、物理パネルの振り子が読むのも同じポーズです。

物理演算だけを調整するときは、「物理演算」ワークスペースを新規作成できます（タブバーの + メニュー）。左から右へ、プレビューキャンバス、パラメータパネル、物理パネルの順で、幅はおよそ 2 : 1 : 1 です。ほかのパネルは隠れ、必要なときはウィンドウメニューから開きます。

その下は物理グループの一覧で、計算順に並び、番号が付きます。各行はチェックで有効にでき、出どころと状態（編集済み / 無効 / 置換済み）が示されます。タイトルバーの ↑ / ↓ は、選択グループの計算順を調整します。Cubism は順に計算し、後ろのグループは同じステップの中で前のグループの出力を読めるので、あるグループが別のグループの出力を入力にするとき（連鎖する物理演算）は、読まれるグループを前に置きます。

「+ 新規」では次ができます。

- 空の振り子を新規作成します。既定の入力は頭と体の揺れで、長さ 10 の振り子が 1 本あり、出力はまだありません。
- 選択グループを新しいグループとして複製します（出力パラメータは空になり、元のグループとの衝突を避けます）。
- physics3.json を読み込みます。ファイル内の各グループがカスタムグループになり、ファイルの順で既存グループのあとに並びます。ID が同じグループは置き換えられます（生成グループは、生成値に戻すまで置き換えられたままです）。同じ出力を駆動するほかのカスタムグループはオフになり、ファイルが宣言する `Fps` がプロジェクトの計算 FPS になります。モデルにないパラメータはログに記録され、対応するグループは無効と表示されます。
- キャンバス上で選択したメッシュまたは曲げデフォーマにスイングを作成します（[スイング編集](SWING.md)に入ります）。

### 振り子キャンバス

グループを選択すると、編集領域の上部がその振り子です。実線はリアルタイムで揺れる振り子、破線はその静止ポーズで、リアルタイムの根元から垂れ下がり、各振り子の末端に輪があります。画面は左右がミラー表示なので、右へ引くと根元は右へ動きます。

| 操作 | 働き |
|------|------|
| 空白を左右にドラッグ | Cubism Viewer でモデルを横にドラッグするようにモデルを引きます（水平方向だけを取ります）。離すと滑らかに元の位置へ戻ります。根元は常に上部の横線に沿って動きます |
| 輪を上下にドラッグ | その振り子の長さです。クリックでその振り子を選択し（もう一度クリックすると解除）、下のスライダーはその振り子だけを調整します |
| 右側の出力ラベル | ラベルは、それが読む振り子と同じ高さにあり、線はその振り子のリアルタイム位置を指し、バーが現在のパラメータ値を示します。上下にドラッグすると、最も近い振り子がハイライトされ、離すとその振り子を読むように変わります（出力行の「振り子番号」） |
| 出力ラベルをクリック（または出力行の前の色点） | 振り子上に、この出力の範囲の扇形を表示します。この振り子が前の振り子に対して扇形の角度だけ振れると、パラメータが一方の端からもう一方の端まで動きます。扇形の縁の丸をドラッグして範囲（倍率）を調整し、扇形が狭いほど揺れが目立ちます |

クリックは選択だけで、少しの距離を超えてドラッグしたときだけ変更されるので、生成グループを誤って変えるのを避けます。ホバーまたはドラッグ中、左上にその項目の意味と数値が表示されます。

引いているとき、ポインタ位置が目標で、モデルは Cubism の CubismTargetPoint に従い、制限された速度と加速度で追従し、さらに CubismLook の係数で角度 X、体の X、眼球 X へ換算されます（グループ内のほかの入力パラメータは、ドラッグ量がその半分の範囲に占める割合に従います）。リアルタイムの振り子は、プレビュー再生時はプレビューパラメータに重ねられ（モーションと視線追従を含みます）、一時停止時はパラメータパネルの値に重ねられるので、パラメータスライダーを直接ドラッグしても反応が見えます。右下のボタンで、振り子をすぐに静止させます。

根元の移動範囲と重力の傾斜範囲（入力の正規化）は、「詳細」で設定します。

### 応答カーブ

振り子の下のカーブは、このグループが 1 回の標準的な引きにどう反応するかを示します。右へ 1 秒引き切ってから離し、出力ごとに 1 本のカーブです（パラメータ範囲で正規化。破線はパラメータの端）。薄いカーブは引き量そのものです。カーブの下には、各出力の最大振幅と、離してから静止するまでの時間が並びます。長さとダイナミクスのスライダーを調整するとカーブも更新され、異なる設定のオーバーシュートと収束を直接比べられます。

### 振り子設定

「プリセット」の行は、Cubism Editor の振り子プリセットに対応します。プリセットを 1 つ選んで「読込」をクリックすると、このグループのすべての振り子がそれで置き換わります（振り子が減るとき、削除された振り子を読んでいた出力は末端を読むように変わります）。組み込みプリセットは、自動生成の前髪、後ろ髪、ゼリー目、3 節の振り子から取ります。「⋯」では、現在の振り子を「追加…」して自分のプリセットにするか、自分のプリセットを上書き保存、改名、削除できます。プリセットはローカルに保存され、すべてのプロジェクトで共有されます。

「編集する振り子」の行は、下のスライダーが作用する対象を選びます。「すべて」はすべての振り子を同時に調整し、数字はその 1 本だけを調整します（キャンバス上の輪をクリックして選ぶこともできます）。これが決めるのは、スライダーがどの振り子を変えるかだけで、出力の「振り子番号」とは無関係です。右側のボタンは次のとおりです。

- ↑ / ↓：選択した振り子を移動します。それを読む出力は、それについていきます。
- +：選択した振り子の下に 1 本追加します（選択した振り子の数値を複製）。未選択のときは末端に足します。より深い出力は下へずれ、引き続き元の振り子を読みます。
- −：選択した振り子を削除します（未選択のときは最後を削除）。それを読んでいた出力は 1 つ前を読むようになり、より深い出力は上へずれます。

| スライダー | Cubism Editor の名称 | 効果 |
|------|-------------|------|
| 全長 / 長さ | 長さ | 長いほど揺れは遅く、振幅は大きくなります。「すべて」を選ぶと、すべての振り子を比例して拡大縮小します |
| 揺れやすさ | 揺れやすさ（Mobility） | 大きいほど止まりにくくなります |
| 反応速度 | 反応速度（Delay） | 大きいほど入力への反応が速くなります |
| 収束の速さ | 収束の速さ（Acceleration） | 大きいほど重力が強く、垂れ下がりへ早く戻ります |

### 入力

各入力は、1 つのパラメータとその影響の仕方です。

- **タイプ**：**位置X** は振り子の根元を左右に押します。**角度** は重力の方向を傾けます。
- **影響度**：0–100%。パラメータの全範囲が、入力の正規化範囲へ写る割合です。
- **⇄**：反転です。

「+ 追加」は使えるパラメータを列挙し、よく使う頭と体の角度が前に並びます。

「プリセット」の行は、Cubism Editor の入力プリセットに対応します。1 つのプリセットには、すべての入力と入力の正規化が含まれます。組み込みプリセットには、頭と体の揺れ（±10°、前髪と同じ。±30°、後ろ髪と同じ）、頭と体の上下（縦のスイングと同じ）、目の開閉（ゼリー目と同じ）があります。モデルにないパラメータと、このグループ自身の出力パラメータは飛ばされます。管理の仕方は振り子プリセットと同じです。

### 出力

各出力は、ある振り子の角度をパラメータへ書き込みます。

- **振り子番号**：出力が何番目の振り子の角度を読むか（前の振り子に対する角度。振り子 1 は重力方向に対する角度）です。Cubism Editor の出力設定の「振り子番号」、`physics3.json` の `VertexIndex` です。上の「編集する振り子」とは無関係です。キャンバス上で右側のラベルをある振り子の横へドラッグして離しても変更できます。複数の振り子を別々のパラメータへつなぐと、ムチのような区間ごとの追従が作れます。
- **倍率**：振り子角 1 ラジアンあたりのパラメータ値です。結果はパラメータ範囲に制限されます。キャンバス上で扇形の弧の端をドラッグしても調整できます。
- **⇄**：反転です。

出力は角度タイプだけです。Cubism のネイティブランタイムは、位置X タイプの出力の倍率を読まず、この種の出力は常に 0 です。読み込んだ古いデータに位置X タイプの出力があるときは案内され、ワンクリックで角度へ変えられます。

「+ 追加」の中で、ほかの有効なグループが駆動しているパラメータは選択不可と表示され、どのグループが駆動しているかが注記されます。

各出力行の右側の「最大出力」は、Cubism Editor の出力設定の同名の列に対応します。このグループを開いてから（または前回のリセットから）、この出力が現在の倍率で達した最大値が、パラメータの端に対して何パーセントかを示します。引きのキャンバス、プレビュー再生、視線追従のいずれでも記録されます。100% を超えると警告色になり、パラメータが端で切られていることを示します。倍率を変えると、百分率はすぐに新しい倍率で換算され、引き直す必要はありません。

- 「最大値で倍率を調整」：各出力の倍率を、最大出力がちょうど 100% になるように調整します。まだ記録がないときは、応答カーブの標準的な引きで測ります。
- 「出力の最大値をリセット」：記録を空にして、測定をやり直します。

### 詳細

「詳細」の下に折りたたまれているのは、キャンバスとスライダーがすでに覆っていて、正確な数値が必要なときだけ使うデータです。

- 振り子設定表：各振り子の長さ、揺れやすさ、反応速度、収束の速さ。
- 出力の詳細：倍率と影響度。
- 入力の正規化：位置X と角度入力の最小値 / 中央 / 最大値。

グループ名はクリックすると改名できます。「⋯」メニューには、改名、複製、スイングの編集（スイング由来）、生成値に戻す、削除（カスタムグループ）があります。

ドラッグ、スライダーのドラッグ、数値入力は、離したあとに履歴を 1 件記録し、取り消せます。編集はプロジェクトに保存され、モデルを再構築したあとも同じグループとして再生成されます。

## プレビューと書き出しの一致

パネル内の振り子、応答カーブ、内蔵レンダリングのソフトウェアプレビュー、MCP のシミュレーションは同じ物理エンジンを使い、項目ごとに Cubism Native Framework 5-r.5 の `CubismPhysics::Evaluate` に対応します。入力の正規化、`Fps` による固定ステップとフレーム間の入力補間、パラメータキャッシュを介したグループ間の受け渡し（後ろのグループは前のグループの同じステップの出力を読めます）、節の更新と空気抵抗、出力の補間とウェイトの混合で、SDK 自身のいくつかの特殊な振る舞いも含みます。リポジトリの `PhysicsReferenceTest` は、公式 Framework が書き出しモデル上で出したフレームごとのデータ（`native/physics_reference`）で検証します。900 フレームの不規則なフレーム間隔、連鎖グループ、反転、部分ウェイト、変位出力について、`Fps` がある場合とない場合の最大偏差はおよそ 1e-5 です。

書き出す `physics3.json` はプロジェクトのフレームレートを宣言し（`Fps`、既定 60。「無制限」のときは宣言しません）、CMO3 の物理 FPS はそれと同じです。揺れはレンダリングのフレームレートでは変わらず、CMO3 から Cubism Editor を経て書き出しても一致したままです。グループは一覧の順で書き出され、それがランタイムの計算順です。公式 SDK のプレビューが使えるときは、プレビューは SDK が書き出した `physics3.json` を直接読みます。

物理演算が書くのはパラメータだけです。揺れの効果は、出力パラメータのキーフォームによります。カスタムグループは、先に出力パラメータの端の形状を作っておく必要があります。そうでないと、パラメータは動いてもモデルは動きません。

## MCP

物理グループの操作は用途ごとにいくつかのツールに分かれ、パラメータは一律 `{"request": {...}}` に置きます（完全なフィールドは [MCP の使い方と API](../agent/MCP_AUTHORING.md) を参照するか、`workspace_get_operation` を呼び出します）。変更とサンプリングには、`project_id`、`state`（`workspace_inspect` または前回の結果から）、一意な `request_id` を付けます。バックグラウンドタスクとマークされたツールはタスクハンドルを返し、`job_wait` / `job_get` で結果を取ります。

- `physics_put`（バックグラウンドタスク）：`id` で新規作成または変更し、与えたフィールドだけを書きます。既存の ID（生成グループを含む）は現在のグループを基礎にします。`inputs` / `outputs` / `segments` は一覧を全体置換し、`length` / `mobility` / `delay` / `acceleration` はすべての節に作用し、`output_scale` はすべての出力に作用し、`segment_count` は節数を変え、`normalization` は入力の正規化を設定し、`enabled=false` は任意のグループをオフにします。
- `physics_delete`（バックグラウンドタスク）：カスタムグループを削除するか、編集済みの生成グループを生成値へ戻します。生成グループ自体は、`physics_put` の `enabled=false` でオフにします。
- `physics_simulate`（読み取り専用のバックグラウンドタスク）：静止から、`inputs` のパラメータを与えた値へステップさせ、`hold` 秒保ってから戻し、各出力について、保持中と離したあとの開始値、ピーク、最終値、安定時間、および `samples` でサンプルしたカーブを返します。`ids` は指定したグループだけを見、`duration` は全体の長さを設定します。
- `physics_fit`（バックグラウンドタスク）：グループ `id` の各出力の倍率を、ピークがパラメータの端の `target`%（既定 100）にぴったり達するように調整します。`observed_peaks` を与えないときは、応答カーブの標準的な引きで測り、リアルタイム記録がないときのパネルの「最大値で倍率を調整」と同じです。与えるときは実測値で調整し、キーは出力の番号（`"0"`、`"1"`…）、値は `physics_audition` が報告する `peaks`（1 がパラメータの端）です。
- `physics_config`（バックグラウンドタスク）：`order` は計算順を設定し（列挙したグループが前に並びます）、`fps` はプロジェクトのフレームレートを設定します（0 は無制限）。
- `physics_import`（バックグラウンドタスク）：physics3.json を読み込みます（`path` は絶対パス）。規則はパネルと同じで、読み込んだグループ、オフになったグループ、欠けているパラメータを返します。

振り子キャンバス上の引きは試聴セッションに対応し、ドキュメント、履歴、保存済みのポーズは変更しません。

- `physics_audition`：`mode` が `start`（`group_id` を与え、任意で `values` をパラメータ値に重ねる）のとき試聴を開始し、このワークスペースの以前のセッションを停止します。`target` は根元を `x`、`y`（-1–1、パネルのポインタ）へ引きます。`release` は手を離し、`reset` は振り子を静止させ、`reset_peaks` は最大値の記録をやり直し、`stop` は終了します。あとの種類はどれも `session_id` を伴います。
- `physics_audition_step`：`dt` 秒（最大 0.1）ずつ `steps` 歩（1–240）進め、振り子の頂点、出力、`peaks` を返します。
- `physics_audition_get`：最新の 1 フレームだけを読み、時間は進めません。

試聴中にドキュメントを変更すると、セッションは新しいグループで揺れ続けます。プロジェクトを開き直すか、そのグループを削除すると、セッションは期限切れになります。引いて、離して、何歩か進めたあと、`peaks` をそのまま `physics_fit` の `observed_peaks` へ渡すのが、パネル上で引いたあと「最大値で倍率を調整」をクリックする操作です。

`workspace_inspect` の `scope=physics` は、計算 FPS と、計算順に並んだすべてのグループを返します。各グループには出どころ、有効かどうか、何に置換されているか、無効な理由が付きます。

入力と振り子のプリセットも MCP から使えます。`physics_preset_list` は組み込みと自分のプリセットを列挙し、`physics_apply_preset` はそのうちの 1 つをあるグループへ適用します。`physics_preset_put` / `physics_preset_rename` / `physics_preset_delete` は自分のプリセットを管理し、一覧が返した `library_state` を付ける必要があります。
