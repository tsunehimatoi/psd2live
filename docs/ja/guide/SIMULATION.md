# シミュレーションとベイク

[ドキュメント目次](../README.md) · [物理演算](PHYSICS.md) · [スイング生成](SWING.md) · [キャンバス編集](CANVAS_EDITOR.md) · [MCP の使い方と API](../agent/MCP_AUTHORING.md)

初めて操作するときは、先に[シミュレーション図解チュートリアル](SIMULATION_TUTORIAL.md)を見て、スクリーンショットに沿ってプリセット、固定点ウェイト、再ベイク、効果の確認を完了できます。

シミュレーションは、エディタの中でメッシュに本物の 2D の布 / 髪のシミュレーションを行います。頂点は固定点に引かれ、重力と慣性で駆動されます。Cubism のランタイムはこの種のシミュレーションを行わないので、**シミュレーション自体は書き出されません**。書き出すには、Cubism が再生できる内容へ**ベイク**する必要があります。新しいパラメータ上のメッシュキーフォームを、当てはめた振り子が駆動し、さらにいくつかのパラメータ上の正確な補正が加わります。ベイク結果はプロジェクトに保存されます。モデルを再構築するときは結果を書き戻すだけで、シミュレーションはやり直されません。

## 基本の流れ

1. キャンバス上でスカートまたは髪のメッシュを選択し、「シミュレーション」パネル（各ワークスペースでは「物理演算」タブのあと、編集ワークスペースでは既定で表示）の「新規」をクリックして「布」または「髪」を選びます。同じ物体の中の複数のメッシュは、一緒にシミュレーションされます。
2. 固定点を指定します。どちらか一方、または両方を使えます。
   - パネルの「頂点ウェイトグループ」で「固定点」の行の「描画」をクリックするか、キャンバスを「シミュレーション」モードに切り替えて、ウェイトブラシで「固定点」ウェイトグループを描きます。
   - パネルの「Glue」で、腰とつながっている Glue を「固定点にする」にします。
3. ツールバーのプレビュースイッチをオンにして「参照シミュレーション」へ切り替え、プレビューで頭を回し、体を揺らし、効果が自然になるまで材質を調整します。
4. 選択中の物体の「ベイク」節（編集領域の最初の節）で「ベイク」をクリックするか、パネル上部のツールバーで「すべてベイク」をクリックします。ベイクには数秒かかり、バックグラウンドで進み、その間ほかの内容の編集を続けられます。完了すると、その時点の最新版の上に、取り消し 1 歩として確定されます。ツールバーの「自動ベイク」スイッチは既定でオフです。オンにすると、パネル内の変更は毎回すぐ確定され、そのあとバックグラウンドでベイクし直されます。ベイク後、物理パネルに出どころが「シミュレーション」の振り子グループが現れ、パラメータパネルに `ParamSim…` パラメータが現れ、書き出しにそれらが含まれます。
5. プレビュースイッチをオフにして「書き出し結果」へ戻すと、プレビューが再生するのは書き出しモデルのモーションで、参照シミュレーションと見比べられます。

### パネルの配置

パネルは物理パネルと同じ配置です。

- **ツールバー**：1 行の中に順に「新規」（布 / 髪）、「すべてベイク」、「自動ベイク」スイッチ、プレビュースイッチ（オフが「書き出し結果」、オンが「参照シミュレーション」。ラベルは現在のほうを表示）があり、次の行がベイク状態です。右側はすべて展開とすべて折りたたみ（物体一覧と編集領域の各節）で、参照シミュレーションのときは一番右にリセットボタンが追加され、リアルタイムシミュレーションを静止へ戻します。「新規」は選択メッシュで物体を作り、名前は `sim` に、最初のメッシュから `ArtMesh` 接頭辞を除いた名前を足したものです（`ArtMeshBottomwear` → `simBottomwear`。同名のときは番号を足します）。「すべてベイク」は、未ベイクまたは期限切れの有効な物体を順にベイクし、後ろの物体は前のベイク結果の上でベイクし、すべて完了すると取り消し 1 歩として確定します。すべて最新のときに再度クリックすると、すべてベイクし直します。ベイク中も編集を続けられ、ほかの物体をさらにベイクできます（キューに入り、次のラウンドでベイク）。ある物体の設定がベイク中に変わると、その結果は古い設定では確定されず、ベイクし直されます。ベイク中に削除された物体は、結果を捨てます。「自動ベイク」はローカルの画面設定で、プロジェクトには保存されず、既定はオフです。ボタンの右側に状態の数が表示されます。ベイク待ちがあるときは黄色で「1/2 件がベイク待ち」、そうでなければ「2/2 件がベイク済み」です。ベイク中はボタンがキャンセルに変わり（キャンセル後はどの結果も確定されません）、状態の場所に現在の物体、番号、進行状況が表示されます。個別の物体のベイクが失敗したときは、その古いベイクを残して一覧の下に案内し、残りは通常どおり確定します。
- **一覧**：折りたたみできる「物体」フォルダです。各行の左側のチェックボックスで物体を有効 / 停止し、右側はベイク状態と種類です。ベイク済みは緑の点だけを表示し、注意が必要な状態だけ文字を書きます（黄色の期限切れは書き出しが引き続き古い結果を使うこと、赤の未ベイクは書き出されないこと、灰色の停止済み）。右クリックメニューでベイク、ベイクの消去、削除ができます。
- **編集領域**：タイトル行は名前と種類（切り替えるとその種類の材質プリセットが適用されます）で、そのあと「ベイク」「材質」「入力」「出力」「Glue」「頂点ウェイトグループ」の順です。ベイク節は、先に未学習のモーション上の視覚検査（振れ幅の比、遅れ、収まり、ジッター。差が見えるときは警告色）を表示し、次に R² と誤差（端に張り付く、またはより震えるときは別に警告）を表示し、そのあと「ベイク / 再ベイク」「ベイクを消去」、モード数、上下パラメータ、キー数、誇張です。モードの書き方、トレーニングに参加するモーション、正確なポーズ、各モードの振れ幅は「詳細」に収まります。「比較」節（既定で折りたたみ）は、ベイク結果と参照シミュレーションを並べて見るために使い、[書き出し結果と参照シミュレーション](#書き出し結果と参照シミュレーション)を参照してください。材質節の上部では名前付きプリセットを選べ、材質を変えると節のタイトルに「この種類のプリセットに戻す」ボタンが出ます。入力節はパラメータ名と ID を行ごとに列挙し、モデルにすでに存在しないパラメータは警告色で「存在しない」とマークされます。ベイク後、各入力の下には、それが物体をどれだけ動かすかが表示され、除外されたものは警告色で「除外済み」とマークされ、「残す」チェックボックスが付きます。その下の行がそのトレーニング範囲です。入力が既定と違うとき、節のタイトルに「既定の入力に戻す」ボタンが出、入力がないときはベイクできないと警告します。出力節は、ベイク後に生成されたモードパラメータと振り子（名前と ID）を列挙し、名前をクリックすると改名でき、空にするか既定名に戻すと物体の名前に戻ります。各モードパラメータの下では、ID、範囲、ゲインを変えられます。

## 頂点ウェイトグループ

ウェイトグループは、各メッシュ上の頂点ごとの 0–1 ウェイトで、本ソフトの中にだけ存在し、`.moc3` / `.cmo3` には書き込まれません。各メッシュの各種類はグループ 1 つで、種類で区別し、名前は不要です。「シミュレーション」モードで、ウェイトブラシまたはウェイトグラデーションにより描きます（[キャンバス編集](CANVAS_EDITOR.md)を参照）。左側ツールバーは、ウェイトツールの下に各種類を列挙し（`1`–`5` でも切り替え）、クリックすると描くグループが切り替わります。ウェイトブラシも、円、直線、矩形の先端を選べます。トポロジ編集のあと、頂点の出どころに従って補間して残します。

| 種類 | 働き |
| --- | --- |
| 固定点（`1`） | Rig に引かれる頂点。ウェイトは、どれだけしっかり固定されるかを表します |
| 剛性（`2`） | 頂点ごとに伸びと曲げの剛性を拡大縮小し、根元は硬く裾は柔らかくするために使います |
| 形状保持（`3`） | 頂点ごとに、原画の形へ戻る強さを拡大縮小します |
| 質量（`4`） | 頂点ごとに質量を拡大縮小します |
| 減衰（`5`） | 頂点ごとに減衰を拡大縮小します |

パネルの「頂点ウェイトグループ」は、対象メッシュが各種類のグループをすでに描いているかを列挙します。各行の「描画」は、最初の対象メッシュを選択し、キャンバスを「シミュレーション」モードへ切り替え、その種類のウェイトブラシを開きます。風などの力場はまだ実装されておらず、パネルとウェイトブラシは「風の影響」グループを提供しません。MCP の `vertex_group_update` / `vertex_group_paint` は引き続き `wind` を受け付け、`simulation_simulate` に `wind` を渡したときだけ作用します。MCP は引き続き名前付きグループを使え、物体の `groups` で名前により指定できます。同じ種類に複数のグループがあるとき、指定がなければ最初のものを使い、それが画面で描いたものです。

## Glue

Glue は自動では固定点にならず、シミュレーションメッシュとつながっている各 Glue は、パネルで個別に選びます。

| 役割 | 働き |
| --- | --- |
| 使わない（既定） | シミュレーションはそれを無視し、ランタイムで溶接するだけです |
| 固定点にする | シミュレーション側の Glue 頂点が、もう一方のメッシュの実際の変形に追従します。たとえばスカートと腰です |
| 両側を結合 | 両側がシミュレーション中のとき、継ぎ目をつなげたままにします。たとえば分かれた前後の身頃です |

## 材質

| 項目 | 意味 |
| --- | --- |
| 質量 | 相対密度です。各頂点の質量は、それが受け持つメッシュ面積（周囲の三角形の面積の 3 分の 1）で計算されるので、メッシュを密にする、または再分割しても変形の詳細が増えるだけで、布が重くなったり柔らかくなったりはしません |
| 伸び | 長くなることへの抵抗です。布と髪は 1 に近づけます |
| 曲げ | どれだけ急に曲がれるかです。隣り合う三角形が回った角度の差です。曲げだけを扱い、縮みは扱いません |
| 面積 | 各三角形が面積を保つ程度です。正面から見ると、布は奥行き方向に折れると短くなり、積み重なります。低い値は薄い布のこのような縮みを許し、高い値は厚いパーツに形を保たせます。いくらに設定しても、三角形は裏返らず、面積ゼロまで潰れません |
| 布目 | 横方向が、布目に沿う方向よりどれだけ柔らかいかです。布目は自動で「固定点から離れる方向」（メッシュに沿って測った経路長が増える方向）を取り、固定点がないときは垂直下向きを取ります。高い値のとき、毛束は長さ方向には伸びず、左右に分かれ、長さ方向に折れます |
| 減衰 | 動きが収まる速さ（毎秒）です |
| 形状保持 | 原画の形へ戻るばねです。0 は純粋な物理です。単位質量で数えるので、メッシュの疎密は戻る速さを変えません |
| 余裕 | 激しく振られたとき、頂点が固定点から離れる距離が、静止時の経路を最大どれだけ超えてよいかです |

既定値：布は面積 0.3、布目 0.3。髪は面積 0.5、布目 0.7。袖、ズボン、脚の装身のプリセットは面積 0.5、首飾りは 0.4 です。

「プリセット」ドロップダウンは、名前付き材質の数値を上表の各項目へ入れ、そのあと調整を続けられます。プロジェクトが保存するのは数値だけで、数値がいずれかのプリセットと一致するときはドロップダウンがその名前を表示し、そうでなければ「カスタム」と表示します。

| 種類 | プリセット | 特徴 |
| --- | --- | --- |
| 布 | 綿（既定） | 上表の既定値 |
| 布 | シルク | 軽く柔らかく、しわが細かく、揺れが長く尾を引き、止まりが遅い |
| 布 | シフォン | 最も軽く最も柔らかく、シルクより早く空気の減衰で止まります |
| 布 | ウール | 重く柔らかく、動き出しが遅く、止まりが速い |
| 布 | デニム | 重く硬く、しわが広く、形を保ちます |
| 布 | 革 | 最も硬く、全体で揺れ、ほとんど積み重ならず、原画の形へ戻ります |
| 布 | 伸縮素材 | 伸びて戻り、ベルトや靴下に向いています |
| 髪 | 髪（既定） | 上表の既定値 |
| 髪 | 細く柔らかい髪 | 軽く、曲がりやすく分かれやすく、長く揺れます |
| 髪 | 太く硬い髪 | やや重く、束ごと揺れて形を保ちます |
| 髪 | 前髪 | 垂れ下がらず額に沿い、戻りが強く減衰が大きく、頭の移動に合わせ、毛先はわずかに遅れます。前髪プリセットが使います |

シミュレーション開始前に先に標定し、原画の形状が静止時の平衡位置になるようにするので、シミュレーションを開いたあと静止したモデルは垂れ下がりません。

ソルバは二次元 XPBD（フレームあたり 16 サブステップ）です。Rig がある場所を引き伸ばすとき（たとえば頭を回したときの視差）、その場所の静止長はそれに合わせて長くなり、Rig の造型と対抗しません。Rig がある場所を縮めるときは奥行き方向への転回とみなし、柔らかい圧縮が担います。

## ベイク

「入力」は物体を揺らすパラメータで、一覧どおりに使われ、暗黙の既定値はありません。物体を新規作成するとき（パネル、MCP が `inputs` を与えないとき、モデルプリセット）は既定の入力が書き込まれます。頭と体の角度（モデルに存在する `ParamAngleX`、`ParamAngleZ`、`ParamBodyAngleX`、`ParamBodyAngleZ`）、およびうなずき、体の上下、前後傾（存在する `ParamAngleY`、`ParamBodyAngleY`、`ParamBodyLean`）です。布タイプの上下入力は `ParamBodyAngleY` だけを取ります。服は体に掛かっているので、うなずきはそれを動かしません。前後傾は主に別のポーズで止まらせるもので、上下の振り子は静的なオフセットを表せず、ほとんど復元力がなく、非常に大きな出力倍率で増幅される振り子へ当てはめられてしまいます。衣装プリセットを適用し直すとき、まだ旧版の汎用既定入力のままの物体は、布の既定入力へ変わります。一覧が空なのは入力がないことを意味し、ベイクはエラーになります。古いプロジェクトで入力が記録されていない物体（当時は既定を使うことを意味していました）は、開くと上述の完全な既定一覧として表示され、モデルにないパラメータは、その物体を次に変更するときに取り除かれます。既定の入力と当時の「空」は同じとみなされ、既存のベイクはこれでは期限切れになりません。

ベイクは、先に Rig から各入力が物体をどう動かすかを読みます。トレーニング範囲の中でどの頂点も 1px 未満しか動かさない入力はベイクに参加せず（パネルでは「除外済み」とマーク。「残す」にチェックするか、MCP の `force_inputs` で強制的に残せます）、物体を左右より上下へ多く動かす入力は上下パラメータへ入り（以下を参照）、残りは左右のモードへ入ります。そのため、既定入力の中でそのパーツと無関係なパラメータ（たとえばスカート上の頭の回転）は、もう振り子へ当てはめられず、ユーザーがそれらのパラメータを動かしても物体が理由なく揺れることはありません。

各入力にはトレーニング範囲（下限から上限、パラメータ単位）を設定できます。ベイクはその範囲の中だけでそれを駆動し、既定はパラメータの全範囲です。範囲は常に既定値を含み、パラメータ範囲を超える部分は切り捨てられます。モードパラメータは、トレーニング中の最も激しい動きで目盛りを決めるので（手順 4 を参照）、範囲が狭いほど範囲内ではより十分に振れ、範囲を超えたあともより早く端に張り付きます。たとえば `ParamBodyAngleX` が普段 ±5 の中でしか動かないとき、トレーニング範囲を ±5 にすると、通常のモーションでもモードパラメータを使い切れます。トレーニング範囲が変わるとベイクは期限切れになります。入力が取り除かれると、そのトレーニング範囲と残す設定も一緒に取り除かれます。

「トレーニングに参加するモーション」（「詳細」の中。MCP の `training_clips`）は、ベイクに、設計済みの励振に加えてモデル自身のモーション（ユーザーモーション、または組み込みの Idle、Nod、Shake など）を学習させ、それぞれ ×0.05–×1 で重み付けします。少数の固定モーションで主に駆動し、フェイストラッキングを使わないモデルに向いています。各モーションは、それが最も多く動かすパラメータグループにだけ計上されます。これらのモーションを編集したあとはベイクし直す必要があります（モーションの内容は期限切れの判断に入りません）。

「出力」は、ベイクが書き出すモードパラメータと振り子です。名前は既定で物体に従います（パラメータは「<名前>」「<名前> 2」「<名前> Y」など、振り子は物体と同名）。改名は物体に保存され、再構築時に適用され、ベイクし直す必要はなく、ID は変わりません。各モードパラメータは、書き出し時の ID、範囲、ゲインを個別に設定でき、同様にベイクし直す必要はありません。ID の既定は生成された `ParamSim<id>_<k>` で、別の ID に変えて、その ID 用に作ったモーションと物理演算を引き継げますが、モデル内のほかのパラメータや、この物体の入力と同名にはできません。範囲は ±1…±100、既定は ±30 で、キーと振り子の出力倍率はそれに合わせて拡大縮小され、動きは変わりません。ゲインは ×0…×3 で、既定は誇張係数を取り、0 は静止です。ベイク結果自体は、常に生成された ID と ±30 で保存され、これらの設定は再構築時に適用されます。物理パネルで「シミュレーション」由来の振り子を改名するのもここに書かれ、振り子は引き続きベイクが駆動します。

### 設定

| 項目 | 意味 |
| --- | --- |
| モード数（1–3、既定 2） | いくつのパラメータを生成するか。それぞれが、当てはめた振り子の 1 頂点で駆動されます。最初のモードは全体の揺れです。そのあとのモードは、下にさらに掛ける 1 節、または独立した振り子 1 本で、上のモードが表せない部分だけを補います。物体が遅れるときの曲がり、積み重なり、圧縮です。モードが 1 つだけのとき、形状は振り角に合わせて全体が動くだけで、布の圧縮感が欠けます。そのため既定は 2 つです。長い毛束やリボンには 3 つを使えます |
| 上下パラメータ（自動 / オン / オフ） | 上下方向の入力を、単独で `ParamSim<id>_Y` へベイクするかどうかです（以下を参照）。「自動」は、それらが物体を 2px 以上動かすときだけ生成します。「オン」は常に生成します。「オフ」のとき上下入力はベイクに参加せず、上下入力しかないときはエラーになります |
| キー数（3 / 5 / 7 / 9） | 各モードパラメータと各正確ポーズパラメータ上のキー数で、均等に分布します。多いほど弧に沿え、増えるのはキーフォームでありパラメータではありません |
| 誇張（×1–×2、既定 ×1.3） | モードの揺れがシミュレーションよりどれだけ大きいかです。キーフォームへ書き戻すときに効き、変えるとすぐに作用し、ベイクし直す必要はなく、パラメータが端に張り付くこともありません。二次元のスタイルでは、実物より少し大きいほうが映えることが多いです |
| 正確なポーズ | 自分の軸上で正確な補正としてベイクするパラメータ（最大 4 つ）。既定ではベイクしません |
| モードの書き方 | 「自動」（既定）、「ブレンドシェイプ」、または「キーフォーム軸」。2 つの書き方の再生効果は同じです。キーフォーム軸はすべての Cubism バージョンが読めますが、各モードがメッシュのキーフォーム数をそのキー数倍にします。ブレンドシェイプ（Cubism 4.2+）のキーフォームは、既存のキーフォームの上に重なります。「自動」は、いずれかの対象メッシュのキーフォームが 64 個を超えるときだけブレンドシェイプを使います。対象バージョンが対応していないときは、一律キーフォーム軸として書きます |

ブレンドシェイプが省くのはキーフォームであり、パラメータではありません。たとえばメッシュがもともとキーフォーム 9 個、モード 2 つ、各 5 キーのとき、キーフォーム軸として書くと 9 × 5 × 5 = 225 個、ブレンドシェイプとして書くと 9 個にブレンド形 8 個を足したものです。

### 手順

1. **正確なポーズ**：Rig を、各正確ポーズパラメータの各キーへ置き、物体を静止させ、Rig との差をそのパラメータ軸上の補正キーフォームとして書きます。正確ポーズパラメータが指定されていないときは、この手順を飛ばします。
2. **入力を 1 つずつ駆動**：ベイクに参加する各入力を単独で駆動し、ほかの入力は既定値に止めます。1 区間は 0.15 秒でトレーニング範囲の上端へ回り、物体が静止するまで止まり（最長 1.6 秒）、既定へ戻り、下端へ回って戻ります。もう 1 区間は 0.25 Hz から 3 Hz への対数スイープで、3 Hz 付近では振幅が徐々に小さくなります。各区間は静止から始まり、それぞれの物体の複製上で並列にシミュレーションされ、左右と上下の 2 組がこれらのシミュレーションを共有します。各フレームは、物体と Rig（正確ポーズの補正を加えたもの）との差を記録し、各メッシュ自身のキーフォーム座標へ換算します。各組には別に、その組の入力が一緒にドラッグされ、揺れ、待機で揺れる区間があり、検査にだけ使います。各区間は運動量で均衡するように重み付けされ（最大 100 倍の差）、物体を少ししか動かさない入力も正しく当てはめられ、大きく振り出される入力に押しつぶされません。
   以前はすべての入力が同じ区間のモーションの中でそれぞれランダムに動き、当てはめはどの入力が物体を動かしたのか区別できませんでした。`tml` の後ろ髪では `ParamBodyAngleX` が毛根をおよそ 70px 動かすのに、振り子はそれに 1% の影響度しか与えず、マウスドラッグに追従するとき書き出しの振れ幅はシミュレーションのおよそ 2 割でした。1 つずつ駆動したあと、各入力は、物体をその入力の仕方で動かす影響度を得ます。
3. **振り子**：Cubism の振り子 `PhysicsSim_<id>` を 1 本当てはめ、節数はモード数に等しく、モードを 1 つずつ当てはめます。先に最初のモードの節だけを当てはめ、そのあと後ろのモードを 1 つずつ当てはめ、各モードは上の各モードが読み取れない残りの動きだけを当てはめ、その残りの動き自身の主方向の中で当てはめます（全体の動きの主方向ではありません）。最後にすべての節と影響度を一緒に微調整し、読み出しは常にモード順に 1 つずつ求めます。後ろのモードには 2 種類の候補があります。振り子の下にさらに 1 節を掛ける（振り子の頂点は上の頂点からしか影響を受けないので、1 節足しても上のモードは変わらず、4 つの起点から探索する）か、独立した単節の振り子 `PhysicsSim_<id>_<k>` を使い、自分の入力、振り子長、反応速度を持つ（圧縮の加速度への反応は、揺れより速く硬いことがあります）かです。検査モーションでより良いほうを使い、パラメータ数は変わりません。一緒に当てはめると、隣り合う頂点の振り角がほとんど同期し、2 つのモードの形がとても大きくなって互いに打ち消し合い、トレーニング以外のモーションで歪みます。採点は誤差だけでなく全体の効果を見ます。シミュレーションへの追従の程度、入力が止まったあとの振り出しと戻りの程度（別に 1 回数える）、各区間のモーションでシミュレーションより震えていないかです。各入力のタイプ（X の平行移動または角度）と初期影響度は、小さな重ね合わせの最小二乗で見積もり（入力が 6 個以下のときはすべてのタイプの組み合わせを 1 つずつ比べ、残差が最小のものを取る）、そのあと Nelder–Mead が各節の振り子長、反応速度、揺れやすさ、収束の速さ、各入力の影響度を同時に探索します。各候補は、書き出しと一致する計算で、実振幅によりすべてのトレーニングモーションを一度再生してから採点します。いくつかの候補のうち、検査モーションで最も得点の高いものが勝ちます。
4. **モードパラメータ**：振り子の第 k 頂点の角度を、-30…30 のパラメータ `ParamSim<id>_<k>` へ書き込みます。出力倍率は、振り子がすべてのトレーニングモーションと検査モーションの中で出した最大振り角に、さらに 10% の余裕を残して決めるので、パラメータは ±30 に張り付きません。パラメータが端で止まると髪が止まり、カクつきに見えます。パラメータ範囲を ±1 ではなく ±30 にするのは、キーフォーム軸がキーから 0.001 以内の値をキーへ吸着し（Cubism のランタイムも同様）、±1 の範囲では大きな物体が静止位置を通過するたびに、この吸着で一瞬止まるからです。
5. **キーフォーム**：モードごとに最小二乗で解きます。各モードのキーフォームは、前の各モードが説明したあとに残った形状をフィットし、各フレームの形状は、各パラメータが振り子の再生値にあるキーフォーム補間の和に等しくなります。キーフォームは滑らかな曲線上に制約され、隣り合うキーでは急に曲がらず、静止キーでは直線が通ります。そうしないと、パラメータがキーを掃くとき速度が急変し、これも一種の引っかかりです。そのあと検査モーション上で 2 つの調整を行い、追従が良くなり、より震えないときだけ採用します。各モードのキーフォームからほかのモードを差し引いてから、それぞれもう 1 周解き（一緒に解くのに近づき、互いに打ち消し合わない）、後ろのモードは ×0.25、×0.5、×0.75 のゲインを試し、小さなモーションで邪魔するのを防ぎます。ほとんど動かないパラメータは生成されません。

**上下方向は単独でベイク**：Cubism の振り子は重力に沿って垂れ下がり、出力するのは角度だけなので、根元が垂直に上下しても角度は変わらず、上下の動きは入力をどう設定してもそれを駆動できません。やり方は、作画者の `裙y`、`长发y` 物理グループと同じです。物体を左右より上下へ多く動かす入力（通常はうなずき、体の上下、前後傾）をほかの入力から分け、手順 3–5 を単独でもう一度走らせます。単節の振り子 `PhysicsSim_<id>_y` を当てはめ、モードパラメータ `ParamSim<id>_Y`（名前は「<シミュレーション名> Y」）を駆動し、キーフォームは物体が上下に遅れ、戻る形状です。2 組のパラメータのキーフォームはメッシュ上で加算されます。上下の動きが 2px 未満のときはこのパラメータを生成しません（上下パラメータが「オン」のときは常に生成し、「オフ」のときは生成せず、上下入力はベイクに参加しません）。上下入力しかないときは、すべてのモードをこの方式で当てはめます。`tml` のスカートでは、しゃがみ / 立ち上がりのときシミュレーション中の残差は最大 47px で、以前のベイク後は静的な傾きが 1 つ残るだけでした。分けてベイクしたあと、検査モーションの R² は 0.37 から 0.61 へ上がりました。

R² は、見た目が合っているかどうかの唯一の基準ではありません。振れ幅が小さく、位相が少しずれているとき、最小二乗はキーフォーム全体を縮小して誤差を下げようとし、書き出したモーションは生気がないように見えます。そのためベイク完了後、パネルは先に各組の検査モーション上の視覚検査を表示します。

| 指標 | 意味 | 警告 |
| --- | --- | --- |
| 振れ幅 | 先端（動きが最大の 10 分の 1 の頂点）が、シミュレーションの主方向に沿って揺れる量。書き出しとシミュレーションの比 | ×0.75–×1.3 の外 |
| 遅れ | 書き出しがシミュレーションより何ミリ秒遅いか（相互相関のピーク） | 80 ms を超える |
| 収まり | 入力が止まったあと静止へ戻るのに必要な時間。書き出しとシミュレーションの比 | ×0.6–×1.6 の外 |
| ジッター | 三階差分エネルギーの比の平方根 | ×1.5 を超える |

方向が逆のときも同様に警告します。MCP はさらに、方向の一致度、戻り回数の差、端に張り付いて止まったフレームの割合、毛束の短縮の程度、静止時の偏差を返します。そのあとの 1 行は R² と、95% のフレームのシミュレーションとの最大偏差です。端に張り付くフレームがある、またはジャークがシミュレーションの 1.5 倍を超えるときは、別に 1 行警告します。各モードパラメータの振れ幅は「詳細」にあります。MCP の `simulation_bake` は、すべての指標と各入力の読み取り結果（`inputs`）を返します。

ベイク後の振り子グループは通常の生成グループと同じく、物理パネルで閲覧、変更、オフにできます。物理パネルでの変更は、生成振り子への上書きです。再ベイクする、または出力の ID や範囲を変更したあと、上書きは三方マージで新しい振り子へ運ばれます。変更したフィールドだけが残り（出力倍率は元の値との比で残ります）、残りは新しい当てはめの値を取り、出力はパラメータの改名に追従し、変更後が新しい振り子と同じになった上書きは取り除かれます。ベイクを消去する、物体を削除する、または新しいベイクがある振り子をもう生成しないとき、その上書き、停止状態、順序は一緒に取り除かれます。

### 効果と所要時間

モデルプリセットが生成した物体（モード 2、キー 5、誇張 ×1）について、ベイク時に現れなかった 13–15 区間のモーション上で、参照シミュレーションと書き出しモデル（Cubism の振り子 + キーフォーム）をフレームごとに比べました。フェイストラッキングに類するマウス追従、頭と体の左右の傾き、組み込みの Idle / Nod / Shake、各入力のステップ、頭を回す、ドラッグ、揺らしです。シミュレーションの中で先端が 10px 以上動いたモーションだけを集計します（括弧内は区間数）。残りのモーションは除外された入力だけが駆動し、シミュレーションの中には物体が動き出すときのわずかな揺れしかなく、計上すると各指標が 0 へ引っ張られます。「方向が合う」は、揺れの方向が一致する（余弦 ≥ 0.9）モーション数です。振れ幅は、各モーションの書き出しとシミュレーションの比が 1 から外れた量の中央値を倍数へ換算し戻したもの、R² は各モーションの平均（-1 未満は -1 として計算）、静止偏差は入力が 1 秒以上止まったときの書き出しとシミュレーションの距離（95 パーセンタイル）です。前の列は、以前モーションライブラリでトレーニングした結果、後ろの列は入力を 1 つずつ駆動した結果です。

- 後ろ髪の、体の左右の傾き（`ParamBodyAngleZ`）に対する揺れの周期（およそ 1.3 秒）は頭を回すとき（およそ 0.9 秒）と違い、形状も違うので、モード 2 つではそこに割り当てられません（ds の後ろ髪の書き出しはほとんど動かず、tml の後ろ髪は振れ幅 0.59 倍、R² 0.11）。モードを 3 つにしても改善しませんでした。
- 頭の回転など、布をほとんど動かさない入力（シミュレーションは 2px 前後しか動かない）は直接除外され、ユーザーが頭を回してもスカートが理由なく揺れることはありません。

所要時間は 32 スレッドのデスクトップ機で測りました。シミュレーションと当てはめはマルチコアで並列なので、コアが少ないとより遅くなります。上表は開発ツール `SimBakeSuite` が生成し、各区間のモーションのすべての視覚指標と先端の軌跡図を出力します。使い方は[開発ツール](DEVELOPMENT.md#開発ツール)を参照してください。

### 期限切れ

ベイクは、それが根拠にした設定、対象メッシュ、ウェイトグループ、関係する Glue、ソルバのバージョンを記録します（ソルバが変わったあと、古いプロジェクトのベイクは期限切れと表示されます）。これらが変わると、パネルはベイクが期限切れになったと知らせます。ツールバーの自動ベイクをオンにすると、パネル内の変更が確定したあとバックグラウンドでベイクし直し（取り消しの独立した 1 歩）、前回の振り子から探索を始めるので、最初からベイクするより速いです。モデルプリセットの適用も、先に確定し、そのあとバックグラウンドでそれが生成した物体をベイクします。MCP の `simulation_put` は、物体自身の `auto_bake`（既定はオン）で決めます。別の場所で行った変更（メッシュ、ウェイト）は、引き続き期限切れと表示されます。期限切れのベイクは引き続き書き出され、「再ベイク」で更新します。「ベイクを消去」は、そのパラメータ、キーフォーム、振り子を取り除きます。自動ベイクが失敗した、またはキャンセルされたときは、古いベイクを残して理由を知らせます。対象メッシュが再構築されたとき（頂点数が変化）、そのメッシュのベイク結果は飛ばされ、パネルで知らせます。

### 書き出し結果と参照シミュレーション

パネル上部と、キャンバスの「シミュレーション」モードのツールバーで、プレビューの内容を切り替えられます。

- **書き出し結果**：プレビューはベイク結果を再生します。つまり、当てはめた Cubism の振り子が駆動するパラメータとキーフォームで、書き出したモデルのモーションと一致します。未ベイクの物体はここでは動かず、キャンバス左下に「未ベイクのシミュレーションがあります」と案内されます。
- **参照シミュレーション**：キャンバスはエディタ自身の物理シミュレーションを表示し、見比べるためだけに使い、書き出されません。キャンバス左下に警告色で「参照シミュレーション · 書き出されません」と示され、このときその物体自身の `ParamSim…` パラメータは静止したままで、2 回重ねられることはありません。

物体の編集領域の「比較」節は、両者を一緒に見ます。

- **表示**（参照シミュレーションがオンのとき使えます）：最初のプレビューキャンバスでの参照シミュレーションの表示方法です。「参照」（書き出し結果の代わり。上と同じ）、「書き出し」（書き出し結果だけを表示）、「重ね表示」（書き出し結果の上に半透明の参照シミュレーションを重ね、シミュレーションされているレイヤーだけを描きます）。キャンバスごとに覚え、ワークスペースとともに保存されます。
- **並べて表示**：参照シミュレーションをオンにし、プレビューキャンバスが 2 枚あることを確認します。1 枚目は書き出し、2 枚目は参照を表示し、両者は同じポーズに追従して同時に再生されます。
- **再生**：ドロップダウンからモーションを 1 つ選びます（組み込みの Idle、Nod、Shake、スケルトンがあるときはボーンモーション、およびユーザーモーション）。参照シミュレーションと書き出しの振り子が一緒に静止へ戻ってからそれを再生し、区間ごとに見比べやすくします。
- **検証**：バックグラウンドで、選択したモーションにより参照シミュレーションと書き出しモデルをそれぞれ駆動し（ゲイン ×1）、ベイク節と同じ視覚検査を出します。MCP では `simulation_compare` に対応します。

## モデルプリセット

「モデルプリセット」パネル（旧「モデル設定」）の「物理演算とシミュレーション」グループは、よくあるパーツを一度にシミュレーションにしてベイクします。結果は通常のウェイトグループと物体で、そのあとも「シミュレーション」パネルで調整できます。パネルの「変形と口形」「モーション」「物理演算とシミュレーション」の 3 グループは、いずれもパラメータパネルのフォルダと同じスタイルの折りたたみ行で、右側に要約が表示されます。「モーション」グループが決めるのは、モデルに「基礎モーション」と「ボーンモーション」の 2 グループがあるかどうかだけで、個別のモーションはモーションパネルで有効化と調整をします。「物理演算とシミュレーション」は項目ごとに 1 行です。前髪と後ろ髪にはそれぞれドロップダウンがあり、「シミュレーション / 従来のスイング / オフ」の間で切り替えます。衣装とゼリー目はチェックボックスで、チェックするとプリセットが適用され、外すと取り除かれ、衣装のメッシュごとのゆったり度一覧は衣装の行の下に表示されます。コントロールの横の灰色の文字は現在の内容を説明し（シミュレーション済みの衣装部位、原画にそのパーツがない。ホバーで全文）、未ベイク、またはシミュレーションの物体が削除されたときは警告色で知らせます。上部ツールバーの「選択のみ（n）」は、チェックを選択中のレイヤーだけに作用させ（チェックを外すときは常に全体を取り除きます）、右側は「Pin 物理ウェイトを自動設定」です。ベイクの進行とキャンセルは下部のステータスバーにあり、失敗理由はグループ内の下部に表示されます。チェックのたびに取り消し 1 歩で、MCP では `model_apply_preset` ツールに対応します。

同じパネルの「部位とモジュール」グループは、部位（頭と顔、目、眉、口と下半顔、髪、体、衣装と装身、表情、モーション）ごとに、Rig を自動生成するモジュールを列挙します。各カードは左右両側を扱い、各モジュールは 1 行で、チェックでスイッチし、右側の灰色の文字は、現在の素材に対してそれが新たに追加するパラメータ、キーフォーム、物理グループです（オフのときは推定値で、“≈” とマーク）。オンにすると、その少量の調整値が表示されます。現在の素材に適用できるモジュールだけが列挙されます。上部のプリセット（完全 / 標準 / 簡略）は、重要度に従って一度にスイッチし、パラメータ予算は「重要度が低いものから高いものへ、パラメータが多いものから少ないものへ」モジュールをオフにして、追加パラメータがそれを超えないようにし、右側のボタンで既定に戻します。新しいプロジェクトは既定ですべてオンです。モジュール導入前に保存したプロジェクトは従来どおり生成され、グループ上部にアップグレードできる案内が出ます。変更のたびに取り消し 1 歩で、MCP は `module_catalog` で閲覧し、`settings_update` の `changes.rig` で変更します。詳しくは [Rig プリセット構成](../spec/RIG_PRESETS.md) を参照してください。

「スタート」ページ（ワークスペースのタブバーの一番左、または「ファイル → スタートページ」）の「PSD から生成」は、PSD をインポートする**前**に同じプリセットをまとめます。プロパティパネル上部の「最小 / 既定 / 完全」は、それぞれ、バインドだけを残す（モーション、物理演算とシミュレーション、口の縁取りなし）、2 組のモーション + 髪の従来のスイング + 衣装シミュレーション + ゼリー目、既定を基礎に前後の髪をシミュレーションし顔のパーツの変位をオンにする、に対応します。下では項目ごとに調整でき、選択は覚えられます。そのあと、スタートページ、「ファイル」メニュー、最近使ったファイル、ドロップによる PSD インポートのいずれでも、生成後に変更されたプリセットが取り消し 1 歩として書き込まれ、そのあと髪と衣装のシミュレーションが順に生成され（各シミュレーションが 1 歩）、編集ワークスペースへ切り替わります。衣装は既定でオンで、原画で衣装が認識されると衣装シミュレーションが生成されベイクされます。PSD から生成したモデルがすでに開いているとき、「生成」ボタンメニューの「現在のモデルへ適用」は、同じプリセットをそれに被せます。右側の「インポート時に独立メッシュを確認」を有効にすると、新しい PSD プロジェクトは先に分割できるレイヤーを確認し、分割を確定するか原状を保ったあとでプリセットを適用します。「モデル → モデル全体の独立メッシュを確認…」から、手動で確認を始めることもできます。

| プリセット | 何をするか |
| --- | --- |
| 前髪 / 後ろ髪 | その種類の髪のすべてのメッシュを 1 つの髪の物体にまとめ（`preset_front_hair` / `preset_back_hair`）、各毛束（メッシュの各連結成分）は自身の上端から固定し、毛先へ向かって自由にし、書くのは固定点グループだけです。前髪は「前髪」材質、後ろ髪は既定の髪材質を使います。同時に、その種類の髪の旧スイング（`ParamHairFront/Back` パラメータ、`DeformHair*Physics` デフォーマと振り子）を取り除き、メッシュ（分割してできたパーツを含む）は追従デフォーマへ掛け替え、原画の位置は変わりません。「従来のスイング」または「オフ」へ選び直すと、その物体を削除して旧スイングを復元します（「オフ」は同時に旧スイングを停止します） |
| 衣装 | 上衣、下衣、首飾り、手（袖）、脚の装身のレイヤーを読み、原画でゆったりして見える場所だけをシミュレーションし、体に沿った部分はリグに追従します。下衣は先にスカートかズボンかを判定します。名前を優先し（裙、skirt、スカート / 裤、pants、ズボン など）、そうでなければアルファ輪郭を見て、股から裾まで続く中央の隙間をズボンと判定します。胴と下衣は行ごとに輪郭と体を比べます。体の輪郭は肩線（下衣は腰線）から始まり、下へはゆっくりとしか広がれず、超えた部分をゆったりと記録します（フリル、リボン、フレアの裾、コートの前開き）。上衣は腰線より下（腰線は下衣の腰線、または上衣の下まで伸びた脚の装身の上端）、スカートは臀部より下で臀部より広いとき、首飾りは結びより下を自由に垂れるとみなし、ストレートパンツとペンシルスカートは体に沿ったままにします。袖と脚の装身は四肢の曲がりに合わせ、モルフォロジーのオープニングに切り替えます。四肢の太さの半分の円盤よりまだ細い部分（袖口 / 靴下口のフリル、リボン）だけがゆったりと数えられ、パフスリーブや折り返しの袖口は四肢に従います。肌色の領域は常に体に沿い、指が開いてもシミュレーションされません。ゆったり度は、体に沿った領域までのレイヤー内距離で漸増し、固定点（1 − ゆったり度）、質量、風の影響（ゆったり度とともに増え、四肢の風の影響は小さめ）を生成します。ゆったり頂点が足りないメッシュは物体を作らず、もともと入っていた衣装プリセットの物体から移出します。物体は部位ごとに `preset_top`、`preset_skirt`、`preset_trousers`、`preset_neckwear`、`preset_sleeves`、`preset_legwear` に分かれ、ズボン、袖、脚の装身は硬めです。衣装の行の下にはメッシュごとに部位とゆったり割合のバーが並び、体に沿ったものは 1 行にまとまり、下衣にホバーすると判定根拠を見られます。チェックを外すと、すべての衣装プリセット物体を削除します |
| ゼリー目 | 目のゼリー振り子を切り替えます |
| 「Pin 物理ウェイトを自動設定」（ツールバー） | パーツの種類に従って、選択レイヤーまたはシミュレーション済みのすべてのメッシュの上述のウェイトグループを計算し直し、それらを使う物体をベイクし直します。物体は新規作成しません |

プリセットが書き込むグループ名は `preset_pin`、`preset_mass`、`preset_wind` です。物体が `groups` で自分のグループをすでに指定しているときは、そのグループをその場で更新します。同じプリセットを再度適用すると既存の物体が更新され、重ねられません。ユーザーが自分で作った物体にすでに属しているメッシュは拒否されます。風の影響グループは、現在のところ MCP の `simulation_simulate` に風を渡したときだけ作用します（上記を参照）。

## MCP

シミュレーションは操作ごとにいくつかのツールに分かれ、パラメータは `{"request": {...}}` に置かれ、どれも `id` で物体を指定し、`project_id`、`state`、`request_id` を伴います。これらはバックグラウンドタスクのハンドルを返し、`job_wait` / `job_get` で結果を取ります。

- `simulation_put`：`id` で物体を新規作成または部分変更します。フィールドには `targets`、`material`、`material_preset`（上表のプリセット名：`cotton`、`silk`、`chiffon`、`wool`、`denim`、`leather`、`elastic`、`hair`、`fine_hair`、`thick_hair`、`bangs`。同時に与えた `material` フィールドがその数値を上書きします）、`groups`、`glue_roles`、`inputs`、`modes`、`keys`、`exaggeration`、`static_inputs`、`blend_shapes`（`true` / `false` / `null` が自動）、`auto_bake`、`output_names`（パラメータまたは振り子の ID で名前を指定し、全体置換）、`input_ranges`（入力パラメータごとに `[min, max]` のトレーニング範囲を与え、全体置換）、`vertical`（`true` / `false` / `null` が自動）、`outputs`（生成されたモードパラメータ ID ごとに `{id, range, gain}` を与え、全体置換。ベイクし直す必要はありません）、`force_inputs`（ほとんど物体を動かさなくても残す入力）、`training_clips`（トレーニングに参加するモーション、`{モーション: 0.05–1}`、全体置換）があります。新規作成時に `inputs` を与えないと既定入力が書き込まれ、空配列を与えると入力がありません。`auto_bake` がオン（既定）のときは同じステップ内でベイクし直し、`bake` の要約または `bake_error` を返します。
- `simulation_simulate`：読み取り専用の試算です（パネルに対応するボタンはありません）。各入力を `hold` 秒保ってから離し、`release` 秒観察し、任意で `wind` を付け、ピーク、静止ドリフト、伸び、設定の案内を返します。
- `simulation_bake`：ベイクします（数秒）。各モードパラメータと振れ幅、キー数、振り子 ID と節数、独立振り子の ID（`own_pendulums`、あるとき）、各入力の読み取り結果（`inputs`：物体を動かす距離、平行移動と回転だけか、所属グループまたは除外済み）、各組の検査モーション上の視覚検査（`visual`）、ベイク方法（`method`）、および検査モーション上の `fit_r2`、`error_p95_px`、`parameter_peak`（モードパラメータが範囲を最大どれだけの割合まで使ったか）、`clipped_frames`（端に張り付いたフレームの割合）、`jerk_ratio`（ジャークとシミュレーションの比）を返します。
- `simulation_compare`：読み取り専用のバックグラウンドタスクです。`motions` のモーション（ユーザーモーション ID または組み込み名、最大 8 個）で参照シミュレーションと書き出しモデルをそれぞれ駆動し、各モーションの視覚検査を返します。
- `simulation_clear_bake`：ベイクを消去します。
- `simulation_delete`：物体を削除します。

参照シミュレーションのプレビューは試聴セッションに対応し、ドキュメントと履歴には入りません。`simulation_preview` は `mode=start` と `simulation_id` で開始し（`restart` / `stop` は `session_id` を伴います）、`simulation_preview_step` は `dt` 秒（最大 0.1）ずつ 1–240 歩進め、`simulation_preview_get` は現在のフレームを読み、`simulation_preview_render` は現在のフレームを描画します。

`vertex_group_update` は規則（`fill`、`outline`、`gradient`、`glue`、`region`）でウェイトグループを生成し、`delete=true` で削除し、頂点ごとの配列は渡しません。`vertex_group_paint` は、キャンバスと同じブラシ、グラデーション、反転でウェイトを変更します。`workspace_inspect` の `scope=simulations` は物体、Glue のキー、ベイク要約（`bake_stale` を含む）を列挙し、`scope=vertex_groups` はウェイトグループを列挙します。

## 現在の範囲

- 実装済み：布と髪（XPBD ソルバ、面積による質量の割り当て、三角形の面積と裏返り防止、回転に基づく曲げ、自動の布目と異方性、固定点、Glue の役割、長距離制約）、頂点ウェイトグループ、参照シミュレーションのプレビュー、パラメータ + キーフォーム（ブレンドシェイプまたはキーフォーム軸、自動選択可）+ 振り子へのベイクと書き出し、自動ベイク、誇張係数。モデルプリセット（髪のシミュレーションが旧スイングを置き換え、ゆったり度に従って上衣 / スカート / ズボン / 首飾り / 袖 / 脚の装身をシミュレーションし、Pin 物理ウェイトを自動設定）。
- 実測：上表の tml 後ろ髪の比較データ。モデルプリセットの tml 上のベイク（検査モーションの R² / 95% 誤差。旧ソルバ上で測定し、新しい材質モデルの下で再測定が必要）：後ろ髪 0.69 / 229 px で、上部 10% を手で固定したときと同じ。前髪 0.25 / 185 px で、どの固定範囲に換えても 0.2–0.3。前髪の問題は材質にあり、固定範囲にはありません。額に沿って横へ掃く前髪は、後ろ髪のように毛束の長さが重力を担わず、既定の髪材質の弱い戻りがそれをおよそ 0.75 Hz の柔らかいばねにし、左右に頭を振るとき（1.2 Hz）スケルトンから 74 px 外れ（スケルトンが動かすのは 33 px）、うなずきのときは 47 px です。「前髪」材質へ変えたあと（新しい材質モデル、tml / ds）：頭振り 41 / 30 px、うなずき 12 / 10 px、頭を回して止めたあとの残留 10 / 6 px、ベイク R² は 0.18 → 0.27 / 0.21 → 0.49、95% 誤差は 216 → 85 / 112 → 57 px。スカートのデータは、すでに取り除いた衝突機能の下で測ったもので、再実測が必要です。髪に質量 / 風の影響グループを足すと、後ろ髪の R² が 0.69 から 0.56 へ下がるので、髪プリセットはこの 2 グループを書きません。
- 障害物：シミュレーションの物体は障害物（`obstacles`）を持てます。別のメッシュに追従する円またはカプセルで、粒子は外に遮られ、参照シミュレーションとベイクに参加し、リアルタイムシミュレーションを再生するランタイム対象（p2lrt、ウェブ）へ書き出されます。現在のところ MCP の `simulation_put` からしか書けず、キャンバス上にはまだ編集の入り口がありません。より早いメッシュ衝突体（辺からの距離による）は実測で信頼できず、取り除かれました。古いプロジェクトのこの種の衝突体と衝突ウェイトグループは、読み込み時に無視されます。
- 未実装：風などの力場の書き出し、剛体と軟体、通常キーへのベイク（ジェネレーターを外す）。
- ゆったり度ヒートマップの目視確認（tml、ds、および Q 版素材 1 点）：tml はスカートの下半分だけがゆったり。ds はエプロン、腰の後ろのリボン、スカートの裾がゆったりで、パフスリーブ、袖口、靴下口は体に沿う。Q 版の開いたコートは腰線より下がゆったりで、ストレートパンツは体に沿う。
- 未実測：サンプルモデル上のスカートと髪を書き出したあと、公式ランタイムでの視覚効果。モデルプリセットが生成した髪と衣装のシミュレーションの自然さ。
