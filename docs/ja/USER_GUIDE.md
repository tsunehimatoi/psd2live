## 動作環境

- **OS**: Windows 10/11 x64（公式 Cubism 5-r.5 ネイティブ描画推奨。Linux / macOS では CPU ソフトウェア描画へ自動フォールバック）。
- **Java 環境**: JDK 21 以降（JetBrains Runtime / OpenJDK 21+ 推奨）。
- **入力ファイル**: レイヤー分けされた `.psd` ファイル（8-bit RGB カラーモード、透明チャンネル付き）。

## 起動方法

### 1. Windows クイック起動
プロジェクトルートの `run-gui.bat` をダブルクリックして起動します。

### 2. Gradle コマンドライン起動
```powershell
# Windows (PowerShell)
.\umamo\gradlew.bat -p .\psd2live run

# Linux / macOS (Bash)
../umamo/gradlew -p ./psd2live run
```

## デスクトップ GUI の概要

メイン画面は**左側ワークスペース + 右側インスペクター + 下部の独立ログドックとステータスバー**で構成されます。

- **メニューバー**:
  - **ファイル**: `PSD を開く...` (`Ctrl + O`), `再解析` (`Ctrl + R`), `出力先を開く`, `生成して書き出し` (`Ctrl + G`), `名前を付けて書き出し...` (`Ctrl + Shift + G`), `終了`.
  - **言語 (Language)**: 簡体字中国語 (`zh`)、英語 (`en`)、日本語 (`ja`) を即時切り替え。
  - **Agent / MCP**: 接続・Skill 設定を開くか、バージョン履歴ツリーへ直接移動します。右上の状態バッジからも接続画面を開けます。
  - **ヘルプ**: バージョン情報および著作権表示。
- **スプリッターバー**: 中央の境界線をドラッグして幅の比率を `25% ~ 85%` で調整可能。

## ワークスペース画面

### 1. 階層ビュー (Hierarchy)
- **デフォーマ＆描画要素ツリー**: 生成されたデフォーマ階層（`BodyXY` -> `BodyZ_Breath` -> `HeadRotation` -> `HeadContainer` -> `FaceNinePose` -> パーツ Warp -> ArtMesh）を表示。
- **VS Code スタイルガイド線**: インデントガイド線と展開/折りたたみ矢印で親子関係を明確化。
- **イアータブ折りたたみ**: ヘッダー左のボタンをクリックしてツリーを左端のコンパクトなタブへ折りたたみ、キャンバス領域を最大化可能。

### 2. トポロジービュー (Topology)
- **メッシュワイヤーフレーム**: 半透明背景上に適応型 Delaunay 三角分割メッシュを描画。
- **選択強調**: 選択された ArtMesh は太線（2.2px）で強調表示。
- **統計バッジ**: 描画要素数、頂点数、三角形数、現在のズーム倍率を表示。

### 3. プレビュービュー (Preview)
- **公式 Cubism 5-r.5 ネイティブエンジン (任意)**: Windows x86-64 環境では公式 Cubism Core/Framework ランタイム（`live2d_renderer.dll`）によるオフスクリーン OpenGL 描画に対応し、公式ランタイムと **100% 忠実な描画・物理挙動の一致性検証（Ground Truth）** を提供します。
  - *注：Live2D 社の専有ライセンス遵守のため、本プロジェクトのソースおよび配布物には公式 SDK バイナリは含まれず再配布も行いません。設定手順は [Live2D SDK 設定ガイド](CUBISM_SDK_SETUP.md) を参照してください。*
- **内蔵純 CPU ソフトウェアラスタライザー**: 公式 SDK 未設定時や Windows 以外の OS（macOS / Linux）では内蔵ソフトウェア描画が自動的に有効化され、追加設定なしで変形確認やパラメータ調整を行えます。
- **インタラクティブ機能**: マウス視線追従（Mouse Look）、6 秒間の呼吸/まばたきアイドリング、およびまばたき連動のぷるぷる瞳物理。
- **ステータスバッジ**: 左下のバッジに現在のズーム倍率、描画エンジン種別（`原生 Cubism` または `ソフトウェアラスタライズ`）、物理状態を表示。

### 4. 履歴ビュー (History)
- **追記専用の分岐ツリー**: System、User、Agent が作成した不変ノードを表示します。緑の `HEAD` は現在のワークスペースを示し、古いノードから編集すると既存の将来を削除せず新しい分岐を作ります。
- **ナビゲーション**: キャンバスのドラッグ、`-` / `+` によるズーム、表示リセット、サマリー／ノード ID／操作者の検索に対応します。
- **確認と復元**: ノードを選ぶと ID、親、リビジョン Hash、操作者、時刻を確認できます。「このノードに復元」は該当する編集可能素材と Rig を再構築し、履歴ノードは削除しません。

## 独立ログドック

ログはワークスペースのタブではなく、Hierarchy、Topology、Preview、History の下に常駐します。

- ヘッダー左の矢印で展開／折りたたみ、上端をドラッグして `80 ~ 450 px` の範囲で高さを変更できます。
- 「すべて」「システム」「Agent / MCP」「画像のみ」で絞り込み、メッセージ／タグ／詳細を検索し、自動スクロールを切り替えられます。ヘッダーにはログ数と画像数が表示されます。
- View 描画と素材インポートはインラインのサムネイルとして表示されます。クリックすると大きな市松模様プレビューで寸法とファイルサイズを確認し、画像をコピーできます。
- 「クリア」は現在の UI ログだけを消去します。「ログをコピー」は絞り込み後のテキストをコピーし、履歴やタスク記録を変更しません。

## AI Agent / MCP ホストへの接続

<p align="center">
  <img src="../imgs/agent.png" alt="PSD2Live AI Agent の素材生成・統合・複数パラメータ描画ワークフロー" />
  <br>
  <em>モデル View の確認、ホストネイティブ画像生成、レイヤー追加、複数姿勢の検証</em>
</p>

PSD2Live は起動時に、Bearer Token で保護された Streamable HTTP MCP を `127.0.0.1:23871/mcp` で公開します。アプリを起動したままにしてください。Token はローカルワークスペースの書き込み権限として扱い、公開またはリポジトリへコミットしないでください。

1. **Agent / MCP → Agent / MCP 接続とプロンプト…** を開きます。
2. 「接続設定」で対応する設定をコピーし、ネイティブ Streamable HTTP を優先します。
   - ChatGPT デスクトップ／Codex: HTTP TOML を `~/.codex/config.toml`、または信頼済みプロジェクトの `.codex/config.toml` へマージし、再起動後に `/mcp` を確認します。
   - Gemini／Antigravity: HTTP JSON の `psd2live` エントリを `~/.gemini/config/mcp_config.json` へマージし、MCP Servers を更新します。
   - その他の HTTP ホスト: 表示されたエンドポイントと `Authorization: Bearer <token>` を使用します。旧 `/sse` へ変更しないでください。
   - Stdio 専用ホスト: Stdio JSON をコピーし、Python 3 でリポジトリ直下の `mcp_proxy.py` を起動します。ブリッジは `PSD2LIVE_MCP_ENDPOINT`（既定は上記アドレス）、`PSD2LIVE_MCP_TOKEN`、任意の `PSD2LIVE_MCP_TIMEOUT` を読みます。Windows では PSD2Live が保存した資格情報へフォールバックできます。
3. 「導入プロンプト」には完全な設定手順があります。ドメイン作業では `.agent/skills/psd2live-rigging` と `.agent/skills/hair-separation` をホスト公式の Skill ディレクトリへコピーします。接続後はツールを列挙し、最初に `project_get_state` を呼び出します。

現在のツール：

| 機能 | ツール |
| :--- | :--- |
| プロジェクト確認 | `project_get_state`、`project_list_layers`、`project_list_parameters`、`object_get` |
| パラメータとキーフォーム | `parameter_create`、`parameter_update`、`parameter_delete`、`keyform_set`、`keyform_copy`、`keyform_delete`、`rig_k_pose` |
| モデル View | `view_render_layer`、`view_render_context`、`view_render_model` |
| 透明素材とレイヤー | `asset_import_png`、`layer_add_from_asset`、`layer_soft_delete` |
| 復旧と長時間タスク | `history_list`、`history_checkout`、`task_start`、`task_update`、`task_get`、`task_list` |

プロジェクトの `HEAD` を進める編集には現在の `expected_history_head_node_id` が必要で、成功後に返る新ノードを次の編集の基準にします。PNG の一時保存とタスクイベントの追記は `HEAD` を移動しません。タイムアウト、切断、セッション失効後はコミット状態が不明な場合があります。再接続し、`project_get_state`、`history_list`、タスク記録、対象オブジェクトを確認してから再試行を判断してください。Stdio ブリッジが自動再試行するのは安全な読み取りだけで、プロジェクト編集は再実行しません。

PNG View は UI スクリーンショットではなくモデルデータから生成され、可逆なピクセル↔キャンバス変換を持ちます。`asset_import_png` は `spatial_reference_id` で配置を維持し、View の一部だけを返す場合は `source_pixel_rect` が必要です。縦横比の不一致は引き伸ばさず拒否します。描画差分、パーツ分割、オクルージョン補完、ピクセル再構築では、Nano Banana Pro/NBP、GPT Image 2（`gpt-image-2`）、または同等のホストネイティブ画像ツールを実際に呼び出します。PSD2Live が提供するのは View とインポートであり、Python、PIL/OpenCV、SVG、Canvas で代替素材を描かないでください。

履歴、タスク、空間参照、SHA-256 で重複排除された RGBA 素材は永続化されます。Windows の既定保存先は `%LOCALAPPDATA%/PSD2Live/agent-workspaces` で、JVM プロパティ `psd2live.agent.store` で変更できます。同じ正規化パスとファイル署名の PSD を再読み込みすると最後の `HEAD` が復元されます。

## インスペクターパネル

### 書き出し制御領域
- 出力先パス入力およびフォルダ参照ボタン。
- 書き出しオプション（物理演算、CMO3、MOC3）の切り替え。
- メインボタン「生成して書き出し」。

### モデル設定領域
- **アトラスサイズ**: プリセット (`1024`, `2048`, `4096`, `8192`, `16384`) + 数値入力スピン (`256 ~ 16384`)。
- **メッシュ間隔**: 間隔スライダー (`16 ~ 128 px`)、クイックチップ (`32`, `64`, `96`)。
- **頭部変形強度**: 9 軸変形および顔パーツ変形の倍率 (`0.0x ~ 4.0x`)。
- **身体変形強度**: 体幹動作および呼吸膨張の倍率 (`0.0x ~ 4.0x`)。
- **詳細設定**: テクスチャ余白 (`0 ~ 32 px`、標準 `2px`)、Alpha 閾値 (`0 ~ 255`、標準 `8`)。

### レイヤー管理テーブル
- 統計情報の表示（表示数 / 総数、認識数、未分類数）。
- 一括操作ボタン（すべて表示、すべて非表示、反転）。
- テーブル列：表示切替アイコン、レイヤー名・番号、セマンティックドロップダウン（31 種）、左右ドロップダウン（`NONE`/`LEFT`/`RIGHT`）。変更時は自動で再計算。

### パラメータ管理パネル
- パラメータ名・ID によるリアルタイム検索フィルター。
- 全体操作：アニメーション再生/一時停止、視線追従切替、全ロック解除、全リセット。
- パラメータ行：固定ロックボタン、名称・ID、スライダー、数値入力、個別リセットボタン。

## 生成・書き出しの流れ

1. **インポート**: 分割 PSD ファイルをウィンドウにドラッグ＆ドロップ。
2. **確認と微調整**: レイヤーテーブルで認識結果を確認；トポロジーでメッシュ密度を確認；プレビューで視線追従や物理を確認。
3. **任意の Agent 精修**: MCP ホストを接続し、モデル View を根拠にパラメータ、キーフォーム、素材を編集します。History で現在の `HEAD` を確認し、古いノードから編集すると新しい分岐になります。
4. **書き出し**: 出力先と形式を確認し、「生成して書き出し」 (`Ctrl+G`) を実行。

## CLI コマンド詳細

```powershell
# 基本実行
.\umamo\gradlew.bat -p .\psd2live run --args="--input D:/models/character.psd --output D:/dist/character"

# 詳細オプション指定
.\umamo\gradlew.bat -p .\psd2live run --args="--input D:/models/character.psd --output D:/dist/character --atlas 8192 --mesh-spacing 48 --head-strength 1.2 --lang ja"
```

| オプション | 型 | 既定値 | 説明 |
| :--- | :---: | :---: | :--- |
| `--input <path>` | パス | *(必須)* | 入力 PSD ファイルパス |
| `--output <path>` | パス | `PSD同階層/psd2live-output` | 出力先ディレクトリ |
| `--lang <zh\|en\|ja>` | 文字列 | システム言語 | 言語設定 (`zh` / `en` / `ja`) |
| `--atlas <size>` | 整数 | `4096` | テクスチャアトラスサイズ (`256 ~ 16384`) |
| `--mesh-spacing <px>` | 整数 | `64` | 基本メッシュ間隔（ピクセル） |
| `--head-strength <val>` | 浮点数 | `1.0` | 頭部 9 軸変形倍率 |
| `--body-strength <val>` | 浮点数 | `1.0` | 体幹動作・呼吸倍率 |
| `--no-physics` | フラグ | `false` | `physics3.json` および CMO3 物理設定の生成をスキップ |
| `--no-cmo3` | フラグ | `false` | `.cmo3` プロジェクト書き出しをスキップ |
| `--no-moc3` | フラグ | `false` | `.moc3` ランタイム書き出しをスキップ |
| `--help` / `-h` | フラグ | - | ヘルプメッセージを表示 |

## トラブルシューティングと FAQ

- **Q: Agent が接続できない、または再接続時にセッション失効と表示される**
  A: PSD2Live を起動したまま、接続画面から現在のエンドポイントと Token を再コピーしてください。ネイティブ HTTP ホストは `/sse` ではなく `/mcp`、Stdio ホストは `mcp_proxy.py` を使用します。再初期化後、変更を続ける前に `project_get_state` と `history_list` を読みます。
- **Q: 古い履歴ノードへ復元すると、その後の編集は削除されますか？**
  A: 削除されません。ノードは追記専用で不変です。復元で移動するのはワークスペースの `HEAD` だけで、そのノードから編集すると元の将来を保持したまま新しい分岐が作られます。

- **Q: 起動時に Java バージョンエラーが発生する**
  A: JDK 21 以降がインストールされ、`JAVA_HOME` が正しく設定されていることを確認してください。
- **Q: 一部のレイヤーが unknown と判定される**
  A: 命名規則に一致しないレイヤーは unknown となり、Y 座標に応じて頭部または体幹に自動配置されます。レイヤーテーブルで手動でタグを変更可能です。
- **Q: 閉眼時にまつ毛が歪んだり裂けたりする**
  A: `eyelash` レイヤーに下まつ毛や下まぶたの輪郭が含まれていないか確認してください。閉眼アルゴリズムは上まつ毛の Alpha 重心軌跡を下方へ湾曲させます。下まつ毛が混在していると重心が眼球中央へ引っ張られ、激しい圧縮破綻が生じます。**まつ毛は目の上半部（上まつ毛）のみに限定**し、下まつ毛は `facedetail` 等の独立レイヤーへ分離してください。
- **Q: 口を閉じたときに輪郭がぼやけたり色が濁る**
  A: 原画の `mouth` は必ず**最大開口状態**で描画し、**唇の外周に明確な線画・輪郭線（アウトライン）を設けることを推奨**します。求心圧縮時、明瞭な輪郭線同士が自然に重なって綺麗な閉口リップラインを形成します。輪郭線のないグラデーション塗りは圧縮時にぼやけや肌色との癒着が発生しやすくなります。
- **Q: 原画の頭部が傾いている場合、垂直に強制補正されますか？回転範囲はどうなりますか？**
  A: 強制的に直立補正されることはありません。両目の基準線から頭部の初期傾き（`initialAngleZ`）を自動検出し、回転デフォーマの軸を合わせます。顔の九軸変形や `ParamAngleZ`（$\pm 30^\circ$）は、**原画の初期角度をニュートラル基準として可動域を展開**します。初期の傾きは自然な範囲（$\pm 25^\circ$ 以内）に留めることを推奨します。
- **Q: 大きく寝そべったり過度に傾いた立ち絵はサポートされますか？**
  A: **過度に傾いた身体はサポートしていません**。身体三軸変形（`ParamBodyAngleX/Y`）や胸部呼吸（`ParamBreath`）は垂直なキャンバス座標系を前提に構築されているため、過度に傾いた体幹では呼吸が横方向に歪み、回転時に深刻なメッシュ破綻を招きます。身体は直立姿勢を保ってください。
- **Q: 目を閉じたときに瞳が消えない**
  A: 瞳（`irides`）は白目（`eyewhite`）をクリッピングマスクとして参照します。`eyewhite` レイヤーが存在し、閉眼時に白目が縮小して瞳が隠れる構造になっているか確認してください。
- **Q: 書き出した `.cmo3` を Cubism Editor で開くと元画像再構築の警告が出る**
  A: CMO3 内の画像はアトラス切片から再構成されているためです（`MissingSourceArt` は正常な動作です）。Modeler 上でのキーフォーム編集やデフォーマ修正には影響ありません。
- **Q: プレビュー画面に「ソフトウェアラスタライズ」と表示される／公式ランタイムの一致性検証を有効化したい**
  A: 本プロジェクトはオープンソースコンプライアンスおよび Live2D 社の専有ライセンス規約に従い、**公式 SDK の専有バイナリはソース・配布物に含まれておらず再配布も行いません**。SDK 未設定時は内蔵の純 CPU ソフトウェア描画が安全に動作します（モデルの解析や `.cmo3`/`.moc3` 書き出しには一切影響しません）。実機ゲーム環境や Cubism Viewer と **100% ピクセル単位で同一の描画・物理表現（Ground Truth）** で検証を行いたい場合は、[Live2D SDK 設定ガイド](CUBISM_SDK_SETUP.md) を参照して設定を行ってください。
