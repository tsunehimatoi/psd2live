# Agent の設計と受け入れ

[ドキュメント目次](../README.md) · [MCP インターフェース](MCP_AUTHORING.md) · [能力の実測](../STATUS.md) · [ロードマップ](../ROADMAP.md)

このページでは、Agent / MCP 接続の設計上の境界と受け入れ方を説明します。具体的なインターフェース契約は、[MCP インターフェース](MCP_AUTHORING.md) と、サービス実行時の Schema に従います。

---

## 1. 役割分担

| 役割 | 責務 |
| --- | --- |
| **外部 Agent** | ユーザーの意図を理解し、対象オブジェクトを選び、ツール呼び出しと観察結果を計画する（画像生成はホストが提供する） |
| **PSD2Live** | 素材、メッシュ、パラメータ、物理、シミュレーション、分岐履歴について、決定的な操作を実行する |
| **モデラー** | 美術のスタイル、効果の取捨、最終的な受け入れを決める |

---

## 2. 中核の設計境界

- **統一コマンド経路**：GUI と MCP は、同じアプリケーション層のコマンド（`WorkspaceHost`）を共有します。どちらも、捕捉した開始時の `state` の上で候補を用意し、CAS で履歴ノードを 1 つ確定します。レンダリングスナップショットだけを変えた変更は、再構築または開き直しのときに失われます。
- **安定した ID 参照**：すべてのオブジェクトは決定的な ID で参照します。表示名を識別子の代わりには使いません。
- **並行と履歴**：`state` は楽観的並行制御に使います。履歴は追記のみで、書き換えません。古いノードをチェックアウトして編集を続けると、分岐になります。
- **オーサードポーズの分離**：プレビューポーズ（`preview_set/reset`、スライダーのドラッグ、自動キーフレーム）は `WorkspacePoseCommands` の補助 CAS を通り、Rig の編集履歴を汚しません。
- **素材と分割は同じ出所**：
  - 画像のインポートと位置合わせは、独立したセッションで用意してから、素材マニフェストを確定します。
  - 連結成分 / ポリゴンの分割（`source_split_components` / `source_split_polygon`）と、奥行きによる遮蔽の分割（`source_split_depth`）は、GUI と同じアプリケーション層のコマンドを共有します。プリセット ID を指定すれば、同じ原子的な一括処理の中で、新しいレイヤーの編集を続けられます。
- **厳密な出力契約とエラー**：公開操作はすべて `request` / `outputSchema` を宣言します（バックグラウンドタスクには、終態の `jobResultSchema` も含みます）。失敗は、構造化されたエラーコードと競合コンテキストを一律に返します。タスク照会の成功は、業務上の成功を意味しません。終態の `status` を確認してください。
- **要約を先にした観察**：照会はまず要約を返し、そのあと対象とページングで展開します。プレビューのスクリーンショットは固定したキャンバスのカメラを使い、元の素材、合成プレビュー、ランタイムモデルを明確に区別します。

---

## 3. タスク受け入れの確認項目

1. **事前確認**：プロジェクトの `state`、対象オブジェクトの ID、依存するレイヤーを確認します。
2. **一括と試行実行**：関連する複数の変更は、まず `workspace_preview_edits` で試行実行し、そのあと `workspace_apply_edits` で原子的に確定します。
3. **再実行と永続化**：変更のあと、取り消しとやり直しができること、そして `.psd2live` プロジェクトを保存して開き直したあとに結果が一致することを確認します。
4. **見た目と書き出しの再確認**：プレビューのスクリーンショットで複数パラメータのポーズを照合し、対象形式を書き出して、`.psd2live.json` の損失レポートを確認します。
