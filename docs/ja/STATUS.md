## 評価基準

| 評価 | 意味 |
| --- | --- |
| とても良い | 安定して完了する |
| 使える | 完了する。少量の人手による修正が必要 |
| ぎりぎり | 大量の手戻り、または人手による穴埋めが必要 |
| 使えない | 完了しない、または結果を受け入れられない |

成功したサンプルが少ないことは、他の素材でも同じように安定することを意味しません。

## 新しい記録の提出方法

各記録には、次を含めてください。

- アプリのバージョンまたは commit、ホスト、モデル。
- タスクの説明とソース素材。画像生成を使ったかどうか。
- サンプル数、手戻りの回数、所要時間、枠の消費。
- 結果ファイルまたは履歴ノード、および明確な通過 / 失敗の理由。

受け入れでは、実際のモデルの中立ポーズ、パラメータの端点、動的な効果を対照し、保存して開き直すことと、書き出し結果を確認します。参照画像だけ、ツールが成功を返したことだけ、またはスクリーンショット 1 枚だけでは、タスクの完了を証明するには足りません。

**メモリと残りのコスト。** 81／75／54 回の OS スナップショットが、それぞれ worker／ワークスペース／パーツツールを覆う。記録した worker は、最終的な解放のあとすべて終了した。圧力シナリオのジオメトリ保持量は、常に 2 MiB を超えない。プロトコルバッファ、JVM、履歴データは含まない。3 つのツールホストのサンプリングした常駐ピークは約 505.49／2,504.92／1,040.82 MiB、worker のサンプリングピークはそれぞれ約 696.64／子プロセスなし／784.06 MiB。これらは離散的なサンプリングのピークであり、総メモリの上限や、リークがないことの証明ではない。

実際の編集の 4 回の候補ビルドの合計中央値は約 1.38／1.33 秒で、そのうち `modifier author: wait for atlas pages` の累積中央値は約 1.32／1.27 秒であり、現在はっきりしている後続の最適化対象である。完全な履歴を閉じる、開き直すシナリオの中央値は、小／中／大が 13.25／10.90／13.33 秒。この区間は、閉じる、保持した読み手の検証、アーカイブを開く、再構築、完全な IR の比較、履歴メタデータの検証を含み、GUI を開く遅延として直接は扱えない。このあとはさらに区間を分け、履歴の保持と読み手を捕捉する契約を残し、履歴を削ってより低いメモリや時間を得ることはしない。

JVM プラグインの契約は、独立モジュール `algorithm-api` へ切り出した。ホストはこのモジュールに依存するよう変えた。インスタンスとパッケージの参照、バージョン解決、依存範囲、実際の評価インターフェースは、もはやアプリのソース定義に従わない。独立モジュールの 3 つの回帰は通過した。ホスト実装のない評価、古い JSON と固定参照の読み戻し、バージョン範囲の比較。この項目は、インターフェースを独立してコンパイルできることを証明する。内蔵アルゴリズムパッケージの読み込みと、履歴バイナリの保持が完了したことを意味しない。

物理グループのアルゴリズムは、インストールできる JVM パッケージとして独立してビルドした。開発ツールでの実測は、インストール、常駐プロセスでの連続 2 回の評価、アンインストール、元のパッケージを入れ直したあとの評価が、いずれも通過した。完全な結果は、アプリプロセス内の同じ実装と一致し、出力エイリアスと無関係な素材の保持を含む。インストールパッケージに、アプリ、UI、プロジェクト、Umamo のクラスは含まない。ワーカープロセスは、要約付きのモデルオブジェクトの差分で結果を返し、ホストに物理アルゴリズムを再実行させることはない。オブジェクト転送と構造検証の対象を絞ったテストは通過した。現在のパッケージ身元は `builtin.70687973696373.v1` に変わり、`physics` エイリアスでプロジェクトの型を保つ。完全なパッケージの保持、旧バージョンのディレクトリを開き直すこと、インスタンス JSON を読み戻したあとの固定参照の評価、アンインストールと再インストールの回復は、いずれも開発ツールの検査を通過した。エイリアスの衝突と管理 schema の対象を絞った回帰は通過した。これは、他の内蔵アルゴリズムの切り出しをまだ覆わず、完全なプロジェクトのコールド再生の受け入れが完了したことも意味しない。

モーションのアルゴリズムは `:algorithms:motion` へ移した。設定データ、JSON の読み書き、カーブ変換は独立モジュールが提供し、アプリの登録入口は呼び出しを委任するだけである。独立モジュールの 2 つの回帰は通過し、4 種の補間、イベント、パラメータの役割、固定の出力 ID、衝突、キャンセルを覆う。アプリのモーション回帰と、レイヤー分け制約の検査は通過した。物理演算とモーションの 2 つの独立パッケージは、いずれもインストール、常駐プロセスの評価、ディレクトリを開き直すこと、アンインストールと再インストールの回復検査を通過し、インストールパッケージにアプリまたは Umamo のクラスは含まない。この項目は、残りの生成テンプレートの移行をまだ覆わない。

ベイクするシミュレーションの評価は `:algorithms:simulation` へ移した。実際のインストールパッケージの検証は通過した。自動ウェイトは元のログ経路と一致し、出力はモードパラメータ、メッシュのキーフォーム、物理グループを含む。ディレクトリを開き直すことと、アンインストールと再インストールのあと回復できる。シミュレーションの書き出しと、ウィンドウなしのベイク入口に関係する回帰は通過した。数値ベイクは元のパイプラインで実行したままで、ソルバーは調整していない。基礎リグは、まだ独立した移行を待っている。この一群の移行は、ベイク結果の独立した評価を覆う。
