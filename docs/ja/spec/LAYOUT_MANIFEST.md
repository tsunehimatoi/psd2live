# Layout マニフェスト

[ドキュメント目次](../README.md) · [利用ガイド](../guide/LAYOUT.md) · [PSD 素材と命名](PSD_LAYER_SPEC.md)

Layout マニフェストは、PSD2Live がレイヤー分けした素材を読むための交換形式です。1 つの JSON ファイルで、1 枚のキャンバスがどの画像から成るかを書きます。各画像のパスとピクセルサイズ、キャンバス上の矩形、上下の順、所属するグループ、意味タグ、差分、可視性、不透明度、そして参照専用かどうかです。どのツールでも、このページに従ってマニフェストを書けます。PSD2Live はそれを使って、まだ生成していない Layout プロジェクトを新規作成するか、素材としてインポートします。

PSD と異なり、画像のピクセル数はキャンバス上の大きさと同じである必要はありません。小さいパーツはキャンバスより多くのピクセルを持てます。PSD2Live は[レイヤーごとのサイズ](DOCUMENT_LAYER.md#レイヤーごとの寸法)に従ってそれらを残すため、テクスチャはより密になります。

## ファイルと圧縮パッケージ

- マニフェストは UTF-8 の JSON オブジェクトで、拡張子は `.json`、16 MiB 以下です。画像パスは、マニフェストがあるフォルダからの相対パスです。
- マニフェストと画像を `.zip` にまとめることもできます。マニフェストは圧縮パッケージのルート、または圧縮パッケージ内の唯一の最上位フォルダに置きます（フォルダを直接圧縮したときによくあります）。PSD2Live はその階層で、`format` を宣言した JSON を見つけ、画像パスはそれに対する相対パスです。同じ階層にマニフェストが 2 つあるときは、読み取りを拒否します。macOS が付ける `__MACOSX/` と `._*` は内容に数えません。
- 画像は、PSD2Live がデコードできるいずれかの形式（PNG、WebP、JPEG、BMP、TIFF）です。非プリマルチプライド alpha の PNG を推奨します。1 枚は 16 MP 以下、1 つの画像ファイルは 1 GiB 以下です。画像の合計に上限はなく、PSD と同じく、デコード後に占めるメモリだけが制限です（1 枚ずつ読み、デコードし、元のバイトは同時には常駐しません）。レイヤーは最大 4096 です。同じ画像を複数のレイヤーが参照できます。

## 構造

```json
{
  "format": "psd2live-layout",
  "version": 1,
  "name": "character",
  "canvas": { "width": 3258, "height": 4344 },
  "groups": [
    { "path": "head", "visible": true, "opacity": 1 }
  ],
  "layers": [
    {
      "name": "source",
      "image": { "path": "source.png", "width": 3258, "height": 4344 },
      "rect": { "left": 0, "top": 0, "width": 3258, "height": 4344 },
      "reference": true,
      "opacity": 0.5
    },
    {
      "name": "back hair",
      "image": { "path": "parts/back_hair.png", "width": 484, "height": 601 },
      "rect": { "left": 804.3, "top": 207.0, "width": 1642.6, "height": 2039.6 },
      "tags": ["hair", "back"]
    },
    {
      "id": "iris_l",
      "name": "iris L",
      "image": { "path": "parts/iris_l.png", "width": 126, "height": 147 },
      "rect": { "left": 1724.24, "top": 745.36, "width": 101.65, "height": 118.63 },
      "group": "head/eyes",
      "tags": ["eye", "iris", "left"]
    },
    {
      "name": "mouth open",
      "image": { "path": "parts/mouth_open.png", "width": 183, "height": 78 },
      "rect": { "left": 1555.6, "top": 935.8, "width": 147.6, "height": 62.9 },
      "group": "head",
      "tags": ["mouth", "open"],
      "variant": { "type": "toggle", "parameter": "ParamMouthOpen" },
      "opacity": 1,
      "visible": true
    }
  ]
}
```

### トップレベル

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `format` | はい | 固定で `psd2live-layout` |
| `version` | はい | 整数。現在は `1`。PSD2Live は、自分より新しいバージョンの読み取りを拒否する |
| `canvas` | はい | `{width, height}`。キャンバスサイズ。整数のキャンバス単位。一辺は 1〜8192、合計は 16 MP 以下。キャンバス単位は、Cubism へ書き出したあとのモデルキャンバスのピクセル |
| `layers` | はい | レイヤーの配列。1〜4096 項目。順序は[上下の順序](#上下の順序)を参照 |
| `groups` | いいえ | グループの属性。`path`（必須）、`visible`（既定 `true`）、`opacity`（0〜1、既定 `1`）。パスは重複できない |
| `name` | いいえ | マニフェストの名前。素材フォルダ名に使う。省略時はファイル名 |

### レイヤー

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `name` | はい | レイヤー名。印字可能な文字で 128 以下 |
| `image` | はい | `{path, width, height}`。画像パス（相対パス。`/` 区切り。`..`、`.` の区間、バックスラッシュ、ドライブ文字を含まず、マニフェストがあるフォルダまたは圧縮パッケージのその階層の外へ出られない）と、画像のピクセルサイズ。サイズは画像と一致している必要がある |
| `rect` | はい | `{left, top, width, height}`。画像が敷き詰められるキャンバス矩形。浮動小数のキャンバス単位。幅と高さは正。キャンバスの外へ出てよい。ピクセルサイズと矩形の比がテクスチャ密度。`126 × 147` の画像を `101.65 × 118.63` の矩形に敷くと、キャンバス単位あたり約 1.24 テクスチャピクセル |
| `id` | いいえ | レイヤー ID。`[A-Za-z0-9_.:#-]{1,96}`。マニフェスト内で一意。その後の編集と MCP は、これでレイヤーを参照する。省略時は通し番号と名前から派生し、同じマニフェストは毎回同じ ID になる |
| `group` | いいえ | グループパス。名前を `/` でつなぐ。例は `head/eyes`。各段がソース画像のグループになる |
| `tags` | いいえ | 文字列の配列。意味タグとユーザータグ。[タグ](#タグ)を参照 |
| `variant` | いいえ | 差分。[差分](#差分)を参照 |
| `visible` | いいえ | 既定は `true` |
| `opacity` | いいえ | 0〜1。既定は `1` |
| `reference` | いいえ | 既定は `false`。`true` は[参照レイヤー](#参照レイヤー) |

未知のフィールドは無視されます。同じバージョンで追加されるフィールドはすべて任意です。既存フィールドの意味を変えるときは、バージョン番号を 1 つ上げます。

### 上下の順序

`layers` は後ろから前へ並びます。あとから書いたレイヤーは、先に書いたレイヤーの上に描かれます。これは PSD2Live のソース画像のレイヤー順と同じです（画家の順序であり、PSD2Live が PSD を読んで得る順序でもあります）。つまり Cubism の描画順が増える方向です。第 i 番のレイヤーの描画順は、第 i−1 番以上です。

PSD2Live のレイヤー表は、この順でレイヤーを列挙し、生成時にはこれで基礎の描画順を決めます。口などのジェネレーターには別の規則があり、描画順の定規にある設定が優先します。

### タグ

- `tags` の部位語と `left` / `right` が、パーツと左右を決めます。たとえば `["eye", "iris", "left"]` は左の瞳、`["hair", "front"]` は前髪です。語彙と組み合わせは[意味タグ](PSD_LAYER_SPEC.md#意味タグ)を参照してください。残りの語はユーザータグで、整理と検索にだけ使い、生成には影響しません。
- 部位語を含むときは、パーツも左右も `tags` から取ります（左右の語がなければ左右なし）。部位語を含まないか `tags` を省略したときは、レイヤー名からパーツと左右を識別します。規則は PSD レイヤーと同じです（[名称の参照](PSD_LAYER_SPEC.md#名称の参照)を参照）。このときも、`tags` の左右の語が左右を決めます。
- 左右はキャラクター自身の左右です。キャラクターの左側は、通常は画面の右側にあります。
- 同じレイヤーに `left` と `right` を同時に付けることはできません。

### 参照レイヤー

`reference` が `true` のレイヤーは参照専用です。たとえばパーツを分ける前の原図で、配置や描画の対照に使います。他のレイヤーと同じく順序、グループ、不透明度を持ち、キャンバスに表示されますが、ジェネレーターは読みません。Rig とすべての書き出しには含まれず、タグは不要です。開いたあと、いつでもモデルレイヤーへ戻せます。まだ生成していない他のレイヤーを参照にすることもできます（素材と Layout の実装を参照）。

### 差分

`variant` は `{type, parameter, switch_id}` で、MCP の `layer_set_variant` と同じです。

| `type` | 意味 | `parameter` | `switch_id` |
| --- | --- | --- | --- |
| `none` | 差分なし（既定） | 与えない | 与えない、または `0` |
| `toggle` | パラメータで表示または非表示にする | 必須 | 与えない、または `0` |
| `switch` | パラメータの `switch_id` 番目の選択肢 | 必須 | 非負の整数 |

## PSD2Live の読み方

- **プロジェクトとして開く**：「スタート」ページまたは開くダイアログでマニフェストか zip を選ぶ、ウィンドウへドロップする、または MCP の `project_import_layout`。まだ生成していない Layout プロジェクトを新規作成し、Layout ワークスペースに入ります。キャンバスは `canvas`、レイヤーはマニフェストどおりに配置され、画像は元のピクセルのまま矩形に敷かれます。タグと差分はレイヤー分類になり、ユーザータグはレイヤータグになり、`reference` のレイヤーは参照レイヤーになります。各レイヤーは同時に素材として登録され（`name` を名前にしたフォルダに置かれる）、それと関連付きます。そのあと通常どおり配置と上下の順を調整してから生成します。プロジェクトはマニフェストと画像ファイルを残さず、ピクセルはプロジェクト履歴に入ります。
- **素材としてインポートする**：素材パネルからインポートするか、MCP の `material_import`。`name` を名前にしたフォルダが 1 つ得られ、グループはサブフォルダになります。各項目の既定の配置はその `rect` で、ピクセルは元の解像度を保ち、`tags` が付きます。`reference` レイヤーの項目は、既定で参照として置くよう印が付きます。差分はレイヤーに属し、素材には付きません。フォルダ全体を置くときは、マニフェストの上下の順を保ちます。フォルダを走査するときは、その中の JSON と zip を飛ばすため、マニフェストの画像は通常の画像として 1 回だけインポートされます。
- 読み取りは、どのエラーでも止まって位置を示します（例：`layers[3]: parts/face.png is 808x935 pixels, the manifest says 800x935`）。部分的なインポートはしません。

## 検証

`LayoutManifestScenario` が覆う内容は次のとおりです。マニフェストを未生成のプロジェクトとして開くこと。画像がマニフェストのピクセルと矩形を保つこと（3 倍ピクセルのパーツは密度を保ち、分数の矩形も保つ）。上下の順、グループとグループの不透明度、タグ分類とユーザータグ、差分、不透明度、素材の登録と関連、参照レイヤーが Rig に入らないこと、生成後も入らないこと、戻したあと待機して次の生成に入ること。上下の順を調整してから生成すること、生成後のレイヤーが調整を拒否すること、保存して開き直すこと。ルートと最上位フォルダの 2 種類の zip が同じ内容を読むこと。素材としてインポートするとき既定の配置とタグが付くこと。フォルダ走査でマニフェストを飛ばすこと。範囲外のパス、サイズの不一致、より新しいバージョン、他の形式、1 つの圧縮パッケージ内のマニフェスト 2 つが拒否されること。PSD またはマニフェストの素材フォルダ全体を置くと、元の上下の順を保つこと。参照素材は印どおりに置かれ、置くときに別に指定できること。
