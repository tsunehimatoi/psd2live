# デフォーマとパラメータ

[ドキュメント一覧](../../README.md) · [中文](../../zh/spec/DEFORMER_AND_PARAMETER_SPEC.md) · [English](../../en/spec/DEFORMER_AND_PARAMETER_SPEC.md) · [PSD の準備と命名](PSD_LAYER_SPEC.md)

自動生成の標準構成と編集上の約束を説明します。実際の構成は素材・設定・編集によって変わるため、階層ツリー、パラメータパネル、MCP `workspace_inspect` の結果を確認してください。

## 構成

体の根は `DeformBodyXY` で、体自身のパーツ（胴体、服、腕、スカート、尻尾）と頭が回る首だけを覆い、髪や脚は含みません。体 X では腰から上の上半身がひとつの立体として中心線を軸に回り、腰も胸と同じだけ回って、腰回りで回転が消えていきます。胸の前面は回る側へ動き、前に出る肩は少し大きく低く見え、軸に近い首はほとんど動かないので、頭は常に体の中央にあります。体 Y では下向きで肩が少し開き、上向きで背筋が伸びます。体全体は腰とともに動き、体 X では少し横へ、体 Y の下向きでは膝を内に向けて沈み、上向きでは脚が伸びて少し高くなります。その下に `DeformBodyLean`（2 つのパラメータ。「身体の前後傾」：体は厚みのある立体として三次元で前傾し、透視で描かれます。骨盤が股関節を軸に一部だけ傾いてスカートを運び、背骨は腰で弧を描いて全角度まで曲がるので、腰だけが潰れることはありません。前傾では胸が透視で縮みながら下がって少し大きくなり、頭は形を保ったまま首とともに下がり、顔は下を向きます。後傾では小さくなり、顔は少し上を向きます。「頭身（デフォルメ）」：正の値では頭が首から一体として大きくなり、胸が広がり、胴体・腕・脚・スカートが短くなって上半身が下がり、デフォルメに近づきます。負の値ではその逆で等身が高くなります。足は動きません。スケルトンがない場合は腕ごとに体 X とこの 2 つを軸とする `DeformArmHang_L/R` もあり、腕は肩から垂れた一体として肩とともに動き拡大し、体と一緒に曲がりません。体 X では回る側の腕が大きく低くなることはなく、肩を軸に逆向きへ約 4° 振れ、手が体より少し遅れます。スケルトンがある場合は上腕の回転デフォーマも体 X を軸に持ち、受け継いだ回転を打ち消して同じように振れます）と `DeformBodyZBreath`（体 Z / 呼吸）があり、さらに頭部回転と頭部追従があります。立っている全身のキャラクターには並列の根 `DeformLegs`（脚。体 X・体 Y・頭身が軸）もあり、脚と靴だけを運びます。足はどの体パラメータでも動きません。頭部の下は顔の格子・輪郭・パーツ変位を通じて目眉鼻口耳を制御します。前髪・後ろ髪には独立した追従・物理の枝があります。領域グループ、瞳の形保持・視線、任意の唇などもあるため、固定の古いツリーをプロジェクトの代わりにしないでください。 生成リグの各部がパラメータ最大のときに動く量は、モデルプリセットの「リグの数値」または MCP の `settings.rigTuning` で調整できます。対象は頭の向きと顔面、パーツ（目、瞳、視線、まばたき、眉、鼻、口、耳）、髪の追従と揺れ、前後傾に合わせた顔の上下、そして体の各パラメータ（回転角度、腕の振れ、腰の横移動、沈み込みと伸び上がり、膝、背中と肩、前後傾の角度と骨盤の分担、頭身の各項目、体 Z と呼吸、胴の厚みと視距離）です。あまり変えない項目はその中の「詳細」に折りたたまれています。デフォルト値は上記のとおりで、「頭部の可動範囲」「身体の可動範囲」が頭と体の量をそれぞれ全体として拡大縮小します。

## 座標とキー形状

画布の左上が原点で、X は右、Y は下です。形状は親の局所空間で評価されます。Warp の正規化座標と Rotation の局所座標は異なります。静止メッシュとキー形状の形式変換は restMeshesToCanvasSpace 等で処理します。

直接の関連付けは対象自身の軸を定め、親の動きは継承されます。キー形状はパラメータ位置での形で、時刻のフレームではありません。モーション・物理はパラメータ値を動かします。新規パラメータだけでは動かず、形との関連付けが必要です。

## 自動変形

頭 X/Y の端点と中点の組み合わせから九姿勢を作り、初期の傾きを局所基準として推定します。顔格子、部分補正、瞳保持、マスク、口耳の処理を使います。脚は股・膝・足首の 2 ボーン IK で曲がり、膝は見る側へ曲がるので正面の太ももは横に振れずに短くなり、1 枚のレイヤーに描かれた脚もそれぞれの膝で曲がります。頭部回転と体に直接下がるスケルトンの回転デフォーマは身体の前後傾と頭身を軸に持ち、それに合わせて拡縮します。脚を分割して脚ボーンにバインドした場合、メッシュを持つ脚ボーンごとにその下へ体 X/Y を軸とする立ち姿ワープを置き、脚ワープが示す位置へメッシュを運びます。回転デフォーマは支点と角度しか伝えないため、脚ワープの曲げはその下に届きません。傾き・呼吸、髪の頭部追従・物理を分け（体 Z は腰から上を腰を軸に傾け、各行は平行移動のみで幅を保ちます。呼吸は原画の肩と腰の線に合わせて肩とそれに載る頭・腕を持ち上げ、胸を少し広げ、腰から下は動かしません）、まばたきから瞳の形を駆動できます。

**前髪から透ける眉**（`SeeThroughLayers`）：前髪に隠れる眉ごとに複製を作り、覆う前髪の上に半透明で描き、その前髪メッシュでクリッピングして髪の範囲にだけ見せます。アニメ調の Live2D モデルで一般的な作り方です：眉レイヤーを複製して前髪の上へ上げ、不透明度を下げて前髪でクリッピングします。二段階です。ベース Rig は候補だけを記録し（`BuiltRig.seeThrough`：眉や目線ごとに、静止姿勢でそのピクセルを覆う前髪メッシュ。設定に関係なく記録し、マテリアライズした Rig と一緒に保存します）、完成した Rig がジャーナル・ジェネレータ・生成結果の上書き・レイヤー表示・描画順の上書きの後に、設定に応じて複製を作ります（`BuiltRig.seeThroughCopies` が複製から元への対応を持ち、ID だけで複製と判断することはありません）。複製の ID は `<元の ID>_SeeThrough` で、同じ ID のメッシュが既にあれば作らず上書きもしません。親デフォーマ・メッシュ・形状キー・ブレンドシェイプ・色・表示は元と共有し、不透明度は元の不透明度（静的値とキー）に `seeThroughOpacity`（既定 50%）を掛けた値です。マスクは候補の前髪のうち、まだ存在し、表示され、すべてのキーで元より上に描かれるもので、なければ作りません。描画順はそれらの前髪の最高順（キーを含む）の半ステップ上、ほかのメッシュの最低順より下です。複製は元と同じパーツで元のすぐ前に並ぶので、パーツを隠したり薄くしたりすると一緒に隠れます。そのため複製は元の変形・キャンバス編集・生成結果の上書き・前髪の描画順の変更にすべて追従し、設定の変更は再生成せず再生だけで反映され、キャンバスのドラッグプレビューでも追従します。複製は作者状態の Rig にないため、複製を名指しする編集は `generated_copy` で拒否され、キャンバスでは選択できません。目線（まつげと閉じ目の線）も複製できます。既定は眉がオン、目線がオフです：眉は表情を担い、アニメの絵では前髪に隠れることが多いので透かすのが一般的です。目は前髪に隠れにくく、目線を透かすかは画風によるうえ、複製ごとにクリッピングマスクが一つ増えます。設定は `seeThroughBrows`・`seeThroughEyes`・`seeThroughOpacity`（CLI `--no-see-through`・`--see-through-eyes`・`--see-through-opacity`）です。以前に保存したプロジェクトはこれらを持たないためオフとして読み、開き直しても Rig は変わりません。読み込んだ cmo3 / moc3 では複製を作らず、同名のメッシュはそのまま残します。制限：グルー・変形パス・頂点グループは複製しません（グルーは相手を二重に引くため）。リアルタイムのシミュレーションは元にだけ作用し、焼き込んだキーは通常どおり複製されます。元が分割・置換されたり前髪メッシュがすべてなくなったりすると複製は作られず、`quality.overrides` に `SEE_THROUGH_DROPPED`（info）として報告します。複製はソースレイヤーに対応せず、MCP では元のレイヤーを報告します。

**前髪から透ける目**：目のパーツ（白目、ハイライトを含む瞳、まつ毛、閉じ目）もすべて候補として記録し、既定でオンです（`seeThroughEyes`、CLI `--no-see-through-eyes` でオフ）。クリッピングマスクは足し合わせしかできず、白目と前髪の両方でクリップされた複製は作れないため、目は前髪に窓を開けて見せます：クリップされていない目のパーツ（白目、まつ毛、白目にクリップされない瞳）を覆う前髪を完成 Rig でそれらで**反転クリップ**し、同じマスクでクリップした前髪の複製（`<前髪 ID>_SeeThrough`）を前髪の不透明度 ×（1 − `seeThroughOpacity`）で上に描きます。目の範囲だけ髪が薄くなり、白目にクリップされた瞳やハイライトもそのまま見えます。まぶたと一緒にフェードする閉じ目はマスクにできないため、眉と同じく前髪の上へ複製します。自前のマスクを持つ前髪は窓を開けず（`bangs_clipped`）、反転マスクのない Cubism 4.0 未満のターゲットでも開けません（`target_unsupported`）。窓は完成 Rig だけのもので、インスペクタはドキュメント自身のマスクを表示・編集します。3.6.5 で保存したプロジェクトは当時既定の `seeThroughEyes: false` を保持し、見た目は変わりません。

これはプリセットであり汎用 3D 復元ではありません。分層・基準点・極端な角度は確認が必要です。曲線定数や分割数は実装を参照し、古い数式を現行の保証として扱わないでください。

| ボーン | ボーン（Cubism に対応がない場合はベイク） | ボーンのポーズ（Shift+W、自動 / FK / IK）、ボーン編集（Alt+W、編集 / 新規 / 押し出し / バインド / 重み）。書き出し時にパラメータとデフォーマへベイク | 既存 |
| シミュレーションの重み | 直接の対応なし | 重みブラシ（Shift+V）、重みグラデーション（Alt+V） | 既存 |
| パラメータのキー | キーの追加・削除・移動 | パラメータパネルでキーの追加・ドラッグ・数値変更・削除・均等配置。選択オブジェクトとパラメータのバインド解除 | 既存 |

キーフォームのコピー / 貼り付け、リセット、補間、複数キーの編集はミラーと同じく確定時に通常の `set` に展開されます。再生時にほかのキーを読み直すことはなく、GUI と MCP は同じ `keyform_apply` コマンドを使い、ジェネレーターが所有するキーフォームのジオメトリ `set` は生成結果の上書きとして記録され、チャンネルの `set` は通常のチャンネルキーフォームです。ソフト選択は 1 回のドラッグでの各点の位置を決めるだけで、確定されるのはそのキャンバスのジオメトリ編集です。

## 検証

初期姿勢、端点、複合角と中間値を確認し、親と局所形状で動きを二重適用していないか調べます。幾何診断と出力再読込は検査であり、全姿勢や公式エディタとの一致の保証ではありません。出力先バージョンによる縮退にも注意してください。
