# デフォーマとパラメータの参照

[ドキュメント目次](../README.md) · [PSD 素材と命名](PSD_LAYER_SPEC.md)

このページでは、自動生成される既定の構造と、編集の取り決めを説明します。実際のオブジェクトは素材、モデルプリセット、その後の編集によって変わります。階層ツリー、パラメータパネル、または MCP の `workspace_inspect` が返す値を基準にしてください。

## 構造

体のルートは `DeformBodyXY` です。体自身のパーツ（胴、衣服、腕、スカート、尻尾）と、頭の回転に伴う首だけを覆い、髪と脚は覆いません。体の X は、腰より上の上半身をひとまとまりとして、中心線のまわりに向けます。腰と胸の回転量は同じで、回転は股のあたりで次第に消えます。胸の前は向いた側へ動き、前に出る肩は少し大きく少し低く、首は回転軸の近くにあってほとんど動かず、頭はいつも体の中央にあります。体の Y は、下向きのとき肩が少し開き、上向きのとき背中が伸びます。体は股関節の移動にも従います。体の X ではわずかに横へずれ、体の Y が下向きのときは沈んで膝が内側に入り、上向きのときは脚が伸びてわずかに上がります。その下には、順に `DeformBodyLean`（パラメータは 2 つです。「体の前後傾」：体は厚みのある立体として三次元で前に傾き、透視で描かれます。骨盤は股関節のまわりで一部だけ前傾し、スカートを伴います。背骨は腰で弧に沿って全角度まで次第に曲がり、腰だけが押しつぶされることはありません。前傾では胸が透視で短くなり、全体が下へ動いてわずかに大きくなり、頭は形を保ったまま首とともに下がり、顔も同時に下を向きます。後傾では小さくなり、顔がわずかに上がります。「大きさの変化（頭身比）」：正の値では頭が首の位置から全体に大きくなり、胸が広がり、胴と腕が短くなり、脚とスカートが短くなります。上半身はそれに伴って下がり、Q 版に近づきます。負の値は逆で、通常のプロポーションに近づきます。足は動きません。スケルトンが無効のとき、左右の腕にはそれぞれ、体の X とこの 2 つのパラメータを軸とする `DeformArmHang_L/R` があります。腕は肩から垂れたひとまとまりとして、肩の移動と拡大縮小に従い、体の曲げには従いません。体の X では、腕は向いた側へ拡大して下がるのではなく、肩のまわりに逆方向へ約 4° 振れ、手は体よりわずかに遅れます。スケルトンが有効のとき、上腕の回転デフォーマも同様に体の X を軸として、継承した回転角を打ち消し、同じ振りをします）と `DeformBodyZBreath`（体の Z / 呼吸）が続きます。頭の回転と頭殻の追従はその下にあります。立っている全身キャラクターには、並ぶルートとして `DeformLegs`（脚。軸は体の X、体の Y、大きさの変化）もあります。載せるのは脚と靴だけで、足はどの体パラメータでも動きません。顔の経緯メッシュ、顔の輪郭、顔パーツの変位が、目、眉、鼻、口、耳を受けます。前髪と後ろ髪には、それぞれ頭殻の追従と物理の分岐があります。実際の階層には、領域グループ、瞳の保持 / 視線、任意の唇などのオブジェクトも含まれます。具体的な構造は、階層ツリーまたは MCP の `workspace_inspect` の戻り値に従ってください。生成した Rig の各所について、パラメータが最大のときの振幅は、モデルプリセットの各部位カードの「数値」、または MCP の `settings.rigTuning` で調整できます。対象は、頭の向きと顔の面、顔パーツ（目、瞳、視線、閉眼、眉、鼻、口、耳）、髪の追従とスイング、前後傾のときの下を向く動きと上を向く動き、そして体の各パラメータ（振り向き角度、腕の振り、股関節の横移動、沈みと上昇、膝、背中と肩、前後傾の角度と骨盤の分担、頭身比の各項目、体の Z と呼吸、胴の厚みと視距離）です。あまり使わない項目は、その中の「詳細」に折りたたまれます。あるモジュールまたは基礎アルゴリズムが自分で描く部分（スタイル化した振り向き、フィットした目、眉、口、髪のチェーン）は、生成時に対応する数値が表示されません。既定値は前述のとおりです。「頭の振幅」と「体の振幅」が、頭と体の振幅をそれぞれ全体として拡大縮小します。

## 座標とキーフォーム

キャンバスの原点は左上で、X は右、Y は下です。オブジェクトのジオメトリは、親のローカル空間で評価します。Warp の正規化したローカル座標と、Rotation のローカル座標は混用できません。静止メッシュとキーフォームは、変換のときにも異なる座標の取り決めを持ちます。書き出しは restMeshesToCanvasSpace などの変換で処理します。

直接のバインドが、オブジェクト自身の形状軸を決めます。親のパラメータは階層を通じて継承されます。キーフォームは、パラメータ座標におけるオブジェクトの形状であり、アニメーションの時間フレームではありません。アニメーションファイルは時間に沿ってパラメータを駆動し、物理もパラメータ値を出力します。パラメータを追加したあとも、形状をバインドして初めて動きになります。

## 自動変形

頭の X/Y は、端点と中点の組み合わせから 9 ポーズを生成します。原画の頭の傾きは、ローカルな基準として推定します。顔は経緯メッシュと区画ごとの整形を使います。目と眉、瞳、口、耳には、独立した補正またはマスクの処理があります。脚は股、膝、足首の 2 ボーン IK で曲がります。膝は観客の方向へ曲がり、正面から見ると太ももは外へ振り出さずに短くなります。脚が 1 枚のレイヤーに描かれていても、左右で別々に膝を曲げられます。頭の回転と、体に直接ぶら下がるボーンの回転デフォーマは、さらに体の前後傾と大きさの変化を軸として、それに合わせて拡大縮小します。脚が分割されて脚のボーンにバインドされているとき、脚メッシュをぶら下げている各脚ボーンの下には、体の X/Y を軸とする立ちポーズの warp がもう 1 つあります。メッシュを、脚の warp が示す位置へ置きます。回転デフォーマが渡すのは支点と角度だけなので、脚の warp の曲がりはその下へ伝わりません。平面の傾きと呼吸は層を分けて処理します。体の Z は、腰線より上を腰のまわりに傾けます。各行は平行移動するだけで、幅は変わりません。呼吸は原画の肩線と腰線で位置を決め、肩と、肩が連れる頭と腕を持ち上げ、胸をわずかに広げ、腰より下は動かしません。前髪と後ろ髪は強い顔の変形から分離し、それぞれスイングのパラメータを出力します。眼球の変形は、まばたきの物理で駆動できます。

**眉と目を前髪越しに見せる**（`SeeThroughLayers`）：前髪に覆われた眉は、それぞれ複製を 1 つ生成します。それを覆う前髪の上に描き、半透明で表示し、それらの前髪メッシュをクリッピングマスクにして、前髪の範囲にだけ現します。これはアニメ調の Live2D モデルで一般的なやり方です。眉レイヤーを複製し、前髪の上へ上げ、不透明度を下げ、前髪でクリップします。手順は 2 つです。基礎 Rig は候補だけを記録します（`BuiltRig.seeThrough`：眉ごと、または目のレイヤーごと——白目、虹彩（ハイライトを含む）、まつ毛、閉眼線——と、静止ポーズでピクセルとしてそれを覆う前髪メッシュ。設定にかかわらず、マテリアライズした Rig とともに保存します。保存時には `see_through_rules` を伴います。3.6.5 が旧規則（まつ毛と閉眼線だけを記録）で保存した候補は未知として読まれ、プレビューが再生成します）。完成 Rig は、ログ、ジェネレーター、生成結果の上書き、レイヤーの表示と非表示、描画順の上書きのあとに、設定に従って複製を作ります（`BuiltRig.seeThroughCopies` が複製から原物への対応を記録します。認識するのはこの記録だけで、ID では識別しません）。複製の ID は `<原件 ID>_SeeThrough` です。同名のメッシュがすでにあるときは、作成も上書きもしません。親デフォーマ、メッシュ、ジオメトリのキーフォーム、ブレンドシェイプ、色、表示は原物と共有します。不透明度は、原物の不透明度（静的な値とキーフォーム）に `seeThroughOpacity`（既定 50%）を掛けた値です。マスクは、候補のうち、まだ存在し、可視で、すべてのキーフォームで原物より上に描かれる前髪です。該当がなければ作成しません。描画順は、それらの前髪の最高順（キーフォームを含む）より生成間隔の半分だけ上で、残りのメッシュの最低順より下です。複製は原物の直前に並び、原物と同じパーツに入り、パーツを隠すかフェードアウトすると一緒に隠れます。そのため複製は、原物のすべての変形、キャンバス編集、生成結果の上書き、前髪の順序の変更に従います。設定を変えても再生するだけで、再生成は起きません。キャンバスのドラッグプレビューも複製を同期します。複製はオーサード Rig には入りません。それを名指しした編集は `generated_copy` を返し、キャンバス上では選択できません。**目を前髪越しに見せる**ときは、別の一般的なやり方を使います。前髪に窓を開ける方法です。クリッピングマスクは加算しかできないため、複製を白目と前髪で同時にクリップできません。虹彩を複製すると、白目の外の虹彩が髪の上に描かれ、閉眼しても消えません。そこで、クリップされていない目のレイヤー（白目、まつ毛、白目のクリップがない虹彩）を覆う前髪のそれぞれを、完成 Rig ではそれらの目のレイヤーをマスクとして**逆クリップ**し、その上に同じマスクで正方向にクリップした前髪の複製を描きます（ID は `<刘海 ID>_SeeThrough`）。不透明度は、前髪の不透明度に `1 − seeThroughOpacity` を掛けた値です。目の範囲の髪は設定した割合で薄くなり、その下の目全体は元のまま表示され、白目にクリップされた虹彩とハイライトは自然に透けます（`BuiltRig.seeThroughWindows` が、前髪から窓を開けた目のレイヤーへの対応を記録します）。複製の描画順は前髪より上で、その上を覆う眉の複製より下です。前髪の直前に並び、同じパーツに入ります。目の開閉とともにフェードするレイヤー（閉眼線）はマスクにできません（マスクは不透明度を見ません）。眉と同じやり方で、前髪の上へ複製します。自身のマスクでクリップされたレイヤー（虹彩、ハイライト）は、そのマスクの窓を通して表示し、個別には扱いません。前髪がすでに自分のマスクまたは逆マスクを持っているときは窓を開けず、`bangs_clipped` を報告します。ランタイムの対象が Cubism 4.0 より前（逆マスクがない）のときは窓を開けず、`target_unsupported` を報告します。窓は完成 Rig にだけあります。オーサードの前髪にはこれらのマスクはなく、インスペクタが表示・編集するクリップ ID と逆マスクは、ドキュメント自身の値です（`authoredMasksOf`）。MCP の `objects` では、前髪の `topologyInfo.seeThroughWindow` が、窓を開けた目のレイヤーを列挙します。眉と目は既定でどちらも有効です。アニメの立ち絵では両方とも前髪に隠れがちで、眉と目を透かすのは一般的なやり方です。設定は `seeThroughBrows`、`seeThroughEyes`、`seeThroughOpacity` です（CLI の `--no-see-through` は両方を切り、`--no-see-through-eyes` は目だけを切り、`--see-through-opacity` で不透明度を指定します）。以前に保存したプロジェクトにこれらのキーがないときは、読み取りはオフになり、開き直しても Rig は変わりません。3.6.5 が保存したプロジェクトは、当時の既定であるオフの `seeThroughEyes: false` を伴うため、オフのまま見た目は変わりません。3.6.5 で目の線をオンにしていたプロジェクトは、開き直すと目全体が透けるように変わります（目の線の部分の見た目は同じで、白目と虹彩が新しく表示されます）。インポートした cmo3 / moc3 は複製を作りません。その中の同名メッシュはそのまま残します。制限：Glue、変形パス、頂点グループは複製へコピーしません（Glue は相手のメッシュを 2 回引いてしまいます）。リアルタイムシミュレーションのフレームは原物にだけ作用し、ベイク済みのキーフォームは通常どおりコピーします。原物が分割または置換されたとき、または前髪メッシュがすべて消えたときは、もう作成せず、`quality.overrides` に `SEE_THROUGH_DROPPED`（info）を報告します。複製はソースレイヤーに対応せず、MCP では原物のレイヤーを報告します。

これらはプリセットのアルゴリズムであり、汎用の 3D 再構成ではありません。原画のレイヤー分け、アンカーの誤差、幅の広い髪片、極端な角度、重なる領域は、人手の整形が必要になることがあります。正確なカーブ定数とメッシュ分割は実装とともに変わります。保守するときはソースを直接照合し、バージョンから離れた式をコピーしないでください。

## ツールの対照と差分

下の表は、変形とキーフォーム編集に関係するツールを、Cubism Editor の公開機能と項目ごとに対照します（Cubism の列は、そのマニュアルの一般的な呼び方です）。状態は次のとおりです。**実装済み**は以前から実装されているもの、**今回**はこの回で補ったもの、**今後**は[ロードマップ](../ROADMAP.md)に記録します。メッシュトポロジの編集（点の追加と削除、辺の接続）と、内部造形のキャンバスハンドルは別に追跡し、この表には入れません。

| カテゴリ | Cubism の機能 | PSD2Live | 状態 |
| --- | --- | --- | --- |
| 選択 | 点選択、矩形選択、なげなわ、ブラシ選択、すべて選択 / 反転 / 連結 | 選択（V）、なげなわ（L）、ブラシ選択（W）、`Ctrl+A` / `Ctrl+I` / `Shift+L`。Z を押しているあいだは一時選択。メッシュは点 / 辺 / 面で選択できる | 実装済み |
| 変形 | 変形枠：移動、拡大縮小、回転、アンカー | 変形ツール（T）：本体をドラッグして移動、角 / 辺で拡大縮小、円で回転。アンカーはドラッグできる。Alt は中心から、Shift は等比または 15°、X / Y 軸の制約。ツール詳細の「正確な数値変形」 | 実装済み |
| ソフト選択 | 直接の対応はない（変形ブラシで代用） | 「ソフト選択」（O）：選択点をドラッグまたは変形するとき、周囲の点が距離減衰で従う。半径と減衰カーブは調整でき、キャンバスは赤い円で影響を示す。確定は通常のジオメトリ編集 | 今回 |

キーフォームのコピー / ペースト、リセット、補間、複数キー編集は、ミラーと同じく、確定時に通常の `set` へ展開されます。再生は他のキーを読み直しません。GUI と MCP は同じ `keyform_apply` コマンドを通ります。ジオメトリの `set` がジェネレーターの所有するキーフォームに作用するときは、生成結果の上書きとして記録します。チャンネルの `set` は通常のチャンネルキーフォームです。ソフト選択と一時変形メッシュが決めるのは、1 回のドラッグのあいだの各点の位置だけです。確定されるのは、その回のキャンバスジオメトリ編集のままです。

## 検証

中立ポーズ、端点、組み合わせの角、中間値を確認します。親とローカル形状が、動きを重複して加えていないかも確認します。書き出しパイプラインにはジオメトリ診断と読み戻し検査がありますが、警告は「すべてのポーズを検証済み」という証明ではありません。ランタイムの対象が対応しない機能は、ダウングレードされることもあります。
