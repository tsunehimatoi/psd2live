# モディファイアと手編集の共存

## 目標と境界

通常の整形は、モディファイアと共存するべきです。ユーザーが先にモディファイアを適用する必要はありません。生成の論理から本当に離れる必要があるときは、範囲を確認でき、取り消せる適用操作を提供します。暗黙に固定することはできず、手編集を黙って捨てることもできません。オブジェクトの親子関係、モディファイア評価の依存、プラグインパッケージの依存は、それぞれ別に扱います。

ブラシは、ジオメトリ編集を生む道具の 1 つにすぎません。頂点のドラッグ、変形枠、一時デフォーマ、パスとハンドル、数値入力、キーフォーム操作、Agent コマンドは、同じ編集契約に従います。対話ツールがサンプリングを担い、モデル層がキーフォームの準備、帰属、再生、依存の検証を担います。ボーンポーズツールの出力はパラメータ値そのものであり、パラメータを固定したあとでジオメトリを変える操作には属しません。

## 編集契約

1 回の編集は、ドキュメントの版、対象、ポーズ、チャンネル、実行段階、結合方式を固定します。表示、ピック、スナップ、プレビュー、確定は、同じ段階のモデルと座標を使います。編集中にドキュメントが変わったときは、確定を取り消すか拒否します。確定の失敗は、部分的なモデルも履歴記録も生みません。

キー値ではない編集は、既定で現在のパラメータ値を保ち、補間結果から必要なキーフォームを用意します。ユーザーは、最も近い共通キーフォームを明示的に選べます。複数オブジェクトはパラメータごとにキー値の共通部分を求め、1 回の選択で最も近い値を取ります。共通部分が空のときはスナップを止め、理由を示します。オブジェクトごとにパラメータを繰り返し切り替えることはできません。ジェスチャーの開始から、非同期の確定が終わるか取り消されるまで、ポーズと結合方式を保ちます。

`edit_stage` は修正の位置を指定します。

| 値 | ソースモデルと実行位置 |
| --- | --- |
| `auto` | 現在の最終モデル。チャンネルの実際の書き込み元へ自動で帰属する |
| `base` | モディファイアより前のオーサードモデル |
| `modifier:<id>` | 指定した有効なモディファイアのあと |
| `final` | この編集の時点で最後の有効なモディファイアのあと。有効なノードがなければ基礎 |

明示的な段階が現在受け付けるのは、ジオメトリとキーフォームの値です。トポロジ操作は受け付けません。1 つのトランザクションで段階を混ぜることはできず、その段階にまだ存在しないパラメータを参照することもできません。停止中または失敗したノードは、編集のソースにできません。`final` は編集開始時に具体的な位置へ解決され、その後に追加されたモディファイアが古い修正を動かすことはありません。

## 修正の帰属と結合

帰属レポートは、オブジェクトと既存キーフォームの実際の書き換えを記録します。同じチャンネルは最後の書き込み元に帰属し、オブジェクトの作成者や、新しく追加した軸だけから判断することはできません。基礎の編集は生成の前に実行します。局所の修正は、関係する生成結果のあとに置きます。最終的な見た目の修正は、作者が明示的に選びます。

`correction_mode` はジオメトリの結合方式を選びます。

- `delta`：メッシュと Warp は、編集前後のローカル座標の差を保存します。生成のたびに 1 回再生し、そのあと下流を実行します。前回の再計算の変位は累積しません。
- `absolute`：明確な固定上書きを保存します。触れていない成分は生成結果に従います。三者の衝突が起きたときは、作者の値を残し、衝突を報告します。

明示的なキーフォーム API がモードを指定しないときは、固定上書きの意味を保ちます。キャンバスはツールバーの選択に従って確定します。モードが記録されていない古い上書きは、これまでの三者マージ規則を残し、差分へ自動では移行しません。

回転の修正は、枢軸と角度にローカルな増分を使い、正の拡大縮小には比率を使います。明示的な代入は固定上書きを使います。色や透明度などのチャンネルは、明確な設定の意味を保ち、加算を強制しません。

ジオメトリの修正はバインドの指紋を記録します。メッシュは頂点数、接続関係、UV、親の連鎖です。Warp は格子の行と列、補間方式、親の連鎖です。バインドが変わったあとは記録を残して不一致を報告し、適用を続けません。現在は保守的な検査を使い、UV の並べ替えでも修正の処理が必要になることがあります。トポロジは自動では移行しません。

アルゴリズムの書き込みと作者の修正は、別に記録します。アルゴリズム同士は、書き込みの組み合わせ可能性を引き続き検査します。作者の修正は指定した段階で再生し、モーションノードのあとにぶら下がるジオメトリ修正を、モーションアルゴリズムが生成したジオメトリとして誤って数えることはできません。キャッシュの再利用と、固定後の再生は、同じアルゴリズム書き込み記録を使います。

## 適用の仕組み

`modifier_apply_plan` は読み取り専用の範囲計画で、GUI とコマンドが共有します。適用の前に、固定するもの、停止するもの、残すもの、修正の数、固定上書きの衝突、不一致の記録、境界をまたぐ依存を示します。適用のあとも、再評価して完全な結果を比較する必要があります。

| 範囲 | 振る舞い |
| --- | --- |
| `selected` | 選択したノードを、元の評価位置で固定し、前後のノードを残す |
| `prefix` | 選択したノードまでの接頭を、等価なものとして基礎へ書き、接尾を残す |

`A → B → C` に対して、`B(A(基础))` を新しい基礎にしたあと、A を実行し続けることはできません。単項目の適用は、元のノードの前後の出力、能力契約、実際の入力の読み取り、アルゴリズムの書き込みを保存します。元のアルゴリズムはもう実行しません。固定したノードの設定、位置、起動と停止の状態は、生成の制御項目ではなくなります。作者はその永続出力を編集します。

適用には完全な結果の検証が含まれ、現在の画面だけを比較することはできません。有効な項目の不一致な修正と、失敗した依存は、適用を止めます。固定上書きの衝突は、現在の作者の値を残して知らせます。停止した項目の作者記録は休眠したままです。接頭の適用を続けるとき、停止したモーションと物理グループは、再び有効にできます。

プラグインの身元は、履歴アーカイブに残り続けます。固定したノードは、実行時に元のプラグインパッケージを探す必要はありません。古い接頭の能力記録に `provides` 契約が欠けているときは、互換の照会を残します。入力契約が互換でないときは上流の変更を拒否し、前置の依存を処理するよう知らせます。無効になった出力で、固定した内容を置き換えることはできません。

## 上下流の依存と内容の編集

計画は、設定の能力、明示的なパラメータの提供者、手作業の構造参照、モーション入力について、境界をまたぐ依存を検査します。作者の修正は、さらにキーパラメータと対象オブジェクトから、先行する実際の寄与者を探します。固定したノードは、置換または削除されたオブジェクトの入力の身元を保存し、対応する依存を表示し続けます。共有する親、パラメータ、トラック、シミュレーション入力は、範囲の判断に含めなければなりません。シミュレーション入力の身元が変わったときは、ベイクし直す必要があります。

既知の依存を固定の契約で満たせるときは、下流を残します。完全な契約を残せないときは、適用範囲を広げるか、操作を拒否して理由を説明します。現在提供するのは単項目と接頭の 2 つの範囲で、依存の最小閉包を自動で完全に選ぶ機能はまだありません。プラグインが宣言していない暗黙の読み取りは、計画だけを根拠に安全とみなすことはできません。最終的な再構築の検証は、常に残します。

モーションの作者記録は、凍結した設定から独立しています。組み込みモーションは元の記録を引き継ぎます。他のプラグインは、実際に追加または変更した Clip に対して作者記録を作り、1 つのノードが複数のモーションを持てます。元の Clip は別に保存し、停止してもそのカーブ、フェードインとフェードアウト、イベント、パラメータ以外のトラックは捨てません。編集時に置き換えるのは、作者が変更したフィールドだけです。汎用記録、接頭の適用、ディスク保存経路の対象を絞った回帰は通過しています。改名、カーブ編集、起動と停止、削除は、永続 Clip を更新します。固定したモーションをコピーすると、複製は元の段階に残り、完全な接頭を適用したあと通常の内容へ変わります。コピー時には元のチャンネルを残します。変更していないカーブは、元の表現を残します。カーブが参照できるのは、元のノード位置にすでにあるパラメータだけで、停止した記録もこの制約を検査します。接頭の適用を続けるときは、編集後の記録と元のトラックを使います。通常のモーションでは、パラメータとパーツの改名が元の参照を同期して更新します。記録を削除すると、元のデータも一緒に取り除きます。ワークスペースの clips ノードは新しい schema を使い、モデルオブジェクトのバイナリはバージョン 7 で、イベント、パラメータ以外のトラック、トラックごとのフェードインとフェードアウトを保存し、同時にバージョン 4〜6 の読み取り互換を残します。これらの新しいフィールドを含まないオブジェクトと、パッケージ全体の補助リソースは、引き続きバージョン 6 で書き、既存の worker が読めるようにします。ホストはバージョン 6 と 7 のパッケージ全体のリソースを読み、ダウングレードで新しいフィールドを捨てることはできません。ホストが管理する SDK は、ビルド前に実際のシリアライズモジュールを更新します。指定した外部 SDK は自動では上書きしません。

固定した物理グループは、通常のパラメータ調整、起動と停止、フィット、削除、インポートに接続します。同じ ID のインポートは、固定したグループを変更します。新しいグループが同じ出力を占めるときは、インポート規則に従って衝突するグループを停止します。組み込みのスイング物理アルゴリズムが他のグループを読むのは衝突検査のためだけで、固定後は ID と出力の衝突を検証し直し、物理リスト全体や FPS を固定したままにはしません。他のプラグインは、元の読み取り契約を残します。

通常の候補、設定の変更、一括コマンドが新しいモディファイア実行の失敗を生んだときは、部分的な結果の確定を拒否します。変わっていない既存の失敗は、無関係な編集を止めません。プリセットの初期化は、明示的に隔離した失敗を記録できます。提供者が能動的に停止したことによる下流依存の停止は、回復できる状態を保ち、アルゴリズム実行のエラーとしては扱いません。固定した内容の構造提供者を削除または停止するとき、固定したモーションの入力パラメータを削除するときは、下流の出力契約を検証します。互換でなければトランザクション全体を拒否し、モデルと履歴は変わりません。

## 実装と受け入れの状態

主な入り口は、`GeometryEditStages`、`GeneratedOverrides`、`RotationCorrections`、`JournalRecording`、`RigModifierEvaluator`、`AppliedModifierNode`、`ModifierApplyPlan`、`WorkspaceDocumentCommands` です。キャンバスは共通の確定経路を通して、段階と結合方式を渡します。

通過済みの、対象を絞った回帰の証拠は次のとおりです。

- 増分の再生が累積しないこと、固定上書き、トポロジの不一致、中間キー値の挿入、共通キー値、既存キーフォームの実際の書き込み帰属。
- 直接のジオメトリ、ストローク、Bezier、回転の修正。段階のソースと、ピック対象のキー軸が一致すること。
- 頂点が中間のパラメータ値から始まったあと実際にドラッグされ、パラメータは変わらないこと。キャンセルするか、起点へ戻して離すと、元のジオメトリに戻り、ロックが解けること。
- 単項目の適用が非可換な操作順序を保ち、最終段階の修正をその場で固定できること。元のプラグインがなくても再生できること。
- 固定したモーションと物理の編集、停止した内容を適用し続けたあとの回復、物理のインポートによる置換と衝突停止。
- 通常の編集が新しいモディファイア実行の失敗に出会ったとき、候補モデルも履歴も公開しないこと。
- 履歴の往復、ワークスペースのディスクへの書き出しと再読み込み、CMO3 のシリアライズの読み戻し、端点と中間ポーズの比較。

主モジュールと形式モジュールの最終的な完全回帰は通過しています（コマンド `./gradlew.bat :format-compile:test :test --console=plain`。ログ `build/modifier-authoring-final-tests-3.log`、2 分 18 秒）。主モジュールは 1228 件を報告し、うち 1087 件が通過、141 件がスキップ、失敗は 0 です。形式モジュールは 5 件が通過です。対象は、古いプロジェクトのリビジョン身元、古い形式の読み取り、プラグイン開発の閉ループ、モーションの元データの保存、失効した補償の原子的な拒否、そしてパス、Bezier ハンドル、ボーンポーズの対話です。スキップした項目は通過には数えません。これらは合成データの検証であり、issue #81 の元の操作録画を再現したことにはなりません。

統一した編集入り口の受け入れは、頂点、変形枠、一時 Warp、パス、Bezier ハンドルについて、ポーズの保持とキャンセルを覆います。実際のワークスペースでの頂点ドラッグは、非同期の確定、取り消しとやり直し、確定後のロック解除を覆います。ボーンポーズは、パラメータがドラッグに伴って変わることを検証し、ジオメトリのポーズロックは取りません。

子の見た目を保つ処理は、親の修正の下にある直接の子の補償を再計算します。子が現在のパラメータにまだバインドされていないときは、必要なキーフォームを用意します。独立したパラメータの中間値は、実際の変形誤差に応じて適応的に分割し、最大 8 ラウンド、各ラウンド最大 16384 個のサンプルポーズです。収束しなければトランザクション全体を拒否します。検証済みなのは、31 個の独立パラメータのサンプル値、再生成、不一致、固定です。このサンプリング検査は、任意に複雑な階層における連続誤差の上界を証明するものではありません。

依存と複雑な階層の追加受け入れは通過しています（`modifier-authoring-tests-35.log`）。固定した内容の提供者を削除または停止すること、固定したモーションの入力パラメータを削除することは、トランザクション全体を拒否し、履歴を変えません。完全な接頭を適用すると、結果を残して生成の依存を解けます。共有する親、入れ子の回転、ブレンド変形の平行移動は見た目を保ちます。非線形の組み合わせが同じ深いメッシュ位置を表せないときは、明示的に拒否します。検証は、子のキー値、ブレンド変形のキー値、制限点とその中点を覆います。上限の外を黙って近似することはありません。

提供範囲の監査：

| 元の要求 | 実装と検証 |
| --- | --- |
| 手編集とプリセットが同時に存在し、衝突を減らす | 編集のポーズと段階の統一、共通キー値、増分／固定上書き、書き込みの帰属、指紋の不一致。`ParameterKeyPoseTest`、`ModifierGeometryCorrectionTest`、`RotationCorrectionsTest`、およびワークスペースの再計算回帰が覆う |
| 変形／編集そのものを対象とし、ブラシだけを直すのではない | 頂点、変形枠、一時 Warp、パス、Bezier ハンドルがポーズと確定経路を共有する。`WorkspaceModifierCommandsTest` と、実際のバックエンドに接続する `ModifierGeometryGestureTest` が覆う。ボーンポーズは、パラメータを変える振る舞いを残す |
| 必要なときは適用でき、上下の依存を考慮する | 単項目のその場での固定、接頭の等価な具現化、依存範囲の計画、入力契約と完全な結果の検証。`AppliedModifierNodeTest`、`ModifierApplyPlanTest`、およびワークスペースでの提供者の削除／停止、パラメータ、履歴の回帰が覆う |
| 保存後も編集と再利用ができる | モーション／物理の作者記録、元のチャンネル、古いプロジェクトの身元、プラグイン欠落時の再生、取り消しとやり直し、保存して開き直すこと、書き出しの回帰が覆う |

メインブランチへ合流したあとの完全回帰も再び通過しています（`build/modifier-merge-tests-3.log`、2 分 17 秒）。主モジュールは 1093 件が通過、147 件がスキップ、形式モジュールは 5 件が通過、失敗はゼロです。実際の Rust ネイティブプラグインの一貫性検査を含みます。パッケージ全体の補助リソースとオブジェクトフレームはバージョン選択を共有し、旧版で表現できるデータはバージョン 6 のまま、新しいモーションフィールドはバージョン 7 を使います。

最後のモーションコピー互換の修正は、完全回帰を通過しています。固定した複製は元の段階にあり、通常の複製は、自動生成した書き出しファイル名の既存の振る舞いを残します。どちらのコピーも、元のカーブ、イベント、パラメータ以外のトラックを残します。上記の提供範囲の受け入れは完了しています。

トポロジの自動移行は、現在の実装には属しません。不一致の記録は残り、明示的な処理を要求します。
