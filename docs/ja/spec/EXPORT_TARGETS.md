# 中立リグ IR と書き出し先

すべての書き出しは、同じ中立リグ IR から始まります。エディタは、現在確定済みの Rig を IR にコンパイルし、各書き出し先が IR を自分の形式へダウングレードし、その形式が残せない内容を列挙した損失レポートを 1 つ書きます。

## モジュール

| モジュール | 内容 | ライセンス |
| --- | --- | --- |
| `:format-model` | 中立リグ IR（`RigIR`）：パラメータ、パーツ、Warp / 回転デフォーマ、メッシュ、キーフォームメッシュ、チャンネル、ブレンドシェイプ、Glue、描画ツリー、テクスチャページとタイル、物理グループ、モーションクリップ、エディタ付随データ | MIT |
| `:format-compile` | 書き出しの枠組み：`ExportTarget`、`CapabilityProfile`、`LossEntry`、`ExportReport`、`Compiler`。ダウングレードの手順：能力の走査、パラメータごとのベイクと交差項の誤差測定（`ParameterBake`）、キーフレームの簡略化（`KeyReduction`）、モーションクリップのサンプリング。ホストインターフェース `FrameRenderer`、`GeometryEvaluator` | MIT |

## IR の取り決め

- メッシュの静止位置と、各デフォーマのキーフォームは、いずれも親デフォーマの空間にあります。ルートはキャンバスのピクセル（y は下）、Warp の子は 0〜1 のマス空間、回転の子はローカルなピクセル座標です。
- すべての ID は安定し、再生成後も変わりません。
- モーションクリップは、すでにプリセットからパラメータカーブへコンパイルされています。Bezier 区間の制御点の時間は区間内に制限され、時間に沿って線形にカーブパラメータを進めて評価します（Cubism の `AreBeziersRestricted` と一致）。
- 表情、ポーズ、モーションイベントはプロジェクトに由来します（`RigEditOverlay.expressions` / `pose`、`MotionClip.events`。[表情、ポーズとイベント](#表情ポーズとイベント)を参照）。コンパイル時に、モデルにもう存在しないパラメータとパーツを外します。表情とポーズは `advanced` にあり、クリップのイベントは `Clip.events` にあります。
- `restPose` は、キャンバス空間の基礎メッシュを必要とする形式が基礎メッシュをベイクするときに使うパラメータ値を与えます（たとえば口を開いたままにし、テクスチャ座標が図の全体を覆うようにする）。
- `PuppetIr` は `PuppetModel` のフィールドを双方向に写します。`toPuppet(toIr(model))` の往復の取り決めは、これらの写したフィールドに限ります。パッケージした画像、テクスチャページのバインド、物理、モーションクリップ、パラメータの役割は `PuppetModel` に保存されないため、`toIr` へ明示的に渡す必要があります。IR にだけある静止ポーズ、タイル素材、ヒット領域、高度なランタイムデータは呼び出し側が残し、IR 全体が自動で損失なく往復すると仮定することはできません。写像の両端にフィールドを追加するときは、同じ変更の中で変換器を更新する必要があります。

## 書き出し先

`spine`、`dragonbones`、`gltf` は実験的な対象です。パラメータを 1 つずつベイクしてから重ねるため、組み合わせポーズはエディタとの差が明確です。「ファイル → 形式を指定して書き出し」メニューからは隠し、コマンドラインからだけ書き出せます（`psd2live targets` では experimental と表示）。`unity` は同じベイクを使いますが、「ファイル → 形式を指定して書き出し」に現れます。書き出しディレクトリを Unity プロジェクトの `Assets` へまとめてコピーすると、同梱のインストールスクリプトがインポータを `Assets/PSD2Live/Editor` に置き、自分を削除するため、2 体目のキャラクターもまとめてコピーできます。後述の実験的な対象の説明は、現状を残します。

ラスター類と `psd-pose` は、ホストが提供する `FrameRenderer` でレンダリングします。エディタの実装（`IrFrameRenderer`）は、エンジンの CPU 評価器でジオメトリを得て、`IrColors` でチャンネルとブレンドシェイプから乗算 / スクリーン色、およびパーツの描画順とグループ合成値を求め、そのあと `:format-compile` の `SoftwareRasterizer`（MIT）がピクセルごとに描きます。プリマルチプライドの浮動小数バッファ、双線形サンプリング、テクスチャ alpha によるマスク（反転を含む）。色のブレンドと alpha 合成は `p2l_runtime.h` の合成規則に従います（エディタと一致）。Cubism の加算 / 乗算は alpha モードを見ず、対象の alpha を保ちます。通常と over の組み合わせはプリマルチプライドの source-over です。残りの組み合わせは W3C のブレンド関数を取り、alpha モードの重なりの重みと、その Porter-Duff 係数（over、atop、out、conjoint/disjoint over）を使います。描画順はレンダリングツリーに従います。各グループ内は描画順で並べ、グループはそのパーツの、そのポーズでの描画順でソートに参加します。隔離パーツのグループは、まず空にしたレイヤーへ描き、そのあとグループの乗算 / スクリーン色を取り、不透明度とマスクの被覆で alpha を拡大縮小し、グループのブレンドモードで合成します。フレームのあいだでは振り子の物理を進めます。

### VTube Studio のモデルパッケージ

書き出しディレクトリ全体を、VTube Studio の `Live2DModels` に入れ、VTube Studio を開くか再起動します。`<名称>.vtube.json` はフェイストラッキングの写像とホットキーを保存し、`FileReferences.Model` は同じディレクトリの `<名称>.model3.json` を指します。後者は `.moc3`、テクスチャ、書き出し済みの物理、モーション、表情などのリソースを参照します。VTube Studio は、モデル選択アイコンとして 512 × 512 の PNG または JPG を推奨します。[公式のインポート説明](https://github.com/DenchiSoft/VTubeStudio/wiki/Loading-your-own-Models)

書き出しは、モデルの既定ポーズで透明背景の `<名称>.icon.png` を生成し、可視の内容を等比で拡大縮小して中央に置き、`FileReferences.Icon` に相対ファイル名を記入します。画面がすべて透明のときは、アイコンを飛ばします。

モーションと表情のホットキーは、実際に書いたファイルを参照し、プロジェクト内の名前を使います。生成したホットキーは、ユーザーがトリガーを割り当てるまで待ち、キーボードの 3 フィールドは空のまま、`Triggers.ScreenButton` は `-1` と書きます。この値は、VTube Studio 同梱モデルの未割り当ての値と一致し、古い書き出しが `0` と書いて表情エディタを開けないことがあった問題を直します。VTube Studio の公式説明は設定ファイルの用途を記録しており、フィールドの値は実際に保存した設定を参考にします。[公式の設定説明](https://github.com/DenchiSoft/VTubeStudio/wiki/VTube-Studio-Model-File) · [問題 #90](https://github.com/tsunehimatoi/psd2live/issues/90)

| ラスター類 | `clip`（クリップの ID または名前。既定は最初のクリップ。クリップがないときは静止ポーズ。未知のときはエラーにし、あるクリップを並べる）、`fps`（既定はクリップのフレームレート）、`size`（長辺のピクセル。既定 1024）、`background`（ARGB の 16 進。既定は透明）、`physics`（既定 true）。`gif` にはさらに `dither`（Floyd–Steinberg ディザ。既定 true）。`sprite-sheet` はレンダリング前にフレーム数とサイズを検査し、16384 px を超えると直ちに拒否する |

## 表情、ポーズとイベント

表情、ポーズ、モーションイベントはプロジェクトのデータで、モーションクリップと同じく Rig を変えません。`core/ModelSidecars.kt` が定義し、編集は `expression_*` / `pose_*` / `motion_set_event` などのドキュメント操作を通ります（[MCP 編集リファレンス](../agent/MCP_AUTHORING.md)を参照）。`RigIrCompiler` はそれらを IR に編成し、各対象は IR に従って書きます。

- **表情**：`RigEditOverlay.expressions` が null のとき、生成した Rig は標準表情を使います（`ModelExpressions.standard`：微笑、悲しみ、怒り、驚き。名前は画面の言語に従い、それぞれモデルがすでに持つパラメータだけを残し、パラメータが 1 つもないものは省く。Rig モジュールのパラメータ（目の形、眉の角度、笑い目、細目、頬の赤みなど）は、モデルにあるとき各表情をより遠くへ押す。照れ、眠気、陰気の 3 つは、モデルに頬の赤みのパラメータ、フィットした目の細目パラメータ、陰気のパラメータがあるときだけ生成する）。インポートした CMO3 モデルには表情がありません。最初の編集は、その時点の一覧をプロジェクトへ収め、それ以後はプロジェクト内の一覧だけを書き出します（項目のない表情も、そのまま書き出し、ホストがリセットするための無表情として使う）。`moc3` は各表情を `<base>.<id>.exp3.json` に書きます（`Type`、`FadeInTime`、`FadeOutTime`、`Parameters` の `Id` / `Value` / `Blend`）。一覧の順に model3 の `FileReferences.Expressions` へ書きます（`Name` は表情の名前、`File` はファイル名）。`p2lrt` は `EXPR` ブロックを書きます。表情 ID は、ファイル名として安全な 1〜64 文字に限り、名前はプロジェクト内で一意です。
- **ポーズ**：`moc3` は `<base>.pose3.json` を書きます（`Type`、`FadeInTime`、`Groups` の中の各パーツの `Id` と `Link`）。model3 の `FileReferences.Pose` へ書き、モデルに存在するパーツだけを残し、グループがないときは書きません。`p2lrt` は `POSE` ブロックを書きます（パーツが少なくとも 2 つのグループだけを残す）。
- **イベント**：クリップのイベントは motion3 の `UserData` に書きます（時間で並べ、`Meta.UserDataCount` / `TotalUserDataSize` を同期する）。`.can3` はシーンのユーザーデータフレームに書き、`p2lrt` はクリップの拡張記録に書きます。イベントだけでカーブがないクリップは、他の空クリップと同じく書き出しません。
- **パラメータとパーツの変化**：パラメータを削除すると、その表情項目も一緒に削除します。パラメータ範囲を縮めると、上書き方式の値は新しい範囲へ収まります（`WorkspaceDocumentEdits.parameter`）。`ModelSidecars.withIdRenamed` は、パラメータまたはパーツの ID を書き換えるとき、モーションカーブ、表情項目、ポーズのパーツを同期する汎用インターフェースです。ID の変更はこれを呼ぶべきです（まだ配線していない）。それ以外の場合（スイング、シミュレーション、レイヤーの削除、再生成）に残った宙ぶらりんの参照は、プロジェクトに残します。編集は、今回書いた項目とパーツだけを検証します（1 つの表情またはポーズグループは、自分にもとからある宙ぶらりんの参照だけを残す）。`expression_get` / `expression_list` の `missing` と、`pose_get` の `missing_parts` がそれらを列挙し、書き出し時には飛ばします。
- **書いた ID**：`moc3` の exp3、pose3、motion3 は、moc が実際に書いた ID でオブジェクトを名付けます（`Moc3Sidecars.withWrittenIds`。cdi3 と同じ）。長すぎて短縮された ID は、短縮後の書き方に置き換えます。書かれなかったパーツ（`hidden_parts` / `guide_parts` で省いたもの）はポーズから外し、空になったグループも外し、モーション内のそれらの透明度カーブも外します（カーブ、区間、点の数を同期する）。ID がすべてそのまま書かれたときは、これらのファイルを解析しません。
- **プレビュー**：エディタのプレビュー bundle は pose3 を持ちません（Cubism SDK は pose3 を読み込むと、各グループの最初以外のパーツを隠す）。書いたファイルだけが持ちます。
- **書き出しの変化（3.6.0 以降）**：生成した Rig は、`moc3` / `vtube-studio` で標準表情の exp3、model3 の `Expressions`、VTube Studio の切り替えホットキーを余分に書きます。インポートした CMO3 は、表情を編集していないとき、`p2lrt` に標準表情を伴わなくなります。生成した Rig を CMO3 の置換インポートで置き換えるとき、その時点の標準表情をプロジェクトへ収めます。
- **読み戻し**：`PSD2LivePipeline` の bundle 検証は、model3 が参照する各 exp3、pose3、motion3 を解析します。メッシュだけの書き出しは、表情とポーズを書きません。

## CMO3 の参照とオーサードデータ

CMO3 を書く前に、メッシュのテクスチャ出所の参照を、対応する出所のテクスチャページとタイルへ具現化し、消費するメッシュ自身の UV とキーフォームを残します。`canvas` と `native` の両方のレイヤー書き出しモードが、このバインドを使います。Glue の既存 ID はファイルとともに書き、インポート時に回復します。ID のない Glue は、決定的な予備の名前を使います。ランタイムの頂点ウェイトグループは CMO3 に保存できないため、各グループをメッシュ ID で `structure` / `dropped` として報告し、損失がないものとして黙って扱いません。

## Cubism Animator

`cmo3` 対象は `<base>.cmo3` を書くと同時に、IR のモーションクリップを `<base>.can3` に書きます（`Can3`、`:targets:cubism`）。古い「Live2D モデルを書き出す」も、CMO3 にチェックしたときは同様に書きます。「motion3 / モーションを書き出す」をオフにしたとき、またはモデルがメッシュだけのときはクリップがないため、can3 も書きません。

- **コンテナ**：cmo3 と同じ CAFF。難読化して圧縮した `main.xml` が 1 つだけです。
- **関連モデル**：can3 はモデルを含みません。唯一のリソースは、ファイル名で同じディレクトリの `<base>.cmo3` を参照します。パラメータは ID（`live2dParam_<Id>`）で関連し、パーツ透明度のトラックは、同じ回の書き出しの cmo3 にある、そのパーツの GUID を伴います。cmo3 の GUID は書き出しのたびに異なるため、can3 は同じ回に書き出した cmo3 とだけ対になります。
- **シーン**：クリップごとにシーン 1 つ。名前は `<base>.<file>` で、moc3 が書き出した motion3 のファイル名と一致します。シーンは Animator 固定のトラック構造を引き継ぎます。ルートグループトラックとモデルトラック。モデルトラックには、ビジュアル、パラメータ、パーツ透明度、口形、まばたきの 5 つの効果があります。クリップの長さ、フレームレート、循環、フェードインとフェードアウト、ユーザーデータ（イベント）は、シーンとモデルトラックに書きます。
- **カーブ**：パラメータカーブはパラメータ効果に入ります（表示名はパラメータ名、範囲はパラメータ範囲を、すべてのキーポイントを覆うまで広げる）。パーツ透明度のカーブはパーツ効果に入り、全体透明度はビジュアル効果の不透明度を置き換えます。カーブ自身のフェードインとフェードアウトは、トラックオプションに書きます。キーポイントは最も近いフレームへ丸め、ベジェの制御点は元の時間（小数フレーム）を両端のハンドルとして残し、階段と逆階段の区間は種類を残します。
- **損失**：まばたきと口形の効果カーブは、Animator に対応するトラックがないため、モデルに存在しないパラメータまたはパーツを指すカーブとともに書かず、`timeline` / `dropped` として記録します。

## Spine

Spine にはボーンがあり、パラメータはありません。書き出したボーン空間の原点はキャンバス下辺の中点で、y は上です。そして次のとおりです。

- **ボーン**：各回転デフォーマがボーン 1 本になります。親ボーンは、その上で最も近い回転デフォーマです（なければルートボーン）。つまりデフォーマの木を鏡写しにします。ボーンのセットアップポーズとキー値は、書き出し側がエディタの回転規則（[ランタイム](RUNTIME.md)の「評価規則」を参照。角度はキーフォームの角度に基準角を足す。親が回転のとき原点は親の変換を通り、角度と拡大縮小が重なり、親の垂直反転または負の拡大縮小は追加で半周する。自身の反転は子の座標にだけ作用する。親が Warp のとき枠は剛体のまま、マスの向きに従って回転する）に従ってワールド枠を求め、親ボーンに対するローカル値へ換算します。これらの枠はすべて、回転に反転付きの等比拡大縮小を加えたもので、掛けても同じ種類のままです。そのため回転と scaleX/scaleY だけを使い（反転は負の拡大縮小）、せん断は不要です。各ボーンには固定の回転角がもう 1 つ付き、ボーンの向きを、それが載せるメッシュの中心へ向け、長さはその方向でのメッシュの最遠距離です。いずれかのサンプルポーズで拡大縮小がゼロに向かう回転はボーンにならず、その子は上のボーンへベイクして報告します。
- **メッシュ**：各可視メッシュはウェイトのないメッシュアタッチメントです。スロットは最も近い回転ボーンに付き、頂点はそのボーン空間の座標です。ボーンが表現しない部分（Warp、メッシュのキーフォーム、ブレンドシェイプ、Glue）は、そのボーン空間の deform オフセットとして書きます。回転の祖先がないメッシュはルートボーンに付き、これまでと同じです。
- **パラメータ**：各パラメータがアニメーション `param/<参数 ID>` の 1 本です。長さは 1 秒で、時間はパラメータの正規化値（最小 0、最大 1）です。パラメータのサンプル点で、ボーンの `rotate`（セットアップ角度に対する増分）、`translate`（増分）、`scale`（セットアップ拡大縮小に対する倍数）、メッシュの deform をキーします。ランタイムはパラメータごとにトラックを 1 つ開き、加算ブレンド（`MixBlend.add`）を使い、パラメータ値でトラック時間を設定します。ボーンは親子関係で掛け合わされるため、複数のパラメータが同時に 1 本の回転連鎖を回すときは直列に組み合わさり、それぞれのキャンバスオフセットを足し合わせるのではありません。キーフォームの透明度はスロットの `rgba` になり、パラメータに応じて変わる描画順は `drawOrder` になります。
- **交差項**：`sample_pairs` 個の 2 パラメータ組み合わせポーズで、Spine の加算規則（ボーンの値と deform オフセットをトラックごとに足す。拡大縮小はセットアップ拡大縮小に倍数の差を足す。ボーンは段ごとに掛ける）で再構成し、評価器と比較します。0.5 ピクセルを超えるメッシュは損失レポートに書きます。Warp の下の回転（たとえば自動スケルトンが体の Warp の下にぶら下げる頭と上腕の回転）は、単一パラメータのサンプル点では正確ですが、その Warp を動かすパラメータと組み合わせると支点が Warp の変形に従わないため、近似として報告します。Warp で実現した関節（前腕、手、上半身の曲げ）は、今までどおりボーン空間でパラメータごとに足します。
- 各モーションクリップがアニメーション `clip/<名称>` の 1 本です。`clip_fps` でサンプリングし、`KeyReduction` で、線形補間が再構成できるキーフレームを外します。deform の許容は `key_tolerance` ピクセルです。ボーンの回転と拡大縮小の許容は、キャンバスの対角線で同じピクセル量へ換算します。オフセットは千分の一ピクセルまで残します。
- アトラスはページごとに、ページ全体を覆う領域が 1 つです。領域名はそのページの画像と同名です（`<名称>_<i>`。画像は `<名称>_<i>.png`）。メッシュアタッチメントの `path` はそれを指し、UV はそのページを直接参照します。ランタイムはアトラスから領域を見つけます。Spine Editor はデータをインポートするときアトラスを読まず、`images` ディレクトリ（`./`）で同名の画像を探すため、インポート後にメッシュを直接表示できます。
- マスクはクリッピングアタッチメントになります。マスクされたメッシュの前にクリッピングスロットを挿入し（`end` はそのメッシュを指す）、ポリゴンは単一のマスクメッシュの外輪郭です。マスクが複数、または輪郭が複数のときは凸包を取り、報告します。クリッピングスロットは、すべてのマスクメッシュが 1 本のボーンを共有するときはそのボーンに付き、そうでなければルートボーンに付きます。クリッピングアタッチメントはマスクメッシュに伴って変形キーを書き、描画順が変わるときはマスクされたメッシュと一緒に動きます。Spine はポリゴンで切り抜き、テクスチャ alpha では切り抜きません。反転マスクは表現できないため、捨てて報告します。
- **物理**：振り子グループのうち、出所が角度の出力で、そのパラメータのアニメーションがボーンを回転させているときは、それらのボーンに Spine 4.2 の物理制約（`rotate` 1）を作ります。Spine はボーン自身の動きで制約を駆動し、振り子の入力パラメータは読みません。設定は経験的な写像です（慣性 1、強さ = 100 × 加速度、減衰 = 可動性、ブレンド = 出力ウェイト / 100、`fps` は物理グループのフレームレート、既定 60）。元の応答は近似できるだけなので、近似として報告します。その出力パラメータが同時にキーする変形はシミュレーションされないことを、レポートに記します。出力がボーンの回転を駆動しない振り子グループ（自動生成した髪の振り子のように Warp に作用するもの）は、捨てて報告します。
- **バイナリ**：`binary=true` のとき、Spine 4.2 のバイナリ `.skel` を書きます（公開されている spine-runtimes 4.2 の `SkeletonBinary` レイアウト。ビッグエンディアンの数値、可変長の正整数、文字列テーブル、nonessential データなし）。内容は JSON と同じです。バイナリのメッシュは三角形数を保存せず、読み取り側は「2 × 頂点数 − hull − 2」から導くため、hull の長さはメッシュの三角形数に従って設定します。その式が許すより三角形が多いメッシュ（三角形が重複するときにだけ現れる）は、末尾に先頭頂点の未使用の複製を足します。
- 検証（実装済みで、次のテストを通している。公式の Spine ランタイムは使っていない。そのライセンスは Spine のライセンス所持を要求する）。Spine 4.3 の試用版は JSON をインポートしてすべてのメッシュを表示できる（バージョンの不一致と nonessential データの欠落は警告のみ）。4.2 のバイナリ `.skel` は、エディタがバージョンの一致を要求するためインポートできない。アニメーションとマスクはエディタでは確認していない。
  - 単体テストは、Spine 4.2 ランタイムの規則（加算トラック、キーフレームの線形補間、ウェイトのない deform はセットアップポーズに対するオフセット、ボーンは通常の継承で段ごとに掛ける、描画順はオフセットのアルゴリズムで並べ替える）に従ってポーズを再構成する。3 段の回転連鎖（メッシュのキーフォーム、反転、負の拡大縮小を含む）は、単一パラメータ、パラメータのあいだ、すべてのパラメータが同時に変わるランダムなポーズで、同じ回転規則を独立に実装したテスト評価器との誤差が 0.002 ピクセル未満。モーションクリップはサンプルフレームで一致する。
  - テスト内で、公開レイアウトに従って書いた最小の `.skel` リーダーがバイナリを読み戻す。ボーン、スロット、物理制約、アタッチメント、各アニメーションから再構成したポーズが JSON と一致し、2 回の書き出しはバイト単位で同じ。

## DragonBones

Spine と同じベイク方式です。ボーンを 1 本ずつ置き、各可視メッシュはウェイトのないメッシュ表示です（原点はキャンバス下辺の中点、y は下）。各パラメータが 1 秒のアニメーション `param/<参数 ID>` で、変形（ffd）フレームはパラメータのキーポイントを整数化したフレームにあり、ホストはパラメータ値で位置を決めて層状に重ねられます。各クリップはフレームでサンプリングしたあと簡略化します。フレーム間の補間は明示的に `tweenEasing: 0` と書きます（省略時は階段）。DragonBones ランタイムは 16 ビットのオフセットで、各アニメーションの変形浮動小数データをアドレスします（各フレームはそのメッシュの全頂点を保存する）。約 3.2 万個の浮動小数を超えると、倍にしてから二分する許容でキーフレームを簡略化し、使った許容を損失レポートに書きます。検証：`DragonBonesFidelityTool`（`PSD2LIVE_TOOLS=1`、node が必要）が `tools/dragonbones-check`（公式 DragonBones 5.7 ランタイムのコア。レンダリングなし）で書き出しを再生します。スケルトンのないサンプルの単一パラメータポーズは、キーフレーム上でエディタとの誤差が 0.25 ピクセル未満です。スケルトンがあるときは、上記の上限の影響を受けたアニメーションの誤差が、報告した許容を超えず、クリップの誤差はレポートを参照します。

## glTF

各可視メッシュは、ライティングなし（`KHR_materials_unlit`）、両面、半透明ブレンドの平面メッシュになり、静止ポーズにあります。描画順に従って、各層は観察者の手前へ 0.5 ミリメートル進みます。単位はメートル（`pixels_per_meter`、既定 1000）、y は上、原点はキャンバス下辺の中点です。各パラメータの、既定でない各キーポイントが、それを動かすメッシュのモーフターゲットになります（`extras.targetNames` は `参数=关键点`）。パラメータ値からウェイトへの写像は、キーポイントのあいだの線形な帽子関数です。パラメータとそのキーポイントは `extras.psd2live.parameters` に列挙します。モーションクリップは `clip_fps` でウェイトアニメーションとしてサンプリングし、`KeyReduction` で簡略化します。検証：単体テストがウェイトからサンプルポーズを再構成します。tml の書き出しは Khronos glTF Validator でエラーも警告もゼロであり、Godot 4.4 で静止ポーズと首振りのモーションが正しくレンダリングされます。

## Unity

Unity 6.0（6000.0）以上が必要です。書き出しディレクトリは、Unity プロジェクトの `Assets` へまとめて置けます。同梱のインストールスクリプトは、`Psd2LiveUnityImporter.cs` を `Assets/PSD2Live/Editor` に入れ（すでにあり、バージョンが古くなければ上書きしない）、そのあと自分を削除するため、2 体目のキャラクターもまとめてコピーすれば足ります。インポータは、描画順で隣り合い、同じテクスチャに載るメッシュを 1 つのスキンメッシュにまとめ、共有ルートボーンに付けます。別のテクスチャのパーツがあいだに入ると、その区間は切れ、各区間は自分の `sortingOrder` を使うため、前髪が後ろ髪と同じページだからといって、ページ全体が顔の前に描かれることはありません。各パラメータの、既定でないキーポイントが Blend Shape になります（ウェイト 0〜100 の帽子関数。glTF と同じ）。複数のパラメータが同時に変わるときは、重ね合わせの近似です。モーションクリップは `clip_fps` で Animator クリップにサンプリングします。Idle という名前のクリップがあるときはそれが既定状態で、なければ最初のクリップを再生します。残りのクリップは同名の `.controller` に書き、遷移がなければ自動では再生しません。プレハブの Animator は、そのファイルが生成されたあとそれを指します。シーン内で、なお埋め込みコントローラを指しているインスタンスは、インポートまたは階層の変化のときにそちらへ変わります。各パラメータには、既定のステートマシンに入らない `param_<id>` クリップがもう 1 本あり、プロジェクト内で単独に再生できます。単位は `pixels_per_unit`（既定 100）分の 1、y は上、原点はキャンバス中央です。テクスチャの V は、PSD2Live の左上原点から Unity の左下原点へ反転します。キャラクターが画面の外にいるときは再生しません。検証：対象モジュールの単体テストが、滑る正方形の頂点、Blend Shape、0.5 秒のウェイトを対照します。完全なキャラクターの tml は、Unity 6000.4.7f1 の組み込みレンダーパイプラインのプロジェクトで静止ポーズとしてインポートし、Play で Idle を再生します。

## クリック領域

ドキュメントのクリック領域（`rigEdits.hitAreas`。エディタのインスペクタ、階層の右クリックメニュー、MCP の `hit_area_*` で編集）は、テスト順に `RigIR.hitAreas` へコンパイルします。各領域は自分の ID（たとえば `HitAreaHead`）、ホストが照会する名前（たとえば `Head`）、覆うメッシュを持ちます。メッシュを分割するとき（連結成分、ポリゴン、奥行きの切り分け）、破片が元のメッシュの領域内の位置を引き継ぎます。レイヤーを削除すると、そのメッシュは領域から外れます（そのため領域にメッシュがなくなると、領域も一緒に削除する）。IR は領域が指すメッシュをすべて残します。対象が書くときは、Rig にもう存在しないメッシュを飛ばし、それぞれに `structure` / `dropped` の損失を記録します。メッシュがすべてない領域も、ドキュメント自身の領域として数え、ランタイムの自動領域へは戻りません。クリック領域を載せない対象（`cmo3`、`spine`、`dragonbones`、`gltf`、`unity`、`psd-pose`、ラスター類）は、各領域に `structure` / `dropped` の損失を記録します。

- **`moc3` / `vtube-studio`**：model3.json の `HitAreas` に書きます。各項目の `Name` は領域の名前、`Id` は moc に書いた ArtMesh の ID です（ID が短縮されたときは短縮後の値。moc に書かれなかったメッシュ、たとえば書き出しオプションで省いた隠しメッシュは列挙せず、`structure` / `dropped` の損失を記録する。1 つも残らないときは `HitAreas` を書かない）。model3 の各項目は ArtMesh を 1 つだけ指すため、複数メッシュの領域は同名の複数項目になり、`structure` / `approximated` の損失を記録します（名前だけで最初の項目を探すホストは、最初のメッシュしか調べない）。領域自身の ID は model3 にはありません。クリック領域のないドキュメントは `HitAreas` を書かず、書き出しはバイト単位で変わりません。
- **`p2lrt`**：バージョン 2 は任意ブロック `HITA` を書きます（領域 ID、名前、メッシュインデックス）。ドキュメントにクリック領域がないときは、意味から自動で得た `HitAreaHead`（顔）と `HitAreaBody`（上衣。なければ首または下衣）を引き継ぎます。バージョン 1 にはクリック領域がなく、ドキュメントの各領域は `structure` / `dropped` の損失を記録します。
- **ヒット規則**：一覧の順で、最初に当たった領域を取ります。メッシュが可視で、不透明度が 0 より大きく、その三角形（辺を含む）がその点を含むとき、ヒットです。エディタプレビューのクリック、MCP の `hit_area_test`、ランタイムの `p2l_hit_test` は同じ規則を使います。Cubism SDK の例はメッシュの外接矩形で判断するため、これと異なることがあります。
- バイナリ IR（`RigIrBinary`）はエンコードバージョン 6 からこのフィールドを書き、それより早いバージョンの読み取りは空です。

## 損失レポート

書き出しのたびに、ファイルの隣へ `<名称>.<目标>.report.json` を書きます。

```json
{"target":"gif","compiler":"2.0.4","files":["model.gif"],
 "losses":[{"object":"*","feature":"structure","handling":"baked","note":"..."}]}
```

`handling` は `baked`（見た目は残し、体積を増やす）、`approximated`（受け入れられる誤差）、または `dropped`（捨てる）です。`object` は安定した ID で、`*` は Rig 全体を表します。誤差を測ったときは `error` を付けます。レポートはコンパイラのバージョンを記録し、2 回の書き出しの差を追うために使います。

## 決定性

同じ IR と同じバージョンのコンパイラは、バイト単位で同じ出力を生みます。書き出しはタイムスタンプも乱数も入れません。例外は `cmo3` です。Cubism Editor は各オブジェクトに一意の GUID を要求するため、ファイルのバイトは毎回異なり、内容は同じです。書き出し経路の再構成は `ExportGoldenTool`（`PSD2LIVE_TOOLS=1`）で、前後のコミットのファイル要約を比較します。cmo3 は、読み戻したあと moc3 へダウングレードした要約を比較します。

## 使い方

- 画面：「ファイル → Live2D モデルを書き出す…」が moc3 / cmo3 を書き出します。「ファイル → 形式を指定して書き出し」は、ランタイムとプレーヤー、画像と動画、レイヤー分けした PSD に分けて、残りの実験的でない対象を列挙します。各対象は自分のダイアログを開き、現在確定済みの状態を書き出し、損失を列挙します。各対象は `ExportTarget.settings` で、自分が読む設定キー（モーションの選択、スイッチ、範囲付きの数値、テキスト）を宣言します。ダイアログは宣言に従って対応する行を生成し、ユーザーが変えた値だけを送り、残りは対象の既定値またはプロジェクトの書き出し設定を取ります。変更は、この実行中は対象ごとに残します。新しい対象はメニューのグループへ登録する必要があります（`exportMenuGroups`。`ExportTargetSettingsTest` が検査する）。
- コマンドライン：[開発とコマンドライン](../guide/DEVELOPMENT.md)の `export` コマンドを参照してください。`psd2live targets` は、各対象とその設定キー、値の範囲、既定値を列挙します。
- エディタ自身の Cubism プレビューパッケージと `moc3` 書き出しは、同じ回のコンパイルです。「Live2D モデルを書き出す」（MCP の `project_export_model`）と「形式を指定して書き出し」は、どちらも確定済みのモデルそのものを書きます（`PSD2LivePipeline.export`）。ソース画像から再構築せず、基礎 Rig も生成しません。両者はレポートが異なるだけです（前者は読み戻して検証し `.psd2live.json` を書き、後者は損失レポートを書く）。コマンドラインは、同じ構築経路（`buildPreview`）でモデルを得てから書きます。
