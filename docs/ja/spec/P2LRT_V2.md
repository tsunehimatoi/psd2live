# `.p2lrt` 2.0 形式

[ランタイム](RUNTIME.md)

状態：コンテナ、コアブロック、`PGUI`、`META`、拡張ブロック `BONE`、`SKIN`、`COLL`、`SIMS`、および付随ブロック `EXPR`、`HITA`、`UDAT`、`POSE` は実装済みで、書き出しは既定でバージョン 2 を書きます。リーダーは、すべての圧縮方式、配列エンコーディング、テクスチャページの種類に対応します。ライターは deflate と zstd の圧縮を書け、配列は f32、テクスチャページは埋め込み PNG です。

## 目標

- **進化の規則を一度に定める**。2.0 のあと、新しい機能はブロックを足すだけで、既存の記録レイアウトは変えず、メジャーバージョンはもう上げません。
- **コア層は Cubism と等価**。コアブロックだけを読めば完全に再生でき、結果は v1 とビットごとに一致し、意味は moc3 と一対一で対応します。
- **拡張層は任意**。ランタイムのスキニング、頂点シミュレーション、衝突などの高度なデータは任意ブロックに置き、それらを知らないランタイムは Cubism の効果へ戻ります（同じファイルの 2 モード）。
- **読み込みやすさ**。ランダムアクセス、必要に応じた読み込み、配列のゼロコピーです。1 つのファイルが、既存のサイドカーの内容を運べます。
- **再現可能**。同じ IR を書くとバイトは完全に同じで、タイムスタンプなどの変わりやすいデータは含みません。

対象外は、汎用のシーン形式、編集できるプロジェクト形式（プロジェクトは引き続き `.psd2live`）、暗号化または難読化です。

## コンテナ

リトルエンディアンです。ファイルは、ファイルヘッダ、ブロックディレクトリ（TOC）、ブロックデータで構成します。

```
Header  (32 字节)
  u8[8]  magic        "P2LRT\0\0\0"
  u16    major        = 2
  u16    minor        写出器所知的最高次版本，仅作信息
  u32    flags        bit0 名称已剥离；其余保留，写 0
  u32    chunk_count
  u32    toc_offset   = 32
  u32    reserved[2]  写 0
TOC     chunk_count × 40 字节
  u8[4]  tag          四字符 ASCII，大写为规范块，小写为厂商/私有块
  u16    version      块版本（布局与求值语义）
  u16    flags        bit0 必需；bit1 有 CRC；bit2–3 压缩方式（见下）；其余写 0
  u64    offset       块数据相对文件头的偏移，16 字节对齐
  u64    length       块在文件中存储的字节数（不含填充；压缩时为压缩后长度）
  u64    raw_length   解压后的字节数；未压缩时等于 length
  u32    crc32        对存储字节（压缩后）计算的 IEEE CRC32（bit1 为 0 时写 0）
  u32    reserved     写 0
Chunks  各块数据，块间用 0 填充到 16 字节对齐
```

- ファイルヘッダの `magic` の先頭 5 バイトは v1 と同じです。v1 は `magic` のあとが `u32 version = 1` で、v2 は同じ位置が `u16 major = 2, u16 minor` です。リーダーは u32 を読んだあと、値が 1 なら v1 として解析し、下位 16 ビットが 2 なら v2 として解析し、それ以外は拒否します。
- 同じ規範タグは、1 つのファイルに最大 1 回現れます。ファイル内のブロック順は自由で、ライターは本文の「コアブロック」の表の順に書きます。
- ブロック同士の重なりは許されず、すべてのブロックはファイルの中になければなりません。ブロックのあと、ファイル末尾の外に余分なデータは許されません（パディングを除きます）。
- オフセットと長さは u64 です。リーダーは、自身のアドレス幅を超えるとき（WASM32 など）、切り詰めずにそのファイルを拒否します。

### ブロック圧縮

| flags bit2–3 | 方式 | 格納する内容 |
| --- | --- | --- |
| 0 | なし | 元のブロックデータ |
| 1 | deflate | zlib ストリーム（RFC 1950） |
| 2 | zstd | 単一の zstd フレーム（RFC 8878）。外部辞書は使いません |
| 3 | 予約 | リーダーは拒否します |

- リーダーは deflate と zstd に対応しなければなりません。伸長後の長さは `raw_length` と等しくなければならず、そうでなければ拒否します。伸長結果は 16 バイト境界のバッファへ入れ、そのあと未圧縮ブロックとして解析します。
- 圧縮が変えるのは格納だけで、ブロックの内容は変えません。ブロック内のオフセットと配列の境界は、いずれも伸長後のデータに対する相対です。
- 圧縮したブロックはゼロコピーできません。メモリマップ、またはストリーム読み込みが必要なホストは、圧縮しないファイルを選ぶべきです。
- ライターは既定で圧縮しません。書き出しオプションで圧縮を開くと、小さくなるブロックだけを圧縮します。すでに圧縮されたテクスチャのペイロード（PNG、KTX2）がある `TEXR` は圧縮しません。圧縮後が元のデータより小さくならないときは、そのブロックを未圧縮で書きます。
- バイトの安定が成り立つのは、同じライターのバージョン、同じ圧縮設定の下だけです。一致の比較は、伸長後のブロック内容を基準にします。

### 互換規則

| 状況 | リーダーの挙動 |
| --- | --- |
| `major` が 1 でも 2 でもない | 拒否します |
| 知っているタグで、`version` が対応するバージョン以下 | 対応するバージョンとして解析し、`length` バイトをちょうど読み切らなければなりません |
| 知っているタグで、`version` がより高い | 知らないブロックとみなします |
| 知らないブロックで、必須ではない | 飛ばします |
| 知らないブロックで、必須 | 拒否し、エラー情報にそのタグを列挙します（「特性 XXXX が必要です」） |
| 必須のコアブロックが欠けている | 拒否します |
| CRC が一致しない（ホストが検証を要求したときだけ検査します） | 拒否します |
| 圧縮方式が予約値である、または伸長に失敗した、伸長後の長さが `raw_length` と等しくない | 拒否します |

`minor` は判断に参加せず、診断にだけ使います。

### 進化の規則

1. 同じメジャーバージョンの中では、公開済みのブロックバージョンのレイアウトと評価の意味は、決して変えません。
2. 既存のオブジェクトへ属性を足すときは、新しい「平行ブロック」を追加し、オブジェクトの添字でその列を格納します。元の記録は変えません。たとえばメッシュへスキニングを足すときは `SKIN` ブロックを書きます（メッシュの添字からスキニングデータ）。`MESH` は変わりません。
3. ブロックの中で、「あるフラグが 1 のとき数バイト多く読む」のような条件フィールドは許しません。任意の内容は、必ず独立したブロック、または明示的な長さの包みで表します。
4. あるブロックの評価の意味を変えるときは、そのブロックのバージョンを上げなければならず、古いバージョンは古い意味のまま評価します。
5. コアブロックは、拡張ブロックに決して依存しません。拡張ブロックが参照できるのは、コアブロックと、より前に定義した拡張ブロックだけです。
6. ベンダーまたは実験のブロックは小文字のタグを使い、必須ではないブロックでなければなりません。規範ブロックは大文字のタグを使います。

## 基礎エンコーディング

| 名称 | エンコーディング |
| --- | --- |
| `u8/u16/u32/i32/f32` | リトルエンディアン。f32 は有限値でなければなりません |
| `ref` | u32 の添字。空にできる参照は i32 で、-1 が空です |
| `sref` | u32 の文字列テーブル添字（`STRS`）。`0xFFFFFFFF` が空です |
| `rgb` | 3 × f32 |
| `str` | `STRS` の内部だけで使います。ほかの位置の文字列は、すべて `sref` です |
| `array<T>` | 先に 0 でブロック内の 4 バイト境界まで埋め、そのあと `u8 codec, u8 reserved[3], u32 count` を書き、続いて `count` 個の要素です |
| `grid<F>` | v1 と同じです。`u16 axes`（`0xFFFF` はメッシュなし）× `{ ref parameter, array<f32> keys }`、`u32 cells` × `{ u16 coordinate[axes], F }` |
| `channels` | v1 と同じです。`u8 n` × `{ u8 channel, u8 kind, grid<value> }`。channel は順に DrawOrder、Opacity、MultiplyColor、ScreenColor、FlipX、FlipY、GlueIntensity です。kind の 0 はスカラー、1 は色、2 はフラグです |
| `bindings<S>` | v1 と同じです。`u16 n` × `{ ref parameter, array<f32> keys, u32 neutral, u8 present + 各キーの S, u16 n × { ref limit_parameter, u16 n × { f32 value, f32 weight } } }` |

配列エンコーディング（`codec`）は、次のとおりです。

| 値 | 要素 | 用途 |
| --- | --- | --- |
| 0 | f32 | 既定。すべての一致テストが使います |
| 1 | f16 | 任意の体積最適化（位置、オフセット） |
| 2 | unorm16 | 任意の体積最適化（UV。範囲は [0,1]） |
| 16 | u16 | インデックス。頂点数が 65535 以下のとき |
| 17 | u32 | インデックス |
| 32 | u8 | バイト列（テクスチャのペイロード） |

浮動小数配列の codec 1 と 2 は、ホストが明示的に「公開時の体積最適化」を選んだときだけ書きます。リーダーはすべてのエンコーディングに対応しなければならず、復号したあとは f32 と同等に扱います。配列は自分で境界を合わせます。ヘッダはブロック内の 4 バイト境界から始まり、長さは 8 バイトなので、要素も 4 バイト境界です。ブロックそのものは 16 バイト境界なので、codec 0/16/17 の配列はスライスとして直接読めます。配列の前のパディング以外に、記録の中にほかのパディングはなく、スカラーは境界に揃っていなくてもかまいません。

## コアブロック

すべて必須ブロックです（bit0 を立てます）。ブロックバージョンは `PHYS` 以外がすべて 1 で、評価の意味は [ランタイム](RUNTIME.md) の「評価規則」「物理」「モーションクリップ」の各節です。フィールドの順序とカウントの幅は v1 と同じで、違うのは、文字列が `sref` になったこと、浮動小数配列、インデックス、バイト列が `array<T>` になったこと、テクスチャページに種類が増えたことだけです。

| タグ | 内容 | 存在が必須か |
| --- | --- | --- |
| `STRS` | 文字列テーブル | はい |
| `CANV` | キャンバス。f32 の width、height、originX、originY、pixelsPerUnit（-1 はなし） | はい |
| `PARM` | パラメータ | はい（0 個でもかまいません） |
| `DEFM` | デフォーマ。親が先 | はい（0 個でもかまいません） |
| `PART` | パーツ | はい |
| `MESH` | メッシュ | はい |
| `GLUE` | Glue | いいえ（欠けているときは 0 個） |
| `DRAW` | 描画ツリー | はい |
| `TEXR` | テクスチャページ | いいえ（欠けているときはテクスチャなし） |
| `PHYS` | 物理グループ | いいえ |
| `CLIP` | モーションクリップ | いいえ |
| `ROLE` | パラメータの役割 | いいえ |

モーションクリップのイベント、パラメータ以外のカーブ、カーブのフェードインとフェードアウトは、必須ではない付随ブロック `CEXT` にあります（下記の「付随ブロック」を参照）。

「存在が必須か」がいいえのブロックが欠けているときは、空集合として扱います。存在するときは、引き続き必須として印します。コアの評価に参加するためです。

### `STRS`

```
u32 count
u32 offsets[count + 1]   每个字符串在 blob 中的起止偏移
u8  blob[...]            UTF-8，不以 0 结尾
```

ライターは重複を除きます。ファイルヘッダの flags bit0（名称を剥がした）が 1 のとき、すべての `name` フィールドは空の `sref` で、`id` は残し、ホストは id でパラメータとメッシュを探します。

### `PARM`

`u32 n` × `{ sref id, sref name, f32 min, max, default, u8 flags (1 blend, 2 repeat) }`

### `DEFM`

`u32 n` × デフォーマです。親は子より前でなければなりません。

```
u8 kind (0 Warp, 1 Rotation), sref id, i32 parent, i32 part,
u8 flags (1 visible, 2 enabled, 4 flipX, 8 flipY, 16 bilinear),
f32 opacity, rgb multiply, rgb screen
Warp:     u32 columns, rows, grid<array<f32> points>, channels,
          bindings<{ array<f32> points, f32 opacity, rgb multiply, rgb screen }>
Rotation: f32 baseAngle, grid<{ f32 x, y, angle, scale }>, channels,
          bindings<{ f32 x, y, angle, scale, u8 flipX, u8 flipY, f32 opacity, rgb multiply, rgb screen }>
```

### `PART`

```
u32 n × { sref id, sref name, u8 flags (1 visible, 2 sketch), u8 groupMode, i32 drawOrder,
          u32 n × { u8 kind (0 part, 1 mesh), ref target },
          channels, composite,
          bindings<{ f32 drawOrder, f32 opacity, rgb multiply, rgb screen }> }
composite = { u8 blend, u8 alphaBlend, u32 n × ref maskMesh, u32 n × ref maskPart,
              u8 invertMask, f32 opacity, rgb multiply, rgb screen }
```

### `MESH`

```
u32 n × { sref id, sref name, i32 parent, u8 blend, u8 alphaBlend, u32 n × ref maskMesh,
          u8 flags (1 invertMask, 2 culling, 4 visible, 8 geometry), i32 texturePage,
          [geometry] array<f32> positions, array<f32> uvs, array<u16|u32> indices,
          grid<array<f32> deltas>, channels,
          f32 drawOrder, f32 opacity, rgb multiply, rgb screen,
          bindings<{ array<f32> deltas, f32 drawOrder, f32 opacity, rgb multiply, rgb screen }> }
```

`[geometry]` が現れるのは、flags の bit3 が 1 のときだけです。`CLIP` の中の Bezier 区間の制御点も、区間の種類が 1 のときだけ現れます。この 2 か所は v1 から残った条件フィールドで、v1 と一対一に対応させるために残してあり、規則 3 の唯一の例外です。

### `GLUE`

`u32 n × { sref id, ref meshA, ref meshB, f32 intensity, u32 n × { u32 a, u32 b, f32 weightA, f32 weightB }, channels }`

### `DRAW`

描画ツリーの根グループです。再帰します。`{ i32 part, i32 drawOrder, channels, u8 hasComposite, [composite], u32 n × { u8 kind (0 group, 1 mesh), group | ref mesh } }`

### `TEXR`

```
u32 n × { u8 kind, u32 width, height, payload }
kind 0  PNG       payload = array<u8> png      所有运行时必须支持
kind 1  KTX2      payload = array<u8> ktx2     可选；不支持的运行时报告该页不可用
kind 2  外部文件  payload = sref uri           相对模型文件的路径，由宿主加载
```

`p2l_texture_png` は、PNG でないページに対して空を返します。追加した `p2l_texture_info(i)` は、kind、幅と高さ、uri を返します。

### `PHYS`

`f32 fps (0 ランタイム既定), u32 n × { sref id, sref name, inputs, outputs, segments, normalization }`。各フィールドは v1 と同じです。

入力と出力の `u8 source` は、0 が横（X）、1 が角度、2 が縦（Y。Cubism physics3 の `Y`）です。ブロックバージョン 2 は縦を許します。ライターは縦を使うときだけバージョン 2 を書き、それより前のランタイムは、これによって「PHYS バージョン 2 が必要です」と報告し、読み誤りにはなりません。バージョン 1 のファイルレイアウトは完全に同じです。縦の入力は、正規化した値を根の y 変位へ足し、縦の出力は、その頂点が 1 つ前の頂点に対して持つ y オフセットを読みます。横と同じく、平行移動の出力のスケールはゼロです（Cubism の挙動）。バージョン 1 のファイル（書き出しオプション `v1`）は縦の入力と出力を書かず、損失レポートに記します。

### `CLIP`

v1 と同じで、文字列は `sref` に変えます。

### `ROLE`

`u32 n × { sref role, u32 n × ref parameter }`

## パラメータ界面ブロック `PGUI`（必須ではない）

ホストがパラメータパネルを表示するためのメタデータで、評価には参加しません。知らない、または必要としないランタイムは、そのまま飛ばします。ブロックバージョン 1 です。

```
u32 n × { ref parameter, array<f32> keys }        吸附值：只列有吸附值的参数，keys 升序
u32 n × { ref horizontal, ref vertical }          二维摇杆：两个参数组成一个平面控件
u32 n × node                                      参数分组树，先序展开
node = { u8 kind (0 参数, 1 分组), u8 open, u8 label (0 无, 1 预设, 2 自定义), u8 reserved,
         i32 parameter (分组为 -1), sref id, sref name, sref preset, u32 argb, u32 children }
```

- ノードは固定長の記録で、すべてのフィールドを常に書きます。パラメータノードの `id`、`name`、`preset` は空で、グループノードの `parameter` は -1 です。`label` が 1 でないとき `preset` は空で、2 でないとき `argb` は 0 です。`children` は、その直後に続く直接の子ノードの数です。
- ファイルヘッダの flags bit0（名称を剥がした）が 1 のとき、グループの `name` は空です。
- グループの木に入っていないパラメータは、ホストが `PARM` の順で末尾に置きます。
- `RigIR.restPose` を使うのは、キャンバス空間の基礎メッシュで格納する形式（Spine など）だけで、p2lrt はパラメータから直接評価するので、書きません。

## 情報ブロック `META`（必須ではない）

`u32 n × { sref key, sref value }`。規範キーは、`generator`、`generator_version`、`source_hash`（プロジェクトのソースデータのハッシュ。キャッシュと診断に使います）、`capabilities`（空白で区切った、ファイル内の拡張タグ。ホストが読み込む前に表示します）です。タイムスタンプは書かず、再現できるようにします。

## 評価段階と拡張のフック

コアの評価は、次の段階に固定します。拡張ブロックが効くのは、示したフックだけで、ブロックの規範は、どの点に掛かり、どの寄与を置き換えるかを書かなければなりません。

| 番号 | 段階 | コアの内容 | 拡張のフック |
| --- | --- | --- | --- |
| 1 | パラメータ | モーションクリップ → 手続き的な振る舞い → Cubism の振り子 → クランプ / 巻き戻し | **H1 パラメータの上書き**。置き換えたパラメータは、この評価では既定値を取り、置き換えた振り子グループは飛ばします |
| 2 | デフォーマ | 親が先。Warp / 回転の枠 | **H2 枠の置き換え**。精密に合成した枠で、指定したデフォーマを置き換えます（折りたたんだリンクなど） |
| 3 | ボーンフレーム | なし（コア層にボーンはありません） | **H3 ボーンフレーム**。デフォーマの枠、または仮想フレームから、各ボーンのキャンバス変換を得ます。H4、衝突体、ホストの装着用です |
| 4 | メッシュ | 静止位置 + キーフォームのオフセット + ブレンドシェイプ → 親の変換 | **H4 メッシュ寄与の置き換え**。指定したメッシュの指定した寄与（スキニング軸のキーフォーム、指定したブレンドシェイプ）を、拡張の計算結果で置き換え、残りは通常どおりです |
| 5 | Glue | 頂点の対が互いに引き合います | なし |
| 6 | 時間ステップ後の後処理 | なし | **H6 頂点シミュレーション**。dt が必要です。今回の評価の頂点を目標に、固定ステップのシミュレーションを行い、対象メッシュの頂点を覆います。衝突はこの段階の中で解きます |
| 7 | 描画順 | 描画ツリーのソート | なし |

フックの共通規則は、次のとおりです。

- 拡張を開いていないとき、すべてのフックは空操作で、コード経路はコアの評価と同じです。
- H1 の上書きは、評価全体に作用します。ライターが列挙できるのは、置き換えたジオメトリだけを駆動するパラメータ（`ParamSim*` など）だけなので、チャンネルは影響を受けません。
- `p2l_evaluate`（dt なし）は H6 を進めず、シミュレーションメッシュは前回のシミュレーション状態を表示し、一度も進めていないときは目標を表示します。

### 拡張ブロックの共通ヘッダ

各拡張ブロックのペイロードは、統一した上書き宣言で始まります。リーダーは、ブロックの内容を理解しなくても、何を置き換えるかを知れます（診断と `META` の表示に使います）。

```
u16 feature_bit           对应 p2l_set_advanced 的特性位
u16 hooks                 位集：H1=1, H2=2, H3=4, H4=8, H6=32
u32 n × ref parameter     H1 被覆盖为默认值的参数
u32 n × ref physicsGroup  H1 被跳过的摆锤组
u32 n × ref deformer      H2 被替换框架的变形器
u32 n × { ref mesh, u32 n × ref axisParameter, u32 n × u32 binding }
                          H4 被替换的贡献：这些关键形轴取默认值、这些混合形不计入
u32 n × u8[4] depends_on  依赖的其他扩展块标签
```

そのあとは、ブロック自身の内容です。依存するブロックが欠けている、または開いていないとき、その拡張は自動で停止します。

### 特性ビットとモードスイッチ

| ビット | ブロック | 説明 |
| --- | --- | --- |
| 1 | `SKIN`（仮想ボーンを参照するときは `BONE` が必要です） | ランタイムのスキニング |
| 2 | `BONE` の円弧 | 精密リンク（円弧に沿って補間する枢軸） |
| 4 | `SIMS` | 頂点単位のリアルタイムシミュレーション |
| 8 | `COLL`（`SIMS` が必要です。シミュレーションに伴って開きます） | 衝突 |

- `p2l_advanced_available()` は、ファイルが持ち、ランタイムが対応するビットを返します。`p2l_set_advanced(bits)` は、実際に開いたビットを返し、0 が Cubism モードです（既定）。切り替えるとき、シミュレーションの状態をリセットします。
- `p2l_bone_count / p2l_bone_id / p2l_bone_transform` は、H3 のボーンフレームを出力します。
- 時間ステップの拡張は、固定ステップ（ステップ長はブロック内に書きます）、シングルスレッド、固定した走査順でなければならず、更新ごとのステップ数に上限があり、超えた時間は捨て、出力は最後の 2 ステップのあいだを補間します。`PHYS` のやり方と同じです。

## 拡張ブロック `BONE`（バージョン 1）

```
公共头                      feature 2，hooks H2 | H3，deformers = 有圆弧的变形器
u32 n × deformer            虚拟骨骼：DEFM 格式的旋转变形器记录，第 i 个的下标为 n_DEFM + i；
                            父级是 DEFM 中的变形器或更早的虚拟骨骼
u32 n × { ref deformer, sref id }            宿主可挂接的骨骼（DEFM 或虚拟骨骼）
u32 n × { ref deformer, ref parameter, f32 cx, cy }   圆弧
```

- **仮想ボーン**。スケルトンをベイクするとき、メッシュが直接掛かっておらず、刈り込まれた、または折りたたまれたボーンです。評価するのはランタイムのスキニングの中だけで、コアの評価には参加しません。ボーンパラメータと角度の関係は、ベイク前の Rotation デフォーマと同じです。角度はパラメータ値 × 方向で、枢軸はボーンの位置です。
- **円弧**。その Rotation デフォーマの枢軸が、`parameter` の 1 本の軸の上にだけキーを持ち、各キーの位置が (cx, cy) を中心とする（親空間の）同じ円の上に落ちます。精密リンクを開くと、隣り合う 2 つのキーのあいだの枢軸位置は、角度と半径で補間し、弦は取りません。ライターが円弧を書くのは、キーが 4 つ以上で、すべて同じ円の上に落ち、転向が一致し、各ステップが半周より小さい枢軸だけです。
- `p2l_bone_count / p2l_bone_id / p2l_bone_transform` は、装着できるボーンを列挙します。仮想ボーンの変換は、現在のパラメータからその場で求めます。

## 拡張ブロック `SKIN`（バージョン 1）

```
公共头                      feature 1，hooks H4，不替换任何贡献
u32 n × {
  ref mesh                  其父级是旋转变形器，且在 bones 中
  u32 n × { ref parameter, array<f32> keys }   蒙皮轴：烘焙时取样的参数及其键
  u32 n × ref deformer      骨骼：DEFM 或虚拟骨骼中的旋转变形器
  array<u16|u32> from, array<u16|u32> to, array<f32> weight   每顶点的两骨权重；长度为 0 时由运行时拟合
}
```

評価（H4。メッシュの親空間で、親変換の前）は、次のとおりです。

1. 各ボーン b が、静止ポーズに対して頂点を運ぶ変換です。A_b = H⁻¹ · B · B_rest⁻¹ · H_rest。H はメッシュの親（home）の枠、B はボーンの枠で、いずれも現在のパラメータの下のキャンバス変換です。
2. 2 本のボーンの線形ブレンドです。LBS(v) = (1 − w) · A_from(v) · p + w · A_to(v) · p。p は静止位置です。
3. メッシュへ、LBS(現在値) − Σ_c w_c · LBS(c) を足します。c は現在値の両側にあるスキニング軸のキーの組み合わせを巡り、w_c はベイクと同じ多重線形のウェイトです。残りのパラメータは現在値を保ちます。

この補正は、各キーの組み合わせでちょうどゼロになるので、高度モードはベイクした各キーの上で Cubism モードと一致します。キーのあいだでは、ベイクの弦をボーンの弧に取り替えます。ウェイトが与えられていないとき、ランタイムは開いたときにフィットします。すべてのキーの組み合わせ（最大 1024。超えるときは軸ごと）で、各頂点について、ベイクした位置を最もよく再現するボーンの対とウェイトを選び、同点のときは 1 本のボーンへの剛体追従を取ります。

ライターは、親が Rotation デフォーマで、その下（Rotation デフォーマでつながります。仮想ボーンを含んでかまいません）にメッシュ軸でキーを持つ Rotation デフォーマがあるメッシュに対して `SKIN` を書きます。ボーンは最大 16 本、軸は 8 本です。脚のメッシュは立ちポーズの Warp に掛かるので、ベイクのままにします。

## 拡張ブロック `COLL`（バージョン 1）

```
公共头                      feature 8，hooks H6
u32 n × { sref id, u8 capsule, i32 deformer, i32 mesh, u32 vertexA, u32 vertexB,
          f32 ax, ay, bx, by, radiusA, radiusB, friction }
```

衝突体は、円（capsule が 0。a 端だけを使います）、または a から b へ、半径が radiusA から radiusB へ漸変するカプセルで、半径はキャンバスピクセルです。位置は、次のいずれかで決まります。

- **メッシュ頂点に追従**。mesh が -1 でないとき、両端はそのメッシュの vertexA / vertexB が、今回の評価で持つ位置を取ります。エディタが書き出す衝突体はすべてこの種類なので、エディタとランタイムが見る位置は同じです。
- **デフォーマに追従**。deformer が -1 でないとき（仮想ボーンでもかまいません）、(ax, ay) と (bx, by) はそのデフォーマの局所空間の点です。
- **固定**。両方が -1 のとき、両端はキャンバス上の固定点です。

friction は 0 から 1 で、接触のときに相殺する滑りの割合です。衝突が効くのはシミュレーションの中だけです。`SIMS` の各シミュレーションは、避ける衝突体を列挙します。

## 拡張ブロック `SIMS`（バージョン 1）

```
公共头                      feature 4，hooks H1 | H4 | H6；parameters、physics groups 为各模拟替换项的并集
u32 n × {
  sref id, f32 fps, u32 substeps, f32 gravityX, gravityY, windX, windY, pinCompliance
  u32 n × { ref mesh, u32 vertexCount }                 目标网格，粒子按此顺序排列
  array<f32> invMass, damping, windFactor, pinWeight, goalCompliance, goalOffsetX, goalOffsetY
  array<u32> anchorMesh (0xFFFFFFFF 为跟随自身), array<u32> anchorVertex
  array<u32> stretchA, stretchB; array<f32> rest, compliance, compressionCompliance
  array<u32> triA, triB, triC; array<f32> areaCompliance
  array<u32> bendT1, bendT2; array<f32> bendCompliance
  array<u32> weldA, weldB; array<f32> weightA, weightB, weldCompliance
  array<u32> longParticle, longRoot; array<f32> maxDistance
  u32 n × ref parameter                                 本模拟替换的烘焙模式参数
  u32 n × u32 physicsGroup                              本模拟替换的摆锤组（PHYS 下标）
  u32 n × { ref parameter, array<f32> keys, u32 n × { ref mesh, keys × array<f32> offsets } }   烘焙加入的静态修正
  u32 n × u32 collider                                  COLL 下标
}
```

シーンは、エディタの XPBD ソルバー（`XpbdSolver`）と項目ごとに対応します。ワールド空間はキャンバスの x と、符号を反転したキャンバスの y（y は上）です。compliance が負なのは、その拘束がないことを表します（エディタでは無限大です）。

シミュレーションを開いたあとは、次のとおりです。

- **H1**。置き換えたモードパラメータは既定値を保ち、対応する振り子グループは飛ばします。
- **H4**。対象メッシュから静的な補正を引きます（各キーのあいだは線形補間です。ベイクがキーフォームへ書くやり方と同じです）。このとき評価した対象メッシュが、未ベイクのバインドであり、各粒子の目標になります。釘付けした粒子は、自身、または追従するメッシュ頂点の位置に従います。
- **H6**。`p2l_update` は、シーン自身の fps で固定ステップを進めます。1 回の更新は最大 4 ステップで、超えた時間は捨て、描画は最後の 2 ステップのあいだを補間します。`p2l_evaluate` は、1 つ前のステップだけを描きます。最初の更新のとき、粒子はそのときのポーズで静止します。`p2l_sim_reset` は次の更新をやり直させ、`p2l_sim_wind` はホストの風を重ねます。

書き出しのとき（ランタイムとウェブの対象だけ）、エディタは最終バインドの上で、ベイク済みの各シミュレーションを再構築して較正します。既定ポーズでは、モードパラメータがゼロで、静的な補正は静止キーにあるので、シーンはベイクしたときと同じです。

## 付随ブロック（必須ではない。バージョン 1。共通ヘッダなし）

### `EXPR`

```
u32 n × { sref id, sref name, f32 fadeIn, f32 fadeOut, u32 n × { ref parameter, u8 blend (0 Add, 1 Multiply, 2 Overwrite), f32 value } }
```

表情は Cubism の exp3 と一致します。ウェイト w は、正弦イージングのフェードインとフェードアウトの係数で、各ブレンド方式の計算は次のとおりです。

- Add。値 + v·w
- Multiply。値 · (1 + (v − 1)·w)
- Overwrite。値 · (1 − w) + v·w

ランタイムは一度に 1 つの表情を再生し、切り替えるときは前の表情がフェードアウトします。更新の順序は、モーションクリップ、表情、手続き的な振る舞い、物理の順です。書き出しのとき、エディタはバインドの中に存在するパラメータから、微笑、悲しみ、怒り、驚きの 4 つの表情を生成し、モデルに対応するモジュールパラメータがあるときは、さらに恥じらい、眠気、陰鬱を足します。フェードインとフェードアウトはそれぞれ 0.5 秒です。

### `HITA`

```
u32 n × { sref id, sref name, u32 n × ref mesh }
```

クリック領域は、そのメッシュが描く範囲を覆います。`p2l_hit_test(x, y)` は、ファイルの順で、可視メッシュがそのキャンバス上の点を含む最初の領域を返します。書き出しのときは、ドキュメントが設定したクリック領域を書きます（[書き出し先](EXPORT_TARGETS.md#クリック領域) を参照）。ドキュメントに設定がないときは、`HitAreaHead`（顔）と `HitAreaBody`（上衣。なければ首または下衣）を生成します。

### `UDAT`

```
u32 n × { u8 kind (0 = 网格), ref target, sref value }
```

メッシュのユーザーデータ（インポートした CMO3 から）で、`p2l_mesh_user_data` を通して読みます。

### `POSE`

```
f32 fadeIn, u32 n × { u32 n × { ref part, u32 n × ref linkedPart } }
```

パーツの排他グループは Cubism の pose3 と一致します。各グループは同時に 1 つのパーツだけを表示し、切り替えるとき、選ばれたパーツは fadeIn 秒でフェードインし、残りは Cubism の規則（φ = 0.5、背面の不透明度のしきい値 0.15）でフェードアウトします。リンクしたパーツは、所属するパーツに従います。

これは評価のあとの 1 ステップです。メッシュの不透明度に、そのすべての祖先パーツのポーズ不透明度を掛けます。どのグループにも入っていないパーツは 1 なので、`POSE` を持たないファイルの評価は変わりません。コアの評価では、パーツの不透明度は引き続きメッシュの不透明度に数えません。初期状態では、各グループは最初のパーツを表示します。

ホストは `p2l_pose_show(group, entry)` で切り替えます。書き出し設定 `pose_groups` は、`パーツ|パーツ; パーツ|パーツ` でグループを指定し、`パーツ+リンクパーツ` がリンクを表します。

### `CEXT`

```
u32 n × { ref clip,
          u32 n × { f32 time, sref value },                                    事件，按时间升序
          u32 n × { u8 target, i32 part, f32 fadeIn, f32 fadeOut,
                    f32 startTime, f32 startValue, u32 n × segment },          非参数曲线
          u32 n × { u32 curve, f32 fadeIn, f32 fadeOut } }                     片段自身曲线的淡入淡出
```

モーションクリップの拡張で、Cubism motion3 のうちパラメータカーブ以外の内容に対応します。必須ではなく、知らないランタイムは `CLIP` の中のパラメータカーブだけを再生します。各クリップの記録は最大 1 件です。

- **イベント**（motion3 の `UserData`）。クリップ時間がイベント時間を通過するとき、`p2l_event_count` / `p2l_event` がホストへ知らせます。循環クリップは 1 周ごとに 1 回発火し、シーク（`p2l_clip_seek`）が飛び越したイベントは発火しません。
- **パラメータ以外のカーブ**。`target` の 1 はパーツの不透明度（`part` はパーツの添字）、2 は全体の不透明度、3 はまばたき効果、4 は口形効果です（あとの 3 つは `part` に -1 を書きます）。カーブ区間のエンコーディングは `CLIP` と同じです。パーツの不透明度と全体の不透明度は、カーブの値で直接設定し（フェードインとフェードアウトには従いません。Cubism と同じです）、乗数として、パーツの下のメッシュとモデル全体に作用します。まばたき効果は `EyeBlink` の役割パラメータへ掛け、口形効果は `LipSync` の役割パラメータへ足します。クリップがそのパラメータのカーブを持つときはカーブの値に作用し、持たないときはクリップのウェイトで現在値に作用します。
- **フェードインとフェードアウト**。負数は、クリップの設定を引き継ぐことを表します。`curve` は、そのカーブが `CLIP` の中で書かれた通し番号です（ファイルに存在するパラメータだけを数えます）。自身のフェードインとフェードアウトを持つカーブは、Cubism の規則でウェイトを取ります。フェードイン係数はカーブのフェードイン（またはクリップのもの）を使い、フェードアウト係数はカーブのフェードアウト（またはクリップのもの）を使い、両者を掛けます。

拡張ブロックの共通の制約は、次のとおりです。

- 置き換える、または補うのは、コアの評価の中の特定の寄与だけです（補正キーフォーム、`ParamSim*` が駆動する形状など）。パラメータ、モーション、振る舞い、Cubism の振り子は、通常どおり駆動します。
- 既定はオフです。ホストは `p2l_set_advanced(features)` で開き、閉じているときの評価結果は、コアブロックだけのファイルとビットごとに一致します。
- ライターは、コアブロックの中に、対応する Cubism のベイク結果を常に残します。

## ランタイムとライター

- **読み取り**。v1 と v2 の両方に対応し、どちらも同じメモリ構造 `Rig` へ解析します。評価のコードは 1 つだけです。
- **書き出し**。`P2lrtTarget` は既定で v2 を書きます。書き出しオプション `v1` は、コアの内容の v1 レイアウトだけを書き、このとき拡張データがあれば、`CapabilityScan` はそれがベイクの形で残っていると報告します。`compress` は deflate で、小さくなるブロックを圧縮し、`strip_names` は名称を剥がします。
- **能力の問い合わせ**。`p2l_format_support()` を追加し、対応するメジャーバージョンと、ブロックタグおよびバージョンの一覧を返します。`p2l_rig_load_ex(bytes, len, flags)` の flags の bit0 は、CRC の検証を要求します。
- **圧縮の依存**。Rust の読み取り側は、純粋な Rust の `miniz_oxide`（deflate）と `ruzstd`（zstd の復号）を使い、WASM へコンパイルでき、ランタイムに必要なのは復号だけです。そのため WASM ビルドは 208 KB から 400 KB へ増え、そのうちバージョン 2 の読み取りと deflate がおよそ 79 KB、zstd がおよそ 113 KB です。Kotlin の書き出し側の deflate は JDK の `Deflater` を使い、zstd は純粋な Java の aircompressor を使います。
- **バイトの安定**。同じ IR を 2 回書くとバイトは同じです。名称の剥離と配列エンコーディングは書き出しオプションが決め、環境には影響されません。

## 検証

- **v1 と v2 のビットごとの一致**。`RuntimeConformanceTool` のすべての無作為モデル、サンプル、物理の軌跡を、v1 と v2 の両方で書き、ランタイムの評価結果を `to_bits()` で比較します。頂点、不透明度、色、描画順は、完全に同じでなければなりません。
- **リーダー**。v1 は受け付けます。v2 の最小ファイルは受け付けます。未知の任意ブロックは飛ばします。未知の必須ブロックは拒否し、タグを報告します。ブロックの範囲外、重なり、読み過ぎ、読み不足、規範タグの重複、必須コアブロックの欠落、誤った境界、CRC の不一致（検証を開いているとき）は、すべて拒否します。Rust（`runtime/src/tests.rs`）と Kotlin（`P2lrtTest.kt`）に、それぞれ 1 組あります。
- **再現可能**。同じ IR、同じ設定で 2 回書くとバイトは同じです。`STRS` は重複を除いたあと、書く順序と無関係な内容が一致します。
- **圧縮**。同じモデルを、圧縮なし、deflate、zstd で書き、伸長後の各ブロックの内容はバイト単位で同じで、評価はビットごとに一致します。`raw_length` の不一致、切れた圧縮ストリーム、予約された圧縮方式は、いずれも拒否します。Kotlin が書き、Rust と WASM が読む 3 つの方式を、すべて覆います。
- **`PGUI`**。グループの木、二次元スティック、吸着値を書いたあと読み戻すと `RigIR` と一致します。`PGUI` を除いたあと、評価は変わりません。
- **配列エンコーディング**。f16 / unorm16 のモデルと f32 のモデルの頂点誤差は、エンコーディング精度の中にあり、別に報告し、ビット一致のコーパスには入りません。
- **言語をまたぐこと**。Kotlin が書き、Rust が読みます。WASM ビルドは、同じ一組のリーダーテストを通過します。
- **拡張があるときの Cubism モード**。拡張ブロックを持つファイルは、特性ビットが 0 のとき、拡張ブロックを除いた同じファイルの評価とビットごとに一致します。開いてから閉じても一致します（残留状態はありません）。
- **拡張の参照実装**。各拡張ブロックには Kotlin の参照実装があり、`RuntimeConformanceTool` の無作為コーパスに入り、ランタイムと突き合わせます。

## 高度モードの路線との関係

本形式は、ランタイムの高度モード（ランタイムのスキニング、精密リンク、頂点シミュレーション、衝突。同じファイルの 2 モード）のコンテナの基礎で、その「段階 0 の形式パイプライン」に対応し、その路線が最初に想定した「v1 の本体のあとにブロックを追加する」案を置き換えます。コアの内容もブロックへ分け直し、すべての内容が同じ一式の進化の規則に従います。そのあとの段階は、それぞれ `BONE`/`SKIN`、`SIMS`、`COLL` のブロック内レイアウトを定義し、フック、共通ヘッダ、特性ビットは本文を基準にします。

路線の中で、実測の結果を見てから決めるとしていた数項目は、次のように決めます。

- **ランタイムの ARAP**。実施しません。スキニングの補正は各キーの上でゼロなので、高度モードはベイクした各キーの上でそれと完全に一致します（一致のサンプルはすべて 0 です）。キーのあいだは、すでにボーンの弧に沿っています。
- **立ちポーズの Warp に掛かるメッシュ（脚）**。ベイクのままにします。脚は立ちポーズの Warp の中で折れ、スケルトンは脚のボーンのために回転の枠を生成していないので、スキニングはフレームを取れません。
- **4 本のボーンのウェイト**。必要ありません。エディタのスキニングは、各頂点がまたぐボーンが最大 2 本です。

## 決まった事項

- ブロック圧縮。deflate と zstd の 2 つを定義し、リーダーはどちらにも対応しなければなりません。ライターは既定で圧縮せず、書き出し設定 `compress` は deflate を選び、さらに `zstd` を足すと zstd を選びます。
- オフセットと長さの幅。u64 です。
- パラメータのグループ、二次元スティック、吸着値は、必須ではない `PGUI` ブロックへ入れ、`PARM` は v1 と一対一に対応します。`restPose` は書きません。
