# PSD2Live ランタイム

`runtime/` は独立した Rust ライブラリ（MIT）です。PSD2Live がコンパイルした `.p2lrt` モデルを再生します。パラメータ駆動の変形、物理、モーションクリップを扱い、他の言語とエンジンが呼び出す C ABI を提供します。エディタは `:format-eval`（JNA）を通して、同じライブラリを呼び出します。

## 構成

| 部分 | 場所 | ライセンス |
| --- | --- | --- |
| `.p2lrt` の書き出しと、書き出し先 `p2lrt` | `:targets:runtime`（`P2lrt`、`P2lrtTarget`） | MIT |
| 読み取り、評価、物理、モーションクリップ、C ABI | `runtime/`（crate `p2l-runtime`、cdylib + staticlib） | MIT |
| C ヘッダ | `runtime/include/p2l_runtime.h` | MIT |
| JVM バインディング | `:format-eval`（`P2lRuntime`、`NativeGeometryEvaluator`） | MIT |
| ウェブプレーヤー | `:targets:web`（書き出し先 `web`：ページ、`p2l.js`、ランタイムの WebAssembly ビルド） | MIT |
| Godot 4 ノード `P2LCharacter` | `runtime/godot/`（GDExtension、godot-rust、Godot 4.3+）。デモプロジェクト `runtime/godot/demo/` | MIT |

ビルド：`runtime/` で `cargo build --release` を実行します。ライブラリは `runtime/target/release/` にあります（Windows では `p2l_runtime.dll`）。Gradle の `buildRuntime` は、cargo があるとき自動でビルドします。`./gradlew run` がそれを使い、パッケージ時にはアプリのリソースとともに配布します。cargo がないときは飛ばし、アプリはエディタの評価器へ戻ります。`P2lRuntime.locate()` は、システムプロパティ `psd2live.runtime.library`、環境変数 `PSD2LIVE_RUNTIME`（ファイルまたはディレクトリ）、システムプロパティ `psd2live.runtime.dir`、パッケージしたアプリのリソースディレクトリ、`java.library.path` の順に探します。

エディタの書き出しベイク（Spine、DragonBones、glTF）は、ランタイムライブラリが使えるときは `NativeGeometryEvaluator` で評価し、そうでなければエンジンの評価器を使います。両者はポーズごとに一致します。エディタのソフトウェアプレビュー（`RigCanvasSupport.evaluate`）も、`NativePreview` を通してランタイムを使います。あるプレビューモデルに初めて出会ったときはエンジンが答え、バックグラウンドでコンパイルし、その後のフレームはランタイムを通ります。ドラッグ中の一時モデルはコンパイルを待たず、失敗したとき、または `-Dpsd2live.preview.runtime=false` のときはエンジンのままです。スケルトン付きの tml で 1 回の評価は約 0.5 ミリ秒で、エンジンと同程度です（JNA 呼び出しと結果変換が、ネイティブの速さを相殺します）。

プレビューキャンバスは、ランタイムをプレビューのバックエンドに選べます（「PSD2Live ランタイム（p2lrt）」。CANVAS_RENDERER.md を参照）。バックグラウンドでプレビューモデルを `.p2lrt` にコンパイルし（シミュレーションを含む）、ランタイムはワークスペースの時計が与える完全なポーズを評価し、`P2lrtGlRenderer` はウェブプレーヤーの規則に従って、ウィンドウ自身の Skia OpenGL コンテキストに描きます。拡張（高度）モードがオンのとき、各ビューのモデルはスキニングと精密リンクをオンにします。リアルタイムシミュレーションと衝突は、プレビューの物理スイッチが制御します（オンのときは `p2l_update_stages(dt, P2L_STAGE_SIM)` で、フレーム時間に沿ってリアルタイムシミュレーションだけを進め、一時停止しても止まりません。オフのときはベイクしたスイングを表示します）。ワークスペースがすでに合成した物理結果はそのまま残し、ランタイムは物理を重複して計算せず、手続き的な振る舞いはオフのままです。バックグラウンドのコンパイルは、スキニングウェイトも同時に用意してキャッシュします。ビューは共有モデルから、それぞれのポーズとシミュレーションのインスタンスを作ります。モードを切り替えても、レンダリングスレッドで再フィットはしません。Cubism SDK が使えないとき、プレビューは自動でこちらに切り替えます。

拡張は、モデルが実際に持っているデータにだけ作用します。適用できる拡張がないとき、またはシミュレーション拡張だけで物理がオフのとき、プレビュー状態はその理由を示します。ベイクしていないシミュレーションは、リアルタイムシミュレーションのデータを提供しません。有効かつベイク済みのシミュレーションが構築または較正に失敗したときは、コンパイルがそのシミュレーションを報告し、拡張が黙って失われることを避けます。

## `.p2lrt` 形式

リトルエンディアンのバイナリで、コンパイル後の IR の密な表現です。キャンバス、パラメータ、デフォーマ（親が先）、パーツ、メッシュ、Glue、描画ツリー、テクスチャページ、物理グループ、モーションクリップ、パラメータの役割（EyeBlink、LipSync など）を含みます。参照はすべてインデックスです。

書き出しは既定でバージョン 2 を書きます。ファイルヘッダ、ブロックディレクトリ、16 バイト境界、CRC 付きのブロック、文字列テーブルに集めた文字列、エンコード付きで 4 バイト境界の配列、それにパラメータパネル（`PGUI`）とジェネレーター情報（`META`）です。レイアウトと進化の規則は [P2LRT_V2.md](P2LRT_V2.md) を参照してください。書き出しオプション `v1` はバージョン 1 を書きます（単一の順次ストリーム。フィールドごとのレイアウトは `P2lrt.kt` のドキュメントコメント）。まだ更新していないプレーヤー向けです。`compress` は deflate で、小さくなるブロックを圧縮します（テクスチャページを除く）。`strip_names` は表示名を外し、id は残します。

リーダー（`runtime/src/rig.rs`、`container.rs`）は両方のバージョンを読み、同じ `Rig` に解析します。評価コードは 1 つだけです。参照、メッシュインデックス、キーフォームのサイズ、ブロックの位置と境界、ブロック内の記録がちょうど読み終わることを検証します。知らない任意ブロックは飛ばし、知らない必須ブロックに出会うとそのタグを報告します。ブロックは deflate または zstd で圧縮できます（書き出し設定 `compress`。`zstd` を加えると zstd）。

## 評価規則

評価は、各メッシュについて、キャンバスのピクセル座標（y は下）での頂点、透明度、乗算 / スクリーン色、描画順を出力します。規則はすべて、エディタ評価器をブラックボックスで調べて得たものです（`WarpProbeTool`、`RuntimeConformanceTool`）。その実装は参照していません。

- **パラメータ**：範囲へクランプします。循環パラメータは、範囲の外の値だけを巻き戻し、両端は元の値を保ちます。
- **キーフォームメッシュ**：多重線形補間です。値があるキーポイントと 0.001 未満しか違わないときは、そのキーポイントを取ります。疎なメッシュで欠けているマスは、ゼロ形状として数えます（メッシュのオフセットはゼロ、デフォーマの絶対形状は原点）。ウェイトは再配分しません。フラグチャンネル（反転）は、現在値以下のキーポイントを取ります。
- **Warp**：単位正方形の内側は、マスごとに双線形、または (1,0)–(0,1) の対角線で 2 つの三角形に分けて補間します。外側は [-2, 3]² の内側で、1 層のより粗い仮想マスを伸ばします。追加の格子点は、マスの四隅の平均アフィン枠を取り、三角形で補間します。さらに遠いところはアフィン枠だけを使います。
- **回転デフォーマ**：角度は、キーフォームの角度に基準角を足したものです。親が回転のとき、原点は親の変換を通り、角度と拡大縮小は親に重なります。親が垂直反転しているとき、または親の拡大縮小が負のとき、子の枠は追加で 180° 回転します。親の水平反転は、子の枠の向きに影響しません。自身の反転は、子の座標にだけ作用します。親が Warp のとき、枠は剛体のままです。原点はマスの写像を通り、角度は原点の 0.1 上で v 方向に沿ったマスの向きに従って回転し、拡大縮小はマスの上で最も近い回転の拡大縮小を継承します。
- **ブレンドシェイプ**：各バインドは、パラメータに沿って隣り合うキーポイントのあいだを線形に混ぜます（キーポイントへ丸めません）。中立のキーポイントと、形状のないキーポイントは寄与しません。ウェイトには、各制限パラメータの区分線形係数を掛けます。デフォーマとチャンネルの形状は目標値で、重ねるのは「目標 − 既定ポーズでの値」です。メッシュ形状は目標オフセットで、重ねるのは「目標オフセット − 既定ポーズでのオフセット」です。
- **透明度**：各段（デフォーマ、メッシュ）は、まず [0, 1] にクランプしてから親と掛けます。パーツの透明度は、メッシュの透明度に含めません。
- **Glue**：すべての変形のあと、頂点の各対は、自分のウェイトに強さを掛けた分だけ、相手へ移動します。
- **描画順**：各描画グループは、子の描画順で並べます。子グループのキーは、そのパーツをチャンネルとブレンドシェイプから求めた描画順です（パーツがないときは静的な値）。キーに千分の一を足してから整数化し、同じときはツリー内の順序を保ちます。隠したメッシュは描きません。規則はエンジンのレンダリング順インターフェースのドキュメント説明から取ったもので、ネイティブのレンダリングとはフレームごとに比較していません。

## 高度なモード

ファイル内の拡張ブロックは、Cubism と等価な評価の外の機能を提供します。すべて既定はオフです。`p2l_set_advanced` でオンにします。オフのとき、評価はコア評価とビット単位で一致します。レイアウトと意味は [P2LRT_V2.md](P2LRT_V2.md) を参照してください。

- **ランタイムスキニング（`P2L_SKIN`）**：膝や肘などの関節で曲がるメッシュは、ベイク時にキーでサンプリングし、キーのあいだは弦に沿って補間します。ランタイムは、ボーン枠を頂点ごとに 2 ボーンの線形ブレンドし、それに「現在のブレンド − キーのあいだで補間したブレンド」を足します。これは各キーでゼロになり、キーのあいだでは弦を弧に置き換えます。ウェイトは、オンのときにベイクしたキーフォームへフィットします。スケルトンが切り落とした、または折りたたんだボーンは、仮想ボーンとしてファイルとともに提供されます。ホストは `p2l_bone_*` でボーン変換を読み、オブジェクトを取り付けられます。
- **精密リンク（`P2L_EXACT_LINKS`）**：同じ円上にキーされた枢軸は、円弧に沿って補間します。
- **リアルタイムシミュレーション（`P2L_SIM`）と衝突（`P2L_COLLISION`）**：ベイク済みの布と髪は、エディタの XPBD ソルバでリアルタイムに動き、ベイクしたモードパラメータと振り子を置き換えます。コリジョンは、メッシュ頂点に沿った円またはカプセルです。

検証：`advanced_tests`（解析解が分かっている腕、リンク、仮想ボーン、ぶら下がるメッシュ）。`p2lrt-conformance --advanced` は、各サンプルがスキニングのキー上でベイクと一致することを要求します（すべて 0）。`--sim` は `RuntimeConformanceTool.simulation` のランダムな布の軌跡でソルバを比較し、エディタとビット単位で一致します（衝突を含む）。`--sim-rig` は tml の後ろ髪のベイクしたシミュレーションを端から端まで比較し、前半 0.5 秒の誤差は 0.21 ピクセル、全体の平均は 0.22 ピクセルです。差は、双方が目標を評価するときの約 1e-4 ピクセルの浮動小数の差に由来し、布がそれを増幅します。

## 物理

Cubism ランタイムが physics3.json を読む方式で実装し、その固有の振る舞いも含みます。入力はパラメータ範囲の中点で正規化します。固定ステップ（`Fps`）のときは、フレーム間で入力を補間し、出力は最後の 2 ステップのあいだで補間します。ステップを限らないときは、出力が 1 フレーム遅れます。平行移動と回転では、すでに回転した x を再利用します。拡大縮小が付くのは角度出力だけで、平行移動出力の拡大縮小はゼロです。5 秒を超える蓄積時間はゼロに戻します。エディタの `PhysicsEngine` と、ランダムな振り子グループおよびサンプルモデル上でフレームごとに比較し、誤差は 2e-5 未満です。

Cubism ランタイムの項目がさらに 3 つあります。縦方向（Y）の入出力（`PHYS` バージョン 2。[P2LRT_V2.md](P2LRT_V2.md) を参照。エディタも Cubism Editor も縦方向は生成せず、physics3 の書き出しは書けます）、風力（`p2l_physics_wind`。各粒子が受ける力に足す。physics3 の Wind と同じ）、安定化（`p2l_physics_stabilize`。現在のポーズに従って、各振り子を力の方向にある静止位置へ直接置き、出力を書く。Cubism の Stabilization と同じ）です。風力がゼロのとき、結果はこれまでとビット単位で一致します。

## モーションクリップ

カーブの区間はエディタと同じです（線形、Bezier（時間の制御点は区間内に制限）、階段、逆階段）。循環クリップは長さで巻き戻り、1 回きりのクリップは末尾で止まります。`Player` は一度に 1 つのクリップを再生し、切り替えるときはクリップのフェードインとフェードアウトの時間（既定 1 秒、コサインイージング）でクロスフェードします。クリップのウェイトは、フェードイン係数とフェードアウト係数の積です（Cubism と同じ）。置き換えられた各クリップは完全にフェードアウトし、連続してすばやく切り替えても、まだフェードアウト中のクリップを失いません。

## 手続き的な振る舞い

ホストがオンにできるもの：まばたき（`EyeBlink` の役割。2〜6 秒に 1 回。閉じる 0.1 秒、保持 0.05 秒、開く 0.15 秒。現在値に掛ける。`p2l_blink_settings` で間隔と各段階の長さを変えられる）、呼吸（`Breath` は範囲内の正弦。`AngleX/Y/Z`、`BodyAngleX` に小さな揺れを重ねる）、視線（`look_at(x, y)` が臨界減衰で追従し、`AngleX/Y`、`BodyAngleX`、`EyeBallX/Y` を駆動する。`AngleZ` は x·y に従って傾く）、口形（`lip_sync(level)`。`LipSync` パラメータは大きい方の値を取る。`p2l_lip_sync_samples` は、一段の音声サンプルの二乗平均平方根にゲインを掛けたものを開き量にする）です。`p2l_behavior_strength` は、呼吸の揺れの振幅、視線の回転の振幅、追従速度を調整します。役割は、エディタがコンパイルするとき、存在する標準パラメータに従って書きます。moc3 の model3.json は、今までどおり EyeBlink と LipSync の 2 組だけを書きます。更新順：モーションクリップ → 振る舞い → 物理 → 変形。

## C ABI

1 つのハンドルが、読み込み済みのモデル 1 つに対応し、パラメータ、モーションプレーヤー、物理状態を持ちます。典型的な流れ：`p2l_rig_load` → パラメータを設定（`p2l_parameter_values` / `p2l_set_parameter`）→ `p2l_update(dt)`（モーション、物理、変形）または `p2l_evaluate` → `p2l_mesh_vertices`、`p2l_mesh_opacity`、`p2l_mesh_colors` を読み、`p2l_render_order` に従って後ろから前へ描く。テクスチャは `p2l_texture_png` が提供します（`p2l_texture_info` がテクスチャページの種類を示す。埋め込み PNG、KTX2、またはモデルの隣のファイル）。`p2l_rig_load_ex` はブロックの CRC 検証を要求でき、`p2l_format_support` は対応するバージョンとブロックを列挙します。表情（`p2l_expression`）は、モーションクリップのあと、手続き的な振る舞いの前に重なります。`p2l_hit_test` は、キャンバス上の点の下にあるクリック領域を返します。`p2l_mesh_user_data` はメッシュのユーザーデータを読みます。`p2l_pose_show` はパーツの排他グループを切り替えます（書き出し設定 `pose_groups`）。置き換えられたパーツは `p2l_update` に伴ってフェードアウトします。`p2l_parameter_values` はホストが設定したポーズで、`p2l_update` のたびにそこからモーション、表情、振る舞い、物理を重ね直します。重ねた結果は書き戻さないため、まばたき、呼吸、加算の表情はフレームごとに累積しません。このフレームで実際に使った値は `p2l_parameter_current` が読みます。すべての関数は空のハンドルを受け付けます。返したポインタは、ハンドルを解放するまで有効です（ポーズデータは次の評価まで）。

ABI 1.1 で増えた部分（すべて新しい関数。1.0 の関数の振る舞いは変わらず、範囲外の添字の戻り値だけが区別できる値に変わった）：

- **モデルとインスタンス**：`p2l_model_load` はファイルを 1 回読んで、読み取り専用でスレッドをまたいで共有できるモデルを得ます。`p2l_rig_create` はその上に、それぞれがパラメータ、モーション、物理状態を持つハンドルを作ります。`p2l_model_free` のあと、すでに作ったハンドルはモデルを持ち続けます。`p2l_rig_load` は両者を 1 つにしたものです。1 つのハンドルを 2 つのスレッドが同時に使うことはできません（読み取りも不可。`p2l_bone_transform` はハンドルを更新する）。
- **層に分けた更新とホスト層**：`p2l_update_stages(dt, stages)` は、選んだ層だけを実行します（モーション、表情、振る舞い、パーツポーズ、物理、リアルタイムシミュレーション。順序は変わらない）。選ばなかった層は、進めも重ねもしません。`p2l_set_parameter_override(index, value, weight)` はホスト層です。モーションと表情のあと、振る舞いと物理の前に、パラメータをウェイトに従って与えた値へ引き寄せます（フェイストラッキングなど）。物理はそれに伴って揺れます。`p2l_parameter_values` は、今までどおり最下層です。
- **パーツと隔離グループ**：`p2l_part_*` は、パーツの id、名前、親パーツ、フラグ、グループ化の方式（直通、グループ全体のソート、隔離）を与えます。`p2l_render_commands` は、隔離グループの境界を残した描画順です（メッシュの添字。`-2 - 部件` でグループを開き、`-1` でグループを閉じる）。グループのブレンドモード、透明度の合成モード、マスク（マスクパーツはそのメッシュへ展開する）は `p2l_part_group` / `p2l_part_masks` が与え、評価後のグループ透明度と乗算 / スクリーン色は `p2l_part_composite` が与えます。描画ツリーでそのグループのチャンネルが、合成した静的な値を覆い、エディタと一致します。`p2l_set_part_opacity` はホストのパーツ透明度を設定し、パーツポーズと同じく、その下のすべてのメッシュに掛けます。`p2l_mesh_part` はメッシュが属するパーツを与え、`p2l_mesh_alpha_blend` はメッシュの透明度合成モードを与えます。
- **ファイル情報**：パラメータの名前とフラグ（循環、ブレンドシェイプのパラメータ）、スナップ値、パラメータパネル（`PGUI`：二次元スティック、グループの木、ラベル）、キャンバス原点と単位あたりのピクセル、モーションクリップの名前、グループ、長さ、フレームレート、循環、フェードインとフェードアウト、再生中のクリップ、現在時刻とシーク（`p2l_clip_seek` はクリップの時間だけを動かし、フェードインは通常どおり）、表情、クリック領域、メッシュの表示名、ジェネレーター情報（`META`）。
- **その他**：`p2l_behavior_seed` はまばたきの乱数シードを設定し直します。プロセス内で最初のあとのハンドルは、それぞれ自分のシードを自動で取ります。範囲外の添字の取得関数は NaN（数値）または -1（添字、モード）を返し、空のハンドルは今までどおり 0 を返します。`p2l_alloc` は長さどおりに正確に割り当て、ゼロで埋めます。PNG でないテクスチャページの `p2l_texture_png` は長さを 0 と書きます。`p2l_parameter_index` は、`p2l_parameter_id` が与える文字列で検索します。

ABI 1.2 で増えた部分（同様に新しい関数だけ）：

- **モーション層**：最大 `P2L_MAX_LAYERS`（16）層。各層は一度に 1 つのクリップを再生し、層の順に下の層の上へ重ねます。`p2l_set_layer_weight` は、その層が下の層を覆うウェイトを設定します。`p2l_play_layer(layer, clip, priority)` は、優先度がその層で再生中のクリップの優先度以上のときだけ開始します（クリップが終わり、または止まったあとは 0）。Cubism のモーションマネージャの優先度に対応します。`p2l_play` と `p2l_clip_*` は第 0 層を操作します。
- **モーションイベントと、パラメータ以外のカーブ**：`CEXT` に由来します（[P2LRT_V2.md](P2LRT_V2.md) を参照）。更新のたびに通過したイベントは `p2l_event_count` / `p2l_event` が与えます（テキスト、層、クリップ、時間）。クリップが設定したパーツ透明度と全体透明度はメッシュに掛けます。`p2l_evaluate` はホストのポーズだけを求めるため、それらを含みません。まばたきと口形の効果は、対応する役割のパラメータに作用します。自身のフェードインとフェードアウトを持つカーブは、Cubism の規則でウェイトを取ります。
- **複数の表情**：`p2l_expression_add` / `p2l_expression_remove` は、複数の表情を同時に有効にします（それぞれフェードインとフェードアウトし、開始順に重ねる）。`p2l_expressions_playing` は有効なものを列挙します。`p2l_expression` は、今までどおり 1 つだけを残します。
- **全体の透明度と色の上書き**：`p2l_set_opacity` はすべてのメッシュに掛けます（クリップが設定した全体透明度とも掛ける。`p2l_opacity` は積を読む）。`p2l_set_mesh_colors` / `p2l_set_part_colors` は、ホストが与えた乗算 / スクリーン色で評価結果を置き換えます。メッシュ自身の設定は、そのパーツ連鎖上で最も近い設定より優先します。
- **物理と振る舞い**：`p2l_physics_wind`、`p2l_physics_stabilize`、`p2l_blink_settings`、`p2l_behavior_strength`、`p2l_lip_sync_samples`。前述の「物理」「手続き的な振る舞い」を参照してください。

ABI 1.3 は `p2l_render` と `p2l_render_texture` を追加します（後述の「ソフトウェアレンダリング」を参照）。ABI 1.4 の追加：

- **変化フラグ**：`p2l_mesh_changes` は、メッシュを描くか（描画順にあり、不透明度が 0 より大きい）、および前回の評価と比べて、可視性、不透明度、描画順の値、描画順の中の位置、頂点、乗算 / スクリーン色が変わったかを与えます。Cubism の dynamic flags に対応し、ホストは変わった部分だけをアップロードすれば足ります。最初の評価のあと、すべてが立ちます。ポーズを変えるすべての入り口（`p2l_update`、`p2l_update_stages`、`p2l_evaluate`、`p2l_set_advanced`、`p2l_physics_stabilize`）は、終わるときに更新します。
- **ログ**：`p2l_set_log` は、読み込み失敗、ハンドルの失効、レンダラがデコードできないテクスチャページを受け取ります。
- **ホストアロケータ**：`p2l_set_allocator` は、それ以後のランタイムのメモリをすべて、ホストの割り当てと解放の関数から取るようにします（大きさと境界はそのまま渡す）。ランタイムの他のどの部分よりも前に、単一のスレッドで呼び出す必要があります。ランタイムがすでにシステムへメモリを要求しているときは false を返し、変えません。既定でオンの `host-allocator` 特性が提供します（ランタイムを Rust ライブラリとして Godot ノードなどが使うときはオフ）。C の例での実測：tml サンプルのレンダリングにおける 7570 回の割り当ては、すべてホストアロケータを通りました。

書き出し側：IR の `Clip` に `events`、`targetCurves` を追加し、`Curve` に `fadeIn` / `fadeOut` を追加し、`PhysicsSource` に `Y` を追加します。p2lrt の書き出しは `CEXT` を書き、必要に応じて `PHYS` バージョン 2 を書きます。moc3 書き出しの motion3 は、`UserData`、`PartOpacity`、`Model`（`Opacity`、`EyeBlink`、`LipSync`）のカーブと、カーブのフェードインとフェードアウトを書きます。physics3 は `Y` を書きます。cmo3 には縦方向の物理がないため、縦方向の入出力は省きます。エディタのモーション編集は、イベントとパラメータ以外のカーブの編集入り口をまだ提供しません。これらのデータは IR に由来します。

描画規則はヘッダの冒頭にあり、基準は `SoftwareRasterizer` です。テクスチャはストレート alpha で、規則はプリマルチプライド色の上で計算します。フラグメント色はまず乗算色を掛け、次に `c + s·a − c·s` でスクリーン色を重ね、最後に不透明度とマスクの被覆を掛けます（マスクメッシュはその点のテクスチャ alpha の最大値。反転は 1 − 被覆。リアルタイムプレーヤーは alpha ≥ 0.5 のステンシルで近似できる）。カリングをオンにしたときは、キャンバス座標（y は下）で時計回りの面だけを描きます。Cubism の通常、加算、乗算は、そのプリマルチプライドの式に従います（加算と乗算は対象の alpha を残す）。拡張モードは W3C の合成式に従います。ブレンドモードと透明度の合成モードには、`P2L_BLEND_*`、`P2L_ALPHA_*` の定数があります。

呼び出しがランタイム内部で panic したとき（欠陥、またはリーダーは通したが評価できないモデル）、ホストへ展開しません。その呼び出しは空のハンドルとして戻り、ハンドルは失効し、`p2l_rig_failure` が理由を与えます。その後は空のハンドルと同じで、`p2l_rig_free` まで続きます。読み込み中（最初の評価を含む）に panic したときは、`p2l_rig_load` が空を返し、理由を書きます。WebAssembly ビルドの panic は、今までどおりインスタンスを中止します（その対象はスタック展開に対応しない）。

ABI のバージョン：ヘッダの `P2L_ABI_VERSION_MAJOR` / `P2L_ABI_VERSION_MINOR` と、ライブラリの `p2l_abi_version()`（`major << 16 | minor`）。関数を追加するときはマイナーを 1 つ上げ、関数を変更または削除するときはメジャーを 1 つ上げます。ホストは `P2L_ABI_COMPATIBLE(p2l_abi_version())` で検査します。`p2l_abi_version` がないライブラリは 1.0 より前です。`p2l_version` はライブラリのビルドバージョンにすぎません。JVM バインディングはライブラリを読み込むとき、メジャーが同じで、マイナーがバインディングの必要以上であることを要求します。そうでなければランタイムがないものとして扱います。評価または更新のあとハンドルが失効したときは例外を投げます（ソフトウェアプレビューはそのためエディタ評価器へ戻り、ランタイムのプレビューバックエンドと書き出しはエラーを報告する）。`cargo test` は、ヘッダが宣言する関数とライブラリがエクスポートする関数が一対一で対応し、バージョン番号が一致することを検証します。

## 検証

- `cargo test`：各評価規則について小さなモデルの単体テスト（数値は調査結果に由来）、および Warp とモーションクリップのテスト。`format_tests` はブロックごとにバージョン 2 のファイルを組み立て、圧縮、CRC、ブロックディレクトリ、各種の拒否、すべての配列エンコード、テクスチャページの種類、パラメータパネルを覆います。
- `RuntimeConformanceTool`（`PSD2LIVE_TOOLS=1`）：80 個のランダムモデル（Warp、回転、入れ子、疎なメッシュ、ブレンドシェイプ、Glue、チャンネル、パーツ、ブレンド）、サンプルとローカルプロジェクトの参照ポーズ、物理の軌跡を生成します。`cargo run --release --bin p2lrt-conformance -- ../build/tools/runtime-conformance`（物理は `runtime-physics`）が例ごとに比較します。各例は同時に、バージョン 2、バージョン 1、deflate と zstd で圧縮したバージョン 2 を書き、4 つは同じ `Rig` として読め、ビット単位で同じポーズになる必要があります。頂点誤差の上限は 0.02 ピクセルです。それを超えるポーズは、自身の条件数で判定します。いずれかのパラメータをその範囲の 100 万分の 1 だけ動かしたとき、頂点が最も大きく動く距離（感度）の 2 倍を、誤差が超えてはなりません。メッシュ内部の補間は倍精度です。現在はすべて一致し、0.02 を超える唯一のものは blend-6 の 1 ポーズです（0.10 ピクセル。感度も 0.10。そのメッシュのこのときの不透明度は 3e-5）。

## ソフトウェアレンダリング

`p2l_render`（ABI 1.3）は、直近の評価を、ホストが与えた RGBA8 画像へ描きます。規則は参照ラスタライザ `SoftwareRasterizer` と同じです。双線形のプリマルチプライドサンプリング、ピクセル中心と左上の規則、テクスチャ alpha によるマスク（反転を含む）、隔離グループのレイヤー、すべての色と透明度の合成モード、カリングです。変換はキャンバスから画像へのアフィンです（空ポインタのときは、キャンバスを等比で画像の左上に入れる）。出力はプリマルチプライドまたはストレート alpha で、既存の内容の上に描けます。埋め込み PNG のテクスチャページは、ランタイム同梱のデコーダが解きます（非インターレース、すべての色の種類）。KTX2 と外部ファイルのページは、ホストが `p2l_render_texture` でピクセルを提供します。自前のレンダラを持たないホスト（C/C++、エンジンプラグイン、サムネイルと検証）向けで、ピクセルごとに CPU 上で動きます。検証：`SoftwareRenderParityTest` は、90 種の合成の組み合わせ、隔離グループ（チャンネル駆動の不透明度と色、メッシュとパーツのマスク、反転、入れ子）、マスク、乗算 / スクリーン色、カリングを覆うモデル上で、3 つのポーズと拡大縮小について参照ラスタライザとピクセルごとに比較し、最大チャンネル差は 1/255 以下です。conjoint の重なりウェイトを故意に間違えると、そのテストは 77/255 の差を報告します。

## ウェブプレーヤー

書き出し先 `web` は、そのまま配置できるフォルダを書きます。`index.html`、`p2l.js`（ES モジュール `P2LPlayer`）、`p2l_runtime.wasm`、モデルです。プレーヤーは WebGL で描き、ヘッダの合成規則に従って、すべての色と透明度のブレンドの組み合わせと隔離グループを描きます。通常（over）と Cubism の加算、乗算はブレンド関数を使い、残りの組み合わせは、まずメッシュのバウンディングボックス内の下層をテクスチャへコピーし、シェーダで合成します。隔離グループは `p2l_render_commands` に従ってレイヤーへ描き、閉じるときにグループのモード、不透明度、乗算 / スクリーン色、マスクで合成します。マスクはステンシルバッファを通ります（テクスチャ alpha 0.5 で切り抜き、反転に対応）。カリングをオンにしたメッシュは表面だけを描きます。`WebPlayerCheckTool`（`PSD2LIVE_TOOLS=1`）は、90 種の組み合わせと 16 種の隔離グループを覆うモデルと、ピクセルごとの参照画像を生成します。Edge（ヘッドレス）では参照との差が最大 1/255 です。ページはモーションと表情の選択、口形のスライダーを提供し、視線はポインタに従い、クリックするとそのクリック領域を表示します。ファイルに高度なモードのデータがあるとき、ページはスイッチを提供します。WebAssembly ビルドはリソースとしてリポジトリに同梱します。ランタイムを変更したあとは `./gradlew :targets:web:updateWasm` で更新します（`rustup target add wasm32-unknown-unknown` が必要）。単体テストは、プレーヤーが呼ぶ各関数を、そのビルドがエクスポートしていることを照合します。tml サンプルは Edge（ヘッドレス）で正しく表示されます。

## Godot

`runtime/godot/` は `cargo build --release` でビルドします。`P2LCharacter` のプロパティとメソッドは、その README を参照してください。ノードはヘッダの描画規則に従って描きます。各メッシュは自分のキャンバス項目の中で `render_commands` の順に並び、テクスチャは読み込み時にプリマルチプライドし、シェーダが乗算 / スクリーン色、不透明度、マスクの被覆を掛けたあと、色と透明度の合成モードで合成します。通常+over、Cubism の加算 / 乗算（任意の透明度モード）、out はハードウェアブレンドを使い、残りは下の色を読んでシェーダで計算します。隔離グループは、内容を対象ビューポートと同じサイズのオフスクリーンビューポート（レイヤー）へ描き、グループの位置で、グループのブレンドモード、透明度モード、不透明度、乗算 / スクリーン色、マスクにより合成します。入れ子にできます。Forward+ と Mobile のバックバッファコピーは alpha を失うため、レイヤー内で下を読む各項目は、それぞれビューポートを 1 つ使い、それまでのレイヤー内容を先にコピーしてから読みます。グループの外は画面を読み、下は不透明として扱います（透明ウィンドウでは近似）。マスクは被覆ビューポートへ描きます（各ビューポートにマスク 3 組）。メッシュとレイヤーは自分のピクセルで被覆を読み、反転マスクは 1 − 被覆を取ります。同じ組のマスクが重なるところでは alpha を足します（参照は最大値）。カリングをオンにしたメッシュは、表面の三角形だけを提出します（キャンバス座標で (b − a) × (c − a) < 0）。マスクはカリングしません。`RuntimeSamplesTool` の特性モデルは、Godot でソフトウェアラスタライザの参照画像と一致します（差は 2/255 以下。反転マスクを含む）。`GodotLayerSamplesTool`（`PSD2LIVE_TOOLS=1`）は、すべての色×透明度の合成モード（不透明な背景の上と、隔離グループの中）、およびグループの色、不透明度、ブレンドモード、メッシュ / パーツのマスク、反転マスク、入れ子を覆う単色モデルと期待値を生成します。Godot 4.7 では、Forward+、Mobile、Compatibility の各サンプル点の差が 1.2/255 以下です。検証：デモプロジェクトの `smoke_test.gd` は、ヘッドレスでモデルを読み込み、1 秒進めます。`--shot` はウィンドウで 1 フレームをレンダリングし、tml と ds のサンプルは正しく表示されます。
