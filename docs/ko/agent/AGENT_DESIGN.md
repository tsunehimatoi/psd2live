# Agent 설계와 검수

[문서 목록](../README.md) · [MCP 인터페이스](MCP_AUTHORING.md) · [능력 실측](../STATUS.md) · [로드맵](../ROADMAP.md)

이 페이지는 Agent/MCP 연결의 설계 경계와 검수 방식을 설명합니다. 구체적인 인터페이스 계약은 [MCP 인터페이스](MCP_AUTHORING.md)와 서비스 런타임 Schema를 기준으로 합니다.

---

## 1. 역할 분담

| 역할 | 책임 |
| --- | --- |
| **외부 Agent** | 사용자 의도를 이해하고, 대상 오브젝트를 고르며, 도구 호출과 관찰 결과를 계획합니다(이미지 생성은 호스트가 제공합니다) |
| **PSD2Live** | 결정적인 소재, 메시, 파라미터, 물리, 시뮬레이션, 분기 히스토리 조작을 실행합니다 |
| **모델러** | 아트 스타일, 효과의 취사선택, 최종 검수를 결정합니다 |

---

## 2. 핵심 설계 경계

- **통일된 명령 채널**: GUI와 MCP는 같은 애플리케이션 층 명령(`WorkspaceHost`)을 씁니다. 둘 다 캡처한 시작 `state` 위에서 후보를 준비하고, CAS로 히스토리 노드 하나를 제출합니다. 렌더 스냅샷만 바꾼 수정은 다시 구축하거나 다시 열면 사라집니다.
- **안정적인 신원 참조**: 모든 오브젝트는 결정적 ID로 참조합니다. 표시 이름을 식별자 대신 쓰지 않습니다.
- **동시성과 히스토리**: `state`는 낙관적 동시성 제어에 씁니다. 히스토리는 추가만 하고 고치지 않습니다. 이전 노드를 체크아웃해 계속 편집하면 분기가 됩니다.
- **저작 자세 분리**: 미리보기 자세(`preview_set/reset`, 슬라이더 드래그, 자동 키프레임)는 `WorkspacePoseCommands`의 보조 CAS를 타며, Rig 편집 히스토리를 더럽히지 않습니다.
- **소재와 분할이 같은 출처**:
  - 이미지 가져오기와 정합은 독립 세션에서 준비한 뒤 소재 목록으로 제출합니다.
  - 연결 덩어리/다각형 분할(`source_split_components` / `source_split_polygon`)과 깊이 가림 분할(`source_split_depth`)은 GUI와 같은 애플리케이션 층 명령을 씁니다. 같은 원자적 일괄에서 새 레이어를 계속 편집할 수 있도록 프리셋 ID를 지정할 수 있습니다.
- **엄격한 출력 계약과 오류**: 공개 조작은 모두 `request` / `outputSchema`를 선언합니다(백그라운드 작업은 종단 `jobResultSchema`도 포함합니다). 실패는 구조화된 오류 코드와 충돌 컨텍스트를 통일해 돌려줍니다. 작업 조회가 성공해도 업무가 성공한 것은 아니며, 종단 `status`를 확인해야 합니다.
- **요약 우선 관찰**: 조회는 요약을 먼저 돌려주고, 그다음 대상과 페이지로 펼칩니다. 미리보기 스크린샷은 고정된 캔버스 카메라를 쓰며, 원본 소재, 합성 미리보기, 런타임 모델을 분명히 구분합니다.

---

## 3. 작업 검수 항목

1. **사전 확인**: 프로젝트 `state`, 대상 오브젝트 ID, 의존 레이어를 확인합니다.
2. **일괄과 시험 실행**: 연관된 여러 수정은 `workspace_preview_edits`로 먼저 시험 실행한 뒤, `workspace_apply_edits`로 원자적으로 제출합니다.
3. **재생과 영속**: 수정 뒤에 실행 취소/다시 실행이 되는지 확인하고, `.psd2live` 프로젝트를 저장한 뒤 다시 열어도 결과가 같은지 확인합니다.
4. **시각과 내보내기 재확인**: 미리보기 스크린샷으로 여러 파라미터 자세를 맞추고, 대상 형식으로 내보낸 뒤 `.psd2live.json` 손실 보고서를 확인합니다.
