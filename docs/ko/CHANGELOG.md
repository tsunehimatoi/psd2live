# 변경 이력

[문서 목록](README.md) · [다운로드](https://github.com/tsunehimatoi/psd2live/releases)

사용자가 느낄 수 있는 변화만 기록합니다. v1.4.2 이전 버전은 [Releases](https://github.com/tsunehimatoi/psd2live/releases)를 참조합니다.

## v3.8.4 · 2026-11-21

### 개선과 수정

- **PSD 다시 불러오기**: 「모델 > PSD 다시 불러오기」를 추가했습니다. 원본 그림을 수정한 뒤 프로젝트 안의 레이어 텍스처를 바로 갱신하면서, 이미 있는 리그, 프로젝트 파일, 실행 취소 히스토리를 유지합니다. 필요하면 메시를 자동으로 다시 만들고 변형, 가중치, 경로 바인딩을 옮깁니다.([#97](https://github.com/tsunehimatoi/psd2live/pull/97))
- **완전한 픽셀 메시 덮기**: 선택적 메시 설정을 추가했습니다. 투명하지 않은 모든 픽셀(alpha > 0)을 덮어, 페더 가장자리, 약한 발광, 가는 머리카락이 메시 경계에서 잘리는 일을 피합니다.([#96](https://github.com/tsunehimatoi/psd2live/pull/96))
- **변형과 파라미터 편집**: 곡면 디포머가 정점과 베지에 두 편집 계층을 동시에 켤 수 있어, 전환 없이 함께 미세 조정합니다. 제어점, 핸들, 변형 상자를 끌 때 `Shift`를 누르면 주축 이동을 잠급니다. 중간 자세를 편집할 때 가장 가까운 키폼에 자동으로 붙고 안내하며, 모디파이어 블렌드 셰이프 덮어쓰기 편집과 컴포넌트 키폼 강조를 지원합니다.([#81](https://github.com/tsunehimatoi/psd2live/pull/81), [#94](https://github.com/tsunehimatoi/psd2live/pull/94), [#95](https://github.com/tsunehimatoi/psd2live/pull/95))
- **히스토리와 레이어 수정**: 실행 취소, 다시 실행, 히스토리 전환 때 현재 파라미터 자세를 유지하고, 더 이상 기본값으로 초기화하지 않습니다. 분할한 레이어를 삭제한 뒤에도 보이는 레이어 분석에 남던 문제를 수정했습니다.([#92](https://github.com/tsunehimatoi/psd2live/pull/92), [#93](https://github.com/tsunehimatoi/psd2live/pull/93))
- **화면 정리**: 시작 페이지와 접을 수 있는 도움말/설정 사이드바를 통일하고, 벡터 아이콘 그리기와 드롭다운의 적응 너비를 개선했으며, 변형 도구 옵션을 더 촘촘한 드롭다운으로 모았습니다.

## v3.8.3 · 2026-11-19

### 개선과 수정

- **PSD 가져오기 마법사**: 프로젝트를 만들기 전에 끊긴 메시를 미리보고 나누고, 레이어 바인딩을 확인하고, 모디파이어 프리셋을 고르고, 머리 회전 스타일을 비교할 수 있습니다. 만들 때 들어갈 작업 공간을 바로 고를 수 있습니다.
- **머리와 입 리그**: 머리 회전이 화면의 이목구비와 머리카락에 더 붙습니다. 캔버스에서 자동 생성한 입 벌림 키폼을 편집하고, 다문 입 소재의 투명도 곡선을 따로 조정할 수 있습니다.
- **시뮬레이션과 가중치**: 정점 가중치를 칠하고, 물리 시뮬레이션을 키폼에 바로 베이크할 수 있습니다.
- **VTube Studio 내보내기**: 내보낼 모델의 아이콘을 고르고, 프로젝트의 모션과 표정 이름을 사용합니다. 화면 버튼을 할당하지 않은 핫키는 `ScreenButton: -1`로 쓰며, 이전 내보내기가 표정 편집기를 열지 못하게 하던 문제를 수정했습니다.([#90](https://github.com/tsunehimatoi/psd2live/issues/90))
- **데스크톱 호환**: Linux 패키지 애플리케이션의 시작과 작업 프로세스 문제, Windows 중국어 경로 인코딩, macOS 패키지 버전의 명령줄 내보내기 작업 디렉터리를 수정했습니다.

## v3.8.2 · 2026-11-18

### 개선과 수정

- **입 자동 리그**: 숨은 입 모양과 구강 마스크 선택을 개선하고, 위아래 입술의 독립 변형을 더 세밀하게 해, 입을 다물 때의 입술선 틈과 입꼬리 떨림을 줄입니다.
- **모디파이어와 프리셋**: 모디파이어를 적용할 때 이미 편집한 내용을 유지하고, 의존 순서대로 갱신합니다. 프리셋 선택과 편집의 저장을 수정하고, 모디파이어 하나가 실패해도 다른 사용 가능한 결과를 남깁니다.
- **시작 페이지와 가져오기**: 시작 페이지의 만들기, 열기, 최근 프로젝트 진입점을 다시 정리하고, 가져오기 프리셋을 유지하며, PSD 썸네일의 투명 표시를 수정했습니다.

## v3.8.1 · 2026-11-17

### 개선과 수정

- **PSD 가져오기와 플러그인 격리**: 불규칙한 PSD 입력의 내성을 높였습니다. 모디파이어 하나가 실패하면 그 오류 정보를 남기고 의존을 격리하며, 다른 사용 가능한 기능은 계속 실행됩니다.
- **눈썹과 변형 정밀도**: 눈썹 형태, 깜빡임, 탄성 리그를 조합할 때의 호환 문제를 수정하고, 큰 캔버스에서 변형 역행렬 정밀도를 높였습니다.
- **눈 원근 마스크**: 앞머리에 이미 자르기가 있으면 원 마스크를 유지하고 눈 원근을 올바르게 겹칩니다. 조합 마스크를 지원하지 않는 내보내기 대상은 기능 손실을 보고합니다.
- **사용자 정의 플러그인 개발**: 플러그인 템플릿, 빌드, 파라미터 설정, 실행 취소할 수 있는 코드 갱신을 지원하고, 의존 잠금과 이전 빌드 산출물의 다시 로드 호환을 수정했습니다.
- **데스크톱 호환**: Linux 창 이동과 파일 선택기 호환을 개선하고, 투명 배경 세션이 실패한 뒤의 복구를 수정했습니다.

## v3.8.0 · 2026-11-15

### 새로운 기능

- **모디파이어 메뉴와 충돌 안내**: 모디파이어 스택과 프리셋 추가 메뉴를 재구성해, 분류, 기초 항목, 상세의 세 열로 단계적으로 펼칩니다. 모디파이어 스택과 추가 메뉴에서 하드 충돌과 소프트 충돌을 표시해, 서로 배타적인 효과를 잘못 겹치지 않게 합니다.
- **부위 플러그인의 중첩 설정과 동작 미리보기**: 접힌 부위 플러그인이 인스펙터에서 하위 기능 설정을 펼치고 동작을 실시간 미리보게 합니다. 부위를 재설정하면 상속 속성도 함께 정리합니다.

### 개선

- **프리셋과 용어 통일**: 「스타일화」 등 알고리즘 용어와 프리셋 이름을 통일하고, 기본 프리셋 설정을 조정했습니다(기본은 변위를 끄고, 치마 자락과 찌그러짐 등 선택 모듈을 구분).
- **원본 PSD 리그와 내보내기 일치**: 메시 분할을 `mesh.split` 모디파이어 플러그인에 넣고, `.cmo3` 내보내기와 읽기의 분할 메시 참조를 유지합니다. 한쪽 눈, 층을 나눈 입(혀 내밀기, 치아궁, 입술선), 짐승 귀/꼬리/날개의 원본 PSD 리그와 내보내기를 다듬었습니다.
- **미리보기 응답과 캐시 성능**: 국소 범위 빌드 계획과 유한 캐시를 도입해, 모디파이어 편집 때의 반복 재구축 비용을 줄이고, 미리보기 첫 프레임과 저장 상태가 정확히 맞게 합니다.

## v3.7.1 · 2026-11-11

### 새로운 기능

- **macOS 앱**: macOS 13 이상은 `./gradlew packageDmg`로 DMG를 만들 수 있습니다. 앱은 Swift 껍질이고, 안에는 기존 편집기가 있으며 Java 런타임을 함께 둡니다. 메뉴는 화면 위에 있고, 창 버튼은 시스템의 것이며, 앱 막대는 시스템 제목 표시줄에 그려집니다(신호등, 메뉴, 파일 이름이 한 줄). 저장하지 않은 프로젝트는 닫기 버튼에 표시됩니다. 패키지 아키텍처는 그것을 빌드한 Mac과 같습니다(Apple 칩 또는 Intel). 공증은 없으며, 네트워크에서 받은 뒤 Finder에서 오른쪽 클릭으로 연 다음 “응용 프로그램”으로 끌어 넣습니다.
- **레이어 이름의 좌우 표시**: ">"는 캐릭터의 왼쪽, "<"는 캐릭터의 오른쪽이며, 다른 좌우 단어가 놓일 수 있는 자리에 둘 수 있습니다(전각 ＞ / ＜ 도 가능).

### 개선

- **생성되는 대기, 끄덕임, 고개 흔들기**: 대기 호흡을 빠르게 들이쉬고 천천히 내쉬며, 사이에 한 박을 비우고, 머리가 호흡마다 같은 길을 가지 않습니다. 자연 동작에서 시선은 머무를 때 약간 흐르고, 돌아올 때 조금 지나치며, 눈썹은 호흡에 따라 오르내립니다. 끄덕임은 먼저 살짝 고개를 들고, 빠르게 숙인 뒤 천천히 들며 조금 지나치고, 몸은 늦게 도착하며, 숙일 때 눈을 가늘게 뜹니다. 고개 흔들기는 양쪽 끝에서 감속하고, 뒤쪽 진폭이 더 작으며, 좌우 간격도 같지 않습니다. 이미 키프레임을 손으로 고친 모션은 그대로 둡니다.

## v3.7.0 · 2026-10-27

### 새로운 기능

- **영역으로 나눈 Rig 모듈**: 자동 생성 Rig를 눈, 눈썹, 입, 머리, 머리카락, 몸, 의상, 표정, 모션 등의 영역으로 나누고, 각 영역은 기초 방안을 고르고 모듈을 겹칠 수 있습니다. 새 프로젝트는 기본적으로 현대 방안을 쓰고 적용 가능한 모듈을 모두 켜며, 프리셋과 비용 예산이 있습니다.
- **그린 눈과 눈썹에 맞춤**: 눈꺼풀은 흰자 윤곽과 감은 눈 선으로 만들고, 머리가 기울거나 돌 때 얼굴을 따라 눈을 감습니다. 눈썹은 호를 따라 돌며 위 눈꺼풀을 이끌고, 앞머리에 가려지면 눈꺼풀이 감정을 표현합니다.
- **단계적으로 벌어지는 입**: 입은 위아래 입술 가장자리를 따라 단계적으로 벌어지며, 모음, 얼굴 캡처, 턱, 오므림 / 벌림을 포함합니다. 층을 나눈 화법(위아래 입술, 입술선, 이, 구강)으로 그린 입을 지원하고, 이와 혀는 입술과 함께 움직이며, 화면 밖으로 벌어져 소리 지를 수 있습니다.
- **머리의 깊이 회전**: 머리는 원기둥을 따라 돌고, 이목구비, 앞머리, 뒷머리, 귀가 서로 다른 깊이에 있으며, 끝까지 돌면 먼 쪽 구레나룻이 얼굴 뒤로 갑니다.
- **머리카락, 의상, 몸의 체인 스윙**: 머리카락은 구간마다 진자 체인처럼 흔들립니다. 치마, 리본, 매달린 장식, 짐승 귀, 꼬리, 날개가 체인으로 흔들립니다. 가슴이 튀고, 팔이 흔들리며, 목이 머리 기울임을 나눕니다.
- **표정과 자연 동작**: 볼터치, 침울 등의 감정 파라미터를 추가하고, 표준 표정을 더 풍부하게 했습니다(수줍음, 졸림, 침울 추가). 자연스러운 깜빡임과 시선 이동. 모듈 Rig에 맞춰 조정한 VTube Studio 매핑.
- **특징점 도구**: `Shift+Y`가 캔버스에 눈, 눈썹, 입의 제어점을 표시하고, 끌면 다시 맞추며 모든 자세가 따라 변합니다. Alt 클릭은 되돌립니다.

### 개선

- 얼굴의 볼터치, 그림자, 앞머리 투영이 얼굴에 잘려, 고개를 돌릴 때 얼굴 밖으로 나가지 않습니다.
- 작업 공간 탭 드래그가 더 매끄럽고, 끝까지 끌 수 있습니다.

### 호환

- 이전 프로젝트는 이전 방안으로 생성되며, 결과는 이전과 바이트 단위로 같습니다. 안내에서 모듈 Rig로 업그레이드할 수 있습니다.

## v3.6.7 · 2026-10-24

### 새로운 기능

- **그래픽 설정 페이지**: 설정에 「그래픽」을 추가했습니다. 렌더 경로(GPU / 소프트웨어 캔버스 / 소프트웨어), 그래픽 카드 선택, 화질 프리셋, 창과 캔버스 안티앨리어싱(MSAA, SSAA), 텍스처 필터, 수직 동기화, 미리보기와 백그라운드 프레임률 등.
- **MCP가 편집기의 제스처 하나를 한 번에 수행**: 눈금자 보조선 읽기·쓰기, 레퍼런스로 가져오기, 표정 미리보기, 소프트 선택 변형, 대칭 획 등. 거부 이유를 구분할 수 있고, 쓴 내용을 다시 읽을 수 있습니다.

### 개선

- **설정 페이지 배치**: 펼친 제목과 두 열 행으로 바뀌었고, 더 이상 카드를 쓰지 않습니다.
- **GPU 캔버스가 더 절약**: 프레임마다 하는 일이 줄었고, 드래그할 때 도구 막대와 상태 막대를 반복 재구성하지 않습니다.
- **저장이 더 빠름**: 작은 프로젝트 저장이 약 3분의 1 빨라졌고, 아카이브 내용은 변하지 않습니다.

### 수정

- Linux에서 편집 캔버스가 GPU 그리기를 회복했고, 더 이상 프레임마다 건너뛰지 않습니다. 복구 안내가 빈 채로 멈추지 않습니다(#62).
- 편집 캔버스의 마스크, 곱하기 / 스크린 색, 각종 블렌드 모드가 미리보기와 일치합니다.

## v3.6.6 · 2026-10-24

### 새로운 기능

- **자유 변형 선택 영역**: 페인팅 모드의 자유 변형(`Alt+T`, 페인팅 모드에서 `T`)이 선택 영역 픽셀(선택 영역이 없으면 레이어 전체)을 변형 상자에 넣고, 이동, 확대·축소, 회전할 수 있습니다. Enter는 한 획으로 적용하고, Esc는 되돌립니다.

### 개선

- **편집기와 Agent가 동시에 편집**: 작업 공간은 런타임을 유일한 권위로 두고, 편집기의 제출하지 않은 수정이 Agent의 제출을 만나면 필드별로 양보하고 나머지는 평소처럼 제출합니다. 저장되는 것이 실제 상태입니다.
- **스크린 블렌드**: PSD의 스크린 레이어는 Cubism 5.3의 Screen으로 내보내고, 더 이전 버전은 가산으로 근사하며 손실 보고서에 기록합니다. 색, 투명도, 그리기 순서의 생성 결과 덮어쓰기도 유지됩니다.
- **창 모드**: 설정 → 표시에서 창, 최대화, 전체 화면을 고르고 기억합니다. `F11` 또는 「보기 → 전체 화면」으로 전체 화면을 전환합니다. 최대화가 더 이상 작업 표시줄을 덮지 않습니다.
- **새 화면 스타일**: 패널이 창 배경 위의 둥근 카드가 되고, 간격이 더 촘촘합니다. 제목 표시줄 메뉴, 드롭다운, 오른쪽 클릭 메뉴가 같은 불투명 유리 메뉴 스타일로 통일됩니다.

### 수정

- 자동 생성한 입술선을 그릴 때 입 레이어와 입 설정에서 온다고 설명하고, 더 이상 「원본 레이어를 찾을 수 없음」을 보고하지 않습니다. 파라미터 이름을 오른쪽 클릭하면 선택한 메시나 디포머와의 바인딩을 해제할 수 있습니다(#55).
- 저장한 창 크기가 화면의 사용 가능 영역 안으로 제한되고, 제목 표시줄이 더 이상 화면 밖으로 나가지 않습니다.
- 큰 캔버스에서 메시에 디포머를 새로 만들거나, 본을 옮기거나, 루트 메시 전체를 압축할 때 퇴화나 재생성 충돌을 잘못 보고하지 않습니다(#56, #59).

MCP에 `reference_set_mode`, `layout_add_reference`, `layout_order_reference`, `layer_pin_reference`, `reference_place_grid`, `view_render_pad`를 추가했습니다.

### 개선

- **Layout은 먼저 편집하고, 그다음 생성**: 아직 생성하지 않았거나 생성 대기 레이어가 있는 Layout 프로젝트에서, 레이어가 캔버스에 들어오면 정식 메시가 있어 메시, 디포머, 파라미터, 계층을 편집할 수 있고 바로 내보낼 수도 있습니다. 빈 캔버스나 레퍼런스 레이어만 있는 프로젝트도 생성할 수 있습니다. 생성할 때 이미 있는 메시 토폴로지를 고정하고 손 편집을 삼자 병합하며, 그림을 교체한 레이어는 여전히 새 픽셀로 다시 만듭니다.
- **편집 캔버스와 파라미터 드래그가 더 매끄러움**: 편집 캔버스를 창 컴포지터가 따로 그리며, 포즈를 잡거나 가리키거나 정점을 끌 때 이 층만 다시 그립니다. 파라미터 슬라이더 드래그와 포즈를 표시하지 않는 패널은 더 이상 프레임마다 포즈에 따라 재구성되지 않고, 복구 점은 손을 뗄 때만 한 번 기록됩니다.
- **소재 패널**: 소재 썸네일이 사용량을 표시하고, 가리키면 그것을 쓰는 레이어와 ArtMesh를 나열합니다. 오른쪽 클릭으로 태그를 편집하고, 「기본으로 레퍼런스 레이어에 배치」로 설정하고, 그것을 쓰는 레이어를 선택할 수 있습니다(여러 개면 레이어별로 나열). 빈 곳을 오른쪽 클릭하면 폴더 만들기, 가져오기, 그리드 / 목록 / 트리 뷰 전환을 할 수 있습니다.
- **내부 조형 패널**: 다른 인스펙터와 같은 도구 막대와 접히는 구역으로 바뀌었고, 시험 동작은 파라미터 패널과 같은 슬라이더와 2D pad가 되었으며, 편집 결과와 실패는 아래 작업 지시에 표시됩니다. 전동 방향은 그린 화살표 칩으로 바뀌었고, 새로 만든 국소 주름은 자동으로 `fold<n>` 번호를 받습니다.
- **로그와 멈춤 진단**: 화면 버전이 콘솔 출력을 로그 파일에 씁니다(`psd2live.log`, 이전 실행을 남기고, 앞에 버전, Java, 시스템을 기록). 화면이 5초 넘게 멈추면 모든 스레드 스택을 로그에 한 번 쓰고, 회복하면 한 줄을 더 기록합니다(#52).
- **PSD 가져오기 준비가 화면 스레드에서 분리**: PSD를 가져올 때 소재 등록과 초기 히스토리 준비가 백그라운드에서 끝나고, 화면 스레드는 마지막 게시만 합니다(#50).
- **오른쪽 클릭 메뉴가 더 명확**: 계층 트리에서 접힌 체인을 삭제할 때 「현재 디포머 삭제」와 「체인 전체 삭제」를 구분하고, 다중 선택 중 한 항목을 오른쪽 클릭하면 조작이 이 항목에만 작용한다고 적습니다. 소재의 「그것을 쓰는 레이어 선택」은 여러 레이어가 참조할 때 각 레이어를 골라 고르게 나열합니다. 주 캔버스에서 오른쪽 클릭에 묶인 명령이 우선 실행되고, 메뉴가 먼저 열리지 않으며, 아틀라스와 같습니다.
- **파라미터 이름 오른쪽 클릭 메뉴**: 파라미터 이름을 오른쪽 클릭하면 속성을 바로 열고, 현재 값을 재설정하고, 잠그거나 풀고, 파라미터를 복사하고, 파라미터 ID를 복사하거나 파라미터를 삭제할 수 있습니다. 왼쪽 클릭은 여전히 속성을 엽니다.

### 수정

- **MOC3 사용자 데이터**: 사용자 데이터 내보내기를 선택하면 `userdata3.json`을 씁니다(쓴 ArtMesh ID로 항목을 만듦). `model3.json`이 참조를 동기화합니다. 사용자 데이터가 하나도 없으면 그 파일을 쓰지 않습니다.
- **가져온 그림과 레퍼런스 레이어의 텍스처**: 새 레이어와 레퍼런스 레이어의 생성 기록이 현재 픽셀로 텍스처 목록을 만들며, 더 이상 1×1 자리 표시 타일에 묶이지 않습니다. 레이어 안의 레퍼런스는 캔버스에 들어오는 즉시 네 점 사각형 메시입니다.
- **레퍼런스 레이어 그리기 위치**: Layout의 레퍼런스 레이어가 자신의 캔버스 사각형으로 그려지며, 더 이상 캔버스 위쪽으로 미러되지 않습니다.
- **미리보기 런타임의 확장 시뮬레이션**: p2lrt 고급 모드가 단계별로 시뮬레이션을 진행하고, 컴파일이 끝난 상태와 일시 정지 뷰도 갱신되며, 연속 다시 그리기가 더 이상 번쩍 되돌아가지 않습니다. 적용할 확장이 없거나 확장 시뮬레이션에 물리를 켜야 하면, 상태 캡슐에 이유를 설명합니다.
- **그래픽 카드 폴백**: Skiko가 렌더러를 교체하거나 잃으면 GPU를 다시 해석하고 폴백하며, 소프트웨어 그리기로 전환한 뒤에도 레이어 캐시를 유지합니다.

- **제목 표시줄 메뉴 정리**: 메뉴는 파일, 보기, 모델, 도움말입니다. 「도구」는 「모델」로 바뀌어, 모델 전체에 작용하는 조작을 모았습니다(PSD 다시 분석, CMO3로 교체, 메시로 레이어 분할, 텍스처 고해상도화, 생성 결과 업데이트). 「파일 → 가져오기」는 「파일 → 새로 만들기」로 바뀌었습니다. 시작 페이지는 「파일」 메뉴에만 남습니다. 「보기」의 화면 확대 비율과 글꼴 크기는 설정 페이지로 넘겼습니다. 설정은 제목 표시줄 오른쪽 톱니바퀴가 되어 언어와 밝기 테마 옆에 있습니다. 밝기 테마 버튼은 사이드바 스위치의 색을 씁니다. 「도움말」 메뉴는 두 항목만 남습니다. 「도움말」은 도움말 페이지를 열고, 「온라인 자료」는 GitHub 저장소, 문서, 예제 저장소, 릴리스, 문제 보고를 엽니다. 도움말 페이지에 「예제」(예제 저장소의 내용과 사용법, 기고 입구)와 「서드파티 라이선스」(사용 구성 요소, 라이선스, 용도)를 추가하고, 레이어 사양에 소재 준비, 앞뒤 머리카락, 좌우 설명을 보충했으며, 링크와 정보 페이지 문구도 함께 갱신했습니다.
- **시작 작업 공간**: 시작은 더 이상 가져온 뒤의 팝업이 아니고, 작업 공간 탭 막대 맨 왼쪽의 고정 「시작」 페이지입니다. 시작할 때 표시되고, 프로젝트를 열거나 새로 만든 뒤 자동으로 넘어가며, 언제든 다시 누를 수 있습니다. 배치는 편집기 패널과 같고, 구분선을 끌어 크기를 조절합니다. 왼쪽 탐색(프로젝트 열기 / 최근 / PSD에서 생성 / 배치 프로젝트 / CMO3에서 가져오기 / 빠른 시작 / 기능 업데이트). 열 때는 「최근」에 있고(최근 파일이 아직 없으면 「PSD에서 생성」), 소재 패널처럼 최근 파일을 나열합니다. 배치 프로젝트에는 NEW 표시가 있고, 가운데는 내용, 오른쪽 속성 패널은 곧 일어날 일을 설정하며, 아래 조작 막대에 눈에 띄는 주 버튼이 있습니다(Enter로도 실행). 원클릭 생성은 여전히 한 단계입니다. PSD를 가져오기 전에 속성 패널에서 프리셋을 고른 뒤, 창의 아무 곳으로 끌어 넣거나 최근 PSD 필름 스트립에서 두 번 클릭하면 그 프리셋으로 생성하고 편집으로 들어갑니다. 한 번 클릭하면 뷰포트에서 미리봅니다. 프로젝트를 연 뒤 「시작」 탭이 애니메이션으로 접히고, 「파일 / 도구 → 시작 페이지」에서 다시 열 수 있습니다. 배치 프로젝트는 비율대로 캔버스 크기를 미리보고, 자주 쓰는 크기를 두 번 클릭하면 바로 만듭니다. 최근 파일은 그리드나 목록으로 보고 거를 수 있으며, 썸네일, 수정 시각, 크기를 표시합니다. 프로젝트를 저장할 때 파일에 썸네일 한 장을 함께 두고, PSD는 내장 썸네일이나 합성 그림을 읽습니다. 원래 빈 캔버스에 그리던 내용은 여기로 옮겼고, 빈 캔버스에는 안내 한 줄과 「시작으로 이동」만 남습니다. 메시로 레이어 분할은 「도구 → 메시로 레이어 분할…」로 바뀌었습니다.
- **창 없는 MCP**: `psd2live mcp`가 더 이상 백그라운드에서 편집기 화면 전체를 만들지 않고, 작업 공간을 애플리케이션 층 호스트가 직접 받습니다. 창이 없어도 `view_sample_motion`이 모션을 샘플링할 수 있습니다(이전에는 시간 초과까지 기다림). 시작할 때 `capabilities`를 출력해 사용 가능 여부를 설명합니다.
- **파츠 벗기기(MCP)**: `material_peel`은 어떤 파츠를 뺀 생성 그림으로 그림에서 파츠를 벗겨, 파츠와 그 아래 그림을 얻습니다. 파츠 밖은 원본 픽셀을 유지하고, 다시 겹치면 원본 그림입니다. `material_set_placement`는 외부에서 생성한 고해상도 그림이 클로즈업 위치를 잡게 합니다. `keep`는 파츠 위의 점으로, 생성 모델이 곁들여 바꾼 잔점을 제거합니다. `compare_scale`은 더 작은 크기로 생성한 뒤 확대한 그림을 생성 크기로 비교하게 합니다. `mcp_proxy.py`는 명령줄이나 Python 스크립트에서 조작을 바로 호출할 수 있습니다. 짝이 되는 ComfyUI 도구는 독립 브랜치 `comfy-tools`에 있습니다.
- **소재 라이브러리**: 소재 패널을 추가했습니다. 그림, PSD, CMO3 안의 레이어 그림, SVG를 가져와 폴더로 정리하고, 태그를 달고, 미리보고, 폴더를 PSD로 내보낼 수 있습니다. 소재는 프로젝트와 함께 저장되고, 수정은 실행 취소할 수 있습니다. 가져온 PSD 레이어도 소재 라이브러리에 나타납니다.
- **먼저 배치하고, 그다음 생성**: 시작 페이지의 「배치」 모드(또는 「파일 > 가져오기 > 새 Layout 프로젝트」)가 빈 캔버스에서 시작해, 소재를 캔버스에 끌어 배치한 뒤 Rig를 생성합니다. 생성한 뒤 그림을 더하고 태그를 바꾼 다음 「다시 생성」으로 합치며, 이미 있는 키폼, 디포머, 물리, 스켈레톤 등의 편집은 남습니다. Layout 작업 공간과 「소재와 배치」 튜토리얼을 추가했습니다.
- **의미 태그**: 레이어 표의 「유형 / 파츠 / 좌우」가 태그로 바뀌어, 부위와 좌우를 조합하고 자신의 태그도 더할 수 있습니다. 차분은 별도 칸입니다.
- **소재로 그림 교체**: 교체한 뒤 레이어의 캔버스상 위치와 크기는 변하지 않습니다.
- **소재 창**: 소재를 두 번 클릭하면 독립 창에서 보고, 확대·이동할 수 있으며, 브러시, 연필, 지우개, 페인트통, 스포이드로 바로 수정하거나, 뒤집고, 색상·채도·명도·대비를 조절합니다. 이미 배치한 레이어가 함께 갱신됩니다. 소재 패널은 간소한 폴더 트리를 남기고, 열 너비를 끌 수 있습니다. PSD / CMO3에서 가져온 폴더는 대응하는 파일 아이콘과 항목 수로 표시됩니다. 소재를 폴더, 트리, 경로 막대 위로 끌어 옮길 수 있습니다.
- **소재 창이 페인팅 모드를 직접 사용**: 도구 막대, 옵션 막대, 페인팅 세션 막대, 오른쪽 클릭 메뉴, 붓끝 표시, 단축키가 캔버스의 페인팅 모드와 같고, 획이 바로 표시됩니다. 적용한 뒤 한 단계의 히스토리로 소재에 기록하며, 그리는 동안 다른 내용을 평소처럼 편집할 수 있습니다.
- **소재가 연결 레이어의 유일한 출처**: 페인팅 모드에서 소재로 배치한 레이어를 그리는 것은 소재를 그리는 것이며, 그것을 쓰는 모든 레이어가 함께 갱신됩니다. 레이어 표는 사슬 표시로 연결된 레이어를 나타내고, 연결을 해제해 레이어를 독립시킬 수 있습니다.
- **소재 트리**: 트리에 폴더 안의 그림이 표시되고, 캔버스로 끌거나 두 번 클릭해 열 수 있습니다. 트리의 오른쪽 클릭 메뉴에서 폴더를 만들거나 가져올 수 있습니다. 소재를 한 번 클릭하면 바로 선택됩니다. 오른쪽 클릭 메뉴는 더 이상 설명 글을 표시하지 않습니다.
- **드롭다운 애니메이션 통일**: 떠 있는 막대의 드롭다운(예: 「생성」 옵션)이 모드 메뉴처럼 줄마다 나타나고, 강조가 포인터를 따라 미끄러집니다.
- **오른쪽 클릭 메뉴 통일**: 각 패널의 오른쪽 클릭 메뉴가 캔버스 오른쪽 클릭 메뉴와 겉모습과 애니메이션이 같고, 클릭한 곳에서 펼칩니다. 오브젝트 모드 캔버스 메뉴의 생성류 조작은 「만들기」 하위 메뉴로 모았습니다. 캔버스 메뉴에 「메시」(메시 다시 만들기, 독립 메시 분할, 앞뒤 분리)와 「소재」(소재 창에서 열기, 연결 해제) 하위 메뉴를 추가했습니다.

### 개선

- **긴 머리카락이 고개를 기울일 때 굽음**: 턱 아래 머리카락이 Angle Z로 고개를 기울일 때 점점 반대로 되돌아갑니다(새 조정 「긴 머리카락 고개 기울임 유지」, 기본 80%). 긴 옆머리와 뒷머리가 더 이상 묶음째 튕겨 나가 몸 아래 부분을 드러내지 않습니다.
- **레퍼런스 그림과 클로즈업**: 소재를 레퍼런스 그림으로 설정해 편집 캔버스 위에 겹칠 수 있습니다(오른쪽 클릭 메뉴에서 설정, 불투명도 조정, 지우기. 캔버스 오른쪽 아래 표시 스위치로 숨김). 레이어가 아니므로 생성과 내보내기에 참여하지 않습니다. 레퍼런스 그림에서 캔버스 영역으로 무손실 클로즈업 소재를 잘라 PNG로 내보낼 수 있고, 배치할 때 원래 위치로 돌아갑니다. 편집 캔버스에 「텍스처 밀도」 히트맵을 추가해, 레이어의 캔버스 단위당 텍스처 픽셀로 색을 칠합니다. MCP에 `layout_set_reference`, `material_crop`, `material_export_png`를 추가했고, `view_render_model`이 레퍼런스 그림, 차이, 텍스처 밀도를 겹칠 수 있습니다. `./gradlew run --args=mcp`로 창을 열지 않고 MCP 서비스만 시작할 수 있습니다.
- **벡터로 그리는 파츠**: MCP에 `material_draw`를 추가했습니다. 캔버스 좌표의 SVG로 파츠를 그리고, 지정한 텍스처 밀도로 렌더하며, 다시 그릴 때 이미 배치한 레이어가 따라 갱신되고 이동합니다. `layout_set_drawing_kit`는 모든 그리기가 공유하는 색, 선 스타일, 그라데이션을 정하고, 수정하면 모든 파츠가 함께 갱신됩니다. SVG는 클래스 스타일 규칙, 키트 색 변수, 양쪽이 가늘어지는 선(`data-taper`)을 지원합니다. `reference_sample`(레퍼런스 그림 색 추출과 주색), `reference_trace`(마법 지팡이로 윤곽을 취해 바로 쓸 수 있는 경로를 반환), `reference_snap`(점을 선에 붙임)을 추가했습니다. `view_render_model`은 좌표가 있는 그리드를 그리고, 그린 윤곽을 레퍼런스 그림 위에 대조할 수 있습니다.
- 소재 패널에 「폴더 가져오기」를 추가했습니다. 중첩된 하위 폴더는 원래 구조대로 소재 폴더가 되고, 파일은 이름 안의 숫자 순으로 정렬되며, 숨김 파일과 폴더는 건너뜁니다.
- PSD 소재를 배치할 때 PSD 캔버스 전체가 프로젝트 캔버스 중앙에 매핑됩니다(프로젝트 캔버스보다 크면 비율을 유지해 축소). 더 이상 PSD 좌표 그대로 왼쪽 위에 놓지 않습니다. 새 Layout 프로젝트 페이지가 캔버스 단위의 의미를 설명합니다. 모델의 크기와 비율을 정하고, 선명도는 소재 픽셀과 텍스처 아틀라스 예산이 정합니다.
- 페인팅이 더 이상 메시 범위에 제한되지 않습니다. 캔버스 전체에 그릴 수 있고, 적용할 때 메시 밖의 부분은 자동으로 원 레이어 바로 위의 새 레이어로 나뉩니다(소재 라이브러리에도 나타남). 원 레이어의 메시와 리그는 변하지 않습니다. 적용할 때 더 이상 「메시 다시 만들기」 대화 상자가 뜨지 않습니다.
- 편집기의 「선택」 모드 이름을 「오브젝트」 모드로 바꿨습니다.
- 이미 생성한 레이어의 분류를 수정해도 바로 다시 생성하지 않고, 다음 「다시 생성」 때 함께 적용됩니다.

## v3.4.5 · 2026-10-13

### 수정

- **저장과 복구**: 저장, 닫기, 크래시 복구의 상태 조율을 다듬었습니다. 복구 체크포인트가 완전한 프로젝트 상태를 유지하고, 연속 자세 편집이 순서대로 제출됩니다.
- **가져온 원본 파일 유지**: 프로젝트가 가져올 때의 PSD / CMO3 원본 내용을 유지하며, 이후 읽기는 외부 원본 파일에 의존하지 않습니다.
- **빈 레이어**: 빈 레이어가 있는 PSD를 가져온 뒤 정상적으로 저장하고 다시 열 수 있습니다.
- **독립 메시 검사**: 검사가 실패하면 오류를 표시합니다. 60초를 넘으면 멈추고, 검사를 닫은 뒤 늦은 결과가 대화 상자를 다시 띄우지 않습니다. 메모리 부족과 호출 스택 오버플로도 명확한 안내가 있습니다.

### 개선

- **예제 소재를 따로 배포**: 예제 소재, 프로젝트, 출력을 [독립 예제 저장소](https://github.com/tsunehimatoi/psd2live-examples)로 옮겼고, 필요할 때 받을 수 있습니다. 주 저장소는 설명과 고정 버전 목록을 남기며, 기고를 환영합니다.

## v3.4.4 · 2026-10-13

- **가져온 그림 재작업**(`tml` 예제 실측: 1024×512 그림을 가져오는 데 약 0.5–1초, 이후 이동, 확대·축소, 회전 제출이 약 40–60밀리초. 이전에는 드래그의 프레임마다 모델 전체를 다시 만들었음): 가져온 그림이 한 번의 제출로 자신의 메시를 갖고, 변형 도구로 바로 이동, 확대·축소, 회전하며, 드래그할 때 다른 객체처럼 매끄럽습니다. 프레임마다 모델 전체를 다시 만들던 “배치 패널”은 없어졌고, 실행 취소하면 가져오기가 취소됩니다. 그림을 아무 디포머 아래에 건 뒤에도 언제든 다시 옮길 수 있고, 픽셀은 다시 샘플링하지 않습니다.
- **레이어 패널이 픽셀의 행방을 표시**: 마우스를 레이어 이름 위에 두면 원본 크기, 텍스처 블록 크기(원본의 백분율), 캔버스에 표시되는 크기, 정점 수, 가져온 그림인지, 전체를 변환했는지가 표시됩니다.
- **메시 ID가 분류나 형제 레이어에 따라 변하지 않음**: 레이어 분류를 바꾸거나 레이어를 더하고 빼기 전에, 기존 모든 메시의 ID가 고정됩니다. 이전에는 분류를 바꾸면 메시 이름이 바뀌고 같은 종류 레이어가 다시 번호가 매겨져, 다시 생성한 뒤 이전 메시 옆에 새 메시(“유령” 메시)가 하나 더 생겼고, 레이어 하나를 삭제해도 같은 종류 레이어의 메시 번호가 바뀌었습니다.
- **레이어 삭제가 진짜 삭제가 됨**: 레이어를 삭제하면 그 픽셀과 메시가 프로젝트에서 함께 떠납니다(그것을 참조하는 마스크, Glue, 경로, 가중치도 함께). PSD 레이어도 생성 입력에서 빠져, 뒤에서 디포머 프레임에 계속 영향을 주지 않습니다. 실행 취소하면 복구되며, 더 이상 “모두 복구”는 없습니다. 이전 프로젝트에서 소프트 삭제한 레이어는 여전히 복구할 수 있습니다. MCP `layer_soft_delete`는 `layer_delete`로 바뀌었습니다.
- **메시 재구축 버튼과 덮기 안내**: 메시 패널이 레이어의 정점 수와 변 길이(캔버스 단위)를 표시하고, “현재 픽셀로 다시 만들기”(MCP `layer_mesh_rebuild`)를 제공합니다. 키폼과 바인딩이 새 메시로 이전됩니다. 페인팅이나 그림 교체 뒤에 픽셀이 메시 밖에 떨어지면, 패널이 표시되지 않을 비율을 안내합니다. 옮긴 레이어는 메시를 다시 만든 뒤 원래 위치를 유지합니다.
- **레이어 전체 변환(`layer_transform`)**: 어떤 레이어든(가져온 것이든 PSD의 것이든, 부모와 바인딩이 있든 없든) 전체를 이동, 확대·축소, 회전할 수 있습니다. 픽셀, 텍스처, 텍스처 좌표는 변하지 않고, 재생성을 일으키지 않으며, 재생성 뒤에도 위치가 남습니다. 선택 모드에서 레이어 전체를 끌면 이 조작이 제출되고, 페인팅은 레이어의 새 위치에 맞으며, 회전한 레이어도 캔버스에 바로 그릴 수 있습니다. 붓질은 레이어 자신의 픽셀에 떨어지고, 사각형과 타원은 레이어와 함께 돕니다. 확대·축소했거나 픽셀 밀도가 캔버스와 다른 레이어에 그릴 때, 브러시, 연필, 지우개, 도형의 크기가 그 레이어의 픽셀 수로 자동 환산되어, 화면에서 보면 이전과 같은 크기입니다(예: 고해상도로 가져온 그림이 들어가자마자 작은 점 하나만 남지 않음). 커서 원과 실제 붓질 크기가 같습니다. 텍스처 패널의 위치, 크기 필드는 같은 조작으로 바뀌어 어떤 레이어에도 쓸 수 있습니다.
- **내보내기 대상별 내보내기(MCP)**: `project_export_target`은 “파일 → 다른 형식으로 내보내기”와 같고, 대상 하나(런타임, 웹, 이미지와 영상, 레이어 PSD 등)로 이미 제출한 모델을 내보내며, 파일과 손실을 반환합니다.
- **시뮬레이션 장애물(MCP)**: `simulation_put`의 `obstacles`가 시뮬레이션 물체에 다른 메시를 따르는 원형 또는 캡슐 장애물(팔, 다리, 몸통)을 더합니다. 머리카락과 천이 밖에 막힙니다. 베이크에 참여하고, p2lrt와 웹으로 내보냅니다.
- **생성 결과 업데이트 미리보기**: “도구 → 생성 결과 업데이트 미리보기”가 업데이트가 모델을 바꿀지, 어떤 항목을 봐야 하는지를 먼저 알려 주며, 프로젝트는 바꾸지 않습니다.
- **재생성 시험 실행(MCP)**: `workspace_preview_regeneration`이 제출 전에 설정 변경, 분류 변경, 분할, 생성 업데이트처럼 Rig를 다시 만드는 편집을 시험 실행하고, 병합 때 깨끗하게 남길 수 없는 내용과 늘어나거나 줄어들 객체를 보고하며, 프로젝트는 바꾸지 않습니다.
- **Cubism Animator 프로젝트 내보내기(.can3)**: CMO3를 내보낼 때 모델의 모션(프리셋 모션과 직접 만든 모션 클립)을 같은 이름의 `.can3`로 따로 저장합니다. 모션마다 장면 하나이며, Cubism Editor의 Animator에서 cmo3와 함께 열면 계속 편집하고 motion3로 다시 내보낼 수 있습니다. 파라미터 곡선, 파츠 투명도, 전체 투명도, 페이드 인·아웃, 루프, 이벤트가 기록됩니다. 깜빡임과 립싱크 효과 곡선은 Animator에 대응하는 트랙이 없어 내보내기 보고서에 나열됩니다. can3는 파일 이름으로 cmo3를 참조하므로, 둘은 같은 폴더에 두고 같은 내보내기에서 와야 합니다.

### 개선

- **생성 설정을 바꾸는 편집이 다시 쓰기와 섞이지 않음**: 같은 편집이 생성 설정(또는 분류)을 바꾸면서 더 이전의 Rig 편집을 다시 쓰면 거부되고 나눠 제출하라는 안내가 나오며, 이전 편집을 새 생성 결과 위에 조용히 재생하지 않습니다.
- **분할한 뒤 파츠가 계속 생성을 따름**: 레이어를 분할할 때(연결 덩어리, 다각형, 앞뒤 분리) 파츠가 원 레이어 위치에서 자동 생성에 참여하고, 원 레이어에서 한 키폼, 경로, 가중치, Glue가 파츠로 옮겨집니다. 이후 얼굴 설정, 선 자세, 스켈레톤, 분류를 바꾸면 파츠도 갱신됩니다. 분할이 개별 조건 때문에 이전 형식으로 되돌아가지 않습니다.
- **생성 설정과 분류 변경이 더 안정적**: 얼굴 특징, 입 모양, 머리·몸 강도, 레이어 분류 등 생성 설정을 수정할 때, 새 생성 결과와 이미 있는 편집이 바로 병합되어 고정 저장되며, 더 이상 열 때마다 다시 추론하지 않습니다. 이전 편집이 생성 규칙 변화로 무효가 되지 않습니다.
- **긴 편집 히스토리가 더 이상 느려지지 않음**: 생성한 모델을 편집할 때, 모델이 일정 간격(첫 편집, 이후 32단계마다)으로 자동 고정 저장되고, 이후 제출, 실행 취소, 다시 실행, 드래그는 최근 고정점 이후만 다시 계산합니다. 히스토리 길이와 무관하며, 그 때문에 기초 모델 전체를 다시 생성하지 않습니다. 시뮬레이션 베이크도 더 이상 기초 모델 생성을 기다리지 않습니다. 이렇게 편집한 프로젝트는 새 개정 형식으로 저장되며, 이전 버전 프로그램은 열 수 없습니다.
- **이전 프로젝트는 한 번만 다시 계산**: 더 이전 버전으로 저장했고, 이전 분할 기록이나 생성 이전 기록이 있는 프로젝트는 평소처럼 열립니다. 처음 편집할 때 현재 모델이 고정 저장되고, 이후에는 이전 기록대로 재생하지 않아 열기와 편집이 더 빠르고 안정적입니다. 이전 분할의 파츠는 자신의 메시로 남습니다.
- **선택 모드에서 가져온 그림의 이동과 확대·축소**: 선택 모드에서 가져온 그림을 끌거나 확대·축소하면(회전하지 않았고, 모션에 바인딩되지 않았으며, 기본 자세일 때) 레이어의 캔버스상 위치와 크기가 바뀌고, 그림 자신의 픽셀은 유지됩니다. 페인팅 모드로 들어가도 레이어가 가져올 때의 크기로 되튀지 않습니다. 이미 모션에 바인딩되었거나, 회전했거나, 메시를 따로 편집한 레이어는 이전 방식으로 메시를 변형합니다.
- **페인팅 브러시가 파츠 자신의 픽셀로 계산**: 브러시, 연필, 지우개, 도형의 px 수가 그리는 레이어 자신의 픽셀로 계산됩니다. 작게 표시되는 고해상도 레이어에서 16 px 브러시는 레이어상의 16픽셀이며, 최소 한 픽셀까지 그릴 수 있습니다.
- **프로젝트 열기와 저장이 진행을 표시**: `.psd2live`를 열거나 저장할 때 아래 상태 막대가 현재 단계(압축 해제, 히스토리 읽기, 모델 구축. 편집 기록, 히스토리와 소재 쓰기, 패키지 검증)와 백분율을 표시해, 큰 프로젝트가 멈춘 것처럼 피드백이 없지 않습니다.
- **시뮬레이션 풀이가 더 빠름**: 머리카락과 천 시뮬레이션의 굽힘 제약이 매번 각도를 한 번만 계산해, 참조 시뮬레이션, 실시간 시뮬레이션, 베이크가 약 3분의 1 빨라졌습니다. 운동 결과는 이전과 미세한 차이가 있고, 편집기와 PSD2Live 런타임(웹 플레이어 포함)은 여전히 프레임별로 일치합니다.
- **시뮬레이션 시작이 더 안정적**: 물체가 정지했을 때의 형태 보정이 더 정확합니다(같은 소요, 그린 형태와의 차이가 원래의 약 3분의 1에서 2분의 1). 참조 시뮬레이션과 실시간 미리보기를 재설정한 뒤의 가벼운 흔들림이 약 3–6 px에서 1–1.5 px로 줄었습니다(치마, 상의, 긴 머리카락). 베이크 학습 데이터에 섞이던 이 흔들림도 함께 줄었습니다.

위 두 항목은 시뮬레이션 결과를 바꿨으므로, 이미 있는 베이크는 만료로 표시됩니다. 다시 베이크하면 됩니다.

### 제거

- **`asset_import_png`의 `spatial_reference_id`**: 가져오기는 `asset_prepare_reference`가 반환한 `reference_id`만 받습니다.
- **도구 → 분할 기록 업그레이드**(그리고 MCP `source_upgrade_split_records`): 새 분할은 모두 생성에 바로 참여하고, 이전 프로젝트는 처음 편집할 때 고정되므로 따로 업그레이드할 필요가 없습니다. 분할 작업 결과에 더 이상 `record_version` / `record_version_reason`이 없습니다.

### 수정

- **내보내기와 미리보기가 일치**: “Live2D 모델 내보내기”(및 MCP `project_export_model`)가 편집기에 이미 제출한 모델을 바로 쓰며, 더 이상 원본 그림에서 한 번 더 생성하지 않습니다. 내보낸 moc3가 미리보기와 바이트 단위로 같고, 다시 연 프로젝트를 내보내도 먼저 기초 Rig를 생성하지 않습니다.
- **스윙 베이크**: 편집한 모델에서 스윙을 삭제하고 “키폼으로 유지”(`swing_delete bake=true`)를 선택해도 더 이상 오류가 나지 않습니다.
- **그림 가져오기**: 텍스처 아틀라스 배치를 저장한 뒤, 고해상도로 가져온 그림을 놓거나 확대·축소해도 더 이상 “does not fit an atlas page”를 보고하지 않고, 한 페이지에 들어가지 않는 타일은 따로 줄어듭니다. 가져온 그림을 계층 패널에서 다른 부모 아래로 끌 수 있습니다(이전에는 Object not found). 머리가 기울어진 캐릭터에서 그림을 머리 회전과 그 아래 디포머로 가져와도 더 이상 위치 오프셋을 보고하지 않습니다.
- **분할한 뒤 레이어 분류 수정**: 레이어를 분할하고 페인팅 때 메시를 다시 만든 프로젝트에서, 아무 레이어의 분류(가져온 그림의 프리셋 포함)를 수정해도 더 이상 “Art primitive part was not generated”를 보고하지 않습니다. 머리카락 시뮬레이션 등 프리셋 뒤에 가져온 그림도 분류를 수정할 수 있습니다(이전에는 Mesh creation artwork is missing).
- **메시 형태로 배치한 텍스처 아틀라스**: 레이어에 원 메시 범위를 넘어 그린 뒤, 그와 맞물린 이웃 타일이 더 이상 서로 덮지 않고, 텍스처 표시가 이상해지지 않으며, 다시 배치할 필요도 없습니다. 그린 뒤의 타일은 새로 그린 칸을 차지하고, 그와 충돌하는 이웃은 빈 자리로 옮깁니다. 그 때문에 빈 자리로 밀린 타일도 자신의 메시 칸만 쓰며, 더 이상 사각형 전체로 이웃을 덮지 않습니다.
- **계층 드래그로 부모 변경**: 계층 패널에서 메시를 다른 디포머 아래로 끌거나(또는 인스펙터에서 그 디포머를 바꿀 때) 메시가 캔버스 원래 위치에 남고, 키폼과 블렌드 셰이프가 따라 환산됩니다. 이전에는 메시가 원래 로컬 좌표를 유지해, 루트 계층이나 회전 디포머에서 Warp로 끌면 캔버스 밖으로 날아가고, Warp에서 루트 계층으로 끌면 점으로 줄어들었으며, 가져온 뒤 선택 모드에서 이동하거나 확대·축소한 그림을 디포머 아래에 걸면 바로 사라졌습니다.

- **런타임 C 인터페이스 1.1**: 자신의 프로그램이나 엔진에서 내보낸 모델을 재생할 때, 같은 캐릭터를 여러 부 불러도 모델 데이터 한 부를 공유할 수 있습니다. 층별로 모션, 표정, 동작, 물리를 진행하고, 모션 위에 자신의 파라미터(예: 페이스 트래킹)를 겹칠 수 있습니다. 파츠를 읽고, 파츠 투명도를 설정하고, 격리 파츠의 그리기 그룹과 합성 방식, 투명도 합성 모드를 읽을 수 있습니다. 파라미터 이름과 유형, 파라미터 패널 그룹, 모션 클립의 길이와 그룹을 읽고, 모션 진행으로 이동할 수 있습니다. 헤더에 완전한 그리기 규칙(프리멀티플라이, 곱하기/스크린, 마스크, 컬링 방향, 각 블렌드 모드 공식)과 멀티스레드 규칙을 적었습니다. 이전 인터페이스만 쓰는 프로그램은 영향이 없습니다.
- **런타임 C 인터페이스 1.2**: 모션을 층으로 나눠 동시에 재생하고 우선순위를 둘 수 있습니다(Cubism의 모션 관리자와 같음). 모션에 이벤트를 둘 수 있고(Cubism 모션의 사용자 데이터), 파츠 투명도, 전체 투명도, 깜빡임, 립싱크 효과를 구동할 수 있으며, 곡선 하나가 자신의 페이드 인·아웃을 가질 수 있습니다. 여러 표정이 동시에 적용될 수 있습니다. 전체 투명도를 설정하고, 자신의 색으로 메시나 파츠의 곱하기/스크린 색을 바꿀 수 있습니다. 물리는 바람, 안정화(정지 상태에서 시작해 먼저 한 번 휘두르지 않음), 세로(Y) 입력·출력을 지원합니다. 깜빡임 간격, 호흡, 시선 진폭을 조절할 수 있습니다. 립싱크는 오디오 샘플이 바로 구동할 수 있습니다. moc3를 내보낼 때 모션의 이벤트, 파츠와 모델 곡선, 곡선 페이드 인·아웃도 motion3에 기록됩니다.
- **런타임 내장 소프트웨어 렌더**: C 인터페이스 1.3에 `p2l_render`를 추가했습니다. 렌더 코드를 쓰지 않아도 모델을 이미지로 그릴 수 있습니다(마스크, 격리 파츠 그룹, 모든 블렌드 모드와 컬링. 편집기가 내보낸 이미지와 픽셀 단위로 일치). C/C++ 프로그램, 엔진 플러그인, 썸네일 생성에 적합합니다.
- **런타임의 C#(Unity) 바인딩과 Android 빌드**: 헤더에서 생성한 C# 선언, Unity 예제 컴포넌트, C/C++ 예제 프로그램, Android(arm64-v8a, armeabi-v7a, x86_64)용 런타임 라이브러리 빌드 스크립트를 추가했습니다.
- **Windows ARM64와 Linux arm64 설치 패키지**: Windows ARM64 포터블 ZIP과 EXE(Cubism 네이티브 미리보기 없음. Live2D가 이 플랫폼의 Cubism Core를 제공하지 않으며, 미리보기는 PSD2Live 런타임을 사용)와 Linux arm64 Deb(Cubism 네이티브 미리보기는 Live2D 실험적 arm64 Core를 사용)를 추가했습니다. 둘 다 아직 실기 테스트를 하지 않았으며, OpenGL 3.1만 지원하는 GPU(예: 라즈베리 파이)에서는 캔버스를 그리지 못할 수 있습니다.
- **런타임 C 인터페이스 1.4**: 프레임마다 실제로 변한 메시만 갱신할 수 있고(Cubism의 dynamic flags와 같음), 런타임의 오류 로그를 받으며, 런타임이 호스트 자신의 메모리 할당기를 쓰게 할 수 있습니다.

### 개선

- **시뮬레이션 베이크가 입력마다 구동하도록 바뀌어, 시뮬레이션에 더 가깝고 더 빠름**: 베이크가 먼저 Rig에서 각 입력이 물체를 얼마나 움직이는지 읽고, 거의 움직이지 않는 입력(예: 치마 위의 머리 회전)은 더 이상 참여하지 않아, 사용자가 그것을 움직여도 물체가 이유 없이 흔들리지 않습니다. 물체를 위아래로 움직이는 입력은 자동으로 위아래 파라미터에 들어갑니다. 각 입력은 이어서 따로 계단과 주파수 스윕을 하고, 진자 안의 각 입력이 물체를 그 방식으로 움직이게 하는 영향도를 얻습니다. 이전에는 모든 입력이 같은 모션 구간에서 무작위로 움직여, `tml` 뒷머리에서 몸의 좌우 회전이 진자에 거의 읽히지 않았고, 마우스를 따를 때 내보낸 진폭이 시뮬레이션의 2할이었는데, 지금은 시뮬레이션과 비슷합니다. 모델 프리셋의 뒷머리, 앞머리 베이크가 본 적 없는 모션에서 대체로 더 정확하고, 소요가 약 4–13초에서 2–7초로 줄었습니다. 천과 위아래 파라미터는 여전히 약합니다. 이미 있는 베이크는 만료되지 않으며, 다시 베이크하면 새 방법을 쓸 수 있습니다.
- **베이크가 시각 검사를 표시**: 베이크 절이 먼저 본 적 없는 모션에서 내보내기와 시뮬레이션의 진폭 비, 지연, 되떨어짐, 떨림을 표시하고, 차이가 보이면 경고색으로 표시하며, R²는 보조로 물러났습니다. 입력 절은 각 입력이 물체를 얼마나 움직이는지 표시하고, 제외된 입력은 「유지」를 선택할 수 있습니다.
- **베이크와 참조 시뮬레이션 비교**: 물리체 편집 영역에 「비교」 절을 추가했습니다. 참조 시뮬레이션을 내보내기 대신 표시, 내보내기만 표시, 겹침(반투명으로 내보내기 위에 겹침)으로 볼 수 있습니다. 「나란히」는 미리보기 캔버스 두 장을 열어 내보내기와 참조를 각각 표시합니다. 모션 하나를 골라 「재생」하면 참조 시뮬레이션과 내보낸 진자가 함께 정지에서 시작하고, 「검사」는 백그라운드에서 그 모션으로 시각 검사를 냅니다.
- **학습에 참여하는 모션**: 「고급」에서 모델 자신의 모션(사용자 모션 또는 내장 모션)이 가중치에 따라 베이크 학습에 참여하게 할 수 있습니다. 주로 소수의 고정 모션으로 구동하는 모델에 적합합니다.
- **MCP**: `simulation_put`에 `force_inputs`와 `training_clips`를 추가했습니다. 베이크 요약이 각 입력의 읽기 결과(`inputs`)와 시각 검사(`visual`)를 반환합니다. 읽기 전용 작업 `simulation_compare`를 추가해, 모션별로 베이크 결과와 참조 시뮬레이션을 비교합니다.
- **내보낸 이미지와 영상이 편집기 합성에 따름**: 내보낸 PNG, GIF, 영상 프레임, 포즈별 PSD가 격리 파츠를 전체 레이어로 합성합니다(그룹의 불투명도, 곱하기/스크린 색, 마스크, 블렌드 모드 포함). 모든 투명도 합성 모드(atop, out, conjoint, disjoint)도 편집기 방식으로 그리며, 그리기 순서 그룹은 파츠의 그리기 순서로 정렬합니다. 컬링을 켠 메시는 앞면만 그립니다.
- **웹 플레이어가 블렌드 모드를 완전히 지원**: 내보낸 웹 플레이어가 모든 색·투명도 블렌드 모드와 격리 파츠 그룹(그룹의 불투명도, 곱하기/스크린 색, 마스크 포함)을 그리며, 더 이상 오버레이, 곱하기 이외의 모드를 일반 그리기로 하지 않습니다. 컬링을 켠 메시는 앞면만 그립니다.
- **Godot 노드가 블렌드 모드를 완전히 지원**: `P2LCharacter`가 격리 파츠 그룹(그룹의 블렌드 모드, 불투명도, 곱하기/스크린 색, 마스크, 중첩 포함), 모든 투명도 합성 모드, 반전 마스크를 그립니다(이전에는 반전 마스크를 마스크 없음으로 그림). 컬링을 켠 메시는 앞면만 그리고, 「가산(발광)」은 편집기 방식으로 그립니다.
- **Windows가 아닌 플랫폼의 세부**: macOS에서 Cmd+Q와 앱 메뉴의 종료가 먼저 저장을 묻고, 메뉴 막대와 Dock에 PSD2Live의 이름과 아이콘이 표시되며, 캔버스 Ctrl+클릭, 레이어와 트리의 다중 선택도 Cmd를 받습니다. Finder에서 열면 Homebrew / MacPorts로 설치한 ffmpeg를 찾습니다. macOS와 Linux에서 텍스처 고해상도화의 명령줄 기본과 MCP stdio 설정이 `python3`를 씁니다. 설치 패키지에 `mcp_proxy.py`가 함께 있고, Agent 대화 상자가 그 경로를 보여 줍니다.
- **런타임 미리보기가 블렌드 모드를 완전히 지원**: 미리보기에서 「PSD2Live 런타임(p2lrt)」을 고르면, 모든 색·투명도 블렌드 조합과 격리 파츠 그룹이 편집기 규칙으로 그려지며, 더 이상 가장 가까운 기본 모드로 돌아가지 않습니다.

### 수정

- **분할하거나 머리카락 시뮬레이션을 켠 뒤에 만든 스켈레톤이 손발을 움직이게 함**: 시작 화면에서 레이어를 나누거나 머리카락 시뮬레이션을 켠 프로젝트에서, 그 뒤에 스켈레톤을 만들거나 수정하면 본은 보이지만 팔과 다리 파라미터가 생성되지 않아, 내보낸 모델과 손 흔들기, 환호 등의 모션에서 손발이 움직이지 않았습니다. 이제 스켈레톤이 모델에 정상적으로 베이크됩니다. 설정에서 머리카락 시뮬레이션 등을 직접 켜고 끄는 변경도 같습니다. 영향을 받은 버전에서 이런 수정을 하고 저장했다면, 프로젝트를 연 뒤 「도구 → 생성 결과 업데이트」를 실행하면 보충됩니다.
- **본 자동 Glue 복구**(v3.1.0부터 무효): 사지를 여러 구간으로 나누고(예: 다리와 신발을 좌우로 나누거나, 소매를 팔꿈치에서 자름) 스켈레톤을 켜면, 이음매의 자동 Glue(`GlueSkel__…`)가 사라지고, 나중에 분할한 파츠가 더 이상 본 아래에 걸리지 않고 본과 함께 돌지 않았습니다. 원인은 첫 분할 이후의 분할 검증이 분할이 새로 만든 쌍 Warp를 고려하지 않아 이전 버전 분할 기록으로 되돌아갔고, 스켈레톤을 켤 때의 병합이 이전 버전 분할 파츠의 스키닝과 Glue를 가져가지 않았기 때문입니다. 두 곳 모두 수정했습니다. 새 분할은 평소처럼 새 버전 기록을 쓰고, 이전 버전 분할 기록이 있는 프로젝트에서 스켈레톤을 켜면 파츠도 스키닝되고 자동으로 Glue가 붙습니다. v3.1.0–v3.1.2에서 스켈레톤을 켠 프로젝트는, 스켈레톤을 켜기 전으로 실행 취소한 뒤 다시 켜면 복구됩니다.
- **이목구비 변위 등 생성 설정을 켠 뒤에 만든 스켈레톤이 메시를 터뜨리지 않음**: 시작 화면에서 「전체」 프리셋을 고르거나(또는 그 뒤에 이목구비 변위, 머리/몸 강도 등 생성 설정을 바꾼) 프로젝트에서 자동 스켈레톤을 켜면, 스켈레톤이 어떤 메시도 스키닝하지 않고(환호 등의 모션에서 팔이 들리지 않음), 꼬리가 꼬리 스윙 때 화면 전체를 덮는 큰 삼각형이 되던 문제가 있었습니다. 원인은 생성 설정이 바뀐 뒤 메시가 생성 디포머의 이름 변경 복제본 아래에 걸리고, 스켈레톤을 켤 때의 병합이 각 메시를 사용자가 부모를 바꾼 것으로 보고 원래 위치를 유지하면서도 스켈레톤이 본 공간에서 만든 포즈 블렌드 셰이프를 가져갔기 때문입니다. 이제 병합이 이름 변경 뒤의 디포머에 맞춰지고, 메시가 정상적으로 스키닝됩니다. 사용자 부모를 유지하는 메시는 다른 부모 공간에서 생성된 블렌드 셰이프를 더 이상 가져가지 않습니다. 영향을 받은 프로젝트는 스켈레톤을 켜기 전으로 실행 취소한 뒤 다시 켜면 됩니다.
- **내보낸 프레임의 「가산(발광)」**: 편집기의 W3C 가산으로 그리며, 더 이상 Cubism 구식 가산으로 그리지 않습니다.
- **모션을 빠르게 전환해도 더 이상 튀지 않음**: 웹 플레이어와 런타임에서, 이전 모션이 아직 페이드 아웃 중일 때 다시 전환하면 가장 이른 모션이 바로 버려져 화면이 갑자기 튀었습니다. 이제 교체된 각 모션이 완전히 페이드 아웃합니다.
- **여러 캐릭터가 동시에 깜빡이지 않음**: 같은 프로그램에 여러 캐릭터를 불러오면, 이전에는 깜빡임 시점이 완전히 같았고, 이제는 각자 어긋납니다.
- **런타임 오류가 더 이상 편집기를 강제 종료하지 않음**: PSD2Live 런타임(p2lrt)이 어떤 모델을 평가할 때 내부 오류가 나면, 이전에는 프로그램 전체가 바로 종료되었습니다. 지금은 그 모델만 응답을 멈춥니다. 소프트웨어 미리보기는 자동으로 편집기 자신의 평가기를 쓰고, 런타임 미리보기 백엔드와 내보내기 보고서가 오류 이유를 알리며, 프로그램은 계속 실행됩니다. 인터페이스가 맞지 않는 런타임 라이브러리(예: `PSD2LIVE_RUNTIME`으로 지정한 이전 버전)는 더 이상 로드되지 않고, 편집기 평가기를 사용합니다.

## v3.1.2 · 2026-10-09

### 개선

- **로그 열을 조절할 수 있음**: 로그 위에 열 제목 행을 추가했습니다. 제목을 끌어 시간, 출처, 태그, 메시지의 순서를 바꾸고, 제목 오른쪽 가장자리를 끌어 너비를 조절하며, 오른쪽 클릭으로 시간, 출처, 태그 열을 표시하거나 숨기거나 열을 초기화할 수 있습니다. 배치가 기억됩니다.
- **자동 스크롤**: 아이콘이 로그 행 옆의 아래 화살표로 바뀌었고, 따라갈 때 화살표가 바닥에 있고 최신 행이 굵게 표시됩니다. 위로 스크롤하면 따라가기가 자동으로 멈추고, 바닥으로 돌아오면 자동으로 회복됩니다.
- **로그 등급이 아이콘으로 변경**: 등급 메뉴가 도구 막대의 아이콘 버튼이 되었고, 아이콘이 선택한 등급의 기호를 표시합니다(디버그는 벌레, 정보는 원 i, 경고는 삼각 느낌표, 오류는 원 엑스). 메뉴 각 항목 앞에도 대응하는 기호가 있습니다. 자동 스크롤과 비우기 버튼 사이에 더 이상 구분선이 없습니다.
- **로그 검색 상자 너비가 내용에 따라 변함**: 비어 있으면 안내 글 너비로 표시되고, 입력하면 내용에 따라 넓어지며, 최대 도구 막대의 절반을 차지합니다. 옆의 필터 태그가 더 이상 「⋯」 안으로 밀리지 않습니다.
- **계층 트리 정렬**: 계층 트리 도구 막대에 정렬 버튼을 추가했습니다. 기본은 높이순(캔버스에서 위에서 아래로, 머리카락이 앞, 발이 뒤)이며, 모델 순서, 수평 위치(왼쪽에서 오른쪽), 그리기 순서(앞에서 뒤), 이름(숫자는 크기로 비교)으로 같은 단계 항목을 정렬하고, 역순으로 전환할 수 있습니다. 디포머는 그 아래 모든 메시의 위치나 가장 앞의 그리기 순서로 정렬에 참여하고, 메시가 없는 디포머는 맨 뒤에 옵니다. 디포머는 여전히 메시보다 앞에 옵니다. 선택한 정렬이 기억되고, 기본이 아니면 버튼이 강조됩니다.
- **그리기 순서 자가 선택한 항목을 우선 조정**: 선택한 항목의 눈금이 자 전체를 가로지르고, 다른 눈금과 겹치면 그 위에서 드래그, 두 번 클릭, 오른쪽 클릭이 선택한 항목을 바꾸며, 더 이상 겹친 선택하지 않은 항목을 잘못 바꾸지 않습니다. 자 오른쪽의 짧은 눈금 구역에서, 다른 눈금에 분명히 더 가까울 때만 그 항목을 선택합니다.
- **그리기 순서 자가 가리키면 메시를 미리봄**: 눈금을 가리키면 계층 트리처럼 메시 텍스처 미리보기를 표시합니다. 여러 눈금이 겹치면 그곳의 모든 메시를 한 번에 나열하고, 이름, 색 표시, 각자의 그리기 순서를 달며, 선택한 항목을 강조합니다.

### 수정

- **앞머리 시뮬레이션이 더 이상 크게 난무하지 않음**: 앞머리는 이마에 붙어 가로로 쓸리며, 뒷머리와 옷처럼 자연스럽게 늘어지지 않는데, 이전에는 같은 머리카락 재질을 써 원화가 형태가 거의 아주 약한 되튐으로만 버텼고, 고개를 흔들 때 진폭이 머리가 이끄는 양의 약 두 배였으며, 끄덕임도 위아래로 튀었습니다. 모델 프리셋이 생성한 앞머리는 새로 추가한 「앞머리」 재질(되튐이 더 강하고 감쇠가 더 큼)을 쓰며, 고개 흔들기와 끄덕임의 진폭이 분명히 줄고, 베이크한 진자도 시뮬레이션에 더 가깝습니다. 기존 프로젝트의 앞머리가 여전히 기본 머리카락 재질이면, 앞머리 프리셋을 다시 적용하면 앞머리 재질로 바뀝니다. 재질을 고친 것은 그대로 둡니다.
- **Alt + 오른쪽 클릭으로 브러시를 조정할 때 축이 섞이지 않음**: 좌우로 끌어 반지름을 조정한 뒤, 다음 위아래 드래그가 반지름 조정을 이어받지 않습니다. 키를 뗐는데 캡처되지 않았으면, 제스처도 다음 이동이나 누름 때 끝납니다. 방향은 약 12픽셀을 끌고 수평이나 수직으로 분명히 치우쳐야 잠기며, 비스듬히 시작하면 쉽게 잘못 잠기지 않고, 잠기기 전의 이동이 수치를 한 번 튀게 하지 않습니다.
- **Windows 설치 패키지가 Inno Setup을 사용**: EXE 설치 패키지가 파일을 바로 복사해, 덮어쓰기 설치가 더 이상 MSI가 이전 파일을 `Config.Msi`로 옮기는 단계를 거치지 않습니다. 일부 컴퓨터에서 덮어쓰기 설치 때 「Error writing to file … .rbf」가 나고 설치 디렉터리를 지운 뒤 다시 시도해야 하던 문제를 피합니다(#14). 업그레이드할 때는 원래 디렉터리로 돌아갑니다. 3.1.x 이전의 EXE / MSI 설치는 자동으로 제거되고 원래 디렉터리를 쓰며, 설치 디렉터리에 직접 둔 파일은 남습니다. 설치 전에 PSD2Live가 실행 중이면 저장하고 닫은 뒤 다시 시도하라는 안내가 나옵니다. 기본은 모든 사용자 설치이며, 시작할 때 현재 사용자만 설치하도록 고를 수도 있습니다(관리자 권한 불필요). 설치 화면은 시스템 언어(중국어, 영어, 일본어, 한국어)를 따르며, 바탕화면 바로 가기를 만들 수 있습니다. 제거할 때 PSD2Live 데이터도 지울지 묻습니다(기본은 유지). 더 이상 MSI 설치 패키지를 제공하지 않습니다.
- **ffmpeg가 있는 Windows 패키지가 ffmpeg를 다시 내장**: 3.0.1부터 `-ffmpeg` 포터블과 설치 패키지가 실제로는 일반 패키지와 같고 ffmpeg가 들어 있지 않아, 영상과 애니메이션 내보내기에 직접 설치가 필요했습니다. 이제 이 패키지에 ffmpeg가 들어 있습니다.

## v3.1.1 · 2026-10-09

### 추가

- **로그 등급 필터**: 로그 패널에 「등급」 메뉴를 추가해, 디버그 이상, 정보 이상, 경고 이상, 오류만 볼 수 있고, 각 항목 옆에 개수가 표시됩니다. 기본은 디버그 등급을 숨깁니다. 로그를 복사할 때 등급을 함께 가져갑니다.
- **로그 범위가 더 넓음**: 사용자가 편집기에서 한 수정마다(히스토리 트리와 같은 이름), 실행 취소 / 다시 실행 / 히스토리 전환, 프로젝트 열기와 저장, 창이 띄운 오류가 로그에 기록됩니다. 상태 막대 메시지는 디버그 등급으로 기록됩니다. AI 인터페이스의 시작, 중지, 시작 실패, AI 클라이언트의 연결과 끊김도 기록됩니다.
- **로그 스타일**: 출처를 「시스템 / 사용자 / AI」로 바꿨습니다. 각 행 왼쪽의 색 막대가 등급을 표시하고, 오류와 경고 행은 옅은 배경이 있습니다. 시간, 출처, 태그가 고정 열을 차지하고 메시지가 정렬됩니다. 요청 파라미터 등 상세는 기본적으로 접히고, 행 앞 화살표를 누르면 펼칩니다. 연속으로 반복되는 행은 한 행으로 합쳐 「×N」을 표시합니다. 렌더 그림 카드는 가리키면 강조되고, 클릭하면 큰 그림을 봅니다.

### 개선

- **미리보기 재생이 더 매끄러움**: 240 Hz 디스플레이에서 미리보기 작업 공간 재생이 약 230 FPS이고, 편집 작업 공간이 70–110 FPS에서 약 215 FPS로 올랐으며, 애니메이션과 물리 작업 공간도 분명히 높아졌습니다. 창이 화면 그림을 GPU에 캐시하고, 재생할 때는 미리보기 자체만 다시 그리며, 화면에 변화가 있을 때만 창 전체를 다시 그립니다. 파라미터 패널은 재생에 따라 슬라이더와 수치만 다시 그리고, 수치 상자는 클릭하거나 포커스를 얻기 전에는 텍스트로 표시되며, 재생을 따르는 갱신은 60 Hz를 넘지 않습니다. 계층 트리, 스켈레톤, 로그, 레이어 표 등 포즈를 표시하지 않는 패널은 더 이상 재생에 따라 다시 조합되지 않습니다. 모든 아이콘은 한 번 그린 뒤 비트맵으로 표시됩니다. 화면 표시가 이상하면 `-Dpsd2live.compositor=false`로 화면 캐시를 끌 수 있습니다.
- **화면 그리기가 CPU를 더 아낌**: 창이 4× 멀티샘플로 그려지고, 둥근 모서리, 아이콘, 곡선의 안티앨리어싱을 그래픽 카드에 맡겨, 높은 주사율에서 편집 작업 공간의 프레임률이 약 2할 올랐습니다.

### 수정

- **MCP 조작과 렌더가 로그에 다시 나타남**: AI가 MCP로 호출할 때마다 한 줄이 기록됩니다. 쓰기 조작(성공), 렌더 뷰(정보 등급, 렌더 그림 첨부, 그림이 여러 장이면 각 한 줄), 조회(디버그 등급), 실패(오류. 상태 충돌, 작업 공간 바쁨은 경고)를 각각 표시하고, 소요와 요청 파라미터를 보여 줍니다.

## v3.1.0 · 2026-10-08

### 추가

- **최근 열기**: **파일 → 최근 열기**가 최근에 연 프로젝트와 PSD를 나열하고, 한 번에 지울 수 있습니다. 시작 화면의 「최근」과 같습니다. 파일 존재 여부는 백그라운드에서 확인하고, 없는 파일은 표시하지 않으며, 네트워크 드라이브가 끊겨도 화면이 멈추지 않습니다. 시작 화면의 「새 기능」과 대화형 튜토리얼이 현재 버전에 맞춰 갱신되었습니다.
- **생성 결과 업데이트**: **도구 → 생성 결과 업데이트**(MCP `rig_update_generation`)가 현재 버전의 생성기로 다시 만들고, 사용자의 편집을 그 위에 병합합니다. 프로젝트에 이미 병합 저장된 생성 결과는 프로그램을 올려도 자동으로 바뀌지 않습니다.
- **도구 옵션 막대**: 캔버스 왼쪽 아래에 현재 도구의 수치(반지름, 강도, 경도, 불투명도, 모드 등)가 표시되고, 점 / 변 / 면과 현재 단계의 확인 / 취소는 위쪽 모드 막대에 있습니다. 좌우로 끌어 수치를 조절하고, 클릭하면 슬라이더가 뜹니다. 오른쪽 클릭 메뉴가 같은 수치 묶음과 그 도구의 조작을 표시하고, 각 조작에 아이콘이 있으며, 수치는 항목마다 한 줄입니다. 열릴 때 줄마다 미끄러져 들어오고, 가리킬 때 강조가 줄 사이를 미끄러지며, 같은 줄의 옵션 버튼 사이에도 미끄러지는 선택·가리키기 블록이 있어 모드 메뉴와 같습니다. 내용이 너무 길 때만 가장 큰 그룹을 하위 메뉴로 접으며, 더 이상 스크롤이 필요 없습니다. 두 곳의 범위가 같고, `[` `]` 등 브러시 단축키도 같은 값을 조정합니다. 도구 패널은 정밀 변환, 만들기 기본값, 경로 목록, 스켈레톤 바인딩과 가중치, 팔레트 등 고급 설정만 남깁니다.
- **숫자 키 옵션**: `1`–`5`가 현재 모드나 도구의 n번째 항목을 선택합니다. 메시 디포머의 단계, 편집 모드의 점 / 변 / 면, 브러시 형태, Glue와 스켈레톤 하위 도구, 가중치 그룹 종류, 페인팅 도형. 도구 막대가 각 항목 옆에 대응하는 숫자를 표시합니다.
- **만들기 도구**: 선택 모드의 왼쪽 도구 막대에 Warp, Rotation, 디폼 경로 만들기를 추가했습니다. 계층 트리의 추가 메뉴와 같습니다.
- **가중치 브러시 형태**: 시뮬레이션 모드의 가중치 브러시가 직선과 사각형 붓끝을 고를 수 있고, 회전할 수 있습니다.
- **변형 모드의 점 / 변 / 면**: 변형 모드도 편집 모드처럼 점, 변, 면으로 메시를 선택할 수 있습니다.
- **편집 캔버스가 더 이상 메시 통계를 표시하지 않음**: 왼쪽 아래의 ArtMesh, 정점, 삼각면, 확대 안내는 미리보기 캔버스에만 표시됩니다.
- **변형 단계**: 모드 막대는 대상이 메시 디포머일 때만 표시되며, 「정점」과 「베지에」로 이름을 바꾸고, 차이가 없던 단계 3을 없앴습니다. 베지에에서는 상세 메시가 옅어지고 편집할 수 없으며, 곡선, 앵커, 핸들의 색을 다시 맞췄습니다.
- **변형 도구가 상자 선택 가능**: 아무것도 선택하지 않았을 때 변형 도구가 선택 도구처럼 점 선택이나 상자 선택을 할 수 있습니다.
- **스키닝 가중치 표시**: 「스키닝 가중치 표시」를 오른쪽 아래 표시 막대로 옮겼습니다.
- **런타임 고급 모드**: 내보낸 런타임 모델이 재생 때 켤 수 있고, 기본은 꺼져 있으며, 끄면 Cubism 효과와 완전히 같습니다.
  - **스켈레톤 스키닝**: 팔, 꼬리 등의 본 굽힘이 키프레임 사이에서 실제 호를 따라 움직이며, 더 이상 직선을 가지 않습니다. 호스트가 본 위치를 읽어 물건을 걸 수 있습니다.
  - **실시간 시뮬레이션**: 이미 베이크한 천과 머리카락이 편집기의 시뮬레이션대로 실시간 실행되며, 바람을 더할 수 있습니다.
  - **충돌**: 시뮬레이션에 몸 메시를 따르는 원 또는 캡슐 충돌체(`obstacles`)를 더할 수 있고, 베이크도 충돌 뒤의 운동을 학습합니다.
- **파츠 상호 배제와 zstd 압축**: 내보내기 설정에서 파츠 상호 배제 그룹을 지정할 수 있습니다(예: 두 종류의 팔 중 하나만 표시). 런타임이 전환할 때 자동으로 페이드 인·아웃합니다. 블록 압축은 zstd를 고를 수 있습니다.
- **미리보기 백엔드를 고를 수 있음**: 미리보기 왼쪽 도구 막대 맨 아래 세 줄에서 Cubism SDK, p2lrt · 표준, p2lrt · 확장을 전환할 수 있습니다(확장은 고급 모드: 호를 따라 스키닝, 실시간 천과 머리카락). 왼쪽 아래 상태 캡슐 메뉴에서도 전환할 수 있습니다. Cubism SDK가 없으면 미리보기가 자동으로 PSD2Live 런타임을 쓰며, 이전의 소프트웨어 폴백 미리보기를 대체합니다.
- **미리보기 프레임률이 디스플레이를 따름**: 미리보기의 프레임률 상한이 물리 프레임률과 독립이며, 기본은 디스플레이 주사율을 따르고, 30 / 60 / 120으로 제한할 수도 있습니다. 미리보기가 여러 개 동시에 보여도 더 이상 각각 30 FPS로 제한하지 않습니다. 왼쪽 도구 막대의 프레임률은 「물리 프레임률」로 이름이 바뀌어, 물리와 내보내기만 결정합니다.
- **표정과 클릭 영역**: 런타임 모델에 미소, 슬픔, 화남, 놀람 네 표정과, 머리와 몸의 클릭 영역이 있습니다. 웹 플레이어와 Godot 노드가 표정을 전환하고, 클릭을 감지하고, 고급 모드를 켜고 끌 수 있습니다.
- **한국어 레이어 이름 인식**: 앞머리, 눈동자, 상의 등의 한국어 레이어 이름을 자동 분류할 수 있습니다. 좌우는 왼쪽 / 오른쪽(또는 왼 / 오른을 이름에 붙여)으로 쓰고, Photoshop 한국어판의 복제본 접미사 「복사」는 무시됩니다.

### 개선

- **통일된 메시 표시**: 각 모드에서 편집 가능한 점과 선이 같은 겉모습을 쓰며, 색의 의미가 고정됩니다. 옅은 색은 구조, 강조색은 선택, 흰 원은 가리키기, 빨간 원은 브러시가 밀 점입니다. 모든 변형 브러시가 가리킬 때 영향을 받을 정점을 표시하며, 가중치 브러시와 같습니다. 선택 브러시는 선택될 점을 표시합니다. Warp 제어점은 사각 점이 되어 원형 메시 정점과 구분됩니다. 표시 막대의 메시 스위치는 메시 선만 그리며, 편집 중인 메시와 Warp를 중복으로 그리지 않습니다.
- **통일된 GPU 렌더**: 편집 캔버스, 텍스처 아틀라스 페이지, 두 가지 미리보기가 모두 창 자신의 OpenGL 컨텍스트에서 그려지고, 그 프레임에 표시되며, 더 이상 프레임마다 화면 전체를 메모리로 읽어 다시 올리지 않습니다. 이동, 확대, 재생이 한두 프레임 뒤처지지 않습니다. 이 때문에 화면은 Windows에서 OpenGL 렌더를 사용합니다. Cubism 미리보기는 `native/live2d_renderer`를 다시 빌드하는 것을 권합니다. 그렇지 않으면 수정할 때마다 임시 파일에서 모델을 다시 불러옵니다.
- **런타임 모델 형식 2.0**: 내보낸 `.p2lrt`가 청크 형식으로 바뀌어, 압축하고 검증할 수 있으며, 파라미터 그룹과 스냅 값을 가져 이후 새 기능을 넣어도 이전 파일을 깨지 않습니다. 런타임, 웹 플레이어, Godot 노드가 새 형식과 이전 형식을 함께 읽습니다. 이전 버전 플레이어에 쓰려면 내보내기 설정에서 「버전 1」을 선택합니다.

### 수정

- **시뮬레이션과 스윙 파라미터에 키를 찍음**: Cubism에서 물리 출력 파라미터를 쓰듯, 다른 메시나 Warp가 시뮬레이션, 스윙 파라미터에 키를 찍을 수 있고, 이 파라미터의 이름과 범위도 바꿀 수 있습니다. 이전에는 「파라미터가 모델에 없음」을 보고했고, 일부 조작(채널 키폼, 기본값에 축 새로 만들기, 생성한 키 삭제, 계층에서 이름 변경)은 오류 없이 제출한 뒤 결과가 사라졌습니다. 사용한 파라미터는 이제 프로젝트에 속하며, 대응하는 시뮬레이션이나 스윙을 삭제한 뒤에도 남습니다.
- **스윙이 작용하는 Warp를 삭제**: 스윙이 그 대상을 빼고, 다른 대상이 없으면 파라미터와 물리 그룹도 함께 제거되어, 아무것도 움직이지 않는 스윙이 남지 않습니다. 다른 이유로 스윙이 무효가 되면(예: 다시 생성한 뒤 대상이 없음) 물리 패널에서 그 스윙의 물리 그룹 아래에 이유가 표시됩니다.
- **생성 키폼 위의 베지에와 MCP 변형**: 스윙, 시뮬레이션이 생성한 키폼에서 베지에 편집이나 MCP `rig_deform`을 해도 더 이상 오류가 나지 않고, 브러시 변형과 같이 생성 결과 덮어쓰기로 저장됩니다. Ctrl을 눌러 자식을 유지하기, 키폼 복사, 생성기의 키를 더하고 빼기는 덮어쓰기로 저장할 수 없으며, 이제 편집할 때 이유를 바로 설명하고, 제출한 뒤 잃지 않습니다.
- **생성 설정을 바꾼 뒤 프로젝트가 열리지 않거나 오류**: 머리카락 시뮬레이션을 켜거나, 스켈레톤을 켜거나 조정하거나, 레이어를 나누는 등 자동 생성 결과를 바꾸는 조작이, 이전에는 편집 히스토리 전체를 새 생성 결과 위에 재생해야 해서, 이미 없는 디포머나 정점을 참조하는 편집이 프로젝트 전체에 오류를 냈습니다(예: “Art primitive parent is missing”, “Vertex group has … weights for … vertices”). 이제 이런 조작은 이미 있는 편집을 새 생성 결과에 병합해 데이터로 저장하고, 이후에는 이 이전 편집을 재생하지 않습니다. 깨끗하게 옮길 수 없는 내용은 품질 보고서에 나열됩니다. 이런 저장점이 있는 프로젝트는 이 버전 이상이어야 열 수 있습니다.
- **프로젝트 열기가 더 빠름**: 저장할 때 각 히스토리 버전의 편집 뒤 모델도 함께 저장해, 열기, 실행 취소, 히스토리 전환 때 바로 읽으며, 더 이상 다시 생성하고 재생하지 않습니다.
- **시뮬레이션 메시 위의 변형 오류**: 메시에 시뮬레이션 프리셋(또는 다른 생성기가 추가한 파라미터)을 더한 뒤, 그 위에서 변형 브러시, 베지에 등으로 편집하면 「파라미터가 모델에 없음」이 났습니다. 편집이 생성기 파라미터를 기록했는데, 편집을 재생할 때 생성기가 아직 실행되지 않았기 때문입니다. 이제 Cubism과 같이, 편집은 대상 자신이 읽는 파라미터만 기록합니다. 부모를 움직이는 스윙, 시뮬레이션 파라미터는 어떤 값에 있든 편집에 영향을 주지 않고, 대상 자신의 생성기 파라미터는 기본값일 때 기록에 쓰지 않습니다. Glue도 Cubism 방식으로 정지 형태에서 붙으며, 파라미터가 기본값이 아니면 먼저 부드럽게 기본값으로 돌아가, 붙는 점이 정지 때 더 이상 당기지 않습니다.
- **Alt를 누른 뒤 화면이 멈춤**: Windows에서 Alt만 누르거나(또는 Alt + 오른쪽 클릭으로 브러시를 조정한 뒤 손을 떼면) 창이 시스템 메뉴 모드로 들어가 이후 키가 삼켜졌습니다.
- **캔버스 도구와 메뉴**: 도구 막대가 길게 펼쳐져도 아래 도구가 더 이상 캔버스로 뚫고 나가지 않습니다. 변형 도구, 가중치 그라데이션, 스켈레톤 모드, 스포이드의 오른쪽 클릭 메뉴가 더 이상 비지 않습니다. Glue 도구는 메시 두 장을 선택하지 않으면 비활성화되고 이유를 설명하며, 더 이상 사라지지 않습니다. 도형 도구의 선 두께와 브러시 크기가 분리되었습니다. 스켈레톤 가중치 브러시는 `[` `]`로 크기를 조절할 수 있습니다. Warp 메시 크기 레이블이 화면 언어에 따라 표시됩니다.
- **런타임 파라미터가 프레임마다 누적**: 웹 플레이어와 C 인터페이스가 프레임을 갱신할 때 호흡, 시선, 깜빡임, 가산 표정을 이전 프레임 결과 위에 겹쳐, 한동안 재생하면 각도 등의 파라미터가 수만까지 흘렀습니다. 이제 매 프레임 호스트가 설정한 포즈에서 다시 계산합니다.
- **Windows에서 저장 실패**: 교체되는 프로젝트 파일이 잠시 점유되면, 저장이 점유 해제를 기다리며, 더 이상 바로 실패하지 않습니다.
- **명령줄 `--mesh-pixels`가 알 수 없는 옵션을 보고**: 도움말에 있던 이 옵션을 이전에는 쓸 수 없었고, 이제 원본 픽셀로 메시 간격을 계산합니다.

## v3.0.1 · 2026-10-08

### 추가

- **한국어 화면**: 설정에서 고를 수 있고, 명령줄은 `--lang ko`를 사용합니다.
- **언어 전환**: 언어 메뉴가 제목 표시줄 오른쪽, 테마 전환 옆의 지구 아이콘으로 바뀌었습니다. 전환하면 창 전체가 바로 새 언어로 바뀝니다.
- **메시가 텍스처에 붙음**: 새 프로젝트의 기본은 「텍스처 이미지를 따라 윤곽을 스케치」이며, 각 레이어 자신의 픽셀로 메시를 만들어, 캔버스 픽셀보다 가는 획도 메시 안에 남습니다. 이전 프로젝트는 원래 방식과 메시를 유지합니다.
- **메시 감싸기**: 메시 설정 「감싸기」를 추가했습니다(전역으로 설정하거나 레이어별로 덮을 수 있고, 명령줄 `--mesh-wrap`). 속눈썹, 머리카락 끝, 손가락 같은 가는 돌기를 같은 윤곽에 넣어 정점이 분명히 줄어듭니다. 기본은 꺼져 있고, 이전 프로젝트는 영향이 없습니다.
- **Windows에 ffmpeg가 포함된 설치 패키지**: `-ffmpeg` 접미사가 있는 zip / exe / msi에 ffmpeg가 내장되어, 영상과 애니메이션 내보내기에 따로 설치할 필요가 없습니다.
- **제거할 때 사용자 데이터를 지울 수 있음**: Windows의 「프로그램 제거 또는 변경」에서 삭제를 고른 뒤 「내 PSD2Live 데이터도 삭제」(기본은 선택하지 않음)를 선택할 수 있습니다.

### 개선

- **아이콘 통일**: 도구 막대 밖의 아이콘을 같은 그리드로 다시 그려, 고해상도 화면에서 선이 더 이상 가늘어지지 않고, 색은 의미 표현에만 씁니다.
- **스켈레톤 편집이 더 빠름**: 본을 만들거나, 바인딩하거나, 옮길 때 영향을 받는 사지만 다시 베이크하고, 병렬로 계산합니다. 큰 프로젝트에서 팔 관절 이동이 약 2–3초에서 1초 안으로 줄었습니다.
- **저장과 열기가 더 빠름**: 저장할 때 모든 이미지를 다시 인코딩하지 않고, 아카이브 전체를 풀어 검증하지도 않습니다. 큰 프로젝트를 열 때 이미지를 병렬로 디코딩합니다.
- **큰 프로젝트가 더 매끄러움**: 텍스처 아틀라스의 채우기, 분류, 합성과, 지정 포즈의 PSD 내보내기가 분명히 빨라졌습니다.
- **설치와 업그레이드**: 업그레이드나 재설치는 기본적으로 원래 디렉터리로 돌아가며, 디렉터리가 비어 있지 않다고 더 이상 묻지 않습니다. 다시 빌드한 같은 버전 설치 패키지는 이미 설치된 버전을 교체하며, 나란히 두지 않습니다.

### 수정

- **Windows 제거나 업그레이드가 설치 디렉터리를 비우던 문제**로, 설치 디렉터리에 저장한 프로젝트가 사라졌습니다. 이제 설치한 파일만 삭제합니다. 새 프로젝트의 기본 위치는 「문서\PSD2Live」로 바뀌었습니다. **3.0.0에서 업그레이드하기 전에, 설치 디렉터리의 프로젝트를 다른 곳으로 옮기세요.**
- 다른 이름으로 저장이 더 이상 기본적으로 현재 연 파일을 가리키지 않습니다. 덮어쓰기 확인이 창 안에서 뜹니다. 편집이 아직 끝나지 않았을 때 요청한 다른 이름으로 저장이 이후의 Ctrl+S에 의해 일반 저장으로 바뀌지 않습니다. 파일 선택 상자가 더 이상 주 창 뒤로 가지 않습니다.
- 편집 / 미리보기 모드를 전환할 때 시점과 캔버스 크기가 유지됩니다.
- 스켈레톤을 켠 뒤, 원래 팔 매달림 디포머 아래에 나뉜 파츠를 재생할 때 「Art primitive parent is missing」이 나던 문제를 수정했습니다.
- 본에 바인딩되고 또 수동으로 다른 디포머 아래에 놓은 메시가, 베이크 뒤 위치가 어긋나거나 범위를 넘던 문제를 수정했습니다.
- 이미 바인딩된 메시의 토폴로지를 수정하거나 실행 취소한 뒤, 프로젝트를 다시 열면 스켈레톤 결과가 편집할 때와 다르던 문제를 수정했습니다.
- 생성 뒤 새로 들어온 레이어가 다시 그린 뒤 메시가 조용히 다시 생성되고, 이후 재구축이 「Mesh migration baseline changed」를 보고하던 문제를 수정했습니다.
- Cubism 미리보기 프레임이 가끔 소프트웨어 미리보기에 덮여 포즈를 잃던 문제를 수정했습니다.

## v3.0.0 · 2026-10-08

v2.0.4 이후 변경이 큽니다. 여러 내보내기 형식과 독립 런타임을 추가했고, 텍스처를 레이어별로 조정할 수 있으며, MCP 인터페이스를 다시 설계했습니다. 이전 프로젝트는 평소처럼 열립니다.

### 추가

- **더 많은 내보내기 형식**: **파일 → 다른 형식으로 내보내기**에 VTube Studio, PSD2Live 런타임 모델, 웹 플레이어, PNG 시퀀스 프레임, 스프라이트 시트, GIF, APNG, WebP 애니메이션, MP4, WebM, ProRes 4444, 지정 포즈의 PSD를 추가했습니다. 내보낼 때마다 손실 보고서가 함께 나와, 대상 형식이 무엇을 잃었는지 설명합니다. 영상과 애니메이션에는 ffmpeg를 직접 설치해야 합니다.
- **PSD2Live 런타임**: 오픈 소스(MIT) Rust 런타임. 브라우저, Godot 4, 또는 C 인터페이스를 호출할 수 있는 어떤 프로그램에서든 내보낸 모델을 재생할 수 있고, 깜빡임, 호흡, 시선 따라가기, 립싱크를 포함합니다.
- **텍스처 작업 공간**: 레이어별로 텍스처 밀도를 조정합니다. 텍스처 아틀라스 페이지에서 타일을 바로 끌고 확대·축소합니다. 메시 형태에 맞춰 촘촘히 배치하고, 다시 배치하라고 할 때까지 배치가 유지됩니다.
- **원본 해상도 유지**: 가져온 그림, 소재, CMO3 텍스처가 더 이상 캔버스 해상도로 줄어들지 않고, 페인팅은 레이어 자신의 해상도에서 이루어집니다.
- **MCP 재설계**: 공개 조작이 25개에서 181개로 늘었고, 페이지로 발견할 수 있습니다. 최대 128개 편집을 원자적으로 제출할 수 있고, 먼저 시험 실행해 기하 문제를 확인할 수 있습니다. 시간이 걸리는 조작은 백그라운드 작업으로 실행됩니다. 이전 도구 이름은 삭제되었으므로 새 인터페이스로 연결해야 합니다.
- 실험적: Spine 4.2, DragonBones 5.5, glTF 2.0 내보내기. 명령줄만 가능합니다.

### 개선

- **분할이 더 안정적**: 메시로 분할, 다각형 분할, 앞뒤 분리로 얻은 파츠가 원 레이어를 바로 대체하고 자동 생성에 참여합니다. 이후 얼굴 설정, 선 자세, 스켈레톤을 수정하면 파츠가 따라 갱신됩니다. 원 레이어가 더 이상 텍스처 아틀라스를 차지하지 않습니다.
- **관절이 더 자연스러움**: 본이 굽을 때 팔꿈치, 무릎 등의 관절이 실측한 인체 관절 자세로 조형되어, 안쪽에 텍스처 접힘이 더 이상 나타나지 않습니다.
- **손 수정이 사라지지 않음**: 스윙, 시뮬레이션 베이크 등 생성 결과 위의 형태 수정이, 다시 생성한 뒤 삼자 병합으로 남습니다. 충돌하거나 이미 무효인 수정은 인스펙터에 안내됩니다.
- **파일 메뉴를 다시 정리**: 「가져오기」「Live2D 모델 내보내기」「다른 형식으로 내보내기」 세 그룹으로 나눴습니다.
- **통일된 변형 상자**: 「변형」 도구, Warp / 레이어 배치 상자, 텍스처 아틀라스 타일이 같은 변형 상자를 사용합니다. 모서리 점 바깥을 끌면 회전합니다(가리킬 때 모서리 점 밖에 화살표가 있는 호가 켜짐). 끌 수 있는 앵커를 추가해 회전과 Alt 확대·축소의 중심이 됩니다(기본은 중앙, 외곽선이 있어 구분하기 쉬움). 확대 커서가 상자의 각도에 따라 돕니다. 핸들은 둥근 사각과 캡슐 형태가 되었고, 끌 때 포인터 옆에 각도, 확대 비율, 이동이 표시됩니다.
- **캔버스와 파라미터**: 메시 선택과 상자 변환을 분리했습니다. 변형 도구는 선택한 파라미터 키 점에 작용합니다. 키 점을 추가하거나 끌 때 기본은 연속 이동이며, 단계 길이를 고른 뒤에야 붙습니다.
- **프로젝트 형식 v2**: 바꾸지 않은 내용이 히스토리 개정 사이에서 공유됩니다. 이전 프로젝트는 평소처럼 열리고, 저장할 때 자동 변환됩니다.
- **더 빠름**: 분류나 단일 레이어의 메시를 수정할 때 영향을 받는 부분만 다시 계산합니다. 프로젝트를 열 때 저장한 스켈레톤 결과를 재사용합니다. 편집 제출이 매번 모델 전체를 다시 만들지 않습니다. Cubism 네이티브 미리보기는 그 자리에서 갱신합니다.
- **결과를 재현할 수 있음**: 같은 PSD를 생성할 때마다 스켈레톤과 내보내기 파일이 완전히 같습니다.

### 수정

- 페인팅 뒤 메시를 다시 만들 때, 본, 선 자세 디포머, 수정한 격자, 가져온 디포머 아래에 있는 메시가 더 이상 어긋나거나 줄어들지 않습니다.
- 애니메이션 재생, 파라미터 슬라이더, 캔버스 포즈가 동기화됩니다. 매끄러운 추적 속도가 더 이상 프레임률의 영향을 받지 않습니다.
- 텍스처 아틀라스에 새로 넣은 타일이 더 이상 다른 타일이 비운 자리로 뛰어들지 않습니다.
- Windows에서 빠르게 연속 저장할 때 가끔 파일 교체에 실패하던 문제를 수정했습니다.
