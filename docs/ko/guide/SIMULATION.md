# 시뮬레이션과 베이크

[문서 목차](../README.md) · [물리](PHYSICS.md) · [스윙 생성](SWING.md) · [캔버스 편집](CANVAS_EDITOR.md) · [MCP 사용과 인터페이스](../agent/MCP_AUTHORING.md)

처음 조작할 때는 [시뮬레이션 그림 안내](SIMULATION_TUTORIAL.md)를 먼저 보고, 스크린샷을 따라 프리셋, 고정점 가중치, 다시 베이크, 효과 확인을 마칩니다.

시뮬레이션은 편집기 안에서 메시에 실제 2D 천 / 머리카락 시뮬레이션을 합니다. 정점은 고정점에 붙잡히고, 중력과 관성의 구동을 받습니다. Cubism 런타임은 이런 시뮬레이션을 하지 않으므로 **시뮬레이션 자체는 내보내지 않습니다**. 내보내려면 Cubism이 재생할 수 있는 내용으로 **베이크**해야 합니다. 새 파라미터 위의 메시 키폼이고, 맞춰진 진자가 구동하며, 몇 개 파라미터 위의 정확한 보정이 더해집니다. 베이크 결과는 프로젝트에 저장됩니다. 모델을 다시 구축할 때는 결과만 다시 기록하며, 다시 시뮬레이션하지 않습니다.

## 기본 흐름

1. 캔버스에서 치마나 머리카락 메시를 선택하고, 「시뮬레이션」 패널(각 작업 공간에서 「물리」 탭 뒤에 있으며, 편집 작업 공간은 기본적으로 표시)에서 「새로 만들기」를 누르고 「천」 또는 「머리카락」을 고릅니다. 같은 물리체 안의 여러 메시는 함께 시뮬레이션됩니다.
2. 고정점을 지정합니다. 둘 중 하나 또는 둘 다 쓸 수 있습니다.
   - 패널 「정점 가중치 그룹」에서 「고정」 줄의 「그리기」를 누르거나, 캔버스의 「시뮬레이션」 모드로 전환해 가중치 페인트로 「고정」 가중치 그룹을 그립니다.
   - 패널 「Glue」에서 허리와 연결된 Glue를 「고정점」으로 설정합니다.
3. 도구 막대의 미리보기 스위치를 켜 「참조 시뮬레이션」으로 전환하고, 미리보기에서 고개를 돌리고 몸을 흔들며 재질을 자연스러워질 때까지 조정합니다.
4. 선택한 물리체의 「베이크」 절(편집 영역의 첫 절)에서 「베이크」를 누르거나, 패널 위 도구 막대에서 「모두 베이크」를 누릅니다. 베이크는 몇 초가 걸리며 백그라운드에서 진행되고, 그동안 다른 내용을 계속 편집할 수 있습니다. 끝나면 그때의 최신 버전 위에 별도의 실행 취소 단계로 제출됩니다. 도구 막대의 「자동 베이크」 스위치는 기본이 꺼져 있습니다. 켜면 패널의 수정마다 바로 제출되고, 이어서 백그라운드에서 다시 베이크됩니다. 베이크 뒤 물리 패널에 출처가 「시뮬레이션」인 진자 그룹이 나타나고, 파라미터 패널에 `ParamSim…` 파라미터가 나타나며, 내보내기에 이들이 포함됩니다.
5. 미리보기 스위치를 꺼 「내보내기 결과」로 돌아가면, 미리보기가 재생하는 것이 내보낸 모델의 모션이며 참조 시뮬레이션과 대조할 수 있습니다.

### 패널 배치

패널은 물리 패널과 같은 배치를 씁니다.

- **도구 막대**: 한 줄에 차례로 「새로 만들기」(천 / 머리카락), 「모두 베이크」, 「자동 베이크」 스위치, 미리보기 스위치(끄면 「내보내기 결과」, 켜면 「참조 시뮬레이션」, 라벨은 지금 있는 쪽을 표시)가 있고, 다음 줄은 베이크 상태입니다. 오른쪽은 모두 펼치기와 모두 접기(물리체 목록과 편집 영역의 각 절)이며, 참조 시뮬레이션일 때 맨 오른쪽에 초기화 버튼이 하나 더 있어 실시간 시뮬레이션을 정지로 되돌립니다. 「새로 만들기」는 선택한 메시로 물리체를 만들며, 이름은 `sim`에 첫 메시에서 `ArtMesh` 접두사를 뺀 이름을 붙입니다(예: `ArtMeshBottomwear` → `simBottomwear`, 이름이 겹치면 번호를 더함). 「모두 베이크」는 베이크되지 않았거나 만료된 활성 물리체를 차례로 베이크하고, 뒤의 물리체는 앞의 베이크 결과 위에서 베이크하며, 모두 끝나면 실행 취소 한 단계로 제출됩니다. 모두 최신이면 다시 누르면 전부 다시 베이크합니다. 베이크 중에도 계속 편집할 수 있고, 다른 물리체를 다시 베이크할 수도 있습니다(대기열에 넣고 다음 베이크). 어떤 물리체의 설정이 베이크 중에 바뀌면 그 결과는 이전 설정으로 제출되지 않고 다시 베이크됩니다. 베이크 중에 삭제된 물리체는 결과를 버립니다. 「자동 베이크」는 이 컴퓨터의 인터페이스 환경설정이며 프로젝트와 함께 저장되지 않고 기본은 꺼져 있습니다. 버튼 오른쪽에는 상태 개수가 표시됩니다. 베이크할 것이 있으면 노랑으로 「1/2개 베이크 대기」를 표시하고, 아니면 「2/2개 베이크됨」을 표시합니다. 베이크 중에는 버튼이 취소로 바뀌고(취소하면 어떤 결과도 제출하지 않음), 상태 자리에는 현재 물리체, 번호, 진행이 표시됩니다. 개별 물리체 베이크가 실패하면 그 이전 베이크를 남기고 목록 아래에 안내하며, 나머지는 그대로 제출됩니다.
- **목록**: 접을 수 있는 「물리체」 폴더입니다. 각 줄 왼쪽 체크 상자는 물리체를 켜거나 끄고, 오른쪽은 베이크 상태와 유형입니다. 베이크된 것은 초록 점만 표시하고, 주의가 필요한 상태만 글을 씁니다(노랑 만료는 내보내기가 여전히 이전 결과를 쓴다는 뜻, 빨강 베이크되지 않음은 내보내지 않는다는 뜻, 회색 꺼짐). 오른쪽 클릭 메뉴에서 베이크, 베이크 지우기, 삭제를 할 수 있습니다.
- **편집 영역**: 제목 줄은 이름과 유형입니다(전환하면 그 유형의 재질 프리셋이 적용됨). 그다음은 차례로 「베이크」「재질」「입력」「출력」「Glue」「정점 가중치 그룹」입니다. 베이크 절은 먼저 본 적 없는 모션에서의 시각 검사(진폭 비, 지연, 되돌아옴, 흔들림. 차이가 보이면 경고색)를 표시하고, 그다음은 R²와 오차(끝에 닿거나 더 흔들리면 따로 경고)이며, 그다음은 「베이크 / 다시 베이크」「베이크 지우기」, 모드 수, 상하 파라미터, 키, 과장입니다. 모드를 쓰는 방식, 학습에 참여하는 모션, 정확한 포즈, 각 모드의 진폭은 「고급」에 들어 있습니다. 「비교」 절(기본은 접힘)은 베이크 결과와 참조 시뮬레이션을 함께 보는 데 쓰입니다. [내보내기 결과와 참조 시뮬레이션](#내보내기-결과와-참조-시뮬레이션)을 참고하세요. 재질 절 위에서는 이름 있는 프리셋을 고를 수 있고, 재질을 바꾼 뒤 절 제목에 「이 유형의 프리셋으로 되돌리기」 버튼이 나타납니다. 입력 절은 줄마다 파라미터 이름과 ID를 나열하고, 모델에 더 이상 없는 파라미터는 경고색으로 「없음」이라고 표시합니다. 베이크 뒤 각 입력 아래에는 그것이 물체를 얼마나 멀리 움직이는지가 표시되고, 제외된 것은 경고색으로 「제외됨」이며 「유지」 체크 상자가 있습니다. 그 아래 한 줄은 학습 범위입니다. 입력이 기본과 다르면 절 제목에 「기본 입력으로 되돌리기」 버튼이 나타나고, 입력이 없으면 베이크할 수 없다고 경고합니다. 출력 절은 베이크 뒤에 생성된 모드 파라미터와 진자(이름과 ID)를 나열합니다. 이름을 클릭하면 바꿀 수 있고, 비우거나 기본 이름으로 되돌리면 물리체 이름으로 돌아갑니다. 각 모드 파라미터 아래에서는 ID, 범위, 게인을 바꿀 수 있습니다.

## 정점 가중치 그룹

가중치 그룹은 각 메시 위의 정점별 0–1 가중치이며, 이 소프트웨어에만 있고 `.moc3` / `.cmo3`에는 기록되지 않습니다. 메시마다 종류마다 그룹이 하나이며, 종류로 구분하고 이름을 붙일 필요가 없습니다. 「시뮬레이션」 모드에서 가중치 페인트나 가중치 그라데이션으로 그립니다([캔버스 편집](CANVAS_EDITOR.md) 참고). 왼쪽 도구 모음은 가중치 도구 아래에 각 종류를 나열하며(`1`–`5`로도 전환), 클릭하면 그릴 그룹이 바뀝니다. 가중치 페인트도 원, 직선, 사각형 붓끝을 고를 수 있습니다. 토폴로지 편집 뒤에는 정점 출처에 따라 보간해 유지됩니다.

| 종류 | 작용 |
| --- | --- |
| 고정점(`1`) | 리그에 붙잡히는 정점. 가중치는 얼마나 단단히 고정되는지를 나타냅니다 |
| 강성(`2`) | 정점별로 늘어남과 굽힘 강성을 확대·축소합니다. 뿌리는 단단하고 밑단은 부드럽게 할 때 씁니다 |
| 형태(`3`) | 정점별로 원화 형태로 되돌아가는 정도를 확대·축소합니다 |
| 질량(`4`) | 정점별로 질량을 확대·축소합니다 |
| 감쇠(`5`) | 정점별로 감쇠를 확대·축소합니다 |

패널 「정점 가중치 그룹」은 대상 메시에 각 종류의 그룹이 그려져 있는지를 나열합니다. 각 줄의 「그리기」는 첫 대상 메시를 선택하고, 캔버스를 「시뮬레이션」 모드로 바꾸며, 그 종류의 가중치 페인트를 엽니다. 바람 같은 힘장은 아직 구현되지 않아, 패널과 가중치 페인트는 「바람」 그룹을 제공하지 않습니다. MCP의 `vertex_group_update` / `vertex_group_paint`는 여전히 `wind`를 받으며, `simulation_simulate`에 `wind`를 넘길 때만 작용합니다. MCP는 이름 있는 그룹을 계속 쓸 수 있고, 물리체의 `groups`에서 이름으로 지정합니다. 같은 종류에 그룹이 여러 개이면 지정하지 않았을 때 첫 번째, 즉 인터페이스가 그린 것을 씁니다.

## Glue

Glue는 자동으로 고정점이 되지 않습니다. 시뮬레이션 메시와 연결된 각 Glue는 패널에서 따로 고릅니다.

| 역할 | 작용 |
| --- | --- |
| 참여하지 않음(기본) | 시뮬레이션이 그것을 무시하고, 런타임에서만 용접합니다 |
| 고정점 | 시뮬레이션 쪽의 Glue 정점이 다른 메시의 실제 변형을 따릅니다. 예를 들어 치마와 허리 |
| 양방향 제약 | 양쪽이 모두 시뮬레이션 중일 때 이음매가 이어지게 합니다. 예를 들어 나뉜 앞뒤 조각 |

## 재질

| 항목 | 의미 |
| --- | --- |
| 질량 | 상대 밀도입니다. 각 정점의 질량은 그것이 나눠 가진 메시 면적(주변 삼각형 면적의 3분의 1)으로 계산되므로, 메시를 촘촘히 하거나 다시 나누면 변형 세부만 늘고 천이 무거워지거나 부드러워지지는 않습니다 |
| 늘어남 | 길어지는 것에 저항하는 정도입니다. 천과 머리카락은 1에 가까워야 합니다 |
| 굽힘 | 얼마나 급하게 굽을 수 있는지입니다. 인접 삼각형이 돌아간 각도 차이입니다. 굽힘만 다루고 수축은 다루지 않습니다 |
| 면적 | 각 삼각형이 면적을 유지하는 정도입니다. 정면에서 보면 천은 깊이 방향으로 접힐 때 짧아지고 겹칩니다. 낮은 값은 얇은 천이 이렇게 수축하게 하고, 높은 값은 두꺼운 파츠가 형태를 유지하게 합니다. 값을 어떻게 두어도 삼각형은 뒤집히거나 면적이 0이 되지 않습니다 |
| 결 | 결을 가로지르는 방향이 결 방향보다 얼마나 더 부드러운지입니다. 결 방향은 자동으로 「고정점에서 멀어지는 방향」(메시를 따라 잰 경로 길이가 늘어나는 방향)을 취하고, 고정점이 없으면 수직 아래를 취합니다. 값이 높으면 머리카락 묶음은 길이를 따라 늘어나지 않지만 좌우로 갈라지고 길이를 따라 접힐 수 있습니다 |
| 감쇠 | 움직임이 잦아드는 빠르기(초당)입니다 |
| 형태 | 원화 형태로 되돌아가는 스프링입니다. 0은 순수 물리입니다. 단위 질량 기준이므로 메시의 성김은 되돌아가는 빠르기를 바꾸지 않습니다 |
| 여유 | 세게 휘둘릴 때 정점이 고정점에서 떨어진 거리가 정지 경로를 최대 얼마나 넘을 수 있는지입니다 |

기본값: 천은 면적 0.3, 결 0.3. 머리카락은 면적 0.5, 결 0.7. 소매, 바지, 다리 착용 프리셋은 면적 0.5, 목 장식은 0.4입니다.

「프리셋」 드롭다운은 이름 있는 재질 하나의 수치를 위 표의 각 항목에 채우며, 그 뒤에도 계속 조정할 수 있습니다. 프로젝트는 수치만 저장합니다. 수치가 어떤 프리셋과 같으면 드롭다운이 그 이름을 표시하고, 아니면 「사용자 지정」을 표시합니다.

| 유형 | 프리셋 | 특징 |
| --- | --- | --- |
| 천 | 면(기본) | 위 표의 기본값 |
| 천 | 실크 | 가볍고 부드럽고, 주름이 가늘며, 흔들림이 길게 이어지고 늦게 멈춥니다 |
| 천 | 시폰 | 가장 가볍고 부드럽습니다. 실크보다 공기 감쇠에 더 빨리 멈춥니다 |
| 천 | 울 | 무겁고 부드럽습니다. 흔들리기 시작하고 빨리 멈춥니다 |
| 천 | 데님 | 무겁고 단단합니다. 주름이 넓고 형태를 유지합니다 |
| 천 | 가죽 | 가장 단단합니다. 전체가 흔들리고 거의 겹치지 않으며, 원화 형태로 되돌아갑니다 |
| 천 | 신축 소재 | 늘어났다가 되돌아옵니다. 밴드, 양말에 맞습니다 |

| 머리카락 | 굵은 머리카락 | 비교적 무겁고, 묶음 전체가 흔들리며 형태를 유지합니다 |
| 머리카락 | 앞머리 | 아래로 늘어지지 않고 이마에 붙습니다. 되돌아감이 더 세고 감쇠가 더 크며, 머리를 따르고 끝은 살짝 늦습니다. 앞머리 프리셋이 사용합니다 |

시뮬레이션을 시작하기 전에 먼저 보정하여, 원화 형태가 바로 정지 때의 평형 위치가 됩니다. 그래서 시뮬레이션을 켜도 정지한 모델은 처지지 않습니다.

솔버는 2차원 XPBD입니다(프레임마다 하위 단계 16개). 리그가 어디를 늘리면(예를 들어 고개를 돌릴 때의 시차) 그곳의 정지 길이도 함께 길어져 리그의 조형과 맞서지 않습니다. 리그가 어디를 줄이면 깊이 방향으로 돌아간 것으로 보고, 부드러운 압축이 맡습니다.

## 베이크

「입력」은 물체를 흔드는 파라미터이며, 목록 그대로 쓰이고 숨은 기본값은 없습니다. 물리체를 새로 만들 때(패널, MCP가 `inputs`를 주지 않음, 모델 프리셋) 기본 입력을 기록합니다. 머리와 몸 각도(모델에 있는 `ParamAngleX`, `ParamAngleZ`, `ParamBodyAngleX`, `ParamBodyAngleZ`), 그리고 끄덕임, 몸 상하, 앞뒤 기울기(있는 `ParamAngleY`, `ParamBodyAngleY`, `ParamBodyLean`)입니다. 천 유형의 상하 입력은 `ParamBodyAngleY`만 취합니다. 옷은 몸에 달려 있어 끄덕임이 그것을 움직이지 않습니다. 앞뒤 기울기는 주로 다른 포즈에 멈추게 할 뿐이고, 상하 진자는 정적 오프셋을 표현하지 못해, 복원력이 거의 없고 매우 큰 출력 배율로 키운 진자로 맞춰집니다. 의상 프리셋을 다시 적용할 때, 여전히 이전 범용 기본 입력을 쓰던 물리체는 천 기본 입력으로 바뀝니다. 목록이 비어 있으면 입력이 없다는 뜻이며 베이크는 오류를 보고합니다. 이전 프로젝트에서 입력이 기록되지 않은 물리체(그때는 기본을 쓴다는 뜻)는 연 뒤 위의 완전한 기본 목록으로 표시되고, 모델에 없는 파라미터는 그 물리체를 다음에 수정할 때 제거됩니다. 기본 입력과 그때의 「비어 있음」은 같은 것으로 보며, 이미 있는 베이크는 이 때문에 만료되지 않습니다.

베이크는 먼저 리그에서 각 입력이 물체를 어떻게 움직이는지 읽습니다. 학습 범위 안에서 어떤 정점도 1px 미만으로만 움직이는 입력은 베이크에 참여하지 않습니다(패널은 「제외됨」으로 표시. 「유지」를 체크하거나 MCP `force_inputs`로 강제 유지). 물체를 좌우보다 상하로 더 많이 움직이는 입력은 상하 파라미터로 들어갑니다(아래 참고). 나머지는 좌우 모드로 들어갑니다. 그래서 기본 입력 중 그 파츠와 관계없는 파라미터(예를 들어 치마 위의 고개 돌리기)는 더 이상 진자에 맞춰지지 않고, 사용자가 그 파라미터를 움직여도 물체가 이유 없이 흔들리지 않습니다.

각 입력은 학습 범위를 설정할 수 있습니다(하한에서 상한, 파라미터 단위). 베이크는 이 범위 안에서만 그것을 구동하며, 기본은 파라미터 전체 범위입니다. 범위는 항상 기본값을 포함하고, 파라미터 범위를 넘는 부분은 잘립니다. 모드 파라미터는 학습 중 가장 격한 움직임으로 눈금을 정하므로(단계 4 참고), 범위가 좁을수록 범위 안에서 더 충분히 흔들리고, 범위를 넘은 뒤에도 더 일찍 끝에 닿습니다. 예를 들어 `ParamBodyAngleX`가 평소 ±5 안에서만 움직이면, 학습 범위를 ±5로 두면 일반적인 모션도 모드 파라미터를 가득 쓸 수 있습니다. 학습 범위가 바뀌면 베이크가 만료됩니다. 입력이 제거되면 그 학습 범위와 유지 설정도 함께 제거됩니다.

「학습에 참여하는 모션」(「고급」 안, MCP `training_clips`)은 베이크가 설계된 가진 외에 모델 자신의 모션(사용자 모션 또는 내장 Idle, Nod, Shake 등)을 더 학습하게 합니다. 각각 ×0.05–×1로 가중하며, 주로 소수의 고정 모션으로 구동하고 얼굴 추적을 쓰지 않는 모델에 맞습니다. 각 모션은 그것이 가장 많이 움직이는 파라미터 묶음에만 들어갑니다. 이 모션을 편집한 뒤에는 다시 베이크해야 합니다(모션 내용은 만료 판정에 들어가지 않음).

「출력」은 베이크가 기록하는 모드 파라미터와 진자입니다. 이름은 기본적으로 물리체 이름을 따릅니다(파라미터는 「<이름>」「<이름> 2」「<이름> Y」 등, 진자는 물리체와 같은 이름). 이름 변경은 물리체에 저장되고 다시 구축할 때 적용되며, 다시 베이크할 필요가 없고 ID는 바뀌지 않습니다. 각 모드 파라미터는 기록할 때의 ID, 범위, 게인을 따로 설정할 수 있으며, 마찬가지로 다시 베이크할 필요가 없습니다. ID 기본은 생성된 `ParamSim<id>_<k>`이고, 다른 ID로 바꿔 그 ID로 만든 모션과 물리를 이어 쓸 수 있지만, 모델의 다른 파라미터나 이 물리체의 입력과 이름이 겹치면 안 됩니다. 범위는 ±1…±100이고 기본은 ±30이며, 키와 진자의 출력 배율이 함께 확대·축소되고 움직임은 바뀌지 않습니다. 게인은 ×0…×3이고 기본은 과장 계수이며, 0은 정지입니다. 베이크 결과 자체는 항상 생성된 ID와 ±30으로 저장되고, 이 설정은 다시 구축할 때 적용됩니다. 물리 패널에서 「시뮬레이션」 출처의 진자 이름을 바꿔도 여기에 기록되며, 진자는 여전히 베이크가 구동합니다.

### 설정

| 항목 | 의미 |
| --- | --- |
| 모드 수(1–3, 기본 2) | 파라미터를 몇 개 만들지입니다. 각각 맞춰진 진자의 정점 하나가 구동합니다. 첫 모드는 전체 흔들림입니다. 그 뒤의 모드는 아래에 더 단 마디 또는 독립 진자이며, 위의 모드가 표현하지 못하는 부분만 보충합니다. 물체가 늦을 때의 굽힘, 겹침, 압축입니다. 모드가 1개뿐이면 형태는 진자각에 따라 전체만 이동하고 천의 압축감이 없으므로 기본은 2개입니다. 긴 머리카락 묶음, 리본은 3개를 쓸 수 있습니다 |
| 상하 파라미터(자동 / 켜기 / 끄기) | 상하 방향 입력을 `ParamSim<id>_Y`로 따로 베이크할지입니다(아래 참고). 「자동」은 그것이 물체를 2px 이상 움직일 때만 생성합니다. 「켜기」는 항상 생성합니다. 「끄기」이면 상하 입력은 베이크에 참여하지 않으며, 상하 입력만 있으면 오류를 보고합니다 |
| 키(3 / 5 / 7 / 9) | 각 모드 파라미터와 각 정확한 포즈 파라미터 위의 키 수이며, 고르게 분포합니다. 많을수록 호에 더 붙고, 늘어나는 것은 키폼이지 파라미터가 아닙니다 |
| 과장(×1–×2, 기본 ×1.3) | 모드 흔들림이 시뮬레이션보다 얼마나 큰지입니다. 키폼을 다시 기록할 때 적용되며, 바꾸면 바로 작용하고 다시 베이크할 필요가 없으며 파라미터가 끝에 닿게 하지도 않습니다. 2차원 스타일은 보통 실제보다 약간 큰 편이 보기 좋습니다 |
| 정확한 포즈 | 자기 축 위에 정확한 보정으로 베이크하는 파라미터입니다(최대 네 개). 기본은 베이크하지 않습니다 |
| 모드를 쓰는 방식 | 「자동」(기본), 「블렌드 변형」, 또는 「키폼 축」입니다. 두 기록 방식의 재생 효과는 같습니다. 키폼 축은 모든 Cubism 버전이 읽을 수 있지만, 각 모드가 메시의 키폼 수에 자기 키 수를 곱합니다. 블렌드 변형(Cubism 4.2+)의 키폼은 기존 키폼 위에 겹칩니다. 「자동」은 어떤 대상 메시의 키폼이 64개를 넘을 때만 블렌드 변형을 쓰고, 대상 버전이 지원하지 않으면 모두 키폼 축으로 기록합니다 |

블렌드 변형이 아끼는 것은 키폼이지 파라미터가 아닙니다. 예를 들어 메시 한 장에 원래 키폼이 9개이고, 모드 2개에 각각 키 5개이면, 키폼 축으로 쓰면 9 × 5 × 5 = 225개이고, 블렌드 변형으로 쓰면 9개에 블렌드 형태 8개를 더한 것입니다.

### 단계

1. **정확한 포즈**: 리그를 각 정확한 포즈 파라미터의 각 키에 두고 물체를 정지시킨 다음, 리그와의 차이를 그 파라미터 축 위의 보정 키폼으로 기록합니다. 정확한 포즈 파라미터를 지정하지 않으면 이 단계를 건너뜁니다.
2. **입력마다 구동**: 베이크에 참여하는 각 입력을 따로 구동하고, 다른 입력은 기본값에 둡니다. 한 구간은 0.15초 안에 학습 범위 상한으로 돌고, 물체가 정지할 때까지 멈추며(최대 1.6초), 기본으로 돌아갔다가 하한으로 돌고 다시 돌아옵니다. 한 구간은 0.25 Hz에서 3 Hz까지의 로그 스윕이며, 3 Hz 근처에서 진폭이 점점 줄어듭니다. 각 구간은 정지에서 시작하고, 각자의 물체 복제본에서 병렬로 시뮬레이션하며, 좌우와 상하 두 묶음이 이 시뮬레이션을 공유합니다. 프레임마다 물체와 리그(정확한 포즈 보정을 더함)의 차이를 기록하고, 각 메시 자신의 키폼 좌표로 바꿉니다. 각 묶음에는 그 묶음 입력이 함께 드래그되고, 흔들리고, 한가하게 흔들리는 구간이 하나 더 있으며, 이것은 검사에만 씁니다. 각 구간은 운동량에 맞춰 가중합니다(최대 100배 차이). 물체를 적게 움직이는 입력도 맞게 맞춰져야 하며, 크게 휘두르는 입력에 눌리지 않습니다.
   이전에는 모든 입력이 같은 구간 안에서 각자 무작위로 움직여, 맞춤이 어느 입력이 물체를 움직였는지 구분하지 못했습니다. `tml` 뒷머리에서 `ParamBodyAngleX`가 머리카락 뿌리를 약 70px 옮기는데 진자는 영향도를 1%만 주었고, 마우스를 따라 드래그할 때 내보낸 진폭은 시뮬레이션의 약 20%뿐이었습니다. 입력마다 구동한 뒤에는 각 입력이 물체를 그 방식대로 움직이게 하는 영향도를 얻습니다.
3. **진자**: Cubism 진자 `PhysicsSim_<id>` 하나를 맞춥니다. 마디 수는 모드 수와 같고, 모드마다 맞춥니다. 먼저 첫 모드의 그 마디만 맞추고, 그다음 뒤의 모드를 하나씩 맞춥니다. 각 모드는 위의 각 모드가 읽어 내지 못하는 남은 움직임만 맞추며, 이 남은 움직임 자신의 주 방향 안에서 맞춥니다(전체 움직임의 주 방향이 아님). 마지막에 모든 마디와 영향도를 함께 한 번 미세 조정합니다. 읽어 내는 것은 항상 모드 순서대로 하나씩 구합니다. 뒤의 모드에는 후보가 두 종류 있습니다. 진자 아래에 마디를 하나 더 다는 것(진자의 정점은 위의 정점 영향만 받으므로 마디를 더해도 위의 모드는 바뀌지 않음. 시작점 4개에서 검색), 또는 독립된 단일 마디 진자 `PhysicsSim_<id>_<k>`를 쓰는 것(자기 입력, 진자 길이, 반응 속도가 있음. 압축은 가속도에 대한 반응이 흔들림보다 더 빠르고 단단할 수 있음). 검사 모션에서 더 나은 쪽을 쓰며, 파라미터 수는 바뀌지 않습니다. 함께 맞추면 이웃 정점의 진자각이 거의 동기화되어 두 모드의 형태가 매우 커지고 서로 상쇄되며, 학습 밖의 모션에서 왜곡됩니다. 점수는 오차만이 아니라 전체 효과를 봅니다. 시뮬레이션을 따르는 정도, 입력이 멈춘 뒤 휘둘리고 되돌아오는 정도(따로 한 번 더 계산), 각 구간 모션이 시뮬레이션보다 더 흔들리는지입니다. 각 입력의 유형(X 이동 또는 각도)과 초기 영향도는 작은 폭을 겹친 최소제곱으로 추정합니다(입력이 6개를 넘지 않으면 모든 유형 조합을 하나씩 비교해 남은 오차가 가장 작은 것을 취함). 그다음 Nelder–Mead가 각 마디의 진자 길이, 반응 속도, 스윙도, 수렴 속도, 각 입력의 영향도를 동시에 검색합니다. 각 후보는 내보내기와 같은 계산으로, 실제 진폭에 맞춰 모든 학습 모션을 한 번 재생한 다음 점수를 매깁니다. 후보 몇 개 중 검사 모션에서 점수가 가장 좋은 것이 이깁니다.
4. **모드 파라미터**: 진자 k번째 정점의 각도를 -30…30의 파라미터 `ParamSim<id>_<k>`에 기록합니다. 출력 배율은 진자가 모든 학습 모션과 검사 모션에서 보인 최대 진자각에 10% 여유를 더해 정하므로, 파라미터가 ±30에 닿지 않습니다. 파라미터가 끝에 멈추면 머리카락도 멈추고, 그것이 버벅임으로 보입니다. 파라미터 범위를 ±1이 아니라 ±30으로 하는 것은, 키폼 축이 키에서 0.001 이내의 값을 키에 붙이기 때문입니다(Cubism 런타임도 같음). ±1 범위에서는 큰 물체가 정지 위치를 지날 때마다 이 붙임에 한 번 걸립니다.
5. **키폼**: 모드마다 최소제곱으로 풉니다. 각 모드의 키폼은 앞의 각 모드가 설명한 뒤 남은 형태를 맞추고, 프레임마다의 형태는 각 파라미터가 진자 재생 값에 있는 키폼 보간의 합과 같습니다. 키폼은 부드러운 곡선 하나로 제약되며, 이웃 키에서 급히 꺾이지 않고 정지 키에서는 직선이 통과합니다. 그렇지 않으면 파라미터가 키를 스칠 때 속도가 갑자기 바뀌어 또 다른 버벅임이 됩니다. 그다음 검사 모션에서 두 가지 조정을 하며, 더 잘 따르고 더 흔들리지 않을 때만 채택합니다. 각 모드의 키폼에서 다른 모드를 뺀 뒤 각각 한 번 더 풉니다(함께 푸는 쪽에 더 가깝고, 서로 상쇄하지는 않음). 뒤의 모드는 ×0.25, ×0.5, ×0.75 게인을 시험해, 작은 모션에서 방해하지 않게 합니다. 거의 움직이지 않는 파라미터는 생성하지 않습니다.

**상하 방향은 따로 베이크**: Cubism의 진자는 중력을 따라 늘어지고 각도만 출력하므로, 뿌리가 수직으로 위아래 이동해도 각도는 바뀌지 않습니다. 그래서 상하 운동은 입력을 어떻게 설정해도 그것을 구동하지 못합니다. 방법은 작가가 쓰는 `裙y`, `长发y` 물리 그룹과 같습니다. 물체를 좌우보다 상하로 더 많이 움직이는 입력(보통 끄덕임, 몸 상하, 앞뒤 기울기)을 다른 입력과 나누고, 단계 3–5를 한 번 따로 실행합니다. 단일 마디 진자 `PhysicsSim_<id>_y` 하나를 맞추고, 모드 파라미터 `ParamSim<id>_Y`(이름은 “<시뮬레이션 이름> Y”)를 구동합니다. 키폼은 물체가 상하로 늦고 되튀는 형태입니다. 두 묶음 파라미터의 키폼은 메시 위에서 더해집니다. 상하 운동이 2px에 못 미치면 이 파라미터를 만들지 않습니다(상하 파라미터를 「켜기」로 두면 항상 만들고, 「끄기」로 두면 만들지 않으며 상하 입력은 베이크에 참여하지 않음). 상하 입력만 있으면 모든 모드를 이 방식으로 맞춥니다. `tml` 치마: 쪼그리기 / 일어설 때 시뮬레이션의 잔차는 최대 47px였고, 원래 베이크 뒤에는 정적 기울기 하나만 남았습니다. 나눠 베이크한 뒤 검사 모션의 R²는 0.37에서 0.61로 올랐습니다.

R²만이 보기에 맞는지의 유일한 기준은 아닙니다. 진폭이 작고 위상이 조금 어긋나면 최소제곱이 키폼 전체를 줄여 더 낮은 오차를 바꾸므로, 내보낸 모션이 생기가 없어 보입니다. 그래서 베이크가 끝나면 패널은 먼저 각 묶음이 검사 모션에서 보인 시각 검사를 표시합니다.

| 지표 | 의미 | 경고 |
| --- | --- | --- |
| 진폭 | 끝(움직임이 가장 큰 10분의 1 정점)이 시뮬레이션 주 방향을 따라 흔들린 것. 내보내기와 시뮬레이션의 비 | ×0.75–×1.3 밖 |
| 지연 | 내보내기가 시뮬레이션보다 몇 밀리초 늦은지(상호상관 봉우리) | 80 ms 초과 |
| 되돌아옴 | 입력이 멈춘 뒤 정지로 돌아오는 데 필요한 시간. 내보내기와 시뮬레이션의 비 | ×0.6–×1.6 밖 |
| 흔들림 | 3차 차분 에너지 비의 제곱근 | ×1.5 초과 |

방향이 반대여도 마찬가지로 경고합니다. MCP는 방향 일치도, 되흔들림 횟수 차이, 끝에 닿거나 걸린 프레임 비율, 머리카락이 짧아진 정도, 정지 때의 편차도 반환합니다. 그 다음 줄은 R²와, 프레임의 95%가 시뮬레이션과 떨어진 최대 편차입니다. 프레임이 끝에 닿거나 저크가 시뮬레이션의 1.5배를 넘으면 따로 한 줄 경고합니다. 각 모드 파라미터의 진폭은 「고급」에 있습니다. MCP `simulation_bake`는 모든 지표와 각 입력의 읽기 결과(`inputs`)를 반환합니다.

베이크된 진자 그룹은 일반 생성 그룹과 같이 물리 패널에서 보고, 수정하거나 끌 수 있습니다. 물리 패널의 수정은 생성된 진자에 대한 덮어쓰기입니다. 다시 베이크하거나 출력의 ID, 범위를 수정하면, 덮어쓰기는 3자 병합으로 새 진자에 옮겨집니다. 사용자가 바꾼 필드만 남고(출력 배율은 원래 값과의 비율로 유지), 나머지는 새로 맞춘 값을 취하며, 출력은 파라미터 이름 변경을 따르고, 바꾼 뒤 새 진자와 같은 덮어쓰기는 제거됩니다. 베이크를 지우거나, 물리체를 삭제하거나, 새 베이크가 어떤 진자를 더 이상 만들지 않으면, 그 덮어쓰기, 꺼짐 상태, 순서가 함께 제거됩니다.

### 효과와 소요 시간

모델 프리셋이 생성한 물리체(모드 2, 키 5, 과장 ×1)를, 베이크 때 나타나지 않은 13–15구간 모션에서 참조 시뮬레이션과 내보낸 모델(Cubism 진자 + 키폼)을 프레임마다 비교했습니다. 얼굴 추적에 가까운 마우스 따라가기, 머리와 몸 좌우 기울기, 내장 Idle / Nod / Shake, 각 입력의 계단, 고개 돌리기, 드래그, 흔들기입니다. 시뮬레이션에서 끝이 10px 이상 움직인 모션만 셉니다(괄호 안은 구간 수). 나머지 모션은 제외된 입력만 구동하므로, 시뮬레이션에는 물체가 출발할 때의 가벼운 흔들림만 있고, 넣으면 각 지표가 0 쪽으로 끌립니다. 「방향 맞음」은 흔들림 방향이 일치하는(코사인 ≥ 0.9) 모션 수이고, 진폭은 각 모션의 내보내기와 시뮬레이션 비가 1에서 벗어난 중앙값을 배수로 되돌린 것이며, R²는 각 모션의 평균(-1보다 낮으면 -1로 계산)이고, 정지 편차는 입력이 1초 이상 멈췄을 때 내보내기와 시뮬레이션의 거리(95% 분위)입니다. 앞 열은 원래 모션 라이브러리로 학습한 결과이고, 뒤 열은 입력마다 구동한 결과입니다.

- 머리카락 개선이 가장 크고, 실제 사용에 가까운 모션에서 특히 분명합니다. tml 뒷머리가 마우스를 따를 때 진폭은 시뮬레이션의 0.19배에서 1.04배로, R²는 -0.15에서 0.92로, Shake 모션의 R²는 0.07에서 0.83으로, `ParamBodyAngleX` 계단은 완전히 움직이지 않던 것에서 R² 0.86으로 갔습니다.
- 천은 입력마다 구동한 뒤 베이크가 2–4배 빠르지만, R²는 원래보다 못합니다(치마, 상의 0.3 전후, 원래 0.35–0.5). 상하 파라미터는 여전히 약합니다(`ParamBodyAngleY` 계단 R² 0.17–0.30, 진폭 0.2–0.8배). 시뮬레이션에서 몸이 위로 움직일 때와 아래로 움직일 때 치마 자락이 모두 같은 쪽으로 휘둘리고, 되흔들림도 한쪽에만 있는데, 진자 출력은 입력의 양음에 대칭이라 맞춤은 절충할 수밖에 없습니다.
- 뒷머리가 몸 좌우 기울기(`ParamBodyAngleZ`)에 흔들리는 주기(약 1.3초)는 고개 돌리기(약 0.9초)와 다르고 형태도 달라, 모드 2개로는 그것에 나눠 주지 못합니다(ds 뒷머리 내보내기는 거의 움직이지 않고, tml 뒷머리는 진폭 0.59배, R² 0.11). 모드 3개로 바꿔도 개선되지 않았습니다.
- 고개를 돌리는 등 천을 거의 움직이지 않는 입력(시뮬레이션은 2px 전후만 움직임)은 바로 제외되므로, 사용자가 고개를 돌려도 치마가 이유 없이 흔들리지 않습니다.

시간은 32스레드 데스크톱에서 측정했습니다. 시뮬레이션과 맞춤은 여러 코어에서 병렬이며, 코어가 적으면 더 느립니다. 위 표는 개발 도구 `SimBakeSuite`가 생성하며, 각 구간 모션의 모든 시각 지표와 끝 궤적 그림을 출력합니다. 사용법은 [개발 도구](DEVELOPMENT.md#개발-도구)를 참고하세요.

### 만료

베이크는 그것이 근거한 설정, 대상 메시, 가중치 그룹, 관련 Glue, 솔버 버전을 기록합니다(솔버가 바뀐 뒤 이전 프로젝트의 베이크는 만료로 표시). 이들이 바뀌면 패널이 베이크가 만료되었다고 알립니다. 도구 막대의 자동 베이크를 켜면, 패널의 수정이 제출된 뒤 백그라운드에서 다시 베이크합니다(별도의 실행 취소 단계). 이전 진자에서 검색을 시작하므로 처음부터 베이크하는 것보다 빠릅니다. 모델 프리셋을 적용해도 먼저 제출한 다음, 그것이 생성한 물리체를 백그라운드에서 베이크합니다. MCP `simulation_put`은 물리체 자신의 `auto_bake`(기본 켜짐)로 결정합니다. 다른 곳에서 한 수정(메시, 가중치)은 여전히 만료로 표시됩니다. 만료된 베이크도 내보내지며, 「다시 베이크」를 누르면 갱신됩니다. 「베이크 지우기」는 그 파라미터, 키폼, 진자를 제거합니다. 자동 베이크가 실패하거나 취소되면 이전 베이크를 남기고 이유를 알립니다. 대상 메시가 다시 구축되면(정점 수가 변함) 그 메시의 베이크 결과는 건너뛰고 패널에 알립니다.

### 내보내기 결과와 참조 시뮬레이션

패널 위와 캔버스 「시뮬레이션」 모드의 도구 막대에서 미리보기 내용을 전환할 수 있습니다.

- **내보내기 결과**: 미리보기가 베이크 결과, 즉 맞춰진 Cubism 진자가 구동하는 파라미터와 키폼을 재생하며, 내보낸 모델 모션과 같습니다. 베이크되지 않은 물체는 여기서 움직이지 않고, 캔버스 왼쪽 아래에 「베이크되지 않은 시뮬레이션이 있습니다」가 표시됩니다.
- **참조 시뮬레이션**: 캔버스가 편집기 자신의 물리 시뮬레이션을 표시하며, 대조에만 쓰고 내보내지 않습니다. 캔버스 왼쪽 아래에 경고색으로 「참조 시뮬레이션 · 내보내지 않음」이 표시됩니다. 이때 그 물리체 자신의 `ParamSim…` 파라미터는 정지를 유지해 두 번 겹치지 않습니다.

물리체 편집 영역의 「비교」 절은 둘을 함께 봅니다.

- **표시**(참조 시뮬레이션이 켜져 있을 때 사용 가능): 첫 미리보기 캔버스에서 참조 시뮬레이션을 표시하는 방식입니다. 「참조」(내보내기 결과를 대신함, 위와 같음), 「내보내기」(내보내기 결과만 표시), 「겹침」(내보내기 결과 위에 반투명한 참조 시뮬레이션을 겹치고, 시뮬레이션되는 레이어만 그림). 캔버스마다 따로 기억하며 작업 공간과 함께 저장됩니다.
- **나란히**: 참조 시뮬레이션을 켜고, 미리보기 캔버스가 두 장 있게 합니다. 첫 장은 내보내기를, 둘째 장은 참조를 표시하며, 둘은 같은 포즈를 따라 동시에 재생됩니다.
- **재생**: 드롭다운에서 모션 하나를 고릅니다(내장 Idle, Nod, Shake, 스켈레톤이 있으면 스켈레톤 모션, 그리고 사용자 모션). 참조 시뮬레이션과 내보낸 진자가 함께 정지로 돌아간 뒤 그것을 재생해, 구간마다 대조하기 쉽게 합니다.
- **검사**: 백그라운드에서 고른 모션으로 참조 시뮬레이션과 내보낸 모델을 각각 구동합니다(게인 ×1). 베이크 절과 같은 시각 검사를 줍니다. MCP는 `simulation_compare`에 대응합니다.

## 모델 프리셋

「모델 프리셋」 패널(이전 「모델 설정」)의 「물리와 시뮬레이션」 그룹은 흔한 파츠를 한 번에 시뮬레이션으로 만들고 베이크합니다. 결과는 일반 가중치 그룹과 물리체이며, 이후에도 「시뮬레이션」 패널에서 조정할 수 있습니다. 패널의 「변형과 입 모양」「모션」「물리와 시뮬레이션」 세 그룹은 모두 파라미터 패널 폴더와 같은 스타일의 접을 수 있는 줄이며, 오른쪽에 요약이 표시됩니다. 「모션」 그룹은 모델에 「기본 모션」과 「스켈레톤 모션」 두 그룹이 있는지만 정하고, 개별 모션은 모션 패널에서 켜고 조정합니다. 「물리와 시뮬레이션」은 항목마다 한 줄입니다. 앞머리와 뒷머리는 각각 드롭다운이 있어 「시뮬레이션 / 클래식 스윙 / 끄기」를 전환합니다. 의상과 젤리 눈은 체크 상자이며, 체크하면 프리셋이 적용되고 해제하면 제거됩니다. 의상의 메시별 헐렁함 목록은 의상 줄 아래에 표시됩니다. 컨트롤 옆의 회색 글은 현재 내용을 설명합니다(시뮬레이션된 의상 부위, 원화에 그 파츠가 없음. 마우스를 올리면 전문이 표시). 베이크되지 않았거나 시뮬레이션체가 삭제되면 경고색으로 알립니다. 위 도구 막대의 「선택만(n)」은 체크가 선택한 레이어에만 작용하게 합니다(체크 해제는 항상 전체를 제거). 오른쪽은 「고정 가중치 자동 설정」입니다. 베이크 진행과 취소는 아래 상태 막대에 있고, 실패 이유는 그룹 안 아래에 표시됩니다. 체크할 때마다 실행 취소 한 단계이며, MCP는 `model_apply_preset` 도구에 대응합니다.

같은 패널의 「부위와 모듈」 그룹은 부위별(머리와 얼굴, 눈, 눈썹, 입과 아랫얼굴, 머리카락, 몸, 의상과 매달린 것, 표정, 모션)로 자동 생성 리그의 모듈을 나열합니다. 카드마다 좌우를 맡고, 모듈마다 한 줄이며, 체크로 켜고, 오른쪽 회색 글은 그것이 현재 소재에 새로 더하는 파라미터, 키폼, 물리 그룹입니다(꺼져 있을 때는 추정값이며 “≈”로 표시). 켠 뒤에는 소량의 조절 값이 표시됩니다. 현재 소재에 적용되는 모듈만 나열합니다. 위의 프리셋(전체 / 표준 / 간소)은 중요도에 따라 한 번에 켜고 끄며, 파라미터 예산은 “중요도가 낮은 것부터 높은 것까지, 파라미터가 많은 것부터 적은 것까지” 모듈을 꺼 새로 더하는 파라미터가 그것을 넘지 않게 합니다. 오른쪽 버튼은 기본으로 되돌립니다. 새 프로젝트는 기본적으로 모두 켜집니다. 모듈을 도입하기 전에 저장된 프로젝트는 예전대로 생성되며, 그룹 위에 업그레이드할 수 있다는 안내가 있습니다. 수정할 때마다 실행 취소 한 단계입니다. MCP는 `module_catalog`로 보고, `settings_update`의 `changes.rig`로 수정합니다. [Rig 프리셋 구조](../spec/RIG_PRESETS.md)를 참고하세요.

「시작」 페이지(작업 공간 탭 막대 맨 왼쪽, 또는 「파일 → 시작 페이지」)의 「PSD에서 생성」은 PSD를 가져오기 **전에** 같은 프리셋을 모읍니다. 속성 패널 위의 「최소 / 기본 / 전체」는 각각 바인딩만 유지(모션, 물리와 시뮬레이션, 입 윤곽선 없음), 모션 두 그룹 + 머리카락 클래식 스윙 + 의상 시뮬레이션 + 젤리 눈, 기본 위에 앞뒤 머리를 시뮬레이션하고 이목구비 이동을 켜는 것에 대응합니다. 아래에서 항목마다 조정할 수 있고, 선택은 기억됩니다. 그 뒤 시작 페이지, 「파일」 메뉴, 최근 파일, 드래그 앤 드롭 중 어디서 PSD를 가져오든, 생성 뒤에 바뀐 프리셋을 실행 취소 한 단계로 기록하고, 이어서 머리카락과 의상 시뮬레이션을 차례로 생성하며(시뮬레이션마다 한 단계), 편집 작업 공간으로 전환합니다. 의상은 기본적으로 켜지며, 원화에서 의상이 인식되면 의상 시뮬레이션을 생성하고 베이크합니다. PSD에서 생성한 모델이 이미 열려 있으면, 「생성」 버튼 메뉴의 「현재 모델에 적용」이 같은 프리셋을 그 위에 씌웁니다. 오른쪽 「가져올 때 독립 메시 검사」를 켜면, 새 PSD 프로젝트는 먼저 나눌 수 있는 레이어를 검사하고, 나누기를 확인하거나 원래대로 둔 다음 프리셋을 적용합니다. 「모델 → 모델 전체의 독립 메시 검사…」에서 직접 검사를 시작할 수도 있습니다.

| 젤리 눈 | 눈의 젤리 진자를 켜고 끕니다 |
| 「고정 가중치 자동 설정」(도구 막대) | 파츠 유형에 따라 선택한 레이어 또는 이미 시뮬레이션된 모든 메시의 위 가중치 그룹을 다시 계산하고, 그것을 쓰는 물리체를 다시 베이크합니다. 물리체를 새로 만들지는 않습니다 |

프리셋이 기록하는 그룹 이름은 `preset_pin`, `preset_mass`, `preset_wind`입니다. 물리체가 `groups`에서 자기 그룹을 이미 지정했으면 그 그룹을 그 자리에서 새로 고칩니다. 같은 프리셋을 다시 적용하면 원래 물리체를 갱신하고 겹치지 않습니다. 이미 사용자가 만든 물리체에 속한 메시는 거부됩니다. 바람 그룹은 현재 MCP `simulation_simulate`에 바람을 넘길 때만 작용합니다(위 참고).

## MCP

시뮬레이션은 조작별로 여러 도구로 나뉩니다. 파라미터는 `{"request": {...}}`에 두고, 모두 `id`로 물리체를 지정하며 `project_id`, `state`, `request_id`를 함께 보냅니다. 이들은 백그라운드 작업 핸들을 반환하며, `job_wait` / `job_get`으로 결과를 가져옵니다.

- `simulation_put`: `id`로 물리체를 새로 만들거나 일부만 수정합니다. 필드에는 `targets`, `material`, `material_preset`(위 표의 프리셋 이름: `cotton`, `silk`, `chiffon`, `wool`, `denim`, `leather`, `elastic`, `hair`, `fine_hair`, `thick_hair`, `bangs`. 함께 준 `material` 필드가 그 수치를 덮음), `groups`, `glue_roles`, `inputs`, `modes`, `keys`, `exaggeration`, `static_inputs`, `blend_shapes`(`true` / `false` / `null`은 자동), `auto_bake`, `output_names`(파라미터 또는 진자 ID로 이름을 지정, 전체 교체), `input_ranges`(입력 파라미터별로 `[min, max]` 학습 범위, 전체 교체), `vertical`(`true` / `false` / `null`은 자동), `outputs`(생성된 모드 파라미터 ID별로 `{id, range, gain}`, 전체 교체, 다시 베이크할 필요 없음), `force_inputs`(물체를 거의 움직이지 않아도 유지할 입력), `training_clips`(학습에 참여하는 모션, `{动作: 0.05–1}`, 전체 교체)가 있습니다. 새로 만들 때 `inputs`를 주지 않으면 기본 입력을 기록하고, 빈 배열을 주면 입력이 없습니다. `auto_bake`가 켜져 있으면(기본) 같은 단계 안에서 다시 베이크하고 `bake` 요약 또는 `bake_error`를 반환합니다.
- `simulation_simulate`: 읽기 전용 시험 계산입니다(패널에는 대응 버튼이 없음). 각 입력을 `hold`초 유지한 뒤 놓고 `release`초 동안 관찰하며, `wind`를 선택적으로 줄 수 있습니다. 최댓값, 정지 표류, 늘어남, 설정 안내를 반환합니다.
- `simulation_bake`: 베이크합니다(몇 초). 각 모드 파라미터와 진폭, 키 수, 진자 ID와 마디 수, 독립 진자의 ID(`own_pendulums`, 있을 때), 각 입력의 읽기 결과(`inputs`: 물체를 움직인 거리, 이동과 회전만인지, 소속 그룹 또는 제외됨), 각 묶음이 검사 모션에서 보인 시각 검사(`visual`), 베이크 방법(`method`), 그리고 검사 모션에서의 `fit_r2`, `error_p95_px`, `parameter_peak`(모드 파라미터가 범위를 최대 얼마나 썼는지), `clipped_frames`(끝에 닿은 프레임 비율), `jerk_ratio`(저크와 시뮬레이션의 비)를 반환합니다.
- `simulation_compare`: 읽기 전용 백그라운드 작업입니다. `motions`의 모션(사용자 모션 ID 또는 내장 이름, 최대 8개)으로 참조 시뮬레이션과 내보낸 모델을 각각 구동하고, 각 모션의 시각 검사를 반환합니다.
- `simulation_clear_bake`: 베이크를 지웁니다.
- `simulation_delete`: 물리체를 삭제합니다.

참조 시뮬레이션 미리보기는 미리듣기 세션에 대응하며, 문서와 히스토리에 들어가지 않습니다. `simulation_preview`는 `mode=start`와 `simulation_id`로 시작합니다(`restart` / `stop`은 `session_id`를 가짐). `simulation_preview_step`은 `dt`초(최대 0.1)씩 1–240단계를 진행하고, `simulation_preview_get`은 현재 프레임을 읽으며, `simulation_preview_render`는 현재 프레임을 렌더링합니다.

`vertex_group_update`는 규칙(`fill`, `outline`, `gradient`, `glue`, `region`)으로 가중치 그룹을 생성하고, `delete=true`는 삭제하며, 정점별 배열을 넘기지 않습니다. `vertex_group_paint`는 캔버스와 같은 브러시, 그라데이션, 반전으로 가중치를 수정합니다. `workspace_inspect`의 `scope=simulations`는 물리체, Glue 키, 베이크 요약(`bake_stale` 포함)을 나열하고, `scope=vertex_groups`는 가중치 그룹을 나열합니다.

## 현재 범위

- 구현됨: 천과 머리카락(XPBD 풀이, 면적으로 질량 배분, 삼각형 면적과 뒤집힘 방지, 회전 기반 굽힘, 자동 결 방향과 이방성, 고정점, Glue 역할, 장거리 제약), 정점 가중치 그룹, 참조 시뮬레이션 미리보기, 파라미터 + 키폼(블렌드 변형 또는 키폼 축, 자동 선택 가능) + 진자로 베이크하고 내보내기, 자동 베이크, 과장 계수. 모델 프리셋(머리카락 시뮬레이션이 이전 스윙을 대체, 헐렁함에 따라 상의 / 치마 / 바지 / 목 장식 / 소매 / 다리 착용을 시뮬레이션, 고정 가중치 자동 설정).
- 실측: 위 표의 tml 뒷머리 비교 데이터. 모델 프리셋이 tml에서 베이크한 결과(검사 모션 R² / 95% 오차, 이전 솔버에서 측정, 새 재질 모델에서 다시 측정 필요): 뒷머리 0.69 / 229 px, 위쪽 10%를 수동으로 고정한 것과 같음. 앞머리 0.25 / 185 px, 고정 범위를 어떻게 바꿔도 0.2–0.3. 앞머리의 문제는 고정 범위가 아니라 재질입니다. 이마에 붙어 가로로 쓸리는 앞머리는 뒷머리처럼 묶음 길이가 중력을 받지 않고, 기본 머리카락 재질의 약한 되돌아감이 그것을 약 0.75 Hz의 부드러운 스프링으로 만듭니다. 좌우로 고개를 흔들 때(1.2 Hz) 스켈레톤에서 74 px 벗어나고(스켈레톤이 움직이는 것은 33 px), 끄덕일 때 47 px입니다. 「앞머리」 재질로 바꾼 뒤(새 재질 모델, tml / ds): 고개 흔들기 41 / 30 px, 끄덕임 12 / 10 px, 고개 돌리고 멈춘 뒤 잔여 10 / 6 px, 베이크 R² 0.18 → 0.27 / 0.21 → 0.49, 95% 오차 216 → 85 / 112 → 57 px. 치마 데이터는 이미 제거된 충돌 기능에서 측정했으므로 다시 실측해야 합니다. 머리카락에 질량 / 바람 그룹을 더하면 뒷머리 R²가 0.69에서 0.56으로 내려가므로, 머리카락 프리셋은 이 두 그룹을 기록하지 않습니다.
- 장애물: 시뮬레이션체는 장애물(`obstacles`)을 가질 수 있습니다. 다른 메시를 따르는 원 또는 캡슐이며, 입자는 밖에 막히고, 참조 시뮬레이션과 베이크에 참여하며, 실시간 시뮬레이션을 재생하는 런타임 대상(p2lrt, 웹)으로 내보냅니다. 지금은 MCP `simulation_put`으로만 작성할 수 있고, 캔버스에는 아직 편집 입구가 없습니다. 더 이전의 메시 충돌체(가장자리 거리 기준)는 실측이 불안정해 제거되었습니다. 이전 프로젝트의 이런 충돌체와 충돌 가중치 그룹은 불러올 때 무시됩니다.
- 아직 구현되지 않음: 바람 같은 힘장 내보내기, 강체와 연체, 일반 키로 베이크(생성기 제거).
- 헐렁함 히트맵 수동 확인(tml, ds, Q판 소재 하나): tml은 치마 아래쪽만 헐렁합니다. ds는 앞치마, 허리 뒤 리본, 치마 자락이 헐렁하고, 퍼프 소매, 소맷부리, 양말 입구는 몸에 붙습니다. Q판의 열린 코트는 허리선 아래가 헐렁하고, 일자 바지는 몸에 붙습니다.
- 아직 실측 필요: 예제 모델의 치마와 머리카락을 내보낸 뒤 공식 런타임에서의 시각 효과. 모델 프리셋이 생성한 머리카락과 의상 시뮬레이션의 자연스러움.
