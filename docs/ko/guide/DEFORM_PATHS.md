# 디폼 경로(실험적)

[문서 목록](../README.md) · [캔버스 편집](CANVAS_EDITOR.md)

경로는 ArtMesh에 매달린 편집 보조 객체이며, Warp / Rotation 밖의 세 번째 디포머가 아닙니다. 지금은 하나의 ArtMesh에 경로를 여러 개 둘 수 있고, 경로 하나가 여러 ArtMesh를 제어하는 것은 지원하지 않습니다.

## 가장 짧은 조작

1. 아트메시를 선택하고, 트리에서 오른쪽 클릭으로 「디폼 경로 추가」를 실행합니다(기본 `P` / `D`).
2. 클릭으로 제어점을 최소 두 개 놓고, Enter로 확정하고, Esc로 취소합니다.
3. **편집 모드**에서 경로의 바인딩 위치, 너비, 경도, 닫힘, 모서리 점을 조정합니다. 이때 이미지 형태는 바뀌지 않아야 합니다.
4. 파라미터 패널에서 목표 자세를 맞춘 뒤 **변형 모드**로 전환해 제어점을 끌어, 결과를 아트메시 형태에 기록합니다.

오브젝트 모드는 객체만 선택합니다. 경로는 L2 / L3 두 그룹으로 나뉘며, 각 그룹이 한 벌씩 저장됩니다(`.cmo3`에 쓸 때는 경로의 편집 계층이 됩니다). 메시 디포머의 「정점 / 베지에」 계층과는 관계가 없습니다. 경로를 새로 만들 때는 배치 패널이나 「도구 세부」의 「경로 편집 계층」에서 그룹을 고르고, 이미 있는 경로는 인스펙터의 「편집 계층」에서 바꿉니다. 캔버스는 현재 그룹의 경로만 표시하고 편집합니다. 보조선은 선택한 객체와 편집 페이지의 뷰 설정에 따라 표시되며, 미리보기 페이지에는 경로가 나오지 않습니다. 일반 편집은 주 캔버스 히스토리를 그대로 씁니다.

## 저장과 내보내기

| 파일 | 저장 내용 |
| --- | --- |
| `.psd2live` | 경로 설정, 바인딩, 재생할 수 있는 형태 편집 |
| `.cmo3` | 네이티브 컨트롤러 구조와 메시 키폼 |
| `.moc3` | 베이크한 메시 키폼. 런타임은 경로 알고리즘을 실행하지 않습니다 |

현재 알고리즘은 곡선 샘플링, 이동 최소제곱, 삼각형 바인딩을 사용합니다. 컨트롤러를 읽고 쓸 수 있다고 해서 드래그 효과가 Cubism Editor와 검증되어 일치한다는 뜻은 아닙니다. 너비, 경도, 큰 각도의 변형, 균일하지 않은 부모 스케일은 특히 확인이 필요합니다.

주 캔버스의 토폴로지 조작은 경로를 다시 바인딩합니다. 너무 성긴 메시나 서로 충돌하는 제약은 변형이 거부될 수 있습니다. 공식 Editor에서 열고, 드래그하고, 다시 저장하는 완전한 호환 검수는 이 페이지에 아직 기록하지 않았습니다.

Agent는 `path_list`, `path_get`으로 경로를 보고, `path_put`, `path_delete`로 경로를 만들거나 수정하거나 삭제하고, `path_preview`로 제어점 드래그를 시험하고, `path_deform`으로 드래그 결과를 키폼으로 씁니다. `workspace_inspect`의 `scope=paths`는 모든 경로를 나열합니다. 필드는 [MCP 인터페이스](../agent/MCP_AUTHORING.md)를 참조합니다.
