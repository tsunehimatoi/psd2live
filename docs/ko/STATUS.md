# Agent 능력 실측

[문서 목록](README.md) · [MCP 사용과 인터페이스](agent/MCP_AUTHORING.md) · [Agent 설계와 검수](agent/AGENT_DESIGN.md)

## 평가 기준

| 평가 | 의미 |
| --- | --- |
| 매우 좋음 | 안정적으로 완료 |
| 사용 가능 | 완료. 적은 양의 수동 수정이 필요 |
| 간신히 | 많은 재작업이나 사람이 마무리해야 함 |
| 사용 불가 | 완료하지 못했거나, 결과를 받아들일 수 없음 |

성공 표본이 적다고 다른 소재에서도 같이 안정적이라는 뜻은 아닙니다.

## 새 기록을 제출하는 방법

각 기록에는 다음을 포함합니다.

- 애플리케이션 버전 또는 commit, 호스트, 모델.
- 작업 설명과 원본 소재, 이미지 생성을 썼는지.
- 표본 수, 재작업 횟수, 소요 시간, 한도 소모.
- 결과 파일 또는 히스토리 노드, 그리고 명확한 통과 / 실패 이유.

검수할 때는 실제 모델의 중립 자세, 파라미터 끝점, 동적 효과를 대조하고, 저장 후 다시 열기와 내보내기 결과를 확인합니다. 레퍼런스 이미지만 있거나, 도구가 성공을 반환했거나, 스크린샷 한 장만 있는 것으로는 작업 완료를 증명하기에 부족합니다.

캐시 이득은 같은 구현의 켬／끔을 비교한 것이며, 이전 버전 대비 전체 가속으로 해석할 수 없습니다. 두 가지 실제 편집 창 모드는 합계 70프레임(예열 포함), 픽셀 2,520개, 후보 빌드 280회를 검사했고, 관찰자 검사 142회는 모두 조정자나 창 재생 잠금을 쥐지 않았습니다. 측정 끝점은 창 Surface GPU 완료이며, 창 교환이나 디스플레이 스캔은 재지 않았습니다. 픽셀 읽기／PNG 쓰기는 끝점 뒤에 있으며, 이후 표본을 흔들 수 있습니다.

**메모리와 남은 비용.** OS 스냅샷 81／75／54회가 각각 worker／작업 공간／파츠 도구를 덮습니다. 기록된 worker는 최종 해제 뒤 모두 종료했습니다. 압력 시나리오의 기하 유지량은 항상 2 MiB를 넘지 않습니다. 프로토콜 버퍼, JVM, 히스토리 데이터는 포함하지 않습니다. 도구 세 개의 호스트 샘플 상주 피크는 약 505.49／2,504.92／1,040.82 MiB이고, worker 샘플 피크는 각각 약 696.64／자식 프로세스 없음／784.06 MiB입니다. 이것은 이산 샘플 피크이며, 총 메모리 상한이나 누수 없음의 증명은 아닙니다.

실제 편집의 후보 빌드 네 번 합계 중앙값은 약 1.38／1.33초이며, 그중 `modifier author: wait for atlas pages`의 누적 중앙값은 약 1.32／1.27초로, 지금 명확한 이후 최적화 대상입니다. 완전한 히스토리를 닫았다 다시 여는 시나리오의 중앙값은 소／중／대 13.25／10.90／13.33초입니다. 이 구간에는 닫기, 유지된 리더 검증, 아카이브 열기, 재구축, 완전한 IR 비교, 히스토리 메타데이터 검증이 들어 있으므로 GUI 열기 지연으로 바로 볼 수 없습니다. 이후에는 구간을 더 나누고, 히스토리 유지와 캡처 리더 계약을 지키며, 히스토리를 잘라 더 낮은 메모리나 시간을 얻지 않습니다.

JVM 플러그인 계약은 `algorithm-api` 독립 모듈로 뽑았고, 호스트는 그 모듈에 의존하도록 바뀌었습니다. 인스턴스와 패키지 참조, 버전 해석, 의존 범위, 실제 평가 인터페이스는 더 이상 애플리케이션 소스와 함께 정의되지 않습니다. 독립 모듈의 회귀 세 항목이 통과했습니다. 호스트 구현 없는 평가, 이전 JSON과 고정 참조 읽기, 버전 범위 비교. 이 항목은 인터페이스를 독립 컴파일할 수 있음을 증명하며, 내장 알고리즘 패키지 로드와 히스토리 바이너리 유지가 끝났다는 뜻은 아닙니다.

물리 그룹 알고리즘은 설치 가능한 JVM 패키지로 독립 빌드했습니다. 개발 도구 실측에서 설치, 상주 프로세스의 연속 평가 두 번, 제거, 원 패키지 재설치 뒤 평가가 모두 통과했고, 완전한 결과가 애플리케이션 프로세스 안의 같은 구현과 일치합니다. 출력 별칭과 무관한 소재 유지를 포함합니다. 설치 패키지에는 애플리케이션, UI, 프로젝트, Umamo 클래스가 없습니다. 작업 프로세스는 요약이 있는 모델 객체 차이로 결과를 반환하며, 호스트에 물리 알고리즘을 다시 실행하도록 맡기지 않습니다. 객체 전송과 구조 검증의 표적 테스트가 통과했습니다. 현재 패키지 신원은 `builtin.70687973696373.v1`로 바뀌었고, `physics` 별칭으로 프로젝트 유형을 유지합니다. 완전한 패키지 유지, 이전 버전 디렉터리 다시 열기, 인스턴스 JSON을 읽은 뒤의 고정 참조 평가, 제거 후 재설치 복구가 모두 개발 도구 검사를 통과했습니다. 별칭 충돌과 관리 schema의 표적 회귀가 통과했습니다. 이것은 다른 내장 알고리즘의 이전을 아직 덮지 않으며, 완전한 프로젝트 콜드 재생 검수가 끝났다는 뜻도 아닙니다.

모션 알고리즘은 `:algorithms:motion`으로 옮겼습니다. 설정 데이터, JSON 읽기·쓰기, 곡선 변환은 독립 모듈이 제공하고, 애플리케이션 등록 진입점은 호출만 위임합니다. 독립 모듈의 회귀 두 항목이 통과했고, 보간 네 종, 이벤트, 파라미터 역할, 고정 출력 ID, 충돌, 취소를 덮습니다. 애플리케이션 모션 회귀와 계층 제약 검사가 통과했고, 물리와 모션 두 독립 패키지 모두 설치, 상주 프로세스 평가, 디렉터리 다시 열기, 제거 후 재설치 복구 검사를 통과했으며, 설치 패키지에 애플리케이션이나 Umamo 클래스가 없습니다. 이 항목은 나머지 생성 템플릿 이전을 아직 덮지 않습니다.

스윙 알고리즘은 `:algorithms:swing`으로 옮겼습니다. 메시 감싸기, 키폼 생성, 물리 그룹 정의가 독립 실행되고, 애플리케이션 진입점은 더 이상 평가를 편집 로그에 맡기지 않습니다. 개발 도구가 감싸기 결과가 원 로그 재생과 일치함을 검증했고, 실제 작업 프로세스, 설치 디렉터리 다시 열기, 제거 후 재설치 복구를 통과했습니다. 정지 자세와 고정 변의 독립 회귀가 통과했습니다. 이 모듈은 GPL Umamo와 형식 변환기에 의존하며, 설치에는 엔진이 들어가지만 애플리케이션, 프로젝트, 히스토리, UI 클래스는 없습니다. 파생 출력 규칙은 이전 이름 접두사, 인스턴스 출력 token, 객체 종류, 규범 접미사를 제약하며, 표적 검증이 통과했습니다.

베이크 시뮬레이션 평가는 `:algorithms:simulation`으로 옮겼습니다. 실제 설치 패키지 검증이 통과했습니다. 자동 가중치가 원 로그 경로와 일치하고, 출력에 모드 파라미터, 메시 키폼, 물리 그룹이 포함되며, 디렉터리 다시 열기와 제거 후 재설치 뒤에 복구할 수 있습니다. 시뮬레이션 내보내기와 창 없는 베이크 진입점의 관련 회귀가 통과했습니다. 수치 베이크는 여전히 원 파이프라인에서 실행되며 솔버는 조정하지 않았습니다. 기초 리그는 아직 독립 이전을 기다립니다. 이 묶음의 이전은 베이크 결과의 독립 평가를 덮습니다.

기초 리그가 `:algorithms:binding`으로 옮겨지기 시작했습니다. 지금은 표정 스위치 파라미터와 투명도 곡선 계산을 분리했고, 원 생성기와 모디파이어가 공유합니다. 일반 사용자 정의 표정은 이 채널을 얻기 위해 리그 생성기 전체를 호출하지 않으며, 표준 파라미터 이름 충돌은 여전히 원 호환 경로를 사용합니다. 독립 커널 함수 회귀, 모디파이어 관련 회귀, 표정 투명도／순서／적용 접두사 동등 검사가 통과했습니다. 표정 적용은 독립 `ExpressionAlgorithm`으로 더 옮겼고, 저작자 입력 컨텍스트를 거쳐 실행합니다. 채널 잔차 합성은 애플리케이션과 플러그인이 공유합니다. 독립 모듈 테스트가 저작자 투명도 잔차, 선택하지 않은 메시, 취소를 검증했고, 원 표정 동등 회귀는 계속 통과합니다. 표정 스위치는 이제 독립 설치 패키지를 만들며, 실제 작업 프로세스의 연속 평가, 디렉터리 다시 열기, 인스턴스 신원 복구, 제거 후 재설치, 규범 진입점 호출이 개발 도구 검사를 통과했습니다. 호스트가 승인한 동적 공유 파라미터의 표적 검증이 통과했고, 잘못된 정의와 승인하지 않은 새 파라미터는 거부됩니다. 나머지 리그는 아직 독립 패키지 이전을 끝내지 못했고, 이 항목이 완전한 생성 소요를 개선하는지도 실측하지 않았습니다.

여섯 언어(Python, Kotlin, Rust, C, C++, C#)의 예제가 Windows에서 독립 설치 패키지로 빌드되었고, 격리 디렉터리 설치, 상주 프로세스의 연속 실제 평가 두 번, 제거 검사를 통과했습니다. 공유 관리 인터페이스의 엄격 schema, 패키지 신원, 저작자 입력 캐시에 표적 회귀가 있습니다. 캐시를 끈 뒤의 완전한 IR이 캐시 결과와 일치합니다. 이 항목은 개발 도구 검수이며, Agent 모델링이나 GUI 수동 검수를 대신하지 않습니다.

내장 알고리즘은 항목마다 플러그인 신원, 완전한 패키지 버전, 진입점 코드 요약을 제공하고, 새 인스턴스는 고정 참조를 쓰며, 이전 인스턴스는 원 형식으로 읽습니다. 스윙, 시뮬레이션, 물리, 모션, 표정 스위치, 눈썹·눈 투과, 피부 자르기가 독립 구현 진입점을 분리했습니다. GUI／MCP가 항목별 켜기와 끄기를 지원하고, 외부 패키지는 내장 진입점에 대한 버전 의존을 선언할 수 있습니다. 신원 지속, 엄격 schema, 의존 중지와 복구가 표적 회귀를 통과했습니다. 나머지 리그 종류는 여전히 공유 템플릿 생성 서비스를 호출하며, 아직 독립 설치 JAR이 아닙니다. 그 히스토리 구현의 독립 배포와 유지는 끝나지 않았으므로, 모든 플러그인화가 검수 완료된 것으로 볼 수 없습니다.

명시적 모션과 이전 유지 이름의 충돌, 생성 모션이 자동으로 키를 찍는 귀속, Windows에서 플러그인을 제거할 때 작업 프로세스가 파일 핸들을 남기던 문제를 수정했습니다. 프리셋 회귀는 이전 버전의 독립 목표 구조와 새 버전의 공유 구조를 구분합니다. 남은 실패는 수렴했고, 이전 라운드의 전체 `test`가 통과했습니다(바뀌지 않은 하위 모듈 작업은 Gradle 결과를 재사용).

이번 라운드는 독립 알고리즘 연결과 이전 템플릿 코드 정리를 먼저 끝내고, 성능 최적화는 재구성 인도 뒤에 합니다. 진단 보고서는 완전한 생성과 동기 베이크 소요를 남깁니다. 기하 경계, 얼굴 특징점, 시뮬레이션 풀이의 프레임 안 상수를 재사용합니다. 원본 그림 분류 캐시는 모디파이어 설정과 베이크 데이터를 제외하고, 일반 저작자 입력은 여전히 캐시 무효에 참여합니다. 시뮬레이션 입력 지문은 대상, 충돌 객체, Glue 연결 객체, 부모 디포머를 추적하고, 나머지 부속 입력은 보수적으로 유지합니다. 첫 가져오기가 아틀라스 고정과 분류 정리를 하며 평가 캐시를 유지하고, 시뮬레이션 사전 검사가 기하 캐시를 이어받습니다. 템플릿 캐시는 더 이상 임시 미리보기 그림의 객체 신원에 의존하지 않습니다. 표정 색과 스위치의 설정은 더 이상 메시 기하 캐시를 무효로 하지 않습니다. 실제 빌드 횟수는 줄었고, 완전한 IR 콜드 재구축은 일치하지만, 엔드투엔드 소요가 안정적으로 줄었음은 아직 증명하지 못했습니다. 개발 도구 실측에서 눈 조정은 의상 재베이크를 일으키지 않았고, 조정 뒤의 캐시 결과가 캐시를 끈 완전한 IR과 일치합니다.

외부 작업 프로세스의 크래시, 오류 응답, 불법 출력, 시간 초과, 실행 중 취소, 대기열 취소, 제거 중단, 재설치 뒤 평가가 표적 회귀를 통과했습니다. 대기열 취소는 실행 중인 다른 요청을 끊지 않습니다. 이 컴퓨터의 실제 Git 서비스 검수는 태그, 완전한 커밋 번호, 기본 브랜치, 버전 공존, 설치 뒤 평가를 덮었고, Windows의 읽기 전용 Git 객체가 임시 저장소 정리를 실패시키던 문제를 수정했습니다. HTTPS／SSH 자격 증명 환경, 복잡한 외부 알고리즘, GUI 조작은 아직 완전한 검수를 끝내지 못했습니다. 구현과 프로토콜은 [알고리즘 플러그인](guide/ALGORITHM_PLUGINS.md)을 참조합니다.

원본 그림 피팅은 레이어 내용과 순서, 좌표계, 눈 중선, 핸들 이동 뒤의 피팅 결과, 파츠 선언의 공유 캐시를 따르며, 운동 옵션은 여전히 독립 평가합니다. 전용 성능 도구가 조정 뒤의 완전한 IR이 캐시를 끈 재구축과 일치하고, 눈 조정이 의상 재베이크를 일으키지 않음을 검증했습니다. 이번 같은 컴퓨터의 전후 측정은 뚜렷한 엔드투엔드 가속을 증명하지 못했습니다. 파라미터 조회가 일으키는 리그 템플릿 전체 빌드는 여전히 교체 대기 경로입니다.

볼터치와 그림자 색 커널은 독립 리그 모듈로 옮겼습니다. 색 추가 경로는 변환 전 입력을 국소 갱신한 뒤 원 Cubism 변환을 다시 실행해, 색 축이 늘어나 필요한 회전 디포머를 빠뜨리지 않습니다. 변환 전 입력은 지연 평가하며, 쓰지 않는 템플릿은 UV를 추가로 변환하지 않습니다. 색 덮어쓰기／적용 접두사, 이전 프로젝트의 완전한 변환 회귀가 통과했고, 전용 도구의 캐시 결과가 완전한 생성 IR과 일치합니다. 리그 빌드 전체 횟수는 줄었지만, 그 측정은 여전히 엔드투엔드 가속을 증명하지 못했고, 첫 목표는 아직 달성하지 못했습니다. 이 두 종류의 모디파이어는 아직 설치 가능한 진입점 이전을 끝내지 못했습니다.

Cubism 블렌드 셰이프 변환은 독립 리그 모듈의 `BlendShapeLowering`으로 뽑았고, 애플리케이션 층은 이름만 맞춥니다. 키폼 예산, 운반 디포머 계산, 결정적 ID를 유지하고, 호출자의 취소 검사를 지원합니다. 변환 기하 효과, 이전 프로젝트의 완전한 변환, 독립 모듈 취소 회귀가 통과했습니다. 이 라운드는 전체 경로 성능을 다시 재지 않았고, 나머지 리그 진입점은 계속 이전이 필요합니다.

색 리그의 파라미터 정리, 파라미터 트리 갱신, 소속 채널 교체, 다운그레이드 변환이 독립 `MoodBinding` 인터페이스에 통합되었고, 제품 층이 캡처한 의미 가중치와 파라미터 정의를 제공합니다. 반복 조정이 파라미터를 누적하지 않고, 다른 메시를 유지하며, 완전한 변환 일치 회귀가 통과했습니다. 설치 가능한 색 진입점과 호스트 덮어쓰기 적응은 아직 연결 대기입니다.

리그 국소 마스크 판정은 독립 모듈로 옮겼고, 메시와 지정한 조상에 따라 변환／캐시 규범 표현을 만들어 매번 완전한 IR을 구성하지 않습니다. 기하 배열, 채널, 조상 변화 판정 회귀가 통과했습니다. 전용 생성 도구가 파라미터 조정이 재베이크를 일으키지 않고, 캐시 결과가 캐시를 끈 재구축의 완전한 IR과 일치함을 확인했습니다. 이번 첫 생성과 반복 생성, 수정 응답은 모두 이전 기록보다 낮지만, 한 번의 차이를 독립 최적화 이득의 증명으로 쓰지 않습니다. 첫 생성은 여전히 베이크를 제외한 제한에 닿지 않았습니다.

눈썹·눈 투과의 복제본, 반전 마스크, 투명도／그리기 순서 상속, 미리보기 갱신을 독립 `SeeThroughBinding`으로 뽑았습니다. 애플리케이션 층은 레이어 픽셀 덮어쓰기 인식과 설정／지역화 적응을 남기고, 원 유형과 호출 인터페이스는 변하지 않습니다. 눈과 눈썹 투과 시나리오 회귀가 통과했습니다. 설치 가능한 진입점과 캡처 입력 프로토콜 연결은 아직 끝나지 않았고, 이번 라운드는 시간을 다시 재지 않았습니다.

눈썹·눈 투과는 버전 있는 캡처 입력과 독립 설치 패키지에 연결되었고, 원본 그림 덮어쓰기 인식은 계산을 한 번 공유하며, 플러그인이 실제 메시 순서대로 복제본／창을 만듭니다. 두 패키지의 실제 설치, 작업 프로세스 반복 평가, 규범 진입점／이전 별칭 일치, 저장 복구, 제거 후 재설치가 모두 통과했습니다. 기존 투과 효과, 적용 뒤 복제본 유지, 완전한 프로젝트 변환 회귀가 통과했습니다. 이전에 기록한 이 두 설치 진입점의 할 일은 끝났고, 나머지 리그 플러그인 이전은 아직 끝나지 않았으며, 이번 라운드는 생성 시간을 다시 재지 않았습니다.

객체 참조 재매핑은 독립 리그 모듈의 `ModelIdRemap`으로 옮겼고, 애플리케이션 호환 별칭을 유지합니다. 무관한 모델 파티션과 메시는 다시 만들지 않습니다. ID 전체 참조 다시 쓰기／충돌 거부, 객체 조작, 완전한 프로젝트 변환, 독립 모듈의 입력 공유／키폼 축 이전 회귀가 통과했습니다. 이 라운드는 성능을 다시 측정하지 않았으며, 엔드투엔드 가속 검수로 치지 않습니다.

저작자 기하 잔차, 메시／디포머 블렌드 셰이프의 삼자 병합, 정점 대응 전달이 독립 리그 모듈로 옮겼습니다. 계산식은 원형 그대로이고, 애플리케이션의 이전 이름은 호환 별칭입니다. 독립 블렌드 셰이프와 조합 모션, 입을 다문 기본값을 생성하는 편집의 귀속, 몸 리그와 그 전치 구조를 적용하는 표적 회귀가 통과했습니다. 이것은 남은 리그 플러그인의 공유 의존이며, 모든 리그 진입점의 이전이 끝났다는 뜻은 아닙니다.

부모 좌표 변환은 독립 `BindingFrames`로 옮겼습니다. 일반 재리그, 모디파이어가 새로 운반 디포머를 추가하는 경우, 공유 조상 아래의 국소 반전이 같은 알고리즘을 씁니다. 모디파이어 호출은 취소 검사를 전달할 수 있습니다. 저작자 부모와 기하 유지, 몸 리그 적용의 전치 구조, 구조 특징 변위를 적용한 뒤의 얼굴 리그 표적 회귀가 통과했습니다. 이번 라운드는 독립 리그 인터페이스에 좌표 전달 능력을 채운 것이며, 생성 성능은 다시 재지 않았습니다.

리그 병합 주 흐름은 독립 `BindingMerge`로 옮겼습니다. 애플리케이션 층은 읽기 전용 `Source`로 캡처 투영, ID 매핑, 정점 대응을 제공하고, 물리와 초기 자세 전략을 유지합니다. 완전한 프로젝트 변환, 독립 블렌드 셰이프／조합 모션, 몸 리그 적용의 전치 구조 회귀가 통과했습니다. 독립 모듈 테스트가 애플리케이션 서비스 없는 채널 병합과 취소를 검증합니다. 축 병합과 유한 좌표 열거도 공유합니다. 이 경계는 아직 외부 전송 프로토콜이 아니며, 템플릿 생성과 남은 플러그인 진입점은 아직 이전 대기입니다. 이번 라운드는 성능을 다시 재지 않았습니다.

피부 자르기는 독립 설치 가능 플러그인이 되었고, IR 마스크를 직접 수정하며, 리그 생성 전체와 모델 변환을 거치지 않습니다. 저작자 마스크 충돌과 이미 적용된 인스턴스의 범위는 원 의미를 유지합니다. 덮어쓰기 판정／대상 범위, 취소, 원 효과와 적용 뒤 편집, 완전한 프로젝트 변환, 실제 설치／작업 프로세스／제거 후 재설치 회귀가 통과했습니다. 전용 도구가 캐시 결과가 캐시를 끈 재구축의 완전한 IR과 일치함을 확인했습니다. 첫 소요는 이전 기록과 거의 같고 아직 목표에 닿지 않았으며, 반복 생성은 이번에 통과했습니다. 이후 리그는 여전히 자신의 입력을 위해 자르기가 포함된 템플릿을 다시 만들므로, 단일 항목의 직접 계산을 생성 경로 전체의 최적화가 끝난 것으로 볼 수 없습니다.
