## 귀속과 우선순위

이 페이지는 이후 방향만 기록하며, 일정을 약속하지 않습니다. 코드에 진입점이 있는지, 전체 워크플로를 쓸 수 있는지, 효과가 검수를 통과했는지는 따로 판단합니다. 평가는 [STATUS.md](STATUS.md)에만 기록하고, 끝난 항목은 이 페이지에서 빼며 [변경 이력](CHANGELOG.md)을 참조합니다.

이번 라운드의 히스토리 패키지 유지, 참조 분할, 콜드·핫 결과, 파츠 설정과 접기, 캐시 소유권, GPL 변환 브리지, 컨트롤러 파일럿은 이미 통합했습니다. 검수는 [STATUS](STATUS.md#2026-11-14-아키텍처-최적화-검수)를 참조합니다. 이후에는 캐시 계약과 첫 프레임 측정 경계를 따라 계속 진행합니다. 텍스처 일괄 교체에서 아틀라스 페이지 대기를 우선 분해하고, 완전한 히스토리를 유지한 채 닫았다 다시 여는 비용을 더 나눕니다. 기존 패키지 의존 예외는 항목마다 없애고, 새 캐시 파일럿은 완전한 의미 차분과 이득 측정을 계속해야 합니다. 전체 회귀의 1분 목표도 계속 대조해야 합니다.

**현재 제품 진행 순서: 사용자 정의 플러그인 폐쇄 루프의 사용성과 실기 검수 → 내장 「스타일」(피팅) 효과 최적화 → 자동 그림자 등 새 효과.** 사용자가 Agent로 능력 확장을 만드는 1기 폐쇄 루프(독립 스캐폴드, 계약 발견, 선언적 파라미터, 첫 추가, 재시작 없이 취소 가능한 패키지 교체, 작업 프로세스 세대 격리, 저장 후 다시 열기)는 코드 구현과 단위／엔드투엔드 테스트를 마쳤습니다. 사용성은 실제 Agent 작업과 창 육안 검수와 함께 마무리하고, 기기 간 패키지 공유는 이후에 제공합니다(기존 사전 컴파일 패키지 설치 규칙은 유지). 전역 UX 재구성은 따로 평가합니다. 내장 효과는 바로 쓰는 기능이기도 하고 플러그인 작성 예시이기도 하므로, 소재를 넘나드는 안정성을 먼저 높인 뒤 종류를 늘립니다.

【다음】**사용자 정의 플러그인 폐쇄 루프의 실기 검수와 기기 간 공유**: 데스크톱 창과 실제 Agent 호스트에서 「내장 목록에 없는 새 동작」의 수동 실측과 사용성 다듬기를 끝내고([STATUS](STATUS.md)에 기록), 기기 간 패키지 공유 능력을 채웁니다.

새 능력은 Cubism과의 관계에 따라 세 단계로 넣습니다.

| 귀속 | 의미 |
| --- | --- |
| p2lrt | Cubism이 전혀 지원하지 않고 베이크할 수도 없으며, p2l 런타임, 웹, Godot, 래스터 내보내기에서만 적용됩니다 |
| 호환 | Cubism은 지원하지 않지만 키폼, 파라미터, 진자, 텍스처로 베이크할 수 있습니다. 키 사이는 근사일 수 있습니다 |
| p2ledior | Cubism이 완전히 지원하고 무손실이거나, 편집 과정에만 영향을 주는 도구입니다 |

우선순위는 각 항목 앞에 표시합니다.

- 【다음】현재 단계에서 우선 구현하며, 동시에 다섯 개 안팎을 넘지 않습니다.
- 【이후】현재 단계 다음이거나 다른 항목에 의존합니다.
- 【장기】어렵지만 나중에 구현하고 싶은 항목입니다.
- 【지속】기능이 진행되면서 조금씩 다듬고, 완료 지점이 하나가 아닌 항목입니다.
- 【미정】할지 아직 정하지 않았습니다.

글 끝에 「당분간 계획하지 않음」이 따로 있습니다. 각 항목 뒤의 괄호는 귀속과 작업 성격입니다. **심화**(있는 시스템에 능력을 더함), **최적화**(같은 알고리즘이나 프리셋의 효과와 성능), **신규**(새 시스템), **재구성**(있는 시스템의 구조를 바꿈).

## 단계

지금은 위의 사용자 플러그인 확장 폐쇄 루프를 먼저 끝내고, 이미 있는 파츠 플러그인 스택을 재사용합니다. 범용 변형 모디파이어를 모두 끝내는 것을 전제로 하지 않습니다. 아래 표는 편집기 능력의 의존 그룹을 남긴 것이며, 현재 제품 우선순위와 경쟁하는 일정이 아닙니다. 범용 모디파이어에 의존하는 새 효과는 필요한 능력에 맞춰 진행해, 이전 디포머 위에 구현한 뒤 다시 옮기는 일을 피합니다.

| 단계 | 내용 |
| --- | --- |
| 독립 능력 | 모디파이어와 관계없는 편집, 애니메이션, 내보내기 기능. 실제 필요에 따라 배치합니다 |
| 단계 목표 | [모디파이어 스택 재구성](#모디파이어-스택-재구성): 착수 전에 설계와 단계 계획을 먼저 씁니다 |
| 의존 능력 | 모디파이어에 의존하는 기능: 조명과 그림자, 내부 조형의 3차원 투영 프리셋, 머리카락 볼륨 셸, 유사 디포머, 2D 지오메트리 노드 등 |

## 모디파이어 스택 재구성

- [ ] 【다음】**범용 변형 모디파이어**(호환 · 재구성): 이미 있는 프리셋／파츠 플러그인 스택 위에서 Warp, Rotation 등을 비파괴 모디파이어(Lattice, Bend, Twist, Wave 등)로 더 표현하고, 키폼으로 베이크합니다. 작업 공간의 런타임 권위와 파츠 플러그인은 이미 있는 기반입니다. 범용 변형 층은 아직 단계 설계가 필요하며, 최소한 다음에 답해야 합니다.
  - 모디파이어가 문서 레이어와 생성기 의존 그래프에서 어디 있는지, `RigEditOverlay` 재생 순서와 생성 결과 덮어쓰기와의 관계.
  - 기존 Warp / Rotation / 디폼 경로 / 스켈레톤 스키닝 / 내부 조형을 모디파이어로 어떻게 표현하고, 이전 프로젝트를 어떻게 호환 재생하는지.
  - Cubism으로 내리는 베이크 정밀도와 손실 보고서, p2lrt가 모디파이어를 원형으로 남길지.
  - 단계: 첫 묶음으로 어떤 모디파이어를 하고, 그것에 의존하는 어떤 기능을 어느 단계에서 여는지.
  - 자동 생성한 파츠도 모디파이어 스택에 연결하고, 「적용」해 일반 레이어로 만들 수 있습니다. 예를 들어 위아래 입술 외곽선은 적용한 뒤 입 모양 설정과의 연동이 끊기고 바로 그릴 수 있습니다([#54](https://github.com/tsunehimatoi/psd2live/issues/54). 지금은 입술선에 그리면 안내만 나옵니다).
- [ ] 【이후】**2D 지오메트리 노드**(p2ledior / 호환 · 재구성, 난이도 있음): 생성기 재구성. 노드 그래프가 파츠를 절차적으로 생성합니다. 정적 생성은 무손실이고, 절차적 애니메이션은 베이크가 필요합니다. 모디파이어 스택 바로 다음입니다.
- [ ] 【장기】**유사 디포머**(호환 · 재구성): 배열 / 인스턴스화, 털 가장자리, 획으로 파츠 생성, 변신. 모디파이어 스택과 같은 한 번의 디포머 재구성에 속합니다.
- [ ] 【지속】Rig 생성의 내부 단계를 독립 그래프 노드로 나눕니다. 블렌드 셰이프가 되쓰는 시뮬레이션 키폼 덮어쓰기.
- [ ] 【지속】프리셋 구현의 등록, 선택, 확장 메커니즘: 부위, 기초 알고리즘, 모듈, 레시피의 레지스트리. 파라미터 양으로 모듈을 켜고 끄는 프리셋과 예산, 파츠 역할의 추론과 수정은 이미 있습니다([Rig 프리셋 아키텍처](spec/RIG_PRESETS.md)). 물리, 스윙, 시뮬레이션, 모션의 레시피 라이브러리는 아직 모듈로 등록되지 않았고, 블렌드 셰이프 출력과 다운그레이더, 모듈 버전과 「생성 결과 업데이트」의 연결은 아직 해야 합니다.
- [x] **자동 생성이 손 미세 조정 수준에 도달**(호환 · 심화): 눈(눈꺼풀 피팅, 웃는 눈, 크게 뜸, 감정, 눈꺼풀이 있는 시선, 잔여 흔들림, 하이라이트, 홍채 눌림), 눈썹(눈썹 피팅, 눈썹 형태, 눈썹·눈 연동, 깜빡임에 따라감), 입(단계적 벌림, 입 모양 중간 키, 다물 때 선 교체, 모음, 페이스 트래킹 립싱크, 턱, 볼이 아래 눈꺼풀을 밀어 올림, 입안 깊이, 되튐), 입체 고개 돌리기와 얼굴 겹침 자르기, 머리카락 다발 체인, 치마 자락 / 리본 / 펜던트 체인과 가슴 흔들림, 볼터치와 침울 및 더 풍부한 표준 표정, 자연스러운 깜빡임과 시선 쓸기, 모듈 Rig에 맞춰 조정한 VTube Studio 매핑, 캔버스 특징점 수정이 구현되었습니다. 소재 네 점의 검토를 통과했고, 새 레시피와 이전 레시피가 함께 있습니다([Rig 프리셋 아키텍처](spec/RIG_PRESETS.md)).
- [ ] 【이후】자동 생성의 남은 항목: 눈썹 스프링과 감정 부채꼴의 파생량. 입의 치아궁 분할, 혀 내밀기, 입안 명암. 목과 몸이 고개 기울임을 나누고, 목 그림자가 머리에 걸려 목까지 잘림. 고개를 돌릴 때 앞뒤 머리카락의 그리기 순서 전환과 깜빡임에 앞머리 떨림, 머리카락 재질 노브가 진자 파라미터에 들어감. 팔의 수동 스윙 체인, 단단한 장식을 천에 고정, 자동 Glue, 짐승 귀 / 꼬리 / 날개의 조건 모듈. 스위치 편성(곱 게이팅, 전환, 충격량)과 만화 기호, 의상 교체. 말하기 곡선, 구동 계층, VBridger 모음 매핑. 캔버스에서 끌어 구동 메시의 오프셋과 떠 있는 매크로 노브. 사용자가 기초 키폼을 편집한 뒤 절대 형식의 블렌드 셰이프가 기준을 다시 잡게 함.

## 조명과 그림자

모디파이어에 의존하는 이후 능력이며, 필요한 모디파이어 능력이 준비된 뒤 따로 진행합니다. 제품 우선순위는 사용자 확장 폐쇄 루프, 관련 사용성, 내장 스타일 최적화 다음입니다. 첫 범위는 「이미 있는 그림자 층이 각도에 따라 이동」 또는 「앞머리가 얼굴에 투영」 중 하나를 검수로 고릅니다. 정적 주광만 하며, 화가가 그린 그림자 층을 우선 돕습니다. 동적 광은 런타임에만 남깁니다. 볼륨 프록시는 고개 돌리기 각도를 넓히는 목표가 아니며, 큰 각도는 다각도 소재에 의존할 수밖에 없습니다.

- [ ] 【이후】**화가가 그린 그림자 / 하이라이트 층이 각도에 따라 이동**(호환 · 신규): 클리핑 + 곱하기 / 스크린 층을 인식하거나, SHADOW / HIGHLIGHT / RIM 태그를 새로 두어 각도에 따라 움직이고 페이드 인·아웃하게 합니다. 윤곽 안의 명암 수축·확장은 내부 조형을 재사용할 수 있습니다.
- [ ] 【이후】**정적 주광**(호환 · 신규): 명암 경계선, 앞머리 투영, 엔젤 링 하이라이트, 먼 쪽 어둡게, 층 사이 접촉 그림자. 그림자 층 키폼과 디포머 색 키폼으로 베이크합니다.
- [ ] 【이후】**런타임 동적 광**(p2lrt · 신규): 노멀 맵의 픽셀 단위 조명. Cubism으로 내보낼 때는 정적 광으로 낮추고 손실 보고서에 기록합니다.
- [ ] 【이후】**머리카락 볼륨 셸**(호환 · 신규, 난이도 있음): 고개를 숙이거나 들 때 앞머리가 이마에서 떨어지거나 붙습니다. 각도 축에 베이크합니다.
- [ ] 【장기】**역방향 조명 베이크**(호환 · 신규): 화가가 이미 그린 명암에서 노멀을 역산해 정적 주광에 씁니다.

## 기본 Rig 품질

- [ ] 【이후】**내부 조형 기반의 3차원 투영 프리셋**(호환 · 심화): 안구 구체(홍채와 하이라이트가 구면을 따라 미끄러지고, 가장자리에 가까워지면 압축), 몸통 비틀림(몸 X일 때 옷 주름과 무늬가 변하지 않는 바깥 윤곽 안에서 가로로 이동), 표면 공간 텍스처(무늬가 레이어와 함께 평행 이동하는 것이 아니라 곡면에 붙어 이동). Cubism의 「3D 회전 표현」과 합쳐 고려합니다. 내부 조형이 모디파이어로 옮겨진 뒤에 합니다.

- [ ] 【미정】**픽셀 렌더, 망점 / 하프톤, ASCII 문자화**(p2lrt · 신규): 화면 공간 후처리. 래스터 내보내기에 쓸 수 있습니다. 「당분간 계획하지 않음」의 화면 공간 효과와 같은 종류이며, 남길지는 미정입니다.
- [ ] 【장기】**그라데이션 맵 색 교체**(p2lrt / p2ledior · 신규): 실시간 색 교체는 런타임에 있습니다. 내보내기 전에 배색을 미리 베이크하면 무손실입니다.
- [ ] 【장기】**스타일화와 연동하는 사전 베이크 텍스처 아틀라스**(호환 · 신규): 화면 공간 효과는 잃습니다.
- [ ] 【장기】**런타임이 텍스처에 쓰기**(p2lrt · 신규): 낙서, 오염, 스티커, 서명. Cubism 텍스처는 런타임에서 읽기 전용입니다.
- [ ] 【장기】**파티클**(p2lrt · 신규): 고정 궤적은 일부를 베이크할 수 있습니다.
- [ ] 【장기】**AOV 렌더 채널 내보내기**(p2lrt · 신규): 깊이, 노멀, UV, 파츠 ID, 모션 벡터. 합성이나 AI 다시 그리기에 씁니다.
- [ ] 【장기】**3D 소품과 부착점**(호환 · 신규): 부착점은 부모 디포머입니다. 소품은 여러 각도로 미리 렌더한 뒤 전환합니다.

## 성능과 엔지니어링

- [ ] 【지속】편집 제출의 증분 재구축: 페인팅, 그림 교체 뒤의 재생성 검사가 형태가 변하지 않는 편집에 대해 먼저 더티 검사를 하고, `BoundBaseKey`의 입력 집합을 재사용하며, G′ 전체를 만든 뒤 버리지 않습니다. 생성 검사가 합성한 아틀라스 페이지가 미리보기의 PNG 구간 재사용을 오염시키지 않습니다. 각 명령 객체가 런타임 수준의 파이프라인 캐시(메시, `RigStageCache`, 생성 기하)를 공유해 첫 제출의 콜드 스타트를 피합니다.
- [ ] 【지속】프로젝트 히스토리 크기: 선택적 히스토리 압축(이전 분기를 접거나 주석이 있는 체크포인트만 유지). 「모든 분기 유지」 의미에 대한 취사선택을 먼저 정해야 합니다. 기존 프로젝트의 Rig 객체는 이전 인코딩을 유지하고, 새 체크포인트만 바이트 평면 인코딩의 혜택을 받습니다.

## 간소 작업 공간과 모바일

- [ ] 【이후】**간소 작업 공간과 모바일 터치 조작**(p2ledior · 신규): 기초가 없는 사용자와 휴대폰/태블릿 터치 쪽에 간소 화면을 제공합니다. 복잡한 파라미터와 패널을 숨기고, 자동 생성과 제스처로 시험, 앞뒤 분리(`source_split_depth` + 앞층 지우개), 이목구비 특징점 미세 조정, 부위 오류 수정처럼 사람이 대신할 수 없는 필수 도구만 남깁니다. MCP로 외부 Agent의 고급 편집을 받습니다. 완전한 데스크톱 작업 공간과 `.psd2live` 프로젝트, `WorkspaceHost` 명령 채널을 공유합니다. [간소 작업 공간과 모바일 설계](spec/LITE_WORKSPACE.md)(설계 중)를 참조합니다.

## Cubism 대조 공백

도움말 매뉴얼은 [`manual/index.txt`](../../src/main/resources/manual/index.txt)에서 각 Cubism 매뉴얼 페이지를 같음, 다름, 고유, 미구현(`missing`)으로 표시합니다. 아직 구현하지 않은 페이지는 위 각 주제에 넣었습니다. 다음 몇 묶음은 당분간 넣지 않습니다.

- **스냅샷**: 파라미터 스냅샷과 어니언 스킨이 이미 대체합니다.
- **장면 패널, 프로젝트 패널**: 여러 파일 관리. 작업 공간 탭과 겹칠 수 있어 미정입니다.
- **장면과 재생 목록**(가져온 모델 배치, 오디오 장면, 배경과 그룹 트랙, 장면 관리, 포즈 전환 모션, 재생 목록): 영상 제작 쪽에 치우치며, 「당분간 계획하지 않음」의 배경과 장면과 같은 종류입니다.

## 모디파이어 알고리즘 플러그인과 성능

실행 순서, 프레임워크 문턱, 항목별 장부는 모디파이어 플러그인 마이그레이션 실행 규범을 참조합니다. 먼저 프레임워크를 검증한 뒤 항목별로 병렬 마이그레이션합니다. 커널을 떼어 내는 것은 완전한 마이그레이션으로 치지 않습니다.

- 【다음】내장 항목은 항목별 관리, 진입점 요약, 외부 패키지 의존 잠금을 갖췄습니다. 독립 배포할 수 있는 내장 패키지를 계속 분리하고 히스토리 바이너리를 남깁니다. 현재 진입점은 여전히 애플리케이션과 함께 컴파일되고, 리그 계산은 여전히 공유 생성 서비스에 의존하므로 독립 배포 마이그레이션이 끝난 것으로 보지 않습니다.(호환, 재구성)
- 【다음】내장 리그를 템플릿 묶음 추출에서 소속 결과를 직접 계산하는 방식으로 바꾸고, 생성 효과와 출력 ID를 유지합니다. 기본 프리셋, 단일 항목 추가, 프리셋 전환은 독립 플러그인을 타고, 호스트의 이전 템플릿 생성 경로를 정리합니다. 이전 프로젝트는 잠긴 버전으로 재생하고, 생성과 베이크는 현재 효과를 유지합니다. 성능 최적화는 재구성 인도 뒤에 배치합니다.(호환)
- 【이후】선언한 읽기·쓰기 의존에 따라 병렬 계산하고, 연속 입력을 합치고, 만료된 후보를 취소합니다. 완전한 경계에서 시간을 잰 뒤 로컬 핫스팟을 옮길지 정합니다.(호환, 최적화)
- 【다음】HTTPS／SSH 자격 증명 환경, 언어를 넘는 복잡한 기하, 화면 조작 검수를 채웁니다. 이 컴퓨터의 Git 배포와 작업 프로세스 장애는 표적 검수를 통과했고, 이번 전체 회귀도 통과했습니다. 여섯 언어의 기초 설치와 평가 통과는 완전한 플러그인 생태계나 성능 목표가 검수되었다는 뜻이 아닙니다.(호환, 심화)
