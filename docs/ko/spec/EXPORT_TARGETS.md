# 중립 리그 IR과 내보내기 대상

모든 내보내기는 같은 중립 리그 IR에서 출발합니다. 편집기는 현재 제출된 Rig를 IR로 컴파일하고, 각 내보내기 대상이 IR을 자신의 형식으로 내리며, 그 형식이 유지할 수 없는 내용을 적은 손실 보고서를 하나 씁니다.

## 모듈

| 모듈 | 내용 | 라이선스 |
| --- | --- | --- |
| `:format-model` | 중립 리그 IR(`RigIR`): 파라미터, 파츠, Warp / 회전 디포머, 메시, 키폼 메시, 채널, 블렌드 셰이프, Glue, 그리기 트리, 텍스처 페이지와 타일, 물리 그룹, 모션 클립, 편집기가 함께 둔 데이터 | MIT |
| `:format-compile` | 내보내기 프레임워크: `ExportTarget`, `CapabilityProfile`, `LossEntry`, `ExportReport`, `Compiler`. 다운그레이드 단계: 능력 스캔, 파라미터별 베이크와 교차항 오차 측정(`ParameterBake`), 키프레임 간소화(`KeyReduction`), 모션 클립 샘플링. 호스트 인터페이스 `FrameRenderer`, `GeometryEvaluator` | MIT |

| `:targets:web` | `web`: 웹 플레이어(런타임의 WebAssembly 빌드, WebGL 재생 스크립트, 페이지와 모델) | MIT |

## IR 약속

- 메시의 정지 위치와 각 디포머의 키폼은 모두 부모 디포머의 공간에 있습니다. 뿌리는 캔버스 픽셀(y는 아래)이고, Warp 자식은 그 0–1 격자 공간이며, 회전 자식은 그 로컬 픽셀 좌표입니다.
- 모든 ID는 안정적이며, 다시 생성한 뒤에도 변하지 않습니다.
- 모션 클립은 이미 프리셋에서 파라미터 곡선으로 컴파일되어 있습니다. Bezier 구간의 제어점 시간은 구간 안으로 제한되며, 시간에 따라 곡선 파라미터를 선형으로 진행해 평가합니다(Cubism의 `AreBeziersRestricted`와 일치).
- 표정, 자세, 모션 이벤트는 프로젝트에서 옵니다(`RigEditOverlay.expressions` / `pose`, `MotionClip.events`. [표정, 자세, 이벤트](#표정-자세-이벤트)를 참조). 컴파일할 때 모델에 이미 없는 파라미터와 파츠를 제거합니다. 표정과 자세는 `advanced`에 있고, 클립 이벤트는 `Clip.events`에 있습니다.
- `restPose`는 캔버스 공간 기초 메시가 필요한 형식이 기초 메시를 베이크할 때 쓰는 파라미터 값을 줍니다(예: 입을 벌린 채로 두어 텍스처 좌표가 그림 전체를 덮게 함).
- `PuppetIr`는 `PuppetModel` 필드를 양방향으로 매핑합니다. `toPuppet(toIr(model))`의 왕복 약속은 이 매핑 필드로 한정됩니다. 묶은 이미지, 텍스처 페이지 리그, 물리, 모션 클립, 파라미터 역할은 `PuppetModel`에 저장되지 않으므로 `toIr`에 명시적으로 넘겨야 합니다. IR에만 있는 정지 자세, 타일 소재, 히트 영역, 고급 런타임 데이터는 호출자가 유지하며, IR 전체가 자동으로 손실 없이 왕복한다고 가정할 수 없습니다. 매핑 양쪽에 필드를 추가하면 같은 변경에서 변환기를 갱신해야 합니다.

## 내보내기 대상

`spine`, `dragonbones`, `gltf`는 실험적 대상입니다. 파라미터를 하나씩 베이크한 뒤 겹치므로, 조합 자세가 편집기와 분명히 다르고, 「파일 → 다른 형식으로 내보내기」 메뉴에서 숨겼습니다. 명령줄로만 내보낼 수 있습니다(`psd2live targets`가 experimental로 표시). `unity`는 같은 베이크를 쓰지만 「파일 → 다른 형식으로 내보내기」에 나타납니다. 내보내기 디렉터리 전체를 Unity 프로젝트의 `Assets`에 복사하면, 함께 있는 설치 스크립트가 임포터를 `Assets/PSD2Live/Editor`에 두고 자신을 지우므로, 두 번째 캐릭터도 전체를 복사할 수 있습니다. 아래의 실험적 대상 설명은 현재 상태를 유지합니다.

| ID | 범주 | 출력 | 주요 손실 |
| --- | --- | --- | --- |
| `moc3` | 구조화 리그 | `.moc3`, model3, physics3, motion3, exp3, pose3, cdi3, userdata3, 텍스처 | 대상 런타임 버전에 따라 지원하지 않는 기능을 벗김. Cubism 5.3의 혼합 모드는 더 이전 버전에서 가장 가까운 이전 모드로 바꿈(스크린과 가산 계열은 가산, 곱하기 계열은 곱하기, 나머지는 일반, Alpha 혼합은 over로 바꿈). 영향을 받는 메시와 격리 파츠마다 ID로 `blend_mode` 손실을 하나 기록(기본 `approximated`, 내보내기 옵션으로 바꿀 수 있음). 바뀐 모드를 적음(`cmo3`, `vtube-studio`는 같은 대상 버전으로 같이 처리). 메시가 여러 개인 [클릭 영역](#클릭-영역)은 같은 이름의 여러 항목으로 나눔 |
| `cmo3` | 구조화 리그 | Cubism Editor 프로젝트. 모션 클립이 있으면 같은 이름의 `.can3`도 씀(Cubism Animator 프로젝트). 파라미터 순환은 `isRepeat`에 씀(Cubism 5.3 대상. 더 이전 대상은 제거하고 손실 보고서에 넣음) | 생성기 의도는 유지하지 않음. 모션 클립의 깜빡임, 립싱크 효과 곡선은 쓰지 않음([Cubism Animator](#cubism-animator)를 참조). 표정과 자세는 쓰지 않음(`structure` / `dropped`로 기록) |
| `dragonbones` | 구조화 리그 | `_ske.json`, 페이지마다 `_tex_<i>.json`과 텍스처 | Spine과 같은 파라미터 애니메이션과 클립 베이크. 키 점은 프레임으로 반올림. 투명도는 정수 퍼센트로 기록. 런타임은 16비트 오프셋으로 각 애니메이션의 변형 데이터를 주소 지정하며, 넘치면 더 큰 허용 오차로 간소화하고 보고(스켈레톤 모델의 전신 클립 오차가 큼). 마스크, 스크린 색, 물리는 쓰지 않음 |
| `vtube-studio` | 구조화 리그 | `moc3`의 모든 파일, `.vtube.json`, 모델 선택 아이콘 PNG | `moc3`와 같음. 얼굴 추적은 표준 파라미터에 매핑(머리, 몸, 눈, 시선, 눈썹, 입, 호흡). 모션 클립마다 핫키 하나, 표정마다 `ToggleExpression` 핫키 하나. Rig 모듈로 생성한 모델(모듈 파라미터가 있음)의 매핑은 따로 조정함. 몸은 머리를 따라 돌고 스무딩을 키워 한 박자 늦음. 눈 벌림에는 데드존과 포화가 있고 클램프됨. 입 벌림은 과구동하고, 입 형태 중간에 데드존이 있음. 입꼬리 미소에 웃는 눈이 따라옴. 페이스 캡처의 비뚤어진 입, 볼 부풀리기는 해당 파라미터에 연결 |
| `spine` | 구조화 리그 | 스켈레톤 JSON 또는 `.skel`, `.atlas`, 텍스처 페이지 | 회전 디포머는 뼈 사슬이 되고, 메시는 가장 가까운 회전 뼈에 매달림. 파라미터마다 1초 애니메이션이 됨(시간은 파라미터 정규화 값). 뼈 변환과 뼈 공간 안의 변형을 키로 넣고, 교차항은 Spine 뼈 연산으로 측정해 보고. 모션 클립은 프레임으로 샘플한 뒤 키프레임을 간소화. Warp, 블렌드 셰이프, Glue는 없음(이미 베이크). 마스크는 윤곽 다각형으로 자르기로 바꿈(반전 마스크는 버림). 뼈 회전을 구동하는 진자는 물리 제약으로 바꿈(근사). 나머지 물리와 스크린 색은 쓰지 않음 |
| `p2lrt` | 구조화 리그 | `.p2lrt`(PSD2Live 런타임) | 편집기가 함께 둔 데이터(출처 레이어, 타일, 편집 경로)는 쓰지 않음. GPU 그리기는 호스트가 하며, 런타임의 `p2l_render`(ABI 1.3부터)가 CPU에서 마스크와 모든 합성 모드를 그릴 수 있음 |
| `web` | 구조화 리그 | `index.html`, `p2l.js`, `p2l_runtime.wasm`, `.p2lrt` | 런타임 헤더의 합성 규칙대로 모든 색과 Alpha 혼합 모드(아래층을 읽어야 하는 모드는 메시 아래 픽셀을 복사한 뒤 셰이더에서 합성)와 격리 그룹(자식 메시를 먼저 레이어에 그린 뒤, 그룹의 불투명도, 곱하기/스크린 색, 마스크, 혼합 모드로 합성)을 그림. 마스크(그룹 마스크 포함)는 스텐실 버퍼로 근사하며, 텍셀 불투명도 ≥ 0.5를 덮임으로 침. 레이어 프레임 버퍼를 만들 수 없으면 격리 그룹은 직통으로 그림. http로 접근해야 함 |
| `gltf` | 구조화 리그 | `.glb`(조명 없는 머티리얼, 모프 타깃, 가중치 애니메이션) | 파라미터 키 점마다 모프 타깃 하나. 파라미터 조합은 겹침 근사이며 오차를 보고. 그리기 순서는 정지 값으로 깊이 층을 나눔. 마스크, 혼합 모드, 파라미터에 따라 변하는 투명도, 물리는 쓰지 않음 |
| `unity` | 구조화 리그 | `.p2lunity`, 텍스처 페이지, 일회성 설치 스크립트 | Unity 6.0(6000.0) 이상이 필요. 그리기 순서상 이웃하고 같은 텍스처인 메시를 스키닝 메시 하나로 합치고, 페이지가 교차로 바뀌면 각 구간이 자신의 `sortingOrder`를 유지. 파라미터 키 점마다 Blend Shape 하나. 파라미터 조합은 겹침 근사이며 오차를 보고. 모션은 Animator로 들어가고, 기본은 이름이 Idle인 클립을 재생. 프리팹은 옆의 `.controller`를 씀. 마스크, 일반이 아닌 혼합, 스크린 색, 불투명도 곡선, 물리는 쓰지 않음. 내보내기 디렉터리 전체를 `Assets`에 복사하면 설치 스크립트가 임포터를 `Assets/PSD2Live/Editor`에 두고 자신을 지우며, 두 번째 캐릭터도 전체를 복사 |
| `psd-pose` | 합성/타임라인 | 보이는 메시마다 레이어 하나, 정지 그리기 순서 | 디포머와 파라미터는 유지하지 않음. 파라미터에 따라 변하는 그리기 순서는 정지 값을 취함. 각 메시는 일반 혼합으로 따로 렌더하고, 색 혼합은 레이어 혼합 모드로 씀(스크린 등 Cubism 5.3 모드는 대응하는 모드로 씀). Cubism 5.3 이전의 가산 / 곱하기는 선형 닷지(추가) / 곱하기로 쓰며, 불투명한 아래층 위에서는 색이 같고, 아래 픽셀이 없는 곳에서만 레이어 자신의 픽셀이 보임. `approximated`로 보고. over 이외의 Alpha 혼합은 레이어 대응이 없어 over로 합성하고 보고 |
| `png-sequence` | 래스터 | 번호가 붙은 PNG 프레임 | 구조는 모두 픽셀로 베이크 |
| `sprite-sheet` | 래스터 | 격자로 배열한 스프라이트 시트 PNG + TexturePacker(hash) JSON | 위와 같음 |
| `gif` | 래스터 | 애니메이션 GIF | 256색(모션 구간 전체 픽셀의 중앙값 분할로 255색을 내고, 모든 프레임이 공유), 1비트 투명 |
| `mp4` | 래스터 | H.264 영상(ffmpeg) | 투명 없음. 배경색에 합성(기본 흰색) |
| `webm` | 래스터 | VP9 영상, 투명 포함(ffmpeg) | 투명은 VP9 사이드 채널에 저장. libvpx 디코드가 필요 |
| `mov` | 래스터 | ProRes 4444, 투명 포함(ffmpeg) | — |
| `apng` | 래스터 | 애니메이션 PNG(ffmpeg) | — |
| `webp` | 래스터 | 애니메이션 WebP(ffmpeg) | 손실 압축 |

래스터 계열과 `psd-pose`는 호스트가 제공하는 `FrameRenderer`로 렌더합니다. 편집기 구현(`IrFrameRenderer`)은 엔진의 CPU 평가기로 기하를 얻고, `IrColors`로 채널과 블렌드 셰이프에 따라 곱하기/스크린 색, 파츠의 그리기 순서와 그룹 합성 값을 구한 뒤, `:format-compile`의 `SoftwareRasterizer`(MIT)가 픽셀마다 그립니다. 사전 곱 부동소수점 버퍼, 쌍선형 샘플링, 텍스처 alpha에 따른 마스크(반전 포함). 색 혼합과 alpha 합성은 `p2l_runtime.h`의 합성 규칙을 따릅니다(편집기와 일치). Cubism의 가산/곱하기는 alpha 모드를 보지 않고 대상 alpha를 유지합니다. 일반과 over는 사전 곱 source-over입니다. 나머지 조합은 W3C 혼합 함수를 취하고, alpha 모드의 겹침 가중치와 그 Porter-Duff 계수를 씁니다(over, atop, out, conjoint/disjoint over). 그리기 순서는 렌더 트리를 따릅니다. 각 그룹 안은 그리기 순서로 정렬하고, 그룹은 그 파츠가 그 자세에서의 그리기 순서로 정렬에 참여합니다. 격리 파츠의 그룹은 먼저 비운 레이어에 그린 뒤, 그룹의 곱하기/스크린 색을 취하고, 불투명도와 마스크 커버로 alpha를 스케일한 다음, 그룹의 혼합 모드로 합성합니다. 프레임 사이에는 진자 물리를 진행합니다.

### VTube Studio 모델 패키지

내보내기 디렉터리 전체를 VTube Studio의 `Live2DModels`에 넣고, VTube Studio를 열거나 다시 시작합니다. `<名称>.vtube.json`은 페이스 캡처 매핑과 핫키를 저장하고, `FileReferences.Model`은 같은 디렉터리의 `<名称>.model3.json`을 가리킵니다. 후자는 `.moc3`, 텍스처, 내보낸 물리, 모션, 표정 등의 자원을 참조합니다. VTube Studio는 모델 선택 아이콘으로 512 × 512 PNG 또는 JPG를 권합니다. [공식 가져오기 설명](https://github.com/DenchiSoft/VTubeStudio/wiki/Loading-your-own-Models)

내보내기는 모델의 기본 자세로 투명 배경의 `<名称>.icon.png`를 만들고, 보이는 내용에 맞춰 등비로 축소해 가운데에 두며, `FileReferences.Icon`에 상대 파일 이름을 적습니다. 화면이 모두 투명이면 아이콘을 건너뜁니다.

모션과 표정 핫키는 실제로 쓴 파일을 참조하고, 프로젝트의 이름을 씁니다. 생성한 핫키는 사용자가 트리거 방식을 할당할 때까지 기다리며, 키보드 필드 세 개는 비우고, `Triggers.ScreenButton`은 `-1`을 씁니다. 이 값은 VTube Studio에 함께 있는 모델의 미할당 값과 같으며, 이전 내보내기가 `0`을 써서 표정 편집기를 열지 못할 수 있던 문제를 고칩니다. VTube Studio 공식 설명은 설정 파일의 용도를 기록하고, 필드 값은 실제로 저장한 설정을 참고합니다. ## 표정, 자세, 이벤트

표정, 자세, 모션 이벤트는 프로젝트 데이터이며, 모션 클립과 같이 Rig를 바꾸지 않습니다. `core/ModelSidecars.kt`가 정의하고, 편집은 `expression_*` / `pose_*` / `motion_set_event` 등의 문서 조작을 탑니다([MCP 편집 참고](../agent/MCP_AUTHORING.md)를 참조). `RigIrCompiler`가 그것들을 IR에 넣고, 각 대상이 IR대로 씁니다.

- **표정**: `RigEditOverlay.expressions`가 null이면, 생성한 Rig는 표준 표정을 씁니다(`ModelExpressions.standard`: 미소, 슬픔, 화남, 놀람. 이름은 인터페이스 언어를 따르고, 각 표정은 모델에 있는 파라미터만 유지하며, 파라미터가 하나도 없으면 생략. Rig 모듈의 파라미터(눈 형태, 눈썹 각도, 웃는 눈, 눈 가늘게, 얼굴 붉힘 등)가 모델에 있으면 각 표정을 더 멀리 밀어 냄. 수줍음, 졸림, 침울 세 개는 모델에 얼굴 붉힘 파라미터, 맞춘 눈의 가늘게 뜨기 파라미터, 침울 파라미터가 있을 때만 생성). 가져온 CMO3 모델에는 표정이 없습니다. 첫 편집이 그때의 목록을 프로젝트에 거두고, 그 뒤로는 프로젝트의 목록만 내보냅니다(항목이 없는 표정도 그대로 내보내며, 호스트가 재설정할 때 쓰는 표정 없음입니다). `moc3`는 표정마다 `<base>.<id>.exp3.json`을 하나 씁니다(`Type`, `FadeInTime`, `FadeOutTime`, `Parameters`의 `Id` / `Value` / `Blend`). 목록 순서대로 model3의 `FileReferences.Expressions`에 씁니다(`Name`은 표정 이름, `File`은 파일 이름). `p2lrt`는 `EXPR` 블록을 씁니다. 표정 ID는 파일 이름에 안전한 문자 1–64개로 제한되고, 이름은 프로젝트 안에서 유일합니다.
- **자세**: `moc3`는 `<base>.pose3.json`을 씁니다(`Type`, `FadeInTime`, `Groups` 안의 각 파츠 `Id`와 `Link`). model3의 `FileReferences.Pose`에 쓰며, 모델에 있는 파츠만 유지하고, 그룹이 없으면 쓰지 않습니다. `p2lrt`는 `POSE` 블록을 씁니다(파츠가 둘 이상인 그룹만 유지).
- **이벤트**: 클립 이벤트는 motion3의 `UserData`에 씁니다(시간순, `Meta.UserDataCount` / `TotalUserDataSize`를 동기화). `.can3`는 씬의 사용자 데이터 프레임에 쓰고, `p2lrt`는 클립 확장 기록에 씁니다. 이벤트만 있고 곡선이 없는 클립은 다른 빈 클립과 같이 내보내지 않습니다.
- **파라미터와 파츠의 변화**: 파라미터를 삭제하면 그 표정 항목도 함께 삭제됩니다. 파라미터 범위를 줄이면 덮어쓰기 방식의 값은 새 범위 안으로 들어갑니다(`WorkspaceDocumentEdits.parameter`). `ModelSidecars.withIdRenamed`는 파라미터나 파츠 ID를 바꿀 때 모션 곡선, 표정 항목, 자세 파츠를 함께 갱신하는 범용 인터페이스입니다. ID를 바꿀 때는 이것을 호출해야 합니다(아직 연결되지 않음). 그 밖의 경우(스윙, 시뮬레이션, 레이어 삭제, 다시 생성)에 남은 끊긴 참조는 프로젝트에 남습니다. 편집은 이번에 쓴 항목과 파츠만 검증합니다(표정 또는 자세 그룹 하나는 자신이 원래 가진 끊긴 참조만 유지). `expression_get` / `expression_list`의 `missing`과 `pose_get`의 `missing_parts`가 그것들을 나열하고, 내보낼 때 건너뜁니다.
- **쓴 ID**: `moc3`의 exp3, pose3, motion3는 moc이 실제로 쓴 ID로 오브젝트를 이름 붙입니다(`Moc3Sidecars.withWrittenIds`, cdi3와 같음). 너무 길어 줄인 ID는 줄인 표기로 바꾸고, 쓰지 않은 파츠(`hidden_parts` / `guide_parts`로 생략한 것)는 자세에서 빼며, 그룹이 비면 함께 빼고, 모션에서 그것들의 투명도 곡선도 뺍니다(곡선, 구간, 점의 개수를 동기화). ID를 모두 원래대로 쓰면 이 파일들을 해석하지 않습니다.
- **미리보기**: 편집기의 미리보기 bundle에는 pose3가 없습니다(Cubism SDK가 pose3를 불러오면 각 그룹의 첫 번째 이외 파츠를 숨김). 쓴 파일에만 있습니다.
- **내보내기 변화(3.6.0 이후)**: 생성한 Rig는 `moc3` / `vtube-studio`에서 표준 표정의 exp3, model3의 `Expressions`, VTube Studio의 전환 핫키를 더 씁니다. 가져온 CMO3는 표정을 편집하지 않으면 `p2lrt`에 표준 표정을 더 이상 넣지 않습니다. 생성한 Rig를 CMO3 교체 가져오기로 바꿀 때, 그때의 표준 표정을 프로젝트에 거둡니다.
- **다시 읽기**: `PSD2LivePipeline`의 bundle 검증은 model3가 참조하는 각 exp3, pose3, motion3를 해석합니다. 메시만 내보내면 표정과 자세를 쓰지 않습니다.

## CMO3 참조와 저작 데이터

CMO3를 쓰기 전에 메시의 텍스처 출처 참조를 해당 출처의 텍스처 페이지와 타일로 물화하고, 소비 메시 자신의 UV와 키폼을 유지합니다. `canvas`와 `native` 두 레이어 쓰기 모드 모두 이 리그를 씁니다. Glue의 기존 ID는 파일과 함께 쓰이고 가져올 때 복구됩니다. ID가 없는 Glue는 결정적 예비 이름을 씁니다. 런타임 정점 가중치 그룹은 CMO3에 저장할 수 없으며, 그룹마다 메시 ID로 `structure` / `dropped`를 보고하고, 조용히 손실 없음으로 치지 않습니다.

## Cubism Animator

`cmo3` 대상은 `<base>.cmo3`를 쓰는 동시에 IR의 모션 클립을 `<base>.can3`로 씁니다(`Can3`, `:targets:cubism`). 이전 「Live2D 모델 내보내기」도 CMO3를 체크하면 같이 씁니다. 「motion3/모션 내보내기」를 끄거나 모델에 메시만 있으면 클립이 없고, can3도 쓰지 않습니다.

- **컨테이너**: cmo3와 같은 CAFF이며, 난독화하고 압축한 `main.xml` 하나만 있습니다.
- **연결 모델**: can3에는 모델이 없습니다. 유일한 자원은 파일 이름으로 같은 디렉터리의 `<base>.cmo3`를 참조합니다. 파라미터는 ID(`live2dParam_<Id>`)로 연결되고, 파츠 투명도 트랙은 같은 내보내기의 cmo3에서 그 파츠의 GUID를 답니다. cmo3의 GUID는 내보낼 때마다 다르므로, can3는 같은 내보내기의 cmo3와만 짝이 됩니다.
- **씬**: 클립마다 씬 하나이며, 이름은 `<base>.<file>`이고, moc3로 내보낸 motion3 파일 이름과 같습니다. 씬은 Animator의 고정 트랙 구조를 그대로 씁니다. 루트 그룹 트랙과 모델 트랙, 모델 트랙 위에 비주얼, 파라미터, 파츠 투명도, 립싱크, 깜빡임 다섯 효과입니다. 클립의 길이, 프레임률, 순환, 페이드 인·아웃, 사용자 데이터(이벤트)는 씬과 모델 트랙에 씁니다.
- **곡선**: 파라미터 곡선은 파라미터 효과로 들어갑니다(표시 이름은 파라미터 이름, 범위는 파라미터 범위를 취해 모든 키 점을 덮도록 확장). 파츠 투명도 곡선은 파츠 효과로 들어가고, 전체 투명도는 비주얼 효과의 불투명도를 바꿉니다. 곡선 자신의 페이드 인·아웃은 트랙 옵션에 씁니다. 키 점은 가장 가까운 프레임으로 반올림하고, 베지에 제어점은 원래 시간(소수 프레임)을 양쪽 핸들로 유지하며, 계단과 역계단 구간은 유형을 유지합니다.
- **손실**: 깜빡임, 립싱크 효과 곡선은 Animator에 대응하는 트랙이 없어, 모델에 없는 파라미터나 파츠를 가리키는 곡선과 함께 쓰지 않으며, `timeline` / `dropped`로 기록합니다.

## Spine

Spine에는 스켈레톤이 있고 파라미터는 없습니다. 내보낸 스켈레톤 공간의 원점은 캔버스 아래 변의 중점이고, y는 위이며, 다음을 따릅니다.

- **스켈레톤**: 회전 디포머마다 뼈 하나가 됩니다. 부모 뼈는 그 위의 가장 가까운 회전 디포머입니다(없으면 뿌리 뼈). 곧 디포머 트리를 미러합니다. 뼈의 설정 자세와 키 값은 내보내기 쪽이 편집기의 회전 규칙으로 구합니다([런타임](RUNTIME.md) 「평가 규칙」을 참조. 각도는 키폼 각도에 기준각을 더함. 부모가 회전이면 원점은 부모 변환을 거치고 각도와 스케일이 겹치며, 부모가 수직으로 뒤집히거나 음수 스케일이면 반 바퀴를 더 돎. 자신의 뒤집기는 자식 좌표에만 작용. 부모가 Warp이면 프레임은 강체를 유지하고 칸 방향을 따라 회전). 세계 프레임을 구한 뒤 부모 뼈에 상대적인 로컬 값으로 바꿉니다. 이 프레임은 모두 회전에 뒤집기가 있는 등비 스케일이며, 곱한 뒤에도 같은 종류이므로 회전과 scaleX/scaleY만 씁니다(뒤집기는 음수 스케일). 전단은 필요 없습니다. 뼈마다 고정 회전각이 하나 더 있어, 뼈 방향이 그것이 담은 메시의 중심을 가리키고, 길이는 그 방향으로 메시의 가장 먼 거리입니다. 어떤 샘플 자세에서든 스케일이 영으로 가는 회전은 뼈가 되지 않으며, 그 자식은 위쪽 뼈에 베이크하고 보고합니다.
- **메시**: 보이는 메시마다 가중치 없는 메시 어태치먼트입니다. 슬롯은 가장 가까운 회전 뼈에 매달리고, 정점은 그 뼈 공간의 좌표입니다. 뼈가 표현하지 않는 부분(Warp, 메시 키폼, 블렌드 셰이프, Glue)은 그 뼈 공간의 deform 오프셋으로 씁니다. 회전 조상이 없는 메시는 뿌리 뼈에 매달리며, 이전과 같습니다.
- **파라미터**: 파라미터마다 애니메이션 `param/<参数 ID>` 하나. 길이는 1초이고, 시간은 파라미터 정규화 값입니다(최소 0, 최대 1). 파라미터 샘플 점에서 뼈의 `rotate`(설정 각도에 상대적인 증분), `translate`(증분), `scale`(설정 스케일에 상대적인 배수), 메시 deform을 키로 넣습니다. 런타임은 파라미터마다 트랙을 하나 열고, 겹침 혼합(`MixBlend.add`)을 쓰며, 파라미터 값으로 트랙 시간을 설정합니다. 뼈가 부모-자식으로 곱해지므로, 여러 파라미터가 동시에 회전 사슬 하나를 회전하면 직렬로 조합되며, 각자의 캔버스 오프셋을 더하는 것이 아닙니다. 키폼 투명도는 슬롯 `rgba`로 쓰고, 파라미터에 따라 변하는 그리기 순서는 `drawOrder`로 씁니다.
- **교차항**: `sample_pairs`개의 두 파라미터 조합 자세에서, Spine의 겹침 규칙(뼈 값과 deform 오프셋을 트랙마다 더하고, 스케일은 설정 스케일에 배수 차를 더하며, 뼈는 단계마다 곱함)으로 재구성해 평가기와 비교합니다. 0.5픽셀을 넘는 메시는 손실 보고서에 씁니다. Warp 아래의 회전(예: 자동 스켈레톤이 몸 Warp 아래에 매단 머리와 위팔 회전)은 단일 파라미터 샘플 점에서는 정확하지만, 그 Warp를 움직이는 파라미터와 조합하면 받침점이 Warp 변형을 따르지 않아 근사로 보고합니다. Warp로 구현한 관절(아래팔, 손, 상체 굽힘)은 여전히 뼈 공간에서 파라미터대로 더합니다.
- 모션 클립마다 애니메이션 `clip/<名称>` 하나. `clip_fps`로 샘플한 뒤 `KeyReduction`으로 선형 보간이 다시 만들 수 있는 키프레임을 뺍니다. deform 허용 오차는 `key_tolerance` 픽셀이고, 뼈의 회전과 스케일 허용 오차는 캔버스 대각선으로 같은 픽셀 양에 환산하며, 오프셋은 천분의 일 픽셀까지 유지합니다.
- 아틀라스는 페이지마다 페이지 전체를 덮는 영역 하나이며, 영역 이름은 그 페이지 그림과 같습니다(`<名称>_<i>`, 그림은 `<名称>_<i>.png`). 메시 어태치먼트의 `path`가 그것을 가리키고, UV는 그 페이지를 직접 참조합니다. 런타임은 아틀라스로 영역을 찾습니다. Spine Editor는 데이터를 가져올 때 아틀라스를 읽지 않고, `images` 디렉터리(`./`)에서 같은 이름 그림을 찾으므로, 가져온 뒤 메시가 바로 표시됩니다.
- 마스크는 자르기 어태치먼트로 바뀝니다. 마스크된 메시 앞에 자르기 슬롯을 넣습니다(`end`가 그 메시를 가리킴). 다각형은 마스크 메시 하나의 바깥 윤곽이며, 마스크가 여러 개이거나 윤곽이 여러 개이면 볼록 껍질을 취하고 보고합니다. 자르기 슬롯은 모든 마스크 메시가 뼈 하나를 공유하면 그 뼈에 매달고, 아니면 뿌리 뼈에 매달립니다. 자르기 어태치먼트는 마스크 메시를 따라 변형 키를 쓰고, 그리기 순서가 바뀌면 마스크된 메시와 함께 이동합니다. Spine은 다각형으로 자르며, 텍스처 alpha로 자르지 않습니다. 반전 마스크는 표현할 수 없어 버리고 보고합니다.
- **물리**: 진자 그룹에서 출처가 각도인 출력은, 그 파라미터의 애니메이션이 뼈를 회전하면, 그 뼈에 Spine 4.2 물리 제약을 만듭니다(`rotate` 1). Spine은 뼈 자신의 운동으로 제약을 구동하고, 진자의 입력 파라미터를 읽지 않습니다. 설정은 경험적으로 매핑합니다(관성 1, 강도 = 100 × 가속도, 감쇠 = 이동성, 혼합 = 출력 가중치 / 100, `fps`는 물리 그룹 프레임률, 기본 60). 원래 응답을 근사할 뿐이며, 근사로 보고합니다. 그 출력 파라미터가 함께 키로 넣은 변형은 시뮬레이션되지 않으며, 보고서에 적습니다. 출력이 뼈 회전을 구동하지 않는 진자 그룹(예: 자동 생성한 머리카락 진자. Warp에 작용)은 버리고 보고합니다.
- **바이너리**: `binary=true`이면 Spine 4.2 바이너리 `.skel`을 씁니다(공개된 spine-runtimes 4.2 `SkeletonBinary` 배치: 빅 엔디안 수치, 가변 길이 양의 정수, 문자열 테이블, nonessential 데이터 없음). 내용은 JSON과 같습니다. 바이너리 메시는 삼각형 수를 저장하지 않으며, 읽기 쪽은 「2 × 정점 수 − hull − 2」로 유도하므로, hull 길이는 메시의 삼각형 수에 따라 정합니다. 삼각형이 그 식이 허용하는 값보다 많은 메시(삼각형이 중복될 때만 나타남)는 끝에 첫 정점의 쓰지 않는 사본을 붙입니다.
- 검증(구현되어 있고 아래 테스트를 거침. 공식 Spine 런타임은 쓰지 않음. 그 라이선스는 Spine 라이선스 보유를 요구). Spine 4.3 평가판은 JSON을 가져와 모든 메시를 표시할 수 있습니다(버전 불일치와 nonessential 데이터 없음은 경고일 뿐). 4.2 바이너리 `.skel`은 편집기가 버전 일치를 요구해 가져올 수 없습니다. 애니메이션과 마스크는 편집기에서 확인하지 않았습니다.
  - 단위 테스트는 Spine 4.2 런타임의 규칙(겹침 트랙, 키프레임 선형 보간, 가중치 없는 deform은 설정 자세에 상대적인 오프셋, 뼈는 정상 상속으로 단계마다 곱함, 그리기 순서는 오프셋 알고리즘으로 재배열)으로 자세를 재구성합니다. 3단 회전 사슬(메시 키폼, 뒤집기, 음수 스케일 포함)이 단일 파라미터, 파라미터 사이, 모든 파라미터가 동시에 변하는 무작위 자세에서, 같은 회전 규칙으로 독립 구현한 테스트 평가기와 오차가 0.002픽셀보다 작습니다. 모션 클립은 샘플 프레임에서 일치합니다.
  - 테스트 안에서 공개 배치로 쓴 최소 `.skel` 읽기가 바이너리를 다시 읽습니다. 뼈, 슬롯, 물리 제약, 어태치먼트, 각 애니메이션으로 재구성한 자세가 JSON과 일치하고, 두 번 내보내기가 바이트 단위로 같습니다.

## DragonBones

Spine과 같은 베이크 방식입니다. 뼈를 하나씩 두고, 보이는 메시마다 가중치 없는 메시 표시입니다(원점은 캔버스 아래 변의 중점, y는 아래). 파라미터마다 1초 애니메이션 `param/<参数 ID>`이며, 변형(ffd) 프레임은 파라미터 키 점을 반올림한 프레임에 있습니다. 호스트는 파라미터 값으로 위치를 잡고 층으로 겹칠 수 있습니다. 클립마다 프레임으로 샘플한 뒤 간소화합니다. 프레임 사이 보간은 `tweenEasing: 0`을 명시적으로 씁니다(기본은 계단). DragonBones 런타임은 16비트 오프셋으로 각 애니메이션의 변형 부동소수점 데이터를 주소 지정합니다(프레임마다 그 메시의 모든 정점을 저장). 약 3.2만 개의 부동소수점을 넘으면 두 배로 늘린 뒤 이분하는 허용 오차로 키프레임을 간소화하고, 손실 보고서에 사용한 허용 오차를 씁니다. 검증: `DragonBonesFidelityTool`(`PSD2LIVE_TOOLS=1`, node 필요)이 `tools/dragonbones-check`(공식 DragonBones 5.7 런타임 코어, 렌더 없음)로 내보낸 것을 재생합니다. 스켈레톤이 없는 샘플의 단일 파라미터 자세는 키프레임에서 편집기와 오차가 0.25픽셀보다 작습니다. 스켈레톤이 있으면 위 상한의 영향을 받는 애니메이션 오차는 보고한 허용 오차를 넘지 않으며, 클립 오차는 보고서를 참조합니다.

## glTF

보이는 메시마다 조명 없는(`KHR_materials_unlit`), 양면, 반투명 혼합의 평면 메시가 됩니다. 정지 자세에 있고, 그리기 순서에 따라 층마다 관찰자 쪽으로 0.5밀리미터 이동합니다. 단위는 미터입니다(`pixels_per_meter`, 기본 1000). y는 위이고, 원점은 캔버스 아래 변의 중점입니다. 파라미터의 기본이 아닌 키 점마다, 그것이 움직이는 메시에 모프 타깃이 하나 됩니다(`extras.targetNames`는 `参数=关键点`). 파라미터 값에서 가중치로의 매핑은 키 점 사이의 선형 모자 함수이며, 파라미터와 그 키 점은 `extras.psd2live.parameters`에 나열됩니다. 모션 클립은 `clip_fps`로 샘플해 가중치 애니메이션이 되고 `KeyReduction`으로 간소화합니다. 검증: 단위 테스트가 가중치로 샘플 자세를 재구성합니다. tml 내보내기는 Khronos glTF Validator에서 오류 0, 경고 0이며, Godot 4.4에서 정지 자세와 고개 흔들기 모션이 올바르게 렌더됩니다.

## Unity

Unity 6.0(6000.0) 이상이 필요합니다. 내보내기 디렉터리는 전체를 Unity 프로젝트의 `Assets`에 넣을 수 있습니다. 함께 있는 설치 스크립트는 `Psd2LiveUnityImporter.cs`를 `Assets/PSD2Live/Editor`에 설치한 뒤(이미 있고 버전이 오래되지 않았으면 덮어쓰지 않음) 자신을 지우므로, 두 번째 캐릭터도 전체를 복사하면 됩니다. 임포터는 그리기 순서상 이웃하고 같은 텍스처에 놓인 메시를 스키닝 메시 하나로 합쳐 공유 뿌리 뼈에 붙입니다. 다른 텍스처의 파츠가 사이에 끼면 그 구간이 끊기고, 각 구간은 자신의 `sortingOrder`를 쓰므로, 앞머리가 뒷머리와 같은 페이지라고 해서 페이지 전체가 얼굴 앞에 그려지지는 않습니다. 파라미터의 기본이 아닌 키 점마다 Blend Shape가 됩니다(가중치 0–100의 모자 함수, glTF와 같음). 여러 파라미터가 동시에 변하면 겹침 근사입니다. 모션 클립은 `clip_fps`로 샘플해 Animator 클립이 됩니다. 이름이 Idle인 클립이 있으면 그것이 기본 상태이고, 없으면 첫 클립을 재생합니다. 나머지 클립은 같은 이름의 `.controller`에 쓰이며, 전환이 없으면 자동으로 재생하지 않습니다. 프리팹의 Animator는 그 파일이 생성된 뒤 그것을 가리키고, 씬에서 아직 내장 컨트롤러를 가리키는 인스턴스는 가져오기나 계층 변화가 있을 때 바뀝니다. 파라미터마다 기본 상태 기계에 들어가지 않는 `param_<id>` 클립이 하나 더 있어, 프로젝트에서 따로 재생할 수 있습니다. 단위는 `pixels_per_unit`(기본 100)의 역수이고, y는 위이며, 원점은 캔버스 중심입니다. 텍스처 V는 PSD2Live의 왼쪽 위 원점에서 Unity의 왼쪽 아래 원점으로 뒤집힙니다. 캐릭터가 화면 밖에 있으면 재생하지 않습니다. 검증: 대상 모듈의 단위 테스트가 미끄러지는 사각형의 정점, Blend Shape, 0.5초 가중치를 대조합니다. 완전한 캐릭터 tml은 Unity 6000.4.7f1의 내장 렌더 파이프라인 프로젝트에서 정지 자세로 가져와지고, Play가 Idle을 재생합니다.

## 클릭 영역

문서의 클릭 영역(`rigEdits.hitAreas`. 편집기 인스펙터, 계층 오른쪽 클릭 메뉴, MCP `hit_area_*` 편집)은 테스트 순서대로 `RigIR.hitAreas`로 컴파일됩니다. 각 영역에는 자신의 ID(예: `HitAreaHead`), 호스트가 조회하는 이름(예: `Head`), 덮는 메시가 있습니다. 메시를 분할하면(연결 덩어리, 다각형, 깊이 분할) 조각이 원 메시가 영역에서 차지한 자리를 이어받고, 레이어를 삭제하면 그 메시가 영역에서 빠집니다(그래서 영역에 메시가 없으면 함께 삭제). IR은 영역이 가리키는 모든 메시를 유지합니다. 대상이 쓸 때 Rig에 이미 없는 메시는 건너뛰고, 각각 `structure` / `dropped` 손실을 기록합니다. 메시가 하나도 없는 영역도 문서 자신의 영역으로 치며, 런타임의 자동 영역으로 되돌아가지 않습니다. 클릭 영역을 담지 않는 대상(`cmo3`, `spine`, `dragonbones`, `gltf`, `unity`, `psd-pose`, 래스터 계열)은 영역마다 `structure` / `dropped` 손실을 기록합니다.

- **`moc3` / `vtube-studio`**: model3.json의 `HitAreas`에 씁니다. 각 항목의 `Name`은 영역 이름이고, `Id`는 moc에 쓴 ArtMesh ID입니다(ID가 줄면 줄인 값을 취함. moc에 쓰지 않은 메시, 예를 들어 내보내기 옵션이 생략한 숨긴 메시는 나열하지 않고 `structure` / `dropped` 손실을 기록. 하나도 남지 않으면 `HitAreas`를 쓰지 않음). model3의 각 항목은 ArtMesh 하나만 가리키므로, 메시가 여러 개인 영역은 같은 이름의 여러 항목으로 쓰고, `structure` / `approximated` 손실을 기록합니다(이름만으로 첫 항목을 찾는 호스트는 첫 메시만 검사). 영역 자신의 ID는 model3에 없습니다. 클릭 영역이 없는 문서는 `HitAreas`를 쓰지 않으며, 내보내기는 바이트 단위로 변하지 않습니다.
- **`p2lrt`**: 버전 2는 선택 청크 `HITA`를 씁니다(영역 ID, 이름, 메시 인덱스). 문서에 클릭 영역이 없으면 의미에서 자동으로 얻은 `HitAreaHead`(얼굴)와 `HitAreaBody`(상의, 없으면 목 또는 하의)를 그대로 씁니다. 버전 1에는 클릭 영역이 없으며, 문서의 각 영역은 `structure` / `dropped` 손실을 기록합니다.
- **히트 규칙**: 목록 순서대로 처음 맞는 영역을 취합니다. 메시가 보이고, 불투명도가 0보다 크며, 그 삼각형(변 포함)이 그 점을 포함하면 맞습니다. 편집기 미리보기 클릭, MCP `hit_area_test`, 런타임 `p2l_hit_test`는 같은 규칙을 씁니다. Cubism SDK 예시는 메시의 경계 사각형으로 판단하므로, 이것과 다를 수 있습니다.
- 바이너리 IR(`RigIrBinary`)은 인코딩 버전 6부터 이 필드를 쓰며, 더 이전 버전은 빈 값으로 읽습니다.

## 손실 보고서

내보낼 때마다 파일 옆에 `<名称>.<目标>.report.json`을 씁니다.

```json
{"target":"gif","compiler":"2.0.4","files":["model.gif"],
 "losses":[{"object":"*","feature":"structure","handling":"baked","note":"..."}]}
```

`handling`은 `baked`(시각을 유지하고 부피를 키움), `approximated`(받아들일 수 있는 오차), `dropped`(버림)입니다. `object`는 안정 ID이고, `*`는 Rig 전체를 뜻합니다. 오차를 측정하면 `error`를 붙입니다. 보고서는 컴파일러 버전을 기록해, 두 번 내보내기의 차이를 추적합니다.

## 결정성

같은 IR과 같은 버전 컴파일러는 바이트 단위로 같은 출력을 만듭니다. 내보내기는 타임스탬프와 난수를 넣지 않습니다. 예외는 `cmo3`입니다. Cubism Editor는 오브젝트마다 유일한 GUID를 요구하므로, 파일 바이트는 매번 다르고 내용은 같습니다. 내보내기 경로 재구성은 `ExportGoldenTool`(`PSD2LIVE_TOOLS=1`)로 전후 제출의 파일 요약을 비교합니다. cmo3는 다시 읽은 뒤 moc3로 내린 요약을 비교합니다.

## 사용

- 인터페이스: 「파일 → Live2D 모델 내보내기…」가 moc3 / cmo3를 내보냅니다. 「파일 → 다른 형식으로 내보내기」는 런타임과 플레이어, 이미지와 영상, 분리 PSD로 묶어 나머지 비실험적 대상을 나열합니다. 대상마다 자신의 대화상자를 열고, 현재 제출된 상태를 내보내며 손실을 나열합니다. 각 대상은 `ExportTarget.settings`에서 자신이 읽는 설정 키(모션 선택, 스위치, 범위가 있는 수치, 텍스트)를 선언합니다. 대화상자는 선언대로 해당하는 행을 만들고, 사용자가 바꾼 값만 보내며, 나머지는 대상 기본값 또는 프로젝트 내보내기 설정을 취합니다. 변경은 이번 실행에서 대상별로 유지됩니다. 새 대상은 메뉴 그룹에 등록해야 합니다(`exportMenuGroups`, `ExportTargetSettingsTest`가 검사).
- 명령줄: [개발과 명령줄](../guide/DEVELOPMENT.md)의 `export` 명령을 참조합니다. `psd2live targets`는 각 대상과 그 설정 키, 값 범위, 기본값을 나열합니다.
- 편집기 자신의 Cubism 미리보기 패키지와 `moc3` 내보내기는 같은 컴파일입니다. 「Live2D 모델 내보내기」(MCP `project_export_model`)와 「다른 형식으로 내보내기」는 모두 제출된 모델 자체를 씁니다(`PSD2LivePipeline.export`). 소스 그림에서 다시 구축하지 않고, 기초 Rig도 생성하지 않습니다. 둘은 보고만 다릅니다(전자는 다시 읽어 검증하고 `.psd2live.json`을 쓰며, 후자는 손실 보고서를 씀). 명령줄은 먼저 같은 구축 경로(`buildPreview`)로 모델을 얻은 뒤 씁니다.
