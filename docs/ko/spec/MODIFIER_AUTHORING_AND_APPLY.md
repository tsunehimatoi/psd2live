# 모디파이어와 수동 편집의 공존

## 목표와 경계

일반적인 형태 수정은 모디파이어와 함께 있어야 하며, 사용자가 먼저 모디파이어를 적용할 것을 요구하지 않습니다. 생성 논리에서 정말 벗어나야 할 때는, 범위를 확인할 수 있고 실행 취소할 수 있는 적용 조작을 제공합니다. 암묵적으로 고정할 수 없고, 수동 수정을 조용히 버릴 수도 없습니다. 오브젝트의 부모-자식 관계, 모디파이어 평가 의존, 플러그인 패키지 의존은 각각 처리합니다.

브러시는 기하 편집을 만드는 도구 중 하나일 뿐입니다. 정점 드래그, 변형 상자, 임시 디포머, 경로와 핸들, 수치 입력, 키폼 조작, Agent 명령은 같은 편집 계약을 따라야 합니다. 상호작용 도구는 샘플링을 맡고, 모델 층은 키폼 준비, 귀속, 재생, 의존 검증을 맡습니다. 스켈레톤 자세 도구의 출력은 파라미터 값이며, 파라미터를 고정한 뒤 기하를 고치는 조작이 아닙니다.

## 편집 계약

한 번의 편집은 문서 버전, 대상, 자세, 채널, 실행 단계, 병합 방식을 고정합니다. 표시, 픽, 스냅, 미리보기, 제출은 같은 단계의 모델과 좌표를 씁니다. 편집 중에 문서가 바뀌면 제출을 취소하거나 거부합니다. 제출이 실패하면 부분 모델이나 히스토리 기록이 생기지 않습니다.

키가 아닌 값의 편집은 기본적으로 현재 파라미터 값을 유지하고, 보간 결과에서 필요한 키폼을 준비합니다. 사용자는 가장 가까운 공통 키폼을 명시적으로 고를 수 있습니다. 여러 오브젝트는 파라미터별로 키 값의 교집합을 구하고, 한 번의 선택으로 가장 가까운 값을 취합니다. 교집합이 비면 스냅을 막고 이유를 설명합니다. 오브젝트마다 파라미터를 반복해서 바꿀 수 없습니다. 제스처가 시작된 뒤 비동기 제출이 끝나거나 취소될 때까지 자세와 병합 방식을 유지합니다.

`edit_stage`는 보정이 놓일 위치를 지정합니다.

| 값 | 원본 모델과 실행 위치 |
| --- | --- |
| `auto` | 현재 최종 모델. 채널의 실제 기록자에 따라 자동으로 귀속 |
| `base` | 모디파이어 이전의 저작 모델 |
| `modifier:<id>` | 지정한 유효 모디파이어 이후 |
| `final` | 이번 편집 시점의 마지막 유효 모디파이어 이후. 유효 노드가 없으면 기초 |

명시적 단계는 현재 기하와 키폼 값을 받으며, 토폴로지 조작은 받지 않습니다. 한 트랜잭션은 단계를 섞을 수 없고, 그 단계에 아직 없는 파라미터를 참조할 수도 없습니다. 끈 노드와 실패한 노드는 편집 원본이 될 수 없습니다. `final`은 편집을 시작할 때 구체적인 위치로 풀리며, 이후에 추가된 모디파이어가 이전 보정을 옮기지 않습니다.

## 보정의 귀속과 병합

귀속 보고는 오브젝트와 기존 키폼의 실제 고쳐 쓰기를 기록합니다. 같은 채널은 마지막 기록자에게 귀속되며, 오브젝트 생성자나 새로 추가된 축만으로 판단할 수 없습니다. 기초 편집은 생성 전에 실행됩니다. 국소 보정은 관련된 생성 결과 뒤에 둡니다. 최종 겉모습 보정은 저작자가 명시적으로 고릅니다.

`correction_mode`는 기하 병합 방식을 고릅니다.

- `delta`: 메시와 Warp는 편집 전후 로컬 좌표의 차를 저장합니다. 생성할 때마다 한 번 재생한 뒤 하류를 실행하며, 지난번 재계산의 변위를 누적하지 않습니다.
- `absolute`: 명시적인 고정 덮어쓰기를 저장합니다. 건드리지 않은 성분은 생성 결과를 따릅니다. 삼자 충돌이 나면 저작자 값을 유지하고 충돌을 보고합니다.

명시적 키폼 API가 모드를 지정하지 않으면 고정 덮어쓰기 의미를 유지합니다. 캔버스는 도구 막대 선택에 따라 제출합니다. 모드가 기록되지 않은 이전 덮어쓰기는 역사적 삼자 병합 규칙을 유지하며, 자동으로 증분으로 옮기지 않습니다.

회전 보정의 피벗과 각도는 로컬 증분을 쓰고, 양의 스케일은 비율을 씁니다. 명시적 대입은 고정 덮어쓰기를 씁니다. 색, 투명도 등의 채널은 명시적인 설정 의미를 유지하며, 강제로 더하지 않습니다.

기하 보정은 리그 지문을 기록합니다. 메시는 정점 수, 연결 관계, UV, 부모 사슬입니다. Warp는 격자 행과 열, 보간 방식, 부모 사슬입니다. 리그가 바뀐 뒤에는 기록을 남기고 불일치를 보고하며, 계속 적용하지 않습니다. 현재는 보수적인 검사를 씁니다. UV를 다시 배열해도 보정을 처리해야 할 수 있습니다. 토폴로지는 자동으로 옮기지 않습니다.

알고리즘 쓰기와 저작 보정은 따로 기록합니다. 알고리즘끼리는 쓰기를 조합할 수 있는지 계속 검사합니다. 저작 보정은 지정한 단계에서 재생하며, 모션 노드 뒤에 걸린 기하 보정을 모션 알고리즘이 만든 기하로 잘못 계산할 수 없습니다. 캐시 재사용과 체크포인트 재생은 같은 알고리즘 쓰기 기록을 씁니다.

## 적용 방식

`modifier_apply_plan`은 읽기 전용 범위 계획이며, GUI와 명령이 공유합니다. 적용 전에는 고정할 항목, 끌 항목, 남길 항목, 보정 수, 고정 덮어쓰기 충돌, 불일치 기록, 경계를 넘는 의존을 보여 줍니다. 적용 뒤에도 다시 평가하고 완전한 결과를 비교해야 합니다.

| 범위 | 동작 |
| --- | --- |
| `selected` | 고른 노드를 원래 평가 위치에 고정하고, 앞뒤 노드를 유지 |
| `prefix` | 고른 노드까지의 접두를 기초에 등가로 쓰고, 접미를 유지 |

`A → B → C`에 대해, `B(A(基础))`를 새 기초로 만든 뒤 A를 계속 실행할 수 없습니다. 단일 항목 적용은 원 노드의 전후 출력, 능력 계약, 실제로 읽은 입력, 알고리즘 쓰기를 저장합니다. 원 알고리즘은 더 이상 실행하지 않습니다. 고정한 노드의 구성, 위치, 켜고 끈 상태는 더 이상 생성 제어 항목이 아니며, 저작자는 그 영속 출력을 편집합니다.

적용에는 완전한 결과 검증이 들어갑니다. 현재 화면만 비교할 수 없습니다. 켠 항목의 불일치 보정과 실패한 의존은 적용을 막습니다. 고정 덮어쓰기 충돌은 현재 저작자 값을 유지하고 알립니다. 끈 항목의 저작 기록은 잠든 채로 남습니다. 접두를 계속 적용할 때, 끈 모션과 물리 그룹은 다시 켤 수 있습니다.

플러그인 신원은 히스토리 아카이브에 계속 남습니다. 고정한 노드는 런타임에 원 플러그인 패키지를 찾을 필요가 없습니다. 이전 접두 능력 기록에 `provides` 계약이 없으면 호환 조회를 유지합니다. 입력 계약이 호환되지 않으면 상류 변경을 거부하고, 선행 의존을 처리하라고 알립니다. 무효가 된 출력으로 고정한 내용을 대신할 수 없습니다.

## 상류·하류 의존과 내용 편집

계획은 구성 능력, 명시적 파라미터 제공자, 수동 구조 참조, 모션 입력의 경계를 넘는 의존을 검사합니다. 저작 보정은 키 파라미터와 대상 오브젝트로 앞선 실제 기여자를 찾습니다. 고정한 노드는 바뀌거나 제거된 오브젝트의 입력 신원을 저장하고, 해당하는 의존을 계속 표시합니다. 공유 부모, 파라미터, 트랙, 시뮬레이션 입력은 범위 판단에 넣어야 합니다. 시뮬레이션 입력 신원이 바뀌면 다시 베이크해야 합니다.

알려진 의존을 고정 계약이 만족할 수 있으면 하류를 유지합니다. 완전한 계약을 유지할 수 없으면 적용 범위를 넓히거나, 조작을 거부하고 이유를 설명해야 합니다. 현재는 단일 항목과 접두 두 가지 범위를 제공하며, 완전한 자동 최소 의존 닫힘은 아직 없습니다. 플러그인이 선언하지 않은 암묵적 읽기는 계획만으로 안전하다고 볼 수 없으며, 최종 재구축 검증은 항상 남습니다.

모션의 저작 기록은 얼린 구성과 독립입니다. 내장 모션은 원래 기록을 그대로 씁니다. 다른 플러그인은 실제로 추가하거나 수정한 Clip으로 저작 기록을 만들며, 노드 하나가 여러 모션을 가질 수 있습니다. 원본 Clip은 따로 저장합니다. 꺼도 곡선, 페이드 인·아웃, 이벤트, 비파라미터 트랙을 버리지 않습니다. 편집할 때는 저작자가 수정한 필드만 바꿉니다. 일반 기록, 접두 적용, 디스크 저장 경로의 방향성 회귀는 통과했습니다. 이름 변경, 곡선 편집, 켜고 끄기, 삭제는 영속 Clip을 갱신합니다. 고정한 모션을 복사하면 사본은 원래 단계에 남고, 완전한 접두 적용 뒤에는 일반 내용이 됩니다. 복사할 때 원본 채널을 유지합니다. 수정하지 않은 곡선은 원래 표현을 유지합니다. 곡선은 원 노드 위치에 이미 있는 파라미터만 참조할 수 있으며, 끈 기록도 이 제약을 검사합니다. 접두를 계속 적용하면 편집된 기록과 원본 트랙을 씁니다. 일반 모션의 파라미터, 파츠 이름 변경은 원본 참조를 함께 갱신합니다. 기록을 삭제하면 원본 데이터도 함께 제거됩니다. 작업 공간 clips 노드는 새 schema를 씁니다. 모델 오브젝트 바이너리는 버전 7로 이벤트, 비파라미터 트랙, 트랙별 페이드 인·아웃을 저장하고, 버전 4–6 읽기 호환을 유지합니다. 이 새 필드가 없는 오브젝트와 패키지 전체 보조 자원은 계속 버전 6으로 써서, 기존 worker가 읽을 수 있게 합니다. 호스트는 버전 6과 7의 패키지 전체 자원을 읽으며, 다운그레이드로 새 필드를 버릴 수 없습니다. 호스트가 관리하는 SDK는 빌드 전에 실제 직렬화 모듈을 새로 고칩니다. 지정한 외부 SDK는 자동으로 덮어쓰지 않습니다.

고정한 물리 그룹은 일반 파라미터 조정, 켜고 끄기, 맞춤, 삭제, 가져오기에 들어갑니다. 같은 ID를 가져오면 고정한 그룹을 수정합니다. 새 그룹이 같은 출력을 차지하면 가져오기 규칙에 따라 충돌 그룹을 끕니다. 내장 스윙 물리 알고리즘이 다른 그룹을 읽는 것은 충돌 검사용이며, 고정한 뒤에는 ID와 출력 충돌을 다시 검증합니다. 물리 목록 전체나 FPS를 잠그지 않습니다. 다른 플러그인은 원래 읽기 계약을 유지합니다.

일반 후보, 설정 수정, 일괄 명령이 새로운 모디파이어 실행 실패를 만들면, 부분 결과 제출을 거부합니다. 바뀌지 않은 기존 실패는 무관한 편집을 막지 않습니다. 프리셋 초기화는 명시적으로 격리된 실패를 기록할 수 있습니다. 제공자를 능동적으로 꺼서 생긴 하류 의존 중지는 복구 가능한 상태로 남으며, 알고리즘 실행 오류로 치지 않습니다. 고정한 내용의 구조 제공자를 삭제하거나 끄거나, 고정한 모션의 입력 파라미터를 삭제할 때는 하류 출력 계약을 검증합니다. 호환되지 않으면 트랜잭션 전체를 거부하고, 모델과 히스토리는 그대로입니다.

## 구현과 검수 상태

주요 입구는 `GeometryEditStages`, `GeneratedOverrides`, `RotationCorrections`, `JournalRecording`, `RigModifierEvaluator`, `AppliedModifierNode`, `ModifierApplyPlan`, `WorkspaceDocumentCommands`입니다. 캔버스는 공통 제출 경로로 단계와 병합 방식을 전달합니다.

이미 통과한 방향성 회귀 증거는 다음과 같습니다.

- 증분 재생이 누적되지 않음, 고정 덮어쓰기, 토폴로지 불일치, 중간 키 값 삽입, 공통 키 값, 기존 키폼의 실제 쓰기 귀속.
- 직접 기하, 획, Bezier, 회전 보정. 단계 원본과 픽한 대상의 키 축이 일치.
- 정점이 중간 파라미터 값에서 시작된 뒤 실제로 드래그되고, 파라미터는 유지됩니다. 취소하거나 시작점으로 되돌린 뒤 놓으면 원래 기하가 복구되고 잠금이 풀립니다.
- 단일 항목 적용은 교환 법칙이 성립하지 않는 조작 순서를 유지하고, 최종 단계 보정은 제자리에 고정할 수 있습니다. 원 플러그인이 없어도 재생할 수 있습니다.
- 고정한 모션과 물리 편집, 끈 내용을 계속 적용한 뒤의 복구, 물리 가져오기 교체와 충돌로 끄기.
- 일반 편집이 새로운 모디파이어 실행 실패를 만나면, 후보 모델이나 히스토리를 게시하지 않습니다.
- 히스토리 왕복, 작업 공간 디스크 저장 후 다시 읽기, CMO3 직렬화 읽기, 끝점과 중간 자세 비교.

주 모듈과 형식 모듈의 최종 완전 회귀는 통과했습니다(명령 `./gradlew.bat :format-compile:test :test --console=plain`. 로그 `build/modifier-authoring-final-tests-3.log`, 2분 18초). 주 모듈은 1228항을 보고했으며, 그중 1087항 통과, 141항 건너뜀, 0 실패입니다. 형식 모듈은 5항 통과입니다. 이전 프로젝트 개정 신원, 이전 형식 읽기, 플러그인 개발 닫힌 고리, 모션 원본 데이터 저장, 무효 보상의 원자적 거부, 경로, Bezier 핸들, 스켈레톤 자세 상호작용을 덮습니다. 건너뛴 항목은 통과로 치지 않습니다. 이것은 합성 데이터 검증이며, issue #81의 원래 조작 녹화가 재현되었다는 뜻은 아닙니다.

통일된 편집 입구의 검수는 정점, 변형 상자, 임시 Warp, 경로, Bezier 핸들의 자세 유지와 취소를 덮습니다. 실제 작업 공간의 정점 드래그는 비동기 제출, 실행 취소와 다시 실행, 제출 뒤 잠금 해제를 덮습니다. 스켈레톤 자세 검증은 파라미터가 드래그에 따라 바뀌고, 기하 자세 잠금을 잡지 않음을 확인합니다.

자식 겉모습을 유지하면 부모 보정 아래의 직접 자식 보상을 다시 계산합니다. 자식이 아직 현재 파라미터에 리그되지 않았으면 필요한 키폼을 준비합니다. 독립 파라미터의 중간 값은 실제 변형 오차에 따라 적응적으로 세분하며, 최대 8라운드, 라운드마다 최대 16384개의 샘플 자세입니다. 수렴하지 않으면 트랜잭션 전체를 거부합니다. 독립 파라미터 샘플 값 31개, 다시 생성, 불일치, 고정을 검증했습니다. 이 샘플 검사는 임의의 복잡한 계층에서 연속 오차 상한을 증명하지 않습니다.

의존과 복잡한 계층의 추가 검수는 통과했습니다(`modifier-authoring-tests-35.log`). 고정한 내용의 제공자를 삭제하거나 끄거나, 고정한 모션의 입력 파라미터를 삭제하면 편집 전체를 거부하고 히스토리를 바꾸지 않습니다. 완전한 접두를 적용하면 결과를 유지하고 생성 의존을 풀 수 있습니다. 공유 부모, 중첩 회전, 블렌드 변형의 이동은 겉모습을 유지합니다. 비선형 조합이 같은 깊은 메시 위치를 나타낼 수 없으면 분명히 거부합니다. 검증은 자식 키 값, 블렌드 변형 키 값, 제한점과 그 중간점을 덮습니다. 상한 밖에서는 조용히 근사하지 않습니다.
