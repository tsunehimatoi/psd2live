# PSD2Live 런타임

`runtime/`은 독립된 Rust 라이브러리(MIT)이며, PSD2Live가 컴파일한 `.p2lrt` 모델을 재생합니다. 파라미터가 구동하는 변형, 물리, 모션 클립을 다루고, 다른 언어와 엔진이 호출할 C ABI를 제공합니다. 편집기는 `:format-eval`(JNA)로 같은 라이브러리를 호출합니다.

## 구성

| 부분 | 위치 | 라이선스 |
| --- | --- | --- |
| `.p2lrt` 쓰기와 내보내기 대상 `p2lrt` | `:targets:runtime`(`P2lrt`, `P2lrtTarget`) | MIT |
| 읽기, 평가, 물리, 모션 클립, C ABI | `runtime/`(crate `p2l-runtime`, cdylib + staticlib) | MIT |
| C 헤더 | `runtime/include/p2l_runtime.h` | MIT |
| JVM 바인딩 | `:format-eval`(`P2lRuntime`, `NativeGeometryEvaluator`) | MIT |
| 웹 플레이어 | `:targets:web`(내보내기 대상 `web`: 페이지, `p2l.js`, 런타임의 WebAssembly 빌드) | MIT |
| Godot 4 노드 `P2LCharacter` | `runtime/godot/`(GDExtension, godot-rust, Godot 4.3+), 데모 프로젝트 `runtime/godot/demo/` | MIT |

빌드: `runtime/`에서 `cargo build --release`를 실행하면 라이브러리는 `runtime/target/release/`에 있습니다(Windows는 `p2l_runtime.dll`). Gradle의 `buildRuntime`은 cargo가 있으면 자동으로 빌드합니다. `./gradlew run`이 그것을 쓰고, 패키징할 때 앱 자원으로 배포합니다. cargo가 없으면 건너뛰고, 앱은 편집기 평가기로 되돌아갑니다. `P2lRuntime.locate()`는 시스템 속성 `psd2live.runtime.library`, 환경 변수 `PSD2LIVE_RUNTIME`(파일 또는 디렉터리), 시스템 속성 `psd2live.runtime.dir`, 패키징된 앱의 자원 디렉터리, `java.library.path`를 차례로 찾습니다.

편집기의 내보내기 베이크(Spine, DragonBones, glTF)는 런타임 라이브러리를 쓸 수 있으면 `NativeGeometryEvaluator`로 평가하고, 아니면 엔진 평가기를 씁니다. 둘은 자세마다 일치합니다. 편집기 소프트웨어 미리보기(`RigCanvasSupport.evaluate`)도 `NativePreview`를 거쳐 런타임을 씁니다. 어떤 미리보기 모델을 처음 만나면 엔진이 응답하고 백그라운드에서 컴파일하며, 이후 프레임은 런타임을 탑니다. 드래그 중인 임시 모델은 컴파일을 기다리지 않습니다. 실패하거나 `-Dpsd2live.preview.runtime=false`이면 엔진을 유지합니다. 스켈레톤이 있는 tml에서 한 번 평가는 약 0.5밀리초이며, 엔진과 비슷합니다(JNA 호출과 결과 변환이 네이티브 속도를 상쇄합니다).

미리보기 캔버스는 런타임을 미리보기 백엔드로 고를 수 있습니다(「PSD2Live 런타임(p2lrt)」, CANVAS_RENDERER.md를 참조). 백그라운드가 미리보기 모델을 `.p2lrt`로 컴파일하고(시뮬레이션 포함), 런타임은 작업 공간 시계가 주는 완전한 자세를 평가하며, `P2lrtGlRenderer`는 웹 플레이어의 규칙대로 창 자신의 Skia OpenGL 컨텍스트에서 그립니다. 확장(고급) 모드를 켜면 각 뷰의 모델이 스키닝과 정밀 링크를 켭니다. 실시간 시뮬레이션과 충돌은 미리보기의 물리 스위치가 제어합니다(켜면 `p2l_update_stages(dt, P2L_STAGE_SIM)`로 프레임 시간만큼 실시간 시뮬레이션만 진행하고, 일시 중지해도 멈추지 않습니다. 끄면 베이크된 스윙을 표시합니다). 작업 공간이 이미 합성한 물리 결과는 그대로 유지하고, 런타임은 물리를 다시 계산하지 않으며, 절차적 동작은 꺼진 채로 둡니다. 백그라운드 컴파일은 스키닝 가중치를 함께 준비하고 캐시합니다. 뷰는 공유 모델로 각자의 자세와 시뮬레이션 인스턴스를 만들며, 모드를 바꿔도 렌더 스레드에서 다시 맞추지 않습니다. Cubism SDK를 쓸 수 없으면 미리보기는 자동으로 이것으로 바뀝니다.

확장은 모델이 실제로 가진 데이터에만 작용합니다. 적용할 확장이 없거나 시뮬레이션 확장만 있는데 물리가 꺼져 있으면, 미리보기 상태가 이유를 설명합니다. 베이크하지 않은 시뮬레이션은 실시간 시뮬레이션 데이터를 제공하지 않습니다. 켜져 있고 베이크된 시뮬레이션이 구축이나 보정에 실패하면, 컴파일이 구체적인 시뮬레이션을 보고해 확장이 조용히 사라지지 않게 합니다.

## `.p2lrt` 형식

리틀 엔디안 바이너리이며, 컴파일된 IR의 압축된 표현입니다. 캔버스, 파라미터, 디포머(부모가 앞), 파츠, 메시, Glue, 그리기 트리, 텍스처 페이지, 물리 그룹, 모션 클립, 파라미터 역할(예: EyeBlink, LipSync)이 들어갑니다. 참조는 모두 인덱스입니다.

내보내기는 기본적으로 버전 2를 씁니다. 파일 헤더, 청크 디렉터리, 16바이트 정렬, CRC가 있는 청크, 문자열은 문자열 테이블에 모이고, 배열은 인코딩되어 4바이트로 정렬되며, 파라미터 패널(`PGUI`)과 생성기 정보(`META`)가 있습니다. 배치와 진화 규칙은 [P2LRT_V2.md](P2LRT_V2.md)를 참조합니다. 내보내기 옵션 `v1`은 버전 1을 씁니다(단일 순차 스트림. 필드별 배치는 `P2lrt.kt`의 문서 주석). 아직 갱신하지 않은 플레이어용입니다. `compress`는 deflate로 작아질 수 있는 청크를 압축합니다(텍스처 페이지 제외). `strip_names`는 표시 이름을 빼고 id는 남깁니다.

읽기(`runtime/src/rig.rs`, `container.rs`)는 두 버전을 모두 읽어 같은 `Rig`로 해석하며, 평가 코드는 하나입니다. 참조, 메시 인덱스, 키폼 크기, 청크 위치와 정렬, 청크 안 기록을 정확히 다 읽었는지를 검증하고, 모르는 선택 청크는 건너뛰며, 모르는 필수 청크를 만나면 그 태그를 보고합니다. 청크는 deflate 또는 zstd로 압축할 수 있습니다(내보내기 설정 `compress`, `zstd`를 더하면 zstd).

## 평가 규칙

평가는 각 메시의 캔버스 픽셀 좌표(y는 아래) 정점, 투명도, 곱하기/스크린 색, 그리기 순서를 출력합니다. 규칙은 모두 편집기 평가기를 블랙박스로 조사해 얻었으며(`WarpProbeTool`, `RuntimeConformanceTool`), 그 구현을 참조하지 않았습니다.

- **파라미터**: 범위로 클램프합니다. 순환 파라미터는 범위 밖의 값만 되감고, 양쪽 끝은 원래 값을 유지합니다.
- **키폼 메시**: 다선형 보간입니다. 값이 어떤 키 점과 0.001보다 작게 차이나면 그 키 점을 취합니다. 희소 메시에서 빠진 칸은 영 형태로 칩니다(메시 오프셋은 영, 디포머의 절대 형태는 원점). 가중치는 다시 나누지 않습니다. 플래그 채널(뒤집기)은 현재 값 이하인 키 점을 취합니다.
- **Warp**: 단위 정사각형 안에서 칸별 쌍선형, 또는 (1,0)–(0,1) 대각선으로 나눈 두 삼각형 보간입니다. 밖은 [-2, 3]² 안에서 한 층 더 거친 가상 칸으로 연장하고, 추가 격자점은 칸 네 모서리의 평균 아핀 프레임을 취해 삼각형으로 보간합니다. 더 멀면 아핀 프레임만 씁니다.
- **회전 디포머**: 각도는 키폼 각도에 기준각을 더한 값입니다. 부모가 회전이면 원점은 부모 변환을 거치고, 각도와 스케일은 부모와 겹칩니다. 부모가 수직으로 뒤집히거나 부모 스케일이 음수이면 자식 프레임이 추가로 180° 회전합니다. 부모의 수평 뒤집기는 자식 프레임 방향에 영향을 주지 않습니다. 자신의 뒤집기는 자식 좌표에만 작용합니다. 부모가 Warp이면 프레임은 강체를 유지합니다. 원점은 칸 매핑을 거치고, 각도는 원점 위 0.1에서 v 방향으로 칸이 향하는 쪽을 따라 회전하며, 스케일은 칸 위쪽의 가장 가까운 회전 스케일을 상속합니다.
- **블렌드 셰이프**: 각 리그는 파라미터에 따라 이웃 키 점 사이를 선형으로 섞습니다(키 점으로 반올림하지 않음). 중립 키 점과 형태가 없는 키 점은 기여하지 않습니다. 가중치에 각 제한 파라미터의 구간 선형 계수를 곱합니다. 디포머와 채널의 형태는 목표 값이며, 더하는 것은 「목표 − 기본 자세에서의 값」입니다. 메시 형태는 목표 오프셋이며, 더하는 것은 「목표 오프셋 − 기본 자세에서의 오프셋」입니다.
- **투명도**: 각 단계(디포머, 메시)는 먼저 [0, 1]로 클램프한 뒤 부모와 곱합니다. 파츠 투명도는 메시 투명도에 넣지 않습니다.
- **Glue**: 모든 변형 뒤에, 정점 쌍마다 자신의 가중치에 강도를 곱해 상대 쪽으로 이동합니다.
- **그리기 순서**: 각 그리기 그룹은 자식의 그리기 순서로 정렬합니다. 하위 그룹은 그 파츠가 채널과 블렌드 셰이프로 구한 그리기 순서를 키로 씁니다(파츠가 없으면 정적 값). 키에 천분의 일을 더한 뒤 정수로 취하고, 같으면 트리 안의 순서를 유지합니다. 숨긴 메시는 그리지 않습니다. 규칙은 엔진 렌더 순서 인터페이스의 문서 설명에서 취했으며, 네이티브 렌더와 프레임마다 대조하지는 않았습니다.

## 고급 모드

파일의 확장 청크는 Cubism과 등가인 평가 밖의 기능을 제공하며, 모두 기본적으로 꺼져 있습니다. `p2l_set_advanced`로 켜고, 끄면 평가가 코어 평가와 비트 단위로 일치합니다. 배치와 의미는 [P2LRT_V2.md](P2LRT_V2.md)를 참조합니다.

- **런타임 스키닝(`P2L_SKIN`)**: 무릎, 팔꿈치 같은 관절에서 굽는 메시는 베이크할 때 키로 샘플하고, 키 사이는 현을 따라 보간합니다. 런타임은 스켈레톤 프레임을 정점마다 두 뼈 선형 혼합하고, 「현재 혼합 − 키 사이 혼합의 보간」을 더합니다. 이것은 각 키에서 영이고, 키 사이에서 현을 호로 바꿉니다. 가중치는 켤 때 베이크된 키폼에 맞춥니다. 스켈레톤이 잘라 내거나 접은 뼈는 가상 뼈로 파일에 함께 제공되며, 호스트는 `p2l_bone_*`으로 뼈 변환을 읽어 물건을 매달 수 있습니다.
- **정밀 링크(`P2L_EXACT_LINKS`)**: 같은 원 위에 키로 잡힌 피벗은 호를 따라 보간합니다.
- **실시간 시뮬레이션(`P2L_SIM`)과 충돌(`P2L_COLLISION`)**: 베이크된 천과 머리카락이 편집기의 XPBD 솔버로 실시간 실행되며, 베이크된 모드 파라미터와 진자를 대체합니다. 충돌체는 메시 정점을 따른 원 또는 캡슐입니다.

검증: `advanced_tests`(알려진 해석해가 있는 팔, 링크, 가상 뼈, 매달린 메시). `p2lrt-conformance --advanced`는 각 샘플이 스키닝 키에서 베이크와 일치할 것을 요구합니다(모두 0). `--sim`은 `RuntimeConformanceTool.simulation`의 무작위 천 궤적으로 솔버를 비교하며, 편집기와 비트 단위로 일치합니다(충돌 포함). `--sim-rig`는 tml 뒷머리의 베이크 시뮬레이션을 끝까지 비교합니다. 앞 0.5초 오차는 0.21픽셀, 전체 평균은 0.22픽셀입니다. 차이는 양쪽이 목표를 평가할 때 약 1e-4픽셀의 부동소수점 차에서 오며, 천이 그것을 키웁니다.

## 물리

Cubism 런타임이 physics3.json을 읽는 방식으로 구현했으며, 그 특유한 동작도 포함합니다. 입력은 파라미터 범위의 중간점으로 정규화합니다. 고정 스텝(`Fps`)이면 프레임 사이에 입력을 보간하고, 출력은 마지막 두 스텝 사이를 보간합니다. 스텝을 제한하지 않으면 출력이 한 프레임 늦습니다. 이동 회전 때는 이미 회전한 x를 재사용합니다. 각도 출력만 스케일이 있고, 이동 출력의 스케일은 영입니다. 5초를 넘는 누적 시간은 영으로 지웁니다. 편집기 `PhysicsEngine`과 무작위 진자 그룹, 샘플 모델에서 프레임마다 비교하면 오차는 2e-5보다 작습니다.

Cubism 런타임의 세 가지가 더 있습니다. 세로(Y) 입출력(`PHYS` 버전 2, [P2LRT_V2.md](P2LRT_V2.md)를 참조. 편집기와 Cubism Editor는 세로를 만들지 않으며, physics3 내보내기는 쓸 수 있음), 바람(`p2l_physics_wind`, 각 입자가 받는 힘에 더함. physics3의 Wind와 같음), 안정화(`p2l_physics_stabilize`, 현재 자세에 따라 각 진자를 힘 방향의 정지 위치에 바로 놓고 출력을 씀. Cubism의 Stabilization과 같음). 바람이 영이면 결과는 이전과 비트 단위로 일치합니다.

## 모션 클립

곡선 구간은 편집기와 같습니다(선형, Bezier(시간 제어점은 구간 안으로 제한), 계단, 역계단). 순환 클립은 길이로 되감고, 한 번 재생 클립은 끝에서 멈춥니다. `Player`는 한 번에 클립 하나를 재생하고, 전환할 때 클립의 페이드 인·아웃 시간(기본 1초, 코사인 이징)으로 교차 전환합니다. 클립 가중치는 페이드 인 계수와 페이드 아웃 계수의 곱입니다(Cubism과 같음). 교체되는 클립은 각각 완전히 페이드 아웃하며, 빠르게 연속 전환해도 아직 페이드 아웃 중인 클립을 잃지 않습니다.

## 절차적 동작

호스트가 켤 수 있습니다. 깜빡임(`EyeBlink` 역할, 2–6초마다 한 번, 닫힘 0.1초, 유지 0.05초, 뜸 0.15초, 현재 값에 곱함. `p2l_blink_settings`로 간격과 각 단계 길이를 바꿀 수 있음), 호흡(`Breath`는 범위 안의 사인으로 설정, `AngleX/Y/Z`, `BodyAngleX`에 작은 스윙을 더함), 시선(`look_at(x, y)`는 임계 감쇠로 따라가며 `AngleX/Y`, `BodyAngleX`, `EyeBallX/Y`를 구동하고, `AngleZ`는 x·y에 따라 기울어짐), 립싱크(`lip_sync(level)`, `LipSync` 파라미터는 더 큰 값을 취함. `p2l_lip_sync_samples`는 오디오 샘플 한 구간의 제곱평균제곱근에 게인을 곱해 벌림 양으로 씀). `p2l_behavior_strength`는 호흡 스윙 폭, 시선 회전 폭, 따라가는 속도를 조정합니다. 역할은 편집기가 컴파일할 때 존재하는 표준 파라미터에 따라 씁니다. moc3의 model3.json은 여전히 EyeBlink와 LipSync 두 그룹만 씁니다. 갱신 순서: 모션 클립 → 동작 → 물리 → 변형.

## C ABI

핸들 하나는 불러온 모델 하나에 대응하며, 파라미터, 모션 플레이어, 물리 상태를 가집니다. 전형적인 흐름: `p2l_rig_load` → 파라미터 설정(`p2l_parameter_values` / `p2l_set_parameter`) → `p2l_update(dt)`(모션, 물리, 변형) 또는 `p2l_evaluate` → `p2l_mesh_vertices`, `p2l_mesh_opacity`, `p2l_mesh_colors`를 읽고, `p2l_render_order`대로 뒤에서 앞으로 그리며, 텍스처는 `p2l_texture_png`가 제공합니다(`p2l_texture_info`가 텍스처 페이지 유형을 줍니다. 내장 PNG, KTX2, 또는 모델 옆의 파일). `p2l_rig_load_ex`는 청크 CRC 검증을 요구할 수 있고, `p2l_format_support`는 지원 버전과 청크를 나열합니다. 표정(`p2l_expression`)은 모션 클립 뒤, 절차적 동작 앞에 겹칩니다. `p2l_hit_test`는 캔버스 점 아래의 클릭 영역을 돌려줍니다. `p2l_mesh_user_data`는 메시의 사용자 데이터를 읽습니다. `p2l_pose_show`는 파츠 상호 배타 그룹을 전환합니다(내보내기 설정 `pose_groups`). 교체된 파츠는 `p2l_update`에 따라 페이드 아웃합니다. `p2l_parameter_values`는 호스트가 설정한 자세이며, `p2l_update`마다 그것에서 다시 시작해 모션, 표정, 동작, 물리를 겹칩니다. 겹친 결과는 다시 쓰지 않으므로, 깜빡임, 호흡, 더하기 표정이 프레임마다 누적되지 않습니다. 이 프레임이 실제로 쓴 값은 `p2l_parameter_current`로 읽습니다. 모든 함수는 빈 핸들을 받습니다. 돌려주는 포인터는 핸들이 해제되기 전까지 유효합니다(자세 데이터는 다음 평가 전까지).

ABI 1.1에서 추가된 부분(모두 새 함수이며, 1.0 함수의 동작은 변하지 않습니다. 범위를 벗어난 첨자의 반환값만 구분할 수 있는 값으로 바뀜):

- **모델과 인스턴스**: `p2l_model_load`는 파일을 한 번 읽어 읽기 전용이고 스레드를 넘어 공유할 수 있는 모델을 얻습니다. `p2l_rig_create`는 그 위에 파라미터, 모션, 물리 상태를 각자 가진 핸들을 만듭니다. `p2l_model_free` 뒤에도 이미 만든 핸들은 모델을 유지합니다. `p2l_rig_load`는 둘을 합친 것입니다. 핸들 하나를 두 스레드가 동시에 쓸 수 없습니다(읽기도 안 됩니다. `p2l_bone_transform`이 핸들을 갱신합니다).
- **층별 갱신과 호스트 층**: `p2l_update_stages(dt, stages)`는 고른 층만 실행합니다(모션, 표정, 동작, 파츠 자세, 물리, 실시간 시뮬레이션. 순서는 변하지 않음). 고르지 않은 층은 진행하지도 겹치지도 않습니다. `p2l_set_parameter_override(index, value, weight)`는 호스트 층입니다. 모션과 표정 뒤, 동작과 물리 앞에 파라미터를 가중치만큼 주어진 값으로 당깁니다(페이스 캡처 등). 물리는 여전히 그것을 따라 흔들립니다. `p2l_parameter_values`는 여전히 가장 아래층입니다.
- **파츠와 격리 그룹**: `p2l_part_*`는 파츠 id, 이름, 부모 파츠, 플래그, 그룹 방식(통과, 그룹 전체 정렬, 격리)을 줍니다. `p2l_render_commands`는 격리 그룹 경계를 유지한 그리기 순서입니다(메시 첨자. `-2 - 部件`는 그룹을 열고, `-1`은 그룹을 닫음). 그룹의 혼합 모드, 투명도 합성 모드, 마스크(마스크 파츠는 그 메시로 펼침)는 `p2l_part_group` / `p2l_part_masks`가 주고, 평가 뒤의 그룹 투명도와 곱하기/스크린 색은 `p2l_part_composite`가 줍니다. 그리기 트리에서 그 그룹의 채널이 그룹 합성의 정적 값을 덮으며, 편집기와 일치합니다. `p2l_set_part_opacity`는 호스트의 파츠 투명도를 설정하고, 파츠 자세와 같이 그 아래의 모든 메시에 곱합니다. `p2l_mesh_part`는 메시가 속한 파츠를 주고, `p2l_mesh_alpha_blend`는 메시의 투명도 합성 모드를 줍니다.
- **파일 정보**: 파라미터 이름과 플래그(순환, 블렌드 셰이프 파라미터), 스냅 값과 파라미터 패널(`PGUI`: 2차원 스틱, 그룹 트리, 태그), 캔버스 원점과 단위당 픽셀, 모션 클립의 이름, 그룹, 길이, 프레임률, 순환과 페이드 인·아웃, 재생 중인 클립, 현재 시간과 이동(`p2l_clip_seek`은 클립 시간만 옮기고 페이드 인은 그대로), 표정, 클릭 영역과 메시의 표시 이름, 생성기 정보(`META`).
- **기타**: `p2l_behavior_seed`는 깜빡임의 난수 시드를 다시 설정합니다. 프로세스에서 첫 번째 이후의 핸들은 자동으로 각자의 시드를 취합니다. 범위를 벗어난 첨자의 값 함수는 NaN(수치) 또는 -1(첨자, 모드)을 돌려주고, 빈 핸들은 여전히 0을 돌려줍니다. `p2l_alloc`은 길이대로 정확히 할당하고 영으로 지웁니다. PNG가 아닌 텍스처 페이지의 `p2l_texture_png`는 길이를 0으로 씁니다. `p2l_parameter_index`는 `p2l_parameter_id`가 주는 문자열로 찾습니다.

ABI 1.2에서 추가된 부분(마찬가지로 새 함수만):

- **모션 층**: 최대 `P2L_MAX_LAYERS`(16)층. 각 층은 한 번에 클립 하나를 재생하고, 층 순서대로 아래층 위에 겹칩니다. `p2l_set_layer_weight`가 그 층이 아래층을 덮는 가중치를 설정합니다. `p2l_play_layer(layer, clip, priority)`는 우선순위가 그 층에서 재생 중인 클립의 우선순위 이상일 때만 시작합니다(클립이 끝나거나 멈춘 뒤는 0). Cubism 모션 관리자의 우선순위에 대응합니다. `p2l_play`와 `p2l_clip_*`는 0층을 조작합니다.
- **모션 이벤트와 비파라미터 곡선**: `CEXT`에서 옵니다([P2LRT_V2.md](P2LRT_V2.md)를 참조). 갱신할 때마다 지나간 이벤트는 `p2l_event_count` / `p2l_event`가 줍니다(텍스트, 층, 클립, 시간). 클립이 설정한 파츠 투명도와 전체 투명도는 메시에 곱합니다. `p2l_evaluate`는 호스트 자세만 구하므로 그것들을 포함하지 않습니다. 깜빡임과 립싱크 효과는 해당 역할 파라미터에 작용합니다. 자신의 페이드 인·아웃이 있는 곡선은 Cubism 규칙으로 가중치를 취합니다.
- **여러 표정**: `p2l_expression_add` / `p2l_expression_remove`는 여러 표정이 동시에 효력을 갖게 합니다(각자 페이드 인·아웃, 시작한 순서대로 겹침). `p2l_expressions_playing`이 효력 중인 것을 나열합니다. `p2l_expression`은 여전히 하나만 유지합니다.
- **전체 투명도와 색 덮어쓰기**: `p2l_set_opacity`는 모든 메시에 곱합니다(클립이 설정한 전체 투명도와 곱함. `p2l_opacity`가 곱을 읽음). `p2l_set_mesh_colors` / `p2l_set_part_colors`는 호스트가 준 곱하기/스크린 색으로 평가 결과를 바꿉니다. 메시 자신의 설정이 그것이 속한 파츠 사슬에서 가장 가까운 설정보다 우선합니다.
- **물리와 동작**: `p2l_physics_wind`, `p2l_physics_stabilize`, `p2l_blink_settings`, `p2l_behavior_strength`, `p2l_lip_sync_samples`. 위의 「물리」「절차적 동작」을 참조합니다.

ABI 1.3은 `p2l_render`와 `p2l_render_texture`를 추가합니다(아래 「소프트웨어 렌더」를 참조). ABI 1.4는 다음을 추가합니다.

- **변화 플래그**: `p2l_mesh_changes`는 메시를 그리는지(그리기 순서에 있고 불투명도가 0보다 큼), 그리고 이전 평가와 비교해 가시성, 불투명도, 그리기 순서 값, 그리기 순서 안의 위치, 정점, 곱하기/스크린 색이 바뀌었는지를 줍니다. Cubism의 dynamic flags에 대응하며, 호스트는 바뀐 부분만 올리면 됩니다. 첫 평가 뒤에는 모두 켜집니다. 자세를 바꾸는 모든 입구(`p2l_update`, `p2l_update_stages`, `p2l_evaluate`, `p2l_set_advanced`, `p2l_physics_stabilize`)가 끝날 때 갱신합니다.
- **로그**: `p2l_set_log`는 불러오기 실패, 핸들 무효, 렌더러가 디코드할 수 없는 텍스처 페이지를 받습니다.
- **호스트 할당자**: `p2l_set_allocator`는 이후 런타임의 모든 메모리가 호스트의 할당과 해제 함수에서 오게 합니다(크기와 정렬은 그대로 전달). 런타임의 다른 부분을 쓰기 전, 단일 스레드에서 호출해야 합니다. 런타임이 이미 시스템에 메모리를 요청한 적이 있으면 false를 돌려주고 바꾸지 않습니다. 기본적으로 켜진 `host-allocator` 특성이 제공합니다(런타임을 Rust 라이브러리로 Godot 노드 등이 쓸 때는 끔). C 예시 실측: tml 샘플을 렌더한 7570회의 할당이 모두 호스트 할당자를 거쳤습니다.

쓰기 쪽: IR의 `Clip`에 `events`, `targetCurves`를 더하고, `Curve`에 `fadeIn` / `fadeOut`을 더하며, `PhysicsSource`에 `Y`를 더합니다. p2lrt 내보내기는 `CEXT`를 쓰고 필요할 때 `PHYS` 버전 2를 씁니다. moc3 내보내기의 motion3는 `UserData`, `PartOpacity`, `Model`(`Opacity`, `EyeBlink`, `LipSync`) 곡선과 곡선 페이드 인·아웃을 쓰고, physics3는 `Y`를 씁니다. cmo3에는 세로 물리가 없어 세로 입출력을 생략합니다. 편집기의 모션 편집은 아직 이벤트와 비파라미터 곡선의 편집 입구를 제공하지 않으며, 이 데이터는 IR에서 옵니다.

그리기 규칙은 헤더 파일 앞에 적혀 있으며, `SoftwareRasterizer`를 기준으로 합니다. 텍스처는 직통 alpha이고, 규칙은 사전 곱한 색 위에서 계산합니다. 프래그먼트 색은 먼저 곱하기 색을 곱하고, `c + s·a − c·s`로 스크린 색을 겹친 뒤, 마지막으로 불투명도와 마스크 커버를 곱합니다(마스크 메시는 그 점 텍스처 alpha의 최댓값, 반전은 1 − 커버. 실시간 플레이어는 alpha ≥ 0.5인 스텐실로 근사할 수 있음). 컬링을 켜면 캔버스 좌표(y는 아래)에서 시계 방향인 면만 그립니다. Cubism의 일반, 가산, 곱하기는 그 사전 곱 공식을 따릅니다(가산과 곱하기는 대상 alpha를 유지). 확장 모드는 W3C 합성 공식을 따릅니다. 혼합 모드와 투명도 합성 모드에는 `P2L_BLEND_*`, `P2L_ALPHA_*` 상수가 있습니다.

호출이 런타임 내부에서 panic하면(결함, 또는 읽기가 통과시켰지만 평가할 수 없는 모델) 호스트로 펼쳐지지 않습니다. 그 호출은 빈 핸들처럼 반환하고, 핸들은 무효가 되며, `p2l_rig_failure`가 이유를 줍니다. 그 뒤 그것은 빈 핸들과 같고, `p2l_rig_free`까지 그렇습니다. 불러오는 중(첫 평가 포함) panic하면 `p2l_rig_load`는 빈 값을 돌려주고 이유를 씁니다. WebAssembly 빌드의 panic은 여전히 인스턴스를 중단합니다(그 대상은 스택 펼치기를 지원하지 않음).

ABI 버전: 헤더의 `P2L_ABI_VERSION_MAJOR` / `P2L_ABI_VERSION_MINOR`와 라이브러리의 `p2l_abi_version()`(`major << 16 | minor`). 함수를 추가하면 부 버전을 하나 올리고, 함수를 수정하거나 삭제하면 주 버전을 하나 올립니다. 호스트는 `P2L_ABI_COMPATIBLE(p2l_abi_version())`로 검사합니다. `p2l_abi_version`이 없는 라이브러리는 1.0보다 이전입니다. `p2l_version`은 라이브러리의 빌드 버전일 뿐입니다. JVM 바인딩은 라이브러리를 불러올 때 주 버전이 같고 부 버전이 바인딩이 요구하는 것 이상일 것을 요구하며, 아니면 런타임이 없는 것으로 칩니다. 평가나 갱신 뒤 핸들이 무효가 되면 예외를 던집니다(소프트웨어 미리보기는 그래서 편집기 평가기로 되돌아가고, 런타임 미리보기 백엔드와 내보내기는 오류를 보고합니다). `cargo test`는 헤더가 선언한 함수와 라이브러리가 내보낸 함수가 일대일로 대응하고 버전 번호가 일치하는지 검증합니다.

## 검증

- `cargo test`: 평가 규칙마다 작은 모델 단위 테스트(수치는 조사 결과에서 옴), 그리고 Warp, 모션 클립 테스트. `format_tests`는 청크를 이어 버전 2 파일을 만들며, 압축, CRC, 청크 디렉터리, 각종 거부 상황, 모든 배열 인코딩, 텍스처 페이지 유형, 파라미터 패널을 덮습니다.
- `RuntimeConformanceTool`(`PSD2LIVE_TOOLS=1`): 무작위 모델 80개(Warp, 회전, 중첩, 희소 메시, 블렌드 셰이프, Glue, 채널, 파츠, 혼합), 샘플과 로컬 프로젝트의 참조 자세, 물리 궤적을 생성합니다. `cargo run --release --bin p2lrt-conformance -- ../build/tools/runtime-conformance`(물리는 `runtime-physics`)가 사례마다 비교합니다. 각 사례는 버전 2, 버전 1, deflate와 zstd로 압축한 버전 2를 함께 쓰며, 넷이 같은 `Rig`로 읽히고 비트 단위로 같은 자세를 얻어야 합니다. 정점 오차 상한은 0.02픽셀입니다. 넘는 자세는 자신의 조건수로 판정합니다. 아무 파라미터나 그 범위의 백만분의 일만큼 옮길 때 정점이 가장 많이 움직이는 거리(민감도)의 두 배를 오차가 넘을 수 없습니다. 메시 내부 보간은 배정밀도를 씁니다. 현재 모두 일치하며, 0.02를 넘는 유일한 것은 blend-6의 자세 하나입니다(0.10픽셀, 민감도도 0.10, 그 메시의 이때 불투명도는 3e-5).

## 아직 끝나지 않은 것

- GPU 렌더는 호스트가 합니다. 런타임은 기하와 속성을 제공하고, `p2l_render`(CPU 소프트웨어 렌더, 다음 절을 참조)로 마스크와 모든 합성 모드를 그립니다. GPU 호스트는 같은 규칙으로 스스로 그립니다(Web 대상의 그리기는 [내보내기 대상](EXPORT_TARGETS.md)을 참조).

## 소프트웨어 렌더

`p2l_render`(ABI 1.3)는 가장 최근 평가를 호스트가 준 RGBA8 이미지에 그립니다. 규칙은 참조 래스터라이저 `SoftwareRasterizer`와 같습니다. 쌍선형 사전 곱 샘플링, 픽셀 중심과 왼쪽 위 규칙, 텍스처 alpha에 따른 마스크(반전 포함), 격리 그룹 레이어, 모든 색과 투명도 합성 모드, 컬링입니다. 변환은 캔버스에서 이미지로의 아핀입니다(빈 포인터이면 캔버스를 등비로 이미지 왼쪽 위에 넣음). 출력은 사전 곱 또는 직통 alpha이며, 이미 있는 내용 위에 그릴 수 있습니다. 내장 PNG 텍스처 페이지는 런타임이 가진 디코더가 풉니다(비인터레이스, 모든 색 유형). KTX2와 외부 파일 페이지는 호스트가 `p2l_render_texture`로 픽셀을 제공합니다. 자체 렌더러가 없는 호스트(C/C++, 엔진 플러그인, 썸네일과 검증)가 쓰며, 픽셀마다 CPU에서 실행됩니다. 검증: `SoftwareRenderParityTest`가 합성 조합 90종, 격리 그룹(채널이 구동하는 불투명도와 색, 메시와 파츠 마스크, 반전, 중첩), 마스크, 곱하기/스크린 색, 컬링을 덮는 모델에서, 세 가지 자세와 확대·축소로 참조 래스터라이저와 픽셀마다 비교합니다. 최대 채널 차는 ≤ 1/255입니다. conjoint의 겹침 가중치를 일부러 잘못 바꾸면 그 테스트가 77/255의 차이를 보고합니다.

## 다른 언어와 플랫폼

[`runtime/bindings/README.md`](../../../runtime/bindings/README.md)를 참조합니다.

- **C/C++**: `runtime/examples/c/render_example.c`가 공유 모델로 불러오고, 1초를 재생한 뒤 `p2l_render`로 BMP를 씁니다. `build_example.bat`는 MSVC로 C와 C++를 각각 한 번씩 컴파일합니다(`/W4 /WX`, 헤더에 경고 없음). 둘의 출력은 바이트 단위로 같습니다. Unreal은 서드파티 모듈 방식으로 같은 헤더와 라이브러리를 씁니다.
- **.NET / Unity**: `bindings/csharp/P2lNative.cs`는 `generate.py`가 헤더에서 생성한 모든 P/Invoke 선언입니다(`cargo test`가 내보낸 함수와 일치하는지 검증). `P2l.cs`는 문자열 보조와 자동 해제의 `P2lRig`를 제공합니다. `Smoke.cs`는 C# 6으로 컴파일한 뒤 `Marshal.Prelink`로 입구 129개를 모두 해석하고, tml 샘플을 불러와 재생하고 렌더합니다. `bindings/unity/P2LCharacter.cs`는 모델을 프레임마다 소프트웨어 렌더로 `Texture2D`에 그립니다. 사용한 Unity API의 스텁 코드로 타입 검사만 했으며, Unity에서 실행하지는 않았습니다.
- **Android**: `runtime/build_android.sh`가 NDK의 clang으로 arm64-v8a, armeabi-v7a, x86_64용 `libp2l_runtime.so`를 빌드합니다. 셋 모두 함수 129개를 전부 내보냅니다. iOS는 Mac에서 빌드해야 하며, 여기서는 검증하지 않았습니다.

## 웹 플레이어

내보내기 대상 `web`은 바로 배포할 수 있는 폴더를 씁니다. `index.html`, `p2l.js`(ES 모듈 `P2LPlayer`), `p2l_runtime.wasm`, 모델입니다. 플레이어는 WebGL로 그리며, 헤더의 합성 규칙대로 모든 색과 투명도 혼합 조합과 격리 그룹을 그립니다. 일반(over)과 Cubism의 가산, 곱하기는 혼합 함수를 쓰고, 나머지 조합은 메시 경계 상자 안의 아래층을 텍스처로 복사한 뒤 셰이더에서 합성합니다. 격리 그룹은 `p2l_render_commands`대로 레이어에 그리고, 닫힐 때 그룹의 모드, 불투명도, 곱하기/스크린 색, 마스크로 합성합니다. 마스크는 스텐실 버퍼를 거칩니다(텍스처 alpha 0.5로 자르며, 반전을 지원). 컬링을 켠 메시는 앞면만 그립니다. `WebPlayerCheckTool`(`PSD2LIVE_TOOLS=1`)은 조합 90종과 격리 그룹 16종을 덮는 모델과 픽셀 단위 참조 그림을 생성합니다. Edge(인터페이스 없음)에서 참조와 최대 1/255까지 차이납니다. 페이지는 모션과 표정 선택, 립싱크 슬라이더를 제공하고, 시선은 포인터를 따르며, 클릭하면 그 클릭 영역을 표시합니다. 파일에 고급 모드 데이터가 있으면 페이지가 스위치를 제공합니다. WebAssembly 빌드는 자원으로 저장소에 커밋되며, 런타임을 수정한 뒤 `./gradlew :targets:web:updateWasm`으로 새로 고칩니다(`rustup target add wasm32-unknown-unknown` 필요). 단위 테스트는 플레이어가 호출하는 각 함수를 그 빌드가 내보내는지 확인합니다. tml 샘플은 Edge(인터페이스 없음)에서 올바르게 표시됩니다.

## Godot

`runtime/godot/`는 `cargo build --release`로 빌드합니다. `P2LCharacter`의 속성과 메서드는 그 README를 참조합니다. 노드는 헤더의 그리기 규칙대로 그립니다. 각 메시는 자신의 캔버스 항목에서 `render_commands`로 정렬하고, 텍스처는 불러올 때 사전 곱하며, 셰이더가 곱하기/스크린 색, 불투명도, 마스크 커버를 적용한 뒤 색과 투명도 합성 모드로 합성합니다. 일반+over, Cubism 가산/곱하기(아무 투명도 모드)와 out은 하드웨어 혼합을 쓰고, 나머지는 아래 색을 읽어 셰이더에서 계산합니다. 격리 그룹은 내용을 대상 뷰포트와 같은 크기의 오프스크린 뷰포트(층)에 그리고, 그룹 위치에서 그룹의 혼합 모드, 투명도 모드, 불투명도, 곱하기/스크린 색, 마스크로 합성하며, 중첩할 수 있습니다. Forward+와 Mobile의 백 버퍼 복사는 alpha를 잃으므로, 층 안에서 아래를 읽는 항목은 각자 뷰포트를 하나 쓰고, 이전 층 내용을 먼저 복사한 뒤 읽습니다. 그룹 밖은 화면을 읽고, 아래는 불투명으로 처리합니다(투명 창에서는 근사). 마스크는 커버 뷰포트에 그립니다(뷰포트마다 마스크 세 그룹). 메시와 층은 자신의 픽셀에서 커버를 읽고, 반전 마스크는 1 − 커버를 취합니다. 같은 그룹 마스크가 겹친 곳의 alpha는 더합니다(참조는 최댓값을 취함). 컬링을 켠 메시는 앞면 삼각형만 제출합니다(캔버스 좌표에서 (b − a) × (c − a) < 0). 마스크는 컬링하지 않습니다. `RuntimeSamplesTool`의 특성 모델은 Godot에서 소프트웨어 래스터라이저 참조 그림과 일치합니다(차이 ≤ 2/255, 반전 마스크 포함). `GodotLayerSamplesTool`(`PSD2LIVE_TOOLS=1`)은 모든 색×투명도 합성 모드(불투명 배경 위와 격리 그룹 안), 그룹의 색, 불투명도, 혼합 모드, 메시/파츠 마스크, 반전 마스크, 중첩을 덮는 단색 모델과 기대값을 생성합니다. Godot 4.7은 Forward+, Mobile, Compatibility에서 각 샘플 점의 차이가 ≤ 1.2/255입니다. 검증: 데모 프로젝트의 `smoke_test.gd`가 인터페이스 없는 모드에서 모델을 불러와 1초를 진행합니다. `--shot`은 창에서 한 프레임을 렌더하며, tml과 ds 샘플이 올바르게 표시됩니다.
