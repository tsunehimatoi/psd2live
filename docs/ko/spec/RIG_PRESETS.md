# Rig 프리셋 구조: 부위, 기초 알고리즘과 모듈

[문서 목차](../README.md) · 모듈과 알고리즘 목록: 얼굴 · [디포머와 파라미터](DEFORMER_AND_PARAMETER_SPEC.md) · [문서 레이어](DOCUMENT_LAYER.md)

이 페이지는 자동 생성이 선택하고, 끄고, 조정할 수 있는 부분으로 어떻게 조직되는지 설명합니다.

- 각 부위에는 서로 배타적인 **기초 알고리즘**이 한 가지 또는 여러 가지 있고, 그 위에 겹칠 수 있는 **모듈**이 몇 개 있습니다.
- 프로젝트의 **레시피**는 부위마다 어떤 기초 알고리즘을 쓰는지, 어떤 모듈을 껐는지, 어떤 수치를 바꿨는지를 기록합니다.

각 알고리즘과 모듈의 설계(무엇을 읽고, 무엇을 내며, 키폼을 어떻게 계산하고, 보기 좋은 기준은 무엇인지)는 네 개의 목록에 있습니다. 이 페이지는 그것들을 어떻게 등록하고, 선택하고, 저장하고, 재생하고, 노출하는지만 규정합니다.

## 목표

자동으로 생성한 모델은 기본적으로, 손으로 정밀하게 조정한 모델이 시각적으로 가지는 장점을 갖춰야 합니다.

- 눈, 눈썹, 입은 완전한 표정 공간을 가지며, 열고 닫는 것만으로는 부족합니다.
- 깜빡임과 말하기는 주변의 연동과 잔진동을 끌어냅니다.
- 고개 돌리기에는 깊이가 있습니다.
- 머리카락과 의상에는 무게와 위상차가 있습니다.

이 능력은 하나씩 모듈로 만듭니다.

- **기본은 모두 켬**: 새 프로젝트는 적용되는 모듈을 모두 켭니다.
- **필요에 따라 끔**: 사용자는 파라미터 양에 따라 아무 모듈이나 끌 수 있고, 프리셋이나 파라미터 예산으로 한 번에 여러 개를 끌 수도 있습니다.
- **적은 노브**: 각 모듈은 의미 있는 노브만 조금 노출합니다. 노브 하나는 내부에서 하위 수치 묶음을 구동합니다. 이후에는 캔버스에서 특징점과 핸들을 드래그해 조정할 수 있습니다.

모듈이 만들어졌는지는 효과만 보고 판단합니다.

1. 검토 도구(`RigReviewTool`)로 포즈 보드와 모션 클립을 만듭니다.
2. 그 부위의 “보기 좋은 모습”과 “흔한 문제”를 항목별로 대조해 확인합니다.
3. 수치 검사는 참고로만 씁니다.

## 용어

| 용어 | 의미 | 코드 |
| --- | --- | --- |
| 부위(area) | 카드 하나가 담당하는 범위입니다. 머리와 얼굴, 눈, 눈썹, 입과 아랫얼굴, 머리카락, 몸, 의상과 장식, 표정, 모션입니다. 카드 하나가 좌우를 함께 담당합니다 | `RigArea` |
| 기초 알고리즘(base) | 부위 안에서 서로 배타적인 방식입니다. 예를 들어 눈꺼풀을 감을 때 기존 알고리즘을 쓸지, 템플릿 피팅을 쓸지입니다. ID는 `部位/名称`이고, 버전 번호와 조정할 수 있는 수치가 있습니다 | `RigBase` |
| 모듈(module) | 부위 안에서 겹칠 수 있는 능력 하나입니다. 예를 들어 웃는 눈, 시선에 따른 눈꺼풀, 깜빡임 잔진동이며, 각각 스위치가 있습니다. ID는 `部位.名称`입니다 | `RigModule` |
| 노브(knob) | 기초 알고리즘이나 모듈의 조정할 수 있는 수치 하나입니다. 단위, 범위, 기본값, 고급으로 접을지입니다 | `RecipeKnob` |
| 레시피(recipe) | 프로젝트가 부위마다 고른 기초 알고리즘, 끈 모듈, 바꾼 수치입니다. 설정 `rig`에 저장합니다 | `RigRecipe` |
| 파츠 역할(part role) | 레이어가 그 부위 안에서 무엇인지입니다. 하이라이트, 동공, 아래 속눈썹, 쌍꺼풀 선, 그림자, 볼터치, 옆머리, 아호게, 포니테일, 땋은 머리, 짐승 귀, 리본, 펜던트, 단단한 장식, 소매, 치마입니다 | `PartRole` |
| 모델 프리셋 | 시작 페이지의 빠른 조합(최소 / 기본 / 전체)과 모델 프리셋 패널의 각 그룹입니다 | `StartQuickPreset` |
| Rig 수치 | 기존 알고리즘이 파라미터가 가득 찼을 때의 진폭이며, 각 부위 기존 기초 알고리즘의 파라미터입니다. 패널에서는 각 부위 카드의 「수치」에 둡니다 | `RigTuning` |

## 레지스트리

`core/recipe/RigModules.kt`가 유일한 레지스트리입니다. 부위는 패널에 카드가 표시되는 순서로 등록합니다.

**기초 알고리즘**

- 각 부위의 첫 기초 알고리즘은 `部位/legacy`이며, 레지스트리를 도입하기 전의 생성 방식입니다.
- 더 새로운 기초 알고리즘은 그 뒤에 등록하고, 마지막이 새 프로젝트의 기본입니다.

**모듈**

각 모듈은 다음을 선언합니다.

| 필드 | 의미 |
| --- | --- |
| `tier` | 중요도입니다. `CORE`(부위가 완전해 보이려면 필요), `MAJOR`(뚜렷한 시각 품질), `MINOR`(더하면 좋은 요소)입니다. 프리셋과 예산이 이것을 기준으로 잘라 냅니다 |
| `requires` | 의존하는 모듈입니다. 의존 대상을 끄면, 그것에 의존하는 모듈도 함께 꺼집니다 |
| `applies` | 소재에 처리할 파츠가 있는지입니다. 부위, 좌우, 파츠 역할로 판단합니다. 적용되지 않는 모듈은 표시하지 않고, 비용에 넣지 않으며, 생성하지도 않습니다 |
| `parameters` | 이 소재에 새로 추가하는 파라미터입니다 |
| `estimate` | 꺼졌을 때의 비용 추정입니다 |
| `physicsGroups` | 생성하는 물리 그룹입니다 |
| `setting` | 설정에 원래 있던 대응 스위치입니다(아래 참조) |

**ID와 버전**

- ID는 프로젝트에 저장될 수 있게 된 뒤에는 이름을 바꾸지 않습니다.
- 알고리즘이 이미 있는 프로젝트의 생성 결과를 바꾸면 버전 번호를 올립니다. 레시피는 설정 수치를 기록할 때의 버전을 남깁니다.

**기존 스위치를 이어 받는 모듈**

레지스트리 이전에 있던 스위치 몇 개도 모듈로 등록합니다.

| 모듈 | 대응 설정 |
| --- | --- |
| `eye.see-through` | `seeThroughEyes` |
| `eye.jelly` | `physicsEyeJelly` |
| `brow.see-through` | `seeThroughBrows` |
| `mouth.outline` | `mouthOutlineEnabled` |

- 이들의 스위치가 원래 설정이며, 이전 프로젝트에서도 그대로 유효합니다.
- 이들에게는 노브가 없습니다.

## 비용

비용의 네 항목은 다음과 같습니다.

- 추가 파라미터(ID를 하나씩 나열)
- 추가 키폼: 그 모듈 파라미터를 키로 가진 메시에서 늘어난 칸 수
- 블렌드 셰이프의 형태 수
- 물리 그룹 수

비용의 출처는 다음과 같습니다.

- 모듈이 켜져 있으면, 생성된 Rig에서 실측합니다(`ModuleCost.measure`).
- 모듈이 꺼져 있으면, 모듈 자신의 추정을 쓰며, 패널에는 “≈”로 표시합니다.

## 레시피: 선택, 저장, 업그레이드

**신규와 기존 프로젝트**

- 새 프로젝트의 설정은 `rig` 키를 씁니다. 내용이 빈 객체이면 전부 기본입니다. 각 부위는 기본 기초 알고리즘을 쓰고, 적용되는 모듈은 모두 켭니다.
- 레시피를 도입하기 전에 저장한 프로젝트는 설정에 `rig` 키가 없으며, 구 레시피(`RigRecipe.Legacy`)로 읽습니다.
  - 각 부위는 `legacy` 기초 알고리즘을 씁니다.
  - 기존 스위치를 이어 받는 모듈을 제외하고, 어떤 모듈도 켜지 않습니다.

  따라서 이전 프로젝트는 예전과 같이 생성되며, 설정 텍스트와 리비전 정체도 바뀌지 않습니다.
- 업그레이드: `rig: {}`를 씁니다. 실행 취소할 수 있습니다.
- 구 레시피로 되돌리기: `rig: null`을 쓰면, 설정에서 이 키가 사라집니다.

**수정(설정 패치 `changes.rig`)**

패널과 MCP는 같은 경로를 탑니다.

| 내용 | 표기 |
| --- | --- |
| 부위의 기초 알고리즘 | `bases: {部位: {base, values}}`. `null`이면 기본으로 돌아갑니다 |
| 모듈 | `modules: {模块: {on, values}}`. `null`이면 “켬, 수치 기본”으로 돌아갑니다 |

- 같은 기초 알고리즘이나 모듈을 유지하면, 수치는 기존 값과 병합합니다.
- 기존 스위치를 이어 받는 모듈은 `on`을 대응 설정에 쓰며, `values`를 둘 수 없습니다.
- 다음은 모두 거부됩니다.
  - 알 수 없는 부위, 기초 알고리즘, 모듈, 수치
  - 범위를 벗어난 값
  - `bases`, `modules` 밖의 키

**저장 형식**

- 기본과 다른 항목만 씁니다. 모듈은 `on: false`와 바꾼 수치만 기록합니다.
- 읽을 때 모르는 부위, 기초 알고리즘, 모듈, 수치는 건너뛰므로, 더 새 버전에서 저장한 프로젝트도 열 수 있습니다. 수치는 범위 안으로 집어넣습니다.

## 재구축과 재생

레시피는 생성 설정이며, 다음 방식으로 재구축에 참여합니다.

- 단계 캐시가 읽을 수 있는 설정에 들어갑니다(`RigBuilder.stageConfig`).
- `RigGenerationChange`는 이것을 생성 규칙 변화로 계산합니다. 레시피를 수정하면 새 기초 G′가 생성되고, 이전 기초 G, 저작 상태 M과 삼자 병합되며, 로그 끝에 `rig_checkpoint`를 씁니다. 사용자가 이전 기초 위에서 한 편집은 병합 규칙에 따라 남습니다.
- 모듈이 추가한 파라미터는 모듈이 생성될 때만 모델에 들어갑니다. 모듈을 끈 뒤 참조되지 않는 파라미터는 병합과 함께 제거됩니다.

따라서 모듈을 켜고 끄거나 노브를 조정하는 것은 실행 취소할 수 있는 히스토리 제출 한 번이며, 저장하고 다시 열어도 그대로 재구축됩니다.

“파라미터를 바꾸면 다시 계산하고, 사용자의 미세 조정은 남기는” 모듈은 로그 이후의 생성기로 구현하고, `DocumentGenerators`에 그것이 소유하는 키폼을 등록해야 합니다([문서 레이어](DOCUMENT_LAYER.md) 참조).

## 파츠 역할

파츠 역할은 의미 태그를 더 세분화합니다.

- 예를 들어 같은 홍채 레이어라도 하이라이트, 동공, 홍채 본체는 각자 움직입니다.
- 같은 속눈썹 레이어라도 아래 속눈썹, 쌍꺼풀 선, 눈꺼풀 그림자는 눈을 감을 때의 동작이 서로 다릅니다.

**태그 단어로서**

- 각 역할은 태그 단어입니다. `highlight`, `pupil`, `lower`, `lid`, `shadow`, `blush`, `side`, `ahoge`, `ponytail`, `braid`, `animal`, `ribbon`, `pendant`, `rigid`, `sleeve`, `skirt`, `upperlip`, `lowerlip`, `upperline`, `lowerline`입니다.
- 역할 단어는 부위, 좌우 단어와 함께 레이어 태그에 씁니다(`LayerTags`).
- 각 역할은 특정 부위만 세분화할 수 있으며, 적용되지 않는 부위에 두면 효과가 없습니다.

**자동 판단**(`PartRoles`)은 순서대로 진행합니다.

1. 레이어 이름과 소속 폴더의 중국어, 일본어, 영어, 한국어 키워드
2. 같은 부위 레이어들 사이에서의 위치와 블렌드 방식. 예를 들면 다음과 같습니다.
   - 홍채 안의 작은 스크린 레이어나 밝은 레이어는 하이라이트이고, 작은 어두운 레이어는 동공입니다.
   - 눈 중선 아래의 속눈썹 레이어는 아래 속눈썹이고, 위 속눈썹 위의 가는 선은 쌍꺼풀 선입니다.
   - 곱하기인 얼굴, 머리카락, 의상 레이어는 그림자입니다.
   - 얼굴 옆에서 얼굴 중부 아래까지 내려온 앞머리는 옆머리입니다.
   - 한 장(좌우를 나누지 않음)의 하의에서, 밑단이 허리보다 좁지 않고 밑단 가운데가 끊어지지 않으면(바지는 두 다리 사이에서 끊어짐) 치마입니다.

**사용자 수정**

- 사용자가 태그에 쓴 역할이 우선합니다.
- 추론된 역할을 태그에서 빼면 `PartRole.PLAIN`(역할 없음)으로 기록하며, 분석은 다시 추론하지 않습니다.
- MCP의 `layer_classify`는 `part` 필드로 설정합니다. 역할 단어, `none`, 또는 `auto`입니다.
- 역할은 레이어 분류 덮어쓰기에 있습니다. 역할이 없는 덮어쓰기는 이전 텍스트와 완전히 같습니다.

**누가 역할을 읽는가**

- 모듈만 역할을 읽습니다. 구 레시피는 읽지 않으므로, 역할은 이전 프로젝트의 생성 결과를 바꾸지 않습니다.

## 패널과 MCP

**패널**

모델 프리셋 패널의 「부위와 모듈」 그룹은 다음과 같습니다.

- 위쪽:
  - 프리셋(전체 / 표준 / 간소 / 사용자 지정)
  - 파라미터 예산: “중요도가 낮은 것부터 높은 것 순으로, 파라미터가 많은 것부터 적은 것 순으로” 모듈을 끄며, 추가 파라미터가 예산을 넘지 않을 때까지 진행합니다.
  - 재설정 버튼
- 아래는 각 부위의 카드입니다. 카드 머리에는 켜진 모듈 수와 추가 파라미터 수가 표시되고, 펼치면 다음과 같습니다.
  - 기초 알고리즘이 여러 개이면, 기초 알고리즘 드롭다운과 그 노브를 표시합니다.
  - 모듈마다 한 줄입니다. 스위치, 비용이 있고, 켜면 노브를 표시합니다.
  - 현재 소재에 적용되는 모듈만 표시합니다.
  - 마지막은 그 부위의 「수치」 접기 항목입니다. 이 부위의 Rig 수치입니다(`RigTuning`. 머리와 얼굴은 머리 회전과 코·귀를 포함하고, 몸은 몸 돌리기, 위아래, 앞뒤 기울기, 크기 변화, 몸 Z와 호흡, 입체와 원근을 포함합니다). 자주 쓰는 것은 소그룹으로 나열하고, 나머지는 「고급」으로 접으며, 이 수치만 재설정하는 버튼이 있습니다.
- 현재 레시피에서 실제로 작용하는 Rig 수치만 표시합니다. 어떤 모듈이나 기초 알고리즘이 생성할 때 직접 그리는 부분에 대응하는 이전 수치는 더 이상 표시하지 않습니다(`RigTuning.replacedBy`, `RigModules.tuningInEffect`). `face.depth-turn`이 생성될 때, 얼굴, 이목구비, 앞뒤 머리카락이 AngleX / AngleY에서 쓰는 3×3 고개 돌리기 수치는 표시하지 않습니다(스타일 고개 돌리기가 그것들을 대체하고, 원래 디포머는 고개 돌리기 키에서 정지합니다). 피팅 눈은 기존 눈 감기 수치(깜빡임 깊이, 눈꼬리, 속눈썹 납작함)를 대체하고, 피팅 눈썹은 눈썹 들어 올리기를 대체하며, 피팅 입은 기존 입 모양 수치를 대체하고, 머리카락 체인은 앞머리·뒷머리 각각의 전체 스윙과 컬을 대체합니다. 이전 프로젝트(레시피를 올리지 않음)와 이 모듈들을 껐을 때는 이 수치들이 그대로 표시되고 작용합니다. 프로젝트 파일과 MCP는 여전히 모든 필드를 받습니다.
- 이전 프로젝트는 그룹 위쪽에 업그레이드할 수 있다고 안내합니다. 자동으로 업그레이드하지 않습니다.

**MCP**

- `module_catalog`(읽기 전용): 모든 부위, 기초 알고리즘, 모듈, 노브를 나열합니다. 프로젝트를 열면 다음도 반환합니다.
  - 새 레시피인지, 각 부위의 현재 기초 알고리즘
  - 각 모듈이 적용되는지, 켜져 있는지, 그리고 비용
- `settings_update`: `changes.rig`로 레시피를 수정합니다.
- `workspace_inspect scope=settings`: 저장 형태를 반환하며, 그대로 다시 쓸 수 있습니다.

## 특징점 피팅(`core/fit`)

이목구비의 새 기초 알고리즘은 고정된 수식에 기대지 않습니다. 원화의 특징점을 읽고, 표준 템플릿을 거기에 맞춥니다.

| 컴포넌트 | 역할 |
| --- | --- |
| `EyeFitting` | 먼저 양쪽 흰자 중심을 잇는 선으로 머리의 수평 방향을 구합니다(눈이 하나뿐이면 Rig의 수평을 씁니다). 눈의 좌표계는 그에 따라 기울어집니다. 고개를 기울이거나 몸을 튼 캐릭터는 자기 얼굴을 따라 열고 닫습니다. 이 방향을 따라 흰자 불투명 픽셀의 양 끝은 안쪽·바깥쪽 눈꼬리이고, 두 눈꼬리 사이에서 “얼굴의 아래 방향”을 따라 위·아래 눈꺼풀 가장자리를 곳곳마다 읽습니다(각 17개 샘플. 작가는 보통 흰자를 속눈썹 아래까지 온전히 그립니다). 감은 눈 선에서는 중심선을 읽고, 홍채에서는 외곽을 읽습니다. 좌표는 안쪽 눈꼬리를 원점으로 하고, 단위는 두 눈꼬리가 머리 수평 방향으로 떨어진 거리입니다. 바깥쪽 눈꼬리는 안쪽보다 높거나 낮을 수 있습니다. 너비, 개폐 비율, 위·아래 눈꺼풀 가장자리 순서, 눈꼬리 기울기를 검사하고, 합격하지 못한 눈은 기존 알고리즘으로 되돌리며 이유를 줍니다 |
| `EyelidModel` | 의사 3D 눈꺼풀입니다. 눈꺼풀은 눈꼬리 연결선을 축으로 회전하는 평면이고, 안구와 만나는 곳이 눈꺼풀 가장자리입니다. 그래서 눈꺼풀이 내려갈 때 가장자리는 항상 안구를 덮는 호이며, 눈꼬리 선을 넘을 때만 곧아지고, 그 뒤 감은 눈의 아래로 굽은 호가 됩니다 |
| `ThinPlateSpline` | 박판 스플라인입니다. 템플릿의 특징점을 검출된 특징점에 정확히 맞추고, 같은 사상을 템플릿의 각 포즈에 씁니다 |
| `BiharmonicField` | 규칙 메시 위의 쌍조화 변위장입니다. 구속점(눈꺼풀 가장자리, 입술 가장자리)에서만 변위를 주고, 나머지에서는 가장 매끄러운 해를 취하며, 바깥 둘레는 0입니다. 눈꺼풀 피부, 그림자 등이 눈꺼풀 가장자리를 따라 여러 줄로 매끄럽게 움직이게 하는 데 씁니다 |
| `EyeRig` / `EyeBand` | `eye/fitted`는 원화에서 주 획의 띠 몸통, 독립 다발, 옆 가장자리, 위아래 파츠, 접합 구역을 관찰합니다. 띠 몸통은 연속 곡선과 가로 단면으로 닫힌 형태를 만들며 선 두께를 유지합니다. 일반 닫기와 웃음 닫기를 각각 생성합니다. 인식된 뾰족 다발은 국소적으로 모이고 띠 몸통의 반대편까지 넘을 수 있으며, 뿌리 구역은 매끄럽게 전환됩니다. 옆 가장자리는 띠 몸통 근처로 모입니다. 추가 눈 형태는 같은 눈 좌표 안에서 변위를 만들고, 전체 고개 돌리기는 이미 있는 부모가 담당합니다. 중립 원화 키는 정확히 변하지 않습니다. 신뢰할 수 있는 획 관찰이 없으면 기존 눈꺼풀 경로를 유지합니다. 흰자 자르기와 획 지오메트리는 따로 생성합니다. 양 눈이 합쳐진 레이어는 출처 위치에 따라 좌우 개폐를 독립적으로 리깅합니다 |
| `BrowRig` | `brow/fitted` 기초 알고리즘과 눈썹 모듈입니다. 눈썹도 머리 좌표계에서 읽습니다. 머리 수평 방향의 양 끝이 안쪽·바깥쪽 끝이고(얼굴 중심선에 가까운 쪽이 안쪽), 중심선은 17개 샘플로 읽습니다. 위아래 이동 폭은 대략 아래 눈 개구 높이의 절반입니다(노브 “이동 폭”). 피팅 눈이 없으면 눈썹 길이의 4분의 1을 씁니다. 각도는 눈썹 중점을 중심으로 호를 따라 회전하며 전단이 아닙니다. 키 포인트는 다섯 개입니다. 좌우 이동, 아치, 깜빡임 하강은 겹치는 블렌드 셰이프입니다 |
| `HeadTurn` | `face.depth-turn` 모듈입니다. 얼굴, 이목구비, 머리카락은 “고개 돌리기 스타일”(`TurnStyle`, 바이너리 `rig/head-turn-style.bin`에 저장)에 따라 변합니다. 스타일은 세 층 구조입니다. **메타 변형**은 이름이 있는 변위량 묶음이며, 모두 얼굴 너비를 단위로 하고 고개 방향에 따라 미러링합니다(+x 방향 회전이 양). 얼굴 중부의 미끄러짐. 얼굴 윤곽을 턱에서부터 호 길이로 등분한 24개 점이 중부 대비 가지는 변위. 각 눈(흰자와 속눈썹)의 중심이 중부 대비 앞서는 양과 위아래, 전체 2×2 선형 변화(좁아짐과 기울기가 함께이며, 먼 쪽 눈의 바깥 끝이 더 많이 좁아지는 것은 선형 변화 자체의 결과이고 회전이 아닙니다), 속눈썹 끝이 흰자 바깥 끝을 넘는 부분의 추가 변위, 홍채가 개구 안에서 차지하는 상대 위치와 자신의 너비, 눈에서 같은 높이 윤곽까지의 여유. 각 눈썹의 선행, 위아래, 너비, 기울기, 아치. 입의 선행, 위아래, 2×2 선형 변화와 입선 굽힘. 가까운 귀, 먼 쪽 귀, 머리 장식의 전체 변위. 머리카락의 각 역할(앞머리, 옆머리, 정수리, 늘어진 머리, 뒷머리, 뒷머리 아랫단)의 장 파라미터 묶음. 각 메타 변형은 고개 돌리기 몫 a와 상하 회전 몫 p 위의 **체비쇼프 곡면**입니다. f(a,p) = Σ c<sub>i0</sub> U<sub>i</sub>(a) + Σ c<sub>0j</sub> V<sub>j</sub>(p) + Σ c<sub>ij</sub> U<sub>i</sub>(a) V<sub>j</sub>(p), U<sub>i</sub>(a) = T<sub>i</sub>(2a−1) − T<sub>i</sub>(−1), V<sub>j</sub>(p) = T<sub>j</sub>(p) − T<sub>j</sub>(0), 각각 4차까지입니다. 정지 때는 0입니다. 첫 항은 좌우 회전만 담당하고, 둘째 항은 고개 들기와 숙이기만 담당하며, 셋째 항은 비스듬한 포즈 자체의 변화입니다. 계수는 직접 읽을 수 있습니다. 고개 돌리기의 1차는 등속 부분이고, 2차는 앞섬 또는 늦음입니다(같은 고개 돌리기 안에서 각 부분이 동기화되어 확대·축소되지 않습니다. 예를 들어 두 눈 간격과 먼 쪽 눈의 좁아짐은 후반에야 뚜렷하고, 가까운 눈은 출발이 느립니다). 상하 회전의 홀수 차는 고개 들기와 숙이기의 차이고, 짝수 차는 둘에 공통된 부분입니다. 곡면은 각 레퍼런스의 모든 키폼에 맞추며, 고차 항은 차수에 따라 페널티를 주므로 키폼이 적은 레퍼런스는 저차와 매끄러움을 유지하고 전체 평균 형태에 가까워집니다. 주축은 계수 위에 만듭니다. 저장할 때는 각 값에서 실제로 쓰는 항만 남깁니다(제거한 뒤 어느 곡면 묶음이든 변화가 허용 오차를 넘지 않아야 합니다). 계수는 값마다 스케일된 8비트 또는 16비트 정수이며, 다시 압축합니다. 스타일 전체는 약 48 KB입니다. **사용자 제어**는 기본 스타일 위에 아트 슬라이더를 겹칩니다. 각 슬라이더는 한 방향으로 메타 변형 묶음을 바꿉니다(100%는 그 스타일 양의 전형적인 차이 하나). 입체감(얼굴 중심선이 윤곽 대비 앞서는 양), 원근(먼 쪽 수축: 먼 쪽 눈, 두 눈 간격, 입 너비), 시선 유지(홍채를 눈 안에 붙잡아 둠), 볼선 스윙(가깝고 먼 양쪽 볼선의 차), 대각 롤(비스듬히 고개를 들거나 숙일 때 눈선 기울기), 상하 깊이(고개를 들거나 숙일 때 이목구비와 앞머리의 위아래), 장식 추종(머리 장식과 앞머리). 머리카락에는 머리카락 추종, 끝 선행, 뒷머리 시차라는 슬라이더 세 개가 더 있어 노브, 패널에서는 “고개 돌리기 스타일” 드롭다운: 표준, 강한 입체, 과장, 큰 폭, 끄덕임, 부드러움). 각각은 스타일 주축 위의 곡면 한 묶음이며 머리카락을 포함합니다. 선택한 뒤 모듈의 나머지 수치는 기본으로 돌아가고, 슬라이더는 그 위에서 조정합니다. 각도 수치는 파라미터의 위치일 뿐입니다. 않으므로 입꼬리가 겹쳐 굵어지지 않습니다. 입꼬리 근처(입 너비의 8% 이내)에서는 두 선의 끝이 점점 함께 움직이다가 입꼬리에서는 각각 절반을 따르므로, 둥근 입에서 두 끝은 항상 겹쳐 입꼬리 하나가 되고 어긋나 계단이 되지 않습니다. 개구가 따르는 것도 같은 선 운동입니다. 위·아래 입술 선이 있으면 입꼬리는 두 선이 만나는 점이며 옆벽의 중점이 아닙니다. 입술 덩어리(입술과 주변 피부)는 가장 가까운 입술 가장자리를 따라 전체로 이동하고, 입술 가장자리에서 멀수록 덜 움직입니다(바깥 가장자리는 약 35% 남음). 입술의 그리는 방식은 굽히기만 하고 납작하게 하지 않습니다. 구강(역할이 없는 입 레이어)은 두 입술 선 사이에서 이동합니다. 입술 선 띠 아래 부분은 그 입술 선을 따르고, 중간은 위치에 따라 두 선 사이를 보간하므로, 어떤 입 모양(입꼬리 포함)에서도 구강 가장자리는 선 아래에 남고 선 밖으로 나오지 않습니다. 입술 덩어리가 있으면 `inside`(기본 50%)만큼만 걷고 나머지는 입술 덩어리가 덮으며, 입술 덩어리가 없으면 전체가 입술 선 아래로 들어갑니다. 구강은 다른 레이어를 자르는 개구이므로 고개 돌리기 시차를 넣지 않고, 그것이 자르는 이, 혀, 구강 깊숙한 곳에만 넣습니다. PSD에서 구강에 클리핑된 역할 없는 입 레이어는 구강 밑색입니다. 어떤 개구보다도 크게 그려지고, 입 모양 읽기에 참여하지 않으며, 구강에 잘리고, 이와 혀 뒤에 배치되며, 입 모양에 따라 움직이지 않습니다. 구강은 보이지 않는 형태일 수 있으며(레이어 불투명도 0), 그래도 자르기 원본이 됩니다. 층 분리 입의 각 레이어는 원화를 따라 그린 메시를 유지하고 스트로크 입의 열 분할 메시로 바꾸지 않으므로, 개구의 메시가 원화를 온전히 덮습니다. 입 위의 하이라이트와 그림자는 중심이 어디에 떨어지느냐에 따라 위 입술, 아래 입술을 따르거나, 구강 깊숙한 곳으로 거의 움직이지 않으며 구강에 잘립니다. 구강만 이, 혀, 구강 깊숙한 곳을 자릅니다. 층 분리 입은 스트로크 띠를 생성하지 않습니다 |
| `EyeModules` | 눈 모듈의 메시와 채널입니다. 개폐 축(`eye.wide`는 2까지 확장)과 웃는 눈 축(`eye.smile`)이 눈꺼풀 키폼 메시를 이룹니다. 시선에 따른 눈꺼풀, 감정 눈 형태와 실눈, 깜빡임 잔진동은 겹치는 블렌드 셰이프이며, 개폐 정도로 가중치를 제한하고 눈을 감으면 작용하지 않습니다. 웃는 눈일 때 원화의 감은 눈 선은 위로 솟은 호가 됩니다. 홍채는 닫힘에 따라 아래로 납작해지고, 크게 뜰 때 약간 줄어듭니다. 하이라이트는 고개 돌리기와 반대로 표류합니다. 눈꺼풀 선과 하이라이트는 개폐보다 앞서 페이드 아웃합니다. 블렌드 셰이프의 각 형태는 메시 자신의 그리기 순서와 불투명도를 기록하고, 변위만 겹칩니다 |

**고개 돌릴 때 눈, 눈썹, 옆얼굴의 연동**은 위·아래 눈꺼풀 가장자리의 사분점과 안쪽·바깥쪽 눈꼬리로 눈의 개구를 잽니다. 피팅은 각 포즈의 얼굴 옆 윤곽을 읽고, 변형된 눈꺼풀 가장자리 높이로 순거리를 구합니다. 가로 회전에 공간 제한이 있으면 먼 쪽 눈은 안쪽 눈꼬리를 앵커로 가로 개구를 줄이고, 원래 피팅의 눈꺼풀 가장자리 높이를 유지하며, 홍채는 개구 너비에 연동합니다. 여유가 여전히 부족하면 눈 전체를 안쪽으로 이동합니다. 눈썹은 같은 쪽 눈의 가로 보정을 따르고, 눈썹 중심선과 위 눈꺼풀 가장자리의 대응 샘플로 세로 간격을 구속합니다. 옆 귀와 얼굴 피부가 겹친 구역에서 접점을 읽을 수 있으면 귓뿌리는 얼굴 피부를 따르고, 귓바퀴 쪽으로 갈수록 독립 변위를 회복하며, 먼 쪽 귀는 옆 회전이 깊어질수록 접점 가중치가 약해집니다. 대응 랜드마크가 없는 부위는 기존 스타일 변형을 그대로 씁니다.

**이마 윤곽**은 기본 고개 돌리기 스타일에서 원화의 이마 꼭대기, 눈선, 이마 가로 단면에 맞춥니다. 앞머리가 원화에서 연속으로 덮고 얼굴 가장자리를 넘는 여유가 작으면, 가로 회전은 도는 쪽의 위 이마 가장자리를 조입니다. 비스듬히 숙이면 상하 회전에 따라 이 조임을 약하게 하고, 스타일 안의 비스듬한 윤곽 변화는 남깁니다. 보정은 이마 가장자리에서 중심선, 이마 꼭대기, 눈선으로 연속해서 감쇠하고, 앞머리는 자기 디포머를 계속 씁니다.

**기본 스타일의 입·코 고개 돌리기**는 두 입꼬리, 위·아래 입술 중점, 눈선에서의 얼굴 너비, 두 눈 간격, 독립 코의 코끝과 위 가장자리, 얼굴 윤곽의 턱을 읽습니다. 좌우로 돌릴 때 턱은 얼굴 윤곽을 따라 이동하고, 눈선 얼굴 너비와 두 눈 간격이 각각 코끝 선행과 입·코 간격을 결정하며, 얼굴 옆 여유는 코끝과 입꼬리가 움직일 수 있는 범위를 제한합니다. 고개 들기와 숙이기는 각자 세로 변위를 계산하고, 숙일 때는 코에서 위 입술, 아래 입술에서 턱까지의 여유로 변형 뒤 개구를 구속합니다. 실제로 눈선까지 그려진 콧대는 위 가장자리에서 얼굴 면으로 이어지고, 짧은 코선과 하이라이트는 코끝과 함께 이동합니다. 얼굴 피부에 그린 코는 얼굴 피부를 따릅니다.

입의 공유 굽힘 디포머는 입 너비가 얼굴 너비에서 차지하는 비율과 원화 개구의 종횡비로, 옆으로 돌릴 때의 너비, 높이, 위·아래 입술 중점을 맞춥니다. 개폐와 입 모양은 그 자식 메시에서 계속 독립적으로 평가합니다. 비스듬한 키폼은 스타일의 교차 항을 유지합니다. 독립 코 레이어나 신뢰할 수 있는 랜드마크가 없으면, 쓸 수 있는 입과 얼굴 윤곽 피팅을 사용합니다.

확장 눈 뜨기 구간(`Eye Open > 1`)은 `EyeOpeningModel`이 따로 표현합니다. 위·아래 눈꺼풀은 각각 가로와 세로의 4차 체비쇼프 변위 곡선을 가지며, 바이너리는 `rig/eye-opening.bin`에 있고 Clenshaw 점화식으로 평가합니다. 변위는 `wideLift × (open − 1)`로 스케일하므로 원화 값 1은 정확히 변하지 않습니다. 가로는 원래 눈 너비를 단위로 하고, 세로는 원래 개구 높이를 단위로 합니다. 곡선의 상수항이 전체 들어 올림을 담당하고, 나머지 항은 양 끝의 차이와 국소 호를 조정해 중앙만 아치를 높이는 일을 피합니다. 위·아래 눈꺼풀은 눈꼬리에서 2차원 변위를 공유하고, 흰자와 속눈썹은 같은 개구를 씁니다. 복합 눈선은 위·아래 눈꺼풀 사이의 위치에 따라 변위를 연속으로 나누고, 밖으로 뻗은 꼬리는 원화 오프셋을 유지하며, 위 속눈썹은 같은 열의 두께를 유지합니다. 아래 눈꺼풀에 가까운 획은 원래 아래 눈꺼풀 위 가장 가까운 가장자리 점을 따라, 가파른 눈꼬리 아래의 두꺼운 꼬리가 세로 열로 잘려 뒤집히는 일을 피합니다. 쌍꺼풀 선과 그림자의 쌍조화 장은 가로·세로 구속을 함께 받습니다. 기본 들어 올림은 원래 개구의 10%이며 0까지 조정할 수 있습니다. 기본 목표는 온건하게 크게 뜨는 것이고, 명시적으로 저장한 폭은 그 값을 유지합니다. 기존 닫힘 구간은 독립적으로 남고, 크게 뜰 때 홍채는 원화의 크기와 위치를 유지하며, 동공 축소는 독립된 감정 제어가 담당합니다.

개폐 관련 투명도 트랙은 크게 뜨는 끝점을 포함해 실제 파라미터 전 범위를 덮습니다. 감은 눈 선은 1보다 클 때 계속 숨고, 속눈썹, 쌍꺼풀 선, 하이라이트는 각자 눈을 떴을 때의 가시성을 유지해, 트랙을 벗어난 뒤 정적 투명도로 돌아가는 일을 피합니다.

`FitDetectionTool`은 검출 결과와 각 열림의 눈꺼풀 가장자리를 원본 위에 겹쳐 그려 피팅을 검사합니다. 피팅 눈의 속눈썹, 흰자, 감은 눈 선 메시는 약 네 배 촘촘해서, 호로 굽어도 다각형 꺾임이 드러나지 않습니다.

## 구현 약속

- `legacy` 기초 알고리즘의 코드 경로는 그대로 둡니다.
  - 새 기초 알고리즘과 모듈은 디스패치 지점에서 `config.recipe.base(部位)`와 `RigModules.builds(模块, config, 素材)`로 구현을 고릅니다.
  - 구현은 순수 기하 입력에만 의존하고, 인터페이스 상태를 읽지 않습니다.
- 모듈 하나가 어떤 파라미터의 키 위치를 바꾸면, 그 파라미터를 공유하는 모든 메시는 같은 키 묶음을 써야 합니다. 예를 들어 흰자는 홍채의 마스크이므로 속눈썹과 같은 키여야 합니다.
- 부차 변화는 주 키폼 위에 블렌드 셰이프로 겹치는 쪽을 우선해, 키폼 수가 차원별로 곱해지지 않게 합니다. 블렌드 셰이프를 지원하지 않는 내보내기 대상은 다운그레이더가 베이크하거나 버리고, 손실 보고서를 씁니다.
- 생성 결과에는 Cubism이 표현할 수 있는 블렌드 셰이프만 들어갑니다(`CubismBlendShapes`, 기초 Rig를 조립한 뒤 실행). Cubism은 “블렌드 셰이프” 유형의 파라미터에만 블렌드 셰이프를 겹치고, 이런 파라미터는 키폼 축이 될 수 없습니다. 일반 파라미터에 달린 블렌드 셰이프는 moc3 / cmo3에 쓸 수 없고, Cubism 런타임이 잘못 그립니다. 그래서 다음을 합니다.
  - 블렌드 셰이프만 쓰고, 기본값이 0이며, 각 형태의 정지 키가 0인 파라미터(모음, 페이스 캡처, 눈썹 형태, 머리카락과 천의 체인 구간, 팔 스윙, 가슴 등)는 블렌드 셰이프 파라미터로 바꿉니다.
  - 동시에 어떤 키폼 축이기도 한 파라미터(고개 돌리기 각도, 눈과 입의 개폐, 시선, 눈썹 높이와 각도, 입 모양) 위의 형태는 키폼으로 바꿉니다. 메시 자신의 키폼 격자(지오메트리와 각 채널 축의 합집합, 즉 moc3에서 그 메시의 키폼 수)가 256개를 넘지 않고 정점 값이 12만을 넘지 않으면, 이 파라미터의 키를 따라 메시에 접어 넣으며 결과는 정확합니다(형태의 가중치는 키 사이에서, 제한은 점 사이에서 모두 선형이므로, 모든 키에서 값을 가진 메시가 완전히 재현됩니다). 넘으면 메시 자신의 Warp에 맡깁니다(`<网格 ID>_Turn`에 고개 돌리기, `<网格 ID>_Shape<n>`에 나머지 연동, 각각 키폼 64개 이하). 메시와 원래 부모 사이에 끼우고, 8×8 격자점이 형태에 따라 메시 정점이 자기 각 키폼에서 가지는 변위를 최소제곱으로 맞춥니다. Live2D 수작업 모델이 고개 돌리기를 파츠 Warp에 두는 방식과 같습니다. 부모가 굽어 있으면 Warp는 격자점으로만 근사할 수 있고, 오차는 캔버스 픽셀 1 정도입니다.
  - 형태가 바꾸는 불투명도와 색은 메시 채널에 접어 넣습니다. 생성한 형태는 그리기 순서를 바꾸지 않습니다(각 형태의 그리기 순서는 메시의 최종 정지 값을 씁니다).
- 생성 객체와 파라미터의 ID는 결정적입니다.
  - 모듈이 추가하는 파라미터는 Cubism 표준 이름을 우선하고, 페이스 캡처 확장은 흔한 커뮤니티 이름을 씁니다.
  - 새 객체 ID는 모듈과 대상에서 파생하며, 난수를 쓰지 않습니다.

## 모듈 하나를 확장하기

1. 목록에 설계를 씁니다.
   - 적용 조건, 산출, 단계별 알고리즘, 노브
   - 보기 좋은 모습과 흔한 문제
   - 실패하면 무엇으로 되돌아가는지
2. `RigModules`에 등록합니다. 소속 부위, 중요도, 의존, 적용 조건, 파라미터, 비용 추정, 노브입니다.
3. 생성 디스패치 지점에서 구현하고, `legacy` 경로는 그대로 둡니다.
4. 네 언어의 이름과 설명을 채웁니다(`settings.rig.module.*`, `settings.rig.knob.*`).
5. 검증합니다.
   - `RigReviewTool`로 포즈 보드와 모션 클립을 만들고, 보기 좋은 기준과 대조해 확인합니다.
   - `ExportGoldenTool`로 구 레시피 프로젝트가 바이트 단위로 변하지 않는지 확인합니다.
   - 회귀 테스트를 추가합니다(`RigRecipeTest`, `RigModulesScenario`).

## 세 층 입 모양과 트래킹 내보내기

입 소재 전체로 스트로크를 생성할 때, 다문 선은 입 모양 설정의 연속 곡선을 쓰고, 개구 윤곽의 중점은 다문 선으로 남기지 않습니다. 독립된 층 분리 입술 선은 원화 구조를 유지합니다. 원화와 목표 윤곽의 샘플 밀도가 다르면 샘플 잔차는 닫힘과 함께 되돌아가, 위·아래 입술 가장자리와 입술을 가로지르는 스트로크의 겹친 구간이 입을 다물 때 같은 선으로 모이고, 가파른 입꼬리에 짧은 꼬리를 남기지 않습니다. 원화의 벌린 포즈는 원래 윤곽을 유지합니다.

생성 스트로크는 입술 원화가 없는 구강 레이어에만 적용됩니다. 위/아래 입술 선, 입술 피부, 또는 닫힌 입 틈이 이미 있거나, 겹치는 완전한 입 모양 차분이 있으면 스트로크를 추가하지 않습니다. 입안 클리핑 레이어, 입술 하이라이트, 그림자도 스트로크의 출처가 되지 않습니다. 네이티브 생성과 알고리즘 플러그인은 같은 후보 레이어 판단을 씁니다.

스트로크 중심선과 원화 입술 선은 따로 바인딩합니다. 중심선은 목표 입술 가장자리를 따라 이동한 뒤, 목표 경로에 따라 선 두께를 유지하는 단면을 생성합니다. 정확히 다물 때, 생성 스트로크와 원화 선 입은 각 표정의 기초 열림 잔차를 없앱니다. 원화 입술 선은 각자 입술 가장자리 지점에서 재질 두께와 입꼬리 획을 유지하고, 입꼬리는 원화의 벌린 호를 추가 두께로 남기지 않습니다. 입안 경계와 입술 가장자리는 같은 대응 관계를 쓰고, 입술 피부는 덮는 면적을 유지합니다. 입술 누르기, 이 드러내기, 턱 같은 추가 운동은 공통 입 모양 목표 위에 계속 겹치며, 획 두께를 구강 열림으로 남겨 둘 수 없습니다.

피팅 입은 정규화 윤곽, 변형 부분 공간, 사용자 파라미터의 세 층으로 평가합니다. 원화의 벌린 중립 포즈는 원래 자리를 유지하고, 다물면 위·아래 입술 가장자리가 만납니다. 셀 입술 선은 국소 접선과 법선으로 굵기를 유지하고, 두껍게 칠한 입술 피부의 바깥 가장자리는 본 얼굴과 입 주변 변형을 공유합니다. 위·아래 이는 각각 위턱과 아래턱을 따르고, 입을 비틀면 치열 전체가 기울며 눌리는 쪽에서 모입니다. 한쪽 입꼬리와 한쪽 볼 부풀림·오므림은 독립 파라미터로 겹칩니다.

층 분리 입의 이와 혀는 구강 마스크로 잘리며 개구에 따라 페이드 인하지 않습니다. 불투명도가 0인 구강 레이어도 마스크가 될 수 있습니다. 혀 내밀기는 결정적 ID의 동반 메시 `<舌网格 ID>_Out`을 생성합니다. 정지 때 투명하고 구강 클리핑을 받지 않으며, 아래 입술 위와 위 입술 아래에 있습니다. 모음 입 모양은 단독으로 구동할 수 있고, 개구 파라미터가 커질수록 감쇠해 음성과 페이스 캡처가 겹칠 때 입을 두 번 벌리지 않게 합니다.

`eye.gaze-lid`는 `ParamEyeBallLX/LY/RX/RY`를 추가합니다. 공유 시선 파라미터는 계속 남습니다. 독립 시선은 대응 홍채와 눈꺼풀에 동시에 작용하며, 2차원 파라미터 미러 및 프로젝트 재구축과 호환됩니다.

VTube Studio 내보내기는 다음 선택을 제공하며, 각 출력 파라미터는 한 번만 매핑합니다. 없는 모델 파라미터는 매핑을 만들지 않습니다.

| 설정 | 선택 값과 동작 |
| --- | --- |
| `vts_mouth` | `standard` 페이스 캡처. `voice` 음성 모음(모음 파라미터가 없으면 음량으로 개구를 구동). `voice_hybrid` 음성과 페이스 캡처 혼합. `vbridger`는 플러그인의 JawOpen, MouthPucker, MouthFunnel, MouthShrug, MouthPressLipOpen 입력을 추가합니다 |
| `vts_gaze` | `independent` 좌우 독립, 이전 모델은 공유 시선으로 되돌아갑니다. `shared` 오른쪽 눈 시선을 함께 씁니다. `mouse` 마우스 위치입니다 |
| `vts_brows` | `independent` 좌우 눈썹 높이. `shared` Brows를 함께 씁니다 |
| `vts_position` | 기본은 끄며, 이미 있는 `ParamFacePositionX/Y/Z`에 매핑합니다 |
| `vts_angry` | 기본은 끄며, 실험적 FaceAngry 입력을 이미 있는 눈 감정 파라미터에 매핑합니다 |

공식 33개 머리, 시선, 입, 마우스, 음성 입력을 덮습니다. 서로 배타적인 입력은 모드에 따라 고릅니다. 사용자 지정 모델은 `Param<输入名>`으로 해당 공식 입력에 접속할 수 있습니다(예: `ParamVoiceSilence`). 내보내기는 그것을 위해 빈 파라미터를 만들지 않습니다. VBridger 모드는 사용자가 플러그인을 실행하고 대응 입력을 제공해야 합니다.

입력 이름은 [VTS 공식 파라미터 표](https://github.com/DenchiSoft/VTubeStudio/wiki/VTS-Model-Settings#supported-input-parameters-face-tracking-etc)를 따르고, 플러그인 파라미터는 [VBridger 공식 문서](https://github.com/PiPuProductions/VBridger-Documentation/wiki)를 따릅니다.

현재 시각적 제한: 두껍게 칠한 입술 피부는 최대 비튼 입과 개구가 겹칠 때, 입 주변 피부의 점별 변위 혼합이 국소 메시를 뒤집을 수 있습니다. 이 조합은 아직 시각 검수를 통과하지 못했으며, 공유 피부 장을 더 고쳐야 합니다.

### 눈 구조 교정

`module_catalog.eye_structure`는 눈마다 원화 경로, 컴포넌트 ID, 출처 요약, 위아래 귀속, 지오메트리 유형, 접합 구역, 분기 경로를 반환합니다. 관찰은 원래 생성 픽셀을 출처로 하며, 원 레이어, UV, 그리기 순서, 명시적 마스크를 유지합니다. 숫자 접미사는 대체 그림을 뜻하지 않습니다.

`settings.rig.eyeParts[layerId][componentId]`는 `side`, `region`, `primitive`, `contacts`, `path`를 덮어쓸 수 있으며, 동시에 일치하는 `sourceStamp`를 가져야 합니다. 경로와 접합 좌표는 그 눈의 국소 좌표를 씁니다. 안쪽 각이 원점, 눈 너비가 단위, 둘째 축은 얼굴 아래입니다. 출처와 맞지 않는 덮어쓰기는 저장되지만 바뀐 원화에는 적용되지 않습니다. 출처가 복구되면 다시 적용됩니다. 컴포넌트, 레이어, 또는 `eyeParts` 전체의 null 패치는 재설정에 쓰며, 연속된 설정 제스처는 재설정 순서를 유지합니다. 새 설정 노드는 schema 5를 씁니다. 구조 교정이 없는 이전 프로젝트는 원래 노드 버전을 유지합니다.
