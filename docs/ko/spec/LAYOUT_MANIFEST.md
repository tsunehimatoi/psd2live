# Layout 매니페스트

[문서 목록](../README.md) · [사용 가이드](../guide/LAYOUT.md) · [PSD 소재와 이름](PSD_LAYER_SPEC.md)

Layout 매니페스트는 PSD2Live가 분리된 소재를 읽는 교환 형식입니다. JSON 파일 하나에, 캔버스 하나가 어떤 그림으로 이루어지는지 적습니다. 각 그림의 경로와 픽셀 크기, 캔버스상의 사각형, 위아래 순서, 속한 그룹, 의미 태그, 차분, 가시성, 불투명도, 그리고 참고용으로만 쓰는지입니다. 어떤 도구든 이 페이지대로 매니페스트를 쓸 수 있습니다. PSD2Live는 그것으로 아직 생성하지 않은 Layout 프로젝트를 만들거나, 소재로 가져옵니다.

PSD와 달리, 그림의 픽셀 수는 캔버스상의 크기와 같지 않아도 됩니다. 작은 파츠는 캔버스보다 많은 픽셀을 가질 수 있으며, PSD2Live는 [레이어별 크기](DOCUMENT_LAYER.md#레이어별-크기)대로 그것들을 유지하므로 텍스처가 더 촘촘합니다.

## 파일과 압축 패키지

- 매니페스트는 UTF-8로 인코딩한 JSON 객체이며, 확장자는 `.json`이고, 16 MiB를 넘지 않습니다. 그림 경로는 매니페스트가 있는 폴더에 상대적입니다.
- 매니페스트와 그림을 `.zip`으로 묶을 수도 있습니다. 매니페스트는 압축 패키지 루트에 두거나, 압축 패키지의 유일한 최상위 폴더 안에 둡니다(폴더 하나를 그대로 압축할 때 흔합니다). PSD2Live는 그 단계에서 `format`을 선언한 JSON을 찾으며, 그림 경로는 그것에 상대적입니다. 같은 단계에 매니페스트가 두 개면 읽기를 거부합니다. macOS가 붙이는 `__MACOSX/`와 `._*`는 내용으로 치지 않습니다.
- 그림은 PSD2Live가 디코드할 수 있는 아무 형식이면 됩니다(PNG, WebP, JPEG, BMP, TIFF). 사전 곱하지 않은 alpha의 PNG를 권합니다. 한 장은 16 MP를 넘지 않고, 그림 파일 하나는 1 GiB를 넘지 않습니다. 그림 합계에는 상한이 없으며, PSD와 같이 디코드 뒤 차지하는 메모리만 제한합니다(한 장씩 읽고 디코드하며, 원본 바이트가 동시에 상주하지 않습니다). 레이어는 최대 4096개입니다. 같은 그림을 여러 레이어가 참조할 수 있습니다.

## 구조

```json
{
  "format": "psd2live-layout",
  "version": 1,
  "name": "character",
  "canvas": { "width": 3258, "height": 4344 },
  "groups": [
    { "path": "head", "visible": true, "opacity": 1 }
  ],
  "layers": [
    {
      "name": "source",
      "image": { "path": "source.png", "width": 3258, "height": 4344 },
      "rect": { "left": 0, "top": 0, "width": 3258, "height": 4344 },
      "reference": true,
      "opacity": 0.5
    },
    {
      "name": "back hair",
      "image": { "path": "parts/back_hair.png", "width": 484, "height": 601 },
      "rect": { "left": 804.3, "top": 207.0, "width": 1642.6, "height": 2039.6 },
      "tags": ["hair", "back"]
    },
    {
      "id": "iris_l",
      "name": "iris L",
      "image": { "path": "parts/iris_l.png", "width": 126, "height": 147 },
      "rect": { "left": 1724.24, "top": 745.36, "width": 101.65, "height": 118.63 },
      "group": "head/eyes",
      "tags": ["eye", "iris", "left"]
    },
    {
      "name": "mouth open",
      "image": { "path": "parts/mouth_open.png", "width": 183, "height": 78 },
      "rect": { "left": 1555.6, "top": 935.8, "width": 147.6, "height": 62.9 },
      "group": "head",
      "tags": ["mouth", "open"],
      "variant": { "type": "toggle", "parameter": "ParamMouthOpen" },
      "opacity": 1,
      "visible": true
    }
  ]
}
```

### 최상위

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `format` | 예 | 고정값 `psd2live-layout` |
| `version` | 예 | 정수. 현재는 `1`. PSD2Live는 자신보다 새로운 버전 읽기를 거부합니다 |
| `canvas` | 예 | `{width, height}`: 캔버스 크기. 정수 캔버스 단위. 한 변 1–8192, 합계 16 MP 이하. 캔버스 단위는 Cubism으로 내보낸 뒤 모델 캔버스의 픽셀입니다 |
| `layers` | 예 | 레이어 배열. 1–4096개. 순서는 [위아래 순서](#위아래-순서)를 참조 |
| `groups` | 아니요 | 그룹 속성. `path`(필수), `visible`(기본 `true`), `opacity`(0–1, 기본 `1`). 경로는 중복될 수 없습니다 |
| `name` | 아니요 | 매니페스트 이름. 소재 폴더 이름으로 씁니다. 생략하면 파일 이름을 씁니다 |

### 레이어

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `name` | 예 | 레이어 이름. 출력 가능 문자 128자 이하 |
| `image` | 예 | `{path, width, height}`: 그림 경로(상대 경로, `/`로 구분, `..`, `.` 구간, 역슬래시, 드라이브 문자를 포함하지 않으며, 매니페스트가 있는 폴더나 압축 패키지의 그 단계를 벗어날 수 없음)와 그림의 픽셀 크기. 크기는 그림과 일치해야 합니다 |
| `rect` | 예 | `{left, top, width, height}`: 그림이 깔리는 캔버스 사각형. 부동소수점 캔버스 단위. 너비와 높이는 양수이며, 캔버스를 벗어날 수 있습니다. 픽셀 크기와 사각형의 비가 텍스처 밀도입니다. `126 × 147` 그림을 `101.65 × 118.63` 사각형에 깔면, 캔버스 단위당 텍스처 픽셀이 약 1.24개입니다 |
| `id` | 아니요 | 레이어 ID. `[A-Za-z0-9_.:#-]{1,96}`. 매니페스트 안에서 유일합니다. 이후 편집과 MCP는 이것으로 레이어를 참조합니다. 생략하면 순번과 이름에서 유도되며, 같은 매니페스트는 매번 같은 ID를 얻습니다 |
| `group` | 아니요 | 그룹 경로. 이름을 `/`로 잇습니다. 예: `head/eyes`. 각 단계가 소스 그림 그룹이 됩니다 |
| `tags` | 아니요 | 문자열 배열. 의미 태그와 사용자 태그. [태그](#태그)를 참조 |
| `variant` | 아니요 | 차분. [차분](#차분)을 참조 |
| `visible` | 아니요 | 기본 `true` |
| `opacity` | 아니요 | 0–1. 기본 `1` |
| `reference` | 아니요 | 기본 `false`. `true`이면 [레퍼런스 레이어](#레퍼런스-레이어)입니다 |

알 수 없는 필드는 무시합니다. 같은 버전에서 새로 추가되는 필드는 모두 선택이며, 기존 필드 의미를 바꾸면 버전 번호를 하나 올립니다.

### 위아래 순서

`layers`는 뒤에서 앞으로 배열합니다. 나중에 적은 레이어가 먼저 적은 레이어 위에 그려집니다. 이것은 PSD2Live 소스 그림의 레이어 순서와 같습니다(화가 순서이며, PSD2Live가 PSD를 읽어 얻는 순서이기도 합니다). 곧 Cubism 그리기 순서가 증가하는 방향입니다. i번째 레이어의 그리기 순서는 i−1번째보다 낮지 않습니다.

PSD2Live의 레이어 표는 이 순서로 레이어를 나열하고, 생성할 때 이것으로 기초 그리기 순서를 정합니다. 입 등의 생성기는 별도의 규칙이 있으며, 그리기 순서 눈금자의 설정이 우선합니다.

### 태그

- `tags` 안의 부위 단어와 `left` / `right`가 파츠와 좌우를 정합니다. 예를 들어 `["eye", "iris", "left"]`는 왼쪽 눈동자이고, `["hair", "front"]`는 앞머리입니다. 단어 표와 조합은 [의미 태그](PSD_LAYER_SPEC.md#의미-태그)를 참조합니다. 나머지 단어는 사용자 태그이며, 정리와 검색에만 쓰이고 생성에는 영향을 주지 않습니다.
- 부위 단어가 있으면 파츠와 좌우를 모두 `tags`에서 취합니다(좌우 단어가 없으면 좌우가 없습니다). 부위 단어가 없거나 `tags`를 생략하면, 레이어 이름으로 파츠와 좌우를 인식합니다. 규칙은 PSD 레이어와 같습니다([이름 참고](PSD_LAYER_SPEC.md#이름-참고)를 참조). 이때도 `tags` 안의 좌우 단어가 좌우를 정합니다.
- 좌우는 캐릭터 자신의 좌우입니다. 캐릭터의 왼쪽은 보통 화면 오른쪽에 있습니다.
- 같은 레이어에 `left`와 `right`를 동시에 둘 수 없습니다.

### 레퍼런스 레이어

`reference`가 `true`인 레이어는 참고용입니다. 예를 들어 파츠를 나누기 전의 원그림으로, 배치와 그리기를 대조하는 데 씁니다. 다른 레이어와 같이 순서, 그룹, 불투명도가 있고 캔버스에 표시되지만, 생성기는 읽지 않습니다. Rig와 모든 내보내기에 들어가지 않으며, 태그가 필요 없습니다. 연 뒤에는 언제든 모델 레이어로 되돌리거나, 아직 생성하지 않은 다른 레이어를 레퍼런스로 설정할 수 있습니다(소재와 Layout 구현을 참조).

### 차분

`variant`는 `{type, parameter, switch_id}`이며, MCP `layer_set_variant`와 같습니다.

| `type` | 의미 | `parameter` | `switch_id` |
| --- | --- | --- | --- |
| `none` | 차분 없음(기본) | 주지 않음 | 주지 않거나 `0` |
| `toggle` | 파라미터로 표시하거나 숨김 | 필수 | 주지 않거나 `0` |
| `switch` | 파라미터의 `switch_id`번째 선택 | 필수 | 음이 아닌 정수 |

## PSD2Live가 읽는 방법

- **프로젝트로 열기**: 「시작」 페이지나 열기 대화상자에서 매니페스트 또는 zip을 고르거나, 창으로 끌어 놓거나, MCP `project_import_layout`을 씁니다. 아직 생성하지 않은 Layout 프로젝트를 만들고 Layout 작업 공간으로 들어갑니다. 캔버스는 `canvas`이고, 레이어는 매니페스트대로 놓이며, 그림은 원래 픽셀을 유지한 채 사각형에 깔립니다. 태그와 차분은 레이어 분류로 쓰이고, 사용자 태그는 레이어 태그가 되며, `reference` 레이어는 레퍼런스 레이어가 됩니다. 각 레이어는 동시에 소재로 등록되고(`name`으로 이름 붙인 폴더에 놓임) 그것과 연결됩니다. 그 뒤 배치와 위아래 순서를 평소처럼 조정한 다음 생성합니다. 프로젝트는 매니페스트와 그림 파일을 유지하지 않으며, 픽셀은 프로젝트 히스토리에 저장됩니다.
- **소재로 가져오기**: 소재 패널에서 가져오거나 MCP `material_import`을 씁니다. `name`으로 이름 붙인 폴더 하나를 얻으며, 그룹은 하위 폴더가 됩니다. 각 항목의 기본 배치는 그 `rect`이고, 픽셀은 원래 해상도를 유지하며, `tags`를 달고 옵니다. `reference` 레이어의 항목은 기본적으로 레퍼런스로 놓는다고 표시됩니다. 차분은 레이어에 속하며, 소재를 따라가지 않습니다. 폴더 전체를 놓을 때는 매니페스트의 위아래 순서를 유지합니다. 폴더를 스캔할 때 그 안의 JSON과 zip은 건너뛰므로, 매니페스트의 그림은 일반 그림으로 한 번만 가져옵니다.
- 읽기는 어떤 오류에서든 멈추고 위치를 설명합니다(예: `layers[3]: parts/face.png is 808x935 pixels, the manifest says 800x935`). 일부만 가져오지 않습니다.

## 검증

`LayoutManifestScenario`가 덮는 범위는 다음과 같습니다. 매니페스트를 아직 생성하지 않은 프로젝트로 열고, 그림이 매니페스트의 픽셀과 사각형대로 유지됩니다(3배 픽셀인 파츠는 밀도를 유지하고, 분수 사각형도 유지). 위아래 순서, 그룹과 그룹 불투명도, 태그 분류와 사용자 태그, 차분, 불투명도, 소재 등록과 연결, 레퍼런스 레이어가 Rig에 들어가지 않고 생성 뒤에도 들어가지 않으며 복구한 뒤 기다렸다가 다음 생성에 들어감. 위아래 순서를 조정한 뒤 생성, 생성 뒤의 레이어는 조정 거부, 저장 후 다시 열기. 루트와 최상위 폴더 두 가지 zip이 같은 내용을 읽고, 소재로 가져올 때 기본 배치와 태그를 달며, 폴더를 스캔할 때 매니페스트를 건너뜀. 범위를 벗어난 경로, 크기가 맞지 않음, 더 새로운 버전, 다른 형식, 압축 패키지 하나에 매니페스트가 두 개인 경우는 거부. PSD나 매니페스트의 소재 폴더 전체를 놓으면 원래 위아래 순서를 유지. 레퍼런스 소재는 표시대로 놓이며, 놓을 때 따로 지정할 수 있습니다.
