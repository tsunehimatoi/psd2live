## Bounded change

Spring v10, Cheek v5 and Gloom v5 already identify materialized outline outputs and exclude them from source measurements. Previously each framing first constructed a native context from the original analysis. If restored outline rasters required a filtered analysis, capture discarded that context and constructed another from the filtered analysis.

The bounded fix assembles the same native configuration first and constructs exactly one context from the final measurement analysis. The primary framing and the separate outline-free face-detail framing remain separate. Source validation, provider checks, mesh fitting, parent frames and serialized values/resources are unchanged. At that stage, ordinary captures whose analysis did not need filtering performed the same work as before.

That fix alone removes a redundant host context, not native scaffold generation. Its retained native context still builds body/head/face/feature/hair motion on a cache miss. Warm scaffold caching can hide that work. The later structural candidate below addresses this remaining construction separately.

No published worker source, shared binding implementation, manifest, schema, package lock, default selector or global source configuration is changed.

## Registered structural-capture candidate

Each trio adapter's registered `definition(source)` now explicitly selects structural measurements. `sourceMeasurementDefinition(source)` aliases that definition; `nativeCaptureDefinition(source)` explicitly selects the retained eager native capture for independent comparisons. It is not a runtime fallback. All three factories share provider/source guards and serialization, changing only context construction. This trio change leaves historical adapters, `RigFittedMouthModuleSource.context`, global source configuration and ordinary rig contexts unchanged.

`RigBuilder.sourceSkinMeasurementContext` reuses the existing no-deformer numeric scaffold observations, then adds an explicit source-alignment flag and static parent/frame metadata. The context reports `deformersEnabled=false` and has no deformers. The source flag allows the existing eye/brow/mouth fitting and raw source meshing code to retain native head alignment without copying formulas or pretending native motion exists.

The static pair allocator receives every eligible sided layer in original source order, including unaffected layers, and the native IDs reserved before pair allocation. The frozen `ScaffoldPairs.build` supplies exact pair names, IDs, frames and membership. It constructs temporary identity lattices with no animated axes; those objects are discarded, not serialized. This is not zero object construction. The path retains the native default parent/frame function and is restricted to face, nose, ear and face-detail targets. Clothing/creature chains are rejected explicitly, as those providers are already outside the trio contracts. Remaining hair and hanging-arm branches cannot own these skin targets and occur after pair allocation.

Generated ancestry is deliberately unavailable: `underFace` rejects access on a measurement context. Before shared mouth capture, the structural path requires one fitted eye and a null styled face turn. This is the existing supported single-eye shell invariant: face landmark eye keys come only from fitted eyes, while a usable styled face turn requires both. The native capture's ancestry-dependent branch therefore remains inactive. No fallback retries, source admission widening or output normalization is added.

The dedicated counter is `source skin: measurement contexts`; static pairing is timed separately as `source skin: static pair frames`. Cold native capture remains a positive control for `scaffold: deformers (built)`, while registered structural capture must have no animated scaffold/template/lowering stage. Setting `generateDeformers=false` alone would lose alignment and pair parents; `neutralScaffold=true` would still construct branches and potentially hair-chain motion. These counters establish avoided work, not a measured latency improvement.

## Separate lid-head numeric optimization

Central commit `fac66bf` changes only the context used to read `faceRig` in `RigEyeWideModifier.kt`'s `captureLidHeadSource`: it passes `turning.copy(generateDeformers = false)`. Numeric head-turn serialization still receives the original `turning` configuration. Unlike the trio's raw mesh capture, this helper needs only face measurements, not generated parent frames or aligned mesh construction.

The separate five-test `WorkspaceLidHeadCaptureTest` suite (`fbc5971`) passed, covering nine consumer versions: smile 3, wide 3, gaze-lid 3, emotion 3, highlight 3, aftershock 4, squash 3/4 and brow-lid coupling 8. It preserves exact context/resources and same-input in-process/installed-worker binary output, with a frozen native helper as the cold positive control. The whole-wide-capture test proves exactly one fewer animated scaffold build while retaining the other required capture work. The optimization removes one unnecessary scaffold build per qualifying capture, not all native generation or object construction; no-head and incomplete-head boundaries remain covered.
