# PSD2Live runtime

`runtime/` is a standalone Rust library (MIT). It plays a `.p2lrt` model compiled by PSD2Live: parameter-driven deformation, physics, and motion clips. It provides a C ABI for other languages and engines to call. The editor calls the same library through `:format-eval` (JNA).

## Composition

| Part | Location | License |
| --- | --- | --- |
| `.p2lrt` writing and the `p2lrt` export target | `:targets:runtime` (`P2lrt`, `P2lrtTarget`) | MIT |
| Reading, evaluation, physics, motion clips, C ABI | `runtime/` (crate `p2l-runtime`, cdylib + staticlib) | MIT |
| C header | `runtime/include/p2l_runtime.h` | MIT |
| JVM binding | `:format-eval` (`P2lRuntime`, `NativeGeometryEvaluator`) | MIT |
| Web player | `:targets:web` (export target `web`: the page, `p2l.js`, and the runtime's WebAssembly build) | MIT |
| Godot 4 node `P2LCharacter` | `runtime/godot/` (GDExtension, godot-rust, Godot 4.3+), demo project `runtime/godot/demo/` | MIT |

Build: run `cargo build --release` in `runtime/`. The library is at `runtime/target/release/` (on Windows, `p2l_runtime.dll`). Gradle's `buildRuntime` builds it automatically when cargo is present: `./gradlew run` uses it, and packaging ships it with the application resources. Without cargo the step is skipped and the application falls back to the editor evaluator. `P2lRuntime.locate()` looks, in order, at the system property `psd2live.runtime.library`, the environment variable `PSD2LIVE_RUNTIME` (a file or a directory), the system property `psd2live.runtime.dir`, the packaged application's resource directory, and `java.library.path`.

The editor's export bake (Spine, DragonBones, glTF) evaluates through `NativeGeometryEvaluator` when the runtime library is available, and otherwise uses the engine evaluator. The two agree pose by pose. The editor's software preview (`RigCanvasSupport.evaluate`) also uses the runtime through `NativePreview`: the first time a preview model is seen, the engine answers and compilation runs in the background, and later frames go through the runtime. A temporary model during a drag does not wait for compilation. On failure, or with `-Dpsd2live.preview.runtime=false`, it stays on the engine. One evaluation on a tml with a skeleton is about 0.5 milliseconds, comparable to the engine (the JNA call and result conversion offset the native speed).

The preview canvas can use the runtime as the preview backend (“PSD2Live runtime (p2lrt)”, see CANVAS_RENDERER.md): in the background the preview model is compiled to `.p2lrt` (including simulation), the runtime evaluates the full pose given by the workspace clock, and `P2lrtGlRenderer` draws in the window's own Skia OpenGL context by the web player's rules. When extended (advanced) mode is on, each view's model turns on skinning and exact links. Live simulation and collision are controlled by the preview's physics switch (when on, `p2l_update_stages(dt, P2L_STAGE_SIM)` advances only the live simulation by the frame time, and pause does not stop it; when off, the baked swing is shown). Physics results the workspace has already composited are kept as they are. The runtime does not compute physics again, and procedural behavior stays off. Background compilation also prepares and caches skinning weights. A view creates its own pose and simulation instance from the shared model. Switching mode does not refit on the render thread. When the Cubism SDK is unavailable, preview switches to this automatically.

Extensions apply only to data the model actually carries. When there is no applicable extension, or the only extension is simulation and physics is off, the preview state states the reason. An unbaked simulation does not provide live simulation data. If an enabled and baked simulation fails to build or calibrate, compilation reports that simulation, so an extension is not lost silently.

## `.p2lrt` format

Little-endian binary. It is a compact form of the compiled IR: canvas, parameters, deformers (parents first), parts, meshes, Glue, the draw tree, texture pages, physics groups, motion clips, and parameter roles (such as EyeBlink and LipSync). Every reference is an index.

Export writes version 2 by default: a file header, a block directory and 16-byte alignment, blocks with CRC, strings gathered in the string table, arrays with an encoding and 4-byte alignment, plus the parameter panel (`PGUI`) and generator info (`META`). The layout and the evolution rules are in [P2LRT_V2.md](P2LRT_V2.md). The export option `v1` writes version 1 (a single sequential stream; the field-by-field layout is in the doc comment of `P2lrt.kt`) for players that have not updated yet. `compress` deflates blocks that can shrink (texture pages excluded). `strip_names` removes display names and keeps ids.

The reader (`runtime/src/rig.rs`, `container.rs`) reads both versions and parses them into the same `Rig`. There is one copy of the evaluation code. It checks references, mesh indices, keyform sizes, block position and alignment, and that a block's records are read exactly to the end. It skips an optional block it does not recognize, and reports the tag of a required block it does not recognize. A block can be compressed with deflate or zstd (export setting `compress`; add `zstd` to use zstd).

## Evaluation rules

Evaluation outputs, for each mesh, the vertices in canvas pixel coordinates (y downward), opacity, multiply/screen color, and draw order. Every rule was obtained by black-box probing of the editor evaluator (`WarpProbeTool`, `RuntimeConformanceTool`). Its implementation was not consulted:

- **Parameters**: Clamped to the range. A repeating parameter wraps only values outside the range. The two ends keep their original values.
- **Keyform meshes**: Multilinear interpolation. When the value differs from a key point by less than 0.001, that key point is taken. A missing cell in a sparse mesh counts as a zero shape (a mesh offset of zero; a deformer's absolute shape is the origin). Weights are not redistributed. A flag channel (flip) takes the key point that is not greater than the current value.
- **Warp**: Inside the unit square, bilinear by cell, or split into two triangles along the (1,0)–(0,1) diagonal. Outside, within [-2, 3]², it extends by one layer of coarser virtual cells. Extra grid points take the average affine frame of the cell's four corners and interpolate by triangles. Farther out, only the affine frame is used.
- **Rotation deformer**: The angle is the keyform angle plus the base angle. When the parent is a rotation, the origin is transformed by the parent, and the angle and scale are composed with the parent. When the parent is flipped vertically, or the parent's scale is negative, the child frame rotates an extra 180°. A horizontal parent flip does not affect the child frame's direction. The object's own flip affects only child coordinates. When the parent is a Warp, the frame stays rigid: the origin is mapped by the cell, the angle rotates with the direction of the cell along v at 0.1 above the origin, and the scale inherits the scale of the nearest rotation above the cell.
- **Blend shapes**: Each binding blends linearly between neighboring key points by the parameter (it does not snap to a key point). The neutral key point and a key point with no shape do not contribute. The weight is multiplied by the piecewise-linear coefficient of each limit parameter. A deformer or channel shape is a target value, and what is added is “target − the value under the default pose.” A mesh shape is a target offset, and what is added is “target offset − the offset under the default pose.”
- **Opacity**: Each level (deformer, mesh) is clamped to [0, 1] first, then multiplied by the parent. Part opacity is not included in mesh opacity.
- **Glue**: After all deformation, each vertex of a pair moves toward the other by its own weight times the strength.
- **Draw order**: Each draw group is sorted by the children's draw order. A child group's key is the draw order of its part, computed from channels and blend shapes (the static value when there is no part). The key is rounded after adding one thousandth. Equal keys keep the order in the tree. A hidden mesh is not drawn. The rule is taken from the documentation of the engine's render-order interface. It has not been compared frame by frame with native rendering.

## Advanced mode

Extension blocks in the file provide features beyond Cubism-equivalent evaluation. All of them are off by default. `p2l_set_advanced` turns them on. When they are off, evaluation matches core evaluation bit for bit. Layout and meaning are in [P2LRT_V2.md](P2LRT_V2.md).

- **Runtime skinning (`P2L_SKIN`)**: A mesh that bends at a joint such as a knee or an elbow is sampled by key while baking, and interpolates along the chord between keys. At runtime the bone frames are linearly blended per vertex with two bones, plus “the current blend − the blend interpolated between keys.” That term is zero at each key, and between keys it replaces the chord with an arc. Weights are fitted to the baked keyforms when this is on. Bones the skeleton cropped or collapsed are supplied with the file as virtual bones. The host can read bone transforms through `p2l_bone_*` to attach objects.
- **Exact links (`P2L_EXACT_LINKS`)**: A pivot keyed on the same circle interpolates along the arc.
- **Live simulation (`P2L_SIM`) and collision (`P2L_COLLISION`)**: Baked cloth and hair run live with the editor's XPBD solver, replacing the baked pattern parameters and pendulums. A collider is a circle or a capsule along mesh vertices.

Verification: `advanced_tests` (an arm, links, virtual bones, and a hanging mesh with known analytic solutions); `p2lrt-conformance --advanced` requires each sample to match the bake on the skinning keys (all zeros); `--sim` compares the solver with the random cloth trajectories of `RuntimeConformanceTool.simulation`, bit for bit with the editor (including collision); `--sim-rig` compares the baked simulation of the tml back hair end to end, with an error of 0.21 pixels in the first half-second and 0.22 pixels on average over the whole run. The difference comes from a floating-point gap of about 1e-4 pixels when the two sides evaluate a target, which the cloth amplifies.

## Physics

Implemented the way the Cubism runtime reads physics3.json, including its particular behavior: inputs are normalized by the midpoint of the parameter range; at a fixed step (`Fps`) the input is interpolated between frames and the output is interpolated between the last two steps; with no step limit the output lags by one frame; a translated rotation reuses the already rotated x; only an angle output carries scale, and a translation output's scale is zero; accumulated time beyond 5 seconds is cleared. Compared frame by frame with the editor `PhysicsEngine` on random pendulum groups and sample models, the error is below 2e-5.

There are also three items from the Cubism runtime: vertical (Y) input and output (`PHYS` version 2, see [P2LRT_V2.md](P2LRT_V2.md); neither the editor nor Cubism Editor produces a vertical axis, and a physics3 export can write it), wind (`p2l_physics_wind`, added to the force on each particle, the same as Wind in physics3), and stabilization (`p2l_physics_stabilize`, which places each pendulum directly at the rest position along the force direction for the current pose and writes the output, the same as Cubism's Stabilization). When wind is zero, the result matches the previous one bit for bit.

## Motion clips

Curve segments match the editor (linear, Bezier with the time control points limited to the segment, step, inverse step). A looping clip wraps by its duration. A one-shot clip stops at the end. `Player` plays one clip at a time. On a switch it crossfades by the clip's fade-in and fade-out time (1 second when absent, cosine easing). A clip's weight is the product of the fade-in and fade-out coefficients (the same as Cubism). Every replaced clip fades out in full. A series of fast switches does not drop a clip that is still fading out.

## Procedural behavior

The host can turn these on: blink (the `EyeBlink` role, once every 2–6 seconds, close 0.1 seconds, hold 0.05 seconds, open 0.15 seconds, multiplied onto the current value; `p2l_blink_settings` can change the interval and each phase duration), breath (`Breath` is a sine inside the range; `AngleX/Y/Z` and `BodyAngleX` add a small swing), gaze (`look_at(x, y)` follows with critical damping and drives `AngleX/Y`, `BodyAngleX`, and `EyeBallX/Y`; `AngleZ` tilts with x·y), and lip sync (`lip_sync(level)`; a `LipSync` parameter takes the larger value; `p2l_lip_sync_samples` uses the root-mean-square of a span of audio samples times a gain as the open amount). `p2l_behavior_strength` adjusts the breath swing amount, the gaze turn amount, and the follow speed. Roles are written by the editor at compile time from the standard parameters that exist. A moc3 model3.json still writes only the EyeBlink and LipSync groups. Update order: motion clip → behavior → physics → deformation.

## C ABI

One handle is one loaded model. It holds parameters, the motion player, and physics state. The typical flow is `p2l_rig_load` → set parameters (`p2l_parameter_values` / `p2l_set_parameter`) → `p2l_update(dt)` (motion, physics, deformation) or `p2l_evaluate` → read `p2l_mesh_vertices`, `p2l_mesh_opacity`, and `p2l_mesh_colors`, and draw back to front by `p2l_render_order`. Textures come from `p2l_texture_png` (`p2l_texture_info` gives the page type: embedded PNG, KTX2, or a file beside the model). `p2l_rig_load_ex` can require block CRCs to be checked. `p2l_format_support` lists the supported versions and blocks. An expression (`p2l_expression`) is applied after motion clips and before procedural behavior. `p2l_hit_test` returns the hit area under a canvas point. `p2l_mesh_user_data` reads a mesh's user data. `p2l_pose_show` switches a part exclusion group (export setting `pose_groups`). A replaced part fades out with `p2l_update`. `p2l_parameter_values` is the pose the host set. Every `p2l_update` starts again from it and layers motion, expressions, behavior, and physics. The layered result is not written back, so blink, breath, and additive expressions do not accumulate frame by frame. The value actually used this frame is read with `p2l_parameter_current`. Every function accepts a null handle. A returned pointer stays valid until the handle is released (pose data until the next evaluation).

What ABI 1.1 adds (all new functions; 1.0 function behavior is unchanged, except that an out-of-range index now returns a distinguishable value):

- **Model and instances**: `p2l_model_load` reads the file once into a read-only model that can be shared across threads. `p2l_rig_create` creates, on that model, a handle that holds its own parameters, motion, and physics state. After `p2l_model_free`, handles already created still hold the model. `p2l_rig_load` is the two combined. One handle cannot be used by two threads at once (not even to read; `p2l_bone_transform` updates the handle).
- **Staged update and the host layer**: `p2l_update_stages(dt, stages)` runs only the selected layers (motion, expression, behavior, part pose, physics, live simulation, in the same order). A layer that is not selected is neither advanced nor layered. `p2l_set_parameter_override(index, value, weight)` is the host layer: after motion and expressions, and before behavior and physics, it pulls a parameter toward the given value by weight (face capture and similar). Physics still swings with it. `p2l_parameter_values` is still the bottom layer.
- **Parts and isolation groups**: `p2l_part_*` gives the part id, name, parent part, flags, and grouping (pass-through, sort the whole group, isolate). `p2l_render_commands` is the draw order that keeps isolation-group boundaries (mesh indices; `-2 - 部件` opens a group, `-1` closes a group). The group's blend mode, opacity composite mode, and masks (a mask part expands to its meshes) come from `p2l_part_group` / `p2l_part_masks`. The evaluated group opacity and multiply/screen color come from `p2l_part_composite`: the channel overrides of that group in the draw tree cover the static value it composited, matching the editor. `p2l_set_part_opacity` sets the host's part opacity and, like the part pose, multiplies it onto every mesh under the part. `p2l_mesh_part` gives the part a mesh belongs to. `p2l_mesh_alpha_blend` gives the mesh's opacity composite mode.
- **File information**: Parameter names and flags (repeat, blend-shape parameter), snap values, and the parameter panel (`PGUI`: 2D sticks, the group tree, labels), the canvas origin and pixels per unit, a motion clip's name, group, duration, frame rate, loop, and fades, the clip that is playing, the current time, and seeking (`p2l_clip_seek` only moves the clip time; fades continue as usual), display names of expressions, hit areas, and meshes, and generator info (`META`).
- **Other**: `p2l_behavior_seed` resets the blink random seed. After the first handle in the process, each handle takes its own seed automatically. A value function for an out-of-range index returns NaN (a number) or -1 (an index or a mode). A null handle still returns 0. `p2l_alloc` allocates exactly the length and clears it. `p2l_texture_png` of a non-PNG texture page writes the length as 0. `p2l_parameter_index` looks up the string given by `p2l_parameter_id`.

What ABI 1.2 adds (again, only new functions):

- **Motion layers**: At most `P2L_MAX_LAYERS` (16) layers. Each layer plays one clip at a time, stacked on the layer below in layer order. `p2l_set_layer_weight` sets the weight with which that layer covers the layer below. `p2l_play_layer(layer, clip, priority)` starts only when the priority is not lower than the priority of the clip that layer is playing (0 after the clip finishes or stops), matching the priority of the Cubism motion manager. `p2l_play` and `p2l_clip_*` operate on layer 0.
- **Motion events and non-parameter curves**: From `CEXT` (see [P2LRT_V2.md](P2LRT_V2.md)). Events passed during each update are given by `p2l_event_count` / `p2l_event` (text, layer, clip, time). Part opacity and overall opacity set by a clip are multiplied onto the meshes. `p2l_evaluate` evaluates only the host pose, so it does not include them. Blink and lip-sync effects act on the corresponding role parameters. A curve with its own fade-in and fade-out takes its weight by Cubism's rule.
- **Several expressions**: `p2l_expression_add` / `p2l_expression_remove` let several expressions apply at once (each fades in and out, stacked in the order they started). `p2l_expressions_playing` lists the ones in effect. `p2l_expression` still keeps only one.
- **Overall opacity and color override**: `p2l_set_opacity` multiplies onto every mesh (multiplied with the overall opacity set by a clip; `p2l_opacity` reads the product). `p2l_set_mesh_colors` / `p2l_set_part_colors` replace the evaluated result with the multiply/screen color given by the host. A mesh's own setting wins over the nearest setting on the part chain it belongs to.
- **Physics and behavior**: `p2l_physics_wind`, `p2l_physics_stabilize`, `p2l_blink_settings`, `p2l_behavior_strength`, and `p2l_lip_sync_samples`. See “Physics” and “Procedural behavior” above.

ABI 1.3 adds `p2l_render` and `p2l_render_texture` (see “Software rendering” below). ABI 1.4 adds:

- **Change flags**: `p2l_mesh_changes` says whether a mesh is drawn (it is in the draw order and its opacity is greater than 0), and, compared with the previous evaluation, whether visibility, opacity, the draw-order value, the position in the draw order, vertices, or multiply/screen color changed. This matches Cubism's dynamic flags. The host only has to upload what changed. After the first evaluation, all of them are set. They are updated at the end of every entry that changes the pose (`p2l_update`, `p2l_update_stages`, `p2l_evaluate`, `p2l_set_advanced`, `p2l_physics_stabilize`).
- **Log**: `p2l_set_log` receives load failures, invalid handles, and texture pages the renderer cannot decode.
- **Host allocator**: `p2l_set_allocator` makes every later allocation of the runtime come from the host's allocate and free functions (size and alignment are passed through). It must be called on a single thread, before any other part of the runtime is used. If the runtime has already requested memory from the system, it returns false and changes nothing. It is provided by the `host-allocator` feature, which is on by default (turn it off when the runtime is used as a Rust library by a Godot node and similar). Measured with the C sample: all 7570 allocations while rendering the tml sample go through the host allocator.

On the writer side: IR `Clip` gains `events` and `targetCurves`, `Curve` gains `fadeIn` / `fadeOut`, and `PhysicsSource` gains `Y`. A p2lrt export writes `CEXT` and, when needed, `PHYS` version 2. A moc3 export's motion3 writes `UserData`, `PartOpacity`, and `Model` (`Opacity`, `EyeBlink`, `LipSync`) curves and curve fades. physics3 writes `Y`. cmo3 has no vertical physics, so vertical input and output are omitted. The editor's motion editing does not yet offer an edit entry for events and non-parameter curves. That data comes from the IR.

The draw rules are written at the start of the header, with `SoftwareRasterizer` as the reference: textures are straight alpha, and the rules are computed on premultiplied color. A fragment color is multiplied by the multiply color first, then the screen color is layered by `c + s·a − c·s`, and finally it is multiplied by opacity and mask coverage (the maximum texture alpha of the mask meshes at that point; inverted coverage is 1 − coverage; a live player may approximate with a stencil of alpha ≥ 0.5). When culling is on, only faces that are clockwise in canvas coordinates (y downward) are drawn. Cubism's normal, add, and multiply use their premultiplied formulas (add and multiply keep the destination alpha). Extended modes use the W3C composite formulas. Blend modes and opacity composite modes have `P2L_BLEND_*` and `P2L_ALPHA_*` constants.

A panic inside the runtime during a call (a defect, or a model the reader let through but that cannot be evaluated) does not unwind into the host: that call returns as a null handle, the handle becomes invalid, `p2l_rig_failure` gives the reason, and from then on it is the same as a null handle until `p2l_rig_free`. A panic during load (including the first evaluation) makes `p2l_rig_load` return null and write the reason. A panic in the WebAssembly build still aborts the instance (that target does not support stack unwinding).

ABI version: the header's `P2L_ABI_VERSION_MAJOR` / `P2L_ABI_VERSION_MINOR` and the library's `p2l_abi_version()` (`major << 16 | minor`). Adding a function increments the minor version. Changing or removing a function increments the major version. The host checks with `P2L_ABI_COMPATIBLE(p2l_abi_version())`. A library without `p2l_abi_version` is earlier than 1.0. `p2l_version` is only the library's build version. When the JVM binding loads the library it requires the same major version and a minor version no lower than the binding needs. Otherwise it is treated as no runtime. When a handle becomes invalid after evaluation or update, it throws (the software preview therefore falls back to the editor evaluator; the runtime preview backend and export report the error). `cargo test` checks that the functions declared in the header correspond one to one with the functions the library exports, and that the version numbers match.

## Verification

- `cargo test`: one small-model unit test per evaluation rule (the numbers come from the probe results), plus Warp and motion-clip tests. `format_tests` assembles a version 2 file block by block, covering compression, CRC, the block directory and the various rejection cases, every array encoding, texture-page types, and the parameter panel.
- `RuntimeConformanceTool` (`PSD2LIVE_TOOLS=1`): generates 80 random models (Warp, rotation, nesting, sparse meshes, blend shapes, Glue, channels, parts, blending), reference poses of samples and local projects, and physics trajectories. `cargo run --release --bin p2lrt-conformance -- ../build/tools/runtime-conformance` (physics is `runtime-physics`) compares them case by case. Each case is also written as version 2, version 1, and version 2 compressed with deflate and with zstd. The four must read as the same `Rig` and produce the same pose bit for bit. The vertex error limit is 0.02 pixels. A pose beyond that is judged by its own condition number: the largest distance any vertex moves when any parameter is moved by one millionth of its range (the sensitivity). The error must not exceed twice that. Interpolation inside a mesh uses double precision. Everything currently matches. The only case beyond 0.02 is one pose of blend-6 (0.10 pixels, sensitivity also 0.10; that mesh's opacity is then 3e-5).

- GPU rendering is done by the host: the runtime provides geometry and attributes, and draws masks and every composite mode with `p2l_render` (CPU software rendering, see the next section). A GPU host draws by the same rules itself (drawing for the web target is in [Export targets](EXPORT_TARGETS.md)).

## Software rendering

`p2l_render` (ABI 1.3) draws the latest evaluation into an RGBA8 image given by the host. The rules match the reference rasterizer `SoftwareRasterizer`: bilinear premultiplied sampling, pixel-center and top-left rules, masks by texture alpha (including inverted), isolation-group layers, every color and opacity composite mode, and culling. The transform is an affine from canvas to image (a null pointer fits the canvas uniformly into the top left of the image). The output is premultiplied or straight alpha, and it can be drawn on top of existing content. An embedded PNG texture page is decoded by the decoder the runtime carries (non-interlaced, every color type). KTX2 and external file pages are pixels provided by the host through `p2l_render_texture`. It is for a host that has no renderer of its own (C/C++, an engine plugin, thumbnails, and checks), and it runs per pixel on the CPU. Verification: `SoftwareRenderParityTest` compares, pixel by pixel, with the reference rasterizer on a model that covers 90 composite combinations, isolation groups (opacity and color driven by channels, mesh and part masks, inverted, nested), masks, multiply/screen color, and culling, at three poses and scales. The maximum channel difference is ≤ 1/255. When the conjoint overlap weight is deliberately wrong, that test reports a difference of 77/255.

## Web player

The `web` export target writes a folder that can be deployed directly: `index.html`, `p2l.js` (the ES module `P2LPlayer`), `p2l_runtime.wasm`, and the model. The player draws with WebGL and, by the header's composite rules, draws every color and opacity blend combination and isolation groups: normal (over) and Cubism's add and multiply use blend functions, and the other combinations first copy the layer below inside the mesh bounds into a texture and composite in the shader. An isolation group is drawn into a layer by `p2l_render_commands`, and on close it is composited by the group's mode, opacity, multiply/screen color, and mask. Masks go through the stencil buffer (clipped at texture alpha 0.5, inverted supported). A mesh with culling on draws only the front face. `WebPlayerCheckTool` (`PSD2LIVE_TOOLS=1`) generates a model and a per-pixel reference image covering 90 combinations and 16 isolation groups. In Edge (headless) the difference from the reference is at most 1/255. The page offers motion and expression choices and a lip-sync slider, gaze follows the pointer, and a click shows the hit area under it. When the file carries advanced-mode data, the page offers a switch. The WebAssembly build is committed with the repository as a resource. After changing the runtime, refresh it with `./gradlew :targets:web:updateWasm` (requires `rustup target add wasm32-unknown-unknown`). Unit tests check that every function the player calls is exported by that build. The tml sample displays correctly in Edge (headless).

## Godot

`runtime/godot/` is built with `cargo build --release`. The properties and methods of `P2LCharacter` are in its README. The node draws by the header's draw rules: each mesh is in its own canvas item, sorted by `render_commands`. The texture is premultiplied on load. The shader applies multiply/screen color, opacity, and mask coverage, then composites by the color and opacity composite modes. Normal+over, Cubism add/multiply (any opacity mode), and out use hardware blending. The rest read the color below and compute it in the shader. An isolation group draws its content into an offscreen viewport (a layer) the same size as the target viewport, and composites at the group's position by the group's blend mode, opacity mode, opacity, multiply/screen color, and mask. Groups can nest. The back-buffer copy of Forward+ and Mobile loses alpha, so each item inside a layer that reads what is below uses its own viewport: it copies the layer content so far, then reads it. Outside a group it reads the screen, and what is below is treated as opaque (an approximation under a transparent window). Masks are drawn into a coverage viewport (three mask groups per viewport). A mesh and a layer read coverage in their own pixels. An inverted mask takes 1 − coverage. Where the same mask group overlaps, alphas add (the reference takes the maximum). A mesh with culling on submits only front triangles (in canvas coordinates, (b − a) × (c − a) < 0). Masks are not culled. The feature model of `RuntimeSamplesTool` matches the software-rasterizer reference in Godot (difference ≤ 2/255, including inverted masks). `GodotLayerSamplesTool` (`PSD2LIVE_TOOLS=1`) generates flat-color models and expected values covering every color × opacity composite mode (on an opaque background and inside an isolation group) and a group's color, opacity, blend mode, mesh/part masks, inverted masks, and nesting. Godot 4.7 under Forward+, Mobile, and Compatibility differs by ≤ 1.2/255 at each sample point. Verification: the demo project's `smoke_test.gd` loads the model in headless mode and advances one second. `--shot` renders one frame in a window. The tml and ds samples display correctly.
