Whether image generation is needed depends on the task. Adjusting existing parameters or physics does not need it. Painting in an occluded region, or adding new artwork, requires the host to provide image generation.

## Evaluation criteria

| Rating | Meaning |
| --- | --- |
| Very good | Completes reliably |
| Usable | Completes, and needs a small amount of manual correction |
| Marginal | Needs a lot of rework, or a person to catch it |
| Unusable | Not completed, or the result is unacceptable |

A few successful samples do not mean it is equally stable on other artwork.

## How to submit a new record

Each record should include:

- The application version or commit, the host, and the model.
- The task description and the source artwork, and whether image generation was used.
- The sample count, the rework count, the time taken, and the quota consumed.
- The result files or history nodes, and a clear pass / fail reason.

During acceptance, compare the actual model's neutral pose, parameter endpoints, and motion, and check save-and-reopen and the export result. A reference image alone, a tool returning success, or a single screenshot is not enough to prove the task is done.
